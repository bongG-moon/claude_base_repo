## 결론과 범위

사용자 요청에 따라 설치·실행 흐름, 회사/개인/프로젝트 경계, 도구 제작·산출물을 나누어 독립 검토하고 서로의 수정도 교차 검토했다. 시작 기준은 `07c0431` / 1.4.18이다. 실제 결함을 재현해 수정했으며, 지침에 문구가 있다는 사실과 실행으로 확인한 사실을 구분한다.

이 검토는 로컬 소스와 격리된 합성 자료를 대상으로 한다. 사용자의 실제 Claude 로그인·설정·MCP·개인 기억을 변경하지 않았고, 사내 HCP·DRM 문서·메일 발송·운영 서버를 시험하지 않았다. 이번 작업에는 커밋·배포·직원 PC 설치 갱신이 포함되지 않는다.

## 재현하여 수정한 결함

### 1. 스킬을 읽지 않은 부모 대화에 읽음 기록이 생김

서브에이전트는 부모와 session_id를 공유할 수 있다. 자식의 Skill/Read 성공을 부모 기록에 넣어 다음 부모 요청이 본문을 재사용한 것으로 처리했다. agent_id가 있는 별도 대화의 읽기 기록·준비 보정 예산을 부모와 분리했다. agent_type만 있는 메인 대화는 유지한다. 작업자의 실행·권한 정책은 그대로 적용한다.

근거: `tests/test_skill_execution.py`의 자식/부모 기록 회귀. [Claude Code Hook 입력 문서](https://code.claude.com/docs/en/hooks#common-input-fields).

### 2. 일부 변경 작업은 완료 검증 없이 통과하고, 미실행 거절은 변경으로 오인

Node 등 인라인 코드와 일부 Git 변경을 변경 이력으로 관찰하지 못했다. 알려진 실행기·Git 변경의 경량 문자열 분류를 보완하고, 순수 버전/목록 조회는 제외했다. PowerShell에서 호스트가 명시한 미실행 거절은 변경 수를 늘리지 않되 이전의 미검증 변경은 유지한다. 단순 PermissionError는 부분 실행 가능성이 있어 미실행으로 단정하지 않는다.

근거: `tests/test_shell_mutation_receipts.py`. 명령 분류는 관찰용이며 모든 셸 문법을 해석하거나 실행 권한을 부여하지 않는다.

### 3. 요청했던 일반 위험 명령 방어가 누락

스킬 준비 이후 일반 Bash가 정책 검사 없이 지나가는 경로에서 `git reset --hard`, 강제 clean/push와 재귀 강제 삭제를 차단하지 않았다. 실행 전의 순수 deny-only 검사를 추가했다. `--repo`로 원격을 지정한 강제 refspec도 검사하며, 설명·검색 인자와 실제 dry-run/WhatIf는 구분한다.

근거: `tests/test_dangerous_commands.py`. 위험 명령은 실행하지 않고 Hook 입력 문자열과 반환 결정으로 재현했다. 새로운 자동 승인·모델 호출·개인 설정 변경은 없다.

한계: 명령 16,384자, 토큰 2,048개, 알려진 셸 래퍼 2단계 이내의 직접 구문만 검사한다. 변수·함수·별칭·스크립트·EncodedCommand·난독화 등은 해석하지 않는다. 이는 실수 방지이며 DLP나 완전한 셸 샌드박스가 아니다. 기존 Claude/OS 권한을 유지하며 알 수 없는 명령에 allow를 발급하지 않는다.

### 4. 정확한 개인 기억이 무관한 프로젝트 기억에 밀림

두 저장소 결과를 단순히 이어 붙인 뒤 5개로 잘라, 무관한 프로젝트 선호 5개가 정확히 일치하는 개인 업무 지식을 밀어냈다. 원래 전체 본문의 관련도를 유지해 두 범위를 함께 정렬하고, 같은 점수만 프로젝트를 우선한다. 중복 제거와 전체 5개 한도는 유지한다. 저장소를 합치거나 점수를 모델에 전달하지 않는다.

근거: `tests/test_resource_scope.py`. 실제 파일 6개로 회귀를 재현했으며 추가 읽기 없이 같은 자료를 한 번씩 읽는다. 긴 본문의 뒤쪽에만 있는 일치와 한도·중복도 검사한다.

### 5. 도구의 JSON 조건을 무시하고 검증 성공 기록 발급

minimum/maximum, enum, additionalProperties 조건이 실제로 적용되지 않았다. 지원할 작은 조건 집합을 명확히 검사하고, 미지원 키·잘못된 중첩 정의·NaN/Infinity는 오류로 반환한다. true와 숫자 1을 다르게 비교한다. 잘못된 입력은 실행 전, 잘못된 출력은 검증 기록 발급 전에 실패한다.

교차 검토에서 과거 검증 기록 재사용도 발견했다. JSON 기반 플랫폼 도구는 현재 기록 없이 신규 활성화·관리 의존성 연결을 하지 않고, Script Tool은 관리 실행 전에도 재시험한다. text-only 플랫폼 도구의 기존 기록은 보존한다. 이미 별도 등록된 네이티브 MCP를 강제로 해제하거나 소스·설정을 자동 변환·삭제하지 않는다.

근거: `tests/test_asset_schema.py`, `tests/test_unified_authoring.py`. 합성 MCP의 정상/조건 위반 실행과 기록 발급·활성화 경계까지 검사한다. 지원 조건은 asset-factory의 조건부 참고 문서에 안내한다. JSON Schema 전체 규격을 구현하거나 새로운 검증 라이브러리를 추가한 것은 아니다.

### 6. HTML→PPT 배치 추출이 원래 flex/grid를 변경

슬라이드를 display:block으로 강제해 중앙 카드 위치가 (380,220)에서 (0,0)으로 이동했다. 보이는 정적 슬라이드의 원래 flex/grid 배치를 그대로 읽는다. 숨김·이동/회전/크기 변형은 임의 복구하지 않고 명시적 제한으로 알린다.

근거: `scripts/test-lab/check-ppt-dom-layout.mjs`로 격리된 실제 Edge에서 flex와 grid의 (380,220,200,100) 보존, 숨김·변형 5종 오류, 외부 요청 0건을 확인했다. 이 검사는 배치 추출 단계이며 실제 회사 PowerPoint의 모든 렌더링을 증명하지 않는다.

### 7. Workspace가 프로세스 종료 전에 반환해 폴더가 잠김

첫 전체 검사에서 Workspace 종료 관련 2개가 WinError32로 실패했고, 두 개만 다시 실행해도 동일했다. 시험 환경에서 taskkill이 실패한 뒤 5초를 기다리고 kill을 호출했지만, 비동기 종료 완료를 다시 기다리지 않았다. 그 결과 close 직후에도 직접 시작한 프로세스가 살아 있고 작업 폴더가 잠겨 있었다.

앱의 입력 연결을 닫고 최대 0.3초 정상 종료를 먼저 기다려, Windows 실행 래퍼가 자식 CLI를 회수하도록 했다. 종료되지 않으면 기존 소유 PID 트리 종료와 보유 Popen 핸들만 대상으로 한 kill 후 wait를 수행한다. 여러 close 호출의 종료 완료 대기를 구분하고, 출력 읽기 스레드의 자기 대기나 스트림 잠금도 피한다. 종료를 확인하지 못했으면 중지 성공으로 표시하지 않는다. 프로세스 이름 검색이나 다른 앱 종료는 추가하지 않았다. taskkill 실패 시 직접 CLI의 종료 확인만 가능하며 모든 하위 프로그램까지 종료했다고 보장하지 않는다.

근거: 실제 합성 CLI를 사용하는 실패 2개가 수정 후 통과했다. `tests/test_workspace_close.py`는 종료 명령 실패/시간 초과, kill 뒤 회수, 동시 호출·재진입, 종료 미확인의 표시를 검사한다. 실패를 무시하거나 임시 폴더 정리를 제외하지 않았다.

## 속도·토큰과 과도한 구현 점검

## 운영 환경에서 남는 확인

1. 승인된 시험 폴더·가상 문서로 스킬 이름 없이 읽기를 요청한다. 목록 제공→실제 본문 로드→Office 읽기 경로를 도구 기록으로 확인한다. 회사 문서 내용이나 전체 로그를 외부에 공유하지 않는다.
2. 등록된 모델 별칭이 실제 HCP 모델과 맞는지, 작업자에게 실행 경로·언어·범위가 전달되는지 확인한다. Unknown skill만으로 플러그인 전체가 비활성이라고 단정하지 않는다.
3. 실제 Office/DRM 승인 전후 대기와 순수 읽기 시간을 나누어 측정한다. 로컬 합성 검사 통과로 사내 보안 프로그램과의 호환을 보장하지 않는다.
4. 모델 기반 선택·업무 정확도, 한국어 응답 일관성, 실제 토큰·전체 시간은 같은 가상 사례의 전후 비교가 필요하다. 이번에는 사내 모델을 호출하지 않았으므로 개선률을 주장하지 않는다.

Windows·승인된 Python·해당 업무의 Office 등 문서화된 환경이 대상이다. 모든 OS·임의 모델·모든 외부 플러그인에서 동일 동작한다고 보장하지 않는다.
