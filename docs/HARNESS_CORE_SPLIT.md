# 기억과 학습 중심의 기본 구성

1.5.0은 개인화 하네스와 개별 업무 기능을 설치 단계에서 분리합니다. 이전 개인 자료를 새 구조로 옮기는 마이그레이션은 하지 않습니다.

## 무엇을 설치하나요?

| 범위 | 포함 내용 |
| --- | --- |
| 기본 하네스 | 개인 기억, 개인 지식, 관련 스킬 선택, 개인 업무 절차 저장과 수정, 근거에 따른 학습, 필요할 때 조회하는 사용성 보고서 |
| 개별 스킬 | HTML, PPT, Excel, 파일 정리, 웹 화면, 업무 기록 분석, DB 조회, 도구와 MCP 제작 |
| 이번 구성에서 제외 | VLM 모델 자동 선택, 이미지 읽기 강제 인계, vision-worker |

기본 스킬은 `company-agent`, `personal-memory`, `personal-knowledge`, `self-learning`, 개인 절차 저장용 `asset-factory`입니다. 개인 전체나 프로젝트에 이미 있는 스킬도 계속 검색합니다. 적합한 스킬이 없으면 일반 실행을 허용하며 기능 설치를 선행 조건으로 삼지 않습니다.

개별 `asset-factory`는 도구와 MCP를 제작하는 기능까지 포함합니다. 기본 스킬과 개별 스킬의 이름이 같을 때는 출처와 선택을 구분합니다. 기존 개인 스킬을 이동하거나 같은 이름의 파일을 자동으로 복제하지 않습니다.

## 소스와 배포의 경계

`deploy/harness-core-manifest.json`이 기본 플러그인에 넣을 파일을 하나씩 지정합니다. `scripts/harness_core/build-profile.py`가 `harness-core/`의 핵심 지침과 공통 런타임을 조합하고, 누락과 추가 파일을 검사합니다. 새 업무 엔진을 소스에 추가해도 기본 설치에 자동으로 포함되지 않습니다.

기능 엔진은 개별 ZIP의 의존 코드로 재사용하므로 개발 저장소의 `company-agent-plugin/`에 남아 있을 수 있습니다. 이 폴더 전체를 직접 `--plugin-dir`로 로드하는 것은 기본 직원 설치본이 아닙니다. 개발 모드의 호환성을 유지하면서 배포본에는 필요한 파일만 넣습니다.

설치된 `resources/core-install.json`을 기준으로 core 실행 경로를 선택합니다. core에서는 business와 vision 명령, 이미지 인계, HTML과 PPT 전용 완료 지침을 노출하지 않습니다. 개인 스킬 만들기와 수정은 유지하지만 MCP와 script-tool 생성 명령은 노출하지 않습니다. 기존 개인 MCP의 연결 정보를 지우지 않습니다.

기존 설치와 같은 범위로 업데이트하면 개인 기억과 지식, 개인 스킬, 학습 내역, 모델과 MCP 설정을 보존합니다. 예전 회사 HTML 스킬 선택이 남아 있더라도 개인 HTML 스킬로 자동 치환하지 않습니다. 새 연결에서 실제 사용 가능한 후보를 확인합니다.

## oh-my-hermes에서 참고한 부분

[확인한 소스](https://github.com/rlaope/oh-my-hermes/tree/76fa9c615c069de07d1122967136f787bfd8618b)는 Hermes용 운영 계층입니다. 전체를 가져오면 이번에 줄이려는 실행 경로와 설정이 다시 늘어나므로 필요한 개념만 비교했습니다.

기존 하네스에는 요청과 관련된 기억만 제한적으로 넣기, 근거가 있는 교정만 접수하기, 후보와 실제 적용 구분, 원본과 복구 이력 보존이 이미 있습니다. 이번에는 [기억 접수 판단](https://github.com/rlaope/oh-my-hermes/blob/76fa9c615c069de07d1122967136f787bfd8618b/src/plugin_bundle/omh/memory_admission.py)의 명시적 판정 방식을 참고해 학습 결과의 이유 코드를 정리했습니다. 근거 부족, 이미 적용됨, 재적용 제한과 적용 대상 보류를 기존 학습 조회에서 설명합니다. 과거 기록도 읽을 때 해석하며 별도 저장소 마이그레이션을 하지 않습니다.

매 요청 회고, 새 모델 호출, 기억 만료와 자동 삭제, 상시 외부 동기화, 추가 작업자 체계는 넣지 않았습니다. 사용자 개인화를 모델 재훈련이나 완전 자동 스킬 생성이라고 설명하지 않습니다. 새 절차 스킬은 저장 요청이나 제안 수락 후 만들며, 자동 절차 학습은 실제 사용하고 검증한 개인 스킬의 작은 점검 항목에 한정합니다.

## 검증 범위

가상 자료와 격리된 Claude 설정으로 다음을 확인했습니다.

- 제한된 설치 파일에서 일반 요청과 파일 쓰기가 기능 스킬 부재 때문에 차단되지 않음
- 개인 스킬 생성, 검증, 조회, 동일 원본 수정, 절차 학습으로 이어지는 흐름
- 선호 학습 접수 후 새 세션에서 관련 기억 제공
- 실제 Claude CLI의 User와 Project 등록, 재설치, 제거, 실패 시 복구, 한글 경로
- 이전 1.4.49에서 1.5.0으로 업데이트할 때 개인 기억, 지식, 스킬, 학습 상태, 모델과 MCP 설정 보존
- 삭제된 회사 기능 스킬의 오래된 선택이 다른 출처로 자동 바뀌지 않음

설치 복사 예제의 JSON 개행 오류도 수정했습니다. JSON 예제를 파싱하는 회귀검사를 추가했습니다. 실제 사용자 설정이나 운영 모델은 이 검증에 사용하지 않았습니다.

같은 가상 요청의 후크 `additionalContext` 문자 수를 비교했습니다. 모델 토큰 수나 응답 속도 측정은 아닙니다.

| 경로 | 이전 1.4.49 | 기본 1.5.0 | 변화 |
| --- | ---: | ---: | ---: |
| 세션 시작 | 7,653 | 7,234 | 5.5% 감소 |
| 첫 요청 | 6,615 | 5,189 | 21.6% 감소 |
| 다음 요청 | 5,433 | 4,078 | 24.9% 감소 |
| 기억이 있는 새 세션 | 10,831 | 7,069 | 34.7% 감소 |

세션 시작의 UTF-8 크기는 11,987에서 12,412 bytes로 3.5% 증가했습니다. 나머지 경로는 약 18~35% 감소했습니다. 글자 수와 바이트 수를 실제 토큰 절감률로 바꾸어 주장하지 않습니다. 사내 모델의 의미 판단과 실제 업무 속도는 운영 환경에서 별도 확인이 필요합니다.
