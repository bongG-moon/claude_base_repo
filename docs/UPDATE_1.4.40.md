# Company Harness 1.4.40

이미지 한 장을 읽다가 일반 작업자로 잘못 인계되어 자기 자신에게 메시지를 보내거나, 파일·설정 탐색을 반복하던 흐름을 보완합니다. 별도 Workspace 앱·Computer Use MCP·실습 자료 변경은 포함하지 않습니다.

## 비전 인계를 짧고 명확하게

- 이미지 확인은 `company-agent:vision-worker`를 명시한 새 작업자가 담당하고 한국어 텍스트 결과를 반환합니다. 메인 모델은 바꾸지 않으며 이후 작업은 원래 모델로 계속합니다.
- 방금 보류한 같은 이미지·대화·폴더와 비전 인계 의도가 확인될 때만 누락된 작업자 종류를 보완합니다. 다른 작업자·다른 파일·이전 대화까지 자동 전환하지 않습니다.
- 자기 자신에게 보내는 인계 메시지와 이미 처리한 인계를 같은 일반 작업자로 다시 시작하는 반복을 차단합니다. 추가 작업자는 `NEEDS_VISION`을 부모에게 직접 반환하며 비전 작업자가 실행되지 않았는데 기다리고 있다고 보고하지 않도록 안내합니다.
- 단순 이미지 읽기에는 `workFile`이 필요하지 않습니다. 전체 전사를 요청하면 보이는 글자·수치·구조를 보존하고 읽지 못한 부분은 표시합니다. 실패 후 Base64·픽셀 통계·사본·OCR 설치·전체 설정 탐색으로 돌아가지 않습니다.
- 실제 접근 권한과 승인 절차는 유지합니다. 비전 라우팅은 접근 승인이나 회사 자료의 AI 처리 허가를 대신하지 않습니다.

## 적용 범위와 검증

기존 환경의 `ANTHROPIC_CUSTOM_MODEL_OPTION`이 `HCP-Vision-Latest`인 경우의 이미지 파일 읽기와 등록된 화면 관찰 경로를 대상으로 합니다. 입력창에 직접 붙인 이미지나 모든 MCP 이미지 응답을 자동으로 분리하는 기능은 아닙니다. 설치기는 개인 모델·MCP·권한 설정을 새로 만들거나 변경하지 않습니다.

직전 소스 검증에서 관련 회귀 테스트 **166개**가 통과했습니다. 이 결과는 누락된 작업자 종류의 보완, 다른 대화·경로와의 분리, 반복 차단 등 로컬 경로에 대한 것입니다. 이번 릴리즈의 재검증·패키지·게시 결과는 별도 검증 기록으로 확인합니다. **사내 HCP Vision의 실제 응답과 게이트웨이 연결은 운영 환경에서 아직 검증하지 않았습니다.**

## 운영 환경에서 확인하기

1. 기존과 같은 설치 범위로 업데이트한 뒤 Claude Code와 사용 중인 앱을 종료하고 다시 엽니다. 개인 기억·스킬·모델·MCP 설정은 그대로 유지합니다.
2. 회사에서 AI 처리를 허용한 시험 이미지 파일 하나를 지정해 **“이 이미지의 내용을 읽고 정리해줘”**라고 요청합니다. 일반 작업자 대신 `company-agent:vision-worker`가 실행되는지 확인합니다. 실제 `HCP-Vision-Latest` 요청 여부는 제공되는 CLI 또는 사내 게이트웨이 기록에서 확인하며 작업자 이름만으로 성공 판정하지 않습니다.
3. 이미지의 제목·수치와 답변을 비교합니다. 필요한 경우 **“보이는 글자를 빠짐없이 옮겨줘. 안 보이는 부분은 표시해줘”**로 전사를 확인합니다. 별도 작업 파일 탐색·자기 메시지·같은 실패 반복이 없어야 합니다.
4. 이어서 **“방금 내용을 세 줄로 요약해줘”**라고 요청합니다. 메인 모델이 기존 설정으로 작업을 계속하며 모델·승인 설정 파일이 변경되지 않았는지 확인합니다.
5. 비전 모델 접근이나 이미지 읽기가 실패하면 실제 오류와 미확인 범위를 확인합니다. 작업자가 실행되지 않았는데 결과 대기 중이라고 하거나 사본·설정 탐색을 이어가면 해당 도구 기록만 담당자에게 전달하세요. 인증 토큰·전체 설정·민감한 원문은 보내지 않습니다.
