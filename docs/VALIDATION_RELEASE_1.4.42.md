# Company Harness 1.4.42 검증 기록

검증일: 2026-10-14. 실제 사내 DRM·HCP 모델·회사 게이트웨이는 시험하지 않았습니다.

## 배포 범위

- `excel-to-pipeline` 스킬, 요청 시 실행하는 CLI, 관련 선택 규칙·문서·가상 시험 자료를 추가했습니다.
- standalone 구현을 단일 원본으로 유지하고 직원용 스킬 실행 파일을 생성합니다. 빌드에서 동기화 여부를 확인합니다. 직원 ZIP에는 시험 코드·XLSM 자료·교육용 매크로를 넣지 않았습니다.
- 기존 미커밋 Workspace 앱·비전 설정 변경은 제외했습니다. HEAD와 이번 변경만 합친 분리 소스에서 빌드했습니다. 선택한 Git 트리의 720개 파일이 시험 소스와 바이트 단위로 같았습니다. 이 검증 기록은 그 뒤 추가했습니다.
- 새로운 후크, 세션 조회, 별도 LLM 호출, 매번 실행되는 의존성 점검은 추가하지 않았습니다. 스킬 설명은 목록에 추가되지만 본문은 해당 요청에서만 읽습니다. 정적 안내를 간결하게 유지하고 상세 절차를 참고 문서로 분리했습니다.

## 자동 시험

- 독립 분석·전처리 시험 **217개 통과**. 별도 소스 복사본에서도 개인 `outputs`, `.smoke`, 네트워크 없이 재현했습니다. 필요한 가상 자료와 원본 VBA 계약·출처·라이선스를 소스에 포함했습니다.
- 새 설치 경로 CLI·대소문자 보존·생성 코드 재실행·개인 스킬 선택·일반 읽기 유지·누락 의존성·한도·오류 처리 시험 **14개 통과**.
- 새 통합 14개와 Windows 실제 후크 연동 21개를 합친 **35개가 126.936초에 통과**했습니다. 내부 검사 분류는 자동 실행 허가가 아니며 기존 권한 정책을 유지합니다.
- 통합 문서 계약 **21개 통과**, 오프라인 패키지 회귀 검사 통과.
- 깨끗한 배포본의 본문 미주입·컨텍스트 크기 시험 통과: 4,864자, 기준본 4,836자, 한도 5,000자. 시험 설치 경로 길이가 달라 이 차이를 실제 토큰 사용량 증가로 계산하지 않습니다. 실제 업무의 토큰 절감률은 측정하지 않았습니다.

### 광역 검사에서 구분한 기존 불일치와 시험 환경 문제

초기 광역 229개 실행은 실패 7개·오류 6개·건너뜀 4개였습니다. 전체 통과로 보고하지 않습니다.

- PowerShell/연결 폴더 생성의 샌드박스 제약은 승인된 격리 실행에서 재검증했습니다. 실제 후크 21개 및 연결 폴더 거절 시험이 통과했습니다. 보안 정책을 변경하지 않았습니다.
- 저장소 내부 TEMP로 인한 상위 프로젝트 스킬 탐색 시험 2건은 HEAD에서도 동일하게 실패했습니다. 기본 Windows TEMP에서는 HEAD와 배포본 모두 통과했습니다.
- **PPT 단순 읽기 후보에 `presentation`이 포함되는 기존 기대값 불일치 3건은 남았습니다.** HEAD 기준본에서도 똑같이 재현됐으며 이번 Excel 변경에서 생긴 회귀가 아닙니다. 이 별도 라우팅 문제를 해결했다고 주장하지 않습니다.
- 별도 작업 폴더의 광역 검사에는 미커밋 비전 코드도 섞이므로 배포 증거로 사용하지 않았습니다. 배포 관련 판단은 분리된 소스의 시험과 위 재검증을 기준으로 했습니다.

## 실제 Excel 읽기 비교

하네스 CLI를 통해 동일 가상 자료를 `auto`와 강제 `xlwings`로 각각 처리했습니다. 실제 VBA는 실행하지 않았고 원본 SHA-256은 유지됐습니다.

| 자료 | 확인 결과 |
| --- | --- |
| 일반 XLSX | 5개 시트·7개 표·82개 수식, 두 경로의 셀 값과 계산 상태 일치 |
| 내장 VBA XLSM | 12개 시트·16개 표·6,798개 수식, 두 경로의 Python 계산값·상태 일치 |
| 제한된 수식 처리 | 계산 6,790개·미지원 4개·오류 4개를 분리. 모두 성공으로 바꾸지 않음 |
| VBA 접근 | 직접 읽기는 17개 모듈 추출. Excel 경로는 VBA 접근 거절을 표시하고 셀·수식 분석 계속 |
| 모델용 요약 | 일반 자료 9,030/9,050자, 복잡 자료 11,989/11,964자. 기본 12,000자 이내 |

`예외신청!E15`는 원본 OOXML의 `" c03 "`을 Excel이 `"c03"`으로 반환했습니다. 사용자가 허용한 앞뒤 공백 차이로 별도 기록했으며, 대소문자는 같았습니다. 원본 관찰 기록 자체를 임의로 대문자화하거나 두 원본 값을 같다고 덮어쓰지 않았습니다.

Python 예제의 자동 `upper()`를 제거해 `c03`과 `C03`을 다른 키로 처리했습니다. 원본 VBA의 `UCase`는 증거로 보존했습니다. 새 Python 결과는 승인 376건·182,230,628·수료 162건·확인 필요 9건이며, 원래 VBA와 의미가 달라졌음을 결과에 명시합니다. 변경된 규칙을 원본 매크로와 완전히 동등한 이전으로 보고하지 않습니다.

일반 파일은 Excel을 시작하지 않았습니다. 시험 당시 CLI 전체 시간은 일반 XLSX 직접 읽기 약 0.8초/Excel 약 28.8초, 복잡 XLSM 직접 읽기 약 15.2초/Excel 약 52.9초였습니다. 다른 회귀 시험과 병렬 실행한 로컬 관찰값이며 성능 보장이 아닙니다. 필요한 파일에만 Excel을 사용하는 이유를 확인한 시험입니다.

Excel은 읽기 전용·VBA/이벤트 비활성화·수동 계산·링크 갱신 미요청으로 열었습니다. 종료가 지연된 시험 인스턴스는 소유권을 확인한 프로세스 핸들만 정리했습니다. 불투명한 보호 파일의 시작 동작·외부 통신 전체를 격리하지 못하며 실제 사내 DRM 호환성은 별도 확인이 필요합니다.

- 통합 안내서: 6개 부분·52개 장·428,757바이트. 내장 Noto Sans KR, 1440/768/390px, 화면 45개·목차 링크 147개 검사. 깨진 글자·넘침·외부 요청·페이지 오류 없음.

- 최초 업데이트 시험은 너무 긴 임시 설치 경로에서 이전 1.4.41 설치가 실패했습니다. 짧은 일회성 시험 경로에서 동일 검사를 통과했으며, 모든 긴 설치 루트의 호환성을 보장하는 것은 아닙니다. 실사용 프로필은 변경하지 않았습니다.
