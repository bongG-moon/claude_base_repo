# 플랫폼 스킬 ZIP 관리

사용할 파일은 저장소의 `skills_zip/등록_설치_안내.html`에서 선택합니다. 각 스킬은 ZIP 하나입니다. 플랫폼에 ZIP 자체를 올리면 이름·설명·태그·설치 안내·업무 흐름을 읽습니다. 조직·분류·공개 범위는 게시자가 선택합니다. 생성만으로 게시되거나 설치되지는 않습니다.

## 다시 생성하기

저장소에서 실행합니다. Python 3.11 이상과 표준 라이브러리를 사용하며 별도 모델을 호출하지 않습니다.

```powershell
python -X utf8 -B scripts/build-skill-packages.py
python -X utf8 -B scripts/build-skill-packages.py --check
```

첫 명령은 현재 작업 파일(미커밋 수정 포함)을 패키징합니다. 두 번째는 ZIP을 다시 계산해 최신 여부만 확인합니다. 변경이 없으면 ZIP을 다시 쓰지 않습니다. ZIP 파일명은 `<스킬명>.zip`, 설치 이름은 `<스킬명>`이며 Company 접두어를 사용하지 않습니다. 기존 플랫폼 업데이트 연결을 위해 내부 `company.skills.<스킬명>` packageId는 유지합니다. 하네스 버전과 실제 플랫폼 게시 버전은 다릅니다.

플랫폼에서 기존 도구의 새 버전으로 등록할 때는 다른 packageId의 ZIP도 선택할 수 있습니다. 플랫폼의 숫자 도구 ID와 최초 정상 packageId는 고정되고 ZIP의 원본 식별자는 별도로 보관됩니다. 이 생성기는 각 스킬의 기존 packageId를 계속 사용하므로 이미 등록한 ZIP을 다시 수정할 필요는 없습니다. MCP·배포 Skill로 게시할 때는 사용자가 지정한 기존 도구 ID와 내용·공개 범위를 확인합니다. 최신 MCP는 명확한 게시 요청을 채팅에서 완료하며, 독립 CLI는 웹 검토 방식을 사용합니다. 이름이 비슷하거나 새 ZIP의 식별자가 다른 도구와 같다는 이유로 자동 덮어쓰지 않습니다.

## 최신 규격은 어디서 오나요?

플랫폼 개발 대화 `01a13d6c-3ce5-73c2-8e6a-857435867972`의 로컬 구현인 `pt_ai_square/static/guides/pt-file-distribution`가 기본 정본입니다. 실행할 때마다 그 폴더의 현재 규격 검사기와 설치 범위 선택 도우미를 사용합니다. 정본 전체의 파일별 해시도 ZIP에 남깁니다. 이전 산출물 폴더의 스크립트나 낡은 내장 사본을 대신 쓰지 않습니다.

정본이 다른 위치에 있으면 두 명령에 같은 옵션을 붙입니다.

```powershell
python -X utf8 -B scripts/build-skill-packages.py --distribution-skill "최신 pt-file-distribution 폴더의 절대경로"
```

플랫폼 소스가 없는 새 PC에서는 이 정본을 별도로 준비해야 합니다. 대화나 원격 저장소를 상시 감시하거나 자동 내려받는 기능은 아닙니다. 개발 지침(AGENTS.md)은 스킬 변경 완료 시 정본 확인·재생성·최신 여부 검사를 요구합니다. 규격이 바뀌어 검사에 실패하면 기존 ZIP을 그대로 두고 생성기를 새 규격에 맞춥니다.

## 무엇을 넣나요?

등록할 이름은 무엇을 하는 도구인지 짧게 적고, 소개는 동료가 넣을 자료와 얻을 결과를 쉬운 말로 설명합니다. 예를 들어 `AI 업무 기록 정리`처럼 동작이 드러나게 쓰고, 슬로건을 덧붙이지 않습니다. 검색 태그에는 실제 사용하는 업무 표현을 넣습니다. 기술 용어·설치 조건·수집 범위는 상세 안내에 남겨 기능이나 제약을 감추지 않습니다. 작성 기준과 예시는 정본 배포 Skill의 **등록 설명과 설치 안내**를 따릅니다. 표시 이름을 고쳐도 packageId와 설치 폴더 이름은 바꾸지 않습니다.

새로 작성하는 제목, 소개와 안내에서 나열용 가운데점을 쓰지 않습니다. `글자와 도형, 표, 차트`처럼 쉼표나 연결 표현으로 쓰며, 코드와 식별자 및 공식 고유명은 유지합니다.

- 하네스 `skills/*/SKILL.md`를 기준으로 목록을 자동 발견합니다. 각 항목은 `portable` 또는 이유가 있는 `harness-only`로 분류합니다. 새 항목을 조용히 누락하지 않습니다.
- 개별 업무 스킬은 `standalone-skills`의 독립형 지침·코드·참고자료를 사용합니다. Company 세션·CLI·후크·작업자 없이 사용할 수 있습니다. 원래 하네스용 스킬은 그대로 유지합니다.
- HTML/PPT는 같은 제작 엔진의 순수 모듈을 `packaging.runtimeModules`로 지정하여 ZIP에 함께 담습니다. 원본 엔진을 두 벌로 수정하지 않으며 빌드 시 정확한 원본 바이트를 포함합니다. 런처·정책·세션·후크 모듈은 포함하지 않습니다.
- `company-agent`, `project-harness`, `self-learning`은 하네스 설치 기능으로 남깁니다. `platform-mcp-builder`는 asset-factory의 이전 이름이므로 중복 ZIP을 만들지 않습니다. 제외 사유는 catalog의 `harnessOnly`와 HTML에서 확인합니다.
- 개인 기억·지식의 독립판은 요청에 따라 범위를 선택한 Markdown 파일을 저장·조회합니다. 하네스의 자동 학습·적용·이력 저장소와 같은 기능이라고 설명하지 않습니다.
- 루트 SKILL.md는 실제 지침으로 연결하는 짧은 진입점이며 상대 경로는 보존합니다. 이미 하네스로 쓰는 기능은 중복 설치하지 않아도 됩니다.
- 개인 기억·세션·인증 설정·캐시는 넣지 않습니다. 설정 변경이나 의존성 자동 설치도 하지 않습니다.

## 스킬을 바꿀 때

`scripts/platform_skills/catalog-metadata.json`의 설명·필요 환경·업무 흐름을 함께 확인합니다. 이는 게시용 설명이며 기능을 자동 추측하지 않습니다. 새 스킬은 이 파일에 설명을 추가하지 않으면 생성기가 누락으로 중단합니다. 하네스 지침을 바꿀 때는 대응하는 독립판도 검토합니다. 실행 엔진 변경은 모듈 목록을 통해 자동 반영되지만 업무 지침의 의미는 기계적으로 변환하지 않습니다. 독립판에 없는 하네스용 참조를 묵시적으로 섞지 않습니다. 필요한 추가 참고자료는 `includeAdditionalPaths`에 지정합니다.

각 ZIP 안의 `PACKAGE_SOURCE.json`은 원본 경로·해시·배포 규격을, `PACKAGE_CONTENTS.json`은 전체 파일 해시를 기록합니다. `catalog.json`과 `SHA256SUMS.txt`는 목록과 ZIP 무결성을 확인하는 기계용 파일입니다. 일반 사용자는 HTML과 ZIP만 보면 됩니다.

하네스에서 분리한 지침은 `packaging.reviewedPluginDigest`에 마지막으로 비교한 원본 폴더의 해시를 기록합니다. 원본 스킬·참고자료가 바뀌면 빌드는 독립판 검토 필요를 알립니다. 독립판에 필요한 변경을 반영하고 실제 비교 후 생성기의 `plugin_digest(snapshot(root), slug)` 값으로 갱신합니다. 해시만 바꿔 의미 검토를 대신하지 않습니다. 이는 개발자의 배포 시 검사이며 일반 사용자 요청에 후크·질문·모델 호출을 추가하지 않습니다.

진입 문서는 요청 분기, 실제 명령과 완료 조건을 먼저 보여줍니다. 저장, 복원, 추가 디자인 같은 선택 절차는 해당 상황에서만 참고자료를 읽습니다. 수정 요청에 전체 선택과 검증을 다시 시작하거나 모든 참조를 한꺼번에 읽도록 만들지 않습니다. 설명의 입력 형식을 주된 제작 기능처럼 나열하면 다른 스킬의 검색 후보로 잡힐 수 있으므로, 목록 설명은 주된 결과물과 사용 조건을 기준으로 작성합니다. 변경 뒤에는 실제 목록의 요청별 선택과 문서 속 명령을 검사하며, 문서 길이 감소를 실제 모델 토큰이나 처리 시간의 측정값으로 표시하지 않습니다.

생성 결과를 직접 편집하지 마세요. 직접 변경한 파일은 덮어쓰지 않고 중단합니다. 제거·이름 변경된 관리 ZIP은 `.previous` 아래로 옮겨 로컬에 보관하며 배포·커밋 목록에서 제외합니다. 무관한 파일은 건드리지 않습니다. 설치기는 같은 설치 폴더를 덮어쓰지 않으며 같은 범위에 기존 `square-company-*`가 있으면 중복 생성 없이 이동 안내를 합니다. 개인 수정분을 검토·백업한 뒤 기존 폴더를 스킬 검색 경로 밖으로 옮겨 설치합니다. 자동 이전이나 삭제는 하지 않습니다.

## 다른 프로젝트의 MCP 함께 배포하기

`skills_zip`에는 개별 스킬 12개와 별도 도구인 **제조 메타데이터 Oracle MCP**가 있습니다. HTML의 **별도 MCP**에서 선택합니다. MCP는 하네스에 내장되거나 Skill로 자동 등록되지 않습니다. ZIP 전체를 풀고 README.md의 설치 범위·MongoDB/Oracle 접속 설정 안내를 따릅니다. asset-factory는 MCP 제작 스킬이며 자체 MCP 서버가 아닙니다. Outlook 스킬도 메일 MCP 서버를 배포하지 않습니다.

이 MCP의 정본은 `metadata_driven_v5` 프로젝트이며, 여기서는 검토된 ZIP을 바이트 그대로 보관합니다. `scripts/platform_skills/external-packages.json`에 원본 프로젝트·산출물·대화·packageId·SHA-256을 기록했습니다. 생성기는 등록된 ZIP의 해시와 최신 플랫폼 규격을 검사하고 목록·설치 안내·체크섬에 포함합니다. 원본 프로젝트를 자동 탐색하거나 수정하지 않습니다.

MCP를 갱신할 때는 정본 프로젝트에서 검증한 새 ZIP을 `skills_zip`에 넣고 위 등록 파일의 파일명·해시·출처를 함께 바꾼 뒤 생성·검사를 실행합니다. 새 PC에서도 이 저장소의 ZIP만으로 목록을 재생성할 수 있습니다. 파일이 없거나 임의로 수정되면 조용히 제외하지 않고 중단합니다. 이전 관리 ZIP은 기존 `.previous` 보관 규칙을 따릅니다. ZIP 내부의 설치기는 스킬용 설치기와 다르며 접속 설정을 재설치 시 유지합니다.

## 검증 명령

```powershell
python -X utf8 -B -m unittest discover -s tests -p "test_platform_skill_*.py" -v
python -X utf8 -B -m unittest discover -s tests -p "test_portable_*skills.py" -v
```

패키지 규격·정규화 원본 바이트·참조·해시·최신 여부, 격리 프로젝트 설치, 합성 엑셀 처리와 업무 맥락 보고서를 확인합니다. 실제 회사 Outlook/MCP·보호 파일·모델 호출은 별도 운영 검증 대상입니다. 새 스킬의 업무 의미·업무 흐름이 정확한지는 소스 변경자도 함께 검토해야 합니다.

2026-10-25 독립판 분리 검증: 패키지 34개, 설치기 28개, 외부 MCP 5개, 독립 업무·HTML/PPT 23개로 총 90개 테스트가 통과했습니다. 빈 사용자 프로필과 저장소 밖 임시 복사본에서 생성·읽기·파일 이동/복구를 실행했습니다. PPT는 네이티브 글자 서식·표·차트·그룹 및 그룹 해제 후 좌표를 XML로 확인했으며 실제 Office 화면을 검증한 것은 아닙니다. HTML/PPT 시험은 선언된 python-pptx가 격리 Python에서 보이는 환경으로 실행해야 합니다. 의존성이 없는 환경의 건너뛴 검사를 통과로 세지 않습니다. 외부 MCP는 더미 설정의 로컬 통신만 시험했고 원본 ZIP 해시는 유지했습니다.

## 줄바꿈과 배포 재현성

배포 생성기는 명시한 UTF-8 텍스트의 CRLF만 LF로 정규화합니다. 원본 파일·BOM·공백·바이너리는 바꾸지 않습니다. `PACKAGE_SOURCE.json`과 규격 메타데이터의 `textNormalization`에 기준을 표시하므로 Windows Git 체크아웃에서도 같은 ZIP을 재생성할 수 있습니다. 원본 해시 비교는 이 정규화 후의 바이트 기준입니다. 외부 MCP ZIP은 원래 바이트를 유지합니다.
