# 스킬 자동 선택 연결 보완 — 2026-09-16

## 적용 범위

1.4.10 설치본에 포함하는 수정입니다. 이미 설치된 PC는 새 설치본에서 기존과 같은 범위를 선택하여 업데이트해야 합니다. 이전 1.4.9 압축파일을 같은 이름으로 덮어쓰지 않습니다. [설치 안내](UPDATE_1.4.10.md)를 참고하세요.

개인 Memory·Knowledge·Skill·우선 설정, 기존 모델 별칭과 MCP 연결은 변경하지 않았습니다. 새 스킬을 추가하지 않았습니다. `locked by plugin`을 해제하거나 Claude의 권한 설정을 넓히는 변경도 없습니다.

## 바뀐 동작

- 질문을 받으면 관련 후보의 이름·용도·호출 방법을 짧은 한국어 안내로 먼저 전달합니다. 긴 모델 등급·학습·실행 경로 정보는 뒤에 옵니다.
- 요청 확인 → 스킬 선택/중복 해소 → 본문 로드 → 필요한 작업자 위임 → 실행 순서로 통일했습니다.
- 등록된 고유 호출명은 Skill 도구로 불러옵니다. 같은 호출명으로 개인/프로젝트 파일이 겹치거나 개인 상태에만 있는 파일은 정확한 경로를 Read로 읽습니다. 후보의 `load`는 호출 안내이지 실제 호스트 등록이나 권한의 보장이 아닙니다.
- 사용자 명시 선택과 기존 우선 설정을 존중합니다. 겹치는 후보를 임의로 하나로 줄이지 않습니다. 읽기와 제작 같은 서로 다른 단계는 중복으로 보지 않습니다.
- 후보 검색 실패를 스킬 부재로 표현하지 않습니다. 전체 인덱스와 필요한 페이지를 확인할 수 있습니다. 본문 전체를 시작할 때 모두 넣지는 않습니다.
- 작업자에게 부모의 선택 파일을 전달하고 작업자도 자기 대화에서 본문을 읽습니다. 부모의 로드 기록으로 자식의 로드를 대신하지 않습니다.
- 안내는 실행 차단/승인 허용이 아닙니다. 반복적인 준비 경고나 Stop 검증 오류를 새로 만들지 않습니다. 기존 DB·메일·도구 권한 제한은 유지합니다.
- HTML 선택만 요청하면서 명령/파일 생성을 금지한 경우에는 보조 명령과 선택 JSON 작성을 보류하고 질문만 합니다.

## 진단 정보

기존 세션 파일(`User State/sessions/<session-id>.json`)에 다음을 구분해 기록합니다. 새로운 원문 로그나 중앙 전송은 없습니다.

| 항목 | 의미 |
|---|---|
| `hookDiagnostics.SessionStart/UserPromptSubmit.status=started` | Python Hook 처리를 시작했지만 완료 기록은 아직 없음 |
| `status=output-produced` | Hook이 출력 정보를 만들었음. 호스트 수신 또는 모델 적용을 증명하지 않음 |
| `status=failed` | 준비 중 실패. 예외 종류만 기록하고 예외 메시지는 저장하지 않음 |
| `elapsedMs` | Python 진입점 처리 시간. PowerShell 실행/Python 시작/모델 응답을 포함한 전체 시간은 아님 |
| `candidateNames`, `catalogRevision`, `indexMode` | 이번 출력의 후보 이름·목록 버전·제공 방식 |
| `hostReceipt`, `modelApplied` | `not-observable`. Hook 혼자 호스트 전달/모델 적용 성공을 주장하지 않음 |
| `skillWorkflow.lastBodyLoad` | 성공한 Read/Skill에서 관찰한 이름·해시·도구·턴 |

`indexDelivery`/`indexDelivered`는 기존 호환 필드입니다. `evidence=output-produced-not-host-acknowledged`로 의미를 명시했습니다. 모델이 목록을 읽고 이해했다는 보증으로 사용하지 않습니다.

진단은 시작/질문 이벤트의 최신 기록만 유지합니다. 사용자 질문 원문, 문서 내용, 스킬 본문, 예외 메시지, 인증 정보는 추가하지 않습니다. 진단 저장 실패는 업무나 권한 검사를 막지 않습니다. 운영자가 원인을 확인할 때 등록된 실행 명령 뒤에 `session status --session <현재 세션 ID>`를 붙이거나 해당 로컬 세션 파일을 확인할 수 있습니다. 정상 사용 중에는 이러한 기록을 사용자에게 중계하지 않습니다.

## 검증을 구분하는 기준

### 자동화 테스트

고유 호출명, 개인/프로젝트 충돌, 우선 설정, 수동 전용 스킬, 큰 후보 묶음의 잘림 방지, 안내와 본문 로드 기록 구분, 진단의 개인정보 미저장, 반복 차단 방지를 확인합니다. 기존 설치/메모리/학습/정책 회귀 테스트도 함께 실행합니다.

### 실제 Claude CLI 전달·본문 로드 검사

```powershell
python -X utf8 -B scripts/test-lab/probe-skill-transport.py --claude "<현재 Claude 실행 파일 경로>"
```

이 검사는 별도의 임시 설정·작업 폴더·개인 상태와 localhost 응답 서버를 사용합니다. 실제 CLI가 스킬을 등록하는지, 업무별 안내를 모델 요청에 넣는지, Skill 호출로 본문을 읽은 뒤 다음 요청에 포함하는지 확인합니다. 실제 문서·Office·MCP·사내 모델·외부 API를 호출하지 않습니다. 모델 이름을 HCP로 지정하더라도 응답은 정해진 로컬 테스트 응답이므로 **사내 모델의 자동 선택 성공을 검증한 것이 아닙니다.**

### 실제 모델의 선택 행동 검사

`scripts/test-lab/run-live-claude.py`의 `S03-natural-office-read`는 별도의 가상 PPT를 만들고 스킬 이름 없이 내용을 읽어 달라고 요청합니다. 기존 로그인으로 실제 모델을 사용하며 소량의 사용량이 발생합니다. 기존 설치나 설정을 변경하지 않습니다. 테스트 실행 권한은 제한되어 있으므로 문서 읽기 명령이 승인 불가로 끝날 수 있습니다. 이 경우 선택 성공과 문서 분석 성공을 구분합니다.

2026-09-16 로컬 Claude Code 2.1.272 / `claude-sonnet-5`에서 관찰:

- S01(없는 가상 PPT): Glob으로 파일 부재만 확인. 스킬 로드 성공 사례로 집계하지 않음.
- S03(존재하는 가상 PPT, 스킬 언급 없음): `Skill(company-agent:office-reader)` → Glob → 정해진 `business office-read` 명령. 임의 ZIP/Python 파서로 시작하지 않음. 읽기 명령은 제한된 테스트 권한에서 거절되어 Office 본문 추출 완료는 미검증.
- T12(HTML 선택만, 명령/저장 금지): 최초 검사에서 HTML 스킬은 선택했지만 보조 명령을 시도하여 보완. 결과 재검증은 아래 최종 기록 참고.

사내 HCP 모델·DRM·Office 자동화의 실제 결과는 이 로컬 검증으로 대체하지 않습니다. 스킬 사용이 반드시 보장되는 실행 강제/샌드박스가 아니라 안내·호출·진단의 개선입니다.

## 최종 검증 기록

- 전체 Python 테스트: 696개 통과, 실패/제외 없음 (`COMPANY_AGENT_TEST_REAL_CLAUDE=1`). 기존 실 CLI MCP 등록 테스트도 격리 설정에서 실행했습니다. 실제 DB·메일 연결 테스트는 아닙니다.
- 실제 CLI + localhost 정해진 응답 검사: 등록, 안내 순서, 후보 전달, 본문 로드, 다음 요청의 본문 포함, 로드 기록, 업무 변경 없음 확인.
- 실제 모델 S03: 스킬 이름 없는 요청에서 첫 도구가 `Skill(company-agent:office-reader)`. 약 22초 내에 지정 실행 경로에 도달했으나 테스트 권한에서 거절됐으므로 문서 분석 완료로 집계하지 않음.
- 실제 모델 T12: 초기 보조 명령 실행 시도 및 이후 의미 없는 `echo noop`도 발견하여 안내 보완. 마지막 재검증에서는 도구 호출이 `Skill(company-agent:html-report)` 한 번뿐이었으며, 파일 쓰기/Bash/승인 거절 없이 디자인 선택을 묻고 종료(약 17초). 이는 한 번의 실제 모델 관찰이며 모든 모델/요청에 대한 보장은 아님.
- 실제 모델 검사 모두 기존 Claude 설정·플러그인 등록 파일의 전후 해시 동일.
- Claude `plugin validate --strict` 통과. Codex용 일반 Skill 검사에서는 기존 `company-agent-role` 확장 필드를 허용하지 않아 공통 스킬에 경고가 남음. 해당 필드는 하네스의 지원 스킬 구분에 사용하므로 삭제하지 않았으며, 실제 Claude 등록/본문 로드로 별도 검증. HTML 스킬의 일반 검사 통과.
- 소스와 설치본은 1.4.10으로 배포합니다. 실사용 PC에 자동 재설치하지 않으므로 새 설치본으로 업데이트해야 합니다.
