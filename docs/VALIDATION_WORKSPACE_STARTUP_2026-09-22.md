# Workspace 0.9 시작 오류 수정 검증

## 범위

일반 더블클릭 후 관리자 권한 경고와 Python 관련 경고가 연이어 표시된 문제를 대상으로 한다. 기존 실행기는 관리자 그룹 여부만 보고 즉시 중단했고, VBS가 모든 실패를 Python·정책 문제로 다시 표시했다. 사용자가 의도적으로 관리자 실행을 했다는 증거는 없으며, 해당 PC의 UAC·부모 프로세스 상태까지 확인한 것은 아니다.

Company Agent 코어는 1.4.25로 유지한다. 이번 변경은 Workspace 0.9 로컬 시험 버전이며 GitHub Release에 자동 게시하지 않는다.

## 동작 변경

- 현재 Windows 계정, 정확한 로그인 세션, 프로필 경로를 읽기 전용으로 확인한다. 다른 사용자, SYSTEM, 서비스 세션, 확인 불가능한 환경은 중단한다.
- 일반 실행 경로에서도 실제 프로세스 토큰의 사용자·세션·기본 토큰 여부·상승 여부·무결성 수준·관리자 권한을 확인한다. 관리자 그룹이 아니더라도 높은 무결성 토큰은 허용하지 않는다.
- 관리자 실행이면 현재 프로세스에 연결된 같은 사용자의 UAC 제한 토큰만 검토한다. 복제한 기본 토큰과 정지 상태 자식 프로세스도 검증한 후 한 번 실행한다. 다른 프로세스 토큰, 다른 계정, 자격증명, 권한 활성화로 대체하지 않는다.
- 자식은 실패 코드를 반환하고 최초 실행기만 한국어 안내를 표시한다. 이미 안내한 코드 20에는 VBS가 두 번째 창을 띄우지 않는다.
- Python 확인이 실제로 실패했을 때만 Python 문제로 안내한다. 시작 확인 시간 초과는 성공으로 처리하지 않으며, 실행 중인 프로세스를 강제로 종료하거나 자동 재시도하지 않는다.
- 기존 Claude 실행 경로·프로필·모델·인증·설정 환경은 상속한다. 인증값을 상태 파일에 복사하거나 설정을 초기화하지 않는다. 환경 전달은 메모리 안에서 수행한다.
- 계정·권한 확인은 서버·CLI·상태 폴더·뮤텍스 생성보다 먼저 수행한다. 모델 호출이나 PC 전체 검색을 추가하지 않는다.

## 시험 방법

가상 CLI, 체험 모드, 테스트 전용 임시 상태 폴더를 사용한다. 실제 모델 요청·로그인 변경·UAC 변경·관리자 권한 요청은 하지 않는다. Windows 로그인 사용자와 다른 샌드박스 계정은 의도대로 거부되므로 실행 통합 시험은 실제 로그인 사용자 환경에서 수행한다.

관련 시험:

```text
python -X utf8 -B -m unittest tests.test_workspace_startup tests.test_workspace_normal_token tests.test_local_workspace tests.test_workspace_close tests.test_workspace_companion tests.test_workspace_history tests.test_html_workspace_preview -q
```

확인 항목은 표준/제한 토큰 허용, 잘못된 계정·세션·권한 거부, 무한 재실행 방지, 한글·공백·특수문자 경로 전달, 오류 분류·중복 안내 방지, 기존 연결·설정 유지, 창 재사용, 다른 버전 실행 중 보호, 종료·기록·미리보기 회귀다. PowerShell 5.1에서 실제 C# 컴파일과 읽기 전용 토큰 확인도 시험한다.

## 미검증 범위와 운영 한계

- 현재 시험 프로세스는 일반 권한이다. **실제 관리자 토큰에서 제한 토큰으로 전환하는 운영 시험은 수행하지 않았다.** 해당 분기는 토큰 조건·인수 전달·실패 처리의 자동 시험 및 코드 검토로 확인했다.
- VBS는 실제 스크립트 호스트에서 실행하되 테스트 사본의 모달 표시만 유니코드 표준 출력으로 대체한다. 한국어 메시지·종료 코드·중복 안내 여부는 검증하지만 사용자가 보는 실제 모달의 육안 검증과 운영 PC 더블클릭 성공까지 포함하지 않는다. 테스트 호스트의 `WScript.Echo`/유니코드 출력 조합 문제는 `StdOut.WriteLine`으로 시험 관찰 방법을 바로잡았으며, 보안 정책이나 실제 실행기 동작을 우회한 것이 아니다.
- UAC가 꺼져 있거나 연결된 제한 토큰이 없으면 일반 권한을 만들어내지 않는다. 회사 정책이 Windows API·PowerShell·VBS·컴파일을 차단해도 정책을 바꾸거나 우회하지 않는다.
- 사내 보안 프로그램, HCP 연결, 회사 PC의 정상 더블클릭 동작은 새 시험 묶음으로 확인해야 한다. 문제가 계속되면 한국어 안내의 `WS-숫자` 코드를 확인한다.
- 수동 개발자 실행이나 Windows 전체를 격리하는 보안 제품이 아니라 이 실행기의 시작 절차를 보완한 것이다.
