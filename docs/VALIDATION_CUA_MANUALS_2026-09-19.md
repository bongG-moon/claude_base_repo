# Cua 준비 확인과 사용자 매뉴얼 검증 — 2026-09-19

## 구현 범위

- Workspace에 선택 기능인 **화면 조작 시험**을 추가했다. 명시한 로컬 Driver 경로 또는 제한된 PATH와, 현재 실행 중인 CLI가 보고한 MCP/도구 목록만 검사한다.
- 파일 존재, 연결 보고, 필요한 도구 노출, 실제 조작 성공을 서로 다른 증거로 취급한다. 끊긴 연결과 과거 대화 보고만으로 시험 버튼을 활성화하지 않는다.
- 같은 MCP 이름의 도구만 비교하고, 여러 후보는 사용자가 선택한다. 없는 도구를 실행하거나 설치하지 않는다.
- 시험 예문 버튼은 입력창만 채운다. 관찰 시험과 입력 시험을 분리하고, 입력 시험은 대상과 계획에 대한 사용자 답변을 요구한다. 예문의 호출 횟수는 강제 제한이 아닌 모델 지침이다.
- 사용자 핸드북, 처음부터 따라 하기, Cua 시험 안내를 Markdown과 오프라인 HTML로 만들었다. 실제 기본 스킬 12개, 후크 7개, 명령 3개, 작업자 3개와 대조한다.
- 앱 링크, 고정 문서 경로, 직원용/Workspace 묶음 빌드에 연결했다. 핵심 후크·모델·인증·개인 저장소·MCP 등록 설정은 바꾸지 않았다.

브라우저는 실제 로컬 앱/API를 사용했고, Claude 실행만 합성 CLI로 대체했다. Cua의 준비 완료 화면은 합성 도구 보고를 사용했다. 실제 Cua MCP나 업무 프로그램을 조작한 시험으로 해석하면 안 된다. 테스트용 기억·지식·설정은 별도 임시 폴더에 두었다.

## 속도와 호출 범위

실제 개발 PC의 상속된 PATH에서 `readiness()`만 20회 측정했다. Driver 미발견/CLI 연결 보고 없음 조건에서 중앙값 **31.02ms**, 최대 **35.69ms**였다. HTTP 왕복·CLI 시작·MCP 연결·AI·회사 프로그램 조작 시간을 포함하지 않은 로컬 파일 확인 측정이다. 사내 성능 보장이나 토큰 절감률이 아니다.

준비 확인에는 추가 모델 호출, 새 CLI 프로세스, 화면 캡처, MCP 연결, 설치/설정 변경, 결과 디스크 저장이 없다. 탭을 열기만 했을 때는 Driver 경로도 조사하지 않는다. 사용자가 시험 예문을 직접 보내면 기존 Claude/HCP 실행과 사용량이 발생할 수 있다.

## 재검증 방법

- `python -X utf8 -B -m unittest discover -s tests`
- `node scripts/build-manuals.mjs --modules <준비된 node_modules 경로> --check`
- `scripts/test-lab/serve-workspace-fixture.py`로 격리된 시험 서버를 열고 `check-manuals-cua.mjs`, `check-workspace-companion.mjs`에 생성된 runtime 파일과 준비된 node_modules 경로를 지정한다. runtime 파일에는 로컬 인증 토큰이 있으므로 공유하지 않는다.
- `powershell.exe -NoProfile -File deploy/Test-OfflineBundle.ps1`
- 새 Workspace ZIP에 `python -X utf8 -B scripts/test-lab/check-workspace-bundle.py <ZIP 경로>`를 실행한다.

## 배포와 남은 확인

이번 개발 검증용 ZIP은 무시되는 `build/manual-cua-packages/` 아래에만 만들었다. Git 커밋·푸시·GitHub Release·기존 dist ZIP 갱신은 하지 않았다.

실제 Driver 버전/출처 검증, 회사 승인, MCP 등록, 사내 HCP의 이미지/도구 지원, 계산기 및 회사 프로그램 실제 조작, 중지/권한 경계는 별도 운영 시험이 필요하다. 준비 확인 통과를 이러한 시험의 성공으로 기록하지 않는다.

## 후속 검증: 온보딩 확장 실습

같은 날 온보딩에 6–8단계의 선택 실습을 추가했다. 팀이 공유하는 프로젝트 지침과 개인 기억, User/Project 설치와 폴더별 CLAUDE.md, 개인 스킬과 로컬 계산 도구를 비교한다. 별도 팀 메모리 서버·새 후크·자동 설치·모델 호출은 추가하지 않았다. 기본 5단계의 Workspace 진행 상태와 예문 구조도 유지했다.

- 관련 Python 시험 **82개 통과**: 실습 예제 5, 매뉴얼 계약 7, 개인 기억 11, 개인 자산 15, 프로젝트 하네스 17, Workspace 연동 27. 위 전체 938개 시험을 이번 확장 후 다시 실행한 것은 아니다.
- 실습 시험은 안내서에 포함된 프로젝트 지침·스킬 본문·계산 코드를 직접 읽어 임시 저장소에서 사용한다. 개인 기억 분리·비활성화, 스킬 발견·동명 파일 보존, 도구 candidate/검증 기록/활성화, 코드 변경 시 기록 무효화, 기존 CLAUDE.md와 다른 프로젝트 보존을 확인했다.
- 계산은 안내서의 정상·반올림·목표 0·빈 목록·길이 차이·음수·문자열·참/거짓·항목 누락과 추가 상한/길이/소수 입력까지 확인했다. 모델이 임의로 생성하는 모든 코드의 품질을 보장하는 시험은 아니다.
- Edge 1280/390px에서 기존 7개 예문 복사·수동 복사 대안, 설치된 안내서 연결, 확장 3개 장의 목차 이동, 선택 코드 예제 펼치기를 확인했다. 페이지 가로 넘침·스크립트 오류·외부 요청은 없었다. 좁은 화면의 표는 내부 좌우 스크롤을 사용한다.
- Markdown/HTML 및 설치 자원 복사본 일치 검사와 직원 ZIP 회귀 검사를 통과했다. 기존 Release나 사용자 설치는 갱신하지 않았다.

실제 HCP의 자연어 스킬 선택, Claude의 지침 로드, 두 직원 환경 간 비교, 개인 기억이 최종 문장에 반영되는지는 이 로컬 시험에서 실행하지 않았다. 안내서에는 저장·조회·로드·실행·결과를 구분해 사용자가 기록하도록 명시했다. 실제 개인 기억·스킬·회사 설정을 이 검증으로 만들거나 변경하지 않았다.
