## 검사 과정과 한계

- Git export의 텍스트 줄바꿈과 생성 HTML의 바이트가 달라 처음 안내서 `--check`가 실패했습니다. 선택 소스에서 같은 생성기로 다시 생성한 후 검사에 통과했고, 결과 해시는 이미 시각 검증한 원본 안내서와 정확히 같았습니다. 내용·레이아웃은 바꾸지 않았습니다.
- 샌드박스에서 기존 Workspace 실행 시험 3건이 `WS-31` 계정 경계로 중단됐습니다. 제품·테스트 코드를 수정하거나 권한 확인을 끄지 않고, 실제 로그인 사용자 환경에서 동일 `test_local_workspace.py` 전체 49건을 다시 실행해 48건 통과·심볼릭 링크 권한에 따른 생략 1건을 확인했습니다. 최종 집계에서는 재실행을 중복 합산하지 않습니다.
- 첫 번째 그룹의 검사 실행기가 임시 폴더를 저장소 안의 긴 경로에 만들어 일부 경로 길이·프로젝트 범위 시험이 실패했고, 외부 검사 실행기의 import 경로 누락도 있었습니다. 실행기만 표준 `python -m unittest`와 같은 검색 경로 및 저장소 밖의 짧은 OS 임시 폴더로 맞추고 42개 파일 전체를 재실행해 통과했습니다. 제품·테스트 코드는 바꾸지 않았습니다. 실제 저장소의 `.claude`·`.mcp.json`·`.claude.json`을 만들지 않았음을 확인했습니다.
- 실제 사내 HCP의 지시 준수·품질·시간·토큰 효과, DRM/Office·전사 API·Chrome 인증 흐름·비전 게이트웨이는 미검증입니다. 별도 Workspace의 WS-33 제한 해결을 포함한 배포가 아닙니다.
- 개인 MCP 실행 묶음은 검증한 버전을 고정하는 장치이지 OS 샌드박스나 비밀값 제거기가 아닙니다. 기존 직접 소스 등록의 자동 이전·권한 자동 확대는 하지 않습니다.
- 학습은 근거 있는 교정/검증 절차에 조건부로 실행합니다. 새 후크·별도 학습 모델·학습용 Stop 재개 루프를 추가하지 않았고 `hostReceipt/modelApplied=not-observable`의 한계는 유지합니다.
