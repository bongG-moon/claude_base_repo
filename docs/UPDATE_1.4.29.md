# 1.4.29 변경·설치 안내

## 달라진 점

- 작업 종료 뒤 완료 확인 안내가 이어질 때, 확인 대상과 현재 대화의 정확한 실행 명령을 모델에 전달합니다. 짧은 안내 문구로 필요한 정보를 지우지 않으며, 내부 기록을 위해 설정 파일·환경변수·후크·다른 세션을 다시 찾지 않도록 했습니다.
- 단순 파일 읽기·경로 조회를 검증 진전으로 보지 않습니다. 관련 수정이나 검증 상태 변화가 없으면 같은 보정을 이어 가지 않고, 실제 결과와 미확인 범위를 남깁니다. 필요한 검사를 생략하거나 검사하지 않은 결과를 자동 성공 처리하지 않습니다.
- 검사 실패와 완료 확인 기록 누락을 구분합니다. 이미 검사한 최신 결과는 기록만 보완하고, 기록 때문에 결과물을 다시 만들거나 발송·이동 같은 업무를 반복하지 않습니다. 실제 검사 실패는 가능한 현재 흐름에서 최소 수정·재검사를 우선하며 별도 작업자를 매번 새로 호출하지 않습니다.
- 검증 실패·확인 불가·보정 종료 뒤 학습 검토를 연달아 붙이지 않습니다. 학습 후보와 미확인 변경은 보존하고, 진행 조건이 갖춰지지 않은 학습은 보류합니다. 자동 학습을 끄거나 개인 기억을 삭제하는 변경은 아닙니다.
- CLI에서 `partial`·`unavailable` 상태를 정상적으로 기록할 수 있게 했습니다. 일부만 확인했거나 권한·기능 제약으로 확인하지 못한 상태를 `pass`로 바꿀 필요가 없습니다.
- 완료 확인 지침과 단독 사용자 안내서·설치용 Markdown을 같은 내용으로 갱신했습니다. 새 스킬·후크·추가 분류 모델이나 외부 서비스를 도입하지 않습니다.

## 설치·업데이트

1. `company-agent-1.4.29-2026.09.03.zip`을 새 폴더에 풉니다. 뒤의 날짜는 회사 지식팩 버전입니다.
2. 기존 설치와 같은 범위에서 백업 후 업데이트하고 Claude Code를 다시 시작합니다. 개인 기억·스킬·지식·모델·별도 MCP 설정을 보존합니다.
3. 선택형 Workspace 묶음은 실행 코드 **0.9**를 유지하고 최신 사용자 안내서를 포함합니다. 하네스와 별도 ZIP이며, 기존 창을 닫은 뒤 새 폴더에서 실행하세요. 별도 개발 중인 Workspace 변경은 이번 배포에 포함하지 않습니다.

기존 태그와 설치 ZIP을 덮어쓰지 않습니다. 승인된 Python 3.11 이상과 Claude Code가 필요하며 외부 실행 파일은 내려받거나 동봉하지 않습니다. 이미 설치된 PC는 자동 갱신되지 않습니다.

## 확인 범위와 한계

회귀 검사에서는 종료 보정, 무관한 조회, 실패·부분 확인·확인 불가, 학습 보류와 기존 검증 의무 보존을 구분합니다. 실제 검사 실패를 숨기거나 권한 제한을 우회하는 변경은 아닙니다.

Claude Code 버전에 따라 필요한 완료 확인 안내가 여전히 `Stop hook error`로 표시될 수 있습니다. 이번 변경은 표시를 숨겨 통과시키는 대신 불필요한 반복과 탐색을 줄이는 것입니다. 해당 표시만으로 결과물 실패나 후크 고장이라고 단정하지 않습니다.

실제 사내 HCP에서의 전체 업무 시간·토큰 절감률과 약한 모델의 지침 준수는 미검증입니다. 회사 PC의 WS-33, 비전 모델·게이트웨이 설정은 이번 변경으로 해결하지 않았습니다.

최종 검사 결과와 배포 파일 해시는 [1.4.29 배포 검증](VALIDATION_RELEASE_1.4.29.md)에 기록합니다. 이전 버전 기록은 보존합니다.
