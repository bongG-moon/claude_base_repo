## 추가로 찾아 개선한 부분

### 1. 개인 MCP의 후보 수정이 활성 연결에 바로 적용되는 문제

기존 연결이 편집 가능한 `server.py`를 직접 가리켜, `asset create`로 후보를 수정하면 재시험·재활성화 전에 기존 연결이 새 코드를 실행할 수 있었다. 실제 로컬 stdio MCP 호출로 확인한 실행 경계 결함이다.

검증·활성화한 실행본과 편집 중인 소스를 분리했다. 기존 `test-mcp` 한 번이 실제 배포될 `.pyz` 실행 묶음을 검사하고, 서명 영수증의 묶음 해시와 같은 바이트만 활성화한다. 새로운 모델, 매 실행 시 검사 후크, 시작할 때마다 소스를 복사하는 절차는 추가하지 않았다. 명시적인 시험/활성화 경로 안에서 처리하며, 활성본 변경 후에는 연결을 다시 시작해야 한다. 구형 원본 소스용 영수증은 재시험, 직접 소스 경로 연결은 해당 연결의 재등록이 필요하다. 임의 파일·인증 자료를 통째로 복사하지 않는다.

후보 변경 전후 실제 합성 MCP 호출에서 기존 활성본 결과 `7`을 유지하고, 새 시험·활성화 후에만 `14`로 바뀌었다. 메타데이터 3곳의 쓰기 실패와 최종 실행본 교체 실패를 각각 주입했을 때도 기존 실행본이 보존되고 이전 메타데이터가 복원됐다. 검증 후 소스가 바뀌는 경합·구형 직접 등록 상태의 편집·예상 밖 `.env` 포함도 회귀 시험했다.

이 보호는 후보 편집이 활성 코드로 새는 것을 막는 장치다. OS 샌드박스, Python 의존성 고정, 같은 계정의 악의적 파일 변경 방지, 소스에 직접 넣은 비밀값의 자동 정제를 보장하지 않는다. 정해진 시험 사례 밖의 모든 업무 분기까지 검증한 것도 아니다.

### 2. 학습 안내의 오래된 절차

상위 스킬의 `staging`/업무 종료 중심 표현을 현재 `self-learning`의 `learning submit` 한 번과 일치시켰다. 지속적인 명시 교정은 작업 중에도 제출 가능하며, 반복 선택·절차 개선은 해당 근거와 검증이 필요하다. 조회·이번만의 선택·대기·압축에는 빈 학습을 만들지 않는다. 새 상태 조회나 종료 후 반복 작업은 추가하지 않았다.

### 3. HTML 장식과 모바일 배치 충돌

짧은 표지를 줄일 때 입체/레트로 장식이 다음 구역을 침범하는 경우를 수정했다. 짧은 스크롤에서는 장식만 숨기고 내용은 유지한다. 기존 입체 슬라이드의 모바일 CSS 우선순위 문제도 수정해 작은 화면에서는 장식이 본문 흐름 안에 배치되도록 했다. 표준 길이·슬라이드·사용자 HTML 양식에는 짧은 스크롤 전용 축약 규칙을 적용하지 않는다.

실제 `create_html` 40개와 Chrome 화면 180건(10양식 × 4변형 × 3폭, 슬라이드 앞/뒤 이동 포함)을 확인했다. 화면 폭 1440/768/390에서 겹침·본문 누락·가로 페이지 넘침·JavaScript 오류·페이지 외부 요청 없이 통과했다.

## DOTS 미검증 영역의 직접 시험

### 기억·학습

신규 9개 통합 시험에서 실제 native CLI/Hook 자식 프로세스 95회를 실행했다. 제품 기억/학습 함수를 mock으로 대체하지 않았으며 모델의 Read·verify 관찰 이벤트만 합성 입력했다.

- 개인 전체/프로젝트 저장·조회, 범위 미지정/회사 공통 쓰기 거절, 원본 보존.
- 같은 내용 재저장, 조건부 수정, 오래된 해시 수정 거절, 비활성화, 이력, 복원.
- 새 세션과 다른 프로젝트의 조회 범위, 충돌 후보의 범위·출처 유지, 일회성 요청의 자동 저장 없음.
- 명시 교정의 한 번 적용, 중복 제출 미적용, 일시 중지·재개, 지정 학습 되돌리기.
- 독립 업무의 반복 선택과 같은 업무의 여러 턴을 구분.
- 실제 읽은 개인 스킬 버전·실패 후 성공·검증 근거가 부족하면 보류, 수동 수정 보존, 학습 체크리스트 복원.

9개 Stop 응답은 모두 빈 객체였고 학습을 이유로 업무를 이어가지 않았다. 외부 요청 시도 0, Claude 설정 생성 0이다. 기억을 후속 입력에 제공했다는 사실은 모델이 실제 사용했다는 증거와 구분한다.

### 개인 스킬·도구 제작과 연결

추가 13개 시험에서 개인 스킬 생성·카탈로그 발견·현재 본문 로드·같은 문맥 재사용·새 프로세스 조회, 공통/개인 동명 후보, 도구 의존성 변경 감지를 확인했다. 도구는 기존 설치된 Python 3.13/MCP SDK 1.28.1로 실제 생성·시험·활성화하고, 격리 `CLAUDE_CONFIG_DIR`에 설치된 Claude CLI의 `mcp add-json`으로 등록했다. 실제 자식 프로세스의 initialize/tools-list/tools-call과 그 자식만 중단·재시작하는 경로도 시험했다.

스킬의 Read 관찰은 합성 호스트 이벤트이므로 실제 모델의 업무 수행 증거로 해석하지 않는다. 웹 스킬 제작 도우미는 합성 메타데이터로 계획 생성만 검증했으며 사이트 로그인·API 키 수집·브라우저 자동 조작은 수행하지 않았다.

### HTML 실제 생성·게시와 화면

합성 CSV 10행의 목표 1,200/실적 1,200/불량 32 및 월별 달성률을 기존 수치 엔진으로 16항목 검사했다. 실제 CLI의 `artifact-start → html → artifact-publish` 후 프로젝트에는 원본 CSV와 최종 HTML만 남고 원본 해시는 유지됐다.

3개 화면 폭에서 5개 구역과 모든 원본 행을 확인했다. A4 인쇄 PDF 3쪽을 실제 렌더링해 한글·표·겹침·잘림을 확인했다. 자료를 잘라 인쇄 한 장으로 맞추지는 않았다. DOTS 원본 HTML은 전달되지 않아 별도 미확인으로 남긴다.

## 무게·성능 판단

- 학습은 근거가 있을 때만 현재 모델의 한 번 제출이며, 별도 학습 모델·상시 작업자·Stop 회고 루프를 추가하지 않았다.
- 이미 읽은 동일 HTML 스킬은 후속 요청에서 재사용된다. compact 뒤 본문 부재나 호스트의 명시 호출 규칙은 별도다.
- 상태 구분은 기존 도구 결과와 짧은 공통 지침을 이용한다. 별도 상태 진단 호출이나 새 검증 파일을 강제하지 않는다.
- `company-agent` 본문은 기존 10,000자 상한을 유지한다. 상세 MCP 설명은 도구 제작 시에만 읽는 참고 문서에 둔다.
- 합성 HTML 3단계 CLI는 이번 측정에서 약 1.21초였다. 모델 생각·선택·승인 대기는 제외했으므로 DOTS의 325초 전체 업무가 1초로 개선되었다는 뜻이 아니다.
- 격리 프로세스의 평균은 CLI 381ms, UserPromptSubmit 603ms, Stop 240ms였다. 동시 검증 중 측정한 현재 PC 값으로, 사내 HCP·PowerShell 부트스트랩·대규모 저장소 성능은 별도다. 문자 수를 토큰 수로 바꾸어 비용 절감률을 주장하지 않는다.

## 아직 확인할 수 없는 범위

1. 사내 HCP 모델의 실제 지시 준수·답변 품질·토큰 사용량, 사내 승인 분류기와 대화형 승인 UI. 현재 회사 연결·실자료 없이 성공을 확정할 수 없다.
2. DOTS 원본 HTML/전사 실행 로그. 보고서만으로 오류 발생 당시의 파일·권한·세션 상태를 모두 복원할 수 없다.
3. Chrome/전사 API의 실제 인증·조회, 네트워크 MCP·회사 서버 배포. 이번 MCP 시험은 합성 로컬 함수다.
4. 모든 업무 자료 길이·회사 양식의 화면/인쇄 조합, 사용자 정의 도구의 모든 분기.
5. Workspace 별도 구현의 기존 계약 불일치. `test_html_workspace_preview` 2건, `test_handbook_contract` 2건은 기존 미커밋 Workspace 미리보기/독립 배포 변경과 예전 테스트 기대가 맞지 않는다. 이를 하네스 테스트 통과를 위해 되돌리거나 테스트를 약화하지 않았다. 따라서 저장소 전체가 녹색이라고 보고하지 않는다.
