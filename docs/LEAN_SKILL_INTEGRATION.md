## 무엇이 달라지나요?

별도 사용 명령은 늘리지 않았습니다. 기존 공통 Skill 11개를 유지하면서 필요한
지침만 보완했습니다. 회사 지식 플러그인과 다른 개인/외부 Skill은 이 개수 밖입니다.

## 스킬 수와 컨텍스트 관리

스킬 개수만으로 성능 저하 여부를 판단할 수 없습니다. 항상 읽는 설명의 크기,
유사한 실행 조건, 상충되는 지시, 불필요한 도구 호출을 함께 관리해야 합니다.

- 새 Skill 이름, 외부 플러그인, MCP, Hook, 실행 의존성은 추가하지 않았습니다.
- 기존 Skill 설명(description)은 변경하지 않았습니다. 검색 대상 메타데이터가
  늘어나지는 않지만, 선택된 본문/참고 문서를 읽을 때는 컨텍스트 비용이 듭니다.
- 작성·용어 관리·오류 진단 참고 문서는 해당 업무에서만 읽습니다. 상시 import는 없습니다.
- 개인 Skill 우선순위와 기존 resolve 절차를 유지합니다. 외부 플러그인의 모든
  행동까지 통제하거나 충돌이 절대 없다고 보장하는 기능은 아닙니다.
- 기존의 업무 완료 시 학습, 안전 검사, 개인 자료 분리 저장을 그대로 사용합니다.

## 선별 기준과 제외한 기능

Matt Pocock의 문서 작성·용어 관리·진단 기준, Ponytail의 기존 기능 재사용 원칙,
i-have-adhd의 결과 중심 응답 방식을 회사 환경에 맞춰 재작성했습니다.
원본 전체 설치, ultra 모드, 강제 한 줄 코드, 매번 진행 보고, 반복 인터뷰,
근거 없는 시간 예측, 자동 외부 설치는 포함하지 않았습니다.

새 자동 학습 엔진, 강제 출력 필터, 자동 rewind를 추가한 것은 아닙니다.
추가 구현한 handoff create/read는 프로젝트별 인수인계 문서 생성·조회입니다.
원래 세션 복원이나 검증 상태 초기화가 아니며, 자료가 없으면 이어가기를 중단합니다.
setup-helper create는 실제 실행 가능한 Windows/Python 질문 도우미를 생성합니다.
선택·일반 텍스트·기존 폴더 입력, 답변 확인/저장, 취소, 재실행을 지원합니다.
비밀값은 받지 않으며 답변은 평문입니다. 설치 명령을 실행하는 범용 엔진은 아닙니다.
회사 Agent 자체 설치·업데이트는 기존의 검증된 설치 프로그램이 수행합니다.
응답 지침 준수는 모델과 주변 플러그인에 영향을 받으므로 구조 테스트만으로
모든 실제 응답이 성공했다고 주장하지 않습니다.

고정된 원본 버전과 MIT 고지는 배포 코어의 THIRD_PARTY_NOTICES.md에 포함합니다.
현재 작업은 개인 Claude 설치·Memory·Skill·MCP·설정 파일을 수정하지 않습니다.

## 선별 지침 통합 단계의 검증 결과 (후속 기능 추가 전)

- 전체 Python 회귀 테스트: 421개 통과, 실패 0개, 제외 0개 (98.706초).
  `COMPANY_AGENT_TEST_REAL_CLAUDE=1`로 기존 조건부 검사도 활성화했습니다.
- 신규 선별 통합 계약 테스트 7개 포함: 기존 11개 이름, 참고 경로,
  조건부 읽기, 본문 크기 상한, 완전한 결과, 명시적 기억 예외, 안전 경계 확인.

  검증용 임시 자료는 테스트 종료 시 정리되며 기존 dist ZIP은 변경하지 않았습니다.
