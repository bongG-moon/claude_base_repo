# 개별 스킬 사용성 개선

아래는 단계별 구현과 검사 기록입니다. 최종 배포 범위와 재검증 결과는 [2026-11-04 스킬 릴리즈 기록](releases/v1.5.2-skills-20261104.md)을 기준으로 합니다. 단계별 검사 수는 서로 겹치므로 합산하지 않습니다.

## 목표와 계획

- 발표 입력: 비정상 ZIP/보호 PPT를 XML로 단정하지 않고 정상 PowerPoint 열기와 요청 장 캡처로 스타일 관찰. 원본 변경과 보호 해제는 하지 않는다.
- 발표 제작: 새 문서를 Python 코드로 생성하여 설치 폴더의 기본 PPT 템플릿 의존 제거. 기존 HTML의 실제 배치를 편집 개체로 변환하고 HTML 승인과 결과 일치를 유지한다.
- 기본 발표 형식: 모든 디자인에서 독립 HTML 발표본에 페이지 이동, 전체 보기, 메모, 문구 및 표 셀 편집, 저장과 인쇄를 제공한다. 발표 조작은 같고 색상, 글꼴, 장별 배치와 내용은 참고자료에 맞춘다. 흑백 보고형 CSS도 별도 시각 양식으로 보존한다.
- HTML 참고 미리보기: 실제 생성 파일 경로와 클릭 링크, 열기 방법을 즉시 전달. 생성과 화면 확인 구분.
- 데이터 조회: 최초 등록에 변수 후보가 있을 때만 선택, 일반 조회는 별도 승인 없이 제한 내 실행, 위험 조건만 승인. PowerShell에서 JSON 인용 오류가 없는 조건 인자와 결과/내부 자료 분리.
- 유지보수: 짧은 SKILL 진입점, 상황별 참고자료. 새로운 상시 후크, 회사 접속이나 모델 호출 추가 없이 배포 ZIP 동기화.

## 검증 원칙

합성 자료와 독립 CLI, 실제 사용 가능한 로컬 브라우저/PowerPoint로 확인한다. 사내 DRM과 DB 서버는 여기서 재현할 수 없으므로 검증 완료로 표시하지 않는다. Python 처리 시간과 LLM 대화 전체 지연은 구분한다.

## 구현 결과

PPT Master의 경로 분리/편집 개체 유지와 Huashu Design의 완성된 HTML 좌표 변환을 선택적으로 참고했다. 외부 스킬 전체 설치, 별도 모델, 상시 웹 검색, 다중 시안 의무나 새 후크는 넣지 않았다. 모든 초안은 공통 발표 조작이 있는 HTML로 만든다. 사용자의 고정 흑백 CSS도 assets로 보존하고 생성기가 실제 장수와 발표 도구, 편집 가능한 본문을 채운다. SKILL 진입 문서는 43줄이며 구체 명세와 참고자료는 필요한 분기에서 읽는다.

HTML만 요청하면 편집형 HTML을 완성본으로 전달한다. PPTX를 요청했을 때만 현재 내용을 확인받아 내보낸다. 저장한 기본 HTML은 nativeDeck 경로에서 실제 문구와 표 셀의 변경을 읽고 기존 네이티브 차트, 도형과 부분 강조를 보존한다. 외부 스크립트를 실행하거나 브라우저를 다시 띄우지 않으며 이전 승인을 재사용하지 않는다. 이 경로는 생성된 UI의 문구 편집용이고, 외부 프로그램에서 바꾼 CSS와 도형 배치까지 반영하는 범용 변환은 아니다.

로컬 검증에서는 업무 보고형과 따뜻한 설명형을 각각 8장으로 생성했다. 같은 발표 조작 안에서 색상과 배치가 달라진다. 해당 실행 산출물과 대화 로그는 배포에서 제외하며, 재사용 양식은 개별 ZIP의 assets에 포함한다.

새 PPT의 빈 OOXML 패키지를 Python 메모리에서 직접 생성하므로 site-packages의 default.pptx는 읽지 않는다. 이는 새 문서 생성이며 보호된 원본 추출이나 보안 프로그램 설정 변경이 아니다. 저장 후 보호된 결과를 재검사할 수 없으면 generated_ppt_unreadable로 별도 보고한다. PowerPoint 정상 열기/장별 Export를 제공하고 화면 캡처와 명확히 구분한다.

HTML 직접 변환의 deckMode는 격리 사본에서 모든 선택 장을 active로 측정한다. 표의 바깥 경계선과 셀 크기 합 차이 보정, 대표 머리글/본문 색상 유지, 간단한 CSS 가상 연결선 보존을 추가했다. 원본 JavaScript는 실행하지 않는다. 셀별 강조, 복잡한 점선/그라디언트와 사용자 환경의 글꼴까지 완전히 동일하다고 보장하지 않는다.

조회 등록의 변수 검토는 고정 조건 후보가 있는 경우에만 필요하다. Oracle 날짜 포맷 문자열은 후보에서 제외한다. 일반 execute와 CSV 저장을 한 호출로 실행하며 위험한 SQL/기본 한도 확대는 기존 승인 경로를 유지한다. 운영 DB의 전체 COUNT를 매번 자동 추가하지 않는다. 기존 결과를 임의 재사용하지 않으며 원문은 기본 0행, 필요한 미리보기만 기본 5행/최대 20행으로 전달한다.

업무 폴더의 outputs에는 CSV 결과를 전달하고 내부 자료는 개인 저장소, 필요한 입력은 .query-work로 구분한다. 기존 _work 및 개인 자료를 임의 이동/삭제하지 않는다.

## 실제 확인과 한계

- 7장 가상 HTML에서 네이티브 PPT 생성 후 설치된 PowerPoint로 전체 장 PNG 렌더를 확인했다. 텍스트 143개, 표 5개, 도형 64개, 전체 장 이미지 0개이며 텍스트 항목 239개가 보존됐다. 9pt 페이지번호/보조문구 경고 21건은 원본 비율 유지에 따른 것으로 실제 본문 잘림과 구분했다.
- 테스트용 합성 승인 기록으로 제작했다. 실제 사용자가 이 디자인을 승인했다는 뜻이 아니며 일반 제작은 HTML 승인 절차를 유지한다.
- 초기 샌드박스의 브라우저/Office 실행 제한은 허용된 격리 검증 환경에서 다시 확인했다. 실제 회사 DRM/게이트웨이/운영 DB는 여기서 검증하지 않았다.
- 독립 더미 CLI의 Python 시작, 조회, CSV 저장은 두 번 각각 607ms/620ms였다. 사내 DB나 LLM 대화 전체 시간의 측정치가 아니다. 기존 execute도 한 호출이 가능했으므로 3분 지연을 모두 실행 코드 탓으로 단정하지 않는다.
- 전체 조회 검사 312개 중 311개가 통과했다. 미변경 HTTP Host 거부 검사 한 건은 Windows 연결 중단(10053)이 발생했으며 해당 HTTP 검사 2개만 재실행하면 통과했다. 전체가 항상 통과했다고 표시하지 않는다.

실제 PowerPoint 렌더 모아보기는 로컬 검증 증거로 보관하고 배포에서 제외한다.

## 배포본 최종 확인

- 플랫폼 배포 검사 70개가 모두 통과했다. 최초 샌드박스에서 멈춘 외부 MCP 검사는 로컬 통신이 가능한 격리 시험으로 다시 실행해 포함했다.
- 새 프로젝트에 실제 presentation ZIP을 설치한 뒤 저장소 코드 없이 HTML 생성 → 초안 → PPT 제작을 실행했다. 설치된 Python 의존성만 명시적으로 사용했으며 하네스나 개인 프로필 설치는 추가하지 않았다.
- 설치된 배포본의 7장 HTML을 실제 브라우저로 열어 다음/마지막 장 이동, Home, 메모, 전체 보기, 제목 편집, 저장 후 재열기와 재이동을 확인했다. 저장본에 전체 보기의 입력 잠금이 남지 않는 것도 확인했다.
- PPT 관련 회귀 검사는 222개 중 220개 통과, 조건부 2개 건너뜀이다. 추가한 기본 템플릿 독립성, HTML 미리보기 전달, 발표 양식 생성 검사도 통과했다. 실제 브라우저 변환과 PowerPoint 렌더 증거는 별도로 남겼다.
- 원본과 개별 ZIP 6개(presentation, html-report, oracle-query, datalake-query, ehub-query, data-query-demo), 카탈로그와 체크섬을 함께 갱신했다. 배포 최신 여부 검사는 변경 필요 파일이 없다고 확인했다.

참고한 정본: [PPT Master](https://github.com/hugohe3/ppt-master), [Huashu Design](https://github.com/alchaincyf/huashu-design). 회사 DRM이 적용된 입력/출력과 운영 DB에서의 최종 확인은 여전히 필요하다.

## 공통 편집형 HTML의 기본 적용 검증

- PPT 전체 회귀 238개 중 235개 통과, 조건부 3개 건너뜀. 공통 발표 화면 검사는 실제 브라우저를 켠 별도 실행에서 5개 모두 통과했다.
- 실제 기본 초안 2개 디자인의 각 8장을 큰 화면과 작은 화면에서 검사했다. 글자와 표 셀의 장 경계 이탈이 없었고 이동, 메모, 전체 보기, 편집과 저장 후 재열기를 확인했다. 작은 화면의 알림이 툴바를 덮던 위치를 수정했다.
- 기본 HTML의 편집 재입력 검사는 10개 모두 통과했다. 실제 8장 HTML의 제목, 부분 강조, 표 값을 바꾼 뒤 새 초안과 합성 승인으로 Python PPTX를 생성했다. 수정 문구와 표 값, 원래 색상과 배치, 데이터가 있는 차트 1개를 확인했다. 전체 장 이미지 변환과 브라우저 재측정은 없었다.
- 최종 ZIP의 패키지 검사 34개가 모두 통과했고 최신 여부 검사는 변경 필요 파일 없음이다. 공통 엔진을 공유하는 presentation과 html-report ZIP, 카탈로그 및 체크섬을 갱신했다.
- HTML 문구 편집은 글자와 표 셀 편집이다. 화면에서 도형을 끌거나 차트 데이터를 직접 바꾸는 전체 편집기를 구현한 것은 아니며 해당 변경은 제작 명세에 반영해 다시 생성한다.

## 최종 시각 보완

- 실제 PowerPoint에서 발견한 판단 도형의 글자 겹침을 재사용 스킬과 제작 엔진에 반영했다. 중앙 안전 영역, 분기 및 건너뛰는 연결의 별도 경로, 연결 라벨 공간을 확인한다. 관련 검사 151개를 통과했으며 이 수는 후속 전체 검사와 중복된다.
- 같은 업무보고형과 따뜻한 설명형을 새 초안으로 생성해 실제 PowerPoint 렌더를 다시 확인했다. 결과 파일만 직접 고친 것이 아니라 원본 스킬, 생성 코드, 검증 코드와 배포 ZIP을 함께 수정했다.
- Claude Code가 수정 스킬로 재생성을 진행했지만 세션 사용 한도에 도달했다. 최종 초안 생성, PPT 내보내기와 PowerPoint 렌더는 Codex가 같은 제작 엔진으로 완료했다. 따라서 마지막 수정 이후 Claude Code의 전체 완료 흐름은 통과로 표시하지 않는다.
- 마지막 비교 실행의 HTML은 정적 검사 범위다. 앞선 브라우저 동작 검증을 최신 HTML의 화면 및 상호작용 검증으로 대신하지 않는다.
