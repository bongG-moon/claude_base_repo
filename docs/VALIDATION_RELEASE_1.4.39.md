# Company Harness 1.4.39 배포 검증

검증일: 2026-10-11. 새 스킬의 Claude 기본 저장 위치·원본 수정·학습 연결, PPT 참고 입력, Outlook 제한 조회, 설치 보존 및 안내서 변경을 선별했습니다. 별도 개발 중인 Workspace 앱·Computer Use MCP·실습 자료는 이번 배포에 포함하지 않았습니다.

## 선별 소스

- 명시적 파일 목록으로 Git index를 구성하고 `core.autocrlf=false archive`로 실제 Git 바이트를 내보낸 소스에서 시험·빌드했습니다. 별도 Workspace 작업과 개인 자료는 보존했습니다.
- 선택하지 않은 기존 파일 557개가 HEAD와 바이트 단위로 같음을 확인했습니다. 새 파일도 선택 목록 밖에서 포함되지 않았습니다.
- 새 `native_skill_storage.py`, `native_skill_learning.py`, `skill_lifecycle.py`, `ppt_reference.py`와 필요한 참조 문서를 포함했습니다. 대표 자격증명·비밀키 패턴 검사 및 `git diff --cached --check`를 통과했습니다. 패턴 검사는 모든 비밀정보 부재를 보증하는 검사는 아닙니다.
- HTML 추가 디자인에서 앱 실행 표시만 보고 카드 지원을 가정하던 충돌을 제거했습니다. CLI·Workspace 모두 일반 채팅 선택 목록을 사용합니다.
- 안내서 계약 시험을 하네스와 별도 앱으로 분리했습니다. 하네스 시험이 미배포 앱의 버전·파일을 요구하지 않도록 했으며, 앱 쪽 검증은 작업 폴더에 별도로 보존했습니다.

## 시험 결과

배포 소스의 927개 검사 항목은 아래 재실행을 포함해 최종 통과했습니다. 실제 사용자 설정·메일함·Office 문서·운영 모델을 사용한 시험은 아닙니다.

| 시험 묶음 | 결과 |
| --- | --- |
| 스킬 선택·생성·수정·학습·PPT·메일·안내서 등 872개 | 최초 861개 통과, 9개 재실행 통과, MCP SDK가 없는 Python에서 제외된 2개는 별도 환경에서 통과 |
| 설치 EXE·GitLab 포장·Read 후크·백업 안내 54개 | 최초 52개 통과, PowerShell 시간 초과 2개 동일 조건 재실행 통과 |
| 로컬 MCP 프로토콜 3개 | 준비된 Python 3.13/MCP SDK에서 3개 통과. 위 제외 2개와 중복, 나머지 1개는 추가 검사 |

첫 통합 실행 중 일부 PowerShell 프로세스 시간 초과가 있었습니다. 또한 임시 폴더를 저장소 안에 두어 Git 상위 경로가 없다는 시험 전제와 달라졌고, 일부 후크 컨텍스트 파싱 검사도 실패했습니다. 저장소 밖의 새 임시 폴더에서 실패 9개를 그대로 다시 실행하여 45.7초에 통과했습니다. 검사 조건이나 제품 코드를 완화하지 않았습니다. 첫 실패를 숨기거나 전체 업무 속도 개선 수치로 해석하지 않습니다.

주요 확인 범위:

- 개인 전체·프로젝트 새 스킬의 기본 Claude 경로, 기존 비공개 스킬 보존, 이름 충돌 거절, 원본 해시 충돌 처리, frontmatter 보존, 중복 실행 사본 방지.
- 실제 원본·본문 로드 근거가 있는 등록 스킬의 학습과 되돌리기, 같은 이름의 다른 파일 및 사용자 수동 수정 보호, 세션 간 기억 전달.
- 합성 PPTX의 대표 장·요청 범위, HTML·이미지 참고, 화면 모드가 캡처가 아닌 계획임을 구분, 확인된 보호 거절 시 중단.
- 가상 Outlook 응답의 본문·최종 JSON 한도, 한글·이모지, 잘린 범위와 보호 제한 보존. 실제 Outlook COM·회사 MCP·발송은 실행하지 않았습니다.
- 앱 표시 환경값이 있더라도 HTML 디자인 목록과 일반 답변 흐름이 유지됨.

## 실제 배포 파일

- 직원 ZIP 생성에서 Claude 플러그인 strict 검사·회사 지식 검증·Python 구문 검사를 생략하지 않았습니다.
- 통합 HTML은 6개 부분·52개 장·424,003바이트이며 7개 Markdown 원본 및 설치 사본과 생성 결과가 일치합니다. 외부 앱 문서는 직원 ZIP에서 제외했습니다.
- 실제 ZIP 회귀시험은 기본 외부 Python 방식, 문서 누락·오래된 사본 거절, 동일 버전의 다른 내용 덮어쓰기 거절, 원본 보존을 통과했습니다.
- 설치 EXE의 `--verify-only`로 내장 ZIP 추출·해시 검증을 통과했습니다. 실제 직원 프로필에 설치하지 않았습니다.
- GitLab 준비 도구에서 manifest의 228개 파일을 검증했습니다. 직원 ZIP은 manifest 자체를 포함해 229개 파일입니다.

각 파일의 `.sha256`도 제공합니다. EXE의 Authenticode 상태는 `NotSigned`입니다. 해시는 파일 일치 확인이며 회사 배포 승인·코드 서명을 대신하지 않습니다.

## 남은 운영 검증

사내 HCP·게이트웨이·Outlook 계정·PowerPoint·DRM의 실제 통합 업무, 회사 PC의 전체 소요 시간·토큰 절감, 사용하는 Claude 호스트의 실시간 스킬 목록 갱신은 별도 확인이 필요합니다. 기본 스킬 경로에 저장하는 것과 현재 호스트가 발견·실행하는 것은 다릅니다. 별도 Workspace 앱의 `/reload-skills` 구현은 이 하네스 설치 파일로 갱신되지 않습니다.

GitLab 파일은 `published:false`, `networkUsed:false`인 수동 게시용 준비 결과입니다. GitHub Release 게시가 사내 GitLab 업로드나 직원 PC 자동 업데이트를 뜻하지 않습니다. 이전 Release·개인 자료·별도 앱 작업은 보존합니다.
