# 실행 준비 오탐과 스크립트 오류 복구 보완

## 확인된 원인

- 기존 `reviewProtocol=1`은 실제 후보가 없는 `review` 상태에서도 첫 Bash/Write를 `permissionDecision=deny`로 반환했다. 사용자가 보낸 폴더 조회 명령은 경로 문제가 아니라 준비 차단이었다.
- 단순 `ls` 조회의 `2>/dev/null`도 변경 감지 정규식의 리다이렉트 항목에 걸렸다. 준비 차단만 제거하면 실행 후 변경 검증을 잘못 요구할 수 있어 결과 분류까지 함께 수정했다.
- “관련 없는 질문”의 일반 단어가 Outlook 설명과 우연히 일치해 후보가 잡혔다. 해당 일반 단어를 후보 점수에서 제외했다. 후보 누락을 스킬 부재로 해석하지 않는 전체 목록 비교는 유지한다.
- 제공된 Python 로그는 `re.compile` 호출 중 실패한 사실만 확인된다. 마지막 예외 문장과 패턴이 없으므로 실제 정규식 결함 또는 전달 과정의 이스케이프 손상은 확정하지 않는다. Write 실패가 인코딩 때문이라는 근거도 없다.

## 변경 범위

1. 위치/폴더 조회는 준비 차단과 교정 횟수 소모에서 제외한다. 실행 코드, 내용 추출, 파이프, 실제 출력 파일, 혼합 실행 명령은 예외가 아니다. Bash의 `/dev/null`을 PowerShell의 출력 파일과 혼동하지 않는다.
2. `review`/`select`/`choose`/`inspect`는 짧은 내부 안내만 한 번 제공한다. 이미 제공된 목록을 무조건 다시 읽게 하거나 무관한 스킬을 강제하지 않는다.
3. 실제 단일 `load` 후보 본문을 건너뛴 실행의 1회 교정은 유지한다. 이를 전부 없애서 PPT가 다시 임의 unzip 방식으로 시작하는 회귀를 피한다. 이 경우 `[스킬 확인]`이 나타날 수 있으며 오류 표시를 숨기지 않는다.
4. 별도 코드는 파일로 작성하고 정확한 경로·내용 확인 후 실행한다. 긴 Bash → PowerShell `-Command` → Python `-c` 중첩을 피한다. Python은 `-X utf8`; Windows PowerShell 5.1의 새 한글 `.ps1`은 UTF-8 BOM을 사용한다. 기존 원본 인코딩을 덮어쓰지 않는다.
5. 정규식 오류/불완전한 traceback/Write 실패를 구분해 복구 지침을 제공한다. 한 요청에서 종류별 한 번만 안내한다. 오류 전 부작용은 미확인으로 남기고 재실행 전 기존 결과를 확인한다. 코드·예외 원문은 상태에 저장하지 않는다.
6. 실제 권한 거절, 사용자 취소, 보호 제한은 대체 실행 안내로 바꾸지 않는다. 개인 로그인·모델·MCP·스킬·계정 설정을 변경하지 않는다.

## 검증

- 관련 회귀 테스트 205개 통과. 추가된 실행 분류/한글 파일/스킬 준비 확인 52개 통과(두 실행의 테스트는 일부 중복).
- 실제 Windows 진입점 → Hook → 격리 상태 테스트 13개 통과.
- 실제 Claude CLI + 로컬 고정 응답 테스트:
  - `skip-list`: 등록된 스킬 본문을 건너뛴 실행 교정 및 후속 Skill 로드 확인, 4.68초.
  - `list-before-skill`: 사용자가 보낸 조회 명령 → Skill 로드, 준비 차단/도구 오류/허위 변경 기록 없음, 5.36초.
  - 외부 모델·회사 문서·사용자 인증정보를 사용하지 않았다. 모델의 자율 선택 성능 검증과는 다르다.
- 5회 중앙값 측정: 첫 요청 준비 11.13ms, 요청 컨텍스트 3,926문자, 재사용 3,762문자. 비교용 공개 1.4.12는 9,009문자다. 문자 수는 토큰 수가 아니며 Office/모델 실행 지연을 포함하지 않는다.
- 추가 모델 호출 0, 필수 선택 기록 명령 0, warm inventory 본문 재읽기 0. 단순 폴더 조회는 상태/목록 재탐색 전에 판별한다.

전체 테스트: `python -X utf8 -m unittest discover -s tests -q` — 854개 중 852개 통과, 2개 조건부 생략, 실패 0개(195.522초). 문법 컴파일과 `git diff --check`도 통과했다.

## 확인하지 않은 범위

사내 HCP 모델이 모든 요청에서 지침을 따르는지, 사용자 로그에서 생략된 실제 정규식, 운영 PC에 새 코드가 설치되었는지는 확인하지 않았다. 이 기록은 소스 수정 검증이며 릴리스/운영 설치 완료 기록이 아니다.

## 참고
