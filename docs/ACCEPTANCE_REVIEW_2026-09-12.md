## 무엇을 실제로 했나요?

초보 사용자, 개인 기억·학습, 업무 기능·안전성을 맡은 서브에이전트 세 명이 각각 별도 시험 폴더에서 사용했습니다. 불만족한 응답은 그대로 남기고, 원인을 수정한 뒤 새로 실행했습니다. 단순히 코드 검사가 통과했다는 이유로 실제 사용이 성공했다고 판정하지 않았습니다.

실제 Claude Code 2.1.263과 이 PC에 이미 설정된 모델을 사용했습니다. 회사의 HCP 모델·Outlook·DB에 접속한 시험은 아닙니다. 시험용 플러그인과 가상 자료만 별도로 불러왔고, 직원용 하네스를 이 PC에 새로 설치하지 않았습니다. 실메일 발송·이동·삭제, DB 변경, 보호 해제는 하지 않았습니다.

## 실제 사용 확인

- HTML 선택: 새 Claude 응답에서 한글 선택지와 추천대로를 확인했습니다. 별도 브라우저 검사에서 결과 다운로드·복사·저장 경고·작은 화면 표시도 확인했습니다.
- 폴더 정리 미리보기: 4개 파일의 정리안을 만들었고 원본 6개의 경로와 내용은 그대로였습니다. 변경 오판정과 Stop 반복이 0이었습니다. 초기 탐색 명령 1회는 승인 거부됐으므로 전체 과정이 무승인이었다고 주장하지 않습니다.
- 보고서 생성: 실제 Markdown을 쓰고 다시 읽어 목표 10건·완료 9건·90%를 확인했습니다. 검증 기록이 유지됐고 최종 답변은 경로와 수치만 전달했습니다. 최종 시험 39.47초, 승인 거부 0건.
- 명시적 개인 기억: 실제 Markdown 1개 저장과 읽기 확인 후 새 대화에서 내용을 다시 찾았습니다. 저장하지 않은 내용을 기억했다고 답하지 않았습니다.
- 업무 단위 학습: 미완료 단계에서는 후보 1개·영구 기억 0개, 완료 후에는 검토 1회·영구 기억 1개·후보 0개를 실제 Claude 호출로 확인했습니다. 완료 답변은 업무 내용 한 문장으로 끝났습니다.
- 보호·정책 설명: 보호 해제 사본을 제안하지 않고 첨부 제외를 안내했습니다. 다른 사람 계정과 DB 쓰기를 대화상 승인으로 허용하지 않았으며 외부 MCP의 실제 설정이 검증됐다고 단정하지 않았습니다.
- 로컬 메일 요약: 실제 EML 읽기 기능으로 가상 파일 3개와 TXT 첨부를 읽었습니다. 일정과 할 일이 맞았고 원본 해시가 유지됐습니다. 최종 시험 38.17초, 승인 거절·변경 오판정·Stop 반복 0건.
- 학습한 방식 적용: 별도 새 대화에서 사용자에게 선호를 다시 받지 않고 ‘결정 사항 먼저’인 보고 문장을 생성했습니다. 해당 선호의 자동 기억 전달도 확인했습니다. 최종 시험 12.46초.

개인 Skill 수정→다음 업무에서 같은 버전 재사용→평가 기록은 독립 엔진 시험으로 확인했습니다. 이를 실제 회사 업무 성과가 향상됐다는 증명으로 해석하면 안 됩니다. 기억이 전달돼도 모든 문장 형식이 항상 그대로 적용된다는 보장은 없습니다.

## 시험기 문제와 제품 문제를 구분했습니다

일부 초기 실패는 시험기의 허용 규칙이 잘못된 것이었습니다. Windows 절대 경로 규칙, 파일 쓰기 규칙, 명령의 따옴표 조합을 수정했습니다. 최신 Claude는 파일 쓰기에도 `Edit(path)`를 확인하며, `Write(path)`는 경로 규칙으로 적용하지 않습니다. [공식 권한 설명](https://code.claude.com/docs/en/permissions).

시험용 승인 범위는 개별 시험 폴더의 지정 파일과 정확한 자체 명령으로 제한했습니다. 전체 Bash 허용·권한 검사 생략은 사용하지 않았습니다. 이 사전 승인은 직원 PC의 기본 권한이나 회사 정책을 변경한 것이 아닙니다. 운영 버전에서 다시 승인 여부를 확인해야 합니다.

이 CLI에서는 승인 거절이 활동 Hook에 전달되지 않는 경우도 실제로 확인했습니다. 따라서 특정 오류 문구 감지만으로 모든 거절을 처리한다고 주장하지 않습니다. 무진전 Stop 종료는 이런 상황에서도 거짓 성공 없이 멈추기 위한 보완입니다.

## 별도 운영환경 확인이 필요한 범위

- 회사 모델별 실제 선택·품질·호출 권한
- Outlook 2016과 사내 DRM, 실제 메일 검색·본문 권한
- 별도 개발 MCP의 SELECT 제한·본인 발신자 강제·PST 보관
- 직원 PC의 회사 관리 정책과 최초 승인 화면
- 실제 파일 이동 승인창과 실제 업무 자료를 사용하는 장기 학습 효과

기존 settings.json과 플러그인 설치 목록의 해시는 각 시험 전후 동일했습니다. PC 전체가 완전히 무변경이라는 뜻은 아니며 시험 자료와 로그는 별도 build 폴더에 생성됐습니다. 원문 실행 로그는 개인 정보가 포함될 수 있어 외부 게시 대상에서 제외합니다.
