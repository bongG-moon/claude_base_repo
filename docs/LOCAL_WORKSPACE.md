# Company Workspace — 로컬 업무 화면 0.3

## 누구를 위한 화면인가요?

터미널에서 명령을 입력하는 것이 낯선 사용자를 위한 Company Agent의 별도 로컬 화면입니다. **기존 Claude Code CLI가 실제 작업을 수행**합니다. Claude Desktop을 설치하거나 회사 모델 연결을 교체하지 않습니다.

**앱 전용 로그인·API 키·모델 설정은 없습니다.** 같은 Windows 사용자, 같은 실행 환경과 작업 폴더에서 `claude`를 실행했을 때 사용하는 로그인·모델·설정·스킬을 그대로 사용하고, 입력과 출력만 업무 화면으로 표시합니다. 기존 Claude가 로그인돼 있다면 앱을 위해 다시 로그인할 필요가 없습니다.

이 버전은 개발용 첫 실행 버전입니다. 사내 HCP 서버·보안 프로그램·실제 DRM 문서에서의 최종 검증과 정식 배포 승인은 별도로 필요합니다. 모든 CLI 화면을 재구현했다는 의미가 아닙니다.

## 처음 쓰는 사람을 위한 도우미

왼쪽의 **첫 업무 따라 하기 / 내 업무 방식·기억 / 사용 현황·결과 확인**으로 엽니다. 화면 열기·조회·통계에 별도 AI를 호출하지 않습니다.

1. **따라 하기:** 자료 읽기 → 결과 만들기 → 수정 → 선호 저장 → 새 대화 재사용의 5단계입니다. 예문 버튼은 입력창만 채우며 직접 보내야 실행됩니다. ‘직접 확인했어요’는 학습 진행 기록이지 업무 성공의 자동 판정이 아닙니다. 오프라인 첫 업무 안내서도 같은 코스 자료를 사용합니다.
2. **개인 기억:** 기존 Company Agent 기억을 조회하고, 추가·수정·비활성화·이전 내용 복원안을 확인한 뒤 저장합니다. 업무 중 학습을 끄거나 기존 학습 변경을 되돌릴 수 있습니다. Claude 자체 자동 기억과 회사 기준은 합치거나 수정하지 않습니다.
3. **회사·개인 지식:** 회사 업무 기준과 공통 지식은 읽기 전용입니다. 개인 업무 지식은 출처와 다음 확인일을 붙여 초안으로 만들고, 직접 검토한 뒤 활성화합니다. 선택한 지식의 내보내기는 로컬 ZIP 후보이며 자동 전송·회사 반영이 아닙니다. 복잡한 테이블/조인/회사 확장 문서는 기존 지식 도구에서 관리합니다.
4. **폴더 업무 지침:** 목표·입력·결과·확인 기준만 `.claude/rules/company-workspace-brief.md`에 저장합니다. 전역 `CLAUDE.md`와 다른 파일은 변경하지 않습니다. 이미 있던 파일 또는 이후 직접 편집한 파일은 덮어쓰지 않습니다. 업데이트 전 버전은 개인 상태의 `workspace/brief-versions`에 보존합니다.
5. **사용 현황:** 현재 요청의 CLI 보고값과 사용자가 선택한 과거 JSONL 분석을 별도로 보여 줍니다. 누락은 ‘미제공’, 사내 모델 비용은 미추정입니다. 같은 메시지의 스트림 기록은 중복 제거하며 CLI 완료값·작업자·로그 합계를 서로 더하지 않습니다. CLI 버전에 따라 완료값이 누적일 수 있어 요청끼리 합산하지 않습니다. 다음 요청의 토큰 알림은 앱을 닫으면 해제되며 강제 비용 한도가 아닙니다.
6. **준비·결과 확인:** 설치·스킬 발견·지침 분량과 실제 업무 결과를 분리합니다. 사용자 확인 기록에서 실패·중지·차단·미확인을 빼고 성공률을 만들지 않습니다. 모델/평가 시 설치 버전별 관찰 그룹을 표시하되 전체 AI 성능 점수나 인과적 개선 증거라고 주장하지 않습니다. 실제 실행 당시 버전을 입증하지 못하면 평가 시 버전과 구별합니다.

기억·지식 기능은 **`workspace` 관리 API가 포함된 Company Agent 1.4.15 설치**가 필요합니다. 기존 1.4.14 설치에 자동으로 생기지 않습니다. 해당 기능이 없는 설치에서는 안내·일반 Claude 대화를 그대로 유지하고 설치 확인 필요만 표시합니다. UI가 임의로 다른 설치/상태 폴더를 선택하거나 플러그인을 설치하지 않습니다.

관리 화면은 기존 사용자 설치 등록과 Claude 설정 루트, 현재 작업 폴더에 맞는 프로젝트 등록을 확인합니다. 사용자 설치와 프로젝트 설치의 기억은 별개입니다. 터미널 호출 스크립트가 내부에서 환경변수를 다시 바꾸는 경우 시작 환경만으로 두 위치의 동일성을 보장하지 않으므로 등록을 확인해야 합니다. 모든 폴더에 스킬 파일을 복사할 필요는 없습니다.

저장은 **미리보기 → 명시 확인 → 현재 내용 해시 재확인**으로 진행합니다. 실행 중인 업무가 있으면 개인 기억/지침 변경을 잠시 보류합니다. 응답 시간 초과 때 저장 여부는 미확인으로 안내하며 원래 업무를 자동 재실행하지 않습니다. 외부 편집기의 동시 저장까지 전역 잠금하는 기능은 아닙니다.

관리 정보는 선택한 탭에서만 조회합니다. 따라 하기·현재 사용 현황은 하네스 조회 프로세스를 띄우지 않습니다. 기억·지식은 20개 파일 단위 목록으로 읽고, ‘내용·출처 보기’ 또는 수정에서 선택한 본문만 가져옵니다. 목록이 바뀌면 새로고침 안내를 하며, 확인 범위 한도에 도달하면 전체 목록이 아님을 표시합니다.

## 시작하기

1. 기존 Company Agent와 Claude Code, 회사가 승인한 Python 3.11 이상이 설치된 Windows에서 사용합니다.
2. 저장소 또는 ZIP을 풀어 놓은 Workspace 폴더의 **`Company-Workspace.vbs`를 더블클릭**합니다. 관리자 권한은 사용하지 않습니다. ZIP 미리보기 안에서 실행하지 마세요.
3. Edge가 있으면 독립 앱 모양의 창, 없으면 기본 브라우저가 열립니다.
4. ‘작업 폴더’를 선택하고 해당 폴더의 설정 실행에 동의합니다.
5. 파일 선택 → 요청 입력 → 필요한 질문/승인 응답 → 결과 확인 순서로 진행합니다.
6. 오른쪽 위 전원 버튼으로 연결된 작업과 로컬 서버를 종료합니다. 창의 X만 닫으면 서버는 남아 있으므로 다시 실행해 열린 작업을 확인할 수 있습니다.

새 ZIP으로 교체할 때도 먼저 기존 앱의 전원 버튼으로 종료하세요. 다른 버전/폴더의 앱이 살아 있으면 구버전을 조용히 재사용하거나 진행 중 업무를 강제 종료하지 않고 안내합니다.

원본 파일을 복사하지 않고 정확한 경로를 전달합니다. 브라우저의 일반 파일 업로드처럼 원본을 임시 복사하지 않습니다. 경로 직접 입력도 지원하며, 웹 드래그 앤 드롭은 아직 지원하지 않습니다.

조직에서 VBS 또는 PowerShell 실행을 차단하면 이를 우회하지 말고 승인된 배포 방식으로 실행기를 배포해야 합니다. CLI 로그인이나 인증서·회사 게이트웨이 설정이 필요하면 기존 조직 안내를 따릅니다. 앱은 비밀번호/API 키를 새로 수집하지 않습니다.

개발자 실행:

```powershell
python -X utf8 -m local_app.server
# 가상 화면 체험: 실제 AI/문서 작업 없음, 별도의 demo 기록 사용
python -X utf8 -m local_app.server --demo
```

더블클릭 실행기는 현재 사용자의 Windows PowerShell 시작 프로필을 적용한 뒤 `Get-Command claude`로 실제 호출 대상을 선택합니다. 별칭, 프로필 함수, `.cmd`/`.ps1` 실행 스크립트도 존중하며, 스크립트를 건너뛰고 별도의 npm 실행 파일을 선택하지 않습니다. 다른 사용자 프로필이나 별도 Claude 인증 저장소는 만들거나 검색하지 않습니다. `CLAUDE_CONFIG_DIR`, 모델·회사 연결·인증 환경변수는 그대로 상속하고, 인증 파일을 앱으로 복사하지 않습니다. 기존 `COMPANY_AGENT_CLAUDE` 명시 지정은 호환용으로 유지하지만 일반 사용자가 새로 설정할 항목은 아닙니다.

Windows PowerShell과 다른 실행 환경(WSL/Linux, Git Bash 전용 프로필, VS Code 전용 환경, 특정 터미널에서만 임시로 만든 변수·함수)은 자동으로 동일하다고 가정할 수 없습니다. 해당 환경만 정상이라면 재로그인부터 요구하지 말고 CLI 경로·설정 위치·실행 환경 차이를 확인해야 합니다. 화면의 ‘연결 상태와 작업 기록’에서 실행 경로와 상속한 설정 위치를 확인할 수 있습니다. 기존 호출 스크립트가 그 안에서 설정 위치를 변경할 수도 있으므로 이 값은 시작 환경 기준입니다.

OAuth 만료 등 실제 인증 오류가 발생하면 앱이 소유한 실패 연결만 종료합니다. 터미널에서 기존 인증을 갱신한 후 사용자가 다시 보내면 새 CLI 프로세스가 같은 로그인 저장소를 다시 읽습니다. 앱 재설정, 별도 로그인, 요청 자동 재전송, 반복 인증 확인용 모델 호출은 하지 않습니다. ‘기존 Claude 사용’ 표시는 실행 파일 확인이며 모델 응답/인증 성공의 증거가 아닙니다.

## 이번 버전에서 되는 것 / 아직 아닌 것

| 기능 | 범위 |
|---|---|
| 한국어 업무 홈, 시작 카드 | 요청 문구만 채움. 사용자가 보내기 전에는 실행하지 않음 |
| 대화·원본 경로 첨부·후속 요청 | 실제 CLI `stream-json` 연결 사용 |
| 회사·개인 스킬, 후크, MCP, 모델 | CLI가 원래 설정을 로드. UI가 덮어쓰지 않음. 실제 `system/init` 보고 목록 표시 |
| 질문 | `AskUserQuestion` 단일/다중 선택, 직접 답변, 답변하지 않기 |
| 승인 | CLI가 요청한 내용 그대로 확인. 이번 요청만 승인/거절. 자동 허용/샌드박스 해제 없음 |
| 진행/오류 | 준비·실행·질문·승인·완료·실패·중지 분리. 작업자 실행 중인 result를 전체 완료로 표시하지 않음 |
| 기록·이어하기 | 이 앱에서 생성한 대화, CLI session ID로 재시작. 기존 모든 CLI 기록을 자동 수집하지 않음 |
| 결과 확인 | 작업 폴더 2단계/100개까지 문서 목록. UTF-8 텍스트·이미지 미리보기. Office/PDF는 원래 앱으로 열기 |
| HTML 미리보기 | 지원 보고서·디자인 화면은 격리된 정적 미리보기. 전체 구역 표시, JS·외부 접속 차단. 일반 첨부 HTML은 소스 표시 |
| 원본 CLI | 고급 메뉴에서 명시적으로 열기. 같은 연결을 중지한 뒤 이어받기 |
| 로그인 | 기존 CLI 인증 공유. 앱 전용 인증 없음. 실제 만료 시 기존 CLI에서 갱신 |
| TUI 전용 슬래시 명령·작업 팀 관리 | GUI에서 동일 지원을 보장하지 않음. 원본 CLI 이용 |
| 사내 DRM Office 열기 | 기존 office-reader 그대로 호출되어야 함. Windows Office/인증/회사 정책은 사내 검증 필요 |

같은 대화의 동시 요청을 막고, 살아 있는 CLI 연결은 최대 3개로 제한합니다. 기다리는 동안의 별도 모델 호출, 자동 제목 생성, 요약 모델, UI 전용 라우터는 없습니다. 질문·승인 응답은 JSON 제어 메시지이며 추가 추론 서비스로 보내지 않습니다. CLI가 원래 허용한 도구는 승인 창이 다시 나타나지 않을 수 있습니다. 앱은 `--permission-mode`, `--setting-sources`, `--model`, 인증/서버 관련 옵션을 강제하지 않습니다. 기존 CLI의 기본값과 회사 정책이 적용되며, 앱이 자동 승인·권한 우회 옵션을 추가하지 않습니다.

## 보안 및 기록

- `127.0.0.1` 임의 포트에만 바인딩하며 외부 공개/릴레이 기능이 없습니다.
- 매 실행 시 생성한 토큰으로 모든 API를 인증합니다. 브라우저 접속 후 주소의 토큰은 지우고 탭 저장소에만 보관합니다.
- Host/Origin/cross-site 확인, CSP 적용. 모델 출력은 HTML로 실행하지 않습니다.
- 파일 열기는 선택한 작업 폴더 또는 사용자가 첨부한 정확한 경로의 문서 확장자만 허용합니다. GUI 파일 접근 범위는 CLI 자체의 권한/샌드박스를 대체하지 않습니다.
- 실행 파일/스크립트·HTML의 자동 실행은 지원하지 않습니다. 재분석만 위해 원본을 덮어쓰거나 인코딩을 손실 변환하지 않습니다.
- `%LOCALAPPDATA%\CompanyAgent\local-ui\history-sessions\<대화 ID>.json`에 대화별로 저장하고 `history-index.json`에는 최근 최대 40개 대화 목록만 둡니다. 갱신된 대화만 저장하며 각 대화는 최대 150개 메시지·본문과 파일 경로 합계 50만 자로 제한합니다. 기존 `history.json`은 다음 정상 저장 때 이전하되 원본은 삭제하지 않습니다. 목록에서 오래되어 빠진 대화 파일도 자동 삭제하지 않습니다. 손상된 기록은 덮어쓰지 않고 새 앱 기록 저장 중지 안내를 표시합니다. CLI 자체 기록은 별개이며, 업무 원문의 이중 보존은 조직 보존 정책에서 검토해야 합니다.
- 승인 요청 원문과 표준 오류, 인증 정보, 전체 도구 결과를 별도의 앱 로그에 저장하지 않습니다. 모델의 일반 답변에 포함된 정보는 대화 기록에 남습니다.
- 새 사용량 스냅샷과 선택 로그 분석은 메모리에만 두며, 기존 대화 보존 정책을 바꾸지 않습니다. 사용자가 직접 확인한 코스 단계/결과만 `local-ui/learning-progress/<폴더 해시>.json`에 최대 100건 보관합니다. 원문·파일 경로·토큰 로그는 이 기록에 저장하지 않습니다. 모델 이름과 평가 시 설치 범위의 해시/버전은 로컬 비교용으로 남습니다.
- ‘확인 기록만 비우기’는 해당 폴더의 학습 진행과 자기 평가만 초기화합니다. 대화 이력·기억·지식·산출물은 보존됩니다. 먼저 원문 없는 확인 기록을 내려받을 수 있습니다. 내려받은 기록은 외부로 자동 전송되지 않습니다.
- 로컬 UI라는 것은 **모델 추론도 오프라인이라는 뜻이 아닙니다.** 기존 Claude/HCP 연결로 요청이 전달됩니다.
- 앱 상태 저장은 현재 사용자의 LOCALAPPDATA 권한을 상속합니다. 공유 계정/공유 프로필 배포는 지원 대상이 아닙니다.
