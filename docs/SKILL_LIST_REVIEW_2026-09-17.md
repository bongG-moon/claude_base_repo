# 사용 가능한 스킬 목록 활용 보완

상태: 1.4.13 소스·설치본에 포함. 기존 v1.4.12 태그·설치 ZIP·운영 PC 설정은 변경하지 않습니다. 운영 PC에는 같은 설치 범위로 업데이트 후 Claude Code를 다시 실행해야 적용됩니다.

## 수정 이유

제공된 운영 로그에서는 목록과 `office-reader` 후보를 Claude에 전달했지만 실제 Skill/Read 없이 직접 파싱을 선택했습니다. `additionalContext`만으로 이미 선택된 도구 호출이 취소되지는 않습니다. 이후 v1.4.12의 본문 삽입도 모델의 실제 선택을 관찰한 것과 달랐습니다.

소스에서 확인한 두 문제를 바로잡았습니다.

- 키워드 후보가 없다는 이유로 곧바로 `general`로 분류했습니다. 전체 목록에는 의미상 맞는 다른 이름/언어의 스킬이 있을 수 있습니다.
- Hook 본문 전달만으로 `selected`를 채우고 다음 요청에서 재사용했습니다. 모델이 적용하지 않아도 실행 전 준비가 끝난 것으로 보였습니다.

이번 수정은 PPT 확장자나 unzip 명령을 개별 차단하는 방식이 아닙니다. 설치된 회사·개인·프로젝트·다른 플러그인 목록을 공통 기준으로 사용합니다.

## 현재 동작

1. 기존 목록 조회 결과를 한 번만 활용합니다. 관련 후보가 있으면 실제 목록에서 확인한 고유 Skill 호출명 또는 정확한 Read 경로를 제시합니다.
2. 후보는 자동 선택이 아닙니다. 요청에 맞으면 해당 본문을 로드합니다. 후보가 맞지 않거나 후보 검색에 실패하면 전체 목록의 용도를 비교합니다.
3. 목록을 확인해도 관련 스킬이 없으면 일반 실행합니다. 자동 사용 가능한 로컬 스킬이 아예 없으면 별도 목록 Read나 선택 기록 명령도 요구하지 않습니다. 호스트가 따로 제공한 기본/원격 스킬의 성공한 호출도 존중합니다.
4. 목록 Read나 적합한 본문 로드 없이 도구 실행으로 넘어가면 요청·목록 버전당 첫 실행만 중단하고 `[스킬 목록 확인 1회]`로 정확한 다음 행동을 안내합니다. 이때 원래 도구는 실행되지 않았습니다. Read/Skill/검색/사용자 질문/준비용 조회는 막지 않습니다.
5. 목록 또는 본문 확인 후에는 계속 진행합니다. 교정을 무시해도 반복 차단하지 않고 `unconfirmed-limit-reached`로 남깁니다. 이는 적용 성공이 아닙니다. 실제 권한 거절은 이 교정과 별개로 계속 적용됩니다.
6. 같은 대화·목록의 실제 읽기 기록은 재사용합니다. 변경·삭제·수동 호출 전용·출처 중복·기존 우선 설정·재개/압축의 무효화 조건을 유지합니다. Hook 본문 삽입과 과거 `providedSkills` 기반 재사용은 제거했습니다.

명확한 정상 경로는 목록 파일을 다시 읽지 않고 **선택한 Skill 1회 로드 → 업무 실행**입니다. 본문을 이미 실제로 읽었다면 그 본문도 다시 로드하지 않습니다. 별도 선택용 LLM/필수 `skill route`/전체 본문 재스캔은 추가하지 않았습니다.

## 진단

기존 읽기 전용 진단 도구에 다음 구분을 추가했습니다.

- `executionMode`: `load`, `reuse`, `review`, `choose`, `select`, `general`, `inspect`.
- `indexRead`: 전체 목록 Read 관찰. 목록 전달과 다릅니다.
- `loadStatus`: 실제 본문 로드 관찰. `native-skill-outside-catalog`는 현재 요청에서 성공한 호스트 스킬이며 로컬 본문 해시나 다음 요청의 재사용 증거로 만들지 않습니다.
- `reviewStatus`: `redirected`, `catalog-read`, `skill-loaded`, `unconfirmed-limit-reached`. 이전 요청의 교정은 현재 증거로 표시하지 않습니다.

원문 질문·도구 명령·스킬/문서 본문은 진단에 저장하지 않습니다. 개인 Memory/Knowledge, 모델/MCP 설정, 관련 없는 플러그인 및 업무 파일은 수정하지 않습니다.

## 검증

운영 HCP 모델의 자율 선택은 이 개발 PC에서 검증하지 않았습니다. 아래 결과는 격리된 로컬 테스트입니다.

- 1.4.13 버전 반영 후 전체 회귀 검사 **767개 통과·제외 0개**, 168.389초. 시작 안내와 1회 교정 메시지의 충돌 검사도 포함합니다.
- 실제 Claude Code **2.1.272** 실행 파일과 로컬 모의 응답 서버로 전달·도구 연결 확인. 회사 로그의 2.1.273 계열과 동일 버전 테스트는 아닙니다.
  - 정상 Skill 로드: 9개 확인 항목 통과.
  - 목록을 무시한 첫 Bash: 12개 확인 항목 통과. 첫 도구 실행 중단 → 실제 Skill 성공 이벤트 → 재개 기록.
  - 목록을 무시한 첫 Write: 12개 확인 항목 통과. 출력 파일 미생성·업무 변경 카운트 0·정상 본문 로드 확인.
- 목록에만 있는 다른 이름/영어 설명 스킬, 빈 목록, 수동 전용, 삭제, 본문 변경, 부분 Read, Unknown skill, 중복, 회사 정책 우선, 작업자 전달, HTML 후속 답변을 검사합니다.
- 설치본 검사: 외부 Python 3.11 이상 방식, 배포 스크립트 18개, 필수 안내서·검증 기록 포함, 같은 버전의 다른 내용 덮어쓰기 거절을 확인했습니다.
- 이전 공개 1.4.12 ZIP을 변경하지 않고 1.4.13으로 실제 업데이트했습니다. 네이티브 Claude 등록·일반 작업 폴더의 SessionStart·개인 Memory/Knowledge/Skill·모델/MCP·사용자 규칙 보존을 확인했습니다.
- 계정/프로젝트 설치·실패 복구·우선 스킬 경로 갱신 검사 통과. CP949 환경과 한글·이모지 경로에서 실행했으며 별도 설치 인코딩 검사 **42개 항목**도 통과했습니다. 모든 설치 검사는 격리된 임시 프로필을 사용했습니다.

재실행 도구:

```text
python -X utf8 -B -m unittest discover -s tests -q
python -X utf8 -B scripts/test-lab/benchmark-skill-list-review.py
python -X utf8 -B scripts/test-lab/probe-skill-transport.py --claude <실제 claude 실행 파일> --scenario native-load
python -X utf8 -B scripts/test-lab/probe-skill-transport.py --claude <실제 claude 실행 파일> --scenario skip-list
python -X utf8 -B scripts/test-lab/probe-skill-transport.py --claude <실제 claude 실행 파일> --scenario skip-list-write
```

테스트는 `company-agent-plugin/scripts`와 `tests`를 PYTHONPATH로 사용합니다. 실제 호스트 검사를 포함하려면 `COMPANY_AGENT_TEST_REAL_CLAUDE=1`을 설정합니다. 전달 검사는 별도 임시 설정·상태·작업 폴더와 localhost 모의 응답만 사용합니다. HCP 이름은 요청 라벨일 뿐 회사 모델을 호출하지 않습니다.

## 성능 측정 범위

동일 PPT 요청, 시작 목록 전달 이후의 준비 함수를 v1.4.12와 각각 격리된 폴더에서 5회 비교했습니다.

| 항목 | 기존 v1.4.12 | 이번 수정 | 실제 로드 후 재사용 |
|---|---:|---:|---:|
| 첫 요청 안내 길이 | 8,855자 | 3,395자 | 3,231자 |
| 준비 함수 중앙값 | 21.37ms | 15.17ms | 19.10ms |
| 목록 캐시 재조회 시 전체 Skill 본문 읽기 | 0회 | 0회 | 0회 |

첫 안내는 **61.7% 감소**했습니다. 이는 글자 수이며 실제 토큰·전체 작업 시간 감소율이 아닙니다. 처음 사용하는 본문은 정상 Skill/Read 호출로 따로 전달됩니다. 해당 도구 호출과 모델 추론·권한 판정·Office 실행 시간은 위 측정에 포함하지 않았습니다. 로컬 처리 시간은 시스템 부하에 따라 달라집니다. 추가 분류 모델 호출 및 필수 선택 기록 CLI는 0회입니다.

## 운영 확인 및 한계

1.4.13 설치본 업데이트 후 새 대화에서 스킬명을 언급하지 않고 원래 PPT 읽기 요청을 재시험해야 합니다. 정상 순서는 목록 기반 후보 안내 → `Skill(company-agent:office-reader)` 또는 정확한 본문 Read → 스킬의 문서 읽기 절차입니다. 키워드에 없는 업무는 전체 목록을 읽고 판단해야 합니다.

1회 교정 이후에도 모델이 계속 무시하면 진단에는 미확인으로 남습니다. 무한 차단을 없애면서 모델의 의미 판단까지 완전히 강제한다고 보장할 수는 없습니다. 실패한 Skill 호출이나 목록 부재를 이유로 가짜 스킬을 만들거나 임의 권한 확대를 하지 않습니다. 운영 모델의 실제 적용 여부는 로드 이후 실행 도구와 최종 읽기 결과까지 확인해야 합니다.
