# 업무별 스킬 선택·중복 질문·Windows 한글 입출력 보완

상태: 1.4.9 배포 소스·설치 묶음에 포함. 이전 1.4.8 설치본과 현재 PC의 설치 설정은 변경하지 않음.

## 변경

- 기존 한 번의 inventory 결과를 재사용해 매 요청 `taskSkills`를 추가합니다. 본문·회사 자료·모델 호출은 추가하지 않습니다.
- 요청의 구두점·첨부 이름 및 한국어 어절 조각을 검색 힌트로 사용합니다. 확장자별 강제 라우터가 아니며, 힌트는 의미상 선택의 증거가 아닙니다.
- 전체 index의 inline/pages/reuse를 유지하면서 관련 후보 설명·정확한 경로를 다시 노출합니다. 후보 최대 3개 이름 그룹, JSON 최대 3,000자입니다. 토큰 수가 아닙니다.
- 같은 이름의 미해결 후보 그룹은 전부 포함하거나 전체 목록 확인으로 넘깁니다. 크기 때문에 일부 후보만 남겨 단일 선택처럼 보이지 않게 합니다.
- 명시 호출·프로젝트/기본 우선 설정을 존중합니다. 이름이 다른 스킬의 의미상 중복은 모델이 설명을 비교한 뒤 질문하도록 지시하며 코드가 의미적 동등성을 보장하지 않습니다.
- 사용자 답 이후 `skill choose`는 현재 session/turn의 임시 선택만 저장합니다. 본문 읽기 기록을 위조하지 않고, 새 turn·목록 변경·압축에서는 임시 선택을 유지하지 않습니다.
- 질문만 했다는 이유로 검증 성공·실패나 학습을 만들지 않습니다. `choose`는 업무 파일 변경이 아닌 내부 준비 기록입니다.
- 선택 누락 시 한 번의 내부 안내에 구체적인 후보를 넣습니다. 도구 거절·승인 자동 허용·Stop 차단은 추가하지 않습니다.
- 등록된 PowerShell 진입점은 Python을 `-X utf8`로 시작합니다. Claude 세션의 자식 Python에는 `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`을 전달합니다. Windows 전역 locale/PATH/개인 프로필은 바꾸지 않습니다.
- Hook 출력은 ASCII-safe JSON으로 보내며 파싱하면 한글이 그대로 복구됩니다. 기존 CLI JSON도 같은 방식을 유지합니다.
- `bin/company-agent.cmd`도 같은 진입점을 거쳐 등록된 Python/설치 범위/개인 상태를 선택합니다. 환경변수 누락 시 다른 기본 상태를 조회하던 우회 경로를 제거했습니다.
- 인코딩 때문에 원본을 변환·재저장하거나 메일/이동/생성을 반복하지 않도록 공통 지침과 작업자 지침에 포함합니다.

## 검증 범위

실행 결과:

- 전체 Python 검사 688개 통과, 제외 0개(123.621초). 격리된 실제 Claude CLI 설정 검사도 활성화했습니다.
- 공통 스킬/목록 명령의 마지막 문구 정리 후 관련 경량 계약 검사 7개 재통과, Claude 플러그인 manifest 검증 통과.
- 로컬 실제 Windows Hook 시험: SessionStart 약 1.064초, UserPromptSubmit 약 0.800초.
  해당 PPT 요청의 후보에 office-reader가 포함됐고 전체 index는 재사용됐습니다. 운영 PC 속도나 모델 판단 시간의 측정은 아닙니다.
- Codex용 quick_validate는 기존 Claude 하네스 필드 `company-agent-role`을 지원하지 않아 거절했습니다.
  해당 필드는 기존 보조 스킬 분류에 필요하므로 제거하지 않았습니다. Claude 검증과 저장소 계약 검사를 별도로 사용했습니다.

`tests/test_task_skill_context.py`는 실제 PPT 요청의 후보 노출, 최초/다음 요청, 대규모 목록,
동일 이름 충돌, 우선 설정, 임시 선택/본문 확인 분리, 잘못된 turn, 직접 호출 전용 스킬,
안내 반복 방지, 상태 기록 분류를 확인합니다.

`tests/test_skill_workflow_native.py`는 실제 Windows PowerShell → Hook → CLI 경로에서
한국어 후보 선택, UTF-8 환경 전달, CP949 부모 환경 및 환경변수 없는 CMD의 설치 범위를 확인합니다.
기존 `tests/test_cli_encoding.py`의 CP949/ASCII/UTF-8 파이프 회귀 검사도 유지합니다.

테스트는 실제 사내 HCP 모델의 자연어 선택 정확도나 운영 DRM/Office 문서 성공률 검사가 아닙니다.
최종 운영 확인은 새 설치본 적용 후 아래 채팅으로 진행해야 합니다.

## 운영 채팅

1. 새 세션에서 `@테스트자료.pptx 여기 PPT 내용을 읽고 MD 파일로 정리해줘.`
   - 전체 목록 반복 조회나 임의 python-pptx 탐색 없이 관련 스킬 본문과 등록 진입점을 사용해야 합니다.
2. 같은 업무의 개인/공통 스킬이 겹치는 테스트 폴더에서 동일 요청.
   - 우선 설정이 없으면 한국어로 출처/차이를 물어야 합니다. 답 전에 파일 작업을 실행하지 않습니다.
3. 개인 후보를 고른 뒤 결과와 설정 확인.
   - 이번 요청에만 적용되고 개인 기본값은 바뀌지 않아야 합니다. 새 요청의 임시 선택은 초기화됩니다.
4. `이 프로젝트는 회사 스킬을 우선 사용해줘.`라고 명시한 뒤 재요청.
   - 설정된 우선순위를 따르고 같은 질문을 반복하지 않아야 합니다.
5. `한글 — 확인 😀.md`처럼 한글·특수문자가 있는 새 결과 파일 요청.
   - 실제 UTF-8 파일 내용과 표시를 구분해 확인하며 기존 파일은 덮어쓰지 않습니다.

인코딩이 여전히 깨지면 원본 파일은 그대로 두고, 실행한 진입점·출력 오류·기존 결과 파일의
인코딩을 확인합니다. 회사 자료 원문을 진단 기록이나 학습에 저장할 필요는 없습니다.
