# 기억과 업무 맥락 사용법

이 하네스의 역할은 **나에 대한 정보를 필요한 만큼 기억하고, 일하는 방식의 교정과 반복 절차를 다음 업무에 활용하는 것**입니다. 업무별 제작기는 필요한 개별 스킬로 따로 선택합니다.

## 1. 무엇을 어디에 남기나요?

| 종류 | 남기는 내용 | 쉬운 예문 |
|---|---|---|
| 개인 기억 | 지속적인 답변 선호와 업무 맥락 | 결론을 먼저 설명하는 방식을 기억해줘. |
| 업무 지식 | 용어와 지표 정의, 출처가 있는 업무 기준 | 이 지표의 정의와 적용 범위를 내 지식으로 정리해줘. |
| 개인 스킬 | 반복할 업무의 입력, 순서, 예외와 확인 방법 | 이 절차를 다음에도 쓰도록 내 스킬로 만들어줘. |
| 학습 기록 | 어떤 근거로 후보를 접수하고 적용하거나 보류했는지 | 이번에 배운 내용과 아직 적용하지 않은 이유를 알려줘. |

원본 대화와 문서 전체를 기억에 복사하지 않습니다. 회사 공용 기준과 개인 보완은 구분합니다. 모델이 추측한 성격이나 민감한 정보는 학습 대상이 아닙니다.

## 2. 저장 범위는 두 가지입니다

**개인 전체**는 같은 개인 설치를 사용하는 여러 업무에 적용할 선호입니다. **이 프로젝트**는 현재 업무 폴더에만 필요한 맥락과 기준입니다. 새 영구 저장 범위가 없을 때만 한 번 묻습니다. 조회나 기존 항목 수정 때는 원래 범위를 유지합니다.

회사 공통 파일은 배포로 바뀌고 개인 자료는 별도 위치에 유지됩니다. 프로젝트 설치는 사용자 전체 설치와 다른 범위를 가질 수 있습니다. 다른 프로젝트와 Claude 자체 기억을 자동으로 합치지 않습니다.

```text
이번 프로젝트의 월간 마감 기준은 매월 마지막 영업일이야. 이 프로젝트의 업무 지식으로 저장하고 적용 범위를 함께 남겨줘.
```

## 3. 학습은 언제 실행되나요?

| 상황 | 처리 |
|---|---|
| 앞으로 계속 적용할 교정을 명확히 말함 | 현재 맥락에 근거가 있으면 개인 학습 후보로 접수 |
| 독립된 업무에서 같은 선택이 반복됨 | 완료와 검증 근거를 함께 보고 반복 패턴인지 판단 |
| 실제 사용한 개인 스킬의 문제를 고쳐 확인함 | 등록된 개인 스킬의 작은 점검 항목에 반영 가능 |
| 일반 인사, 단순 조회, 대기, 대화 압축 | 학습을 위한 별도 호출 없음 |
| 새 스킬이 필요해 보임 | 사용자 요청 또는 제안 수락 후 생성 |

학습 후보를 판단하는 데는 현재 모델의 해석이 포함됩니다. 기록이 쌓였다는 이유만으로 판단이 항상 맞다고 보지 않습니다. 적용 사유와 실제 사용 결과를 함께 확인하세요. 상시 별도 모델이나 종료 후 학습 프로그램을 추가로 돌리지 않습니다.

## 4. 다시 불러올 때는 필요한 것만

현재 요청과 관련된 개인 및 프로젝트 기억을 고릅니다. 기본 회상은 최대 5개, 전체 4,000자 범위이며 모든 기억을 매번 넣지 않습니다. 이미 저장돼도 이번 질문과 관련이 적거나 분량을 넘으면 전달되지 않을 수 있습니다. 전달됨은 모델이 실제로 활용했음을 보증하는 표시가 아닙니다.

```text
내 기억 중 이번 요청에 어떤 내용이 전달됐는지 확인 가능한 범위에서 알려줘.
```

정확한 설명에 필요한 연결 정보가 없으면 그 부분만 미확인으로 두고 업무는 계속합니다. 사용자가 내부 세션 ID나 파일 구조를 찾아올 필요는 없습니다.

## 5. 기억 수정, 학습 중지와 복원

```text
내 보고서 선호에서 소수점은 한 자리로 바꿔줘. 다른 선호는 유지해줘.
```

```text
자동 학습을 잠시 중지해줘. 이미 저장한 기억을 삭제하지는 마.
```

```text
최근 학습으로 바뀐 내용을 보여주고, 내가 고른 변경만 이전 상태로 되돌려줘.
```

기억 수정과 학습 되돌리기는 범위가 다를 수 있습니다. 실제 항목과 버전을 확인한 뒤 요청한 부분만 처리합니다. 수동으로 바꾼 파일을 자동 덮어쓰지 않습니다.

## 6. 설치된 스킬 선택과 재사용

공통, 개인과 프로젝트의 사용 가능한 스킬을 목록으로 비교합니다. 같은 역할이 겹치고 기존 선택이 없을 때만 이름과 출처를 한 번 묻습니다. 사용자가 지정한 스킬과 저장한 우선 선택을 먼저 따릅니다. 관련 스킬이 없으면 가능한 일반 실행을 계속합니다.

`/company-agent:skills`에서 목록과 선택 설정을 볼 수 있습니다. 목록만 보고 싶다고 했을 때 파일이나 우선순위를 바꾸지 않습니다. 하네스에서 기억한 선택과 Claude의 기본 슬래시 이름 우선순위는 같지 않을 수 있으므로 실제 표시되는 정확한 호출명을 사용합니다.

## 7. 개인 스킬을 만들고 수정하기

기본 제작기는 **이미 한 업무의 절차를 저장하는 용도**입니다. 새 스킬은 개인 Claude skills 폴더 또는 프로젝트의 .claude/skills에 한 번 저장하고 같은 원본을 수정합니다. 기존 private 원본과 회사 배포본을 자동 이전하지 않습니다.

```text
주간 업무를 진행, 완료, 확인 필요로 나눴던 절차를 내 스킬로 저장해줘.
```

```text
방금 만든 스킬에 담당자 확인 단계를 추가해줘. 같은 파일을 수정하고 다른 이름의 사본은 만들지 마.
```

실행 코드나 MCP, 웹 자동화 도구를 만드는 작업은 별도 `asset-factory` 개별 스킬에서 제공합니다. 기본 하네스가 모든 업무 도구를 직접 만들어 주는 것은 아닙니다.

## 8. 개별 업무 스킬은 필요한 것만

| 하고 싶은 일 | 선택할 개별 스킬 |
|---|---|
| HTML 보고서 | html-report |
| 편집 가능한 PPT | presentation |
| Excel을 Python 데이터 처리로 구조화 | excel-to-pipeline |
| 파일 정리 | file-organizer |
| 웹 화면 제작과 참고 사이트 재구성 | web-interface, website-rebuild |
| 전체 업무 기록과 흐름 분석 | work-context-catalog |
| Oracle, Datalake, E-Hub 조회 | oracle-query, datalake-query, ehub-query |
| 스크립트, 도구와 MCP 제작 | asset-factory |

개별 스킬 ZIP에는 필요한 코드와 참조가 함께 들어 있습니다. 해당 기능이 필요한 사람만 설치하며 기존에 설치한 개인 스킬은 하네스 업데이트로 지우지 않습니다. 이미지의 자동 VLM 전달 기능은 이번 기본 구성에서 제외했습니다. 현재 모델과 도구가 이미 지원하는 이미지 기능은 그 환경의 동작을 따릅니다.

## 9. 느리거나 불편할 때

```text
최근 이 프로젝트에서 반복 질문이나 실패 때문에 지연된 부분을 사용성 보고서로 정리해줘.
```

사용성 보고서는 요청할 때만 기존 기록을 읽습니다. 자동으로 설정을 고치거나 대화를 압축하지 않습니다. 긴 대화는 현재 업무의 목표와 남은 일, 결과 경로를 남긴 후 Claude가 제공하는 `/compact`를 사용할 수 있습니다. 다른 업무라면 새 대화를 시작하는 편이 낫습니다.

## 10. 업데이트와 이전 설치 파일 정리

1.5.1부터 설치 화면의 **사용하지 않는 이전 설치 파일 삭제 (백업 없음)** 옵션을 선택할 수 있습니다. 기본은 꺼져 있습니다. 선택하면 설치 성공 후 사용하지 않고 배포 원본과 일치하는 이전 설치본과 Claude 플러그인 캐시만 삭제합니다. 개인 기억과 지식, 학습 기록, 스킬, 기존 백업, 작업 파일과 설정은 보존합니다.

Claude가 실행 중이거나 다른 설치 범위에서 쓰는 버전, 원본을 확인할 수 없거나 수정된 파일은 정리를 보류합니다. 로컬 MCP나 다른 플러그인이 있거나 프로젝트 또는 설정을 확인할 수 없는 경우에는 안전을 위해 정리를 보류할 수 있습니다. 정리가 보류되거나 일부만 끝나도 설치 성공은 유지됩니다. 정리할 설치 파일의 새 백업은 만들지 않지만, 기존의 설치 전 개인 자료 안전 백업은 유지합니다.
