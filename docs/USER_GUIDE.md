# Company Agent 사용자 안내서

코딩을 몰라도 시작하는 나만의 업무 도우미

대상 버전 1.1.2 · 작성일 2026년 9월 8일

Company Agent는 평소 사용하는 Claude Code에 업무 처리 방법과 개인 기억을 더해 주는 도우미입니다. 새 프로그램의 복잡한 메뉴를 외울 필요 없이, 하고 싶은 일을 한국어로 설명하면 됩니다. 보고서 초안을 만들고, 자료를 비교하고, 회사 용어를 정리하고, 자주 하는 일을 재사용 가능한 절차로 만들 수 있습니다.

가장 중요한 사용법은 간단합니다. **작은 업무 하나를 맡기고, 결과를 확인하며 원하는 방식을 알려 주세요.** 1.1.0부터는 업무를 마칠 때 재사용할 경험을 자동으로 검토합니다. 분명하게 고쳐 준 선호와 반복되는 선택을 바탕으로 개인 기억과 업무 절차를 발전시킵니다. 개인 자료는 공통 프로그램을 업데이트하는 영역과 분리해 보관합니다.

이 안내서는 설치가 끝난 사용자를 기준으로 합니다. 예문은 Claude Code에 입력하는 요청이며, 버튼 하나로 결과가 보장되는 기능 목록은 아닙니다. 실제 결과는 제공한 자료, 연결된 사내 도구, 사용 가능한 모델에 따라 달라집니다. 예문 속 날짜·이름·부서·업무 기준은 연습용입니다. 실제 업무에서는 본인의 자료와 승인된 기준으로 바꿔 주세요.

1.1.2에서는 일부 회사 PC의 ‘관리자 권한’ 설치 오류를 보완하고, 본인이 쓰는 Claude 프로그램과 개인 설정 위치를 각각 확인합니다. 이미 사용 중인 Company Agent는 **업데이트**로 안내합니다. 자동 학습 사용법은 1.1.0부터 이어지며, 새 버전 적용 방법과 완료 화면은 17장에 설명되어 있습니다. 이 안내서를 읽거나 새 ZIP을 받는 것만으로 PC의 기존 설치가 바뀌지는 않습니다.

## 1 가장 먼저 이것만 해보세요

### 설치가 끝났다면

1. 열려 있는 Claude Code를 종료한 뒤 다시 엽니다.
2. 평소 회사에서 안내받은 방식으로 업무 폴더에서 Claude Code를 시작합니다.
3. 아래 문장을 입력합니다. 설치 명령을 다시 실행할 필요는 없습니다.

업무 폴더는 자료와 결과물을 모아 두는 폴더입니다. Company Agent는 따로 여는 업무 앱이 아니라 Claude Code 안에서 사용합니다. 설치 프로그램의 선택 화면이 아니라 **Claude가 답하는 대화 입력줄**에 예문을 입력하세요. 대화창을 여는 방법부터 모른다면 회사에서 안내한 Claude Code 시작 방법을 먼저 확인하세요.

```text
Company Agent를 처음 사용해.
지금 적용된 설치 범위와 개인 자료 저장 위치를 확인해줘.
내가 사용할 수 있는 기능을 쉬운 말로 설명해줘.
실제로 확인한 것과 아직 확인할 수 없는 것은 구분해줘.
설정은 바꾸지 말아줘.
```

확인 결과에서 현재 작업 폴더와 개인 자료 저장 위치를 살펴보세요. Company Agent를 찾지 못했다면 설치 성공 문구만 믿고 계속 진행하지 말고, 16장의 확인 방법을 이용하세요.

### 첫 업무는 짧은 글 정리로 시작하기

```text
아래 내용을 팀장님께 공유할 짧은 업무 보고로 정리해줘.
완료한 일, 진행 중인 일, 도움이 필요한 일로 나눠줘.
내가 적지 않은 담당자나 완료일은 만들어 넣지 말아줘.

설비 점검표 수정 완료.
현장 확인은 진행 중이고 내일 오후에 결과를 받을 예정.
새 양식 적용일은 아직 결정되지 않음.
```

결과에는 ‘점검표 수정 완료’, ‘현장 확인 진행 중’, ‘양식 적용일 결정 필요’가 구분되어야 합니다. 아직 정해지지 않은 날짜를 확정 일정으로 적었다면 바로 고쳐 달라고 하세요. 이 첫 연습에는 회사 데이터 조회나 메일 연결이 필요하지 않습니다.

### 처음부터 잘 말하려고 애쓰지 않아도 됩니다

```text
하고 싶은 일은 있는데 어떻게 설명해야 할지 모르겠어.
이번 주 업무 내용을 한 장으로 정리하고 싶어.
꼭 필요한 것만 쉬운 질문으로 물어봐줘.
```

중요한 정보가 부족하면 짧은 질문이나 선택지가 나올 수 있습니다. 예를 들어 ‘누가 볼 자료인가요?’라는 질문에는 ‘팀장님이 볼 거예요’라고 답하면 충분합니다. 화면 환경에 따라 선택 버튼 대신 번호나 글로 답하는 방식이 나올 수도 있습니다.

## 2 어떤 일을 맡길 수 있나요

Company Agent가 더해 주는 것은 업무의 정리·검토 절차와 개인화 기능입니다. 글을 쓰고 자료를 해석하는 기본 능력은 기존 Claude Code와 사내 모델을 사용합니다.

| 하고 싶은 일 | 시작하는 방법 | 먼저 알아둘 점 |
| --- | --- | --- |
| 보고서와 업무 공유문 초안 | 메모를 주고 독자와 원하는 분량을 설명 | 제공하지 않은 사실은 확인 필요로 남기기 |
| 회의록과 할 일 정리 | 회의 메모나 읽을 수 있는 파일 제공 | 자동 녹음이나 회의 참석 기능은 기본 제공하지 않음 |
| 문서 비교와 변경점 확인 | 비교할 두 자료와 비교 기준 지정 | 원본 수정 없이 비교부터 요청 가능 |
| 표와 숫자 검토 | 표를 붙여 넣거나 읽을 수 있는 파일 지정 | 단위·기간·중복·계산 기준을 함께 확인 |
| 메일 초안 작성 | 전달할 내용과 수신자 관계 설명 | 초안 작성과 실제 발송은 별개 |
| 개인 취향과 업무 기준 기억 | 앞으로 적용할 내용을 명확히 요청 | 개인 기억 저장 후 확인 필요 |
| 회사 용어와 데이터 설명 축적 | 실제 정의·출처·적용 범위 제공 | 배포된 회사 지식과 개인 보완을 구분 |
| 자주 하는 업무를 절차로 만들기 | 반복해서 할 일을 설명하고 스킬 제작 요청 | 만들어진 절차를 대표 업무로 시험하기 |
| 프로젝트 전용 업무 도우미 구성 | 대상 폴더·목적·원하는 결과 설명 | 구성 생성과 실제 업무 완료는 별개 |
| 회사 데이터 조회와 메일 발송 | 회사 담당자가 연결한 도구 이용 | 연결과 권한 확인 후 가능 |

### 설치만으로 모두 제공되지는 않는 것

Word·Excel·PowerPoint·PDF 파일을 정교하게 읽고 만들려면 해당 작업을 지원하는 도구가 추가로 필요할 수 있습니다. Python이 설치되어 있다는 사실만으로 모든 문서 작업이 가능한 것은 아닙니다. 막히면 표를 복사해 붙여 넣거나, 사내에서 허용된 텍스트·CSV 형태로 자료를 제공할 수 있습니다.

회사 자료실 전체를 이미 알고 있거나, Outlook을 자동으로 연결하거나, 인터넷에서 도구를 내려받는 기능도 기본 설치에 포함되어 있지 않습니다. 현재 소스의 기본 회사 지식 묶음에는 작성용 틀만 있고 실제 회사 용어는 들어 있지 않습니다. 담당자가 채워 배포하거나 사용자가 개인 지식으로 보완해야 합니다.

```text
이 파일로 작업하기 전에 읽을 수 있는지 먼저 확인해줘.
필요한 도구가 없다면 무엇이 부족한지 쉬운 말로 알려주고,
지금 가능한 대체 방법을 제안해줘.
인터넷에서 프로그램을 내려받거나 원본을 바꾸지는 말아줘.
```

## 3 요청할 때 알려주면 좋은 네 가지

길게 설명하기보다 **무엇을 할지, 어떤 자료를 쓸지, 어떤 결과를 원하는지, 무엇을 조심할지**를 알려 주세요. 모두 정해져 있지 않으면 아는 것만 적어도 됩니다.

```text
하려는 일: 지난주 업무를 부서장에게 보고하려고 해.
사용할 자료: 아래에 붙인 업무 메모만 사용해줘.
원하는 결과: 핵심 내용 다섯 줄과 확인이 필요한 사항 목록.
주의할 점: 미완료 업무를 완료로 쓰지 말고, 추측은 따로 표시해줘.
```

### 파일을 사용할 때

‘바탕화면에 있는 그 파일’보다는 정확한 파일 이름이나 위치를 알려 주세요. 파일명에 공백이나 한글이 있어도 됩니다. 아래 경로는 예시이므로 실제 경로로 바꿔야 합니다.

```text
C:\Work\주간보고\업무메모.txt를 읽고 주간보고 초안을 만들어줘.
원본 파일은 그대로 두고 결과는 먼저 대화창에 보여줘.
파일을 읽지 못하면 읽지 못했다고 알려줘.
```

결과를 파일로 남기고 싶다면 저장까지 요청하세요. 대화창에 글이 보이는 것과 파일이 만들어진 것은 다릅니다.

```text
확인한 초안을 이 업무 폴더에 새 텍스트 파일로 저장해줘.
같은 이름의 파일이 있으면 덮어쓰지 말고 먼저 알려줘.
저장 후 파일을 다시 읽어 내용이 들어 있는지 확인하고 위치를 알려줘.
```

### 질문이 나왔을 때

정확한 기간, 결과물을 받을 사람, 적용할 기준처럼 결과를 바꾸는 정보만 답하면 됩니다. 답을 모를 때는 ‘아직 몰라. 미정으로 표시해줘’라고 말하세요. 질문이 너무 많으면 ‘우선 초안을 만들고 꼭 필요한 질문 하나씩만 해줘’라고 요청할 수 있습니다.

권한 허용 화면이 나오면 파일 읽기인지, 수정인지, 실행인지 확인하세요. Company Agent가 설치되어 있어도 모든 권한을 무조건 허용해야 하는 것은 아닙니다. 이해되지 않는 요청에는 무엇을 왜 하려는지 설명을 먼저 요구하세요.

## 4 업무 예시 하나 주간보고 만들기

### 상황과 첫 요청

업무 메모는 있지만 보고 형식으로 정리하는 데 시간이 걸리는 상황입니다. 아래 내용을 그대로 연습해 볼 수 있습니다.

```text
아래 메모를 주간보고 초안으로 정리해줘.
독자는 팀장님이고, 1분 안에 읽을 수 있으면 좋겠어.
완료, 진행 중, 의사결정 필요 순서로 작성해줘.

검사 체크리스트 개정안 작성 완료.
개정안은 담당자 검토 중이며 승인된 것은 아님.
현장 의견 두 건은 반영했지만 추가 의견은 아직 확인 중.
다음 주부터 적용할지는 팀장님 결정이 필요함.
```

### 결과를 확인하는 방법

‘개정안 작성 완료’와 ‘개정안 승인 완료’는 다릅니다. 보고서가 이 둘을 구별했는지 확인하세요. 현장 의견의 건수, 미확정 일정, 필요한 결정도 원문과 맞아야 합니다.

더 나은 결과를 위해 다음처럼 구체적으로 고칩니다.

```text
작성 완료와 승인 완료가 혼동되지 않도록 고쳐줘.
첫 줄에 팀장님이 결정해야 할 내용을 배치해줘.
이번 보고서는 표 대신 짧은 문장으로 작성해줘.
```

### 다음 업무에도 이어가기

결과가 만족스러우면 이번에만 적용할 수정과 계속 쓸 기준을 구분해 주세요.

```text
앞으로 팀장님께 드리는 보고는 결정이 필요한 내용을 먼저 쓰는 걸 기억해줘.
다만 표를 쓰지 말라는 요청은 이번 보고서에만 해당해.
계속 기억할 내용만 짧게 저장하고, 저장한 내용을 확인해줘.
```

이렇게 하면 일회성 요구가 모든 보고서에 잘못 적용되는 것을 줄일 수 있습니다. 실제 저장은 Claude가 Company Agent의 저장 절차를 수행해야 하므로, 마지막의 저장 확인을 확인하세요.

## 5 업무 예시 둘 회의 메모에서 할 일 찾기

### 회의 메모를 회의록으로 바꾸기

```text
아래 회의 메모를 정리해줘.
결정된 사항, 해야 할 일, 아직 정하지 못한 사항으로 나눠줘.
할 일에는 담당자와 기한을 표시하되, 없으면 미정이라고 써줘.

신규 점검 양식은 다음 회의에서 다시 검토하기로 함.
김 담당이 기존 양식과 달라진 항목을 정리하기로 함.
현장 시범 적용 부서는 아직 정하지 않음.
정리 자료의 제출 기한은 논의하지 않음.
```

결과에는 담당자가 있는 일과 없는 일이 구분되어야 합니다. ‘다음 회의에서 검토’가 ‘적용 확정’으로 바뀌면 안 됩니다. 기한을 논의하지 않았다면 임의로 이번 주 금요일이라고 정하면 안 됩니다.

### 회의 후 공유문까지 만들기

```text
방금 회의록을 참석자에게 보낼 업무 공유문으로 줄여줘.
결정되지 않은 부분은 확정처럼 보이지 않게 써줘.
지금은 공유문 초안만 만들고 메일은 보내지 말아줘.
```

회의 메모를 정리하는 작업은 실제 회의를 듣거나 자동으로 참석자를 확인하는 기능과 다릅니다. 메모에 없는 내용이 필요하면 사용자가 추가해 주세요.

## 6 업무 예시 셋 숫자와 문서 비교하기

### 숫자 계산과 해석을 나눠서 보기

다음 표는 연습용 데이터입니다. 회사의 실제 불량률 정의와는 무관합니다.

```text
아래 수치를 확인하고 주차별 불량률을 계산해줘.
이번 계산에서 불량률은 불량 수량을 생산 수량으로 나눈 비율이야.
이 기준은 연습용이므로 회사 지식으로 저장하지 말아줘.

1주차 생산 1000개, 불량 20개
2주차 생산 1200개, 불량 18개

계산식과 결과를 함께 보여주고,
수치로 확인되는 변화와 원인에 대한 추측은 구분해줘.
```

확인할 계산 결과는 1주차 2.0%, 2주차 1.5%입니다. 비율의 차이는 0.5%포인트 감소입니다. 이 수치만으로 설비 개선이 원인이라고 결론 내릴 수는 없습니다. 원인을 판단하려면 추가 자료가 필요합니다.

### 큰 파일을 바로 수정하지 않기

파일을 정리할 때는 먼저 읽기 가능 여부와 구조를 확인하게 하세요. ‘중복을 지워줘’만 말하면 무엇을 중복으로 볼지 불분명합니다.

```text
이 CSV 파일을 수정하지 말고 먼저 확인해줘.
열 이름, 전체 행 수, 값이 없는 항목, 중복으로 의심되는 행을 요약해줘.
중복 판단 기준은 내가 정할 수 있게 설명해줘.
정리 결과를 저장할 때도 원본은 남겨줘.
```

### 문서 두 개의 차이 확인하기

```text
이전 안내문과 새 안내문을 비교해줘.
단순한 표현 수정과 실제 업무 기준 변경을 구분해줘.
업무 기준이 달라진 부분은 두 문서의 해당 문장을 근거로 보여줘.
파일을 수정하지 말고 비교 결과만 알려줘.
```

PDF나 Office 파일을 읽을 도구가 없다면 비교할 부분을 텍스트로 제공할 수 있습니다. 읽지 못한 파일까지 비교를 끝냈다고 보고하지 않았는지 확인하세요.

## 7 업무 예시 넷 메일과 회사 데이터 사용하기

### 메일 초안은 연결 없이도 시작할 수 있습니다

```text
다른 부서에 검토 자료를 요청하는 메일 초안을 써줘.
이번 주 목요일 오후까지 받고 싶고, 부담스럽지 않은 정중한 말투로 써줘.
제목과 본문을 나눠줘. 실제 발송은 하지 말아줘.
수신자 이름과 요청 자료명은 아직 미정이니 표시해줘.
```

초안을 확인한 뒤 실제로 보내고 싶다면 발송을 별도로 요청해야 합니다. 회사의 Outlook 연결 도구인 `corp-outlook-self`가 준비되어 있고 본인 계정으로 연결되어 있어야 합니다. 설치 프로그램이 대신 연결해 주는 것은 아닙니다.

```text
확인한 메일을 내 Outlook 계정으로 보내고 싶어.
지금 사용 가능한 회사 메일 연결과 발신 계정을 먼저 확인해줘.
수신자나 첨부처럼 빠진 정보가 있으면 물어봐줘.
보낸 뒤에는 실제 발송 확인 여부를 알려줘.
연결이 없으면 초안만 유지하고 보내지 말아줘.
```

다른 사람이나 공용 메일함 명의로 보내도록 요청하지 마세요. 본인 계정으로만 보내도록 하는 제한은 회사에서 연결한 메일 도구가 실제로 적용해야 합니다.

발송 중 오류가 나면 바로 ‘다시 보내줘’라고 하지 않는 편이 좋습니다. 이미 발송됐는데 응답만 끊겼을 수 있습니다.

```text
같은 메일이 이미 보내졌는지 먼저 확인해줘.
발송 여부를 확인할 수 없으면 재발송하지 말고 알려줘.
```

### 회사 데이터는 연결된 조회 도구로 확인합니다

회사 데이터 조회 도구인 `corp-db-read`가 연결되어 있어야 합니다. 회사 용어 설명 문서가 있다는 것만으로 실제 데이터에 접속할 수 있는 것은 아닙니다.

```text
연결된 회사 데이터 조회 도구가 있는지 확인해줘.
있다면 지난주 생산 현황을 라인별로 요약하고 싶어.
기간과 수량 기준이 모호하면 먼저 물어봐줘.
등록된 용어와 데이터 설명을 참고하고, 사용한 기준을 결과에 적어줘.
데이터는 조회만 하고 추가하거나 수정하거나 삭제하지 말아줘.
```

데이터를 새로 넣거나 수정·삭제하는 요청은 지원 범위 밖입니다. 조회 권한이 없거나 대상 정보가 등록되지 않았다면 다른 경로로 우회하지 말고 담당자에게 확인하세요. Company Agent의 지침만으로 회사 전체 데이터 접근 권한이 통제되는 것은 아닙니다.

## 8 내 업무 방식을 기억시키기

### 개인 기억과 회사 지식과 스킬은 다릅니다

이름을 외울 필요는 없지만, 무엇을 남기려는지 구분하면 잘못 저장되는 일을 줄일 수 있습니다.

| 남길 내용 | 쉬운 설명 | 요청 예시 |
| --- | --- | --- |
| 개인 기억 | 나의 선호와 지속적인 업무 맥락 | 앞으로 설명은 쉬운 한국어로 해줘 |
| 개인 지식 | 회사 용어와 업무 사실에 대한 내 기록 | 이 지표의 계산 기준과 출처를 등록해줘 |
| 스킬 | 여러 번 재사용할 일의 순서와 확인 기준 | 주간보고 만드는 절차를 스킬로 만들어줘 |

### 기억시키는 방법

```text
앞으로 답변은 결론을 먼저 말하고, 근거는 그다음에 설명해줘.
처음 나오는 어려운 용어는 한 번만 쉽게 풀어줘.
이 내용을 내 응답 선호로 기억하고, 저장한 내용을 보여줘.
```

명확하게 ‘앞으로’, ‘기억해줘’라고 요청하면 해당 내용을 짧게 추려 저장하도록 구성되어 있습니다. 1.1.0부터는 이런 표현이 없어도 사용자가 직접 고쳐 준 지속적인 선호와 반복해서 선택한 업무 방식을 자동 검토합니다. 추측한 선호는 한 번에 확정하지 않고 관찰을 쌓습니다. 다음 요청에서는 관련 있는 기억 일부를 찾아 참고하며, 모든 기억을 매번 전부 읽는 방식은 아닙니다.

### 기억이 맞는지 확인하고 고치기

```text
보고 방식과 관련해서 저장된 내 개인 기억을 찾아 보여줘.
어느 설치 범위의 기억을 확인했는지도 알려줘.
지금은 수정하지 말아줘.
```

```text
예전에는 보고서를 다섯 줄로 요청했지만 앞으로는 열 줄 이내로 해줘.
같은 보고 분량에 대한 기존 기억이 있으면 그 항목을 수정해줘.
서로 다른 두 기준이 동시에 적용되지 않도록 확인해줘.
```

더 이상 적용하고 싶지 않으면 ‘이 기준은 앞으로 사용하지 않도록 정리해줘. 어떤 항목을 바꾸는지 알려줘’라고 요청하세요. 과거 수정 이력이 남는 것과 현재 업무에서 사용되는 것은 별개입니다. 기억을 사용하지 않게 바꾸는 것이 관련 파일과 이력의 완전 삭제를 뜻하지는 않습니다.

### 무엇을 기억시키지 않는 것이 좋을까요

비밀번호, 인증정보, 메일 본문 전체, 고객별 상세 내역, 조회 결과 전체를 개인 기억으로 저장하지 마세요. 계속 쓸 기준만 남기고, 일회성 결과는 해당 업무 파일로 관리하는 편이 좋습니다.

Company Agent는 개인화 저장소에 전체 대화를 별도로 복제하지 않습니다. 다만 Claude Code 자체의 대화 기록 설정은 그대로이므로, ‘대화가 어디에도 저장되지 않는다’는 뜻은 아닙니다.

## 9 회사 용어와 업무 지식 쌓기

### 회사에서 받은 기본 설명에 내 경험을 보태기

회사가 제공하는 공통 설명은 기본 자료입니다. 사용자는 자신의 업무에서 발견한 주의점이나 예외를 개인 기록으로 추가할 수 있습니다. 개인 기록을 수정한다고 다른 직원의 공통 설명까지 바뀌지는 않습니다.

아래는 가상의 용어 예시입니다. 실제 기준과 출처를 알고 있을 때 사용하세요.

```text
우리 업무에서 사용하는 '완료 건수'의 뜻을 개인 지식으로 등록해줘.
기준은 검토 승인이 끝난 건수이고, 접수만 된 건은 포함하지 않아.
적용 범위는 우리 팀의 주간 현황 보고야.
출처는 내가 제공한 주간보고 작성 기준 문서야.
기존에 같은 설명이 있으면 먼저 비교하고,
회사 전체의 기준으로 단정하지 말아줘.
```

출처 문서를 주지 않았다면 실제로 읽은 근거처럼 적지 않게 하세요. ‘담당자에게 들은 내용이며 문서 확인은 아직 안 됨’처럼 출처의 상태도 명확히 할 수 있습니다.

### 테이블 설명도 말로 정리할 수 있습니다

데이터를 담는 표의 이름, 각 항목의 뜻, 날짜의 의미, 제외할 상태 등을 기록할 수 있습니다. 어려운 형식의 파일을 직접 작성할 필요는 없습니다.

```text
내가 전달한 이 데이터 설명을 개인 지식으로 정리해줘.
데이터 이름, 한 행이 뜻하는 것, 주요 항목, 날짜 기준,
조회할 때 주의할 점으로 나눠줘.
모르는 항목은 추측하지 말고 확인 필요로 남겨줘.
일회성 조회 결과나 상세 개인정보는 포함하지 말아줘.
```

단순히 파일을 아무 폴더에 복사했다고 자동으로 회사 지식에 등록되는 것은 아닙니다. Company Agent에게 등록을 요청하고, 저장 후 다시 찾아지는지 확인하세요. 공통 프로그램이 설치된 폴더를 직접 편집하지 않는 것이 좋습니다.

### 공통 설명과 개인 기준이 다르면

공통 기준에 설명을 덧붙이는 것인지, 특정 업무에서만 다른 기준을 쓰는 것인지 구분해야 합니다.

```text
이 기준은 회사 공통 기준을 바꾸려는 것이 아니야.
이 프로젝트의 참고 분석에서만 적용할 개인 기준으로 구분해줘.
공통 기준과 다른 부분을 결과에 표시해줘.
```

다른 기준을 쓰더라도 회사 보안 규칙이나 접근 권한을 완화할 수는 없습니다. 회사에서 새 지식을 배포한 뒤 내 기록과 충돌하면, 어느 쪽을 쓸지 확인이 필요할 수 있습니다. 개인 보완의 기준이 되는 회사 항목이 없어지면 기록은 남아도 업무 참고에서 빠질 수 있으므로 점검을 요청하세요.

## 10 잘된 업무를 반복해서 쓰는 스킬로 만들기

스킬은 ‘이 일을 할 때 따라갈 작업 방법’입니다. 예를 들어 주간보고를 만드는 순서, 빠지면 안 되는 항목, 결과를 확인하는 기준을 한 번 정리해 두고 다음에 다시 활용할 수 있습니다.

### 작은 절차 하나부터 만들기

보고서 한 번을 잘 만든 뒤 다음처럼 요청해 보세요.

```text
방금 확인한 주간보고 작성 방법을 개인 스킬로 만들어줘.
다음에도 업무 메모를 주면 같은 순서로 정리하고 싶어.
입력 자료, 작성 순서, 결과 형식, 확인할 항목을 포함해줘.
담당자와 일정이 없으면 지어내지 말고 미정으로 표시하게 해줘.
이름이 같은 기존 스킬이 있는지 먼저 확인하고,
만든 뒤 이번 메모로 한 번 시험해줘.
메일 발송이나 자동 예약 실행은 포함하지 말아줘.
```

개인 스킬은 만들어지면 별도의 전사 승인이나 승격 없이 사용 대상으로 등록됩니다. 하지만 자동으로 사용할 수 있다는 것과 검증된 완벽한 절차라는 것은 다릅니다. 실제 자료 한 건으로 결과를 확인하세요.

### 다음에 다시 사용하기

```text
지난번 만든 주간보고 스킬을 찾아서 이번 업무 메모에 적용해줘.
실제로 어떤 스킬을 사용하는지 먼저 확인해줘.
맞는 스킬을 찾지 못하면 비슷한 방법을 썼다고 넘기지 말고 알려줘.
```

개인 스킬이 모두 슬래시 메뉴에 나타나는 것은 아닙니다. Company Agent가 업무에 맞는 스킬 파일을 찾아 읽고 사용하는 방식도 포함되어 있습니다. 메뉴에 안 보인다고 바로 다시 설치하거나 새로 만들 필요는 없습니다.

### 결과가 어긋나면 스킬도 고치기

```text
이번에는 승인 전인 일을 완료 항목에 넣었어.
현재 보고서를 고치고, 앞으로 같은 실수를 줄이도록
이 주간보고 스킬의 확인 기준에도 반영해줘.
승인 완료, 승인 대기, 상태 미상인 예시로 각각 시험해줘.
```

1.1.0부터는 실제로 읽어 사용한 개인 스킬에 재사용할 개선점이 있는지 자동 검토합니다. 검증된 오류 수정이나 충분한 관찰이 있으면 작은 확인 절차를 덧붙일 수 있습니다. 이번 수정이 반드시 스킬에 남아야 한다면 ‘스킬에도 반영해줘’라고 명확히 요청할 수도 있습니다. 공통 스킬이나 다른 플러그인을 자동으로 고치는 기능은 아닙니다.

## 11 스킬이 겹치거나 여러 개일 때 고르기

이미 사용하던 스킬과 새로 만든 스킬의 이름이 같을 수 있습니다. Company Agent는 지원하는 로컬 위치를 살펴보고 같은 이름의 후보와 출처를 보여줄 수 있습니다. 기능이 비슷하지만 이름이 다른 스킬까지 모두 자동으로 중복 판정하는 것은 아닙니다.

### 목록을 보는 가장 확실한 진입 방법

Claude가 답하는 대화 입력줄에 다음을 입력합니다. `PS C:\...>` 같은 Windows 명령 입력줄에 입력하는 설치 명령이 아닙니다.

```text
/company-agent:skills
```

명령 이름을 외우기 싫으면 아래처럼 요청해도 됩니다.

```text
Company Agent에서 사용할 수 있는 스킬을 업무별로 간단히 보여줘.
같은 이름이 겹치는 경우에는 어디서 온 것인지 알려줘.
지금은 목록만 보고 선택은 바꾸지 않을게.
```

### 이 프로젝트에서만 선호하는 스킬 정하기

```text
이 프로젝트에서는 방금 만든 개인 주간보고 스킬을 우선 사용하고 싶어.
같은 이름의 후보를 보여주고 내가 고를 수 있게 해줘.
다른 프로젝트의 기본 선택은 바꾸지 말아줘.
선택한 뒤 실제로 어떤 스킬이 적용되는지 확인해줘.
```

‘이 프로젝트만’은 해당 프로젝트에 적용할 선택입니다. ‘기본값’은 현재 사용 중인 개인 저장소에서 사용할 기본 선택입니다. 별도로 프로젝트 범위에 설치했다면 전체 범위 설치와 기본값이 자동으로 합쳐지지 않습니다.

이 선택은 Company Agent가 찾아 읽는 스킬에 적용됩니다. Claude의 일반 `/이름` 명령 전체의 우선순위를 바꾸거나 다른 플러그인의 실행을 강제로 바꾸지는 않습니다. 혼동될 때는 Company Agent를 통해 사용할 후보를 선택해 주세요. 기존 스킬 원본을 지우거나 이름을 바꿀 필요는 없습니다.

## 12 프로젝트마다 다른 업무 도우미 만들기

### 프로젝트는 한 업무를 모아 둔 폴더입니다

코드가 들어 있어야만 프로젝트인 것은 아닙니다. ‘월간 품질보고’, ‘설비 점검 개선’, ‘신규 직원 안내서’처럼 관련 자료와 결과물을 모아 둔 폴더도 대상이 될 수 있습니다.

프로젝트 도우미는 그 폴더에서 어떤 순서로 작업하고 무엇을 확인할지 구성해 줍니다. 자료 정리, 초안 작성, 수치 확인처럼 단계가 여러 개인 일을 반복할 때 유용합니다. 짧은 문장 하나를 고치는 일에는 굳이 만들 필요가 없습니다.

### 프로젝트 폴더에서 이렇게 요청하기

```text
이 프로젝트 하네스를 구성해줘.
이 폴더에서는 매달 품질 현황 보고서를 만들 거야.
제공된 자료 확인, 지표 계산, 보고 초안 작성,
수치와 근거 확인 순서로 진행하고 싶어.
아직 모르는 업무 기준은 나에게 물어봐줘.
기존 파일은 먼저 살펴보고 함부로 덮어쓰지 말아줘.
완성되면 내가 다음에 입력할 문장도 알려줘.
```

‘하네스’는 여기서 업무 도우미의 구성이라는 뜻입니다. 이 단어를 기술적으로 이해할 필요는 없습니다. 대상 폴더가 분명하지 않으면 폴더 위치를 물을 수 있고, 어떤 결과물을 만들지 정해지지 않았다면 필요한 선택만 물을 수 있습니다.

구성이 끝나면 해당 프로젝트에서 Claude Code를 다시 시작하고 안내받은 문장으로 대표 업무를 한 번 실행해 보세요. 구성 파일이 만들어졌다는 사실만으로 보고서 품질까지 검증된 것은 아닙니다.

### 업무가 바뀌면 구성도 바꾸기

```text
이 프로젝트의 보고서 구성에 전월 대비 변화 설명을 추가해줘.
기존 지표 정의와 직접 수정한 자료는 보존해줘.
원본과 충돌하는 변경이 있으면 차이를 쉽게 설명해줘.
변경 후 대표 자료로 새 단계가 제대로 작동하는지 확인해줘.
```

### 설치 범위와 프로젝트 구성을 혼동하지 않기

| 구분 | 무엇을 정하나요 | 기억할 점 |
| --- | --- | --- |
| Claude 전체에 설치 | 현재 Windows 계정의 여러 작업에서 Company Agent 사용 | 같은 설치의 개인 기억을 여러 업무에서 참고 가능 |
| 이 프로젝트에 설치 | 선택한 프로젝트에서 Company Agent 사용 | 프로젝트 설치의 개인 저장소를 별도로 사용 |
| 프로젝트 도우미 구성 | 특정 폴더의 업무 순서와 확인 기준 만들기 | 전체 설치 사용자도 필요한 프로젝트에 만들 수 있음 |

전체 설치와 프로젝트 설치를 둘 다 했다면 해당 프로젝트 안에서는 프로젝트 설치의 개인 자료를, 그 밖의 작업에서는 전체 설치의 개인 자료를 사용합니다. 두 범위의 기억과 선택이 하나로 자동 합쳐지지는 않습니다. 혼동되면 먼저 ‘현재 쓰는 개인 저장 위치와 프로젝트를 확인해줘’라고 요청하세요. 다른 폴더에서도 같은 구성이 작동할 것이라고 가정하지 마세요.

## 13 나에게 필요한 작은 도구 만들기

스킬만으로 충분하지 않은 반복 계산이나 파일 변환은 작은 실행 도구로 만들 수 있습니다. 회사 시스템과 연결하는 도구는 보통 MCP라고 부릅니다. 사용자는 이 이름을 구분하기보다 하려는 일과 허용 범위를 설명하면 됩니다.

### 파일 정리 도구를 요청하는 예시

```text
매번 받는 CSV에서 날짜 형식이 잘못된 행을 찾아주는 도구를 만들고 싶어.
원본은 수정하지 말고 확인 결과만 별도 파일로 만들게 해줘.
어떤 날짜 형식을 정상으로 볼지는 먼저 나에게 물어봐줘.
정상 날짜, 잘못된 날짜, 빈 값, 빈 파일을 넣어 시험해줘.
사내에 이미 준비된 도구만 사용하고 부족한 것은 알려줘.
```

Company Agent는 입력과 결과의 형태, 필요한 권한, 시험 방법을 정하고 구조와 실행 결과를 검사하도록 구성되어 있습니다. 실행 도구와 연결 도구는 필요한 검사를 통과한 뒤 사용하도록 등록합니다. 코드를 바꾸면 이전 검사 결과를 그대로 재사용하지 않고 다시 검사해야 합니다.

### 초보자가 특히 확인할 부분

- 어떤 파일을 읽고 어떤 파일을 만드는지 확인합니다.
- 인터넷이나 다른 프로그램 실행 권한이 왜 필요한지 설명을 듣습니다.
- 회사 연결 도구를 대체하여 권한을 우회하게 만들지 않습니다.
- 작은 복사본이나 연습 자료로 먼저 시험합니다.

이 검사는 실수를 줄이기 위한 절차이지, 만든 도구를 PC와 완전히 격리하는 장치는 아닙니다. 실행 도구는 현재 Windows 계정의 권한으로 동작합니다. 사내에서 승인한 부품이 없어서 멈추면 필요한 준비물을 담당자에게 전달하세요. 인터넷 설치를 우회 방법으로 요구하지 마세요.

## 14 사용할수록 어떻게 발전하나요

### 현실적인 발전 방식

Company Agent는 1.1.0부터 업무가 끝날 때 자동으로 경험을 정리하고, 개인 기억과 기존 개인 스킬의 확인 절차를 개선한 뒤 다음 사용 결과를 연결합니다. 모델 자체를 다시 학습시키는 것은 아닙니다. 관찰할 내용이 없는 짧은 질문에는 억지로 기억을 만들지 않습니다.

예를 들어 보고서를 고칠 때마다 ‘결정이 필요한 내용을 먼저 보여줘’라고 선택한다면, 이런 선호를 관찰합니다. 같은 선택이 서로 다른 요청에서 반복 확인되면 개인 기준으로 적용할 수 있습니다. 장기적으로 적용할 분명한 사용자 교정은 더 빨리 반영할 수 있습니다. 이번에만 바꾸라는 요구나 아무 말 없이 넘어간 상황은 지속적인 선호나 만족의 증거로 취급하지 않습니다.

개인 스킬로 만든 보고서에서 승인 대기 항목이 빠졌고, 수정 후 확인까지 했다면 다음에는 해당 항목을 확인하도록 점검 절차를 보완할 수 있습니다. 다음 보고서에서는 그 버전을 실제로 사용했는지와 검증·실패 기록을 연결합니다. 비교할 기록이 부족하면 ‘효과 확인 중’으로 남기며, 오류가 줄었다고 무조건 개선 효과가 입증되었다고 말하지 않습니다.

자동 개선이 해로웠다는 근거가 있으면 해당 자동 변경만 되돌리는 절차를 사용합니다. 개인 선호는 자동 적용을 멈추고, 스킬은 자동 점검 영역을 이전 상태로 돌립니다. 사용자가 직접 수정한 부분과 충돌하면 덮어쓰지 않고 알려 줍니다. 이 복구는 업무 파일 전체나 이미 보낸 메일을 되돌리는 기능은 아닙니다.

업무를 마무리할 때 다음 세 가지를 분명하게 나누면 도움이 됩니다.

1. **이번 결과만 수정하기**: 현재 보고서의 잘못된 표현이나 숫자를 고칩니다.
2. **앞으로 기억하기**: 오래 쓸 개인 선호나 업무 정의를 남깁니다.
3. **반복 절차 바꾸기**: 다음에도 사용할 스킬의 순서나 확인 기준을 고칩니다.

```text
오늘 작업을 마무리하자.
이번 결과에서만 고친 내용과 앞으로 재사용할 기준을 구분해줘.
지속적인 선호와 재사용할 확인 절차를 자동 학습 기준으로 검토해줘.
관찰 중인 내용과 실제 반영한 내용을 구분해줘.
근거가 부족한 추측을 확정된 업무 사실로 만들지 말아줘.
전체 대화나 원본 자료를 개인 기억으로 옮기지는 말아줘.
```

위 문장을 매번 입력해야 학습이 켜지는 것은 아닙니다. 기본 상태에서는 자동으로 검토하며, 이 문장은 학습 결과를 직접 확인하고 싶을 때 사용할 수 있습니다.

### 학습 내용을 확인하거나 잠시 멈추기

Claude Code에서 `/company-agent:learning`을 입력하면 내역을 확인하는 절차로 들어갈 수 있습니다. 다음처럼 말로 요청해도 됩니다.

```text
최근 내 업무 방식에서 배운 내용을 보여줘.
아직 관찰 중인 것, 실제로 반영한 것, 되돌린 것을 구분해줘.
지금은 조회만 하고 바꾸지 말아줘.
```

```text
자동 학습을 잠시 멈춰줘.
기존 기억과 스킬은 남기고 계속 사용할 수 있게 해줘.
```

다시 켜려면 ‘자동 학습을 다시 시작해줘’라고 말합니다. 잠시 멈춘 동안에도 ‘이 내용은 기억해줘’라고 직접 요청할 수 있습니다. 최근 자동 변경이 마음에 들지 않으면 ‘방금 자동으로 바꾼 기준을 되돌려줘’라고 요청하세요. 대상을 알 수 없으면 어떤 변경을 말하는지 질문할 수 있습니다.

### 한 가지 업무를 발전시키는 연습 순서

| 순서 | 해볼 일 | 다음 단계로 가기 전에 확인 |
| --- | --- | --- |
| 처음 | 짧은 업무 메모 정리 맡기기 | 사실을 덧붙이지 않았는지 |
| 익숙해지면 | 원하는 말투와 보고 순서 기억시키기 | 저장한 기준이 맞는지 |
| 기준이 생기면 | 회사 용어와 예외 조건 등록하기 | 출처와 적용 범위가 있는지 |
| 반복되면 | 만족스러웠던 방법을 스킬로 만들기 | 새로운 자료에도 통하는지 |
| 단계가 늘어나면 | 프로젝트 도우미 구성하기 | 실제 업무 한 건을 끝낼 수 있는지 |

스킬을 많이 모으는 것 자체가 목표는 아닙니다. 자주 쓰는 업무 하나의 결과가 안정되고, 같은 설명을 반복하는 일이 줄어드는지를 확인하세요. 개인 자료는 다른 직원에게 자동으로 배포되지 않습니다. 공유하려면 필요한 지식이나 스킬만 골라 회사가 허용한 방식으로 전달하세요. 개인 저장소 전체나 백업 전체를 공유하지 마세요.

## 15 어려운 일과 긴 대화는 어떻게 처리하나요

### SMALL MEDIUM LARGE를 매번 고를 필요는 없습니다

Company Agent는 요청 내용과 작업 성격을 보고 업무를 맡길 모델 단계를 정하도록 구성되어 있습니다. 간단한 요약은 SMALL, 일반 분석과 작성은 MEDIUM, 복잡한 설계나 재사용 도구 제작은 LARGE를 사용하는 방향입니다. 실제 분류는 요청의 표현과 범위에 따라 달라질 수 있습니다.

사용자는 기존 모델 설정을 다시 입력할 필요가 없습니다. 다만 화면의 메인 대화 모델 이름이 매번 바뀌는 방식은 아닙니다. 주 대화는 기존 모델을 유지하고, 업무를 처리할 때 설정된 단계의 작업 담당 모델을 활용하는 구조입니다. 단계를 올려야 하거나 사용이 불가능한 경우에는 그 사실을 설명하도록 되어 있습니다.

중요한 작업은 다음처럼 명확하게 요청할 수 있습니다.

```text
이 작업은 LARGE 모델로 처리해줘.
최종 결론보다 근거 확인이 중요해.
실제로 사용할 수 없다면 다른 모델을 썼다고 숨기지 말고 알려줘.
```

단순한 일에 낮은 단계를 요청하더라도 위험하거나 복잡한 작업으로 판단되면 더 높은 단계가 필요할 수 있습니다. 높은 단계의 모델도 오류가 없다는 뜻은 아니므로 결과 확인은 필요합니다.

### 대화가 길어질 때

Claude Code의 자동 대화 정리가 켜져 있다면 긴 대화가 요약될 수 있습니다. Company Agent는 그 이후에도 개인 자료의 위치와 필요한 작업 상태를 다시 전달하고, 관련 기억과 지식을 찾아 쓸 수 있게 합니다.

개인 기억은 정확히 같은 내용의 중복을 검색 목록에서 줄이도록 정리합니다. 서로 다른 사실을 임의로 하나로 합치거나 원본 기억 파일을 자동 삭제하는 방식은 아닙니다. 기존 사용자의 긴 지시 문서를 허락 없이 잘라내지도 않습니다.

```text
대화가 길어졌으니 이어서 일할 핵심만 정리해줘.
목표, 확정한 기준, 결과 파일 위치, 아직 확인할 일,
이미 보낸 메일이 있다면 발송 확인 상태를 남겨줘.
중요한 업무 기준은 별도로 저장되어 있는지도 확인해줘.
```

회사 데이터 원문이나 비밀번호까지 요약에 남기라는 뜻은 아닙니다. 주제가 크게 바뀌면 작업 결과를 저장하고 새 대화를 시작하는 편이 이해하기 쉬울 수 있습니다. 새 대화에서도 모든 과거 대화가 그대로 보존되어 있다고 가정하지 마세요.

### 실패했을 때

파일을 바꾸는 작업은 가능한 확인 절차를 수행하고, 문제가 생기면 제한된 범위에서 고쳐 다시 확인하도록 구성되어 있습니다. 일반 작업에서는 같은 실패가 두 번 이어지면 무한 재시도 대신 원인과 막힌 지점을 알리도록 합니다. 프로젝트별로 만든 절차의 재시도 기준은 해당 구성에 따라 다를 수 있습니다.

‘확인 완료’라는 말만으로 결과가 독립적으로 증명되지는 않습니다. 무엇을 실제로 확인했는지 보세요.

```text
수정했다고만 하지 말고 실제로 확인한 내용을 알려줘.
파일을 다시 읽었는지, 어떤 계산이나 시험을 했는지,
아직 확인하지 못한 부분이 무엇인지 구분해줘.
```

현재 버전은 실패 때 대화나 업무 파일을 무조건 자동으로 되돌리지 않습니다. 대화를 되돌려도 이미 보낸 메일이나 외부 작업이 취소되는 것은 아닙니다. 되돌리기가 필요하면 현재 파일 상태와 이미 실행한 일을 먼저 확인하세요.

## 16 막혔을 때 이렇게 말해보세요

### Company Agent가 적용된 것 같지 않을 때

```text
Company Agent가 이 작업에 적용되어 있는지 확인해줘.
현재 프로젝트, 설치 범위, 개인 자료 위치,
Company Agent의 스킬을 확인할 수 있는지 점검해줘.
진단만 하고 재설치나 설정 초기화는 하지 말아줘.
```

먼저 설치 후 Claude Code를 다시 시작했는지, 프로젝트 설치라면 그 프로젝트에서 실행 중인지 확인하세요. `/company-agent:skills`도 찾을 수 없으면 설치 결과와 오류 문구를 담당자에게 전달하세요. 개인 자료 폴더를 지우는 것으로 해결하려고 하지 마세요.

### 기억한 내용을 사용하지 않는 것 같을 때

```text
전에 저장한 보고서 작성 기준을 찾아줘.
현재 사용하는 개인 저장소에서 검색했는지 확인해줘.
찾은 기준을 이번 요청에 어떻게 적용할지 설명해줘.
찾지 못하면 새로 추측해서 만들지 말아줘.
```

저장되지 않았거나, 다른 설치 범위에 있거나, 질문과 관련성이 낮아 선택되지 않았을 수 있습니다. 새 대화에서 ‘그때 그것’이라고만 하지 말고 ‘주간보고 작성 기준’처럼 제목이나 업무명을 함께 말해 보세요.

### 스킬이 없거나 이름이 겹칠 때

```text
새로 만들기 전에 같은 업무의 스킬이 이미 있는지 찾아줘.
이름이 겹치면 출처와 현재 선택을 보여줘.
기존 파일을 지우거나 덮어쓰지 말아줘.
```

### 파일을 읽지 못하거나 도구가 부족할 때

```text
어디까지 읽었고 무엇을 읽지 못했는지 알려줘.
필요한 준비물을 담당자에게 전달할 문장으로 정리해줘.
지금 가능한 텍스트 방식으로 작업을 이어갈 수 있는지도 알려줘.
```

### 같은 오류가 계속 날 때

```text
같은 방식으로 계속 재시도하지 말고 지금 상태를 정리해줘.
이미 변경된 파일, 변경되지 않은 파일, 실패한 확인 항목,
도움이 필요한 내용을 구분해줘.
원본을 삭제하거나 초기화하지 말아줘.
```

담당자에게는 무엇을 요청했는지, 정확한 오류 문구, 설치 범위, 개인 저장 위치를 전달하면 도움이 됩니다. 화면을 공유할 때 업무 원문, 개인정보, 비밀번호가 함께 보이지 않는지 확인하세요.

## 17 업데이트 후에도 내 자료를 이어서 쓰기

공통 프로그램과 개인 자료는 분리되어 있습니다. 같은 설치 범위와 같은 프로젝트로 정상 업데이트하면 기존 개인 저장 위치를 재사용하고, 개인 기억·지식·스킬·선호 선택·자동 학습 내역과 일시 중지 설정을 유지하도록 구성되어 있습니다. 사용자가 추가한 업무 규칙과 자동 실행 설정도 일반 업데이트에서는 지우거나 끄지 않습니다.

일반적인 전체 설치의 개인 자료 위치는 다음과 같습니다. 사용자 이름 부분은 PC마다 다르고, 별도 위치를 선택했다면 설치 결과에 표시된 위치가 기준입니다.

```text
C:\Users\사용자이름\AppData\Local\CompanyAgent\states\user
```

프로젝트 설치의 개인 자료는 별도 프로젝트 저장 위치를 사용합니다. 프로젝트의 업무 파일과 프로젝트 도우미 구성은 해당 프로젝트 폴더에 있습니다. 모든 자료가 위의 한 폴더에만 들어 있는 것은 아닙니다.

### 새 배포 파일을 받았을 때

1. 작업 결과를 저장하고 열려 있는 Claude Code를 닫습니다.
2. 회사에서 받은 새 ZIP을 새 폴더에 전부 압축 해제합니다.
3. 최상위 `Install-CompanyAgent.cmd`를 평소처럼 더블클릭합니다. 별도로 ‘관리자 권한으로 실행’을 선택할 필요는 없습니다.
4. 이전과 같은 설치 범위를 고릅니다. 프로젝트 설치였다면 같은 폴더를 지정합니다.
5. **Company Agent 업데이트** 화면에서 현재 버전과 새 버전을 확인합니다. 1번 업데이트를 선택하거나 Enter를 누르면 백업 후 진행합니다. 2번 현재 버전 유지는 아무것도 바꾸지 않고 끝납니다.
6. 자동으로 찾은 본인 계정과 Claude 위치를 확인합니다. Claude 후보가 여러 개면 평소 쓰는 것을 선택합니다. 스킬 선택을 바꾸지 않을 생각이면 ‘기존 선택 유지’를 고릅니다.
7. **업데이트 완료**와 개인 자료·백업 위치를 확인한 뒤 Claude Code를 다시 시작합니다.

예를 들어 1.1.1을 쓰던 PC에서 1.1.2 설치 파일을 실행하면 **1.1.1 → 1.1.2**로 안내합니다. 프로그램과 회사 지식 버전이 모두 같으면 ‘같은 버전 다시 적용/복구’로 표시합니다. 이때도 개인 자료를 초기화하는 것은 아닙니다.

완료 화면에 영어가 보이더라도 아래처럼 읽으면 됩니다.

| 화면에 보이는 결과 | 뜻 | 다음에 할 일 |
| --- | --- | --- |
| `status: updated` | 새 버전으로 업데이트 완료 | Claude Code를 다시 열기 |
| `status: reapplied` | 같은 버전을 다시 적용 완료 | Claude Code를 다시 열기 |
| `status: installed` | 처음 설치 완료 | Claude Code를 다시 열기 |
| `status: kept` | 현재 상태를 그대로 유지 | 업데이트하지 않은 상태로 계속 사용 |
| `status: input-required` | 필요한 선택이 아직 남아 있음 | 안내에 따라 선택한 뒤 설치 계속하기 |

Company Agent가 아닌 다른 도우미 구성만 발견되면 기존처럼 유지 또는 백업 후 교체를 묻습니다. 이미 Company Agent를 쓰고 있는데 이 화면이 나오면 설치 범위와 프로젝트 폴더가 이전과 같은지 먼저 확인하세요. 일반 업데이트를 하려고 기존 규칙을 끄는 교체를 대신 선택할 필요는 없습니다.

업데이트 전에 쌓아 둔 기억 하나와 스킬 하나를 새 대화에서 찾아 보세요. 이전 버전의 설치 파일, 맞지 않는 설치 기록, 같은 버전인데 내용이 다른 파일이라는 경고가 뜨면 폴더를 지우거나 보호 검사를 우회하지 말고 담당자에게 전달하세요.

설치 백업은 일부 설정과 개인 학습자료를 보관하는 것이며, 업무 폴더·메일·모든 도구 환경을 통째로 복구하는 PC 전체 백업은 아닙니다. 설치 범위를 바꾸거나 프로젝트 폴더를 옮기는 경우에는 개인 자료가 자동으로 합쳐지거나 이동한다고 가정하지 마세요.

## 18 자주 묻는 질문

### 코딩을 전혀 몰라도 사용할 수 있나요

네. 업무 목적과 자료를 한국어로 설명하는 것부터 시작할 수 있습니다. 필요한 선택이 나오면 업무 관점에서 답하면 됩니다. 다만 실제 회사 데이터나 특수 파일 작업에 필요한 준비는 담당자의 도움이 필요할 수 있습니다.

### 그냥 더블클릭했는데 관리자 권한으로 실행하지 말라고 나와요

1.1.1에서는 회사 PC의 실행 권한을 높게 감지하면 본인 계정이어도 설치가 중단될 수 있었습니다. 계정이나 Claude가 망가졌다는 뜻은 아닙니다. 담당자에게 받은 **1.1.2 ZIP 전체를 새 폴더에 풀고**, 최상위 `Install-CompanyAgent.cmd`를 다시 더블클릭하세요. 이미 Company Agent를 쓰고 있었다면 같은 범위로 업데이트합니다.

새 설치기는 지금 로그인한 본인의 환경인지 확인한 뒤 진행합니다. 본인 계정이 확인되면 권한이 높게 표시된다는 이유만으로 막지 않습니다. 다른 계정이거나 확인할 수 없는 경우에는 멈추고 안내합니다. 이때는 정확한 오류와 화면에 나온 계정·폴더 위치만 담당자에게 보여 주세요. 회사 보안 설정을 끄거나, 기존 Claude 설정·개인 자료를 지우거나, 보호 검사를 생략할 필요가 없습니다. 초반 검사에서 멈추면 아직 백업이 만들어지지 않았을 수 있습니다.

### Claude 위치를 선택하라고 나오는데 무엇을 골라야 하나요

설치기는 보통 Claude를 자동으로 찾습니다. 여러 후보가 있거나 찾지 못한 경우에만 평소 사용하는 Claude의 실행 파일을 선택하거나 그 위치를 입력합니다. 모르겠다면 아무 파일이나 고르지 말고 회사에서 Claude를 설치해 준 담당자에게 확인하세요. Claude나 Python을 다시 내려받을 필요는 없습니다.

Claude 프로그램이 있는 폴더와 개인 설정이 있는 폴더는 서로 다를 수 있습니다. 설치기는 둘을 따로 확인하고 기존 Company Agent의 개인 자료 위치도 유지합니다. 비밀번호나 모델 연결 정보를 다시 입력하라는 의미가 아닙니다. 화면에 다른 사람의 계정이나 낯선 설정 폴더가 보이면 진행하지 말고 확인을 요청하세요.

### 회사 공통 프로그램을 바꾸면 내 기억도 지워지나요

같은 설치 범위의 정상 업데이트에서는 개인 자료를 따로 유지합니다. 개인 저장 폴더를 직접 삭제하거나 다른 범위로 다시 설치하는 것은 다른 상황입니다. 업데이트 후 기억과 스킬을 찾아 확인하는 습관이 좋습니다.

### 내가 알려준 내용이 모든 직원에게 퍼지나요

개인 지식과 스킬은 자동으로 공통 자료에 반영되거나 다른 직원에게 전송되지 않습니다. 공유하고 싶다면 필요한 내용만 골라 검토 후 전달하세요. 프로젝트 폴더를 공유할 때는 그 안의 도우미 구성이나 자료가 함께 전달될 수 있습니다.

### 그냥 대화만 하면 알아서 모든 것을 기억하나요

모든 내용을 기억하는 것은 아닙니다. 업무 후 자동 검토에서 지속적인 교정과 반복 선택을 추리고, 근거 조건을 만족하면 개인화에 반영합니다. 중요한 기준은 여전히 ‘기억해줘’라고 명확히 요청할 수 있습니다. 전체 대화를 무작정 저장하거나 회사 사실을 추측해서 확정하지 않습니다.

### 잘못된 기억이 생기면 영원히 따라오나요

아닙니다. 현재 기준을 검색한 뒤 수정하거나 더 이상 사용하지 않게 정리할 수 있습니다. 다만 최신 적용 기준을 바꾸는 것과 과거 이력까지 완전히 삭제하는 것은 다릅니다.

### 만들어 둔 스킬은 매주 자동으로 실행되나요

아닙니다. 재사용할 방법을 저장하는 것과 정해진 시간에 자동 실행하는 것은 별개입니다. 현재 기본 하네스에는 직원의 반복업무를 예약하는 기능이 포함되어 있지 않습니다. 필요할 때 다시 요청해서 사용하세요.

### Claude를 닫아도 계속 일하나요

현재 기본 구성은 Claude Code에서 요청을 받아 작업하는 방식입니다. 닫힌 뒤에도 독립적으로 계속 일하는 상시 서비스로 생각하면 안 됩니다. 종료 전에 진행 상태와 결과 파일을 확인하세요.

### 기존에 설치한 스킬도 계속 쓸 수 있나요

기존 일반 스킬과 다른 플러그인을 유지하도록 설치합니다. 이름이 겹치면 Company Agent에서 사용할 후보를 선택할 수 있습니다. 선택이 Claude 전체의 모든 호출 순서를 강제로 바꾸는 것은 아닙니다.

### 설치할 때 이전 하네스가 비활성화되었다고 나왔어요

다른 하네스를 ‘백업 후 Company Agent 설치’로 교체한 경우 선택 범위의 이전 지시·규칙·Hook을 백업 후 비활성화할 수 있습니다. 모델 설정·MCP·일반 스킬·개인 자료까지 모두 초기화했다는 뜻은 아닙니다. 일반 Company Agent 업데이트는 기존 규칙·Hook도 유지하므로 이 교체와 다릅니다. 이전 구성을 복원하려면 백업 위치를 보관하고 담당자에게 요청하세요.

### 결과가 맞는지는 누가 확인하나요

Company Agent는 가능한 시험과 재확인을 하도록 돕습니다. 하지만 회사 지표의 의미, 보고 대상, 외부 발송 같은 최종 업무 판단은 사용자가 확인해야 합니다. 확인한 근거가 없는 결론을 그대로 확정하지 마세요.

## 19 복사해서 쓰는 짧은 요청 모음

### 시작할 때

```text
하고 싶은 일을 쉬운 질문으로 정리해줘. 이미 말한 내용은 다시 묻지 말고,
확인되지 않은 부분만 물어봐줘. 우선 작은 초안부터 만들어보자.
```

### 결과를 받을 때

```text
결과와 근거, 아직 확인하지 못한 내용을 나눠서 알려줘.
실제로 저장한 파일이 있으면 위치도 알려줘.
```

### 개인화할 때

```text
이 기준은 앞으로도 사용할 개인 기준이야.
같은 내용이 이미 있으면 비교해서 수정하고, 저장한 내용을 보여줘.
```

### 반복업무로 만들 때

```text
이번에 잘된 방법을 개인 스킬로 만들어줘.
적용할 상황과 적용하지 않을 상황을 적고, 다른 예시로도 확인해줘.
```

### 모르는 도구를 요구받았을 때

```text
내가 이해할 수 있게 무엇을 왜 하려는지 설명해줘.
현재 가능한 대안과 담당자에게 확인할 내용을 구분해줘.
```

### 오늘 업무를 마칠 때

```text
오늘 만든 결과물, 검증한 내용, 남은 일을 정리해줘.
다음에 다시 시작할 때 입력할 문장 하나도 만들어줘.
```
