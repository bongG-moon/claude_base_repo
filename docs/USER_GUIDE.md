# Company Agent 업무별 사용 가이드

하고 싶은 업무의 예문을 복사하고 자료·범위·결과 형식을 바꿔 요청하세요. Company Agent는 기존 Claude Code의 회사 계정·모델·권한을 그대로 사용합니다.

## 1. 요청은 목적·자료·결과·제한 순서로

| 알려줄 것 | 예 |
| --- | --- |
| 목적과 독자 | 부서장에게 월간 실적을 설명 |
| 자료와 범위 | 가상 세 달 수치, 또는 첨부 파일 1~5장 |
| 결과 | 핵심 요약과 확인할 사항, 편집 가능한 PPT |
| 제한과 완료 조건 | 원인 추측 금지, 원본 보존, 직접 확인한 범위만 보고 |

어렵다면 “필요한 정보만 한국어로 물어봐줘”라고 시작합니다. 질문이 오면 번호나 이름으로 답하고, 답변 대기 중 같은 제작 요청을 다시 보내지 않습니다.

질문 제목·선택지·설명·추천 표시는 기본 한국어입니다. 흔한 영문 선택 문구는 추가 AI 호출 없이 바꿉니다. 파일명·명령어·제품명은 유지하며, 대화 언어를 따로 요청하면 그 범위를 따릅니다. Claude 자체 메뉴·권한 버튼이나 외부 도구의 원문까지 번역하는 기능은 아닙니다.

참고 파일은 필수가 아닙니다. [시작하기](ONBOARDING_COURSE.md) 1단계에서 가상 자료를 만들어 연습할 수 있습니다. PPT는 2단계의 새 디자인 예문으로 제작합니다.

## 2. 문서 읽기와 비교

실제 파일은 CLI의 `@` 또는 Workspace의 파일 선택으로 지정합니다. 처음에는 가상 MD·텍스트 자료로 연습하세요. 파일 형식별 읽기 지원은 실제 설치된 스킬과 도구에서 확인합니다. 문서 본문이 대화에 전달될 수 있으므로 승인된 자료만 사용합니다.

```text
첨부한 실습_가상자료.md를 읽고 핵심 내용·월별 수치·확인할 사항을 정리해줘.
원본은 수정하지 말고 실제 읽은 범위와 미확인 부분을 알려줘.
자료에 없는 증가 원인은 추측하지 마.
```

실패·시간초과·개수 차이만으로 DRM 원인을 단정하거나 실제 접근 제한을 다른 사본으로 우회하지 않습니다.

조회만 했다면 저장 확인은 필요 없습니다. 이전 변경의 검증 의무와 실행 권한은 유지됩니다.

문서 비교 파일이 없어도 아래 예문으로 시작할 수 있습니다.

```text
다음 가상 문구 두 개를 비교해줘.
이전안: 월 1회 점검. 변경안: 월 2회 점검. 그 외 조건은 동일.
바뀐 항목과 바뀌지 않은 항목만 표로 정리해줘. 실제 회사 규정으로 기억하지 마.
```

### Excel을 표와 Python 처리 단계로 정리하기

XLSX·XLSM 파일을 첨부하고 이렇게 요청하세요.

```text
이 엑셀의 시트와 표, 수식, 접근 가능한 매크로 코드를 분석해줘.
한 시트에 표가 여러 개면 나누고 DATA와 PROCESS로 분리된 Python 프로젝트를 만들어줘.
코딩에 익숙하지 않아도 수정 위치를 알 수 있도록 한국어 주석을 넣어줘.
원본과 데이터 대소문자는 유지하고, 확인하지 못한 부분은 따로 알려줘.
```

일반 OOXML 파일은 기존 방식으로 직접 읽습니다. 직접 해석할 수 없는 바이너리 파일 후보만 설치된 Excel·xlwings로 한 번 확인하며, 이것만으로 DRM 여부를 확정하지 않습니다. 접근 거절·손상·크기 제한 오류를 다른 방식으로 우회하지 않습니다. Excel이 필요한 경우 승인된 Windows Excel과 `xlwings`가 있어야 하며, 직접 읽기에는 `openpyxl`, VBA 파일 추출에는 `oletools`가 필요할 수 있습니다. 하네스 설치기가 라이브러리를 자동 설치하지 않습니다.

데이터의 대소문자를 임의로 바꾸지 않습니다. 앞뒤 공백 정리도 필요한 업무 규칙에만 적용하며 원본을 덮어쓰지 않습니다. 기존 수식에 `UPPER`가 있으면 원래 계산 의미로 구분하고, VBA 변환이 필요한 코드는 명시적 확인 없이 같은 동작으로 옮겼다고 주장하지 않습니다. VBA 접근이 막혀도 가능한 표·수식 분석을 계속하며, 원본 매크로 실행이나 보안 설정 변경은 하지 않습니다.

모델에 보내는 요약은 **표별 5행·전체 12,000자**가 기본입니다. 더 많은 표본이 필요해도 표별 최대 1,000행이며 전체 문맥 상한이 함께 적용됩니다. 전체 계산은 로컬의 분석 한도 안에서 처리하고 미지원 수식·접근 불가 VBA·불명확한 표는 따로 표시합니다. 따라서 모든 매크로를 자동 변환했거나 원본 Excel과 완전히 같다고 보장하지 않습니다. 실제 사내 DRM 파일과 매크로 실행 결과는 별도 검증이 필요합니다.

결과 폴더의 `main.py`가 실행 시작점입니다. 입력 위치·Python/DB 연결은 `DATA/`, 계산은 `PROCESS/`, 새 결과는 `outputs/`에 둡니다. **계산 시트당 Python 파일 하나**에 같은 행 수식을 반복문으로 묶고 한국어 주석을 넣습니다. `PROCESS/pipeline.py`가 선행 시트부터 계산하며, 서로 참조하는 시트는 셀 단위로 계산합니다. SUM·IF·ROUND 등은 Excel의 계산 의미를 보존하는 Python 보조 함수를 사용합니다.

평소에는 `README.md`와 DATA·PROCESS만 보면 됩니다. 표는 `tables/`에, 상세 진단은 `_details/`, 계산 지원·입력 계약은 `_support/`에 모아 둡니다. 셀별 전체 수식 JSON은 기본으로 나열하지 않습니다. 같은 열 의미·행 배치·자료형이면 DATA만 교체해 재사용하지만 행 추가·열 이동은 다시 검토합니다.

**필요한 결과만 남기려면** “집계 시트의 A1:D20을 만드는 데 필요한 데이터와 계산만 남겨줘”처럼 요청하세요. 해당 결과와 선행 입력·수식만 포함한 새 프로젝트를 만듭니다. 원본과 기존 결과를 삭제하지 않습니다. VBA·동적 참조 등으로 필요한 범위를 확정하지 못하면 임의로 제외하지 않고 이유를 알려줍니다.

### 엑셀의 업무 흐름도 보기

엑셀을 Python 프로젝트로 구조화하면 같은 결과 폴더의 `업무흐름.html`에서 원본 표 → 계산 → 결과의 관계를 볼 수 있습니다. 인터넷 연결 없이 Noto Sans KR 글꼴로 열립니다. 표는 의미 있는 이름과 실제 표 ID를 함께 표시합니다. 예를 들어 분석 결과의 ID가 `s01_t01`이면 `교육 신청 테이블 (s01_t01)`로 나타납니다. ID 표기 형식을 따로 강제하거나 바꾸지는 않습니다. 자동으로 제안한 이름은 확정된 업무 용어와 구분합니다. 셀 수식에서 확인한 연결만 그리고, 매크로·미지원 함수처럼 관계를 확인하지 못한 부분은 따로 표시합니다. 흐름도는 처음 프로젝트를 만들 때 생성하며 `main.py`를 실행할 때마다 다시 만들지 않습니다.

연결도 아래에는 **표에 어떤 데이터가 있는지 → 어떤 계산을 하는지 → 어느 열에 결과가 나오는지**를 설명합니다. 예를 들어 금액 열의 `수량 × 단가`는 “두 값을 곱해 금액을 계산”, `SUMIFS`는 “여러 조건을 모두 만족하는 항목의 값을 합산”처럼 읽을 수 있습니다. 반복되는 행 수식은 묶어 보여주며 자세한 대표 수식과 참조 위치는 펼쳐서 확인합니다. 실제 행 값과 모든 셀 수식을 나열하지 않으므로 설명만으로 개별 데이터 값까지 확인했다고 판단하지 마세요.

설명은 원본에서 확인한 열 이름과 계산 구조를 사용합니다. 함수의 뜻을 설명하는 것과 계산이 검증된 것은 다르므로 미지원·오류·VBA 제한도 함께 확인하세요. 열이 많거나 설명을 일부만 표시하면 생략 범위를 알려줍니다. Python 계산을 직접 바꾸었다면 생성 당시의 HTML 설명도 함께 갱신해야 합니다.

```text
이 엑셀을 Python 프로젝트로 구조화하고 업무 흐름도도 보여줘.
각 표가 어떤 데이터인지 쉽게 이름을 붙이고 원본 위치도 함께 표시해줘.
확실하지 않은 연결이나 표 이름은 추정이라고 알려줘.
```

## 3. 보고서·HTML·편집 가능한 PPT


모양을 설명하기 어렵다면 [디자인 용어 참고](DESIGN_TERMS.md)에서 느낌과 예문을 골라 보세요. 모든 용어가 기본 선택지는 아닙니다.

HTML 보고서는 새 디자인 또는 참고 HTML을 선택합니다. **PPT는 참고 양식이 없으면 깔끔한 업무 보고형으로 바로 전체 HTML 초안을 만듭니다.** 목적·독자·장수 중 빠진 것만 물으며 참고 파일이나 디자인 목록 선택을 먼저 요구하지 않습니다. 원하는 분위기가 있거나 참고 캡처·기존 PPT·저장한 HTML 양식이 있다면 요청에 함께 알려 주세요.

글꼴은 **Noto Sans KR**(긴 본문·보고서), **Pretendard**(표·버튼), **나눔스퀘어 네오**(제목·안내) 중 고르거나 **알아서 선택**, **직접 입력**할 수 있습니다. 이미 정한 글꼴은 유지합니다. “디자인과 글꼴은 알아서 선택해줘”라고 하면 바로 제작합니다. 글꼴은 자동 설치하지 않으며 PC에 없으면 대체 글꼴로 표시됩니다.

예: `이 자료로 HTML 보고서를 만들어줘. 깔끔한 업무형, 보통 분량, 스크롤, Pretendard로 해줘.`

레퍼런스는 **1 스토리형**(질문·근거·해석), **2 데이터 리포트형**(지표·비교·목차), **3 발표형**(메시지·넓은 표/차트) 중 선택합니다. 예: `레퍼런스 2로 만들어줘.` 별도 검색 없이 적용합니다.

내용이 한 묶음이면 넓게 쓰고 비교할 내용만 나란히 놓아, 오른쪽 빈 칸이나 장식의 남은 여백을 없앱니다. 긴 표는 좁은 칸에서 글자를 잘게 나누지 않고 표 안에서 스크롤하도록 합니다. 화면 크기별 배치와 읽기 순서도 확인합니다.

HTML의 페이지 보기에는 짧고 은은한 전환을 적용합니다. 스크롤을 기다려야 본문이 나타나거나 숫자가 바뀌는 효과는 넣지 않습니다. “움직임 없이 만들어줘”라고 요청할 수 있고, PC의 움직임 줄이기 설정과 인쇄에서는 전환을 끕니다. 브라우저에서 스크립트를 실행하지 못해도 본문은 읽을 수 있습니다.

기존 웹사이트의 화면·버튼·컴포넌트를 고치는 일은 별도 `web-interface` 스킬이 담당합니다. 예: `현재 웹앱의 신청 화면에서 카드 높이와 버튼 크기를 다듬고 모바일에서도 확인해줘. 기존 기능과 글꼴은 유지해줘.` 단일 보고서 제작에 웹앱 개발 절차를 추가하지 않습니다.

이미 알려준 조건은 다시 묻지 않습니다. 필요한 정보가 갖춰지면 본문과 HTML 초안을 준비합니다. “초안 필요”나 “확인 대기”는 제작 오류가 아닙니다. 기본 디자인으로 시작했다는 것이 최종 PPT 제작 승인까지 뜻하지는 않습니다.

**참고자료는 편한 형식으로 주세요.** 보호되지 않은 PPTX는 그대로 첨부할 수 있고 HTML·장표 이미지도 사용할 수 있습니다. 디자인 참고라면 표지·본문·표가 있는 대표 2~3장부터 확인합니다. 전체 내용이 필요하면 “전체 장표 내용을 참고해줘”라고 범위를 알려 주세요. 보지 않은 장의 내용을 읽었다고 처리하지 않습니다.

참고자료에서는 색과 배치뿐 아니라 제목·본문의 글꼴과 굵기, 설명 순서, 문장 길이와 말투도 함께 참고합니다. 이미지에서 정확한 폰트를 알아내지 못하면 비슷한 한국어 글꼴을 사용하고 초안에서 차이를 알려 줍니다. “이 PPT의 분위기와 간결한 말투를 참고하되, 내용은 이번 자료로 바꿔줘”처럼 요청하면 됩니다.

PPT 참고 양식은 제목·본문·강조·출처별 서식을 살피고, 색·도형이 쓰인 목적까지 새 내용에 반영합니다. 명사형 보고체·고정 용어는 유지하며, 이미지에서 추정한 특징과 PPT에 명시된 서식은 구분합니다.

예: `첨부한 장표의 제목 말투, 도형, 색상과 글자 굵기를 참고해줘. 내용은 이번 자료만 사용하고, 먼저 전체 HTML 초안을 보여줘. 최종 PPT의 글자와 도형은 편집하고 그룹을 풀 수 있게 해줘.`

새로 만든 PPT의 글자는 색·굵기·크기를 수정할 수 있는 텍스트입니다. 카드·지표처럼 함께 움직일 부분은 그룹으로 만들 수 있고, 자동 배치의 KPI 이름과 값은 함께 묶입니다. 그룹을 선택해 이동하거나 내부 글자를 다시 선택해 편집하고, 필요하면 PowerPoint의 그룹 해제를 사용하세요. 표·차트는 독립된 편집 개체로 유지하며 사진·로고 안의 글자는 이미지로 남습니다. 긴 문장으로 바꾸면 글자 크기를 자동으로 줄이지 않으므로 상자 크기와 줄바꿈을 조정해 주세요.

보호 문서는 파일 읽기 실패만으로 DRM이라고 단정하지 않습니다. 회사에서 화면 캡처와 AI 처리를 허용한 경우에만, 정상적으로 열린 PowerPoint를 승인된 화면 도구로 장표별 확인합니다. 연결된 화면 도구가 없으면 허용된 캡처 이미지를 첨부할 수 있습니다. 실제 캡처 금지나 접근 제한은 우회하지 않습니다. 캡처는 참고자료이고, 편집 가능한 PPT를 요청했다면 최종 장표 전체를 이미지로 대체하지 않습니다.

선택한 양식 안에서 내용에 맞게 배치합니다. 비교 자료는 차이를, 의사결정 자료는 결론과 근거를 먼저 보여주며 모든 보고서에 큰 숫자나 카드를 붙이지 않습니다. 이미 선택한 디자인·글꼴은 유지하고, 흐름도·관계도 같은 설명용 다이어그램은 흐름이나 구조를 그림으로 설명해 달라고 했을 때 사용합니다.

PPT의 요약 장은 결론과 핵심 근거, 근거 장은 표·차트와 짧은 해석, 비교 장은 같은 기준의 차이, 후속 조치 장은 확인할 항목과 현재 상태를 보여줍니다. 없는 수치·담당자·기한을 채우지 않습니다.

보고서·PPT·메일 초안은 추가 스킬·승인 없이 반복·번역투·과장을 줄입니다. 수치·날짜·인용·회사 고정 문구·불확실성 표현·표와 목록은 보존하고 지정한 말투와 관련 개인 선호를 따릅니다. 승인본은 임의로 수정하지 않습니다.

“이 문단만 더 자연스럽게 다듬어줘”, “원문 표현을 그대로 써줘”라고 요청할 수 있습니다. 문체 기준은 작성 지침이지 AI 작성 여부를 판별하거나 정확성을 보증하는 검사가 아닙니다.

수치 정정 시 지표명·기간·단위도 맞춥니다. 예: 순매출 `262.0백만원`, 달성률 `93.6%`. 계산 검사와 의미 확인은 별개입니다.

오류 자료를 정리할 때는 원본 ID와 행 기준을 함께 확인합니다. “데이터 12행(헤더 제외)”과 “파일 13줄”은 다를 수 있으며, 필터한 표의 순번으로 원본을 수정하지 않습니다.
“짧은 스크롤 보고서”는 여백을 줄여 한 HTML에서 읽는 방식이고 인쇄 한 장을 보장하지 않습니다. A4 한 장이 필요하면 그렇게 요청하고 인쇄 미리보기도 확인하세요.

```text
가상 월간 실적으로 짧은 HTML 보고서를 만들어줘.
6월 목표 100건·실적 90건, 7월 목표 100건·실적 110건, 8월 목표 100건·실적 130건.
참고 파일은 없어. 새 디자인 목록에서 하나 고른 뒤 스크롤 방식으로 만들어줘.
목표 300건·실적 330건·달성률 110%를 대조해줘. 원인과 연도는 추측하지 마.
최종 HTML 한 파일만 전달하고 기존 파일은 덮어쓰지 마.
```

PPT는 전체 HTML 초안 → 사용자 확인 → 편집 가능한 PPT → 결과 확인 순서입니다. 실제 초안을 연 뒤 “이 초안대로 PPT를 만들어줘”라고 답하면 제작합니다. 카드·둥근 모서리·그림자·태그를 지원하지만 웹 화면과 모든 효과가 같지는 않습니다. 복잡한 효과·움직이는 내용·병합 표는 변환 가능 여부를 먼저 확인하세요. 차트 수치도 바꾸려면 “데이터도 수정 가능한 차트로 만들어줘”라고 요청합니다.

이미 만든 HTML을 변환할 때는 **모든 장이 같은 고정 크기로 보이는 정적 초안**을 사용합니다. 원래 카드의 가로·세로 정렬은 유지합니다. 보이지 않는 장이나 이동·회전·확대/축소 효과 때문에 변환이 멈추면 같은 초안을 수정하고 다시 확인하세요. 이를 “PowerPoint는 카드를 만들 수 없다”는 뜻으로 해석하거나 전체를 이미지로 바꾸지 않습니다.

HTML 초안·변환 시도·검사 이미지는 내부 임시 작업 공간에 두고 한 요청에서는 최종 결과 한 개가 기본입니다. 여러 결과를 명시적으로 요청하거나 다음 질문에서 다른 형식을 요청하면 별도로 생성할 수 있습니다. 기존 결과는 자동 삭제하지 않습니다.

최종 파일을 확인해 전달하면, 기본 제작기가 생성·기록한 변경 없는 중간 파일은 자동 정리합니다. 원본·최종 결과·대표 양식·개인 기억과 스킬은 남깁니다. 사용자가 수정한 파일, 등록되지 않은 파일, 이전 버전의 중간물도 임의로 지우지 않습니다. 최종 결과가 참조하는 파일과 열려 있어 지우지 못한 파일은 보존합니다. 정리 때문에 결과물을 다시 만들거나 계속 재시도하지 않습니다.

```text
이번 작업에서 만든 불필요한 중간 파일만 정리하고 원본과 최종 결과는 남겨줘.
확실히 구분되지 않는 파일은 지우지 말고 알려줘.
```

이 정리는 기본 HTML·PPT 제작기의 등록된 작업 파일에 적용됩니다. 폴더 전체를 비우거나 다른 도구가 만든 모든 파일을 자동으로 찾아 지우는 기능은 아닙니다.

대표 디자인은 내용·숫자·캡처를 제거한 **HTML 양식**으로 저장하고 개인 전체/이 프로젝트 중 범위를 고릅니다. 실제 파일이 있어야 저장 성공이며 기억에 선호를 적는 것과 다릅니다. 기존 PPT 이미지 크기만 수정하는 작업은 원본을 보존하며 별도 결과를 만듭니다. 그림을 키운다고 글자가 편집 가능해지는 것은 아닙니다.

### 끝난 작업을 그림으로 이해하기

“방금 작업의 흐름을 그림으로 보여줘”, “이 구조를 HTML로 설명해줘”라고 요청하면 확인한 내용을 바탕으로 작은 설명 도표를 만듭니다. 일반 보고서나 작업 완료 때 자동으로 붙이지 않습니다. 단순한 “정리해줘”는 글 요약부터, “글로만”은 도표 없이 답합니다.

```text
방금 작업한 흐름을 HTML 한 파일로 설명해줘.
확인된 결과·남은 일·미확인을 구분하고 단계별 설명 재생을 넣어줘.
업무를 다시 실행하거나 실제 진행률처럼 표시하지 마.
```

전체 그림이 먼저 보이고 **설명 재생·한 단계씩 보기·일시정지**로 순서를 짚어봅니다. 실제 업무를 다시 실행하는 버튼이 아닙니다. 움직임 줄이기 설정·인쇄·스크립트 없는 미리보기에서는 정적 내용을 봅니다. SVG/PNG 저장은 버튼을 눌렀을 때만 하며 상세 설명·근거는 HTML에 남습니다. 편집 가능한 PPT 도표로 자동 변환하는 기능은 아닙니다.

Google Fonts를 사용하고 싶으면 요청에 적어 주세요. 이때 글꼴 서비스에 연결하며, 연결할 수 없으면 PC 글꼴로 표시됩니다. 기본은 외부 연결 없는 PC 글꼴입니다. 새 디자인 설문 없이 현재 선택이나 간단한 기본 양식으로 진행합니다.

## 4. 회의 메모와 메일 초안

```text
다음 가상 회의 메모를 결정 사항·진행 중·확인할 사항으로 정리해줘.
점검표 수정 완료. 현장 확인 진행 중. 새 양식 적용일은 미정.
담당자와 날짜를 만들어 넣지 마. 이어서 팀에 공유할 메일 초안도 대화에 보여줘.
메일에 연결하거나 발송하지 마.
```

메일 초안은 연결 없이 작성할 수 있습니다. 실제 메일 조회·발송·PST 이동은 별도 승인된 연결과 본인 계정 범위가 필요합니다. 선택적 로컬 Outlook 점검기는 읽기 전용입니다. 초안 작성이나 조회 승인을 실제 발송 승인으로 해석하지 않습니다. 보호된 본문·첨부는 권한 범위에서만 처리합니다.

**메일이 많으면 목록에서 필요한 것부터 고릅니다.** 기간·제목·보낸 사람 조건으로 제목·날짜 등 후보 목록을 먼저 보고, 필요한 메일 본문만 읽습니다. 보통 후보 20건에서 관련 본문 5건 이내로 시작하며, 이미 정한 계정·기간은 다시 묻지 않습니다. 첨부 본문과 같은 메일을 반복해서 읽거나 전체 메일함을 자동으로 펼치지 않습니다.

로컬 읽기 기능은 본문을 기본 합계 12,000자 안에서 읽고 전체 응답에도 별도 크기 제한을 적용합니다. 한도에 도달하면 읽지 못한 범위를 구분하며, 잘린 내용을 전체 요약이라고 하지 않습니다. 연결된 회사 메일 도구는 실제 제공하는 검색·필드·페이지 제한을 사용합니다. 이 문자 제한은 전체 대화의 토큰 상한은 아닙니다.

```text
최근 7일의 교육 일정 변경 메일을 찾아줘.
먼저 제목과 날짜로 좁히고 관련 메일 5건 이내만 읽어서 변경 내용과 할 일을 알려줘.
첨부는 열지 말고, 읽지 못한 범위는 구분해줘.
```

발송은 수신자·본문·첨부를 보여준 뒤 실제 도구의 승인 단계로 이어집니다. 같은 발송에 채팅 확인 질문을 덧붙이지 않으며, 읽기나 초안 작성에는 발송 승인을 요구하지 않습니다.

## 5. 파일 정리와 회사 데이터

```text
지금 연습 폴더 바로 아래 파일의 정리안만 보여줘.
이동 전후 위치를 설명하고 아직 이동·삭제·덮어쓰기는 하지 마.
내 답변을 기다려줘. 회사 공용 폴더와 다른 프로젝트는 확인하지 마.
```

이동은 계획 확인 후 허용된 범위에서만 합니다. 되돌리기도 이후 파일 상태와 기록을 확인해야 합니다. 파일이 없다면 ‘정리할 파일 없음’이 정상입니다. 실습을 위해 업무 파일을 복사할 필요는 없습니다.

회사 DB 조회는 승인된 연결의 읽기 범위 안에서 수행합니다. 담당자가 제공한 테이블·필터·기간을 확인하고 임의의 회사 DB 접속이나 데이터 변경을 하지 않습니다. 연결이 없으면 가상 표로 계산 연습만 합니다.

### Chrome에서 반복하는 조회를 스킬로 만들기

어느 사이트에서 어떤 항목을 읽고 무슨 결과를 원하는지만 말하면 됩니다.

```text
Chrome에서 보는 사내 포털 공지 목록을 요약하는 스킬을 만들어줘.
대상은 [사용할 사이트 주소]의 공지 목록, 최근 7일의 제목·게시일·링크야.
먼저 승인된 브라우저 연결이 있는지 확인하고 대상 화면과 읽을 범위를 맞춰줘.
연결되어 있으면 최대 3건만 읽어 표로 정리하는 시험부터 해줘.
시험 후 개인 전체 또는 이 프로젝트 중 저장할 곳을 물어봐줘.
연결이 없으면 준비 안내와 실제 조회 미확인인 절차 초안까지만 해줘.
```

승인된 기존 연결 확인 → 대상 확인 → 소량 조회 시험 → 저장 범위 선택 → 스킬 저장 순서입니다. 이미 정한 범위는 다시 묻지 않습니다. 스킬을 저장해도 조회 권한이나 연결이 새로 생기지는 않습니다. 이 하네스는 Chrome·공통 브라우저 연결 도구를 설치하거나 자동으로 실행·로그인하지 않으며, 필요한 연결 준비는 담당자가 진행합니다.

비밀번호·쿠키·토큰을 대화에 붙이지 마세요. 인증 값과 네트워크 요청·응답 원문을 모델에 보내거나 스킬에 저장하지 않습니다. 승인된 화면에서 필요한 항목만 사용합니다. 기존 도구로 가능하면 그대로 재사용하며 새 업무 도구가 필요한 경우에만 별도 제작·검증 절차를 따릅니다.

**성공 확인:** 저장한 스킬의 위치와 실제로 조회한 사이트·건수·항목을 따로 확인합니다. 절차 안내나 초안이 완성돼도 실제 조회가 확인된 것은 아닙니다. 실제 도구의 조회 결과와 화면을 대조하며, 조건에 맞는 항목이 없으면 0건도 정상일 수 있습니다. 자료 없이 가상 표로 연습하는 예문은 [시작하기](ONBOARDING_COURSE.md) 8-5에 있습니다.

**연결이 없으면:** 담당자에게 “이 사이트를 읽을 수 있는 승인된 브라우저 연결을 준비해 주세요”라고 요청하세요.

| 지식 | 출처가 있는 용어·계산식 | 출처·기준일 확인, 개인 초안 검토 |
| 스킬 | 반복 보고서를 만드는 절차 | 설명서 생성 후 발견·로드·결과 시험 |
| 도구 | 달성률을 계산하는 프로그램 | 후보 생성 → 실제 시험 → 검증 → 활성화 |
| 하네스 | 스킬·도구·규칙·후크를 연결한 구성 | 누가 관리하고 어디에 적용되는지 확인 |

MCP 도구는 **편집 중인 초안과 실제 연결에서 쓰는 활성본**을 나눕니다. 수정만으로 실행 코드가 바뀌지 않고, 새 시험·활성화 후 연결을 다시 시작해야 반영됩니다. 예전 방식의 연결은 해당 연결만 다시 등록해야 할 수 있으며 다른 도구나 개인 설정은 그대로 둡니다.

**스킬 설명서 수정은 도구 코드 재설치와 다릅니다.** 만든 스킬은 “신청현황 정리 스킬 실행해줘”, “아까 만든 스킬의 정렬 순서만 바꿔줘”처럼 요청합니다. 기존 이름·저장 범위를 유지하고 실제 사용 중인 원본을 갱신하므로 파일 복사나 명세 재생성을 직접 할 필요가 없습니다. 같은 이름의 후보가 여러 개일 때만 출처를 확인합니다. 설명서 수정만으로 기존 도구를 다시 설치·활성화하지 않습니다.

**새로 만든 스킬은 `/스킬이름`으로 사용합니다.** 개인 전체는 현재 Claude 설정 폴더의 `skills`, 이 프로젝트는 작업 폴더의 `.claude/skills`에 실제 원본 하나만 저장합니다. 기존 비공개 저장소의 스킬은 이동·복제하지 않으며 “스킬이름 실행해줘” 또는 `/company-agent:skills 스킬이름 실행`을 계속 사용할 수 있습니다. 같은 이름이 있으면 새 사본을 만들지 않고 기존 원본을 확인합니다.

새 스킬이 `/` 목록에 없으면 원본 Claude에서 `/reload-skills` 또는 새 대화로 확인하세요. 수동 호출 메뉴에 표시하지 않는 기존 스킬(`user-invocable: false`)은 그 설정을 유지합니다. “파일 저장·구조 확인”과 “현재 대화에서 인식·실제 업무 시험”은 다릅니다. 작성용 임시 파일이 아니라 저장 결과에 표시된 실제 원본을 수정합니다.

회사 공통 / 개인 전체 / 이 프로젝트를 먼저 구분합니다. 회사 공통은 담당자가 배포하고 사용자는 읽기·개선 제안을 합니다. 새 개인 기억·스킬·도구는 개인 전체 또는 이 프로젝트 중 하나를 선택하며 범위를 이미 명시하면 다시 묻지 않습니다. 비공개 기억·도구 저장소는 폴더 공유만으로 전달되지 않지만, **새 프로젝트 스킬은 작업 폴더 안에 있어 폴더와 함께 공유될 수 있습니다.**

**구성 한눈에**에서 연결된 회사 배포본과 로컬 개인 저장소의 실제 위치를 확인합니다. 개인 전체는 같은 사용자 설치·저장소를 쓰는 여러 폴더에, 프로젝트 개인 기억은 저장한 프로젝트 경로에 적용됩니다. 폴더 복사나 다른 PC·계정으로 자동 동기화되지 않으며 이전 후에는 연결과 조회를 다시 확인합니다. Claude Code 자체 자동 기억은 별도 저장소입니다.

```text
내 보고서 표현 선호를 저장해줘. 결론부터 설명하고 미확인 내용은 구분하는 방식이 좋아.
이 선호만 저장하고 원본 문서는 넣지 마.
개인 전체와 이 프로젝트 중 어디에 저장할지 먼저 물어봐줘.
```

저장 후 새 대화에서 실제 조회하고 결과에 적용됐는지 각각 확인합니다. 자동 학습은 재사용할 교정이 있을 때만 한 번 제출합니다. “앞으로 팀 보고서는 결론부터”처럼 지속적인 명시적 교정은 업무 중에도 기존 자동 학습 범위에 반영할 수 있으며 저장 위치를 매번 다시 묻지 않습니다. “이번만”이나 모호한 지시는 장기 저장하지 않고 추정한 선호는 독립된 업무의 반복 근거가 필요합니다. 같은 범위·같은 항목을 A → B → A로 고치면 마지막 교정을 사용하며, 같은 업무의 반복 답변을 독립 근거로 늘리지 않습니다.

학습 이력과 개인 선호는 기존 설치 저장소에 남습니다. “기억에 저장해줘”라는 별도 요청에서 범위를 선택해도 자동 학습 설정은 바뀌지 않습니다. 스킬은 기존 자동 학습 대상과 제작기로 새로 만든 native 원본만 조건부로 개선합니다. 직접 설치한 사용자 스킬·회사 정책·프로젝트 `CLAUDE.md`는 자동 수정하지 않습니다. 전체 본문을 읽은 정확한 버전과 실제 검증 근거가 있는 작은 점검 항목만 개선하며, 수동 편집과 충돌하거나 근거가 부족하면 보류합니다. **새 스킬 생성은 별도 요청이나 제작 제안에 대한 동의 후 진행**하고 공통 스킬의 개인 복제본을 자동으로 만들지 않습니다.

매 답변을 회고하거나 학습만을 위해 끝난 응답을 다시 이어가지 않습니다. 별도 학습 모델·작업자는 강제 호출하지 않지만 필요한 교정 추출과 제출에는 현재 모델의 처리 비용이 듭니다. 자동 학습 카드나 `/company-agent:learning`에서 **접수·후보·실제 적용·보류**를 구분해 확인하고 일시 중지·재개·선택한 변경 되돌리기를 요청합니다. 미제출과 “제출했지만 배울 내용 없음”은 다르며, 나중에 기억이 모델에 전달됐어도 실제 사용을 증명하지는 않습니다. 중지는 기존 기억 삭제나 사용 중단이 아니고 되돌리기는 업무 파일·발송 메일을 취소하지 않습니다. 자세한 조건과 후보 보존 한계는 [핸드북](COMPANY_AGENT_HANDBOOK.md) 7장, 비교 실습은 [시작하기](ONBOARDING_COURSE.md) 6~8단계를 참고하세요.

기억이 안 보이면 삭제됐다고 단정하지 말고 저장 범위·사용 상태·제목을 확인합니다. 자동 참고 목록은 관련 내용을 골라 짧게 전달하는 것이지 저장된 기억 전체가 아닙니다. “개인 전체의 ‘실습 요약 순서’를 조회해줘. 수정하지 마”처럼 범위와 제목을 지정해 비교할 수 있습니다.

“학습한 내용과 이번 작업에서 기억을 참고했는지 쉽게 설명해줘”라고 요청하면 접수·적용·보류와 기억 전달 기록을 나눠 보여줍니다. 관련 기억을 찾지 못한 경우와 입력 분량 제한으로 빠진 경우도 구분합니다. 대화 정보가 없으면 확인 불가로 안내하며 다른 대화를 찾아보지 않습니다. 모델 입력용 출력에 포함한 기록만으로 실제 답변에 반영됐다고 판단하지 않습니다. 이 설명은 요청할 때만 제공하며 평소 업무에 질문이나 추가 모델 호출을 넣지 않습니다.

### 저장한 기억 수정·복원하기

기존 기억은 원래 범위와 항목을 유지해 수정합니다. 프로젝트 전용 요청을 개인 전체로 바꾸지 않습니다. 저장 응답의 실제 범위와 버전을 확인하며, 정상 저장을 재검증하려고 작업을 반복하지 않습니다.

예: “이 프로젝트의 보고서 순서만 표 먼저, 아래 두 문장 요약으로 수정해줘.” 수정 후 “방금 수정 전으로 복원해줘. 이후 다른 수정은 덮어쓰지 마”라고 요청합니다.

복원은 확인된 백업으로 새 버전을 만듭니다. 이후 다른 수정이 있거나 백업이 미검증이면 보존하고 멈춥니다. 예전 미검증 백업은 직접 검토 후 별도 수정으로 요청하세요. 자동학습 ‘되돌리기’는 선호의 **사용 중단**이며 이전 내용 복원과 다릅니다.

**저장과 적용은 별개입니다.** HTML·PPT의 요청한 배치와 실제 결과를 비교하세요. 순서 검사만으로 문장 의미·화면 품질까지 보증하지 않으며, 이번 초안 수정으로 장기 기억을 바꾸지 않습니다.

## 7. 겹치는 스킬과 프로젝트 지침


기본 스킬 13개와 호환용 이전 이름 1개, 후크 7개의 실제 역할·한계는 [핸드북](COMPANY_AGENT_HANDBOOK.md) 4~5장에 정리되어 있습니다. 스킬은 필요한 업무 절차를 읽어 적용하고, 후크는 요청 시작·도구 실행·종료 시 자동으로 안내·관찰·정책 확인을 수행합니다. 목록에 있다는 사실만으로 이번 업무에서 실행됐다고 판단하지 않습니다.

스킬 이름을 외우지 않고 업무부터 요청합니다. 정확한 이름을 명시했다면 그 선택을 먼저 따릅니다. 같은 업무의 같은 역할을 맡는 후보가 여럿으로 명확히 확인되고 우선 선택이 없으면 실제 이름·출처·차이를 질문하고, 선택을 반영한 뒤 해당 본문을 읽어 적용합니다. 이름이 같아도 출처가 다르면 별도 후보입니다. 읽기 → 제작처럼 서로 다른 단계의 스킬은 함께 사용할 수 있습니다. 관련 스킬이 없으면 허용된 일반 작업을 하며, 단어가 비슷한 모든 스킬을 같은 역할로 판단하거나 선택 질문을 강제하지는 않습니다. 이번 선택과 지속적인 우선 설정 저장은 별개입니다. 없는 스킬을 설치하거나 추측 이름 `company`로 실행하지 않습니다.

목록에서 경쟁 후보가 확인되면 본문을 읽기 전에 한국어로 선택을 묻습니다. Claude 세션에만 있는 별도 스킬은 로컬 목록에 없을 수 있습니다. 그런 스킬의 실제 로드가 확인되면 공통 제작 스킬과 역할을 비교해 선택하며, 사용자의 선택을 무시하고 공통 스킬로 다시 만들지 않습니다. 이미 선택한 제작 절차에 디자인 보조가 필요한 경우에만 함께 사용합니다. 선택 답변은 현재 작업에 반영하며 별도 저장 명령을 매번 실행할 필요는 없습니다.

“이미지 읽기 스킬 ZIP을 설치해줘”는 설치 요청이지 이미지 읽기 요청이 아닙니다. 설치·제작·설명과 실제 업무 실행을 구분하며, 약한 단어 일치만으로 무관한 스킬을 강제하지 않습니다.

목록 확인·단순 파일 탐색마다 오류를 내는 방식은 아닙니다. 이번 작업에 맞는 스킬이 확인됐는데 본문을 건너뛰거나 경쟁 후보의 선택을 생략하면 짧은 `[스킬 확인]` 또는 `[스킬 선택]` 안내가 나올 수 있습니다. 해당 도구는 아직 실행되지 않았고 파일 권한 오류도 아닙니다. 같은 실행을 반복하지 말고 필요한 선택·본문 로드를 마칩니다. 본문 로드가 실패하면 실제 실패를 알리고 멈춥니다. 회사 정책·도구 권한은 별도로 적용됩니다.

자료 요약 다음에 HTML 작성을 요청하면 `html-report` 등 작업에 맞는 스킬을 다시 확인합니다. 이전 목록을 봤거나 다른 스킬을 읽었다는 사실만으로 새 작업의 준비를 마친 것은 아닙니다. 일반 스킬은 같은 스킬의 변경 없는 전체 본문이 현재 대화에 남아 있다면 다시 읽지 않아도 됩니다. 별도 작업자 실행이나 모델·도구 제한 등 원본 CLI의 실행 기능이 필요한 스킬은 현재 요청에서 정확한 스킬 호출이 성공해야 합니다. 본문 파일을 읽은 것만으로 이 기능을 대신하지 않으며, 정확히 호출할 수 없으면 그 제한을 안내합니다. 관련 스킬이 없는 작업에는 스킬 설치·로드를 강제하지 않습니다.

새 작업 폴더에서 실제 작업 요청을 하면 조건에 따라 기본 `CLAUDE.md`를 한 번 생성합니다. 기존 지침·상위 지침은 보존하며 계획/변경 금지 요청이나 시스템·설정 폴더에는 만들지 않습니다. 이는 짧은 시작 안내이며 CLI `/init`의 프로젝트 분석을 실행하는 것은 아닙니다. 프로젝트 지침은 목적·단위·완료 기준부터 짧게 유지하세요.

## 8. 느릴 때와 비용을 줄이는 방법

대상·기간·범위를 한 번에 지정하고 이미 답한 선택을 유지합니다. 같은 결과 생성·파일 이동·메일 발송을 대기 중에 재요청하지 않습니다. 필요한 자료만 첨부하고 읽을 페이지나 기간을 좁히면 불필요한 처리를 줄일 수 있습니다.

짧은 문서 읽기·요약·상태 조회는 현재 대화에서 처리합니다. 단순 읽기 때문에 별도 작업자를 호출하거나 계획 파일·완료 검증·빈 학습 기록을 만들 필요는 없습니다. 파일 작성·수정, 복잡한 분석, 명시한 작업자 요청은 필요한 위임과 검증을 유지합니다.
짧은 요청이라고 문서가 작다는 뜻은 아닙니다. 실제 읽기는 지정한 범위와 도구의 분량 제한을 따릅니다.

파일 오류가 나면 첨부한 실제 경로와 오류 내용을 비교합니다. 한글이 들어 있다는 이유만으로 인코딩 문제라고 단정하지 않습니다. 파일 없음·지원하지 않는 형식·접근 제한은 구분하고 실제 결과를 확인한 뒤 필요한 부분만 다시 시도합니다.

Workspace 사용 현황에서는 실제 CLI 토큰 보고와 실행·질문·승인 대기를 구분합니다. 미제공 값은 0이 아니며 누적값을 요청별 값처럼 합산하지 않습니다. 사내 가격을 모르면 금액이나 절감률을 단정하지 않습니다. 대화가 길 때는 원본 CLI의 `/context`·`/compact`를 사용할 수 있지만 업무마다 강제 압축하지 않습니다. 압축은 영구 기억 저장이나 결과 검증의 대체가 아닙니다.

이미지·PPT는 처음에는 전체를 확인하고, 수정 후에는 변경된 부분과 영향을 받은 부분을 다시 확인합니다. 공통 폰트·배치가 바뀌거나 영향 범위가 불분명하면 전체를 다시 확인합니다. 같은 이미지를 반복해서 대화에 넣기보다 파일 버전과 확인 결과를 짧게 남깁니다. 압축 뒤에는 유효한 현재 작업의 로컬 스킬 선택을 이어가되 필요한 본문만 다시 읽습니다. 이미 읽었다는 기록이나 검증 성공을 임의로 복원하지 않습니다.

### 여러 프로젝트의 업무 자료 집계하기

`company-agent:work-context-catalog`는 지정한 폴더의 스킬·기억·지식과 현재 사용자의 Claude·Codex 세션 기록을 기본으로 함께 살펴봅니다. Company Agent가 없는 환경에서도 독립 스킬 폴더를 사용할 수 있습니다. 내부 저장 경로를 외울 필요 없이 업무 폴더와 집계할 내용을 말하면 됩니다. 세션은 알려진 저장 위치에서 확인하며 PC 전체나 기록에 등장하는 다른 폴더를 따라 검색하지 않습니다.

```text
work-context-catalog 스킬로 지금까지의 Claude 사용 기록과 이 폴더의 업무 자료를 정리해줘.
반복한 업무나 처리 순서가 있는 업무 중심으로, 어떤 자료를 어떻게 처리하는지 순서도로 보여줘.
각 업무에서 Claude가 실제로 한 동작도 펼쳐보고, 나중에 모아서 쓸 수 있도록 Markdown도 만들어줘.
업무와 관련 없어 보이는 대화는 제외 후보로 구분하고 질문 원문은 넣지 말아줘.
```

세션은 한도 안에서 차례로 확인해 전체 업무 유형을 분류합니다. 상세 흐름은 **스킬·기억·지식으로 남긴 업무**를 중심으로 보여줍니다. 저장 응답이 관찰된 절차만 연결하며, 스킬 조회나 저장 요청만으로 선정하지 않습니다. 인사·감사·빈 기록은 제외하고, 짧은 요청·실패한 업무는 큰 분류에 남깁니다. 확인한 수·남긴 수·제외 이유를 표시하고 질문 원문은 기본으로 넣지 않습니다. “세션은 빼고 문서만”, “지정한 폴더의 기록만”처럼 범위를 줄일 수 있습니다.

업무별 흐름에는 기록에서 확인한 대상·요청한 처리 순서와 출처를 표시합니다. 각 업무의 **실제 도구 동작**을 펼치면 자료 읽기, 스킬 호출, Python 실행, 파일 작성 등 관찰된 동작과 대상 이름을 차례로 볼 수 있습니다. 도구 응답 수신·명시적 오류·결과 미확인을 구분합니다. 한 요청에 여러 업무가 섞인 경우는 연결이 불명확하다고 표시합니다. 이는 기록에서 관찰한 실행이며 결과물의 정확성이나 업무 완료까지 확인한 것은 아닙니다. 긴 표는 표 안에서 스크롤할 수 있습니다.

문서가 있다는 사실, 도구 호출을 관찰했다는 사실, 업무가 성공했다는 사실은 다릅니다. 한도에 걸리거나 기록 형식을 읽지 못하면 미확인 범위를 표시하며, 전체를 다 확인한 것처럼 보고하지 않습니다. 분류는 업무 후보이며 개인의 성과나 실제 전체 업무량을 뜻하지 않습니다.

결과는 `업무현황.html` · `업무자산.md` · `catalog.json`입니다. HTML에서 읽고 같은 Markdown을 내려받을 수 있습니다. Markdown에는 업무별 자료·절차·실제 도구 동작·다른 진행 방식·관련 지식 후보와 출처를 담습니다. 이를 검토해 업무 기준과 예외를 보완하면 팀 지식이나 재사용 스킬을 설계하는 자료로 쓸 수 있습니다. 관련 지식 후보는 문서의 제목·설명에 근거하므로 확정된 업무 규칙과 구분합니다.

여러 사람의 결과를 모을 때는 Markdown으로 내용을 검토하고 `catalog.json`으로 중복·출처를 보존해 합칩니다. 원본 대화·명령어·인증정보를 중앙으로 모을 필요는 없습니다. 제목·대상 이름·상대경로에도 업무정보가 남을 수 있으므로 공유 전에 검토하세요. 내보낸 목록만 합칠 때는 이 PC의 기록을 끼워 넣지 않습니다. **이 스킬을 실행할 때만 확인**하며 평소 작업에 상시 수집이나 자동 업로드, 추가 모델 호출은 없습니다.

## 9. 오류가 났을 때


| 상황 | 먼저 할 일 |
| --- | --- |
| 목록은 있는데 스킬을 안 씀 | `/skills`와 정확한 본문 로드 기록, 업무 실행을 따로 확인 |
| `locked by plugin` | 플러그인 관리 표시인지 확인. 비활성·미설치로 단정하지 않음 |
| `Unknown skill` | 현재 목록의 정확한 네임스페이스 확인. 캐시 존재만으로 호출 가능하다고 하지 않음 |
| 승인 전 대기 | 실행 준비·권한 판정·도구 실행을 구분. 승인 응답 대기라고 미리 단정하지 않음 |
| 파일 없음 | 요청한 파일명·현재 폴더를 확인. 다른 폴더까지 자동 검색하거나 보호 오류로 단정하지 않음 |
| 위험 명령이 차단됨 | 그 명령은 실행하지 않음. 대상과 필요성을 검토하고 우회·보호 해제 없이 안전한 계획 확인 |
| 기존 개인 도구에 재시험 필요 | 같은 저장 범위에서 정상·오류 입력을 다시 시험. 소스 삭제·재설치·검사 조건 제거로 해결하지 않음 |
| 작업 중지 후 계속 진행 중 | 종료 확인 결과를 기다리고 마지막 실행 상태 확인. 같은 작업 재요청이나 다른 프로그램 전체 종료 금지 |
| 한글 깨짐 | 기존 파일과 표시 인코딩부터 확인. 반복 생성·원본 손실 변환 금지 |
| 스크립트 오류 | 마지막 예외와 정확한 경로를 확인. 한글 문제로 단정하거나 중첩 실행하지 않음 |
| 앱만 인증 실패 | 기존 CLI 로그인과 앱의 실행·설정 환경을 비교. 인증 값 공유·전체 초기화 금지 |
| 검증 오류 반복 | 마지막 상태·파일 유무를 남기고 중지. 미검증을 성공으로 기록하지 않음 |

설치 ZIP을 모두 푼 뒤 **Diagnose-CompanyAgent.cmd**를 열고 실제 작업 폴더를 지정하면 설치·스킬 기록·준비물을 읽기 전용으로 확인할 수 있습니다. 문서·메일·DB 본문이나 모델을 자동 조회하지 않습니다. 로그를 공유하기 전 개인 경로·업무 내용·인증 값을 가리세요.

작업 중지는 이미 만든 파일·보낸 메일을 되돌리지 않습니다. Workspace가 직접 시작한 CLI의 종료를 확인했어도 모든 하위 프로그램이 종료됐다는 뜻은 아닙니다. 중지가 확인되지 않으면 마지막 상태를 담당자에게 전달하고 실제 결과부터 확인합니다.

## 10. 업데이트와 의견 보내기

[최신 Release](https://github.com/bongG-moon/claude_base_repo/releases/latest)의 직원용 설치 ZIP 전체를 풀고 기존과 같은 범위를 선택해 업데이트합니다. `Source code (zip)`은 직원용 설치 파일이 아닙니다. Workspace 사용자는 같은 Release의 별도 미리보기 ZIP을 사용합니다. 개인 기억·스킬·지식·모델·MCP·다른 플러그인을 임의로 초기화하지 않습니다. 업데이트 후 Claude Code를 다시 시작하세요.

```text
설치 버전 / 사용 화면 (CLI·VS Code·Workspace):
실제 요청 (가상 자료로 재현):
기대한 결과 / 관찰한 결과:
확인한 파일·수치·범위 / 미확인 부분:
개선하거나 선택 기능으로 바꾸고 싶은 점:
```

실제 사용 PC에서 작은 가상 예제로 확인한 뒤 업무에 적용하세요. 조직의 권한·보안 설정에 따라 사용할 수 있는 기능이 다를 수 있습니다.
