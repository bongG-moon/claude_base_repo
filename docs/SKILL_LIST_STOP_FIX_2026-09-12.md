# Skill 목록 조회 뒤 Stop 오류가 나오던 문제

> 배포 정정: 이 문서에서 기록한 1.3.0 수정 ZIP은 기존 설치와 버전 충돌로
> 업데이트할 수 없습니다. 설치는 [1.3.1 패키지](UPDATE_1.3.1.md)를 사용하세요.
> 아래 해시는 문제 조사 당시의 기록이며 현재 권장 설치 파일이 아닙니다.

## 확인한 원인

실제 사용자 세션 `6110f4ae-7903-4837-bd12-5dd936979a9e`의 두 Bash 호출은
`skill inventory --project-root ...`, `skill conflicts --project-root ...`였다.
둘 다 조회였으나 활동 분류기가 Skill 명령에서 `--state-root`만 인식하여,
프로젝트 옵션이 붙은 명령을 알 수 없는 실행으로 분류했다. 이 때문에
mutationCount가 2가 되고 불필요한 Stop 검증 요구가 발생했다.
이전 업무의 미검증 변경 때문에 생긴 사례가 아니었다.

## 수정

- 목록·중복·검색·해결 조회의 실제 옵션 문법을 분류기에 반영했다.
- 프로젝트/기본 범위와 설치 전 미리보기 옵션도 읽기 전용으로 분류한다.
- 우선 설정 변경(prefer/order/reset), 쉘 조합, 출력 리다이렉션, 알 수 없는
  옵션은 조회 예외에 포함하지 않는다. 권한 자동 승인을 늘리지 않는다.
- 기존 진짜 미검증 변경이 있다면 새 조회가 이를 지우지 않는다.
- `/company-agent:skills`는 기본 한국어 목록과 간단한 중복 안내로 끝낸다.
  이후 정당한 보정이 있더라도 최종 목록을 상태 한 줄로 대체하지 않는다.
- 목록 개수는 `summary.bySource`/`summary.byPlugin`에서 계산한다.
  다른 플러그인은 기본적으로 이름과 개수만 보여주고 없는 항목을 보태지 않는다.

## 검증 구분

실제 Claude Code 조회 재실행 증거는 바탕화면 실험실의
`controller-smoke/evidence/skills-list-fix-01-fa247e`에 보존했다.
mutationCount=0, stopRetryCount=0, verification=null, learningAttempts=0을 확인했다.
첫 재실행에서 모델이 목록 개수를 잘못 말해 집계와 표시 지침을 추가 보완했다.
최종 실제 재실행: `controller-smoke/evidence/skills-list-final-01-8eb183`.
37.89초 정상 종료, 한국어 목록 유지, 실제 집계 개수 반영,
mutationCount=0 / stopRetryCount=0 / verification=null / learningAttempts=0.
최종 실행에서는 비교한 사용자 설정 두 파일의 해시도 동일했다.

첫 재실행 중 실제 Claude settings.json의 해시 변경이 관찰됐으므로 이 실행에
대해서는 사용자 설정 무변경을 주장하지 않는다. 기록된 모델 도구 호출은
목록 조회와 결과 Read뿐이며 변경 주체는 확인되지 않았다. 별도 사용자 작업이
진행 중일 수 있어 설정을 되돌리거나 덮어쓰지 않았다.

분류기 회귀 테스트는 실제 오류 명령 형식, 읽기 전용 조회 후 Stop 통과,
기존 실제 변경 보존, 잘못된 옵션·쓰기 명령 제외를 확인한다.
최종 전체 테스트는 414개 통과, 제외 0개(110.995초)이며 실제 Claude 확인
옵션을 켠 상태로 실행했다. 테스트 실행기의 모의 응답 테스트는 위 실제
Claude Code 사용 증거와 구분한다.
