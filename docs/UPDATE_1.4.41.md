# Company Harness 1.4.41

비전 작업이 끝났다는 사실과 이미지를 실제로 읽었다는 근거를 구분하도록 안내를 보완합니다. 필요할 때만 회사에서 입력 경로를 비교할 수 있는 별도 시험 키트도 제공합니다. 별도 개발 중인 Workspace 앱·Computer Use MCP 변경은 포함하지 않습니다.

## 평소 업무는 그대로

- 비전 작업자는 이미지 내용을 확인하지 못하면 `VISION_UNAVAILABLE`과 확인하지 못한 범위를 반환합니다. 파일명·질문·이전 답변으로 내용을 추측하거나 OCR로 조용히 대체하지 않도록 안내합니다.
- 작업자 정상 종료, 모델의 자기 소개, 토큰 수, 기록에 이미지가 있다는 사실만으로 판독 성공이나 실패 원인을 확정하지 않습니다. 요청한 별칭과 응답 모델명 차이만으로 다른 모델로 전환됐다고 판단하지 않습니다.
- 실행 분기·후크 등록·승인 정책·메인 모델 설정은 바꾸지 않았습니다. 상시 연결 시험·추가 LLM 호출·정확도 판정 서비스를 넣지 않습니다. 작업자 지침은 오히려 축약했으며, 실제 토큰 수나 운영 속도가 개선됐다고 단정하지 않습니다.
- 기존 비전 인계와 반복 방지, 개인 기억·스킬·모델·MCP 설정 보존은 유지합니다. 이번 변경은 지침을 명확하게 한 것이며 모든 모델의 준수를 보증하는 장치는 아닙니다.

## 회사에서 필요할 때만 입력 경로 비교

별도 파일 `VLM-Input-Check-20261013.zip`에는 `시작하기.html`, README, Python 스크립트, 가상 PNG 2장만 들어 있습니다. 하네스 설치 ZIP에 자동 등록되는 기능이 아니며 사용하지 않으면 호출·토큰 소모가 없습니다.

1. 기본 실행은 이미지 크기·해시만 확인하는 오프라인 점검입니다. 네트워크 요청이나 인증정보 조회를 하지 않습니다.
2. 회사에서 승인한 주소·모델을 확인하고 명시적으로 전송하면 **A: 일반 이미지 입력**, **B: 같은 이미지의 합성 Read 도구 결과**를 각 한 번씩 비교합니다. 응답 상한은 각각 600토큰이며 자동 재시도는 없습니다. **B는 실제 CLI 실행이 아닙니다.**
3. **C: 실제 Claude Code에서 비전 작업자가 파일을 Read로 읽는 시험**은 새 대화에서 별도로 진행합니다. 이미지 PNG만 사용하고 정답표·스크립트는 모델에 주지 않습니다.

인증값·원본 요청·base64·서버 오류 본문은 결과에 저장하지 않습니다. 결과를 공유하기 전에는 사용자가 검토합니다. 모델 계열에 비전 기능이 있다고 해서 현재 사내 연결이 정상이라고 확정하지 않습니다. **실제 사내 HCP 모델의 응답 정확도와 게이트웨이의 이미지 전달은 아직 미검증입니다.**

## 검증 기록

변경 직후의 로컬 회귀 시험과 별도 키트·안내 HTML 확인 결과는 [비전 입력 검증 기록](VALIDATION_VISION_INPUT_20261013.md)에 정리했습니다. 이 기록의 152개 시험은 로컬 구현에 대한 것이며 실제 사내 모델 호출 결과가 아닙니다. 이번 릴리즈 패키지와 게시 검증 결과는 릴리즈 검증 기록에서 별도로 확인합니다.
