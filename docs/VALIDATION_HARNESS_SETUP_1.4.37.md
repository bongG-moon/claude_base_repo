# Company Harness 1.4.37 단일 EXE 설치 검증

검증일: 2026-10-05. 로컬 구현·배포 준비 결과이며, 1.4.37 Release와 사내 GitLab에는 아직 게시하지 않았습니다.

## 직원 사용 흐름

`Company-Harness-Setup.exe`를 내려받아 두 번 클릭합니다. 기본은 **내 Claude Code 전체에서 사용**입니다. 필요하면 **선택한 업무 폴더에서만 사용**을 고른 뒤 **설치하기**를 누릅니다. 진행·완료·실패를 같은 창에서 표시하고 완료 후 Claude Code를 다시 실행하도록 안내합니다.

기존 Company Agent는 업데이트합니다. 기존 스킬 선호는 보존하며, 다른 하네스를 교체해야 하는 경우에는 **기존 유지 / 백업 후 설치**를 한국어로 묻습니다. Python·Claude 경로를 확인할 수 없을 때만 파일 선택창을 사용합니다. 정상 경로에 명령어·모델·세션·토큰 입력이나 새 승인을 추가하지 않았습니다.

## 구현

- `deploy/CompanyAgent.Setup.cs`: Windows Forms 설치 UI, 검증된 내장 파일 준비, 숨겨진 PowerShell 실행, 결과 표시.
- `deploy/CompanyAgent.SetupBridge.ps1`: 현재 사용자 환경을 상속하여 기존 `Setup-CompanyAgent.ps1`를 호출합니다. UI용 인자만 전달하고 보호 검사 생략 옵션을 받지 않습니다.
- `deploy/New-CompanyAgentSetup.ps1`: 승인된 직원 ZIP을 그대로 포함한 EXE를 생성합니다. 실제 내장 ZIP의 추출·해시 확인을 수행한 뒤 배포 파일을 만듭니다.
- `deploy/New-GitLabHarnessDelivery.ps1 -SetupExe`: EXE 버전과 내장 ZIP이 입력 직원 ZIP과 같은지 확인하며, 직원 안내를 EXE 다운로드·더블클릭으로 작성합니다.
- 통합 사용자 안내서의 시작하기와 설치 문서를 같은 사용 흐름으로 갱신했습니다.

EXE는 현재 사용자의 `%LOCALAPPDATA%\CompanyAgent\setup-cache`에 자체 준비 파일을 풉니다. `asInvoker`로 실행하며 설치 대상·계정 검사는 기존 설치기가 담당합니다. 모델·MCP·개인 자료 보존과 기존 백업·복구 절차를 사용합니다. 자동 업데이트, 의존성 자동 설치, 추가 모델 호출, 업무 후크·상주 프로세스를 추가하지 않았습니다.

## 화면 배율 수정 — 2026-10-05 추가 확인

초기 EXE는 기본 배율의 렌더링만 확인하여 고배율 환경에서 글자·버튼이 잘리는 문제를 놓쳤습니다. 고정 행 높이·고정 버튼 크기를 자동 크기로 바꾸고 96 DPI 기준 자동 배율을 지정했습니다. 작은 창에서는 내용만 스크롤하고 설치·닫기 버튼은 별도 하단 영역에 유지합니다. 설치 기능과 내장 직원 ZIP은 그대로입니다.

컴파일된 EXE 연결·UI 시험은 **8개 통과**입니다. 기존 6개에 100%·150%·200% 상당의 글꼴/컨트롤 확대 및 작은 창의 겹침·잘림·버튼 위치 검사를 추가했습니다. Windows 설정을 변경하지 않았으며, 이 확대 시험과 실제 Windows 화면 관찰은 구분합니다.

Computer Use로 수정 EXE의 실제 Windows 창과 업무 폴더 선택 상태를 확인했습니다. 제목·본문·선택지·버튼이 온전히 표시됐습니다. 마지막 검증용 창 닫기 단계에서 사용자가 물리 Esc로 Computer Use를 중단하여 추가 UI 조작은 하지 않았습니다. 실제 설치는 실행하지 않았습니다.

기존 실행 파일 경로와 GitLab 준비 자료도 수정 EXE로 교체했습니다. 현재 EXE SHA-256은 `74e0452593348a44c90dca156e36aa427ea44ee29c5f6e4e8e75b266f946d1de`입니다. 위 최초 빌드의 EXE 해시는 초기 검증 기록이며 현재 파일의 해시와 다릅니다. 내장 직원 ZIP 해시는 유지됩니다. 배포 설명의 해시·해시 파일·담당자 전달 ZIP도 현재 EXE와 일치하는지 확인했습니다.

## 설치 표시 이름 변경 — 2026-10-05 추가 확인

설치 창 제목은 **Company Harness 설치**, 본문 제목은 **Company Harness**, 직원용 실행 파일은 **Company-Harness-Setup.exe**로 변경했습니다. 폴더 선택·교체 안내·업데이트 진행 문구와 파일의 제품 정보, GitLab 게시 설명도 같은 이름을 사용합니다. 내부 플러그인 ID·명령·저장 경로와 검증된 직원 ZIP은 변경하지 않았습니다. 위 EXE 경로와 해시는 앞선 빌드의 기록이며 아래가 이름 변경 후 최신 빌드입니다.

- 최신 직원 실행 파일: `dist/harness-setup-1.4.37-harness/Company-Harness-Setup.exe`, 1,342,464바이트.
- 최신 EXE SHA-256: `4f648dd8f983064bb3a8fc677b1e482d49b1183b4279f9f371c855682e64e75d`.

- 이름 변경 후 설치·업데이트·오류·배율 테스트 8/8, GitLab 자료 준비 테스트 10/10을 다시 실행하여 통과했습니다. 100%·150%·200% 상당의 글꼴 크기에서 실제 컴파일된 창의 제목·본문과 배치를 검사합니다.

사내 GitLab 배포는 **파일·해시·게시 설명·담당자 안내 생성까지** 구현되어 있습니다. 실제 GitLab 파일 업로드·Release 게시 기능은 없으며 담당자가 수동으로 진행해야 합니다. 생성 결과의 `published:false`, `networkUsed:false`도 검사했습니다. 이름 변경 검증에서 실제 사용자 설치나 사내 업로드를 실행하지 않았습니다.

## 임시 파일 정리 — 2026-10-05

이전 이름의 테스트 EXE·중복 GitLab 준비 자료 8곳, 중간 빌드 폴더 5곳, 임시 검증 폴더 3곳을 휴지통으로 옮겼습니다. 위 초기 검증 경로와 미리보기 경로는 과거 기록이며 현재 파일이 남아 있다는 뜻은 아닙니다. 최신 `harness-setup-1.4.37-harness`·`gitlab-harness-1.4.37-harness`·담당자 전달 ZIP, 원본 직원 ZIP과 게시된 Release 원본, 자동 테스트 소스는 보존합니다. 다른 Workspace 앱·MCP·실습 작업 자료는 정리 대상에 넣지 않았습니다.
