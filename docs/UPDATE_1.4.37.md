# 1.4.37 — Company Harness 간편 설치와 조건부 이미지 검토

직원은 **Company-Harness-Setup.exe 하나**를 내려받아 두 번 클릭합니다. **Company Harness 설치** 화면에서 사용 범위를 고르고 **설치하기**를 누르면 기존 설치기를 통해 설치하거나 업데이트합니다. 완료 후 Claude Code를 다시 실행합니다. 설치 화면의 표시 이름은 Company Harness이며 기존 `company-agent` 플러그인·명령·개인 저장 경로는 유지합니다.

이번 하네스에는 이미지 관찰을 위한 `company-agent:vision-worker`도 포함합니다. 기존 메인 모델과 일반 작업자 3개의 모델 선택은 유지하고, 운영 환경에서 필요한 이미지 확인만 별도 작업자에게 맡깁니다.

## 설치 화면

- 기본 선택은 현재 Windows 사용자의 Claude Code 전체입니다. 한 업무 폴더에서만 사용할 경우 폴더를 선택합니다.
- 필요한 Claude Code·Python은 자동으로 확인합니다. 확인할 수 없을 때만 준비된 실행 파일 위치를 선택합니다.
- 기존 Company Agent는 업데이트하며 개인 자료·기존 스킬 선호·모델·MCP 설정을 보존합니다. 다른 하네스를 교체해야 하는 경우에만 백업·변경 설명과 한국어 선택창을 표시합니다.
- 진행 상태와 완료·실패를 설치 창에서 보여줍니다. 성공 시에만 완료를 표시하며 상세 내용과 안내서를 열 수 있습니다.

## 담당자 빌드

기존 `New-OfflineBundle.ps1`로 새 버전의 직원 ZIP을 만들고 다음 도구에 전달합니다.

```powershell
powershell.exe -NoProfile -File .\deploy\New-CompanyAgentSetup.ps1 -BundleZip "<검증된 직원 ZIP 경로>"
```

생성된 EXE는 해당 직원 ZIP을 그대로 포함합니다. EXE 준비 파일은 현재 사용자의 `%LOCALAPPDATA%\CompanyAgent\setup-cache`에 풀며, Python·Claude Code·사내 인증은 기존 PC 환경을 사용합니다. 자동 다운로드·자동 업데이트·새 로그인은 추가하지 않았습니다. 관리자 권한을 요구하지 않는 `asInvoker` 실행 파일이며, 설치 대상 검사는 기존 설치기가 담당합니다.

GitLab 게시용 파일 준비에는 `New-GitLabHarnessDelivery.ps1 -BundleZip "<같은 직원 ZIP>" -SetupExe "<생성한 EXE>"`를 사용합니다. EXE 안의 직원 ZIP이 입력 ZIP과 같은지 확인한 뒤 직원에게 EXE를 내려받도록 게시 설명을 만듭니다. 이 도구는 실제 업로드나 Release 게시를 하지 않습니다. 생성된 안내에 따라 담당자가 사내 GitLab에 파일을 첨부하고 게시합니다.

## 이미지 확인과 후속 업무

기존 환경의 `ANTHROPIC_CUSTOM_MODEL_OPTION` 값이 정확히 `HCP-Vision-Latest`일 때만 `visionRouting.enabled`가 켜집니다. 설정이 없거나 값이 다르면 비전 라우팅은 비활성 상태이며 기존의 허용된 이미지 읽기 흐름을 유지합니다. 설치기는 이 설정을 추가하거나 모델 목록·API를 시험 호출하지 않습니다.

활성화된 환경에서는 이미지 파일 `Read`와 정해진 화면 캡처 도구의 호출을 이미지 전용 작업자로 안내합니다. 일반 작업자는 필요한 이미지 경로·확인할 부분을 조율자에게 돌려주며 직접 재위임하지 않습니다. 조율자는 별도 문맥의 비전 작업자에게 필요한 경로 또는 관찰 도구·인자와 질문·범위만 전달하고, 한국어 텍스트 결과를 받아 기존 모델로 같은 업무를 이어갑니다. 이미지 관찰을 수행할 때만 이 별도 작업자의 모델 호출이 추가됩니다. 메인 모델 전환, 상주 작업자, 업무마다 수행하는 모델 탐색은 추가하지 않습니다.

이미지를 파일로 저장한 뒤 다음처럼 요청할 수 있습니다.

```text
"C:\업무\발표자료\3페이지.png"에서 제목과 표가 겹치는지 확인해줘.
```

결과를 받은 뒤에는 “방금 확인한 문제를 반영해서 설명 문장을 짧게 다듬어줘”처럼 이어갑니다. 비전 작업자는 관찰 결과만 반환하며 원본 업무 파일을 수정하거나 별도 결과물을 만들지 않습니다. 전체 대화·무관한 문서·원본 이미지·raw base64·전체 OCR 전문을 일반 작업자에게 전달하지 않습니다.

비전 모델·이미지 입력·관찰 도구를 사용할 수 없으면 `VISION_UNAVAILABLE`과 확인하지 못한 범위를 남깁니다. 다른 모델로 자동 대체하거나 같은 이미지를 반복 전송하지 않습니다. 가능한 내용·구조 검사는 계속하되 **시각 검증 미확인**을 알립니다. 실제 권한 거부·승인 대기와 DRM·원자료 처리 제한은 그대로 적용합니다.

원본 CLI에 이미지를 직접 붙여넣는 입력은 도구 후크보다 먼저 모델에 전달되므로 이 라우팅으로 가로챌 수 없습니다. 모든 MCP의 혼합 텍스트·이미지 출력을 자동 변환하지도 않습니다. 알려진 이미지 파일·화면 캡처 경로에 대한 처리이며, 사용자는 파일 경로와 확인할 범위를 지정하는 방식으로 요청합니다.

## 운영 확인과 배포 범위

로컬 모형 시험은 라우팅, 기존 모델 유지, 텍스트 후속 업무와 오류 처리 계약을 확인합니다. 사내 HCP 모델의 실제 이미지 이해·게이트웨이 권한·요청 모델 로그는 운영 환경에서 별도로 확인해야 합니다. 담당자는 HCP 모델 목록 등록, 정확한 `HCP-Vision-Latest` ID의 계정·게이트웨이 허용, 설치된 Claude Code의 사용자 지정 작업자 모델 ID 지원을 각각 확인한 뒤 승인된 시험 이미지로 관찰 결과와 일반 텍스트 후속 질문을 검증합니다. 설정값이나 작업자 파일만으로 운영 성공을 판단하지 않습니다.

이미 게시한 1.4.36과 이전 Release 파일은 변경하지 않습니다. 이번 배포는 하네스·간편 설치기·사용자 안내서이며 별도 Workspace 앱 변경은 포함하지 않습니다. 로컬 빌드·시험, 공개 Release 게시, 사내 GitLab 게시와 사내 PC 적용은 각각 확인해야 합니다. 기존 설치 PC에는 승인된 새 설치 파일을 같은 범위로 실행하여 적용합니다.
