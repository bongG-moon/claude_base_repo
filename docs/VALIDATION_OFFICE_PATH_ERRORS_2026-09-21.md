# Office 읽기 진입 경로와 오류 안내 검증

검증일: 2026-09-21. v1.4.21 이후 수정이며 1.4.22에 포함합니다. 설치·업데이트 검증은 [1.4.22 배포 검증](https://github.com/bongG-moon/claude_base_repo/blob/main/docs/VALIDATION_RELEASE_1.4.22.md)을 참고하세요. 기존 PC는 새 설치본으로 업데이트해야 적용됩니다.

## 운영 로그에서 확인한 원인

1. 첫 호출의 `plugin/skills/office-reader/scripts/Invoke-CompanyAgent.ps1`은 기존 배포에 없는 경로였습니다. PowerShell 실행 자체가 실패했으므로 Excel 잠금 여부를 확인한 단계가 아닙니다.
2. 공통 진입점으로 실행한 뒤의 `source_not_found`도 Office를 열기 전 경로 검사 결과입니다. 로그에 실제 `--file` 값이 모두 나오지 않아, 모델이 어떤 경로로 잘못 조합했는지는 확정하지 않습니다.
3. 실패 후크가 안내 문구의 `DRM`이라는 단어까지 보호 차단으로 오인했습니다. 이는 파일이 실제로 보호되어 읽히지 않았다는 근거가 아닙니다.
4. 현재 폴더에서 파일이 확인됐는데도 Desktop 전체를 탐색하는 복구는 불필요합니다.

## 수정 범위

| 구분 | 변경 |
| --- | --- |
| 진입점 | 스킬 옆 `scripts/Invoke-CompanyAgent.ps1`을 추가해 실제 공통 Office 읽기에 연결. 같은 PowerShell에서 실행하며 Python 준비를 중복하지 않음 |
| 파일 경로 | `--file "AI_과정구분.xlsx"`처럼 현재 폴더의 정확한 파일명을 지원. 실제 실행 폴더와 결합하며 임의 폴더 탐색이나 잘못된 절대 경로 자동 교정은 하지 않음 |
| 연결 정보 | 설치된 자기 Office 진입점에만 기존 후크의 누락 연결 정보 보완 적용. 사용자 지정 파일·범위·세션 보존, 자동 권한 승인 없음 |

| 사용 중 파일 | Windows 공유/잠금 위반이 확인되면 `file_in_use`로 구분해 해당 파일을 저장·닫은 뒤 다시 요청하도록 안내. Office 시작 오류·일반 COM 오류를 원본 잠금으로 추측하지 않음 |
| 스킬·가이드 | 직접 사용할 명령, 현재 폴더의 파일명 사용, 현재 폴더 한 번 확인 후 위치 질문, 잠금 안내를 반영 |

## 비용과 안전 경계

- 정상 읽기에 새 모델 호출, 세션 검색, 별도 사전 잠금 검사를 추가하지 않습니다.
- Windows가 실제 파일 읽기의 공유 위반을 일반 PermissionError로 반환한 경우에만, 같은 경로의 읽기 전용 핸들을 한 번 확인합니다. 승인 전 문서 본문은 읽지 않습니다.
- 스킬-local 진입점은 `business office-read`만 받으며 다른 CLI 작업의 별칭이나 임의 실행 통로가 아닙니다.
- 읽기 승인, 회사 정책, 문서 접근 권한, 파일/범위 제한은 유지합니다. 대체 파서·복사본·강제 프로세스 종료는 추가하지 않았습니다.
- 파일이 Excel에 열려 있다는 사실만으로 읽기 실패나 잠금으로 판정하지 않습니다. 실제로 읽을 수 있으면 기존 읽기 절차를 사용합니다.

## 검증

- 전체 회귀 1,225개 실행: 1,220개 통과, 5개 제외, 실패 없음 (358.009초). 실행 중 마무리된 MCP 오류와 프로그램 시작 단계 구분은 아래 최종 계열별 재실행으로 확인했습니다. 제외 항목은 Windows 심볼릭 링크 권한 관련 3개와 별도 신청 방식의 실제 Claude 설정/등록 시험 2개입니다.
- 한글·공백 폴더와 한글 파일명을 이용한 실제 Git Bash → 스킬-local PowerShell → 공통 CLI 시험: 첫 호출에서 `office_read_consent` 도달, Python 준비 1회, 승인 전 Office 미실행.
- 실제 Windows 배타 파일 핸들을 이용한 합성 시험: 잠금을 `file_in_use`로 구분하고 Office 미실행. 사용자 프로그램을 종료하지 않음.
- 최종 Office 계열 98개와 Excel 16개 통과. 정상 읽기에 핸들 검사가 추가되지 않음, 일반 권한 오류·도구 시작 오류를 파일 잠금으로 오인하지 않음 포함.
- 최종 business 계열 84개 통과. 오류 분류 신규 회귀 11개 포함.
- 별도 독립 검토의 실행 계약 26개·Office 연결 20개 통과. 보호 오류 분류에서 발견한 일반 JSON 거절 누락, 셀 내용 오탐, MCP 명시 오류 누락은 보완 후 재확인.
- 오프라인 설치 ZIP 생성·검증 시험 통과. 새 스킬-local 진입점의 포함을 필수 검사 항목에 추가. 시험용 임시 패키지는 게시하지 않았습니다.
- `office-reader` 스킬 형식 검사, 통합 가이드 및 설치 Markdown 동기화 검사 통과.

로컬 로그: `.smoke/office-path-errors-20260921.log`, `.smoke/office-path-readers-final-20260921.log`, `.smoke/office-errors-business-final-20260921.log`, `.smoke/office-path-bundle-20260921.log`.

## 실제 환경 확인 범위

사내 HCP 모델의 지침 준수, 실제 `AI_과정구분.xlsx`, 사내 Excel/DRM 환경은 직접 실행하지 않았습니다. 합성 시험의 통과를 실제 업무 성공이나 속도 보장으로 제시하지 않습니다.

새 수정본을 배포·설치한 뒤 새 대화에서 원래 요청을 확인합니다. 정상 기대 흐름은 스킬 로드 → 준비된 명령과 정확한 파일명 → 읽기 승인 → 결과입니다. 세션·설치 폴더·Desktop 탐색이나 임의 파서로 전환하지 않아야 합니다. 실제 잠금일 때는 저장·닫기 안내 뒤 기다려야 하며 자동 반복 실행하지 않아야 합니다.
