# 첫 업무 스킬 선택 연결 개선

## 바뀐 동작

사용자는 기존처럼 “PPT 내용을 분석해줘”, “업무 메모를 만들어줘”라고 요청하면 됩니다.
처음에는 전체 목록을 보고 용도를 비교하고, 선택한 스킬만 자세히 읽은 뒤 업무를 진행합니다.
같은 목록을 매번 다시 읽거나 모든 스킬 본문을 한꺼번에 넣지 않습니다.

목록만 만들어 두었던 기존 구조와 달리, 이제 지원되는 업무 실행 직전에 읽기 기록을 확인합니다.
목록/스킬을 건너뛴 경우 짧은 준비 안내로 실행을 보류하며, 업무 마지막의 Stop 오류를 추가하지 않습니다.
개인·프로젝트 우선 설정, 명시적 스킬 호출, 본인 PC의 모델·Memory·기존 스킬은 유지합니다.

## 자동 검사 범위

- 처음 요청의 목록 → 본문 → 실행 순서
- 성공한 전체 읽기와 실패·부분 읽기의 구분, 나누어 읽기
- 새 요청의 재선택과 읽었던 본문 재사용
- 컴팩트·설치·삭제·본문 변경에 따른 기록 무효화
- 프로젝트 우선 설정, 모호한 이름, 직접 호출 전용 스킬
- 조율 지침만 읽고 실제 업무 스킬 선택을 생략하는 문제
- 스킬 없음 처리와 잘못된 세션/턴의 기록 거부
- 목록 조회에 검증 실패를 요구하지 않는지, 기존 DB 제한이 계속 적용되는지
- 실제 Windows 설치 진입점과 시작/요청/읽기/실행 Hook의 연결

## 실제 Claude Code 확인

별도 임시 폴더의 소스 플러그인과 가상 자료로 검사했습니다. 현재 설치 플러그인이나 사용자 설정은 덮어쓰지 않았고, 실제 메일·DB·회사 Office 문서를 읽지 않았습니다.

첫 PPT 읽기 요청에서는 모델이 처음 자체 확인 명령을 시도했습니다. 실행 준비 확인이 이를 보류하자, 전체 목록과 `office-reader/SKILL.md`를 읽고 하네스의 `business office-read` 진입점을 선택했습니다. 두 읽기 기록과 선택 상태가 실제 세션에 남았으며 Stop 보정은 발생하지 않았습니다.

이 시도의 실제 Office 명령은 격리 테스트의 승인 제한으로 실행되지 않았습니다. 따라서 **스킬 선택 연결은 확인했지만 사내 문서 읽기 성공을 검증한 것은 아닙니다.** 첫 시도부터 모든 모델이 항상 스킬을 정확히 선택한다는 뜻도 아닙니다.

별도 프로젝트 전용 `custom-memo` 스킬 테스트에서는 목록과 해당 스킬을 읽고
`업무 메모 → 핵심 → 근거 → 확인 문구` 양식의 Markdown 파일을 실제 생성했습니다.
결과물에 목표 10건, 완료 9건, 달성률 90%가 반영된 것을 다시 읽어 확인했습니다.
프로젝트 스킬 선택과 작성까지 연결되었으며, 기존 사용자 설정 해시는 전후 동일했습니다.

두 실제 세션 모두 처음에 스킬 확인보다 자체 확인 명령을 먼저 시도했고 준비 확인이 이를 교정했습니다.
메모 작성 테스트에서는 기존 완료 검증의 Stop 보정이 한 번 발생했고 결과 재확인 뒤 종료했습니다.
일부 영어 진행 안내와 내부 확인 설명도 관찰했습니다. 따라서 이번 결과는 **스킬 선택 연결 검증**이며,
첫 도구 선택의 완전성·모든 안내의 무출력·최종 결과 단 한 번 출력을 보증하지 않습니다.
관찰 후 짧은 시작 지침에도 한국어·조용한 처리·Glob/Read/Grep 우선을 명시했습니다.

마지막 지침을 반영한 별도 목록 안내 질문에서는 도구 호출·승인 거절·추가 검증 없이
한국어 답변 한 번으로 종료했습니다(11.54초). 이 경우는 Claude가 이미 제공받은 스킬 설명으로
답했으므로 MD를 실제 읽었다는 검증으로 계산하지 않습니다.

이 실사용 검사는 이 PC의 Claude Sonnet 5 환경입니다. 사내 HCP 모델의 선택 정확도나 처리 시간을 대신 검증하지 않습니다.

## 최종 자동 검사 결과

2026-09-15 최종 소스 기준: **610개 통과, 실패 0개, 제외 0개** (101.399초).
`COMPANY_AGENT_TEST_REAL_CLAUDE=1`로 전체 unittest를 실행했습니다.
22개의 선택 연결 검사는 Windows 설치 진입점 검사와 작업자에게 선택 경로를 전달하는 검사도 포함합니다.
공통 안내문은 179줄이며 기존 180줄 제한을 유지했습니다. 변경 파일의 공백/패치 검사도 통과했습니다.
