# 초보자 업무 도우미 구현·검증 — Workspace 0.3

2026-09-19 · Windows 개발 환경 · 정식 Release 및 사내 시범 사용 전

## 구현한 범위

기존 Claude Code 연결과 Company Agent 저장·검증 기능을 화면에 연결했다. 회사 + 개인의 두 관리 영역을 유지한다. 부서 기준은 회사 정책 안에 두고, 프로젝트는 적용 범위로만 취급한다. 새로운 AI 라우터나 기억 저장소를 경쟁적으로 추가하지 않았다.

| 기능 | 이번 구현 | 사용자 확인 또는 제한 |
| --- | --- | --- |
| 첫 업무 코스 | 읽기 → 결과 만들기 → 수정 → 기억 → 재사용. 앱/오프라인 안내가 공통 JSON 사용 | 예문은 입력창만 채우며 자동 전송하지 않는다. 현재 진척은 직접 확인 여부이며 세분화된 코스 상태 머신은 후속 범위 |
| 개인 기억 | 조회, 변경안, 명시 저장, 비활성화, 이전 내용 복원안. 기존 저장/검색/버전 서비스 사용 | 저장 성공과 다음 모델 답변의 반영 성공을 구분 |
| 회사·개인 지식 | 회사 읽기 전용, 개인 용어/업무 지식 초안·검토·활성화·중단, 출처/검토일 | 테이블/조인/회사 확장 문서의 편집은 기존 도구 사용. 공유는 선택한 지식의 로컬 ZIP 후보만 생성 |
| 짧은 폴더 지침 | 목표·입력·출력·검증 기준을 `.claude/rules/company-workspace-brief.md`로 저장 | 기존/빈 파일·수동 수정은 보존. 전역 `CLAUDE.md`, 회사 정책, 모델/MCP 설정을 교체하지 않음 |
| 사용 현황 | 기존 완료 이벤트, 질문/승인 대기 구간, 사용자가 선택한 JSONL 분석, 모델별 집계 | 누락은 미제공, 재시도 추정은 하지 않음. CLI 합계·부모/자식·선택 로그를 더하지 않음 |
| 토큰 알림 | 사용자가 정한 다음 요청 알림 기준 | CLI가 보고한 완료값 기준. 기간/계정 한도·실시간 강제 한도가 아님 |
| 준비·결과 확인 | 설치/스킬/지침 상태와 사용자 자기 확인 결과 분리. 실패/중지/차단/미확인 포함 | 실제 HCP 정답률·자동 성능 점수·공정한 전후 개선 측정을 구현했다고 주장하지 않음 |
| 개인 기록 | 폴더별 최소 진행/확인 기록, 최대 100건, 별도 내보내기/초기화 | 회사 전체 집계, 직원 순위, 원문 자동 수집 없음 |

## 구현 계약

- `local_app/harness_client.py`가 현재 사용자 설치 등록, Claude 설정 루트, 프로젝트 범위, 활성 플러그인 버전을 확인한다. 임의의 다른 프로필/상태 저장소로 대체하지 않는다.
- 새 `workspace` 관리 명령은 설치된 코어가 범위를 다시 해석한다. 브라우저는 셸 명령·상태 루트를 주입하지 못하며, 기존 API 인증/Origin 확인과 폴더 신뢰 동의를 유지한다.
- 변경안은 서버에서 보존하고 세션/폴더/10분 유효기간에 묶는다. 실제 저장 전 대상 해시를 확인하며 같은 작업 ID의 중복 클릭은 같은 결과를 반환한다. 모든 외부 편집기를 전역 잠그는 트랜잭션은 아니다.
- 진행 중 업무가 있으면 기억·지침 저장/학습 변경을 보류한다. 관찰 화면은 실제 업무를 실행하거나 모델·Office를 기동하지 않는다.
- 기존 스킬 선택/충돌 처리/없는 스킬의 일반 실행, 모델·승인 설정을 이번 도우미에서 바꾸지 않았다. 새 상시 후크도 추가하지 않았다.
- 잘못된 지식 항목 하나가 같은 폴더의 정상 항목을 숨기지 않도록 하고, 일반 README는 지식 레코드로 취급하지 않는다.
- 승인 직후 CLI가 빠르게 종료할 때 늦은 승인창 닫기 이벤트가 완료 상태를 다시 ‘진행 중’으로 바꾸던 경쟁 상태를 수정했다.

## 자동 검증

최종 전체 시험 결과는 이 문서의 아래 결과를 기준으로 한다. 외부 보안 프로그램·일시 파일 잠금 가능성이 있는 시험의 재실행 이력도 숨기지 않는다.

- 신규 도우미 전용 시험: **23개 통과**. 읽기 전용 조회, 실제 저장/검색, 수동 변경 충돌, 범위 격리, 중복 적용, 이전 내용 복원, 초안 활성화/내보내기, 회사·개인 설정 보존, 잘못된 입력/원문·자격증명 거절을 포함.
- 기존 로컬 화면 시험: **43개 중 42개 통과, 심볼릭 링크 생성 권한 부재 1개 건너뜀**. 인증/질문/승인/중지/이어하기/한글/숨김 실행기 및 늦은 승인창 닫기 회귀 포함.
- 사용량 분석 시험: **6개 통과**. 누락, 중복 스트림, 알려지지 않은 모델, 모델별 합계, 관찰 오류를 확인.
- 최종 전체 시험: **879개 실행, 877개 통과, 2개 건너뜀, 실패 0 (191.948초)**. 건너뜀은 심볼릭 링크 생성 권한 부재와 별도 선택 실행이 필요한 실제 Claude 설정 시험이다.
- 재실행 이력: 앞선 877개 전체 실행은 통과(2개 건너뜀). 다음 전체 실행에서는 기존 자산 검증 시험의 임시 `__pycache__` 교체에 Windows 접근 거부가 1회 발생했다. 해당 자산 시험 15개 단독 재실행은 수정 없이 통과했다. 이 일회성 실패의 OS 수준 원인은 단정하지 않는다.
- JavaScript 구문 검사와 Python 컴파일 검사 통과.

## 화면·실제 연결 검증

격리한 설치 등록/개인 상태/한글·공백 폴더와 **실제 관리 API + 모형 CLI**로 브라우저를 시험했다. 개인 계정·회사 설정을 수정하지 않았다.

- 첫 코스 5개, 자동 전송 없음, 기억 변경안/저장/비활성화/복원안, 지식 초안, 짧은 업무 지침 저장.
- 질문 응답 → 승인 → 완료 전이, 사용량 미제공 표시, 선택 JSONL, 자기 확인 기록.
- 가로 390/768/1440 화면에서 넘침 없음. 브라우저 오류 0, 외부 요청 0, 모델 요청 0.
- 화면 캡처를 직접 확인하고 과도하게 늘어나던 왼쪽 메뉴 크기와 대화상자 제목 스크롤을 수정했다.
- 오프라인 안내: 5단계/7개 복사 버튼, 클립보드 성공 및 수동 복사 대체 경로, 가로 390/1280 확인. 외부 요청/브라우저 오류 0.
- 설치된 Claude Code **2.1.272**와 프롬프트 없는 초기화 성공: **2,700ms / 2,476ms**, 각 모델 요청 0. 실제 인증 갱신·모델 답변 성공 시험은 아니다.
- 격리된 작은 상태(스킬 12개, 개인 기억 2개)의 관리 API 조회 3회: **244/233/247ms**. 현재 개발 PC 측정이며 사내 PC/대규모 지식/Office 지연 보장이 아니다. 추가 모델 호출은 하지 않는다.

## 배포 상태와 남은 운영 확인

Workspace 0.3 별도 UI 미리보기 ZIP은 현재 소스와 17개 파일이 동일하고 대화/인증/실행 상태를 포함하지 않는지 검사한다. **기존 공개 1.4.14 설치에 새 관리 API가 자동 추가되는 것은 아니다.** 해당 코어 API가 없는 설치에서는 일반 대화·안내만 유지하고 기억 관리는 설치 확인 필요로 표시한다.

이 작업에서 운영 PC를 업데이트하거나 정식 코어 버전/Release를 교체하지 않았다. Git 커밋·푸시도 하지 않았다. 기존 설치에 같은 버전의 다른 코어 묶음을 덮어쓰지 않는다.

다음 검증은 실제 사내 PC에서 필요하다.

1. 새 코어 설치/업데이트 후 기존 로그인·모델·개인 기억·MCP 유지 확인.
2. 스킬 이름을 쓰지 않은 원본 PPT 읽기 → 실제 office-reader 호출 → 승인 대기 → 페이지/표/수치 대조.
3. HTML/PPT 디자인 선택 대기 → 제작 → 편집 가능성과 원본 보존 확인.
4. 개인 선호 저장 → 같은 설치 범위의 새 대화에서 실제 조회 → 결과 반영 확인.
5. HCP가 주는 토큰/가격 필드, 공유 담당자, 통계 보존 기간 확정.

고정 시험 자료별 실제 HCP 실행 근거, 정확도 자동 판정, 동일 조건의 전후 비교, 기간별 예산, 회사 통계 서버는 후속 고도화 범위다. 현재 자기 확인 통계를 전체 에이전트 성능으로 해석하지 않는다.
