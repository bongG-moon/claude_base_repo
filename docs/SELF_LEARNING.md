# 필요한 교정만 한 번 접수하는 개인 학습 — 현재 소스

이 문서는 현재 소스의 개인 학습 흐름을 설명합니다. 과거 버전의 회고 절차와 달리 일반 학습은 한 번 제출하며, 학습만을 위해 끝난 답변을 다시 이어가지 않습니다. 소스나 안내서 갱신만으로 기존 PC가 업데이트되지는 않으므로 같은 범위의 배포본으로 업데이트해야 합니다. 실제 사내 HCP 모델에서의 해석 정확도와 체감 속도는 별도 확인이 필요합니다.

지속적으로 쓸 교정만 추려 개인 선호와 업무 절차에 반영하고 다음 사용 결과를 확인합니다. 사용자가 매번 “기억해줘”라고 말할 필요는 없습니다. 기존 Claude Code와 사내 모델을 그대로 사용하며 별도 모델 서버, SaaS, 인터넷 다운로드를 추가하지 않습니다.

## 사용자에게 달라지는 점

- “앞으로 팀 보고는 결론부터 써줘”처럼 지속적으로 적용할 명확한 교정은 업무 중에도 개인 선호로 반영할 수 있습니다. “이번 보고만”이나 뜻이 모호한 지시는 이번 작업에만 적용합니다.
- 사용자가 반복해서 선택하는 형식은 먼저 관찰로 쌓고, 서로 독립된 두 업무에서 완료 또는 해당 요청의 실제 성공 검증을 확인한 뒤 적용합니다. 같은 업무의 다른 요청·재시도, 한 번의 선택이나 사용자의 침묵을 선호 확정으로 간주하지 않습니다.
- 이번에 실제 사용한 개인 스킬에 빠진 확인 절차가 있었다면 그 부분을 작은 점검 목록으로 개선할 수 있습니다. 원래 스킬 전체와 실행 코드를 자율 재작성하는 기능은 아닙니다.
- 다음 사용에서는 같은 종류의 업무와 같은 스킬 버전이 관찰되었는지 확인하고, 검증 결과·오류 수·명시적 피드백을 연결합니다. 비교할 자료가 부족하면 효과 미확인으로 남깁니다.
- 개선이 해롭다는 평가나 사용자가 특정 자동 변경을 지목한 교정이 확인되면 해당 변경만 되돌리는 절차를 사용합니다. 일반적인 “다시 고쳐줘”는 무관한 기억을 취소하는 근거가 아닙니다. 사용자 수동 편집과 충돌하면 덮어쓰지 않고 알립니다.

## 자동 실행 경로

1. 하네스가 현재 요청 식별자와 제한된 실행 근거를 관리합니다. 질문 원문을 학습 저장소에 복사하지 않습니다.
2. 업무 중 도구 성공/실패·검증 횟수와 제한된 개인 스킬 읽기 기록을 수집합니다. 경로·이름·내용 해시와 나눠 읽은 줄 범위를 남기며 본문은 복사하지 않습니다. 같은 요청·같은 버전에서 전체 본문이 확인돼야 읽기 근거가 되고, 새 요청에서는 불완전한 읽기 범위를 초기화합니다.
3. 변경 작업은 기존 검증 절차를 먼저 수행합니다. 검증 없이 성공으로 만들거나 실패 횟수를 초기화해서 학습을 통과시키지 않습니다.
4. 지속적인 명시적 교정, 독립된 업무의 반복 선택, 검증된 재사용 절차 또는 실제 다음 사용 평가가 있을 때만 현재 대화에서 필요한 내용을 짧게 추립니다. 매 답변을 회고하거나 원문 로그를 다시 읽지 않습니다.
5. `learning submit` 한 번으로 제출하면 엔진이 접수·중복·근거·개인 경로와 버전을 확인하여 적용하거나 후보로 보류합니다. 일반 제출 전에 status → stage → checkpoint를 실행할 필요가 없습니다.
6. 접수는 업무 완료 선언이 아닙니다. 개인 선호는 명시적인 지속성이 있으면 진행 중에도 반영할 수 있지만, 절차 개선에는 실제 전체 본문 로드·변경 없는 정확한 버전·해당 요청의 최신 검증 성공이 필요합니다. 오류를 고친 절차라고 학습하려면 실제 실패와 수정 성공도 관찰해야 합니다. 검증되지 않은 절차를 성공으로 만들지 않습니다.
7. Stop은 학습만을 위한 추가 대화를 시작하지 않습니다. 대기·실패·근거 부족은 그대로 남기고 사용자에게 업무 결과와 필요한 제한만 전달합니다. 접수된 내용을 확인하려고 같은 제출이나 업무를 반복하지 않습니다.

검토할 내용이 없는 인사·단순 질의는 학습 호출 자체를 생략합니다. 접수·후보·실제 적용은 서로 다릅니다. 후보 수와 이력에는 상한이 있으며 모든 교정의 보존·적용을 보장하지 않습니다. 같은 업무의 반복 응답은 독립된 선호 근거로 계산하지 않습니다. 내부 상태는 기본 답변에 나열하지 않습니다. 대화 압축도 업무 완료나 새로운 반복 근거가 아닙니다. 명시적 기억 저장 요청은 기존 개인 메모리의 범위 선택을 따릅니다.

개발 인터페이스: 현재 후크 JSON이 제공한 정확한 `cliCommand`에 `learning submit --session <id> --turn <turnId> --spec "<stateRoot>/tmp/learning-review-<turnId>.json"`을 붙입니다. 스키마는 기존 review의 형식을 유지합니다. 모델이 스스로 상태 조회·후보 적재·업무 완료 표시를 순서대로 수행할 필요는 없습니다. 기존 stage/review/checkpoint 인터페이스가 있어도 일반 학습의 선행 절차는 아닙니다. 현재 식별자가 없으면 학습만 보류하고, 설정·환경변수·세션 폴더를 뒤져 복구하거나 임의 ID를 만들지 않습니다. 일시 중지·보호 제한에서는 새 자유 서술 후보를 저장하지 않습니다.

보정 기회를 소진한 완료/취소 업무는 새 업무 시작 시 최대 8건의 미해결 기록에 남길 수 있습니다. 실제로 해당 산출물/외부 상태를 확인·보완한 뒤 현재 턴의 검증 성공을 기록하고 `work resolve --session <id> --turn <id> --work-id <대상 업무 ID>`로 한 건만 연결합니다. 이전 실패 기록은 해결 이력에 보존하며 삭제하거나 성공으로 바꾸지 않습니다. 무관한 검사로 해소했다고 주장하지 마세요. 해결 이력은 64건으로 제한되며 상한에서 기록을 지우지 않고 운영자 확인을 요구합니다.

## 무엇을 자동으로 바꾸는가

| 대상 | 처리 |
| --- | --- |
| 새로 관찰한 개인 응답 선호 | 근거 조건을 통과하면 별도 자동 학습 Memory 항목으로 적용 |
| 사용자가 직접 작성한 기존 Memory | 임의로 덮어쓰지 않고 충돌 시 보류 |
| 실제 전체 본문을 읽은 개인 저장소의 SKILL.md | 관찰 당시 버전과 관련 검증을 확인하고 작은 자동 학습 점검 영역만 개선. 근거 부족은 보류 |
| 공통 Skill, 다른 플러그인, 프로젝트 생성기의 파일 | 자동 학습 수정 대상이 아님 |
| 실행 스크립트, MCP 코드, 권한, 인증정보 | 자동 수정/활성화하지 않음 |
| 회사 용어와 데이터 정의 | 모델의 추측을 회사 사실로 확정하지 않음. 출처가 있는 기존 개인 지식 절차 사용 |
| 업무 결과물, 발송 메일, 외부 시스템 | 학습 변경 복구의 대상이 아님 |

개인 스킬이 아직 없는 업무에서도 근거에 맞는 개인 선호를 축적할 수 있습니다. 새 재사용 절차는 사용자 생성 요청이나 제작 제안에 대한 동의 후 기존 Asset Factory로 만듭니다. **새 스킬 생성과 조건부 자동인 기존 개인 스킬 점검 항목 개선은 별개**입니다. 공통 스킬의 개인 복제본도 자동 생성하지 않습니다. 제작된 개인 스킬은 즉시 사용 가능한 상태가 되지만, 실제 발견·본문 로드·업무 적용은 따로 확인합니다.

## 저장과 개인정보

자동 학습은 활성 설치의 `stateRoot` 안에서만 관리합니다. User 설치는 개인 전체, Project 설치는 해당 설치 저장소입니다. 새 기억·스킬을 명시적으로 저장할 때의 개인 전체/이 프로젝트 선택은 자동 학습 범위를 바꾸지 않습니다. User 설치에서 별도 프로젝트 범위에 만든 개인 자산은 자동 학습 수정 대상이 아닙니다.

```text
현재 개인 저장 위치/
  config/learning.json                 자동 학습 켜기와 일시 중지
  learning/state.json                 관찰, 자동 변경 부분 복구 자료, 다음 사용 평가
  memory/items/                       적용된 개인 선호
  personal-root/.claude/skills/        개인 스킬 원본과 자동 점검 영역
  tmp/learning-review-<요청식별자>.json  짧은 추출 내용 제출용 파일
```

User 설치의 프로젝트별 개인 자산은 `project-scopes/<프로젝트 경로 식별자>/` 아래 별도 저장소에 있습니다. 실제 절대경로는 Workspace의 **구성 한눈에**에서 확인합니다. 개인 전체는 같은 설치·저장소를 사용하는 여러 폴더에서 참고하고, 프로젝트 개인 자료는 해당 경로에 연결됩니다. 폴더 복사·이름 변경이나 다른 PC·계정으로 자동 이전·동기화하지 않습니다. 옮겨 쓸 때는 백업·이전·연결 설정을 확인하고 새 대화에서 조회를 시험합니다.

회사 공통은 담당자가 검토·배포한 지식·스킬·후크이며 개인 자동 학습으로 바뀌지 않습니다. Claude Code 자체 자동 기억도 별도 경로·설정으로 관리하고 서로 다른 설치나 저장소의 기록을 자동 합치지 않습니다.

전체 대화, 질문 원문, 메일 본문, DB 조회 행, 비밀번호는 학습 입력 파일에도 넣지 않습니다. 성공·실패 기록의 요약은 자료 내용이 아니라 수행 결과와 재사용할 교훈을 담습니다. 기존 Claude의 대화 기록 설정을 변경하거나 기록을 지우는 기능은 아닙니다.

제출용 임시 JSON은 처리 후 내용이 바뀌지 않았음을 확인하고 제거합니다. 유효하지 않은 제출도 같은 규칙으로 정리하며 다른 임시 파일이나 사용자가 수정한 파일은 삭제하지 않습니다. 프로그램이 갑자기 종료되면 처리되지 않은 임시 파일이 남을 수 있습니다. 이런 경우도 전체 대화를 넣지 않는 입력 원칙은 동일합니다.

개인 기억과 스킬은 코어 업데이트와 분리됩니다. 설치 전 선택 백업에 자동 학습 설정·변경 이력과 복구 자료도 포함합니다. 작업 중 새 기록과 백업이 섞이지 않도록 업데이트 전에 Claude를 닫습니다.

관찰·평가는 최근 구간만 순환 보관합니다. 개인 원본 기억과 스킬을 오래됐다는 이유로 삭제하지 않습니다. 이미 해롭다고 판단한 교훈은 별도의 제한된 거부 기록으로 재적용을 막습니다. 활성 자동 기억·변경 수에는 상한이 있으므로 용량 때문에 보류되면 내역 확인에서 알립니다. 복구 자료는 자동 기억 또는 자동 점검 영역의 이전/이후 내용이며 전체 개인 스킬 복사본이 아닙니다.

## 사용자가 확인하고 제어하기

Claude Code에서 `/company-agent:learning` 또는 다음 자연어 요청을 사용할 수 있습니다.

> 최근 내 업무 방식에서 배운 내용을 보여줘. 관찰 중인 것과 실제 적용한 것을 구분해줘.

> 자동 학습을 잠시 멈춰줘. 기존 기억과 스킬은 지우지 말아줘.

> 자동 학습을 다시 시작해줘.

> 방금 자동으로 바꾼 보고서 기준을 되돌려줘. 내가 직접 고친 부분은 보존해줘.

일시 중지는 이후 자동 회고·적용을 멈추는 것이지 기존 기억의 사용이나 명시적인 “기억해줘” 요청을 금지하는 것이 아닙니다. 상태 확인만 요청했을 때 설정이나 개인 자료를 바꾸지 않습니다.

내역에서는 **미제출 / 접수 / 후보 / 실제 적용 / 보류**를 구분합니다. “제출했지만 배울 내용 없음”은 아예 제출하지 않은 것과 다릅니다. 현재 세션 정보가 제공된 경우 나중에 기억이 모델 문맥으로 출력된 기록도 확인할 수 있지만, 이는 실제 답변에 반영됐다는 증거가 아닙니다. 세션 정보가 없어도 일반 학습 내역 조회는 가능하며 조회를 위해 세션을 재탐색하지 않습니다.

‘되돌리기’는 개인 선호의 경우 현재 자동 기억을 비활성화하여 적용을 멈추고, 스킬의 경우 자동 점검 영역을 이전 상태로 복원합니다. 비활성화한 선호의 과거 기준까지 자동으로 다시 적용하지는 않습니다. 과거 기준을 다시 사용할지는 사용자가 요청한 내용을 기준으로 정합니다.

**명시 기억 수정은 별도 경로입니다.** 사용자가 기존 기억을 고치면 원래 범위와 ID를 유지하는 조건부 `memory upsert`를 사용합니다. 조회 시의 revision·sha256이 맞아야 변경합니다. `memory history`로 확인한 이전 버전은 `memory restore`로 새 버전으로 복원합니다. 이후 수동 수정이 있으면 보존하며, Memory 버전 백업이 없으면 복원하지 않습니다. 자동학습 ledger의 이전 내용을 몰래 복원 자료로 합치지 않습니다.

새 Memory 백업은 내용 해시를 함께 기록하고 복원 전에 대조합니다. 예전 백업처럼 비교 근거가 없거나 값이 다르면 자동 복원하지 않고 현재 기억과 백업을 보존합니다. 필요하면 내용을 직접 검토하여 명시적 기억 수정을 요청할 수 있습니다. 이 로컬 해시는 변경 감지용이지 외부 진위 인증 서명은 아닙니다.

현재 `learning submit`은 관찰별 `storageScope`나 임의 `targetMemoryId`를 지원하지 않습니다. 프로젝트 전용 교정을 User 설치의 개인 전체로 저장하지 말고 해당 범위의 명시 기억 흐름으로 연결합니다. 세션 저장소와 자동학습 저장소를 바꾸는 확장은 이번 개선에 포함하지 않았습니다. 학습 응답의 과거 변경 해시는 현재 기억을 다시 읽은 해시가 아니므로 명시 기억의 조건부 수정에 재사용하지 않습니다.

정상 기억 저장·복원은 저장된 내용과 실제 범위를 코드에서 확인하므로 같은 저장을 위해 모델이 Markdown을 재해석하거나 별도 `session verify`를 할 필요가 없습니다. 이 확인은 그 기억 한 건만 대상이며 기존 업무의 미완료 검증을 지우지 않습니다. 새 모델 호출이나 매 답변 실행하는 학습 단계를 추가하지 않습니다.

## 검증의 의미와 한계

형식 검사, 실패 횟수, 정확한 스킬 버전, 중복 요청 방지와 개인 경로 보호는 코드에서 처리합니다. 어떤 사용자 표현이 장기 선호인지, 어떤 절차가 도움이 되었는지는 모델의 의미 해석이 필요합니다. 모델이 보고한 ‘도움이 됨’과 실제 도구 검사 통과는 별도 증거로 취급합니다.

다음 업무에서 오류가 줄어도 업무 난도나 입력이 달랐을 수 있습니다. 비교는 같은 업무 종류의 관찰이며 성공률 향상에 대한 인과 증명이 아닙니다. 스킬 파일을 읽은 것 역시 실제 적용 사실의 독립 증명은 아니므로, 검토 지침은 단순 조회를 적용으로 평가하지 않도록 요구합니다.

실사용 검증은 기존 수동 기억과 충돌하지 않는 별도 가상 교정으로 수행합니다. 실제 적용된 기억의 ID·버전을 확인하고, 새 세션에 제공된 기록과 답변에 반영된 결과를 따로 비교한 뒤 그 자동 변경만 되돌립니다. 선호는 비활성화 후 다음 조회에서 제외되어야 하며, 이전 본문 복원과 혼동하지 않습니다. 이 시험을 위해 실제 개인 선호나 회사 자료를 바꾸지 않습니다. 엔진·CLI 회귀검사 통과만으로 특정 사내 모델의 답변까지 검증되었다고 안내하지 않습니다.

교정의 의미를 추리는 과정은 현재 모델에 의존합니다. 별도 학습 모델이나 작업자를 강제로 호출하지 않으며 닫힌 Claude를 대신 실행하지 않습니다. 필요한 교정을 추리고 제출하는 데는 현재 대화의 토큰과 도구 실행 시간이 들지만, 매 답변마다 빈 검토를 하거나 Stop으로 학습 대화를 이어가지 않습니다. 제출이 막히면 학습을 보류할 뿐 이미 만든 결과물을 다시 만들지 않습니다. 실제 HCP 환경의 성공률이나 절감량을 검증했다고 주장하지 않습니다.

개인 자동 변경의 복구는 업무 파일 전체 rollback이나 메일 취소와 다릅니다. 이 버전도 외부 부작용을 무조건 되돌리거나 대화 JSONL을 조작하지 않습니다.

### 관리자 참고: 현재 후보 보존 한계

현재 한 미완료 업무에서 같은 개인 스킬의 서로 다른 항목을 연이어 교정하면 뒤의 후보가 앞의 후보를 대체할 수 있습니다. 같은 항목의 A → B → A 교정과는 다른 제한입니다. 여러 항목을 모두 보존했다고 보고하지 말고 적용 내역을 확인해야 합니다. 이 제한을 우회하려고 같은 업무를 여러 새 업무로 나누어 학습 근거를 늘리지는 않습니다.

### 보호 자료가 포함된 세션

도구가 보호 설정 또는 접근 제한을 보고한 세션에서는 자동 학습 제출을 중단하며, 자유 서술 내용·개인 선호 관찰·Skill 평가나 대체 학습 검토 기록을 저장하지 않습니다. 이미 쌓인 개인 기억과 스킬은 삭제하지 않습니다. 하나의 세션 안에서 제한된 내용과 다른 업무 내용이 섞일 수 있어 보수적으로 적용하는 범위입니다. 허용된 자료만 다루는 새 대화에서 다음 업무를 시작할 수 있으며, 이것이 차단된 자료를 다시 추출해도 된다는 뜻은 아닙니다. 실제 회사 DRM 권한, 다른 프로그램의 저장, Claude 자체 대화 기록까지 이 기능이 통제하지는 않습니다.
