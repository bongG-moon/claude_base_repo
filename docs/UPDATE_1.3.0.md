# Company Agent 1.3.0 적용 안내

> 정정: 내용이 달라진 1.3.0 패키지는 기존 1.3.0 위에 재적용할 수 없습니다.
> 동일 버전 재적용 안내를 따르지 말고 [1.3.1 업데이트 안내](UPDATE_1.3.1.md)를 사용하세요.

이 묶음은 1.2.0 운영 피드백을 반영한 로컬 업데이트 후보입니다. GitHub Release 게시 및 회사 운영환경 합격을 의미하지 않습니다.

## 적용 방법

1. Claude Code를 닫습니다. Python과 기존 사내 모델 설정은 그대로 둡니다.
2. 새 ZIP을 이전 압축 해제 폴더와 다른 폴더에 풉니다. 설치된 코어나 개인 자료 폴더에 직접 덮어쓰지 마세요.
3. ZIP 안의 `Install-CompanyAgent.cmd`를 평소 Windows 계정으로 실행합니다.
4. 기존과 같은 설치 범위를 선택합니다. 프로젝트 설치라면 같은 프로젝트 경로를 선택합니다.
5. 기존 Company Agent의 업데이트로 인식하는지, 이전/새 버전과 백업 위치를 확인하고 진행합니다. 다른 하네스를 교체하라는 안내만 나오면 중단하고 설치 범위를 확인하세요.
6. Claude Code를 다시 열고 설치 버전 1.3.0과 개인 기억·스킬 경로를 확인합니다.

개인 기억·스킬·지식과 기존 모델·MCP 설정은 보존 대상입니다. 설치 로그에 표시되는 백업 위치를 기록하세요. 설치파일은 선택한 범위의 업데이트를 담당하며 PC 전체의 다른 하네스를 초기화하지 않습니다.

## 달라지는 점

- 목록 조회·중간 선택마다 학습하지 않습니다. 업무가 완료되고 배울 내용이 있을 때 검토합니다.
- 중간 교정은 최대 5개의 검증된 후보로 보관합니다. 같은 업무에서 반복한 답변은 별도 학습 표본으로 부풀리지 않습니다.
- 일반 학습 성공·내용 없음은 최종 답변에 나열하지 않습니다. 명시적인 기억 요청은 즉시 처리할 수 있습니다.
- 변경이 없는 조회를 코드 검증 실패로 표현하지 않습니다. 문서·파일 이동·코드는 각각 적절한 확인을 유지합니다.
- 정확한 내부 진단 명령 두 가지(`business doctor`, `business mail-capabilities`)만 제한된 방식으로 자동 승인할 수 있습니다. 일반 Python/Bash, 파일 변경, 메일 본문·발송·이동에 대한 포괄 허용은 추가하지 않습니다.
- Outlook 검색의 시간대 누락을 PC 시간대로 처리하고 그 기준을 표시합니다. 날짜 입력 문제와 실제 연결 문제를 구분합니다.
- 메일은 제목·발신자 기반 제한 검색입니다. 본문 전체 검색·PST 생성/이동·발송 기능을 새로 추가한 것은 아닙니다.
- 모델 별칭과 worker 실행 기록을 구분합니다. 확인되지 않은 실제 사내 모델 식별자는 추정하지 않습니다.

## 처음 확인할 것

### 9월 12일 독립 사용 검토 보완

- HTML 보고서 선택을 한글 3가지와 `추천대로`로 안내합니다.
- 파일 정리안을 저장하거나 개인 기억을 검색한 것만으로 업무 파일이 바뀌었다고 판단하지 않습니다.
- 검증 설명에 `90%`처럼 백분율이 포함돼 검증 성공 기록 자체가 취소되던 문제를 수정했습니다. 신뢰된 실행 파일의 직접 호출에만 적용하며 배치 파일·명령 체인 허용은 늘리지 않았습니다.
- 명시적인 기억 요청과 업무 중 교정을 구분합니다. 업무 중 후보는 완료 시 한 번 반영하며, 이미 보관한 후보도 완료 검토 대상입니다.
- 로컬 `.eml`의 일반 텍스트 본문과 지원되는 `.txt` 첨부를 읽는 기본 기능을 추가했습니다. Outlook 연결이 아니며 HTML 실행·외부 URL 조회·보호 해제는 하지 않습니다. 읽지 못한 부분은 제외 사실을 알립니다.
- 보호 해제 사본을 요청하라는 안내, Claude 로그인 주소를 Outlook 계정으로 추측하는 안내를 제한했습니다. 외부 MCP의 실제 권한 구현은 별도 검증 대상입니다.
- 연습실은 다운로드 버튼을 눌렀다는 이유만으로 저장 완료로 간주하지 않습니다. 다운로드 파일을 확인한 뒤 저장 확인 버튼을 누릅니다.

일부 승인 거절은 Claude 버전에 따라 활동 Hook에 전달되지 않을 수 있습니다. 추가 실행 증거가 없는 Stop 재진입은 반복하지 않되, 기존 미검증 변경은 남깁니다. 자동화 시험의 제한된 사전 승인은 직원 PC의 권한을 변경한 것이 아닙니다.

동봉한 검증 질문셋의 T30 → T31 → T32 → T33 → T34를 먼저 실행하세요. 실제 계정 시험은 승인된 가상 메일로만 진행합니다. 결과지에 실행 응답·오류 단계와 결과를 기록하고, 메일 원문·저장소 ID·비밀값은 외부에 보내지 마세요.

업무 완료와 새 업무의 판단은 Claude의 조정 지침에 의존합니다. 엔진은 완료 표시 없는 학습 제출을 차단하지만 의미를 독립적으로 이해하는 것은 아닙니다. Claude를 닫은 뒤에도 실행되는 백그라운드 학습은 없습니다. 공통 업무 스킬을 자동으로 개인 복제해 개선하는 기능은 이번 범위에 포함하지 않았습니다.

검증 실패 후 정해진 재시도를 소진한 업무는 미해결 기록으로 남긴 채 새 업무를 시작할 수 있습니다. 이 기록은 해결됐다는 뜻이 아닙니다. 기존 산출물/외부 작업 상태를 확인하지 않고 재실행하지 마세요. 자동 승인 지원과 도구 실행 표시 방식은 운영 PC의 Claude Code 버전 및 회사 정책으로 최종 확인해야 합니다.
