# 스킬 선택 목록 자동 전달 검증

## 반영 범위

목록 경로만 알려주던 방식을 보완했습니다. 문서 종류별 강제 분기나 도구 실행 차단은 추가하지 않았습니다.

- 새 대화·재개·대화 압축·목록 변경 시 선택용 메타데이터를 자동 전달합니다.
- 같은 대화·같은 목록은 짧은 재사용 정보만 전달합니다. 관련 스킬 본문은 별도로 읽습니다.
- 자동 전달은 본문 읽기 기록·실행 권한·업무 검증 성공을 만들지 않습니다.
- 큰 목록은 출처별 페이지로 분리합니다. 가능한 경우 모든 스킬 이름은 처음부터 전달하고 설명만 페이지에서 읽습니다. 이름 목록도 예산을 넘으면 전체 이름의 디렉터리 위치를 명시합니다. 앞부분 후보만 남기는 방식은 아닙니다.
- 설치·삭제·설명 변경·우선 설정 변경을 반영하며, 현재 대화에서 이미 읽은 변경 없는 본문은 재사용합니다.
- 다른 작업자는 자기 대화에서 필요한 본문을 읽습니다. 부모에게 선택이 없으면 작업자에도 선택용 목록을 전달합니다.

## 충돌 점검과 보완

- 기존 `indexRead=false`만으로 전체 목록 재읽기를 요구하던 지침을 자동 전달 여부와 구분했습니다.
- 큰 목록에서 필요한 본문을 읽었는데도 전체 목록을 다시 읽으라고 안내하던 충돌을 제거했습니다.
- 사용자·프로젝트 우선순위, 명시적 스킬 호출, 수동 호출 전용 스킬 제한을 유지했습니다. 페이지 분리 시에도 출처 간 우선순위를 유지합니다.
- 타사 플러그인의 중첩 YAML·별칭 문법 때문에 이름/설명 수집 전체가 실패하지 않도록, 필요한 최상위 호출 제한 값만 읽습니다.
- 기존 DB·Outlook 정책, 권한 처리, 완료 확인·학습 기록은 변경하지 않았습니다.
- 보조 스킬과 안내 문서의 “항상 상세 목록부터 읽기” 지침을 새 흐름에 맞췄습니다.

## 실행한 검사

- 전체 자동 검사 670개 통과, 제외 0개. 실제 Claude 설정 호환 검사는 격리 환경에서 활성화했습니다.
- 이후 큰 목록의 이름 안내를 보완한 최종 코드에서 관련 13개 검사와 실제 Windows 실행 경로 6개 검사를 다시 실행해 모두 통과했습니다.
- 실제 Windows Hook에 `@테스트자료.pptx 이 자료 내용 확인해서 정리해줄 수 있을까?`를 전달해 초기 목록 노출, 다음 요청에서 재사용, 선택 본문 읽기 기록, 압축 후 재전달을 확인했습니다. 본문 선택 자체는 테스트가 명시적으로 수행했습니다.
- 공통 스킬 12개만 있는 격리 환경에서 초기 선택 메타데이터는 JSON 2,797자, 다음 요청의 재사용 메타데이터는 129자였습니다. 토큰 수가 아니라 문자 수이며 전체 Hook 크기와도 다릅니다.
- Claude 플러그인 엄격 검사·Python 구문 검사·변경 공백 검사 통과.
- Codex 전용 스킬 검사기는 기존 Claude용 `company-agent-role` 필드를 지원하지 않아 해당 검사 결과를 이 플러그인의 유효성 판정에 사용하지 않았습니다. 기존 필드를 제거하지 않았습니다.

## 확인하지 않은 범위

사내 모델의 실제 선택 정확도나 회사 문서 읽기 성공률을 측정한 검사는 아닙니다. 선택 정보 제공과 실행 경로를 검증했으며, 모델이 요청의 의미를 정확히 판단할 것을 100% 보장하지 않습니다. 원본 업무 파일·실제 개인 설정은 수정하지 않았습니다.

이 변경은 1.4.7 소스와 설치 묶음에 포함됩니다. 기존 1.4.6 ZIP은 변경하지 않습니다. 설치된 개인 환경에는 같은 범위로 업데이트하고 Claude Code를 다시 시작해야 적용됩니다.
