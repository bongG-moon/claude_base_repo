# HTML 양식 첨부와 반복 준비 메시지 수정

후속 요청 반영: Office/HTML/PPT 읽기 지침, 공유 참조, 자동 주입 안내에서
‘우회 금지’라는 일괄 지시 자체를 제거했습니다. 우회 절차를 추가한 것은 아니며
실제 읽기 코드의 권한 검사, DB/Outlook 제한, 원본 보존은 변경하지 않았습니다.

## 무엇이 문제였나

1. HTML 선택 흐름에 직접 양식을 첨부하는 분기가 없었습니다.
2. 디자인 예시 HTML은 있었지만 기존 명령은 경로만 반환했습니다.
3. 스킬 준비 확인을 실행 권한 거절로 반환해서, Claude가 폴더 오류나 실행 문법 오류로 오해하고 같은 시도를 반복했습니다.

## 변경 사항

- 첫 디자인 질문은 추천 업무형 / 지표 중심형 / 추가 디자인 / HTML 양식 직접 첨부입니다.
- 추가 디자인은 바로 8가지 목록과 로컬 미리보기를 안내합니다. 분량·보기 방식은 그 뒤에 묻습니다.
- HTML 첨부는 파일 확인 → 새 샘플 미리보기 → 느낌 확인 → 남은 분량·보기 선택 → 제작 순서입니다.
- 첨부의 literal HEX 색상, 글꼴 이름, px 모서리, 구역 개수를 참고합니다. 임의 DOM 배치·외부 CSS·이미지·JavaScript를 복제/실행하지 않습니다. 원본과 같은 화면이라고 주장하지 않습니다.
- 준비 누락은 요청·목록 버전당 한 번만 내부 참고로 전달합니다. 실행을 허용하거나 거절하는 기능이 아닙니다. 같은 안내를 위해 파일을 반복 읽지 않습니다.
- `skill route`는 선택적 진단 명령이며 매번 실행할 필요가 없습니다. 이미 읽은 변경 없는 본문은 재사용합니다.
- 파생 인덱스 형식을 4로 갱신해 이전 필수 명령 안내가 재사용되지 않게 했습니다. 개인 Memory/Skill/Knowledge나 우선순위 설정은 변경하지 않습니다.
- DRM 표시와 실제 접근 거절을 구분하도록 Office 설명을 수정했습니다. xlwings/COM 읽기를 유지하며 보호 해제·실제 접근 거절 우회는 추가하지 않았습니다.
- 독립 정책 Hook의 JSON 전송은 CP949/UTF-8 모두에서 읽히도록 수정했습니다.

## 검증과 한계

운영 로그 재현 보완까지 포함한 최종 전체 자동 검사 634개 통과, 제외 0개 (`COMPANY_AGENT_TEST_REAL_CLAUDE=1`, Python UTF-8 모드, 116.925초). 아래 가상 Claude S01/S02 채팅 결과는 앞선 수정 단계의 기록이며, 이번 최종 검사에서 같은 채팅을 다시 실행한 결과는 아닙니다.

- 단위 검사: 첨부 분기/기존 답변 보존, 미리보기 생성, CSS 적용, 원문/스크립트 미전달, CP949, 크기 제한, 변경된 양식/기존 결과물 보존, 반복 안내 억제.
- 실제 Windows Hook 검사: 스킬 준비가 권한 거절을 반환하지 않으며 DB DELETE 제한은 유지됩니다.
- 가상 Claude S01: 없는 PPT 파일을 Glob으로 확인하고 8.47초에 종료. 다른 파일·Office에 접근하지 않았습니다. 단순 존재 확인이므로 스킬 본문 선택 성공의 증거는 아닙니다.
- 가상 Claude S02: 프로젝트 custom-memo 스킬을 읽고 목표 10/완료 9/90% 메모를 생성했습니다. 54.28초. 스킬 준비 안내는 한 번이며 해당 안내에 의한 거절은 없습니다.
- S02에서는 테스트의 제한된 실제 명령 권한이 별도 Bash 호출을 거절했고, 이후 완료 검증 Stop 메시지가 2회 발생했습니다. 영어 중간 안내와 내부 기록 설명도 남았습니다. 전체 채팅 UX가 완전히 해결되었다거나 모든 요청이 인덱스를 읽는다고 주장할 수 없습니다. 이 테스트에서는 인덱스 대신 프로젝트 스킬을 직접 읽었습니다.
- 두 가상 실행 모두 원래 Claude 설정 해시가 유지되었습니다. 실제 회사 자료·메일·DB·개인 상태는 사용하지 않았습니다.
- 이 세션의 브라우저 정책이 로컬 HTML 열기를 차단해서 실제 화면의 시각 검사는 미완료입니다. 다른 경로로 우회하지 않았습니다. 미리보기 열기 성공은 기본 앱에 요청한 상태만 의미합니다.

실행 근거는 로컬 임시 폴더 `company-agent-advisory-check-20260915-01/evidence`에 있습니다.
새 소스만 수정했으며 기존 공개 v1.4.3 ZIP이나 실제 설치본을 덮어쓰지 않았습니다.

## 적용 후 확인할 채팅

### 운영 로그 재현 후 추가 보완

- 기존 1.4.3에서는 선택 기록이 비어 있으면 실행 전에 거절했습니다. 표준 출력이 가려진 것이 아니라 명령 자체가 실행되지 않은 상태였습니다. 새 코드에서는 준비 안내만 내부 문맥으로 전달하며 반복 실행을 막지 않습니다.
- 사용자의 다음 답변마다 현재 선택은 다시 판단하지만 이미 읽은 목록과 본문은 재사용할 수 있습니다. `selected`가 비었다는 이유로 필수 복구 명령을 요구하지 않습니다.
- 스킬 본문을 먼저 읽고 목록을 나중에 읽어도 본문 읽기 기록을 보존합니다. 목록을 읽었다는 기록까지 임의로 만들지는 않습니다.
- 짧은 `powershell.exe` 명령도 실제 Windows 기본 실행 파일로 확인될 때 조회/내부 기록으로 분류합니다. 다른 위치의 동명 프로그램, 복합 명령, 출력 리다이렉트까지 조회로 취급하거나 자동 승인하지 않습니다.
- `<stateRoot>/tmp/html-choices-<short-id>.json`의 제한된 디자인 선택 데이터는 실제 보고서 변경과 구분합니다. 보고서 본문, 임의 JSON, 결과 HTML, 기존 미확인 변경은 완료 확인 대상입니다.
- 준비 기록 형식이 잘못되어도 그 이유로 일반 도구를 막지 않습니다. 다음 사용자 요청에서 파생 기록을 다시 준비합니다. 회사 DB 정책 검사는 별도로 계속 실행합니다.
- 운영 로그와 같은 ‘스킬 읽기 → 사용자 선택 답변 → 입력 파일 작성 → 선택 확인’ 흐름을 실제 Windows 실행 진입점과 Hook으로 재현하는 회귀 검사를 추가했습니다. 회사 PC에서 모델이 만드는 모든 채팅 흐름까지 보증하는 검사는 아닙니다.

이 변경은 소스와 검사에 반영한 상태입니다. 기존 GitHub Release 및 운영 PC 설치본에는 자동 적용되지 않습니다. 배포할 때는 기존 1.4.3을 덮어쓰지 말고 새 버전 설치본을 만들어 업데이트해야 합니다.

> HTML 보고서를 만들어줘. HTML 양식 직접 첨부로 할게. 파일부터 받고 예시를 보여줘. 분량과 보기 방식은 그 뒤에 물어봐줘.

> 추가 디자인을 미리 보고 고를게. 이미 정한 상세 / 스크롤은 유지해줘.

> 이 PPT의 내용을 읽어줘. 내 PC 전체를 찾지 말고 내가 지정한 파일만 사용해줘.

마지막 요청의 확인 기준은 스킬 준비 오류로 pwd/ls/도움말을 반복하지 않는지입니다.
실제 Office 거절·명령 승인 대기·미완료 검증이 있다면 그것까지 숨기거나 성공으로 바꾸지는 않습니다.
