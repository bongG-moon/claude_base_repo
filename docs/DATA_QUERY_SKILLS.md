# 저장한 쿼리로 데이터 조회하기

필요한 스킬만 하나씩 설치해서 사용하는 독립 스킬입니다. Company Harness 설치나 MCP 등록은 필요하지 않습니다. Python 3.11 이상과 스킬 안의 requirements.txt에 적힌 패키지는 필요합니다.

| 배포 파일 | 하는 일 |
| --- | --- |
| [oracle-query.zip](../skills_zip/oracle-query.zip) | Oracle DB를 여러 개 등록하고 저장한 SQL로 조회 |
| [datalake-query.zip](../skills_zip/datalake-query.zip) | LakeHouse 데이터레이크 조회 |
| [ehub-query.zip](../skills_zip/ehub-query.zip) | LakeHouse에 제공되는 E-HUB 데이터 조회 |
| [data-query-demo.zip](../skills_zip/data-query-demo.zip) | 계정 없이 가상 데이터로 같은 흐름 연습 |

E-HUB는 제공받은 명세의 LakeHouse 경유 방식입니다. 별도 E-HUB 웹 API를 연결하는 구현은 아닙니다. 운영 연결 성공은 사내 환경에서 확인해야 합니다.

## 처음 사용할 때

ZIP 안의 INSTALL.md에 따라 필요한 스킬 하나를 설치하고 Claude에게 말합니다.

> 오라클 조회 스킬을 처음 사용할 거야. 연결 설정해줘. DB 이름은 생산DB로 할게.

Claude가 로컬 설정창을 엽니다. 이 창에서 아이디, 비밀번호, **DSN 접속 정보**를 입력합니다. DSN은 `host:port/service` 또는 여러 줄 TNS 문자열입니다. 계정 정보를 대화에 붙여 넣을 필요가 없습니다. 저장만으로 서버에 접속하지 않습니다.

Datalake와 E-HUB는 사번, 토큰, 회사 API 주소를 입력합니다. 클러스터 준비 API가 기동을 유발할 수 있어 그 사용 여부는 처음 연결 설정에서 확인합니다. 연결 설정창은 tkinter가 있는 Python에서 동작합니다.

> DB 하나 더 추가해줘. 이름은 품질DB야.

기존 연결을 지우지 않고 추가합니다. 이후 목록에는 엔진 이름을 앞에 붙이지 않고 `생산DB`, `품질DB`처럼 본인이 정한 이름을 표시합니다.

## SQL을 업무 이름으로 저장하기

> 이 SQL을 ‘생산실적조회’라는 이름으로 저장해줘. 날짜와 공정은 조회할 때마다 바꾸고 싶어.

Claude가 SQL에서 바뀔 조건과 고정할 업무 규칙을 구분해 확인합니다. 조건은 문자열을 이어 붙이지 않고 DB의 바인드 변수로 전달합니다. 쿼리를 저장하는 것만으로 데이터 조회를 실행하지 않습니다.

> 저장한 쿼리를 보여줘.

목록 예시:

```text
1. 생산실적조회 — 생산DB
2. 생산실적조회 — 품질DB
```

같은 업무 이름도 DB와 번호로 구분합니다. 수정은 기존 번호를 유지합니다. 없는 연결을 다른 DB로 자동 대체하지 않습니다.

## 조건을 정해서 실행하기

> 1번을 2026년 10월 WB 공정으로 조회해줘.

조회할 DB, 실제 날짜 범위와 값, 결과 한도를 짧게 확인한 뒤 실행합니다. 한 번 확인한 동일한 계획을 반복해서 묻지 않습니다. 기본 결과 한도는 10,000행, 20MiB, 실행 시간은 30초입니다. 연결 준비 시간은 별도일 수 있습니다.

> 이번에는 범위가 넓어도 괜찮아. 5만 행, 50MiB, 90초까지 허용할게.

넓은 범위나 많은 데이터를 일괄 거절하지 않습니다. 허락한 한도로 새 계획을 만들고 그 조건으로 실행합니다. 기본값을 넘는 경우 추가 동의를 확인하지만 DB의 접근 권한을 바꾸지는 않습니다. 최대 지원 한도는 100만 행, 512MiB, 1,800초입니다. 그보다 크면 기간 등을 나누어 조회합니다.

계획은 15분 동안 유효하고 한 번만 실행합니다. SQL, DB, 접속 정보나 조건이 바뀌면 이전 계획을 재사용하지 않습니다. 동의 인자는 사용자 답변을 기록하는 실행 방식이며, 사람의 답변을 독립적으로 인증하는 장치는 아닙니다.

건수는 확인된 수준대로 안내합니다. 실습은 합성 데이터의 정확한 건수를 셉니다. Oracle은 자동 전체 COUNT나 계획 테이블 기록을 하지 않아 사전 건수가 미확인일 수 있습니다. LakeHouse는 실행계획의 단계별 추정치를 참고하며 이를 정확한 결과 건수로 말하지 않습니다. 반환 행 한도는 서버가 읽는 전체 데이터량의 보장이 아닙니다.

## 결과를 활용하기

조회 데이터는 Python이 로컬 JSONL 파일로 저장합니다. Claude에는 저장 위치, 행 수, 완료 여부만 전달합니다. 원본 행 전체가 대화에 들어가지 않습니다.

> 조회 결과에서 공정별 합계만 계산해줘. 원본 행은 대화에 출력하지 마.

> 결과를 CSV로 저장해줘.

후속 Python 계산은 같은 결과 파일을 재사용합니다. CSV는 요청할 때만 생성하며 수식으로 해석될 수 있는 문자열을 보호합니다. 원래 값은 JSONL에 남습니다. 일부만 저장된 결과는 전체 합계로 사용하지 않습니다. 정밀한 소수는 문자열로 저장하므로 후속 계산에서 Decimal 등으로 변환합니다.

## 계정 없이 연습하기

`data-query-demo`만 설치하고 아래처럼 말합니다. 서버, 비밀번호와 토큰은 필요하지 않습니다.

1. “데이터 조회 연습 스킬로 가상 자료를 준비해줘. 저장된 쿼리를 보여줘.”
2. “1번을 2026년 10월 WB 공정으로 조회해줘.” 조건 확인 후 1행이 저장됩니다.
3. “같은 조건을 품질DB로 조회해줘.” 1행이 저장되고 합성 수량은 생산DB의 두 배입니다.
4. “대량조회 실습을 실행해줘.” 12,005행으로 기본 한도를 넘는다는 안내를 확인합니다.
5. “이번 가상 조회는 2만 행까지 허용할게.” 확대 계획으로 12,005행 전체가 저장됩니다.
6. “지금 결과를 Python으로 읽어서 행 수와 수량 합계만 알려줘.” 전체 데이터를 모델에 보내지 않고 로컬 계산 결과만 확인합니다.

실습은 SQLite 합성 데이터이며 세 운영 DB의 문법과 성능을 모두 재현하는 에뮬레이터는 아닙니다. 실습 실행기를 운영 모드로 바꾸는 옵션은 없습니다.

## 내 자료가 저장되는 곳

Windows의 기본 개인 저장소는 `%LOCALAPPDATA%\DataQuerySkills\personal`입니다. 실습은 별도의 `demo` 폴더를 사용합니다.

- `catalog.sqlite3`: 연결 이름, 저장 SQL과 조건 정의, 실행 계획
- `connections`: 개인 접속 정보의 env 파일
- `results`: 조회 결과 JSONL과 열 이름 및 완료 정보

설치 폴더 밖에 있으므로 스킬 ZIP을 바꿔도 개인 쿼리와 연결은 유지됩니다. 접속 정보는 평문 파일이며 암호화 저장을 보장하지 않습니다. 개인 저장소를 Git이나 배포 ZIP에 넣지 마세요. 일반 작업에 실행되는 후크, 모델 호출이나 자동 동기화는 추가하지 않습니다.
