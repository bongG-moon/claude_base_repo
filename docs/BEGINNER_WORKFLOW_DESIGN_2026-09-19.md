# 초보자 업무 시작·기억·품질·사용량 통합 설계안

2026-09-19 · 최초 설계 기록

후속 구현: Workspace 0.3의 첫 업무 코스·기억/지식 관리·폴더 지침·사용량·자기 확인 화면을 연결했다. 실제 구현/시험 범위와 남은 운영 확인은 [구현·검증 기록](VALIDATION_BEGINNER_WORKSPACE_2026-09-19.md)을 기준으로 한다. 아래는 구현 전 설계 근거이며 모든 장기 목표가 완료됐다는 뜻은 아니다.

## 1. 결론과 범위

가능합니다. 현재 Company Agent의 회사/개인 기준, 스킬 선택, 기억·지식, 검증, 사용량 집계를 재사용하고, **사용자가 따라 할 수 있는 안내와 결과 확인 화면으로 연결**하는 방향이 적합합니다. 새 하네스나 별도 팀팩을 하나 더 설치하는 방식은 제안하지 않습니다.

핵심 흐름은 `첫 업무 선택 → 필요한 정보 입력 → 실행 → 결과 확인 → 필요한 내용만 기억 → 다음 업무에서 재사용`입니다. 초보자에게 스킬 이름, JSON, 터미널 명령을 먼저 가르치지 않습니다. 개념은 해당 기능을 처음 쓸 때 짧게 설명하고, 상세 안내는 필요할 때 펼칩니다.

이번 검토는 공개 저장소의 안내서·스킬·측정 코드, 사용자 첨부 설명, 현재 로컬 소스를 비교한 설계입니다. 프로그램과 설치본은 변경하지 않았습니다. 아래의 신규 화면·자료 형식·검증 목표는 **아직 구현된 기능이 아닙니다**.

## 2. 참고 자료에서 취할 것과 바꿀 것

검토한 공개 저장소 기준: `jubijubiguri/claude-code-starter`, 커밋 `a5c0e2be8d77befd8eaabc761259dd9b239f80e5`.

| 참고한 개념 | Company Agent 적용안 |
| --- | --- |
| 설명서와 실습 코스를 함께 제공 | 기능마다 짧은 설명, 바로 넣을 예문, 성공 확인법, 실패 시 다음 행동을 한 묶음으로 제공 |
| 프로젝트 지침을 계속 개선 | 선택한 업무 폴더의 목표·입력·출력·확인 기준을 짧게 관리. 기존 파일은 변경안 확인 후 적용 |
| 진단 후 개선하고 다시 측정 | 준비 상태, 실제 업무 결과, 사용량을 분리하고 같은 조건에서 전후 비교 |
| 지침과 축적 지식 구분 | 항상 필요한 짧은 기준과 필요할 때 찾는 지식·업무 절차를 분리 |

참고 저장소의 [온보딩 코스](https://github.com/jubijubiguri/claude-code-starter/blob/a5c0e2be8d77befd8eaabc761259dd9b239f80e5/guides/onboarding-course.md)와 [핸드북](https://github.com/jubijubiguri/claude-code-starter/blob/a5c0e2be8d77befd8eaabc761259dd9b239f80e5/guides/claude-code-handbook.md)은 이러한 안내 구성의 참고 자료입니다. 회사 직원용 실습에서는 Git 설치·코드 작성·위험 명령 실행을 필수 단계로 삼지 않습니다. 차단 체험은 모의 화면으로 설명합니다.

그대로 가져오지 않을 부분도 있습니다.

- 해당 저장소의 준비도 검사에서 `Agent Outcomes`는 실제 업무 정답률이 아니라 평가 폴더·결과 파일·측정 단서의 존재를 점수화합니다. 우리 화면에서 이를 모델 성능 점수로 표시하지 않습니다. [채점 코드](https://github.com/jubijubiguri/claude-code-starter/blob/a5c0e2be8d77befd8eaabc761259dd9b239f80e5/plugins/team-toolbox/skills/ai-readiness-cartography/scripts/score.py#L539)
- 사용량 분석 코드에는 미등록 모델에 다른 모델 가격을 적용하고, 파일 단위 재읽기를 집계하는 로직이 있습니다. 사내 HCP에는 가격을 대입하지 않고, 범위가 다른 읽기와 검증용 재읽기를 낭비로 단정하지 않습니다. [분석 코드](https://github.com/jubijubiguri/claude-code-starter/blob/a5c0e2be8d77befd8eaabc761259dd9b239f80e5/plugins/team-toolbox/skills/improve-token-efficiency/scripts/analyze_sessions.py)
- 참고 스킬의 사용량 보고서는 외부 차트 CDN에 의존합니다. 우리 안내·진단 화면은 설치 묶음의 자원만으로 표시하도록 설계합니다. [스킬 설명](https://github.com/jubijubiguri/claude-code-starter/blob/a5c0e2be8d77befd8eaabc761259dd9b239f80e5/plugins/team-toolbox/skills/improve-token-efficiency/SKILL.md)
- 전역 `~/.claude/CLAUDE.md`를 회사 파일로 교체하지 않습니다. 공식 문서에서 이 위치는 사용자 공통 지침이며, 개인 프로젝트 지침의 파일명은 첨부 설명의 `.claude.local.md`가 아니라 `CLAUDE.local.md`입니다. 기존 파일을 발견했다고 자동 이동·수정하지 않습니다. [공식 기억 문서](https://code.claude.com/docs/en/memory)
- `/revise-claude-md` 같은 추가 플러그인 명령을 기본 내장 기능으로 전제하지 않습니다. 실제 기능 목록에 없는 명령은 호출하거나 설치하지 않습니다.
- 공개 저장소에서 LICENSE/COPYING/NOTICE 파일은 확인되지 않았습니다. 이번에는 개념만 참고했고 외부 코드를 복사·설치·실행하지 않았습니다. 코드 재사용은 라이선스 확인을 별도로 선행합니다.

## 3. 현재 구현과 실제 부족한 부분

아래는 배포된 회사 PC가 아니라 **이 작업 폴더의 현재 소스** 기준입니다.

| 분야 | 현재 있는 기반 | 보완할 부분 |
| --- | --- | --- |
| 첫 사용 | `resources/first-work.html`에 읽기·보고서·선호 저장 예문과 확인법 | 실제 업무 화면의 안내 진행, 완료 근거, 다음 단계와 연결 |
| 로컬 화면 | `local_app`에서 기존 CLI 연결, 파일 선택, 질문·승인, 결과 목록, 대화 이어하기 | 첫 사용 코스, 기억 관리, 품질·사용량 화면 |
| 회사/개인 구분 | `company_policy.py`와 `workStandards`, 업무별 기준 전달 | 현재 적용 기준과 개인화 가능 범위를 사용자가 이해할 화면 |
| 업무 폴더 구성 | `project_harness.py`의 확인·계획·적용·검증, 소유 파일 보호 | 단순 업무도 쓸 수 있는 짧은 업무 설명서와 검토 흐름. 매 폴더에 전체 하네스 생성은 불필요 |
| 개인 기억 | `memory.py`의 저장·검색·버전 백업·분량 제한 | 무엇을 왜 저장했고 어디에 적용하는지, 최근 변경/사용 중지/복원 확인 |
| 개인/회사 지식 | `knowledge.py`의 회사 기반 + 개인 보완, 충돌 확인, 검색·선택 내보내기 | 출처·확정 여부·관계·최신성, 회사 공유 후보 검토 화면 |
| 학습 | `learning.py`의 업무 단위 후보, 조건부 개인화, 효과 관찰·되돌리기 | 기존 자동 학습과 수동 저장을 한 이력으로 보여 주기 |
| 환경/지침 진단 | `diagnostic_report.py`, `context_audit.py`, 설치 진단 | 업무별 준비 체크리스트와 개선 순서. 현재 크기 검사는 전체 실제 로드 목록 검사가 아님 |
| 사용량 | `usage_diagnostics.py`가 선택 로그의 토큰·같은 범위 읽기·관찰 시간을 제한 집계 | 모델별 집계·가격 근거·업무별 전후 비교, UI 표시 및 중복 합산 방지 |
| 실시간 통계 | `local_app/bridge.py`가 완료 이벤트의 `usage`, `costUsd`, `durationMs` 전달 | 현재 프런트는 완료 상태/파일 갱신만 처리. 통계 화면과 영속 집계는 추가 필요 |
| 성능 검증 | 기존 연습실 35개 시험/55개 요청, 경로·스킬·실행 복구 테스트 | 대표 업무별 정답/검증 기준과 실제 HCP 실행 결과를 연결하는 평가 기록 |

즉, 기억·진단·로그 집계 엔진을 새로 만드는 것이 주된 과제가 아닙니다. **지금 있는 기능의 연결, 적용 범위 표시, 근거 있는 완료 판정**이 우선입니다.

## 4. 관리 구조: 회사와 개인, 두 영역 유지

| 관리 주체 | 포함 내용 | 사용자에게 보이는 의미 |
| --- | --- | --- |
| 회사 | 필수 정책, 기본 업무 방식, 부서별 기준, 공통 스킬·지식·양식 | 회사가 제공한 기준. 필수와 기본값을 구분 |
| 개인 | 선호, 개인 지식·스킬, 자신이 관리하는 업무 폴더 구성 | 내 업무 방식을 저장하고 관리 |

프로젝트는 **어디에서 적용하는가**이고, 팀/부서는 **어떤 회사 기준을 적용하는가**입니다. 별도 팀팩이나 세 번째 정책 소유자를 만들지 않습니다. 회사 지식에 있는 문장이 곧 필수 정책은 아닙니다.

개인 화면의 적용 범위는 현재 설치 등록에서 계산합니다. User 범위와 Project 범위의 상태 저장소를 자동 합치지 않습니다. 예를 들어 현재 프로젝트 설치의 기억을 ‘모든 폴더에 적용됨’으로 표시하면 안 됩니다. 범위 변경·이관은 대상과 충돌을 확인하는 별도 작업입니다.

기존 로그인·모델·MCP·개인 플러그인·Claude 설정을 그대로 사용합니다. 이 설계를 위해 새 앱 계정, 별도 API 키, 다른 모델 연결을 만들지 않습니다.

## 5. 초보자의 실제 화면과 안내 과정

기존 업무 홈을 유지하고, 필요한 관리 화면만 추가합니다.

```text
업무 홈
  ├─ 처음이라면: 첫 업무 따라 하기
  ├─ 자료 읽기 / HTML 보고서 / PPT / 자유 요청
  ├─ 내 업무 방식: 저장한 기억·지식·절차
  └─ 사용 현황: 준비 상태 / 업무 결과 / 시간·사용량
```

### 5.1 첫 실행

1. 기존 CLI 경로·설정 위치·Company Agent 설치 범위를 읽기 전용으로 확인합니다.
2. 작업 폴더를 선택하고 기존 신뢰/승인 절차를 따릅니다.
3. ‘처음 사용해요’ 또는 ‘바로 업무 시작’을 선택합니다. 온보딩은 건너뛸 수 있습니다.
4. 준비된 연습 자료 또는 사용자가 선택한 허용 자료 하나로 시작합니다.

정적 설치 확인은 모델을 부르지 않습니다. 실제 인증·응답은 첫 사용자 요청에서 확인합니다. 실행 파일 발견만으로 ‘연결 정상’이라고 하지 않습니다. 초보자도 폴더마다 `/init`이나 `/company-agent:skills`를 입력할 필요가 없어야 합니다.

### 5.2 짧은 기본 코스

각 단계는 `한 줄 설명 / 해보기 / 이렇게 되면 성공 / 잘 안되면`을 같은 형식으로 제공합니다. 시간 표시는 학습 안내용 목표이며 사내 모델 응답 시간 보장은 아닙니다.

| 단계 | 사용자 행동 | 성공 근거 |
| --- | --- | --- |
| 1. 자료 하나 읽기 | 원본 첨부 후 ‘내용을 정리해줘’ | 관련 스킬이 있으면 실제 본문 사용, 페이지·표·핵심 수치를 원본과 대조 |
| 2. 결과 만들기 | 가상 월간 실적으로 HTML 또는 PPT 선택 | 디자인/기존 양식 질문에 답한 뒤 생성. 파일 열기와 수치 확인 |
| 3. 수정 요청하기 | ‘결론부터 보여줘’ 등 한 가지 수정 | 수정된 결과 확인. 이번 수정과 앞으로의 개인 선호 저장을 구분 |
| 4. 내 방식 저장하기 | 장기 적용할 선호 하나만 명시 | 저장 내용·적용 범위 확인 후 같은 범위의 새 대화에서 조회 |
| 5. 다음 업무에 활용 | 새 업무에서 같은 선호/지식 사용 | 실제 조회·사용 근거와 결과 확인. 말투가 비슷한 것만으로 저장 성공 처리 금지 |

Office가 없으면 텍스트 실습으로 시작할 수 있지만 상태는 ‘텍스트 요약 체험’입니다. 이를 Office 읽기 검증으로 바꾸지 않습니다. 코스용 가상 선호는 연습 범위임을 표시하고, 실무 저장소로 옮길지는 사용자가 선택합니다.

코스 진척은 `미시작 / 진행 / 결과 확인 필요 / 확인 완료 / 건너뜀 / 환경 미준비`로 보관합니다. AI의 완료 문구만으로 완료 체크하지 않고, 파일 확인과 사용자 확인을 각각 기록합니다. 프로그램 업데이트 후 재검증이 필요한 항목은 과거 통과와 현재 상태를 분리합니다.

### 5.3 업무 요청 안내

입력창에는 ‘자료 / 원하는 결과 / 꼭 확인할 것’ 세 가지 힌트만 둡니다. 입력한 내용은 그대로 재사용하고 누락 정보만 묻습니다. 같은 디자인을 고르기 위해 번호 묶음과 세부 번호를 두 번 고르는 흐름은 만들지 않습니다.

예문: ‘이 자료를 읽고 핵심 내용과 확인할 사항을 정리해줘. 자료에 없는 이유는 추측하지 말고, 실제 읽은 범위도 알려줘.’

관련 스킬 이름은 화면이 실제 목록에서 알아낼 수 있어야 합니다. 없는 스킬을 호출하도록 예문에 고정하지 않습니다. 같은 역할이 겹칠 때만 차이를 보여 주고 선택을 받습니다.

## 6. 기억을 어디에 무엇으로 남길 것인가

사용자에게 모두 ‘기억’으로 설명하되 내부 저장 목적은 구분합니다.

| 내용 | 저장/관리 방식 | 예 |
| --- | --- | --- |
| 개인 표현 선호 | 기존 Personal Memory | 결론 → 근거 → 확인 필요 순서로 보고 |
| 폴더의 작업 기준 | 짧은 프로젝트 지침 또는 기존 생성 규칙의 검토된 변경 | 입력 폴더, 결과 형식, 단위, 확인할 사항 |
| 재사용할 사실·정의·결정 | 기존 Knowledge 항목과 출처 | 실적 집계 기준, 결정일과 확정 상태 |
| 반복 작업의 순서 | 기존 개인 Skill/프로젝트 하네스 | 월간 자료 취합 → 대조 → 보고서 제작 |
| 원본 문서와 전체 대화 | 원래 업무 파일/기존 대화 보존 정책 | 기억 저장소에 통째로 복제하지 않음 |

### 6.1 ‘이번 업무에서 남길 내용’ 검토

- 기존 업무 완료 시점의 학습 후보를 재사용합니다. 새 요약 에이전트가 매 답변 뒤 전체 대화를 재분석하지 않습니다.
- 카드에는 `내용 / 출처 구분 / 적용 범위 / 저장 유형 / 새로 추가·변경 / 확인 상태`를 보여 줍니다.
- 명시적 ‘기억해줘’는 기존 저장 절차로 처리합니다. 반복 교정 등 기존 자동 학습의 허용 조건과 사용 중지 설정도 유지합니다. 이번 개편을 이유로 모든 저장을 다시 승인받거나 기존 자동 학습을 조용히 끄지 않습니다.
- 새 프로젝트 지침 변경과 회사 공유 후보는 변경안을 확인받습니다. 개인 메모나 문서에서 추출한 내용을 회사 정책으로 자동 승격하지 않습니다.
- 후보가 없거나 승인/작업자 결과를 기다리는 중이면 검토를 강요하지 않습니다. 학습 미완료를 이유로 업무 완료를 반복 차단하지 않습니다.

`저장됨`과 `다음 작업에서 조회됨`, `결과에 반영된 것이 확인됨`을 구분합니다. 관찰할 수 없는 경우 ‘반영 여부 미확인’으로 표시합니다. 기존 기억 파일의 버전 백업과 자동 변경 되돌리기를 활용하고, 일반 기억 변경 복원은 해시 비교·현재 수동 편집 보존이 가능한 경로를 보완합니다.

### 6.2 프로젝트 지침 관리

간단한 업무는 목표·입력·출력·검증 기준의 짧은 설명만으로 충분합니다. 다단계 반복 작업일 때만 기존 Project Harness Factory로 확장합니다.

기존 `CLAUDE.md`를 발견하면 덮어쓰지 않습니다. 새로 만들거나 수정할 때는 미리보기 → 사용자 확인 → 현재 파일 해시 재확인 → 백업 → 반영 → 재읽기 순서를 사용합니다. 생성기 소유 파일과 사용자가 직접 만든 파일을 구분합니다. 공유될 수 있는 위치에 개인 정보가 섞이지 않게 설명하고, Git 업로드는 별도 요청이 있을 때만 합니다.

사용자가 관리하던 Claude 자체 auto memory와 Company Agent의 개인 기억은 다른 저장소입니다. 화면에서 출처를 구분하고 자동 동기화·이중 저장을 하지 않습니다. 파일 존재를 실제 세션 로드 증거로 바꾸지 않습니다.

### 6.3 회사 지식과 개인 보완

기존 회사 기반/개인 보완 구조에 `출처 참조, 확정 상태, 검토일, 관련 항목 ID`를 선택적으로 보강합니다. 오래된 항목은 검토 필요로 표시하고 자동 삭제하지 않습니다. 전체 본문 대신 주제별 색인과 관련 항목을 검색합니다. 도입 초기에 별도 벡터 DB나 그래프 서버는 필요하지 않습니다.

공유 흐름은 `개인이 선택한 항목 → 민감 정보/원문 포함 검토 → 공유 후보 내보내기 → 회사 담당자 검토 → 회사 묶음 배포`입니다. 공유 후보 상태는 세 번째 관리 영역이 아닙니다. 전송·게시·정책 반영을 자동으로 하지 않습니다.

## 7. 평가 화면: 하나의 성능 점수로 합치지 않기

### 7.1 사용 준비 상태

업무를 실행하지 않는 읽기 전용 진단입니다. 기존 설치 진단과 지침 크기 검사를 우선 활용합니다.

확인 항목: 실제 CLI/설치 범위, 스킬 목록의 유효성, 필요한 프로그램·양식, 자료 위치와 입력·출력 설명, 검증 기준, 지침/회사 지식의 버전과 참조 연결.

초기 화면은 ‘준비됨 5 / 확인 필요 2 / 해당 없음 1’처럼 근거를 보여 줍니다. 필수 준비물이 없는데 평균 점수가 높다고 준비 완료로 표시하지 않습니다. 향후 점수화하더라도 규칙 버전, 확인 비율, 제외 항목을 함께 표시하고 실제 업무 성공률과 분리합니다. 일반 문서 폴더에 Git·코드 테스트가 없다고 감점하지 않습니다.

### 7.2 실제 업무 결과

기존 연습실 중 대표 사례를 선정해 같은 입력과 판정 기준으로 비교합니다.

| 업무 | 대표 확인 기준 |
| --- | --- |
| PPT/Excel/Word 읽기 | 스킬 이름 없이 요청해도 올바른 경로 사용, 전체 확인 범위, 표·수치 정확도, 원본 보존 |
| HTML/PPT 제작 | 새 디자인/기존 양식 선택, 질문에서 실제 대기, 산출물 열림, 숫자 대조, PPT 편집 가능 개체 |
| 개인 선호 | 저장 확인, 같은 범위 새 대화 조회, 다른 범위로 잘못 전파되지 않음 |
| 회사 지식 + 개인 보완 | 적합한 기준 선택, 출처/충돌 표시, 회사 필수 기준을 개인 내용으로 변경하지 않음 |
| 스킬 없음/중복 | 없는 스킬 호출 없음, 허용된 일반 작업 가능, 같은 역할 충돌 때만 질문 |
| 오류 회복 | 파일 미생성·인코딩·정규식 오류를 구별, 같은 실패 무한 재시도 없음, 완료된 부작용 재실행 없음 |

표시 지표는 첫 시도 성공 건수/시험 수, 최종 확인 성공 건수/시험 수, 재작업 횟수, 필요한 도움, 결과 정확성, 스킬 적용 근거입니다. 실패·취소·환경 미준비·미검증을 별도 분류하고 빠진 사례도 보이게 합니다. 평가 제외로 성공률을 높이지 않습니다.

모형 CLI 테스트, 코드 자동 테스트, 실제 HCP 업무 시험은 별도 배지로 구분합니다. 평가용 정답은 실행 모델에게 제공하지 않습니다. 고정 가상 자료의 수치·파일 검사는 결정적 검사로, 디자인·가독성은 사용자/검토자 확인으로 판정합니다. LLM 심사는 선택적 보조 수단이며 기본 추가 호출로 만들지 않습니다.

### 7.3 개선 효과 비교

비교 조건에는 프로그램·스킬·회사 기준·CLI 버전, 실제 보고된 모델 ID, 입력 fixture, 설치 범위, 판정 기준, 캐시 조건을 남깁니다. 미확인 값은 채우지 않습니다. 개인 선호나 입력 자료가 다른 실행을 공정한 전후 비교로 묶지 않습니다.

‘5회 중 4회 → 5회 중 5회’처럼 분모를 공개합니다. 소수 사례의 차이는 관찰 결과이지 일반적인 성능 향상 보장이 아닙니다. 환경차단도 별도 집계하고, 시간·토큰 감소는 결과 품질이 유지되는 범위에서만 개선으로 평가합니다.

## 8. 사용량과 시간 관리

### 8.1 수집 경로와 표시

1. 현재 앱 업무: 기존 CLI 스트림이 이미 주는 사용량을 정규화합니다. 화면 표시 자체에는 모델을 부르지 않습니다.
2. 이전 업무: 사용자가 고른 로그만 기존 `analyze_usage`로 읽습니다. 전체 PC나 다른 프로필을 탐색하지 않습니다.
3. 회사 집계: 추후 회사가 승인한 경우에만 기존 계측 시스템 또는 OpenTelemetry와 연결합니다. 초기 버전의 필수 구성으로 두지 않습니다.

CLI 버전에 따라 이벤트·기록 형식이 달라질 수 있으므로 기능/스키마 판별과 누락 표시가 필요합니다. 공식 문서도 로그 내부 필드 연결의 버전 의존성을 명시합니다. [공식 모니터링 문서](https://code.claude.com/docs/en/monitoring-usage)

표시할 값: 입력·출력·캐시 쓰기·캐시 읽기 토큰, 모델, 관찰 범위, 도구 요청/실패/재시도, 업무 시간, 같은 범위 읽기. 필드가 없으면 0이 아니라 ‘미제공’입니다. 일부만 관찰되면 부분 합계임을 표시합니다.

CLI 완료 합계와 메시지별 사용량을 더하지 않습니다. 한 업무는 한 집계 원천을 우선 선택하고, 메시지/실행 식별자로 중복을 제거합니다. 부모 합계에 작업자 사용량이 포함되는지 모르면 별도 더하지 않고 포함 범위를 미확인으로 남깁니다. 앱 재연결·이어하기·기존 로그 가져오기도 같은 원칙을 적용합니다.

### 8.2 비용과 예산

가격이 있는 모델만 `정확한 모델 ID + 적용일 + 통화 + 단가 출처`로 추정 비용을 계산합니다. 별칭만으로 HCP 모델을 외부 상용 모델에 대응시키지 않습니다. CLI 제공 비용도 계산 근거가 미확인이면 그대로 회사 청구액으로 표시하지 않습니다.

개인 Claude 구독의 토큰 환산액은 추가 청구액이나 남은 구독 한도가 아닙니다. 계정 한도는 제공자가 실제 제공한 범위만 표시합니다. [공식 비용 안내](https://code.claude.com/docs/en/costs)

초기에는 사용자가 요청한 업무/기간 기준의 알림 한도를 제공합니다. 응답이 끝난 뒤 받는 집계만으로 실시간 강제 예산 한도를 보장할 수 없습니다. 중단 버튼은 보낼 수 있으나 진행 중 응답/작업의 비용은 더 발생할 수 있음을 표시합니다. 회사 강제 한도는 기존 제공자/게이트웨이 정책과 별도로 다룹니다. UI가 모델·승인 설정을 자동 변경하지 않습니다.

### 8.3 느린 구간 구분

`로컬 준비 / 모델 응답 / Claude 도구 승인 / Office 확인 창 시작 / 사용자 응답 대기 / 실제 도구 실행 / 결과 확인`을 관찰 가능한 이벤트로 나눕니다. 구간이 겹치면 중복 합산하지 않습니다. UI의 질문·승인 대기와 Office 결과의 시간을 연결할 수 없으면 미확인으로 표시합니다.

전체 관찰 시간을 순수 모델 시간으로 표시하지 않습니다. ‘느리니 다시 실행’ 버튼 대신 현재 단계·마지막 진행·중지 선택을 보여 줍니다. 승인 전 지연을 사용자 대기로 오인하지 않게 합니다.

### 8.4 절감 안내

반복 탐색, 변경 없는 스킬 본문 재로드, 지나치게 긴 지침, 관련 없는 대화 누적을 근거가 있을 때 알려 줍니다. 캐시 비율/응답 길이만으로 A~F 등급을 매기지 않습니다. 필요한 검증을 줄여 점수를 높이는 유인도 만들지 않습니다.

‘업무를 나눠 새 대화 시작’과 ‘필요한 결정만 남기기’를 제안할 수 있지만 기존 대화를 자동으로 지우거나 매 작업마다 `/compact`를 강제하지 않습니다. CLI 전용 명령은 해당 환경 지원을 확인하고, GUI 미지원 기능은 기존 원본 CLI 경로를 유지합니다.

| 업무 평가 | 기존 `scripts/test-lab`와 신규 결과 집계 | 입력/평가 기준 고정, 실제 실행 근거, 버전별 전후 비교 |

브라우저가 임의 파일 경로나 셸 명령을 전달해 실행하게 만들지 않습니다. 로컬 서버는 기존 인증·Origin 검사에 더해 허용된 작업 이름과 자료 형식을 검증하고, 현재 설치 등록에서 해석한 경로만 기존 런타임에 전달합니다. 기억 저장/지침 변경 같은 쓰기 요청은 기존 권한·검증 경로를 유지합니다.

설계용 공통 기록에는 `schemaVersion, recordId, source, observationStatus, scopeRef, componentVersions`를 둡니다. 범위는 설치 기록에서 계산하며 UI 입력만 믿지 않습니다. 쓰기 요청에는 대상 해시와 작업 ID를 사용해 수동 편집 충돌·중복 클릭을 검출합니다. 중간 상태의 재연결은 조회이며 업무 자동 재실행이 아닙니다.

새 기록은 기존 메모리 파일을 대량 변환하지 않는 부가 파일로 도입합니다. 이전 버전 자료가 없거나 읽을 수 없으면 ‘기록 없음/호환 확인 필요’로 처리합니다. 공유 내보내기는 별도 허용 필드 목록으로 만들고 사용자명·원문 경로·대화·메일/문서 본문·자격증명은 기본 제외합니다.

## 10. 실행 시간·토큰 증가 방지 조건

- 홈/안내/통계/준비 상태 화면을 열기 위한 추가 LLM 호출: **0회 목표**.
- 일반 업무 요청에 이번 온보딩 문서·핸드북·전체 지식·전체 스킬 본문을 주입하지 않습니다. 관련 짧은 지침/색인만 사용합니다.
- 기존 목록 revision/본문 재사용 판단을 유지합니다. 목록 안내를 길게 늘리거나 일반 폴더 조회를 다시 막지 않습니다.
- 준비 상태는 설치/프로젝트/관련 파일의 변경 시 갱신하고, Office 실행·인증 확인은 실제 필요할 때만 합니다. UI 열 때마다 Office를 띄우지 않습니다.
- 기존 사용량 분석 제한(최대 8개 로그, 합계 32 MiB/50,000행)을 유지합니다. 더 큰 범위는 나눠 요청하며 전체 로그 자동 탐색으로 확대하지 않습니다.
- 소규모 안내를 위해 상위 모델·추가 작업자를 띄우지 않습니다. 기존 업무별 위임·최소 위험 기준은 보존합니다.
- 새로운 상시 Hook 비용을 만들기보다 기존 이벤트를 화면에서 소비합니다. 모니터링·기억 검토는 실행 중 업무와 분리해 지연/실패가 업무를 막지 않게 합니다.
- 기존 스킬 선택 누락 교정과 실제 권한 거절은 구분합니다. 이번 기능이 새 전역 차단·Stop 재시도 루프를 만들지 않아야 합니다. CLI 자체의 오류 색상을 화면 문구 변경만으로 없앴다고 주장하지 않습니다.

실제 토큰은 제공된 usage로, 안내 크기는 문자/바이트로 각각 비교합니다. 내부 기준 PC에서 반복 실행해 추가 준비 시간과 전체 업무 지연을 별도로 측정합니다. 목표 수치는 기준 측정 후 정하며 아직 확인하지 않은 절감률을 약속하지 않습니다.

## 11. 개인정보·공유·호환성

로컬 UI는 모델까지 오프라인이라는 뜻이 아닙니다. 기존 Claude/HCP 전송 범위를 안내하고, 새로운 분석 서버·계정을 추가하지 않습니다. UI의 기존 대화 이력과 Claude 이력이 별도 저장된다는 점도 숨기지 않습니다.

새 통계 저장은 원문 없는 최소 집계만 대상으로 하고 보존 기간/기록 사용 여부를 회사 기준에 맞게 정합니다. 기록 삭제/내보내기는 해당 기록만 대상으로 하며 개인 기억·작업 결과·다른 프로그램 로그를 같이 삭제하지 않습니다. 회사 집계를 개인 순위표로 기본 제공하지 않습니다.

지원 목표는 우선 현재 Windows + 기존 CLI 환경입니다. 비-Git 폴더, 한글·공백 경로, 설정 루트 변경, User/Project 설치, 개인 계정/사내 HCP를 각각 검증합니다. 다른 셸·WSL·Mac/Linux와 CLI 전용 기능까지 같은 수준으로 지원한다고 약속하지 않습니다. 미지원 상황에서도 기존 원본 CLI 사용 경로는 남깁니다.

## 12. 단계별 구현과 통과 기준

| 단계 | 범위 | 완료 기준 |
| --- | --- | --- |
| 1. 첫 사용 연결 | 공통 코스 자료, 기존 홈 연결, 기능 준비 상태, 확인 근거 표시 | 처음 쓰는 사람이 명령 없이 업무 1건 진행. 스킬 명시 없는 요청/스킬 없음/질문 대기 모두 검증 |
| 2. 기억 관리 | 기존 기억·지식·학습 조회, 범위 표시, 저장·변경 검토, 충돌/되돌리기 | 새 대화 재조회, 범위 격리, 기존 수동 변경 보존, 회사 정책 무변경 |
| 3. 시간·사용량 | 완료 usage 표시, 선택 로그 가져오기, 중복 방지, 미확인 값, 전후 비교 | 알려진 fixture와 정확히 일치. HCP 미등록 가격이 금액으로 바뀌지 않음 |
| 4. 업무 품질 | 기존 연습실 결과 집계, 업무별 판정 기준, 개선 이력 | 코드/모형/실제 HCP 시험 분리. 실패·미검증·환경차단의 분모 공개 |
| 5. 배포 | 안내서/오프라인 묶음/Workspace 버전 호환 및 회사 시범 사용 | 신규 설치와 기존 사용자 업데이트 모두에서 개인 자료·로그인·모델·MCP 보존 확인 |

모든 단계는 현재 테스트를 회귀 실행하고, 실제 업무 흐름을 대표 사례로 확인한 뒤 다음 단계로 갑니다. 문서만 읽은 성공, 스킬 등록만 된 성공, 모형 실행만 된 성공을 실제 사용자 업무 성공으로 기록하지 않습니다.

필수 회귀 사례:

1. 작업 폴더에 스킬 파일이 없어도 등록된 회사 스킬을 인식한다.
2. 관련 스킬이 없으면 없는 스킬을 강제 호출하지 않고 허용된 일반 작업을 한다.
3. 후보가 겹치면 같은 역할일 때만 질문하며 사용자 답변을 기다린다.
4. 파일 생성 실패를 인코딩으로 단정하지 않고 실제 응답과 정확한 경로를 확인한다.
5. 승인/디자인 질문/작업자 실행 대기를 검증 실패로 반복 보정하지 않는다.
6. 개인 기억 저장 후 새 대화에서 조회되며, 프로젝트 설치의 기억이 다른 범위로 새지 않는다.
7. 전체 대화·문서·자격증명이 새 통계/기억 기록에 복제되지 않는다.
8. 중복 스트림·재접속·작업자 합계·로그 재가져오기에서도 토큰이 중복 계산되지 않는다.
9. 알 수 없는 모델/누락 토큰/부분 로그는 미확인/부분 집계로 남는다.
10. 회사 PC의 실제 Office/HCP 결과와 일반 개인 PC의 결과를 구분해 기록한다.

초보자 시범 사용에서는 기능 통과뿐 아니라 첫 결과까지 걸린 시간, 도움 요청 횟수, 재시도 이유, 사용자 본인의 결과 확인 여부를 관찰합니다. 사용자 테스트의 대화 원문을 별도 분석 목적으로 수집하려면 범위와 동의를 먼저 정합니다.

## 13. 이번 검토로 정한 우선순위

**1차 구현은 ‘첫 업무 안내 + 현재 적용 범위 표시 + 결과/기억 확인 연결’이 적합합니다.** 그 다음 이미 집계 가능한 사용량을 화면에 연결하고, 실제 업무 평가를 정교화합니다. 새로운 스킬 여러 개를 추가하거나 기존 하네스 전체를 교체하는 것은 우선순위가 아닙니다.

아직 정하지 않은 운영값은 사내 HCP의 토큰/가격 제공 범위, 허용된 통계 보존 기간, 회사 공유 담당자와 반영 절차입니다. 개발 기본 동작은 가격 미확인, 로컬 최소 기록, 외부 자동 공유 없음으로 두되 회사 정책 확인 뒤 확정합니다.

이 설계안에는 소스 검토 근거가 포함되어 있지만, 설계한 신규 기능의 테스트 통과나 사내 동작 확인을 뜻하지 않습니다. 구현과 실제 시범 결과를 각각 별도로 남겨야 합니다.
