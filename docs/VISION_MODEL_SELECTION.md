# 이미지 전용 모델 선택 — 구현·검증 기록

확인일: 2026-10-14. 소스 변경이며 Release 게시·설치 PC 업데이트는 아직 하지 않았습니다.

## 플러그인 사용 안 함과 연결 갱신

Company Harness 기능은 `company-agent` 플러그인으로 제공되며, 앱의 설정 저장·재연결 UI와 역할이 다릅니다. 네이티브 설치 기록만 보던 활성 판정을 사용자 설정 → 현재 업무 폴더의 프로젝트 설정 → 프로젝트 로컬 설정 순서로 확인하도록 수정했습니다. 프로젝트에서 `enabledPlugins`가 `false`이면 사용자 전체 설치 기록으로 되살리지 않습니다. 파일·프로필·등록 상태 확인만 하며 설정·개인 자료를 변경하거나 모델 연결 시험을 추가하지 않습니다. 일반 텍스트 Read의 빠른 경로도 유지합니다. Windows의 현재 업무 폴더 기준이며 CLI의 명령행·조직 정책까지 대체하는 자체 권한 판정기는 아닙니다. [Claude 공식 설정 범위·우선순위](https://code.claude.com/docs/en/settings)

`Agent type 'company-agent:vision-worker' not found`는 모델 API 호출 전에 현재 CLI에서 작업자 정의를 찾지 못한 오류입니다. 하네스가 활성인 상태에서 이 실패를 받으면 모델 장애·백업 대상으로 처리하지 않으며, 자동 재활성화·설정 탐색·같은 호출 반복을 안내하지 않습니다. 플러그인이 비활성이면 이미지 인계 안내와 선택값 갱신도 출력하지 않습니다.

앱의 설정 적용 확인창은 별도 Workspace 소스에서 확인했으며 이 작업에서 중복 구현하지 않았습니다. 재연결은 기존 대화를 유지하므로 과거에 받은 이미지 인계 지시가 남을 수 있습니다. 비활성 플러그인은 그 대화를 정정하는 후크도 실행할 수 없으므로, 이 경우 새 대화에서 현재 기능만 사용합니다. 설정 저장이나 재연결만으로 과거 지시 제거를 보장하지 않습니다.

이번 보완 검증: `test_native_runtime` + `test_vision_dispatch` 66개 통과, 비활성 후크 통합·활성 판정·비전·Read 회귀 묶음 109개 통과(두 묶음은 일부 중복). 새 `test_plugin_scope_activation` 12개는 실제 `native_entry`와 설치 기록을 연결해 비활성 시 안내·비전 기록 미생성, 재활성화·다른 폴더·일반 Read 보존을 확인합니다. 기존 위험 명령 차단은 바꾸지 않았습니다. 별도 앱 저장소의 적용·재연결 관련 60개 검사도 통과했습니다. 실제 회사 PC에서 플러그인을 끄고 새 연결·새 대화를 비교하는 시험은 별도입니다.

## 사용자 흐름

1. 이미지 작업이 실제 필요할 때만 처음 사용할 모델을 한국어로 묻습니다. 실제 모델 ID를 직접 입력하거나 `HCP-Vision-Latest`를 고릅니다. 취소하면 모델을 호출하지 않습니다.
2. 개인 저장소 `config/vision-model.json`과 기존 Claude 설정 위치의 `agents/company-harness-vision-<범위 해시>.md` 한 개를 관리합니다. 기존 개인 자료·인증·주 모델·MCP·권한은 변경하지 않습니다. 같은 파일로 변경하며 사용자 수정·파일 충돌·다른 프로필로의 중복 생성을 거절합니다.
3. 처음 저장·변경한 뒤에는 **Claude를 다시 열어 새 연결**에서 사용합니다. 앱에서는 현재 작업을 마친 뒤 새 대화를 엽니다. 같은 연결의 다음 질문, `/resume`, `/compact`만으로 모델 변경을 보장하지 않습니다.
4. 이후 이미지 확인은 선택 모델을 재사용합니다. `/company-agent:vision-model` 또는 “이미지 모델을 바꿔줘”로 변경합니다. 일반 대화 모델은 처음부터 바꾸지 않으므로 복구 호출이 필요 없습니다.

## 왜 새 연결이 필요한가

공식 [서브에이전트 문서](https://code.claude.com/docs/en/sub-agents)는 전체 모델 ID를 작업자 정의에서 지정하도록 안내합니다. 설치된 CLI 2.1.296의 `Agent.model` 입력은 별칭만 허용합니다. 후크에서 전체 ID를 넣어도 스키마 검증으로 거절됩니다.

로컬 CLI의 지속 `stream-json` 연결에서 정의 파일 생성·변경 후 다음 사용자 턴까지 기다려도 이전 모델 또는 미등록 작업자 상태가 유지됐습니다. 파일 감시 설명만 믿고 즉시 적용했다고 하지 않습니다. `SessionStart(startup)`의 선택 버전과 실제 요청 시 버전을 비교하며, 변경 뒤 같은 연결에서는 이전 모델로 대신 실행하지 않습니다. `/resume`은 같은 프로세스에서도 가능하므로 새 연결 증거로 간주하지 않습니다.

새 Mods API를 강제 의존하거나 기존 하네스 설치 조건을 높이지 않았습니다. 새 연결에 적용되는 네이티브 작업자 방식입니다. 운영 CLI 버전에서도 새 연결 후 실제 요청 모델을 확인해야 합니다.

## 백업 범위

네이티브 `PostToolUseFailure`의 `Agent terminated early due to an API error` 오류에서 종류·HTTP 상태·실제 API 요청 모델을 확인합니다. 현재는 `model_not_found/404`, `model_unavailable/503`, `service_unavailable/503`, `overloaded_error/529`만 인정합니다. 선택 모델과 오류의 요청 모델이 같아야 합니다.

- 원래 선택값은 유지하고 HCP 백업을 새 읽기 작업자로 한 번만 요청합니다.
- 대화·폴더·원래 프롬프트 해시와 5분짜리 실패 기록에 묶습니다. 같은 토큰의 병렬 재사용도 원자적으로 차단합니다. 프롬프트·이미지·인증정보는 기록하지 않습니다.
- 백업 자체의 실패, 이미 HCP를 선택한 경우, 취소·권한 거절·파일/판독 오류·문맥 초과·불명확한 오류에는 추가 호출하지 않습니다.
- 작업자가 작성한 `VISION_UNAVAILABLE` 문장이나 다른 응답 모델명만으로 장애·백업을 확정하지 않습니다.
- 조직의 작업자 모델 강제 설정은 해제하거나 우회하지 않습니다. 알 수 없는 구형 CLI 오류 형식에는 보수적으로 백업하지 않습니다.
- 하네스의 백업은 1회지만 CLI·게이트웨이 자체 재시도 횟수까지 제어하는 것은 아닙니다.

## 평소 비용과 보안

일반 텍스트 Read는 설정 파일·세션·코덱·모델 목록을 읽지 않는 빠른 경로를 유지합니다. 프롬프트 준비에는 선택 여부만 전달하고, 이미지 요청에서만 작은 선택값·연결 버전·소유 파일을 확인합니다. 새 연결당 선택 버전 기록 외에 별도 모델 시험·LLM 분류·자동 학습·Stop 검증 단계를 넣지 않습니다. 큰 PNG/JPEG 보정은 기존처럼 성공한 Read 결과에만 적용합니다.

직접 붙여넣은 이미지나 모든 MCP의 이미지 응답을 포괄적으로 가로채는 기능은 아닙니다. 이미지 파일 경로 또는 지원되는 읽기·캡처 경로를 사용합니다.

## 실제 CLI 로컬 검증

빈 Claude 프로필·합성 이미지·localhost 가짜 API로 다음을 확인했습니다. 사용자 계정·회사 자료·HCP 서버는 사용하지 않았습니다.

- 사용자 지정 전체 모델 ID로 새 작업자 실행
- 설정 이후 새 연결 전에는 이전 모델 사용 차단
- 합성 모델 404 → 정확한 네이티브 실패 후크 → HCP 백업 1회 → 주 모델 유지
- 백업 재사용 차단, 저장한 사용자 모델 유지
- Agent의 전체 모델 ID 직접 주입 거절 재현
- Read 전처리 후 이미지 블록 전달은 별도 [이미지 처리 기록](VISION_IMAGE_PREPROCESSING.md) 참조

실제 사내 모델의 접근 권한·이미지 이해·토큰·처리 시간은 운영에서 확인해야 합니다. 설정 저장이나 합성 API 성공만으로 운영 성공을 보증하지 않습니다.

모델 선택 구현 당시 회귀 검사 247개 중 **246개 통과, 1개 제외**였습니다. 제외된 것은 Windows 계정의 실제 symlink 생성 권한이 필요한 검사이며, reparse 경로 모의 검사는 통과했습니다. 실제 CLI 합성 흐름의 9개 판정도 모두 통과했습니다. 격리 실행 제한으로 요청 자체가 시작되지 않은 한 번은 성공으로 세지 않았고, 승인된 로컬 검증 환경에서 다시 확인했습니다.

통합 HTML은 Markdown·설치 사본 일치 검사를 통과했습니다. 독립 파일로 1440·768·390px 표시, 링크·선택 복사·인쇄 검사에서 외부 요청과 페이지 오류가 없었습니다. 새 입력 예문을 평소 모델 문맥에 모두 넣지 않고 사용자 안내서에만 담았습니다.

개발 회귀 검사: `test_vision_settings`, `test_vision_dispatch`, `test_vision_routing`, `test_vision_handoff`, `test_read_hook`, `test_read_hook_install`, `test_vision_image_preprocessing`, `test_image_review_efficiency`, `test_execution_contract`, `test_native_runtime`. 일상 업무에 실행하는 검증 단계가 아닙니다.
