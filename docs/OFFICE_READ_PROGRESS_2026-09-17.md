# 문서 읽기 준비·승인 대기 구분과 짧은 스킬 교정

상태: 1.4.14 소스·설치본에 포함. 기존 v1.4.13 태그·설치 ZIP과 운영 설치는 변경하지 않습니다. 운영 PC에는 같은 설치 범위로 업데이트 후 Claude Code를 다시 실행해야 적용됩니다.

## 관찰과 범위

운영 로그에서는 1회 교정 뒤 `company-agent:office-reader`가 정상 로드됐지만,
사용자는 별도 확인 창이 뜨기 전부터 오래 기다렸습니다. 따라서 그 시간을 전부
사용자 응답 대기나 Office 읽기로 해석할 수 없습니다. 개발 PC에서 실제 운영
PC의 보안 검사·모델·도구 권한 판정 지연을 재현하거나 원인을 확정한 것은 아닙니다.

## 변경

- 스킬 교정은 실행 미수행·정확한 호출·관련 스킬 없음 처리만 짧게 안내합니다.
  단일 후보이면 긴 카탈로그 경로를 중복 출력하지 않습니다. 1회 제한, 실제
  목록 비교, 중복 선택, 없는 스킬을 강제하지 않는 동작은 유지합니다.
- 문서 읽기 진입점은 Python 준비부터 짧은 단계 안내를 제공합니다. 중복 후보
  실행 경로는 다시 검사하지 않으며, 버전 확인 프로세스가 10초 안에 응답하지
  않으면 멈춥니다. 승인 절차나 기존 Python 선택·설치 범위를 바꾸지 않습니다.
- 확인 창의 실제 `Shown` 이벤트를 구분합니다. 시작 제한 30초가 지나면
  `confirmation_start_timeout`, 표시 후 300초 무응답이면
  `confirmation_wait_timeout`입니다. 둘 다 문서를 열지 않습니다.
- Office 실행·열기·권한 확인·내용 읽기·닫기·원본 확인을 구분합니다.
  보조 프로세스 전체 60초 제한은 그대로이며 타임아웃 시 마지막 단계를 반환합니다.
  사용자 Office나 전체 프로세스 트리를 강제 종료하지 않습니다.
- stdout은 결과 JSON을 유지하고 stderr만 짧은 단계 안내로 사용합니다.
  호스트가 stderr를 모아서 전달하면 실시간으로 보이지 않을 수 있습니다.
  최종 `diagnostics.progress`에는 고정된 단계 이름·밀리초만 추가합니다.
  원문·오류 원문·파일 경로를 진행 로그에 넣지 않고 별도 로그 파일도 만들지 않습니다.
- 추가 모델 호출·주기적 모델 확인·선택 기록 명령 없이 현재 명령 안에서 처리합니다.
  정상 Skill 로드·같은 본문 재사용은 기존 경로를 그대로 사용합니다.

## 시간 해석

`stageMs.bootstrap`은 진입점 시작부터 Python 준비까지, `runtime`은 Python 진입 후
설치·명령 준비입니다. 그 뒤 요청 검증, 확인 창 시작/응답, 원본 확인, Office
단계 시간이 이어집니다. `totalMs`는 관찰한 현재 실행 시간입니다. Claude 추론,
권한 분류기, 명령 시작 전 호스트 대기는 포함하지 않습니다. 따라서 이 변경을
사내 모델의 전체 실행 시간 단축이나 특정 DRM 지연 해결로 주장하지 않습니다.

## 검사

모의 보조 프로세스로 확인 창 시작/응답 대기, 읽기·닫기 정지, 큰 출력, 반복
표시 이벤트, 승인 신호 누락을 검사합니다. 실제 Windows PowerShell 진입점에서는
격리된 취소 전용 확인 도구로 UTF-8 단계 출력·JSON 보존·원본 보존을 검사합니다.
회사 문서나 실제 Office 앱은 이 검사에서 열지 않습니다.

2026-09-17 검증 결과:

- 1.4.14 버전 반영 후 전체 unittest 782개 통과(156.470초). 실제 Windows PowerShell 진입점과
  기존 Hook·스킬 목록·Office 읽기 회귀 검사를 포함합니다.
- `probe-skill-transport.py --scenario skip-list` 통과(4.28초).
  실제 Claude Code 호스트에서 최초 실행 1회 교정 → Skill 본문 로드 → 회복을
  확인했습니다. 응답은 로컬 모의 모델이므로 사내 HCP의 자율 선택 정확도나
  실제 문서 읽기 속도를 검증한 것은 아닙니다.
- `git diff --check` 통과. 승인 신호만 있거나 확인 창 표시 증거만 있는 경우는
  승인으로 처리하지 않습니다. 취소·시간초과 시 Office를 시작하지 않습니다.

1.4.14 설치 묶음 검증:

- 기본 외부 Python 설치 묶음 검사 통과. 새 `office_progress.py`, 업데이트 안내와
  이 검증 문서를 포함하고, Python 실행 파일·DLL이나 테스트용 개인 자료는 넣지 않습니다.
- 변경하지 않은 공개 1.4.13 ZIP에서 1.4.14 후보 ZIP으로 업데이트 검사 통과.
  실제 Claude 등록·일반 작업 폴더의 시작 Hook과 새 모듈·확인 창 스크립트의
  설치 캐시 해시 일치를 확인했습니다. 개인 Memory·Knowledge·Skill·모델·MCP·
  사용자 규칙과 입력 ZIP은 보존됐습니다. 격리된 임시 프로필만 사용했습니다.
- 설치 인코딩 검사 42개 항목 통과. CP949 부모 환경에서 한글·이모지 경로와
  실제 설치 전 확인을 검사했으며 사용자 운영 설치는 변경하지 않았습니다.
