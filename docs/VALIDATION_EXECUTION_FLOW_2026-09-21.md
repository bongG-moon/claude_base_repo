# 문서 읽기·후속 HTML 작업 수정 검증

검증일: 2026-09-21. 기준: v1.4.20 이후 수정이며 1.4.21에 포함합니다. 설치 ZIP·업데이트 검사 결과는 [1.4.21 배포 검증](https://github.com/bongG-moon/claude_base_repo/blob/main/docs/VALIDATION_RELEASE_1.4.21.md)을 참고하세요.

## 확인한 원인과 수정

| 확인한 문제 | 수정 |
| --- | --- |
| 정상 Office 명령 끝의 `2>&1` 때문에 현재 세션 보완·읽기 전용 분류가 빠짐 | 설치된 자기 Office 명령의 마지막 stderr 병합만 인식. 파일·범위를 보존하고 병합 앞에 누락된 연결 정보만 추가 |
| 스킬을 나중에 불러오면 바로 복사할 명령이 없는 경우 | 실제 회사 `office-reader` 본문 로드를 관찰한 직후 현재 설치 경로·대화 정보가 들어 있는 명령 전달 |
| JSON 항목 이름을 명령으로 실행하고 설치·세션을 재탐색 | 스킬 첫 실행 안내를 실제 문자열 중심으로 정리. 항목 이름 실행 실패 시 실제 현재 값을 안내하되 실행 결과·권한을 바꾸지 않음 |
| `TEST용`을 `TEST`로 잘못 바꾼 경로도 일반 오류로 표시 | `source_not_found`와 요청한 경로를 반환. 형식·범위·파일정보 확인 실패도 구분. 경로 자동 교정·인코딩/DRM 원인 추측 없음 |
| 이전 목록 읽기, 다른 스킬 로드, 두 번째 실행 시도가 HTML 준비를 대신함 | 현재 요청의 적합한 본문 기록 확인. 정확한 XLSX → HTML 후속 요청 재현 시험 추가 |
| 강화된 확인이 무관한 스킬을 강제할 가능성 | 부정·코드 진단 요청은 후보 참고만 제공. 원본 보존·외부 API 금지 조건은 정상 업무 선택을 유지. 실제 명시한 외부 스킬의 현재 로드 성공 존중 |
| 보완 지침을 나중에 읽으면 업무 본문 로드 기록을 잃을 가능성 | 요청별 최대 32개 본문 해시 기록 유지. 새 요청·문맥 초기화 때 초기화하며 본문을 보관하지 않음 |

## 유지한 경계와 비용

- 실제 문서 읽기 승인, 회사 정책, 파일·범위 제한, 명시한 다른 세션/저장소, 실제 권한 거절을 유지합니다.
- `2>&1` 인식은 일반 셸 허용이 아닙니다. 외부 실행 파일, 파이프, 출력 파일, 복합 명령, 중복 옵션은 자동 보완하지 않으며 자동 승인도 추가하지 않습니다.
- 추가 모델 호출·세션 파일 검색·별도 로그인·매번 목록 재검색은 없습니다. 모든 Read 앞에 새 후크를 붙이지 않습니다.
- 관련 스킬이 없거나 후보가 불명확하면 일반 실행을 막지 않습니다. 단일 후보를 잘못 찾은 예외에는 현재 요청의 선택/일반 실행 판단만 기록할 수 있습니다.
- 단순 읽기를 변경 작업으로 잘못 기록하지 않으며 새 Stop 검증 의무를 만들지 않습니다.
- Excel의 B2:E23처럼 원점이 A1이 아닌 범위, 제목·빈 행은 기존 고정 읽기 구현이 위치를 보존함을 확인했습니다. 모델의 임의 재추출을 권하지 않습니다.

## 검증

- 전체 회귀: 1,194개 실행, 1,189개 통과, 5개 제외, 실패 없음 (348.846초).
- 위 회귀 실행 중 마무리된 스킬 예외 처리: 최종 대상 시험 31개 통과. 파일 고정 후 스킬 계열 전체 183개 추가 재실행 통과 (94.316초).
- 최종 Office 연결 시험: 20개 통과 (11.060초). 가상 XLSX로 실제 Git Bash → PowerShell 실행 파일 → CLI를 거쳐 첫 호출이 `office_read_consent`에 도달하고, 승인 전에 Office를 열지 않음을 확인했습니다.
- 실제 임시 복사 설치 경로의 PowerShell 후크에서 스킬 로드 후 현재 플러그인 경로·세션·저장소가 담긴 명령이 전달되는지 확인했습니다.
- Office 요청 검증·Excel 고정 읽기 회귀, 지원 스킬·이전 본문 재사용·현재 요청 초기화·실제 회사 정책 거절·위험한 명령 문법 검증 포함.
- `office-reader` 스킬 형식 검사, 통합 가이드 재생성/동기화 검사, `git diff --check` 통과.
- 제외: Windows 심볼릭 링크 권한 관련 3개, 별도 신청 방식의 실제 Claude 설정/등록 시험 2개.

로컬 로그: `.smoke/execution-flow-regression-20260921.log`, `.smoke/office-context-final-20260921.log`, `.smoke/skill-flow-final-20260921.log`.

## 실제 환경에서 남은 확인

사내 HCP 모델, 실제 보호 문서, 회사 Office 프로그램으로 실행한 검증은 아닙니다. 위 소요 시간은 개발 테스트 시간이며 업무 응답 속도나 토큰 절감률을 뜻하지 않습니다. 일반 PowerShell에서 다른 PowerShell을 다시 감싸는 모든 셸 형태까지 보장하지 않으며, 운영 로그와 같은 Git Bash 호출 및 직접 실행 파일 호출을 검증했습니다.

새 배포본 설치 후 새 대화에서 아래 두 요청을 순서대로 확인합니다.

1. `@AI_CAMP_지원현황.xlsx 여기 파일 내용 읽고 어떤 정보들이 있는지 확인해줘`
   - `office-reader` 본문 → 현재 명령 → 파일·범위 승인 → 고정 읽기 → 실제 읽은 범위 요약.
   - 세션 환경변수·설치 폴더·도움말 탐색, 임의 pandas/xlwings 재작성으로 전환하지 않아야 합니다.
2. `위 내용을 바탕으로 신청자 현황과 강사 현황을 볼 수 있는 html을 만들고싶어`
   - `html-report` 본문을 새로 불러온 뒤 제작 절차로 진행해야 합니다.
   - 회사 자료의 사용 범위와 기존 스킬의 디자인 선택·산출물 전달 절차는 유지합니다.

본문 로드 기록은 모델이 지침 전체를 준수했다는 증명이 아닙니다. 실제 HCP에서 위 실행 흐름·실패 여부·모델 응답과 승인 대기 시간을 분리해 확인해야 합니다. 기존 설치본은 작업 복사본 수정만으로 바뀌지 않습니다.
