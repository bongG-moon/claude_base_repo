# Excel 업무 흐름도와 업무 맥락 집계 검증

검증일: 2026-10-22. 이번 요청 범위의 소스·배포 사본·안내서를 검증했습니다. 실제 직원 프로필이나 회사 세션을 수집하지 않았으며 설치·공개 배포·Release 게시를 수행한 기록은 아닙니다.

## 구현 범위

### Excel 업무 흐름도

- 기존 DATA / PROCESS / main.py 결과에 `업무흐름.html` 하나를 추가합니다. 최초 프로젝트 생성 시만 렌더링하고 일반 재실행에는 비용을 추가하지 않습니다.
- 실제 수식의 표 참조를 HTML 카드와 SVG 연결선으로 나타냅니다. Noto Sans KR 전체 글꼴과 OFL 라이선스를 내장해 외부 연결 없이 한글을 표시합니다.
- 의미 있는 표시 이름과 실제 분해된 표 ID를 함께 사용합니다. 실제 ID가 `s01_t01`이면 `교육 신청 현황 테이블 (s01_t01)`로 표시하며, 특정 ID 형식을 강제하거나 별도 별칭으로 변환하지 않습니다. 자동 이름은 시트·헤더 기반 제안이며, 모델이 이미 읽은 제한된 자료로 확인한 이름을 기존 plan의 `display_name`에 지정할 수 있습니다.
- 표 밖 참조, 상호 참조, 미지원·오류 수식, 미분석 VBA, 표시 상한을 드러냅니다. 생략된 연결 때문에 중간 표를 최종 결과로 잘못 표시하지 않습니다.
- 연결이 없는 표는 상세 목록에 유지하고 연결도와 구분합니다. 이 그림은 수식 의존성이지 실제 전체 업무·매크로 실행 순서를 복원한 결과가 아닙니다.

### 범용 업무 맥락 집계

- `standalone-skills/work-context-catalog`가 원본이며 Company Harness 없이 Python 표준 라이브러리로 실행할 수 있습니다. 배포용 사본은 `company-agent-plugin/skills/work-context-catalog`입니다.
- 지정한 여러 프로젝트·AI 프로필·관리 상태 폴더에서 Markdown 지침·스킬·기억·지식을 분류하고 출처를 기록합니다. Company Agent의 title/summary frontmatter 형식도 처리합니다.
- 설정은 파일의 존재만 확인합니다. 관리형 JSON 본문은 미지원으로 남깁니다. 아래 초기 검증 후 사용자 요청에 따라 세션 수집을 기본으로 변경했습니다. 현재 동작과 추가 검증은 아래 「세션 기본 수집 보완」을 참고하세요.
- 세션의 cwd는 이미 지정한 프로젝트에만 연결하고 다른 폴더를 따라가지 않습니다. 내용·세션·호출 식별자로 중복을 합치며 출처는 보존합니다.
- 출력은 `업무현황.html`과 재집계용 `catalog.json`입니다. 여러 직원이 각자 검토해 내보낸 catalog를 로컬에서 합칠 수 있습니다. 자동 업로드·중앙 수집·개인 평가 기능은 없습니다.
- 자산 정의, 설정 존재, 도구 호출 관찰을 구분합니다. 현재 업무 분류는 짧은 제목·설명·허용된 질문의 키워드에 따른 후보이며 전체 업무 절차의 의미 분석이나 성공률 판정은 아닙니다.
- 초기 구현의 상한은 파일 1,500개, 항목 10,000개, 깊이 8, 총 읽기 16MiB, MD 512KiB, 세션 2MiB, JSONL 한 줄 64KiB였습니다. 후속 보완에서는 세션을 앞부분만 읽지 않도록 별도 스트리밍 한도로 분리했습니다. 현재 한도는 스킬의 `references/collection.md`와 실행 결과 `coverage`에서 확인합니다.
- 도구 인수/결과·생각 과정·이미지를 출력하지 않습니다. 질문 원문은 기본 미포함, 별도 동의 때만 가림 발췌를 포함합니다. 자동 가림이 모든 개인정보나 기밀을 제거한다고 보장하지 않으므로 공유 전 검토가 필요합니다.

## 세션 기본 수집 보완

후속 요청에 따라 집계 스킬을 실행하면 세션도 기본 확인하도록 변경했습니다. 일반 업무마다 실행되는 후크는 추가하지 않았습니다.

- 현재 사용자의 알려진 Claude `projects`, Codex `sessions`·`archived_sessions`만 자동 발견합니다. `CLAUDE_CONFIG_DIR`·`CODEX_HOME`이 지정되면 그 위치를 우선하며, 잘못된 경로라고 다른 기본 프로필로 조용히 전환하지 않습니다.
- 명시한 `--profile-root`가 있으면 그 프로필만 사용합니다. `--no-auto-sessions`는 지정한 폴더만, `--no-sessions`는 문서만 집계합니다. `--catalog`만 합치는 실행은 현재 PC의 기록을 추가하지 않습니다.
- 세션 앞부분 2MiB 표본을 읽던 방식을 줄 단위 읽기로 교체했습니다. 큰 줄은 메모리에 계속 쌓지 않고 건너뛴 뒤 다음 줄을 확인하며, 일부 미확인을 표시합니다. 기본 총량 2GiB·20,000파일·줄당 1MiB·이벤트 처리 200,000개의 한도를 따로 둡니다.
- 중복 세션을 합친 뒤 인사·감사만 있는 대화, 빈 기록, 확인된 환경 문맥 전용 기록을 제외합니다. 짧은 요청·실패·이미지 전용·불명확한 기록은 보존합니다. 호출 결과와 감사 인사만 남은 불완전 기록도 단순 인사로 버리지 않습니다.
- 질문 발췌는 계속 별도 선택입니다. 로컬 파서가 필요한 이벤트만 집계하며 대화 전체·도구 인수·결과·이미지·생각 과정을 모델이나 보고서로 넘기지 않습니다. 별도 모델 호출은 없습니다.

## Excel 데이터·계산 설명 보완

단순 연결도 아래에 표의 데이터 항목·실제 Excel 열·입력/수식 혼합 여부, 대표 수식의 입력 참조와 결과 열·범위, 함수·연산의 한국어 설명을 추가했습니다. SUMIFS의 합계 범위와 조건 범위 등 주요 함수는 실제 인자의 역할까지 표시합니다. 반복 행 수식을 묶되 다른 상수·조건·고정 참조는 분리하고 비연속 행을 연속 범위로 표현하지 않습니다. 문자 상수·실제 행 값·계산값·캐시는 HTML에 싣지 않습니다. 원문 누락·미지원 분기·표시 한도는 별도로 표시합니다.

설명은 기존 분석 결과와 파서를 재사용합니다. 원본 재열기·모델 호출·상시 후크·일반 재실행의 보고서 생성은 추가하지 않았습니다. 제한은 전체 설명 대상 수식 20,000개, 표별 40열·16묶음이며 생략 범위를 표시합니다. 16개 표·6,798개 수식 예제에서는 36개 설명 묶음을 만들었습니다. 독립 검토의 구조·HTML 생성 합계는 약 0.30초였으며 원본 분석·전체 업무 시간은 제외한 단일 로컬 측정입니다.

최종 검증은 Excel 전체 회귀 **268개**, 설치 사본 통합 **15개**, 안내서 계약 **21개**로 합계 **304개 통과**했습니다. 일부 최초 실행의 임시 폴더 접근 거절은 정상 테스트 환경에서 재실행했습니다. 사용자 설정·Office 권한은 바꾸지 않았습니다.
