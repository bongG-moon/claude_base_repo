배포 시험 중 Windows PowerShell의 한글 파일명 해석 때문에 Workspace ZIP에서 호환 안내 2개가 빠지는 문제를 찾아 빌드 스크립트 인코딩을 수정했습니다. 최종 ZIP은 필수 항목 집합과 바이트 일치를 다시 통과했습니다. 격리 업데이트 자체 검증은 통과했으나 첫 실행의 긴 경로 정리 과정에서 오류가 발생해, 시험용 `-KeepArtifacts` 옵션으로 임시 결과를 보존하고 다시 실행하여 종료 코드 0을 확인했습니다. 실제 사용자 설정은 변경하지 않았습니다.

## 검증 범위와 한계

- 통합 가이드는 온보딩·업무 예문·하네스 설명·Claude Code 명령·선택적 Cua 안내를 한 HTML에 담습니다. 처음 화면·가상 자료 생성 실습·모바일 명령어 화면을 직접 확인했으며 45개 절의 모든 문장을 시각 검수한 것은 아닙니다. 자세한 기록은 [통합 가이드 검증](VALIDATION_UNIFIED_GUIDE_2026-09-19.md)을 참고하세요.
- 가상 자료 생성 프롬프트는 기존 PPT·이미지 없이 시작하도록 설계했습니다. 실제 사내 모델에 모든 예문을 전송하여 성공률을 측정한 것은 아닙니다. Office가 없는 PC는 MD·HTML 실습까지 진행할 수 있습니다.
- Workspace 브라우저 시험은 실제 앱/API와 격리 가상 CLI를 사용했습니다. Cua 상태는 합성 자료이며 실제 화면 제어 시험이 아닙니다.
- 편집형 HTML-first PPT는 로컬 Chrome 측정과 실제 PowerPoint 렌더링을 확인했습니다. 카드·텍스트 등의 실제 변환·시각 검사는 [PPT 검증](VALIDATION_PPT_NATIVE_HTML_2026-09-19.md)에 분리해 기록했습니다. HTML의 모든 효과가 동일하게 재현되지는 않으며 특정 Edge 빌드의 빈 DOM 출력은 운영 PC 확인이 필요합니다.
- 실제 HCP 자동 스킬 적용, 계정 인증, DRM Office, 회사 MCP 및 Cua 연결은 운영 환경에서 추가 확인해야 합니다. 발견된 파일·설정을 실제 적용 성공으로 보고하지 않습니다.

업데이트는 기존과 같은 User/Project 범위에서 실행하고 Claude Code를 다시 시작합니다. Workspace는 기존 앱의 전원 버튼으로 종료한 뒤 새 0.5 ZIP을 별도 폴더에 풀어 실행합니다.
