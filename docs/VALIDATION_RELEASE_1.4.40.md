# Company Harness 1.4.40 배포 검증

검증일: 2026-10-12. 이미지 읽기의 잘못된 일반 작업자 인계와 자기 메시지 반복을 수정한 하네스 배포입니다. 사내 HCP 모델·회사 문서·실제 개인 프로필은 시험에 사용하지 않았습니다. 별도 Workspace 앱·Computer Use MCP·실습 자료 변경은 제외했습니다.

## 소스와 회귀 시험

- 명시적 파일 목록으로 Git index를 구성하고 `core.autocrlf=false archive`로 배포 소스를 분리했습니다. 소스 624개 파일의 바이트를 Git 객체와 비교했으며, 검증 기록 추가 전 선택한 27개 이외 597개는 기존 HEAD와 같습니다. 새 검증 기록도 별도로 포함합니다.
- 대표 자격증명·개인키 패턴 검사와 staged whitespace 검사를 통과했습니다. 패턴 검사가 모든 비밀정보 부재를 보증하지는 않습니다.
- 최종 소스에서 비전 인계·Read 후크·런타임·컨텍스트·안내서·설치 EXE·GitLab 준비 회귀 시험 **185개가 110.854초에 통과**했습니다. 실제 회사 업무의 소요 시간이나 토큰 절감 수치는 아닙니다.
- 누락된 작업자 종류의 보완은 같은 대화·폴더·현재 유효한 대상 경로와 비전 인계 의도가 맞을 때만 적용합니다. 다른 작업자·재개·자식 호출은 변경하지 않습니다. 새 사용자 요청·만료·경로 접두어·잘못된 입력·중복 인계·자기 메시지를 시험했습니다.
- 일반 텍스트 읽기와 무관한 Agent 호출의 빠른 경로, 메인 모델·기존 승인 보존, 단순 읽기의 workFile 불필요, 전체 전사 요청 처리 지침을 확인했습니다. 안내서는 6개 부분·52개 장·424,469바이트이며 생성 결과와 설치 사본이 일치합니다.

첫 166개 배포 소스 시험에서는 업무팩 안내의 이전 버전 표기 1건이 실패했습니다. 현재 버전으로 수정하고 최종 185개 전체를 재실행했습니다. 빌드의 Python 구문 검사는 긴 캐시 경로에서 한 번 실패하여 같은 Git 소스를 짧은 빌드 경로로 옮겨 통과했습니다. 제품 코드나 검증 조건을 완화하지 않았습니다.

## 실제 설치 파일과 업데이트 시험

- 직원 ZIP 빌드에서 Claude 플러그인 strict 검사·회사 지식 검증·Python 구문 검사를 생략하지 않았습니다. 기본 외부 Python 방식이며 의존성을 내려받거나 설치하지 않았습니다.
- ZIP manifest의 229개 파일·크기·SHA-256을 전부 검증했습니다. manifest 자체를 포함해 230개 파일입니다. 새 `vision_handoff.py`, 라우팅·진입 코드·작업자·후크·안내서가 소스와 일치합니다.
- EXE의 `--verify-only`가 실제 내장 ZIP 추출과 무결성 검증을 통과했습니다. GitLab 준비 도구에서도 EXE 내장 ZIP이 승인 ZIP과 같음을 확인했습니다.
- 격리 프로필에서 실제 1.4.39 ZIP 설치 후 최종 1.4.40 ZIP으로 업데이트했습니다. 개인 기억·스킬·지식·CLAUDE.md·MCP·모델·다른 플러그인 설정, 260자 초과 스킬 경로의 원본과 백업, 이전 ZIP 보존을 확인했습니다.
- 새 플러그인 등록·소스 파일·Read 후크의 정확한 실행 경로를 확인하고 `claude --init-only`에서 SessionStart 한 번 실행을 검증했습니다. 모델 요청은 하지 않았습니다.

업데이트 시험의 이전 가정 두 가지도 바로잡았습니다. 설치 시 `hooks.json`의 Read 실행 명령·인자는 정상적으로 변경되므로 전체 JSON의 예상 변경만 정확히 비교합니다. Claude 등록의 캐시 폴더와 관리 배포 폴더를 구분하여 후자의 `read-hook.cmd`를 확인합니다. 이 보완 후 업데이트 시험이 통과했으며 설치 제품 코드는 바꾸지 않았습니다.

## 운영 환경에서 남은 확인

사내 게이트웨이의 실제 `HCP-Vision-Latest` 요청·이미지 응답은 사용자가 운영 환경에서 확인합니다. 작업자 이름만으로 모델 호출 성공을 판정하지 않습니다. 이미지의 실제 내용과 결과를 비교한 뒤 텍스트 후속 작업이 기존 메인 모델에서 계속되는지 확인합니다. 구체적인 순서는 [운영 시험 안내](UPDATE_1.4.40.md#운영-환경에서-확인하기)를 참고하세요.

입력창에 직접 붙인 이미지나 이름만으로 구분할 수 없는 모든 MCP 이미지 응답은 자동 인계 범위가 아닙니다. 실제 권한 거절을 우회하지 않으며 비전 실패는 확인하지 못한 범위로 보고해야 합니다. 기존 PC는 자동 업데이트되지 않고 별도 앱은 이번 설치 파일로 갱신되지 않습니다.
