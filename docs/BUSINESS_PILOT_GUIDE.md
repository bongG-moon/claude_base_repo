# Company Agent 업무팩 시범 사용 안내

업무 시범 안내 · 배포 준비 버전 1.4.24 (Release 초안)

**적용 범위:** 이 안내서는 1.4.24를 기준으로 설명합니다. 기본 Office Reader 제거와 학습·스킬 선택 보완은 유지하고 단독 사용자 안내서를 갱신합니다. 기존 Release·ZIP·설치된 PC는 자동으로 바뀌지 않으며, 실제 사용할 수 있는 기능은 업데이트 후 설치 버전과 연결된 도구를 먼저 확인합니다. [변경 내용](UPDATE_1.4.24.md)과 [검증 범위](https://github.com/bongG-moon/claude_base_repo/blob/main/docs/VALIDATION_RELEASE_1.4.24.md)를 참고하세요.

이 안내서는 코딩을 하지 않는 직원이 **파일 정리, 메일 확인, HTML 보고서, PPT 만들기**를 시작하는 방법을 설명합니다. Claude에 하고 싶은 일을 말하면 필요한 것만 질문하고, 준비된 도구로 진행하는 방식입니다.

공개 배포 현황은 [Release 목록](https://github.com/bongG-moon/claude_base_repo/releases)에서 확인합니다. 1.4.24는 아직 일반 공개 다운로드가 아닌 초안입니다. 직원은 담당자가 검토·승인한 배포본을 받습니다. 폐쇄망에서는 회사에서 승인한 전달 경로를 사용하세요. 회사 Office·Outlook과 사내 모델을 연결한 실제 업무 검증은 별도로 필요합니다. 시범 사용에서는 승인된 연습 자료나 복사본으로 먼저 확인하세요.

## 1 처음에 무엇을 하면 되나요

이미 Company Agent를 사용 중이라면 Claude를 다시 설치하거나 모델을 다시 설정할 필요는 없습니다.

1. 회사 담당자가 제공한 승인 ZIP의 버전과 시범 범위를 확인합니다. 현재 공개 버전은 1.4.23이며 후속 시험본은 담당자가 별도로 지정합니다. Workspace를 사용한다면 별도 0.8 묶음을 함께 적용합니다.
2. 작업을 저장하고 Claude Code를 닫습니다.
3. ZIP **전체를 새 폴더에 압축 해제**합니다. 설치 파일 한 개만 옮기지 마세요.
4. 압축을 푼 폴더의 최상위 `Install-CompanyAgent.cmd`를 평소처럼 더블클릭합니다.
5. 이전에 **Claude 전체**로 설치했다면 같은 선택을, **이 프로젝트만**이었다면 같은 프로젝트 폴더를 선택합니다.
6. **Company Agent 업데이트** 화면에서 기존 버전과 전달받은 새 버전을 확인하고 진행합니다. 같은 버전은 다시 적용/복구이며 일반 설치로 더 낮은 버전으로 내리지 않습니다. 모르는 경로나 계정이 나오면 임의로 고르지 말고 담당자에게 확인합니다.
7. 업데이트 완료와 개인 자료·백업 위치를 확인한 뒤 Claude Code를 다시 엽니다.

같은 설치 범위의 정상 업데이트에서는 기존 개인 기억, 지식, 스킬, 선호와 학습 내역을 유지합니다. 모델이나 기존 회사 연결 도구도 이 업무팩을 위해 초기화하지 않습니다. 일반 업데이트를 하려고 ‘기존 하네스 교체’를 대신 선택할 필요가 없습니다.

이제 **Claude가 답하는 대화 입력줄**에 다음을 입력하세요. Windows의 `PS C:\...>` 명령줄에 입력하는 명령이 아닙니다.

```text
/company-agent:business-check
```

명령을 외우지 않아도 됩니다.

```text
파일 정리, 메일 확인, HTML 보고서, PPT 만들기 중
이 PC에서 무엇을 사용할 수 있는지 먼저 확인해줘.
추가 준비가 필요한 것은 담당자에게 물어볼 말로 설명해줘.
프로그램을 내려받거나 계정을 새로 연결하지는 말아줘.
```

이 점검은 모든 실제 업무가 성공했다는 시험 성적표가 아닙니다. Python, Office, 연결 도구 등 지금 확인할 수 있는 준비 상태와 별도로 시험해야 할 부분을 알려줍니다. 질문이 나오면 폴더, 계정, 디자인, 분량처럼 필요한 선택에만 답하면 됩니다.

## 2 폴더 안의 파일을 먼저 살펴보고 정리하기

### 이렇게 부탁하세요

```text
이번 달 업무자료 폴더를 종류별로 정리하고 싶어.
대상 폴더를 내가 고를 수 있게 해줘.
어떤 파일을 어디로 옮길지 먼저 보여주고, 확인 후에만 실행해줘.
하위 폴더와 원본 내용은 건드리지 말고 삭제·덮어쓰기는 하지 말아줘.
```

### 실제 진행 순서

먼저 지정한 폴더 바로 아래 파일을 확인하고, 다음처럼 **정리안만** 만듭니다.

| 파일 종류 | 만들어 사용할 하위 폴더 |
| --- | --- |
| PDF·Word·텍스트 등 | 문서 |
| Excel·CSV 등 | 표자료 |
| PowerPoint | 발표자료 |
| 사진·그림 파일 | 이미지 |
| ZIP·7z | 압축자료 |

정리안을 확인한 뒤 실행을 요청하면 별도의 Windows 확인 창이 나옵니다. **직접 확인하고 승인해야 파일이 이동합니다.** Claude가 대신 승인했다고 적는 것으로 실행하지 않습니다. 취소하거나 확인을 끝내지 않으면 이동하지 않습니다.

### 지원하는 정리 범위

- 한 폴더 바로 아래의 항목이 **500개 이하**여야 합니다. 하위 폴더까지 계속 훑는 정리는 하지 않습니다.
- 정해진 파일 종류를 같은 업무 폴더 안의 분류 폴더로 옮깁니다. 날짜·프로젝트명·본문 의미별 자유 분류는 아직 기본 실행 기능이 아닙니다.
- 삭제나 덮어쓰기를 하지 않습니다. 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 제외하거나 실패로 알려줍니다.
- 계획을 만든 뒤 파일이 바뀌었으면 그대로 이동하지 않고 새 확인을 요청합니다.
- 드라이브 전체, 사용자 홈 전체, Windows·프로그램·Claude 설정 폴더는 대상으로 삼지 않습니다. 네트워크 폴더나 연결된 바로가기 폴더도 이 시범 범위에서 제외합니다.
- 256 MiB보다 큰 파일이나 접근할 수 없는 파일 등은 제외할 수 있습니다. 처리한 파일과 처리하지 못한 파일을 구분해서 확인하세요.

이 기능은 문서 본문을 이해해서 분류하는 것이 아니라 파일 종류를 기준으로 분류합니다. 계획에는 파일 이름, 이동 위치와 파일 변경 확인 정보가 기록됩니다. 내용을 요약해서 개인 기억에 쌓는 작업은 아닙니다.

### 되돌리고 싶을 때

```text
방금 Company Agent로 정리한 파일을 원래 위치로 되돌리고 싶어.
기록을 확인해서 되돌릴 수 있는 파일을 먼저 알려줘.
다른 파일을 덮어쓰거나 지금까지 추가로 바꾼 내용을 지우지는 말아줘.
```

이 도구가 이동한 기록을 바탕으로 다시 확인 창을 거칩니다. 이동 후 바뀐 파일, 원래 위치에 같은 이름이 생긴 파일 등은 자동으로 덮어쓰지 않습니다. 이 되돌리기는 **해당 파일 이동 작업만** 대상으로 하며, 다른 프로그램의 수정이나 메일 발송을 취소하지 않습니다.

## 3 내 Outlook 메일을 확인하고 요약하기

### 이렇게 부탁하세요

```text
내 Outlook에서 이번 주 받은 메일 중 오늘 대응해야 할 것을 요약해줘.
사용 가능한 내 계정과 메일함을 먼저 확인하고,
요청사항·기한·내가 해야 할 일로 정리해줘.
본문과 첨부 중 무엇을 실제로 읽었는지 구분해서 알려줘.
지금은 읽기만 하고 보내거나 이동하거나 삭제하지 말아줘.
```

기존 회사 메일 도구인 `corp-outlook-self`를 우선 사용합니다. 이미 연결되어 있다면 같은 연결을 계속 쓰며, Company Agent가 임의로 다른 메일 연결로 교체하지 않습니다.

해당 도구가 없을 때는 회사에서 허용하는 경우에 한해 **실행 중인 Classic Outlook의 읽기 전용 조회**를 사용할 수 있습니다. Outlook 2016 같은 기존 데스크톱 환경을 위한 선택적인 보조 기능이며, 실제 회사 PC의 동작 확인이 필요합니다. 새 Outlook이나 웹메일에서 동일하게 동작한다고 가정하지 마세요.

이 보조 조회는 현재 Outlook 프로필의 계정·메일함 연결을 확인합니다. 사번이나 실제 사람의 신원을 증명하거나 회사의 발신자 제한을 대신하는 기능은 아닙니다. 조회할 본인 계정과 메일함을 좁혀 선택하며, 본문 읽기는 회사에서 허용한 범위가 확인된 경우에만 사용합니다.

본문을 읽기 전에는 실제 Windows 확인 창이 나옵니다. AI 처리가 허용된 메일인지 본인이 확인하고 승인해야 합니다. 이 확인이 회사의 권한 허가를 새로 만들어 주는 것은 아닙니다. 허용된 본문을 읽으면 현재 Claude 대화에 전달되므로 **Claude 자체 대화 기록에는 남을 수 있습니다.** 하네스의 별도 개인 기억·지식으로 저장하지 않는다는 설명을 ‘어디에도 기록되지 않는다’는 뜻으로 받아들이면 안 됩니다.

### 범위를 좁혀야 할 때

한 번에 모든 메일을 읽지 않습니다. 결과가 일부라고 나오면 “지난 일주일, 받은 편지함만”처럼 기간과 폴더를 좁히세요. 읽지 않은 범위까지 확인했다고 보고하지 않습니다. 보조 조회는 첨부파일을 자동 다운로드하거나 내용을 추출하지 않습니다.

### 검색 결과를 해석하는 방법

- “최근 3일”은 별도 설명이 없다면 현재 시각부터 지난 72시간으로 보고, 실제 검색 기간을 함께 알려줍니다. 달력 날짜 기준을 원하면 “9월 8일부터 11일까지”처럼 말하세요.
- 날짜에 시간대가 빠졌다면 PC의 해당 날짜 기준 현지 시간대를 사용하고 그 사실을 알려줍니다. PC 시간대가 잘못 설정되어 있다면 담당자에게 확인하세요. 직접 날짜 코드를 작성할 필요는 없습니다.
- 기간 형식이 잘못되면 날짜를 수정하도록 안내합니다. 이를 계정 연결이나 PST 문제로 바꾸어 설명하거나, 계정·검색 범위를 임의로 바꿔 재시도하지 않습니다.
- 이 보조 검색은 **제목과 발신자**를 찾습니다. 메일 본문 전체 검색은 아닙니다. `AX TF`와 `AX-TF`처럼 표기가 다르면 결과가 다를 수 있습니다.
- 결과 개수, 확인한 메일 수, 폴더 수 또는 시간 제한에 걸리면 일부만 검색했다고 표시합니다. 보호되거나 접근하지 못한 항목도 구분합니다. 일부 검색에서 0건이라고 나와도 전체 메일함에 없다고 단정하지 않습니다.
- Outlook 연결 확인은 계정·메일함 정보를 확인했다는 뜻입니다. 실제 메일 검색이나 본문 읽기까지 성공했다는 뜻은 아닙니다. 서버 전체 메일을 빠짐없이 조회했다고 보장하지도 않습니다.

같은 업무에서 이미 고른 본인 계정과 검색 범위를 불필요하게 다시 묻지 않도록 안내를 보완했습니다. 본문은 선택한 메일 최대 20건을 한 번의 확인 창으로 묶어 읽을 수 있습니다. 다만 다른 메일이나 작업으로 범위가 바뀌면 다시 확인하며, 회사 정책과 Claude 자체 권한 확인은 유지합니다.

### 본문은 읽었는데 첨부가 막혔다면

다음과 같이 부분적으로 완료되었다고 알려주는 것이 정상입니다.

> 메일 본문은 확인했지만 첨부파일은 보호 설정 때문에 분석하지 못했습니다. 첨부 내용은 제외하고 요약했습니다.

본문이 허용되었다고 첨부까지 허용된 것은 아닙니다. 제목·본문·첨부의 실제 확인 범위를 구분하고, 읽지 못한 첨부의 내용을 추측하지 않습니다. 첨부 다운로드 기능이 없는 경우와 보호 때문에 거부된 경우도 구분합니다.

### 보내기와 오래된 메일 보관은 별개입니다

```text
오래된 메일을 별도 PST 보관 파일로 정리하고 싶어.
어느 기간과 폴더가 대상인지 먼저 물어보고 보관 계획만 보여줘.
기존 회사 도구가 PST 만들기와 메일 이동을 지원하는지 확인해줘.
내 확인 없이 실제로 옮기거나 삭제하지는 말아줘.
```

PST는 Outlook의 별도 메일 보관 파일입니다. **이 시범 업무팩에는 새 메일 발송이나 PST 생성·이동을 처리하는 연결 기능을 새로 넣지 않았습니다.** 기존 승인 회사 도구가 해당 기능을 지원하면, 그 도구의 권한과 승인 절차를 따릅니다. 없으면 ‘해당 기능의 회사 연결이 필요합니다’라고 알려주고 멈춥니다.

읽기 전용 보조 기능은 이미 Outlook에 열려 있고 본인이 조회 대상으로 선택한 PST를 읽을 수 있을 뿐입니다. PST를 새로 만들거나 연결하거나, 메일을 옮기거나 지우지 않습니다. 메일을 보내려면 기존 회사 도구에서 본인 발신 계정·수신자·내용·첨부를 확인한 뒤 별도로 승인해야 합니다.

## 4 분위기와 읽는 방식을 고르는 HTML 보고서

### 이렇게 부탁하세요

```text
이 실적 자료로 팀장님이 볼 HTML 보고서를 만들어줘.
핵심 결과와 주의할 점이 잘 보이면 좋겠어.
디자인을 쉽게 설명해 주고 2~3개씩 고를 수 있게 해줘.
5분 정도 읽는 분량으로 생각하고 있어.
페이지를 넘겨 볼지 아래로 스크롤할지도 먼저 물어봐줘.
```

자료, 독자, 포함할 내용부터 확인한 뒤 모양과 분량을 고릅니다. 이미 요청에 답이 들어 있으면 같은 질문을 반복할 필요는 없습니다. 이름을 모르면 “회사 보고용으로 단정하게 추천해줘”라고 말해도 됩니다.

| 분위기 | 쉬운 설명 |
| --- | --- |
| 미니멀리즘 | 장식을 줄이고 핵심을 또렷하게 |
| 에디토리얼 | 잡지나 기사처럼 글의 흐름을 강조 |
| 벤토그리드 | 내용별 카드가 한눈에 보이게 |
| 글래스모피즘 | 반투명 유리판 같은 느낌 |
| 브루탈리즘 | 굵은 선과 강한 대비로 눈에 띄게 |
| 뉴모피즘 | 부드러운 그림자로 살짝 입체감 있게 |
| 그라디언트 메시 | 여러 색이 자연스럽게 섞이는 배경 |
| 자유양식 | 자유양식용 기본 스타일로 내용 구성을 시작 |

읽는 방식은 **아래로 스크롤**, **발표처럼 페이지 넘김**, **둘 다** 중 선택합니다. 자유양식도 현재는 준비된 기본 스타일을 사용하며 세밀한 색·글꼴·배치 편집은 별도 확인이 필요합니다. 모든 웹사이트나 첨부 디자인을 똑같이 복제한다는 뜻은 아닙니다.

승인된 Python의 기본 기능으로 HTML을 만듭니다. 웹사이트에 게시하거나 외부 서비스를 연결하지 않고, 결과 파일을 브라우저에서 열어 인터넷 없이 볼 수 있습니다. 파일을 받으면 숫자·출처·문장 잘림·슬라이드 넘김을 확인하세요. 실제 편집은 “두 번째 부분을 더 짧게 해줘”처럼 수정 요청으로 진행할 수 있습니다.

## 5 참고 PPT 분위기로 편집 가능한 발표자료 만들기

### 이렇게 부탁하세요

```text
이 참고 PPT의 색과 배치를 참고해서 6장 발표자료를 만들어줘.
팀 회의에서 사용할 자료이고, 내가 나중에 문구를 바꿀 수 있어야 해.
현재 연결된 도구로 참고 파일을 읽을 수 있는지와 PPT 제작 준비 상태를 확인해줘.
목차와 각 장의 내용을 정하고 HTML 초안을 먼저 보여준 뒤 PPT로 만들어줘.
사진이 필요하면 연결된 승인 이미지 도구가 있는지도 확인해줘.
```

첫 질문에서는 독자, 목적, 장수, 참고 파일, 저장 위치처럼 필요한 정보만 확인합니다. 참고 파일은 수정하지 않고 새 결과 파일을 만듭니다.

### 어떻게 비슷하게 만드나요

현재 참고 파일은 `.pptx` 형식입니다. 페이지 수, 글상자·표·그림이 있는지, 기본 틀과 페이지 크기를 확인하고, 원본 테마와 기본 틀을 재사용하여 새 내용을 배치합니다. 참고 원본의 예시 페이지를 그대로 결과에 남기는 것이 아닙니다. 읽기·변환이 보호 설정 때문에 막히면 다른 경로로 추출하지 않습니다.

**원본의 모든 페이지를 자동 이미지화하고 그 화면의 색·배치를 추론하여 재구성하는 기능은 아직 기본 실행 흐름에 없습니다.** 허용된 별도 참고 이미지가 있다면 요청에 참고 자료로 제공할 수 있지만, 이것이 원본 자동 복제를 보장하지는 않습니다. 생성 결과의 이미지 미리보기는 PowerPoint가 있을 때 시도합니다. 이미지 미리보기를 만들지 못했으면 PPT 파일 생성 여부와 미리보기 실패를 따로 알려줍니다.

그 뒤 **제목·본문은 글상자, 표는 표, 숫자 그림은 차트**처럼 편집할 수 있는 요소로 새로 구성합니다. 참고 슬라이드를 사진 한 장으로만 붙이는 것과는 다릅니다. 사진이나 생성 이미지 자체는 이미지이므로, 그 속의 모든 글자·물체가 자동으로 편집 가능한 PPT 요소가 되는 것은 아닙니다. 복잡한 도식·특수 개체까지 자동으로 재구성하는 기능은 현재 범위에 없습니다.

### 어떤 준비물이 필요한가요

승인된 Python과 설치된 데스크톱 PowerPoint를 사용할 수 있습니다. 이미 `python-pptx`라는 PPT 제작 도구가 준비돼 있다면 그 경로도 사용할 수 있습니다. **`python-pptx`가 없다고 반드시 인터넷 설치가 필요한 것은 아닙니다.** PowerPoint가 있으면 Office를 사용하는 경로를 확인합니다. 어느 쪽도 준비되지 않았으면 필요한 준비물을 안내하고 목차·원고 수준에서 멈춥니다.

회사의 PowerPoint 설치 방식, 폰트, 보안 설정에 따라 결과가 달라집니다. 현재 **실제 회사 Office에서 제작하고 열어 편집하는 통합 검증은 완료되지 않았습니다.** 시험 결과를 보기 전에는 완성 품질, 원본 디자인의 완전 복제, 모든 도형의 변환을 보장하지 않습니다.

### 이미지 생성 도구가 없으면요

새 외부 이미지 생성 API를 자동 연결하지 않습니다. 이미 연결된 승인 이미지 도구가 있고 그 자료의 이용이 허용되면 스킬이 해당 도구를 사용할 수 있습니다. 도구가 없거나 일반적인 생성 장애가 나면 표·도형·텍스트 중심으로 바꿀 수 있습니다.

이 대체는 이미지 도구 부족에 대한 대체입니다. **보호된 참고 자료를 다른 프로그램이나 이미지 생성 도구에 보내 다시 읽는 대체는 하지 않습니다.** 결과를 받으면 내용 정확성, 슬라이드 잘림, 글자·표·도형 편집 여부를 직접 확인하세요.

## 6 보호된 자료 때문에 막혔을 때

DRM은 회사가 문서의 열기·복사·출력 등을 제한하는 보호 설정입니다. 정상적으로 보이는 자료도 AI 읽기나 다른 파일로 내보내기가 허용되지 않을 수 있습니다.

Company Agent는 보호 신호나 권한 제한을 확인하면 **해당 항목만 멈추고**, 허용된 다른 항목을 계속 처리할 수 있습니다. 결과에는 완료한 것, 제외한 것, 담당자 확인이 필요한 것을 나누어 알려줍니다.

- 차단된 자료를 캡처·OCR·다른 앱·확장자 변경·보호 해제로 우회하지 않습니다.
- 보호된 원문과 추출 내용은 개인 Memory·Knowledge·자동 학습 자료로 저장하지 않습니다.
- 차단된 첨부의 내용을 본문이나 파일 이름만 보고 추측하지 않습니다.
- 회사가 허용한 새 자료를 받거나 담당자가 권한을 확인하기 전까지 같은 제한을 반복 재시도하지 않습니다.

```text
보호 때문에 막힌 부분은 우회하지 말고 제외해줘.
실제로 읽은 내용만으로 가능한 결과를 만들어줘.
무엇을 제외했는지와 담당자에게 확인할 내용을 짧게 알려줘.
제한된 원문은 개인 기억이나 학습 자료로 저장하지 말아줘.
```

모든 사내 DRM 제품의 상태를 이 프로그램이 완벽히 판별하는 것은 아닙니다. Outlook의 메일 보호 상태 확인도 외부 첨부 DRM의 허용을 증명하지 않습니다. 실제 사내 정책과 도구에서 허용한 범위를 기준으로 사용해야 합니다.

## 7 문제가 있으면 이렇게 알려주세요

### 학습은 업무를 마무리할 때 합니다

Outlook 연결 확인 → 기간 선택 → 검색 → 요약 → 결과 수정은 보통 **하나의 메일 업무**입니다. 각 단계마다 학습을 완료하라는 안내를 보여주는 대신, 중간에는 계속 쓸 만한 수정 요구만 짧게 모아 두고 업무 완료 시점에 검토하도록 변경했습니다.

단순 조회나 배울 내용이 없는 질문은 학습 검토를 생략합니다. 승인 대기·작업 중단·완료가 불명확한 상태는 학습 완료로 간주하지 않습니다. ‘앞으로 이렇게 해줘’, ‘기억해줘’ 같은 명시적 요청은 기다리지 않고 별도로 반영할 수 있습니다.

정상적인 마지막 답변에는 요청한 업무 결과를 보여줍니다. 내부 학습 접수 메시지나 ‘코드를 바꾸지 않아서 검증 실패’ 같은 설명으로 끝내지 않습니다. 반대로 일부 메일을 읽지 못한 사실이나 파일 이동 확인 등 중요한 안내는 생략하지 않습니다. 학습 내역이 궁금할 때만 “최근 배운 내용을 보여줘”라고 요청하면 됩니다. Claude Code 자체 도구 실행 표시까지 모두 숨기는 기능은 아닙니다.

학습을 미뤄도 파일 이동·생성 결과 확인과 필요한 승인은 작업 직후 유지합니다. Claude를 닫은 뒤 별도 프로그램이 계속 학습한다는 뜻도 아닙니다.

명시적 저장은 개인 전체/이 프로젝트 중 선택한 범위를 따르지만 자동 학습은 현재 활성 설치의 저장소를 사용합니다. User 설치에서 프로젝트에 기억 하나를 저장했다고 이후 자동 학습이 그 프로젝트로 옮겨지지 않으며, User 설치의 별도 프로젝트 자산을 자동 수정하지 않습니다. 스킬은 작업 지침이고 후크는 정해진 실행 시점의 안내·검사·기록입니다. 설치나 목록 표시만으로 외부 도구 권한이나 업무 성공을 보장하지 않습니다.

시작할 때 Skill 경고가 나면 `/company-agent:skills`에서 출처와 현재 선택을 확인하세요. 정상 선택된 중복과 서로 다른 호출명으로 공존하는 항목은 반복 경고 대상이 아닙니다. 실제 미해결 선택, 사라진 선택, 읽기 실패는 구분해서 안내합니다. 기존 스킬 파일을 지우거나 설치를 초기화할 필요는 없습니다.

업무팩 오류는 다음처럼 전달하면 됩니다.

```text
파일 정리 / 메일 / HTML / PPT 중 어떤 작업인지:
내가 요청한 내용:
실제로 완료된 부분:
실패한 부분과 오류 문구:
현재 Company Agent 버전:
```

메일 원문, 첨부 내용, 비밀번호, 인증정보를 오류 신고에 그대로 붙이지 마세요. 원인을 확인하기 위해 업무 자료 전체를 지울 필요도 없습니다.

## 8 담당자용 확인 목록

직원은 아래 이름을 외울 필요가 없습니다. 개발·운영 담당자가 지원 범위를 확인할 때 참고합니다.

사용자 진입 명령은 `/company-agent:business-check`입니다. 내부 실행 항목은 `business doctor`, `files-plan`, `files-execute`, `files-undo`, `html`, `ppt`, `ppt-inspect`, `mail-search`, `mail-read`, `mail-capabilities`입니다. 실제 호출은 현재 설치가 안내하는 실행 경로를 사용하며, 직원에게 Python 경로나 내부 자료 형식을 직접 조합하게 하지 않습니다.

시범 검증에는 다음 항목을 포함합니다.

- 파일 정리: 정리안만 생성, 확인 창 취소, 본인 승인 후 이동, 같은 이름 충돌, 변경된 파일 거부, 일부 실패 표시, 제한된 되돌리기.
- HTML: 10가지 분위기, 추가 디자인에서 번호 하나로 바로 선택, 스크롤·슬라이드·둘 다, 한글, 긴 문장, 표, 인터넷을 끊은 상태에서 열기.
- PPT: 설치된 PowerPoint 경로와 이미 준비된 제작 도구 경로를 구분해서 시험, 참고 파일 원본 보존, 결과 열기와 글자·표·도형 편집, 보호 문서 중단.
- 메일: 기존 승인 연결 우선, 연결 없음 안내, 본인 계정·선택한 메일함 범위, 부분 조회, 본문과 첨부 접근 결과 구분, 발송·PST 이동이 보조 조회 경로에 없는지 확인.
- 개인화: 공통 업데이트 후 기존 개인 자료 유지, 보호된 본문·첨부·추출 내용의 기억·지식·학습 저장 금지 확인.
- 추가 운영 점검: 시간대가 없는 날짜의 해석 표시, 날짜 오류와 연결 오류의 구분, 검색 한도에 따른 부분 결과, 중간 대화에서 반복 학습하지 않기, 최종 결과 중심 응답, 명시적 기억 요청 즉시 처리.

모의 도구나 임시 파일 테스트가 통과해도 실제 사내 Outlook·Office·모델의 통합 시험을 대신하지 않습니다. 직원 배포 전에 승인된 작은 업무로 확인하고, 결과가 불분명한 기능은 시범 적용으로 계속 표시하세요.

**과거 검증 기록:** 2026년 9월 9일 개발 PC에서는 당시 Python 회귀 테스트 310개를 제외 없이 통과했습니다. 선택 실행하는 실제 Claude 설정 검사도 임시 설정 폴더에서 실행했습니다. Windows PowerShell 5.1의 일반·CP949 설치/업데이트, 개인 자료 백업·보존, Skill 선택과 배포 묶음 검사도 통과했습니다. 합성 HTML은 실제 브라우저에서 페이지 넘김·모바일 줄바꿈·외부 요청 없음, 합성 PPT는 글·표·차트 편집 후 저장·다시 열기를 확인했습니다. 이는 현재 소스 전체나 새 배포본의 시험 결과가 아닙니다. **실제 Outlook 연결, PowerPoint 자동화, 회사 DRM, 사내 모델을 연결한 업무 실행은 이 검증에 포함되지 않습니다.**
