# PPT 분리 배포와 제작 흐름 검증

2026-11-02 기준 작업본과 실제 생성 ZIP을 확인했습니다. 공개 Release 게시나 현재 사용자 설치 변경은 수행하지 않았습니다.

## 확인한 원인

- `/company-agent:skills`는 설치된 스킬을 조회하고 선택하는 명령이며 PPT 제작 스킬이 아닙니다. 기본 하네스에도 유지합니다.
- 실제 회사 PPT 스킬은 `/company-agent:presentation`입니다. 공개 `v1.4.50`은 전체 플러그인 소스를 복사하므로 PPT가 포함됩니다. 기억과 학습 중심의 분리 구성은 현재 `1.5.1` 작업본에 있으며 아직 공개 배포 전입니다.
- 이 PC에서 관찰한 활성 설치는 `1.4.37`입니다. 별도 운영 PC의 설치 상태까지 확인한 것은 아닙니다.
- PPT 진입 지침과 선택 도우미가 참고자료 없는 요청에 `new/business`를 바로 적용하여 원래 원했던 양식 선택을 생략했습니다.
- 독립판에는 HTML 초안과 승인 후 제작 기능은 있었지만 선택과 양식 비교 명령이 없었습니다.

## 반영한 흐름

1. 새 작업에서 디자인이나 첨부 자료가 없으면 업무 보고형, 흑백형, 설명형, 기존 양식 활용, 내용에 맞게 추천, 직접 입력을 한 번 제시합니다. 빠진 목적과 장수는 같은 질문에 묶습니다.
2. 기존 선택이나 job, 첨부 양식은 재사용합니다. 추천을 요청했거나 일부 개체만 고치는 요청에는 선택을 다시 시작하지 않습니다.
3. PPT 파일은 제한된 대표 장의 구조와 실제 사용 가능한 열람 도구의 화면을 함께 참고합니다. 이미지 첨부는 바로 참고합니다. 실제 도구가 없거나 보호 정책이 거부하면 미확인 범위를 알리며 우회하지 않습니다. 독립 `reference` 명령 자체는 PowerPoint를 열거나 캡처하지 않습니다.
4. 새 디자인은 `compositionMode: content-led`로 요약, 데이터 근거, 비교와 실행안에 맞춰 배치를 정합니다. 기존 job과 명시한 layout, contentOrder, elements는 바꾸지 않습니다.
5. 모든 장의 HTML 초안을 먼저 보여주고 실제 승인을 기다립니다. 승인 기록, 명세와 초안이 일치한 경우에만 편집 가능한 PPT를 제작합니다.

독립판 `presentation.py`에 `choices`와 선택적 `gallery` 명령을 추가했습니다. 갤러리는 오프라인 가상 예시이며 승인 기록이 아닙니다. 상시 후크, 모델 호출, 외부 다운로드와 개인 설정 변경은 추가하지 않았습니다.

## 기존 사용자 PPT로 추가 실행

`outputs/agent-strategy-2027/2027_1인1Agent_표와그룹편집.pptx`를 실제 ZIP의 참고 분석 명령으로 읽었습니다. 이 원본은 2장으로, 맑은 고딕 서체와 회색 계열, 3열 흐름 및 그룹과 표를 포함합니다. 구조 분석의 관찰이며 실제 화면을 봤다는 뜻은 아닙니다.

실제 실행에서 두 문제를 재현하고 수정했습니다.

- 원본 서체 `맑은 고딕`은 거절하고 영문 이름 `Malgun Gothic`만 통과했습니다. 실제 설치 목록에 있는 동일 서체의 언어별 이름을 동등하게 인식하도록 수정했습니다. 선언 이름은 바꾸지 않으며 임의의 미설치 서체를 허용하지 않습니다.
- 그대로 둘 그룹을 `keepShapeIds`에 넣어도 양식 유지 모드가 거절했습니다. 명시한 그룹은 하위 개체와 위치 및 서식을 유지하도록 수정했습니다. 그룹 내부 자동 교체, 미지정 그룹 및 다른 미지정 이전 내용은 계속 거절합니다.

수정한 ZIP으로 원본 서체를 그대로 사용해 전체 2장 HTML과 편집 가능한 PPT를 새로 구성했습니다. 별도로 양식 유지 모드에서도 원본 2장의 제목과 부제 4칸만 바꿔 제작했습니다. 승인 없는 제작은 두 경로 모두 거절했습니다. 제작에 사용한 승인값은 시험용이며 실제 사용자 승인이라고 설명하지 않습니다.

양식 유지 결과의 주요 그룹 2개와 네이티브 표의 전체 subtree SHA-256은 원본과 일치했습니다. 테마와 레이아웃 및 마스터 9개도 유지됐고 원본 해시는 바뀌지 않았습니다. 이 추가 실행 당시의 HTML은 교체할 글자 4개만 표시하고 고정 개체 43개를 생략했습니다. **이는 아래 고도화 전의 검증 이력이며 현재 구현의 한계를 설명하는 문장이 아닙니다.** 이번에는 고정 개체를 포함한 HTML 투영을 구현했으며, 지원 범위와 근사는 아래 기준으로 구분합니다.

추가 산출물은 `outputs/ppt-live-20261102/`에, 근거는 `.smoke/ppt-live-20261102/style-evidence.json`, `preserve-final-evidence.json`과 회귀 로그에 있습니다. 신규 폰트 7개와 그룹 유지 5개 회귀 검사를 추가했습니다.
수정 후 PPT 134개, presentation 22개, 배포 패키지 52개, 독립 HTML/PPT 12개로 총 220개가 통과했습니다. 이번 추가 실행에서 기본 하네스 검사 22개를 다시 실행한 것으로 합산하지 않습니다. 스킬 validator와 ZIP 최신 여부 검사도 통과했습니다.

PowerPoint 앱의 실제 실행 요청은 컴퓨터 사용 도구의 앱 승인 대기에서 303초 후 시간 초과됐습니다. 창 재확인에서도 PowerPoint가 없어 실제 글자 편집, 그룹 해제, 표 편집, 저장과 재열기는 대기 상태입니다. 실행 코드와 파일 검증 결과를 실제 UI 동작 성공으로 표시하지 않습니다. 개인 설치나 현재 사용자 앱 보안 설정은 변경하지 않았습니다.

## 복잡한 구성과 한글 장표의 추가 고도화

PPT Master 고정 원문 `5e8856be0da8e6bc85c4aa28acc614478f7b7137`에서 네이티브 편집 개체, 서체 역할, 자료의 관계에 맞는 구성과 영향받은 장만 보정하는 원칙을 참고했습니다. 전체 SVG 엔진, 설치기, 별도 작업자 체계나 잠금 파일을 복사한 것은 아닙니다. 기존 양식 선택과 전체 HTML 초안 확인, 실제 승인 후 PPT 제작 흐름을 그대로 사용합니다.

| 반영 영역 | 현재 동작과 확인 범위 |
|---|---|
| 장별 역할 | `pageRole`의 cover, key-message, comparison, workflow, timeline, detail, closing 7종을 목적과 자료에 맞게 선택합니다. 표지, 핵심 메시지, 비교, 분기 흐름, 날짜 비례 일정, 상세 표와 결론을 같은 카드 반복 대신 서로 다른 구성으로 만듭니다. 기존 job, 명시한 elements와 contentOrder는 자동 역할로 덮지 않습니다. |
| 선택용 갤러리 | 업무 보고형, 흑백형, 설명형의 세 색감과 일곱 장 역할을 조합한 가상 예시 21장을 만듭니다. 비교를 원할 때만 실행하며 일반 작업에서 예시를 먼저 모두 생성하지 않습니다. |
| 복잡한 편집 개체 | 기존 rect, roundRect, ellipse에 화살표와 chevron, diamond, triangle, hexagon, parallelogram, trapezoid, pentagon, octagon 등을 더해 16종 도형을 지원합니다. 추가 다각형은 HTML과 같은 좌표의 네이티브 freeform입니다. line의 직선과 꺾은 경로, path의 M/L/C/Q/Z 구조화 명령으로 Bézier 곡선과 폐곡선을 만듭니다. 임의 SVG 문자열이나 실행 코드는 받지 않습니다. |
| 부분 강조와 한글 | `runs`로 같은 상자 안의 글자별 색, 굵기, 크기와 글꼴을 유지합니다. 모든 구간을 합친 문자열이 원문 text와 같은지 검사하고 동아시아 서체와 `ko-KR` 언어를 기록합니다. 본문과 제목의 역할, 수치와 단위, 한글의 의미 단위 줄바꿈을 지침에 반영했습니다. |
| 짧은 서식 프로필 | 같은 job의 `presentationProfile`에 제목, 본문, 강조, 주석과 표의 크기, 제목과 본문의 글꼴, 여백과 간격, 발표용 또는 읽기용 밀도를 유지합니다. 참고 분석의 `suggestedPresentationProfile`은 명시된 서식과 설치된 글꼴에서 얻은 제안이며 기존 선택을 덮지 않습니다. 새 설정 파일이나 사전 설문은 없습니다. |
| 고정 개체를 포함한 HTML | preserve 초안에 읽을 수 있는 고정 개체, 마스터와 레이아웃 개체, 중첩 그룹, 표와 차트, 그림과 배경을 교체 내용과 함께 투영합니다. 이전의 고정 개체 43개 생략 방식은 이 구현으로 대체했습니다. 미지원 개체와 근사 효과는 `templatePreview` 확인 범위와 초안에 표시합니다. 원본 개체를 보존하는 PPT 제작과 미리보기용 의미 투영은 서로 다른 처리입니다. |
| 제한된 사전 점검 | 이미 준비한 장면을 한 번 순회해 `scenePreflight`로 글자 넘침과 글자 영역 겹침 가능성을 알립니다. 최대 20개 경고, 5,000개 글자 영역 쌍 비교에서 멈추고 잘렸는지 표시합니다. 자동 글자 축소, 추가 모델, 반복 대기와 새 승인 단계를 만들지 않습니다. |

새 도형과 경로, 글자 구간, 위치를 HTML과 PPT가 같은 장면 명세에서 사용합니다. 다각형 freeform의 점을 편집할 수 있지만 Office 프리셋의 모든 조정 핸들을 구현한 것은 아닙니다. 선의 끝점이 도형 이동에 맞춰 자동으로 다시 붙는 연결점 기능도 보장하지 않습니다. 의미별 그룹은 해제할 수 있는 네이티브 그룹이며 표와 차트는 각 편집 기능을 유지합니다.

workflow 자동 배치는 실제 `nodes`와 `edges`만 사용하며 최대 8개 노드, 12개 연결, 순환 없는 4단계 이내입니다. 더 복잡한 분기나 순환은 자유 배치 elements로 작성합니다. timeline은 실제 ISO 날짜 사이의 간격을 반영합니다. 제공되지 않은 관계나 날짜를 만들어 빈 공간을 채우지 않습니다.

실제 presentation.zip을 새 격리 폴더에 풀고 `-I` Python으로 양식 선택, 21장 가상 갤러리, 10장 한글 복합 HTML, 미승인 제작 거절, 시험용 승인 뒤 PPT 생성, 승인 후 내용 변경 거절과 10개 배치의 대표 양식 저장을 실행했습니다. ### 독립 검토 후 추가로 바로잡은 두 경로

- 역할형 장표를 대표 HTML 양식으로 저장할 때 `pageRole`이 자유 배치 양식 저장 조건에 포함되지 않아 저장된 layouts가 0개로 줄어드는 경로를 확인했습니다. 역할형 장면도 저장하도록 수정하고 일곱 역할의 배치 보존과 업무 본문의 가상 문구 치환을 확인하는 회귀 검사를 추가했습니다. 저장 양식에 비공개 업무 내용을 그대로 남기지 않습니다.
- workflow, milestones, panels 자료에 다른 자유 배치나 contentOrder, 전체 이미지 모드를 섞거나 필요한 pageRole을 빼면 의미 자료가 렌더링 경로에서 누락될 수 있었습니다. 이런 혼합을 초안 준비 단계에서 구체적인 입력 오류로 반환하고 같은 job에서 알맞은 역할이나 전체 elements로 정리하도록 수정했습니다. 세 가지 의미 자료의 혼합과 역할 누락 조합을 회귀 검사에 추가했습니다. 일반 작업에 새 후크나 확인 질문을 추가한 변경은 아닙니다.

미리보기의 확인 범위는 작은 도구 응답과 전체 HTML을 구분합니다. 응답 `templatePreview`의 `unsupportedReasons`와 `approximationsReasons`는 제한된 이유 요약이고, HTML 전체 coverage의 `unsupported`와 `approximations`가 개체별 세부 근거입니다. 생략 여부와 실제 화면 검토 상태를 함께 읽으며 요약만으로 모든 개체의 시각 일치를 확인했다고 설명하지 않습니다.

## 참고자료의 색 조합과 구성 규칙을 PPT 및 HTML에 함께 적용

첨부 PPT와 여러 이미지를 기본적으로 스타일 참고로 처리합니다. 원본 개체 유지 요청이 있을 때만 preserve를 사용합니다. 최대 60장의 목록과 순서를 유지하고 2~3장씩 확인해 공통 규칙, 변형과 미확인 범위를 현재 job에 요약합니다. 일반 작업의 후크, 별도 모델 호출과 개인 설정 변경은 추가하지 않았습니다. 스킬 본문에는 시작 규칙만 넣고 상세 관찰 항목은 참고자료가 있을 때 읽는 `references/reference-style.md`로 분리했습니다.

`referenceStyle`에는 실제로 관찰한 글꼴 역할, 크기, 여백, 배치, 표, 차트, 도형, 강조, 말투와 색 조합을 남깁니다. 이미지에서 확정할 수 없는 서체 이름이나 정확한 색상값은 추정으로 구분합니다. 이 자료형은 호스트가 관찰한 결과를 검증하고 출력에 연결하는 기능이며 이미지 이해 모델이나 자동 화면 캡처 엔진은 아닙니다. 배치와 말투 등의 `patterns`는 작성에 적용하는 메모이며 픽셀 복제 명령이 아닙니다.

- 색은 배경, 표면, 글자, 주색, 보조색, 경계와 차트 계열로 나누어 적용합니다. 지정한 계열색 목록이 짧아도 남은 기본색을 섞지 않습니다.
- 표 헤더와 본문, 교차행, 테두리, 정렬, 안쪽 여백을 HTML 초안과 편집 가능한 네이티브 표에 연결했습니다.
- 차트 계열색, 범례 위치, 격자, 수치와 범례의 크기, 마커와 선 두께를 양쪽 출력에 적용했습니다. HTML 기본 선 두께가 PPT 초안의 명시 서식을 덮던 충돌도 수정했습니다.
- 제목과 본문, 주석의 글꼴 역할 및 크기, 여백과 간격은 역할형뿐 아니라 일반 배치에도 적용합니다. 명시한 자유 배치 개체의 위치와 서식을 덮지 않습니다. 공간이 부족하면 자동 축소하거나 내용을 버리는 대신 구체적인 배치 오류를 반환합니다.
- 사용자의 명시값은 해당 필드에 우선합니다. 참고 관찰이 있으면 기본 디자인 질문을 반복하지 않습니다. Python이 없을 때 참고 서식을 무시하는 COM 제작으로 조용히 바꾸지 않습니다.
- PNG/JPEG/WebP 참고 이미지를 지원합니다. 참고 이미지는 슬라이드에 자동 삽입되지 않으며 변경되면 이전 HTML 승인 기록을 사용할 수 없습니다.

최종 PPT 및 HTML 관련 **406개**, 플랫폼 배포 **34개** 자동 테스트가 모두 통과했습니다. 네 곳의 SKILL 형식 검사, ZIP `--check` 및 각 ZIP의 실행 모듈과 핵심 지침 27개씩, 총 54개 파일 바이트 일치도 확인했습니다. 별도 앱 미리보기의 `test_html_workspace_preview.py` 확장 검사에서는 기존 작업본과 기대값이 다른 2건이 남았습니다. 일반 HTML 첨부를 정적 미리보기로 반환하는 정책과 비활성 form 태그 보존 여부에 관한 것으로, 이번 스킬 변경에서 앱 코드를 바꾸거나 전체 저장소 검증이 통과했다고 처리하지 않았습니다.

최종 ZIP을 직접 풀어 녹청/황토와 자주/청색 두 조합으로 HTML 및 PPT를 생성하는 명령 12회를 실행했습니다. 각 PPT의 표 1개, 차트 1개, 제목 크기와 색, 그림 개체 0개를 실제 OOXML에서 확인했고 HTML 72행 표의 기능 코드와 색상 규칙을 확인했습니다. 시험에 사용한 관찰 프로필과 승인은 합성값입니다. 기존 사용자 PPT는 구조 분석만 했으며 원본 해시는 유지됐습니다. 화면 참고 명령은 `captured:false`인 계획으로 반환됐습니다.
