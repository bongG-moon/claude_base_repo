# 스킬 선택·기억 검색·실행 부담 검증

확인일: 2026-10-25. 기존 작업 폴더의 다른 변경을 유지하고, 이번 개선의 영향만 구분했습니다.

## 적용한 내용

- 예문·코드블록을 설명하거나 번역하는 요청을 실제 제작 요청으로 오인하지 않도록 후보 검색을 보완했습니다. 실제 제작 요청, 인용한 결과물 제목, 명시한 스킬 선택은 유지합니다.
- 스킬 설명에서 다른 스킬로 안내한 업무를 자기 기능으로 집계하지 않습니다. 자기 이름으로 설명한 역할은 유지합니다.
- `AI/email`, `API/capital`, `DB/feedback`, `SUM/summary` 같은 잘못된 기억 검색을 줄였습니다. `정리해줘` 같은 요청 표현만으로 다른 업무 기억이 선택되지 않도록 했습니다.
- 개인 전체와 현재 프로젝트만 검색하는 범위, 수정된 기억의 버전, 지속적인 선호, 최대 5개·4,000자 한도는 유지합니다. 의미 기반 동의어 검색이나 오래된 기억의 자동 삭제는 추가하지 않았습니다.
- `/company-agent:learning`의 기본 상태 설명은 기존 기록을 짧은 한국어로 보여줍니다. 접수·적용·보류와 기억 전달을 구분합니다. 세션 정보가 없으면 확인 불가로 표시하고 다른 세션을 찾거나 새 상태 파일을 만들지 않습니다. 이전 요청 기록과 현재 요청도 구분합니다.
- 모델 입력용 후크 출력에 포함한 기록은 모델의 실제 수신·답변 반영 증명이 아닙니다. 학습 적용 기록 수 역시 수동 기억 전체나 현재 파일 재검사 결과가 아닙니다.

## 평소 업무에 추가하지 않은 것

새 후크, 추가 모델 호출, 별도 평가 에이전트, 상태 조회 의무, 새 저장 범위 질문, 모든 세션 탐색을 추가하지 않았습니다. 설명 기능은 요청할 때만 실행합니다. 기존 후크의 명령 분류에는 새 읽기 전용 상태 옵션을 인식하는 분기만 추가했습니다.

개인 기억·자가학습 스킬 본문은 변경 전보다 각각 123자·3자 짧아졌습니다. 상태 설명용 명령 안내는 사용자가 해당 명령을 요청할 때만 읽습니다.

테스트 묶음에는 서로 겹치는 검사가 있어 단순 합계를 제시하지 않습니다. Codex 일반 스킬 검사기는 자가학습 스킬의 기존 `company-agent-role` 확장을 알지 못합니다. 이 확장을 제거하지 않았으며 하네스 전용 지침·배포 계약 검사를 기준으로 확인합니다.

외부 MCP의 기존 연결 시험은 제한된 실행 환경의 Python 내부 소켓 준비에서 멈췄습니다. 로컬 프로세스 통신이 허용된 환경에서 같은 임시 폴더 기반 검사를 다시 실행해 5개 모두 통과했습니다. 실제 사용자 프로필 등록·회사 DB 접속·플랫폼 게시·모델 호출은 수행하지 않았습니다.

## 부담 비교

대표 업무 8종(인사, HTML, PPT, 기존 브라우저 도구 사용, 실제 중복 후보, 명시 선택, 스킬 본문 재사용, 대화 압축 후 복원)을 임시 프로필에서 각각 3회 확인했습니다. 이번 변경 전 `skill_task_context.py`만 복원한 기준과 비교했으며 다른 작업의 변경까지 포함한 과거 제품 전체 비교는 아닙니다.

8종 모두 기본 지침·정규화한 컨텍스트 문자/바이트·선택 질문 계획의 증가가 0이었습니다. 이는 모델 토큰이나 실제 사용자 질문 횟수 측정이 아닙니다. 로컬 준비 시간은 파일시스템과 동시 작업 영향으로 증가·감소가 섞여, 전체 실행 시간이 단축됐다고 주장하지 않습니다.

기억 40개, 질의 4종, 변경 전후를 번갈아 8회 실행한 검색·출력 중앙값은 216.802ms → 204.630ms였습니다. 출력은 `987/997/1009/989`자 → `987/997/1009/987`자였습니다. 해당 로컬 검사에서 지연 증가는 관찰되지 않았지만 사내 모델 성능이나 토큰 절감의 증거는 아닙니다.

## 담당자가 다시 비교하는 방법

아래 도구는 개발 환경에서 명시적으로 실행할 때만 작동합니다. 임시 프로필과 가상 자료만 쓰며 네트워크·외부 프로세스 호출을 차단합니다.

```powershell
python -X utf8 -B scripts/test-lab/evaluate-harness-efficiency.py --output baseline.json
# 수정 후 같은 업무·환경으로 비교
python -X utf8 -B scripts/test-lab/evaluate-harness-efficiency.py --baseline baseline.json --strict --output comparison.json
```

`--strict`는 기존에 품질 검증을 통과했던 사례의 입력 분량·선택 계획 증가를 실패로 표시합니다. 기존 오선택을 고친 사례는 별도로 표시합니다. 시간 변화는 참고 수치로만 둡니다. 비교 결과 파일은 후크에 연결하거나 자동으로 모델에 넣지 않습니다.

실제 업무는 같은 입력·모델·환경으로 성공한 작업 전체를 비교합니다. 재시도와 승인 대기까지 포함한 `elapsedMs`, 실제 보고된 `inputTokens`·`outputTokens`·`cacheReadTokens`·`cacheWriteTokens`, `retries`, `questions`를 익명 기록으로 준비해 `--runs`와 `--baseline-runs`로 비교할 수 있습니다. 모르는 값은 `null`로 두며 문자 수에서 토큰을 추정하지 않습니다. 실패하거나 실행 수가 다른 업무는 비용 개선으로 비교하지 않습니다. 원문 대화·파일 경로·개인정보를 측정 파일에 넣지 않습니다.
