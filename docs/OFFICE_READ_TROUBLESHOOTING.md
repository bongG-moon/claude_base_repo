# 사내 파일 읽기 수정 및 재시험 안내

이 문서는 1.4.1 이후 작업 중인 소스 수정에 대한 안내입니다. 기존 PC 설치본과
GitHub Release는 자동으로 바뀌지 않습니다. 배포 시 새 버전으로 묶어야 하며
이미 배포한 1.4.1 코어를 같은 버전명으로 덮어쓰면 안 됩니다.

## 무엇이 달라졌나요?

- PPT: 글자만 나열하지 않고 표의 행·열, 개체의 위치·크기, 그룹 안의 글자를 함께 읽습니다.
- Word: 본문 문단의 순서, 표 ID·행·열, Office가 제공하는 페이지·제목 단계 정보를 읽습니다.
- Excel: 셀의 행·열 정보를 유지합니다. 빈 칸이 생략돼도 옆 열로 당겨 해석하지 않습니다.
- 여전히 그림 속 글자, SmartArt, 차트 내부 데이터, 완전한 병합 셀·디자인 해석은 지원하지 않습니다.
  좌표 정보가 있다는 것이 문서를 이미지로 보고 이해했다는 뜻은 아닙니다.
- 파일 경로를 바로 전달하는 실행을 추가했습니다. JSON 임시 파일이나 doctor 선행 실행이 필요 없습니다.
- 모듈 실행이 출력 없이 종료되던 문제와, 긴 안내 때문에 실행 경로 정보까지 사라질 수 있던 문제를 보완했습니다.

## PDF 오류의 의미

`PdfStreamError`는 PDF 파서가 내부 데이터 구조를 읽지 못했다는 뜻입니다.
이 오류만으로 DRM 때문이라고 판단할 수 없습니다. 이번 시험은 Office를 이용한
Excel/PPT/Word 읽기와 달리 pypdf로 PDF 파일 자체를 읽습니다. Acrobat 연동이 아닙니다.

수정본은 PDF 헤더와 EOF 표식의 존재 여부를 확인하고, 일반 PDF가 아닌 경우와
PDF 내부 구조를 읽지 못한 경우를 구분합니다. 확인 결과를 보여줄 뿐 파일을
복구·변환·복호화하거나 다른 파서로 반복 시도하지 않습니다. 헤더/EOF 존재도
정상 파일임을 보장하지는 않습니다. 암호화 PDF는 기존과 같이 중단합니다.

문제 PDF는 사내에서 허용된 뷰어로 **같은 경로의 같은 파일**이 열리는지 먼저
확인해 주세요. 외부로 원본을 보낼 필요는 없습니다. 수정본의 오류 종류와
PDF 형식 확인 결과만 전달해도 다음 진단에 도움이 됩니다.

## 독립 시험 파일 실행

수정된 `scripts/office_read_test.py`는 여전히 파일 하나만 복사해서 사용할 수 있습니다.
바탕화면 전달용은 `office_read_test_v2.py`이며 기존 파일은 보존합니다.

```powershell
python office_read_test_v2.py
```

예를 들어 PPT 4장 전체를 비교하려면:

```powershell
python office_read_test_v2.py "C:\업무\자료.pptx" --start 1 --end 4 --max-chars 20000
```

한 번에 최대 50개 단위를 읽습니다. PPT/PDF는 장·쪽, Word는 **문단** 단위입니다.
기본 시험은 PPT/PDF 3개, Word 20개, 최대 3,000자의 미리보기입니다. 이전 시험
코드도 기본은 앞부분만 읽었습니다. ‘파일 열기 성공’을 전체 읽기로 판단하지 마세요.
Excel은 첫 시트의 앞 20행×10열 시험이며 start/end로 시트를 선택하지 않습니다.

## Claude에서 읽을 때

업데이트 설치 후 이렇게 요청할 수 있습니다.

> 이 PPT는 4장입니다. 지정한 원본만 읽어서 표의 행·열과 개체 배치를 반영해 요약해줘.
> 다른 사본으로 대체하지 말고, 읽힌 장수가 다르면 원인은 단정하지 말고 알려줘.

Skill은 설치된 진입점에 `business office-read --file "절대경로" --start 1 --end 4
--expected-count 4`를 전달합니다. Python 모듈 위치를 전체 PC에서 찾거나 코드를
만들지 않습니다. 실제 로컬 확인창과 Claude 자체의 실행 승인은 유지합니다.

## 수동 실행은 4장, Claude는 1장이라면

Office에서 보고된 total=1만으로 DRM이 3장을 숨겼다고 결론낼 수 없습니다.
독립 시험과 하네스의 원본 SHA256, 요청 경로/열린 경로, Python 실행 파일,
선택 범위, Office 인증 상태를 비교해야 합니다. 두 코드의 PPT/Word 열기 인자는
동일하며 구조 추출 코드는 회귀 테스트로 동일성을 검사합니다.

다른 경로의 비슷한 이름 사본이나 이전 HTML은 원본과 같은 자료라는 증거가 아닙니다.
개수가 다르면 일부 읽기로 표시하고 동일 파일 재열기를 반복하지 않습니다.

## 느린 이유를 구분합니다

진입점 탐색, 소스 읽기, 출력 없는 명령 재시도는 이번 수정 대상입니다.
실제 Office 열기·내용 읽기 시간은 diagnostics로 반환하고 독립 시험에도 표시합니다.
모델 생각 시간, 승인 대기, Office/DRM 인증 창 대기는 별개이며 이 수치에 전부
포함되는 것은 아닙니다. 최대 60초 응답 제한과 접근 거절 시 중단은 유지합니다.
읽기만 한 작업은 산출물 변경 검증 대상으로 만들지 않으며, 예전 작업의 미완료
검증을 이번 파일 읽기 실패로 설명하지 않습니다.

공식 참고: [PowerPoint 그룹 읽기](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.shape.groupitems),
[Word 범위 정보](https://learn.microsoft.com/en-us/office/vba/api/word.range.information),
[pypdf 읽기 구현](https://github.com/py-pdf/pypdf/blob/main/pypdf/_reader.py).

## 개발 PC 검증 결과 (2026-09-15)

합성 자료를 실제 Office로 열어 PPT 4장·그룹 안 글자·표 행/열, Word 표 행/열,
독립 시험의 PPT 4장 읽기를 확인했습니다. 세 실행 모두 원본 SHA256이 유지됐습니다.
하네스 PPT 약 2.9초, Word 약 3.2초였습니다. Claude의 모델 응답/승인 대기를
포함한 시간은 아닙니다. 사내 DRM 원본과 PDF 문제 원본은 이 PC에서 검증하지 못했습니다.
Excel의 구조 추가는 자동 테스트로 확인하며 이 PC에는 xlwings가 없어 실제 Excel
재시험은 하지 않았습니다. 사용자가 확인한 회사 PC의 열기 성공과 구분합니다.
