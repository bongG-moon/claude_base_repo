# 중간 파일 정리·한국어 선택지 — 검증

검증일: 2026-09-22. Windows 로컬 작업 사본에서 가상 자료로 확인했다. 실제 사내 HCP 대화, 사용자 설치, Release 게시를 실행한 기록은 아니다.

## 반영 범위

- 기본 HTML·PPT 제작기는 새 작업에서 직접 생성한 파일의 경로·파일 식별 정보·내용 해시를 기록한다. 최종 게시 확인 후 변경 없는 등록 파일만 정리한다.
- 원본, 최종 결과, 대표 양식, 개인 기억·스킬, 사용자 수정 파일, 미등록 파일, 이전 형식의 작업 기록은 자동 삭제하지 않는다. 최종 HTML의 로컬 의존성을 확정할 수 없는 경우에도 중간 파일을 보존한다.
- Windows에서 최종 결과와 삭제 대상의 파일 핸들을 유지하여 확인과 삭제 사이의 교체·수정 위험을 줄였다. 링크·접합점·하드링크·사용 중인 파일은 보존한다. Windows 외 플랫폼에서는 삭제하지 않는다.
- 잠금·정리 실패가 이미 성공한 게시를 실패로 바꾸지 않는다. 작업 기록과 빈 폴더는 남긴다. 범용 강제 삭제 보호와 기존 도구 승인은 유지한다.
- `business artifact-cleanup --work "<workFile>"`는 해당 작업의 정리만 다시 확인한다. 게시 전 작업을 삭제하지 않으며, 전체 임시 폴더를 탐색하지 않는다. 등록은 최대 256개다.
- 모델이 만드는 질문·제목·선택지·설명은 한국어를 기본으로 한다. 흔한 영어 표시 문구와 추천 표시는 결정적 규칙으로 바꾸며 추가 AI 호출이 없다.
- 임의 영어 문장의 모델 보정 요청은 턴당 한 번으로 제한한다. 파일명·명령·제품명·식별자·질문의 답변 연결 키를 보존하고, 같은 한국어 선택지로 합쳐지는 경우 자동 변환하지 않는다. 명시적인 다른 대화 언어는 존중한다.
- Claude 자체 메뉴·권한 버튼·설문·외부 도구 원문은 이 변환의 대상이 아니다. 임의 Bash/Write·타사 제작물도 자동 소유권 추적 대상이 아니다.

## 남은 운영 확인

- 실제 사내 Claude CLI가 `AskUserQuestion`의 수정 입력을 적용하는지, 일반 업무에서 모델이 한국어 재질문을 따르는지 확인해야 한다.
- 실제 제작 작업에서 최종 파일 확인 후 등록된 중간 파일만 없어지는지 확인한다. 임의로 만든 기존 파일을 자동 정리할 것이라고 기대하면 안 된다.
- 사용자 폴더의 기존 자료는 정리하지 않았다. 삭제 검사는 전용 가상 자료만 대상으로 했다. 기존 설치 ZIP과 별도 CUA 시험 가이드는 변경하지 않았다.
