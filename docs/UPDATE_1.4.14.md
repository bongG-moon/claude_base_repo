# 1.4.14 — 문서 읽기 대기 구간 구분·짧은 스킬 교정

## 설치·업데이트

[1.4.14 설치 ZIP](https://github.com/bongG-moon/claude_base_repo/releases/download/v1.4.14/company-agent-1.4.14-2026.09.03.zip)을 새 폴더에 모두 압축 해제한 뒤 `Install-CompanyAgent.cmd`를 실행하세요. 이전과 같은 내 계정/프로젝트 범위를 선택해 백업 후 업데이트하고 Claude Code를 닫고 다시 엽니다. GitHub의 `Source code (zip)`은 직원용 설치 파일이 아닙니다.

개인 Memory·Knowledge·Skill·선호, 모델·MCP와 기존 사용자 규칙·Hook을 유지합니다. 기존 1.4.13 ZIP은 덮어쓰지 않으며 이미 설치된 PC가 자동으로 바뀌지는 않습니다. 파일명 뒤 `2026.09.03`은 회사 지식팩 버전입니다. 기존 승인 Python 3.11 이상과 문서 형식에 맞는 Office·읽기 라이브러리는 별도로 필요하며 자동 설치하지 않습니다.

## 바꾼 점

- `[스킬 목록 확인 1회]` 문구를 짧게 줄였습니다. 실제 실행을 한 번 멈추는 교정이므로 빨간색 표시는 남을 수 있습니다. 파일 권한 오류나 추가 승인 요청은 아닙니다.
- 실제 사용 가능한 관련 스킬부터 적용하고, 관련 스킬이 없으면 일반 실행합니다. 없는 스킬을 만들어 호출하거나 같은 준비 사유로 반복 차단하지 않습니다.
- `[문서 읽기]` 단계 안내로 Python 준비, 확인 창 시작, 창 표시 후 사용자 응답 대기, Office 실행·열기·읽기·닫기를 구분합니다. 최종 결과에도 단계별 소요시간을 남깁니다.
- Python 버전 확인은 10초, 확인 창 시작은 30초, 창 표시 후 응답은 300초로 제한합니다. Office 보조 프로세스의 기존 전체 60초 제한은 유지합니다. 시간 초과 시 무조건 재시도하거나 사용자 Office를 강제 종료하지 않습니다.
- 확인 창의 실제 표시와 승인 응답을 모두 확인한 뒤 문서를 엽니다. 승인 절차는 생략하지 않습니다.
- 중복 Python 실행 경로 확인을 줄였습니다. 추가 모델 호출·선택 기록 명령·자동 재시도 없이 현재 실행 안에서 처리합니다.

## 확인 범위와 한계

전체 회귀 검사 **782개**와 실제 Claude Code 호스트의 1회 교정 → Skill 본문 로드 연결 검사를 통과했습니다. 연결 검사는 로컬 모의 응답을 사용하며 사내 HCP 모델의 자율 선택 정확도나 회사 Office·DRM 연동 검증은 아닙니다. 상세 결과는 [검증 기록](https://github.com/bongG-moon/claude_base_repo/blob/v1.4.14/docs/OFFICE_READ_PROGRESS_2026-09-17.md)을 참고하세요.

기본 설치 묶음 검사, 이전 1.4.13 ZIP에서 1.4.14 후보 ZIP으로 업데이트하는 검사, 설치 인코딩 42개 항목도 통과했습니다. 새 모듈·확인 창 스크립트가 설치 캐시에 그대로 반영되고 개인 자료·모델·MCP·사용자 규칙이 보존되는 것을 격리된 임시 프로필에서 확인했습니다. 실제 사용자 운영 설치는 변경하지 않았습니다.

Claude가 출력을 모아 보여주면 단계 안내가 즉시 보이지 않을 수 있습니다. 최종 `diagnostics.progress`의 단계·시간으로 지연 구간을 확인하세요. 모델 추론과 도구 실행 전 권한 판정 시간은 여기에 포함되지 않습니다. 실제 사내 PC의 지연 원인과 체감 속도 개선은 업데이트 후 재확인이 필요합니다.
