# 회사 기준과 개인 업무 연결

2026-09-18 개발 반영. 기존 설치 ZIP은 바뀌지 않으며 새 배포 전에는 개발 소스에만 적용됩니다.

## 관리 영역은 두 가지

| 영역 | 관리 대상 | 변경 주체 |
| --- | --- | --- |
| 회사 관리 | 회사 필수 정책, 기본 업무 방식, 부서별 적용 기준, 공통 스킬·지식·양식 | 회사 배포 담당자 |
| 개인 업무 | 개인 선호·기억·지식·스킬, 프로젝트별 작업 흐름 | 해당 사용자 |

부서 기준은 회사 기준 안에 포함합니다. 별도 팀팩 설치·버전·선택 계층을 만들지 않습니다. 프로젝트는 적용 폴더이며 세 번째 정책 소유자가 아닙니다. User/Project 설치 범위 선택은 그대로 유지합니다.

- **필수(required)**: 확인하지 않은 결과를 성공으로 보고하지 않기, 개인 자료 보존 등 유지할 기준.
- **기본값(default)**: 사용자 요청이 없을 때의 표현·디자인 등 개인화 가능한 기준.
- **참고 지식**: 근거 자료이며 실행 명령이나 권한으로 해석하지 않습니다.

이 구분은 업무 지침입니다. JSON에 required를 넣는 것만으로 운영체제·도구 접근을 강제하지 않습니다. 기존 정책 검사, Claude 권한, 회사 시스템 권한은 계속 적용되며 개인 설정으로 해제하지 않습니다.

## 회사 기준 배포

관리자는 `config/managed.json`의 선택 항목 `workStandards`를 관리합니다. 이 파일이 없으면 오프라인 묶음 생성기가 `config/managed.example.json`을 `payload/config/managed.json`으로 포함합니다. 명시한 관리자 파일을 덮어쓰지 않으며 예제 MCP 서버를 자동 연결하지 않습니다.

```json
{
  "workStandards": {
    "revision": "1",
    "rules": [
      {"id":"verified-results","level":"required","workflows":["*"],"text":"확인한 범위만 결과로 보고합니다."},
      {"id":"report-style","level":"default","workflows":["html-report","presentation"],"text":"별도 요청이 없으면 쉬운 한국어 보고로 작성합니다."}
    ]
  }
}
```

위 예시는 추가 항목만 보여줍니다. 기존 파일의 다른 설정은 보존합니다.

- `revision`: 1–40자의 영문·숫자·점·밑줄·하이픈.
- `rules`: 최대 64개. 각 규칙은 `id`, `level`, `workflows`, `text`만 허용합니다. 실행 명령 필드는 없습니다.
- `id`: 소문자로 시작하는 영문·숫자·하이픈, 최대 64자, 중복 불가.
- `workflows`: `*` 또는 실제 스킬 이름, 최대 12개. 전체 및 해당 업무 기준만 전달합니다.
- `text`: 제어문자 없는 설명, 최대 300자.

현재 적용 필터는 업무 이름입니다. 부서 소속 자동 판별이나 인사 DB 연결을 추가한 것은 아닙니다. 부서의 특수 기준은 회사 담당자가 배포 기준과 적용 업무로 정합니다. 개인 파일을 회사 정책으로 자동 승격하지 않습니다.

설치 등록의 정확한 `managedConfigPath`만 사용합니다. 작업 폴더의 동명 파일로 대체하지 않습니다. 네이티브 설치와 기존 실행기 설치 모두 연결합니다. 오래된 설정에 `workStandards`가 없으면 호환 동작하며 파일을 변경하지 않습니다. 등록된 파일의 손상·누락은 ‘미확인’이지 ‘정책 없음’이 아닙니다.

회사 기준은 1,200자 안으로 전달하며 필수 기준을 먼저 포함합니다. 초과분은 `truncated`와 원본 경로를 명시해 필요할 때 확인합니다. 작업자에게도 선택 업무의 기준을 전달하며 모델 설정·권한을 바꾸지 않습니다.

`forWorkflows`는 이번 안내에 반영한 업무 범위입니다. 모델이 목록에서 다른 업무를 선택하면 같은 원본의 해당 기준을 확인합니다. 지나치게 긴 경로는 잘라서 실행하지 않고 확인 필요로 표시합니다.

## 첫 업무 시작

설치 묶음의 `First-Work.html` 또는 설치 완료 시 표시되는 `resources/first-work.html`을 엽니다. 연습실에서는 `00_FIRST_WORK.html`로 연결됩니다.

1. 자료 하나를 읽고 실제 확인 범위와 원본을 대조합니다.
2. 가상 실적으로 보고서 디자인을 선택하고 결과 파일을 확인합니다.
3. 원할 때만 개인 선호 하나를 저장하고 같은 설치 범위의 새 대화에서 확인합니다.

화면에는 외부 통신·자동 실행·대화 수집 기능이 없습니다. 복사는 실행이 아닙니다. 개인 선호는 해당 요청을 실제로 보낸 경우에만 저장합니다. 매 요청마다 읽거나 필수 온보딩 단계로 만들지 않습니다.

프로젝트 하네스는 목표·입력·출력 중 빠진 정보만 최대 세 가지 질문으로 확인하고 변경 계획을 보여 줍니다. 생성기 v3는 회사/개인 경계와 대표 업무 확인 기준을 계약에 포함합니다. v1/v2 소유권 검증과 기존 충돌·백업 절차는 유지하며 자동 마이그레이션하지 않습니다.

## 하나의 진단 결과에서 구분해서 확인

기존 `Diagnose-CompanyAgent.cmd`에 HTML 저장 옵션을 추가했습니다. 경로는 실제 작업 폴더와 **새 파일 이름**으로 바꾸세요.

```powershell
.\Diagnose-CompanyAgent.cmd -ProjectRoot "C:\Work\Report" -ReportPath "C:\Work\Report\환경확인-01.html"
```

상위 폴더가 있어야 합니다. 기존 보고서를 덮어쓰거나 설정을 변경·재설치하거나 업무를 다시 실행하지 않습니다. `-ReportPath`를 지정한 경우에만 새 HTML 파일을 만듭니다.

진단은 설치 경로·적용 범위·개인 자료 위치·회사 기준 상태, 업무별 의존성 준비 상태, 목록 확인·본문 로드·업무 도구·검증 기록을 구분합니다. 프로그램을 띄우거나 모델을 호출하지 않습니다. **준비 상태·본문 로드·도구 호출은 실제 결과 정확성의 증거가 아닙니다.** 검증 기록 역시 기록된 범위만 뜻합니다.

### 선택한 로그만 시간·사용량 분석

로그는 기본 진단에서 수집·자동 탐색하지 않습니다. 필요할 때 파일을 지정합니다.

```powershell
.\deploy\Diagnose-CompanyAgent.ps1 -ProjectRoot "C:\Work\Report" -ReportPath "C:\Work\Report\환경확인-02.html" -UsageLog "C:\Logs\선택한세션.jsonl" -OfficeResult "C:\Work\Report\office-result.json"
```

`-UsageLog`는 UTF-8 JSONL 최대 8개, 합계 32 MiB/50,000행 범위로 읽습니다. 로컬에서 집계하며 원문·명령·본문·읽은 파일 경로를 출력하지 않습니다. 모델 호출·업로드·분석 캐시는 없습니다. 보고서 설치 경로에는 사용자명이 포함될 수 있으니 외부 공유 전에 확인하세요.

- 메시지 ID별 누적 사용량은 중복 제거합니다. 식별자·토큰 필드 누락은 명시하며 0으로 꾸미지 않습니다.
- 동일 파일·동일 범위 Read 요청을 집계합니다. 다른 페이지는 반복으로 세지 않습니다. 필요한 재확인도 포함될 수 있습니다.
- 도구 요청 횟수는 실행 성공 횟수가 아닙니다.
- 관찰 구간은 사용자 대기를 포함하므로 순수 실행 시간으로 해석하지 않습니다.
- Hook 안내 크기는 문자 수이며 토큰 수가 아닙니다.
- 사내 모델 단가가 없으므로 비용은 미확인입니다. 다른 모델 가격을 대입하지 않습니다.
- Office 결과에서 준비·확인 창 시작·응답 대기·읽기 시간을 구분합니다. Claude 자체 승인 대기는 이 결과에서 알 수 없으므로 미확인입니다.

## 유지하는 실행 원칙과 한계

실제 사용 가능한 목록을 기준으로 관련 스킬을 먼저 불러오고, 없으면 허용된 일반 방식으로 진행합니다. 같은 역할의 중복만 기존 선택 또는 사용자 질문으로 해결합니다. 없는 스킬 강제 호출, 전체 본문 반복 주입, 추가 LLM 라우팅, 권한 우회는 추가하지 않습니다.

코드 검증이 사내 HCP 모델의 지침 준수를 보증하지 않습니다. 회사 PC에서 스킬 이름을 지정하지 않은 문서 읽기, 디자인 선택 대기, 개인 선호 유지 등 대표 업무를 직접 확인해야 합니다.
