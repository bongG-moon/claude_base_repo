# 1.3.1 배포 버전 충돌 수정 검증

## 원인과 수정

기존 설치의 `versions/1.3.0/release.json`에 기록된 payload와 새로 전달한
1.3.0 ZIP의 payload가 달랐다. 설치기는 같은 CoreVersion의 변경된 내용을
거부하도록 설계되어 있다. 버전을 올리지 않은 패키지와 재적용 안내가 잘못됐으며,
이 안전 검사를 제거하는 것은 해결책이 아니다.

- CoreVersion, 플러그인 버전, Python 패키지 버전을 모두 1.3.1로 변경.
- 사용자 안내서와 최신 패키지 기본 경로를 1.3.1로 변경.
- 이전 같은 버전 재적용 안내는 정정하고 최신 안내로 연결.
- 빌드의 `-Force`도 기존 ZIP과 같은 CoreVersion에 다른 payload가 있으면
  거부한다. 같은 payload 재생성은 허용한다. 이 검사는 지정된 출력 파일을
  비교하는 검사이며, 다른 파일명이나 외부 게시판의 모든 배포 이력을 찾는 것은 아니다.

## 결과

- 전체 Python 테스트: **414개 통과, 제외 0개**, 137.005초.
- `Test-OfflineBundle.ps1`: 통과. 같은 payload 재생성 허용, 다른 payload의
  같은 버전 재생성 거부, 거부 후 기존 ZIP 해시 보존을 확인.
- ZIP 내부 manifest, 플러그인 manifest, Python 버전이 모두 1.3.1이며
  `docs/UPDATE_1.3.1.md` 포함을 읽기 전용으로 확인.
- 실제 기존 1.3.0 ZIP과 새 1.3.1 ZIP을 별도 임시 프로필에 설치하여
  프로젝트 범위 업데이트, 개인 상태 보존, 선택 Skill 연결 유지 등을 확인.
  생성한 가짜 1.3.1 버전이 아니라 배포할 두 실제 패키지를 사용했다.
