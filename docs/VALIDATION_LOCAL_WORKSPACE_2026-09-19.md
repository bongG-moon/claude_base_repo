# 로컬 업무 화면 0.2 — 기존 CLI 실행 환경 공유

## 변경 계약

- 앱 전용 로그인, API 키, 계정/모델/서버 설정 화면과 별도 Claude 설정 폴더를 만들지 않는다.
- 기존 Windows 사용자와 작업 폴더에서 실행하는 Claude Code가 인증·모델·권한·스킬·후크·MCP를 소유한다. 앱은 입력/출력 연결 옵션만 추가한다.
- Windows PowerShell 프로필 적용 후 실제 `claude` 호출 대상(별칭/실행 스크립트 포함)을 따른다. 실행 스크립트를 건너뛰어 회사 연결 설정을 누락하지 않는다.
- 프로필 함수는 동일한 함수가 복원되는지 지문을 비교하며 다른 PATH 실행 파일로 조용히 대체하지 않는다. 함수 본문/인증 정보는 앱 상태 파일에 복사하지 않는다.
- 다른 셸/WSL/VS Code 전용 환경이나 일회성 터미널 변수까지 자동으로 동일하다고 보장하지 않는다.
- 인증 오류가 난 앱 소유 연결만 종료하고, 사용자가 다음 요청을 보낼 때 기존 Claude 인증을 다시 읽는다. 업무 자동 재실행·로그인 초기화·재설치·추가 모델 호출 없음.
- 다른 폴더/버전의 서버가 남아 있으면 구버전을 조용히 재사용하거나 강제 종료하지 않는다.

## 검증 항목

- Workspace 전용 unittest: 41개 실행, 40 통과, 심볼릭 링크 권한 부재 1 건너뜀, 실패 0 (37.732초).
- 모형 CLI로 공용 인증 만료 → 기존 인증 갱신 → 앱 재시작 없이 다음 명시 요청 성공을 검증.
- 인증/모델/서버/설정 위치 환경변수를 변경 없이 전달하고 별도 인증 파일을 생성하지 않는지 검증.
- 실제 Windows PowerShell 별칭을 통한 숨김 실행, 공용 설정 위치 상속, 같은 앱 재실행 시 PID 재사용, 다른 버전 재사용 거절 검증.
- 실제 PowerShell 실행 스크립트 경유 JSON 초기화·질문·승인·한글 후속 응답 검증. PowerShell 공통 매개변수가 Claude의 `--verbose`를 소비하는 회귀를 포함.
- 기존 보안·질문·승인·파일 범위·원본 비변경 테스트 재실행.
- 설치된 Claude Code 2.1.272와 실행 스크립트 경유 초기화: `.cmd` 4,406ms, Windows PowerShell이 실제 선택한 `.ps1` 6,115ms, 모두 성공. 각각 사용자 프롬프트/모델 요청 0. 이 결과는 실계정 인증/모델 응답 성공을 뜻하지 않는다.
- JS 문법 검사 및 Python 컴파일 통과.

## 미확인 범위

개인 계정의 실제 모델 응답과 사내 HCP/DRM 업무는 별도 확인이 필요하다. 테스트 중 계정을 로그인/로그아웃하거나 인증 파일·회사 설정을 변경하지 않았다. CLI의 터미널 전용 화면 전체를 GUI에 재구현한 것은 아니다. Git 커밋/푸시 및 정식 Release 교체는 수행하지 않았다.
