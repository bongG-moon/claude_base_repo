## 독립 서브 에이전트 검토

구현하지 않은 별도 검토자가 다음 결함을 찾아 수정 후 재현을 반복했습니다.

1. Stop만 완료 확인하고 직접 review 제출은 허용하던 문제 → 엔진에서도 차단.
2. 후보 8개/검토 5개 불일치 및 같은 항목 교정 충돌 → 5개 일치·명시적 교정 병합.
3. 같은 업무의 반복 평가가 성공 표본을 늘리던 문제 → 업무별 표본으로 중복 제거.
4. 완료 후 다음 턴에서 새 업무 경계가 사라지던 문제 → 완료 경계 유지·회귀 시험.
5. 미해결 기록을 해소할 경로 없음 → 실제 현재 검증을 요구하는 개별 연결 명령.
6. 일시적인 Windows 파일 교체 거부 → 재현 시험과 제한된 동일 교체 재시도.

최종 독립 검토는 추가 차단 결함을 찾지 못했습니다. 검토자가 직접 업무 시험 17개와 앞서 실패한 전환/네이티브 사례를 다시 실행했습니다. 중간 실행에서 일시적인 WinError 5가 한 번 발생했고, 단독 재실행 및 수정 후 재실행이 통과한 이력도 숨기지 않습니다.

기존 테스트의 “매 턴 학습” 기대값은 업무 완료 표시를 사용하는 새 계약으로 수정했습니다. 백업 시험의 학습 자료 생성도 같은 완료 조건을 거치게 했습니다. 배포 HTML 문서가 1개에서 2개로 늘어 패키지 검증도 두 문서의 원본 해시를 각각 비교하도록 수정했습니다. 안전 검사를 제거하거나 실패를 pass로 바꾸지 않았습니다.

## 운영 확인이 남은 범위

- 사내 Outlook/DRM·실제 메일 검색 완전성·사내 모델 endpoint 선택.
- 실제 대화에서 업무 완료/새 업무를 적절히 판단하고 지침대로 간결히 답하는지.
- 회사 Claude 버전에서 제한적 자동 승인 Hook이 기대대로 실행되는지.
- 일반 메일 검색/본문의 포괄 자동 승인, 사용자용 저장소 별칭, 백그라운드 학습, 공통 스킬 자동 개인 복제는 이번 구현 범위가 아닙니다.

실제 업무 파일·메일 발송·메일 이동·DB 쓰기·실제 사용자 프로필 설치는 수행하지 않았습니다. 자동 테스트는 의미 있는 학습 품질이나 회사 환경 전체의 성공을 보증하지 않습니다.
