# 개별 스킬 실사용 점검 · 2026-11-02

실제 참고자료는 읽기만 하고 결과는 복사본에 만들었습니다. 이전 Claude Code 실행 기록과
사용자 파일, 개인 설정은 보존했습니다. 가상 데이터는 실제 성과나 회사 데이터가 아닙니다.

## PPT와 HTML

PowerPoint에서 참고 PPT 1장, 이전 생성 결과 7장, 보완본 1·3·7장을 직접 확인했습니다.
이전 결과는 참고의 회색 중심 3열 구성 대신 청록색과 반복 카드가 중심이었고, 3장의
분기 화살표가 연결되지 않았습니다. 7장의 화살표 안 글자는 오목한 흰 영역에 겹쳤으며
두 상자가 내용에 비해 컸습니다. 일부 주석은 9pt였습니다.

별도 사본 `outputs/ppt-visual-polish-20261102/시각검토-색상범례-최종.pptx`에
연결선, 글자 위치, 상자 크기, 주석, 무채색 계열과 실제 색에 맞는 범례를 반영했습니다.
PowerPoint에서 3장의 연결·범례와 7장의 글자·여백을 다시 확인했습니다. 전체 원본
레이아웃을 똑같이 재현한 결과는 아닙니다. 7장, 표 3개, 그룹 37개를 유지하며 원본을
덮지 않았습니다.

PPT 스킬은 배치 오류가 `artifact_failed`로만 전달되던 문제를 수정하고, 기존 초안의
제한된 검사에 분리된 화살표, 오목한 도형과 글자, 작은 주석의 자문 경고를 추가했습니다.
참고 파일의 `--summary`는 스타일 작업에 필요한 구조·글꼴·색상 단서만 반환합니다.
전체 분석은 기존 명령으로 유지하며, 파일 구조 분석을 실제 화면 확인이라고 말하지 않습니다.

HTML은 브라우저 도구가 `file:` URL을 보안 정책으로 거절하고 우회를 금지해 실제
화면·클릭 비교를 진행하지 못했습니다. 기존 참고 분석이 색과 글꼴 외에는 단순 태그 수만
반환하던 점을 보완해 목차, 카드, 그리드, 단계 목록, 배지, 접이식 영역의 수를 제한된
`layoutHints`로 전달합니다. 실제 CSS 배치나 시각적 일치를 판정하는 기능은 아닙니다.
원문·클래스명·스크립트를 모델에 돌려주거나 외부 자원을 실행하지 않습니다.

두 최신 독립 ZIP을 격리 폴더에 풀어 사용자의 기존 참고 파일을 직접 분석했습니다.
7.25MB HTML 분석·미리보기 응답은 약 2.4KB였습니다. PPT 구조 요약은 한국어 출력 보완 후
실제 Claude 도구 호출에서 3,442바이트의 완전한 JSON으로 전달됐습니다. Claude도 구조 분석과
실제 화면 검토를 구분했습니다. 실제 Claude의 HTML 분석에서도 구조 단서와 한글 경고가 정상
전달됐습니다. 이 크기는 도구 응답 바이트이며 토큰이나 전체 업무 속도를 뜻하지 않습니다.
Windows에서 Python 기본 출력과 Claude 도구의 해석 방식 차이로 한글이 깨지는 문제를 재현해
두 독립 실행 도구의 표준 출력을 UTF-8로 고쳤습니다. 시스템 설정은 변경하지 않았습니다.
일반 작업에 상시 후크나 추가 모델 호출을 넣지 않았습니다.
