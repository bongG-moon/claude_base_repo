# 스킬·도구 통합 제작 검증

## 적용 범위

- 새 제작 요청의 진입점을 `company-agent:asset-factory` 하나로 통합했다. `platform-mcp-builder`는 이전 사용자의 명시 호출을 위한 짧은 호환 안내만 남겼고 자동 후보에서는 제외했다. 기존 개인 자산, 회사 원본, 모델·인증·MCP 설정을 일괄 변경하지 않는다.
- 새 재사용 도구는 `platform-tools-v1` 형식의 `src/mcp/tools.py`와 `register_tools(mcp: FastMCP)`를 사용한다. 로컬은 관리되는 stdio 어댑터로 연결하며, 같은 업무 소스를 전사 HTTP 호스트에 등록할 수 있다. 전사 인증·설정·배포는 별도 확인 사항이다.
- 기존 Script Tool과 일반 stdio MCP의 형식 및 검증 경로는 보존한다. 형식이 없는 기존 AssetSpec을 자동 변환하지 않는다. 글쓰기·절차형 스킬이나 일회성 작업에 MCP를 강요하지 않는다.
- 생성 → 정적 검사 → 실제 MCP 업무 시험 → 소스에 묶인 검증 영수증 → 연결 등록을 사용한다. health 성공만으로 새 표준 도구를 활성화하지 않는다.
- 스킬의 `tool_dependencies`는 같은 선택 저장소의 검증·활성화된 도구에만 연결한다. 없는 도구, 변경된 소스/스키마, 다른 프로젝트의 연결, 등록 충돌은 구분한다. 다른 저장소/외부 MCP를 사용할 때 이 검증이 완료됐다고 표시하지 않는다.
- `asset check-skill`은 읽기 전용이다. 권한 자동 승인이나 과거 미검증 변경 초기화를 하지 않는다. 현재 세션에서 실제 도구가 연결됐는지는 별도로 확인한다.
- 통합 HTML 가이드와 설치용 Markdown의 8-2 실습도 표준 계산 도구 → 스킬 재사용 흐름으로 맞췄다. 실습은 합성 자료를 사용한다.

## 실제 시험 결과

Windows / Python 3.13 / MCP SDK 1.28.1에서 임시 폴더·격리된 `CLAUDE_CONFIG_DIR`로 실행했다. 사내 API, 모델 호출, 패키지 자동 설치는 하지 않았다.

| 검사 | 결과 |
| --- | --- |
| 기존 자산 생성·영수증·변조 방지·런타임 재연결 | 15개 통과 |
| 새 표준 생성·실제 stdio 호출·스킬 연결·실패 경로 | 15개 통과 |
| 네이티브 MCP 등록·충돌·재시도·개인/프로젝트 범위 | 12개 통과 |
| 기존 독립 HTTP 템플릿·실제 localhost 연결·호스트 계약 | 9개 통과 |
| 짧은 스킬 구조·조건부 참조 | 7개 통과 |
| 요청별 후보 선택 | 14개 통과 |
| 개인 전체/프로젝트 저장 분리 | 15개 통과 |
| 스킬 준비 절차·실제 Windows 후크 | 38개 통과 |
| 읽기 전용 분류·기존 실행 권한 보존 | 26개 통과 |
| 가이드 실습의 실제 실행 | 6개 통과 |
| 통합 가이드 내용·설치본 동기화 | 14개 통과 |
| 오프라인 Noto Sans KR·문자 범위·표 레이아웃 규칙 | 4개 통과 |
| 합계 | **175개 통과, 건너뜀 없음** |

통합 실행은 121.509초였다. 마지막 예약 도구명 검사 보완 후 새 표준 관련 15개를 다시 실행하여 모두 통과했다.

실제 Claude CLI의 `mcp add-json`을 임시 설정에서 실행해 개인 전체/프로젝트 등록을 확인했다. 별도 통합 사례에서는 CLI로 프로젝트 범위를 선택한 생성 → 실제 업무 시험 → 네이티브 등록 → 스킬 생성 → 읽기 전용 연결 확인까지 실행했다. 등록된 현재 프로젝트 외에는 연결됐다고 판정하지 않았다. 기존 사용자 계정 설정이나 실제 프로젝트의 `.mcp.json`은 변경하지 않았다.

달성률 실습은 정상, 반올림, 목표 0, 빈 목록, 길이 차이, 음수, 문자열, 참/거짓, 필수 항목 누락, 항목/값 상한, 실수 입력의 12개 사례를 실제 MCP 호출로 검증했다.

`deploy/Test-OfflineBundle.ps1 -KeepArtifacts` 최종 실행은 통과했다. 새 실행 모듈·조건부 참고 파일·호환 지원 파일·가이드가 ZIP에 포함되고 무결성 검사에 통과하는지 확인했다. 시험 파일은 임시 디렉터리에만 남겼다. Release 업로드나 설치 적용은 하지 않았다.

## 시간·문맥 사용

- 제작 스킬의 상시 본문은 기존 8,072자에서 2,263자로 줄었다. 상세 절차는 해당 작업에 필요한 참고 파일만 읽는다. 이는 문자수 비교이지 모델별 실제 토큰 측정은 아니다.
- 합성 도구 1개가 연결된 스킬의 읽기 전용 확인을 30회 측정했다. 중간값 14.00ms, 최대 25.34ms였다. 동일 프로세스 내 함수 시간으로 Python/PowerShell/Claude 승인 대기 시간은 포함하지 않는다.
- 연결 확인은 서버 시작과 모델 호출이 없다. 테스트는 검사 전후 파일 바이트가 같고 하위 프로세스를 호출하지 않음을 확인한다. 같은 대화에서 변경 없는 결과의 재사용을 안내하며 모든 작업에 새 후크를 추가하지 않았다.

## 아직 보장하지 않는 것

- HCP 등 실제 사내 모델의 자동 선택·지시 준수율, 사용자 세션의 MCP 도구 호출 성공, 회사 플랫폼의 인증·배포 성공은 이 로컬 시험으로 보장하지 않는다.
- 새 표준 경로에는 승인된 `mcp>=1.28,<2` 환경이 필요하다. 없는 경우 미검증으로 남기고 자동 설치/업그레이드하지 않는다.
- 검증 영수증·정적 검사·시간/크기 제한은 OS 샌드박스가 아니다. 테스트 입력은 명시한 합성 사례이며 외부 쓰기 시험은 별도 승인된 대상만 사용해야 한다.
- 브라우저 직접 확인은 로컬 파일 URL 정책에 차단되어 완료하지 못했다. HTML 재생성, 설치본 일치, 글꼴 포함, 문자 범위, 링크·표 규칙은 검사했지만 이번 변경의 시각 검증 완료로 표시하지 않는다.
- Codex용 일반 스킬 검사기는 통합 본문을 통과했지만 Claude 전용 호출 제어 필드를 지원하지 않는다. 호환 이름의 제어는 실제 하네스 목록 시험 및 [Claude Code 공식 호출 제어 문서](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill)를 기준으로 확인했다. 명시 호출을 보존하기 위해 `user-invocable: false`는 사용하지 않았다.
