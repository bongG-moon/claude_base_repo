보고서가 제시한 사례를 현재 작업본과 `skills_zip`의 실제 실행기로 대조했다. 현재도 재현되는 코드 문제부터 고치고, 모델이 만든 산출물의 재생성 및 설명 품질은 해당 작업에서만 적용하는 짧은 지침과 실행 예제로 보강한다. 상시 후크, 추가 분류 모델, 반복 승인 절차는 추가하지 않는다.

## 1단계 현재 재현되는 코드 결함 수정

### 파일 정리의 예측 가능한 부분 이동 방지

수정 위치는 `standalone-skills/file-organizer/scripts/organize.py`의 `plan()`과 실행 시작 전 검증이다. 현재 `move_one()`의 `target.parent.mkdir()`에 도달해야 부모가 일반 파일인 장애를 알게 된다.

- 계획에서 최종 목적지뿐 아니라 필요한 부모 경로의 존재와 파일/폴더 유형을 검사한다.
- 실행 직전 전체 계획을 다시 점검한다. 이동 도중 생긴 변경도 개별 이동 직전에 검사한다. 사전 검사만으로 모든 동시 변경을 막을 수 있다고 설명하지 않는다.
- 이미 충돌이 확인된 계획은 첫 이동 전에 차단한다. 일부 항목을 제외하여 실행한다면 바뀐 계획을 명시하고 기존 승인을 무관한 이동에 확장하지 않는다.
- 실제 실행 중 오류에 대한 영수증과 undo는 그대로 유지한다. 잠금 파일 제외는 별도의 선택적 사용성 보완으로 두며 기존 약속 위반으로 분류하지 않는다.

합격 기준: 일반 파일 `이미지`와 `b.png`가 함께 있는 합성 폴더에서 이동 수 0. 정상 자료의 이동 및 undo 해시 보존. 계획 이후 부모 유형이 바뀌는 경우도 첫 이동 전에 발견. 중간 실행 실패 시 완료/실패/미시도 수를 정확히 구분.

### 업무 분석의 후속 연결과 집계 일관성

수정 위치는 `work-context-catalog/scripts/work_process.py`의 `request_steps()`와 `summarize_work()`, `work_catalog.py`의 `pure_greeting()` 및 topic 집계, `work_report.py`의 표시 기준이다. 하네스 사본과 독립 정본을 함께 동기화한다.

- “이 월간 매출 마감 작업을 스킬로 저장해줘”와 “이 재고 집계 기준을 지식으로 저장해줘”를 후속 후보로 인식한다.
- 후보를 발견한 다음 업무명, 대상과 시간 순서, 명시적 업무 전환을 비교한다. 단순히 같은 세션의 모든 앞 작업을 합치지 않는다.
- 근거가 부족한 연결은 미확인으로 남긴다. 모델 호출이나 사용자에게 매번 연결 여부를 묻는 절차를 추가하지 않는다.
- “안녕! 고마워” 등 전체가 인사인 조합만 제외한다. “안녕! 보고서를 작성해줘”, “응”, “왜?” 같은 업무/모호한 발화는 보존한다.
- topic이 빈 기록을 한 곳에서 정규화해 JSON, HTML과 Markdown에 동일하게 적용한다. 손상 기록의 불확실성은 별도로 유지한다.

합격 기준: 근거 있는 읽기→중복 정리→집계→저장이 상세 FLOW에 이어진다. 명시적으로 다른 업무로 전환한 반례는 합쳐지지 않는다. 실패/미확인 저장이 성공으로 승격되지 않고 복사 세션의 중복 집계도 늘지 않는다. 빈 topic을 포함한 세 출력의 미분류 건수가 같다.

수동 연결을 저장하는 별도 편집기와 새 저장소는 이번 결함 수정에 필요하지 않다. 실제 수요가 생기면 후속 기능으로 검토한다.

## 2단계 다음번에도 같은 결과를 만드는 흐름 보강

### HTML 정상본 보존

현재 배포 CLI는 기존 출력 덮어쓰기를 거부하고 신규 임시 결과를 완성한 뒤 게시한다. 이 보호를 제거하거나 `overwrite`를 무조건 허용하지 않는다.

`html-report`와 실행형 자산 작성 참고자료에 재생성할 때만 사용하는 작은 예제를 추가한다. 순서는 입력 확인 → 작업 내부 staging에 분석/job/HTML/근거 생성 → 완료 검사 → 정상본 전환이다. 이전 정상본을 먼저 지우지 않는다. 여러 결과 파일을 전환할 때는 같은 실행의 파일 묶음이 유지되도록 설계하고 실패 복구 경로를 둔다. 모든 플랫폼에서 디렉터리 교체가 원자적으로 동작한다고 가정하지 않는다.

합격 기준: 잘못된 JSON, 분석 오류, HTML 작성 실패를 각각 주입해도 직전 report/job/evidence의 해시가 유지된다. 중간 파일이 없는 새 사본에서도 한 명령으로 정상 재생성된다. 최종 안내에는 하나의 결과만 노출하고 staging은 내부 자료로 관리한다.

### PPT 보정을 재생성 원본에 유지

`presentation`에서 직접 PPT만 수정하여 완료하는 흐름을 피하고, 보정을 job의 지원 필드 또는 명시된 후처리 코드에 반영한다. 재생성 경로에 포함되지 않은 보정은 완료로 간주하지 않는다.

- 같은 승인 명세로 재생성한 PPT와 전달본의 텍스트, 표, 차트, 개체 위치와 크기를 비교한다. ZIP 타임스탬프 등 때문에 PPTX 전체 바이트 동일성을 요구하지 않는다.
- 초안 상태는 가능한 한 본문 밖 미리보기 상태로 표시한다. 이미 승인된 본문의 의미를 자동으로 바꾸지 않으며 필요한 변경은 기존 승인 계약을 따른다.
- 실제 렌더가 가능하면 표 겹침, 차트 라벨 간격, 작은 글씨, 표 제목과 값의 의미를 확인한다. 수정 후에는 영향받은 장만 재확인한다.
- 렌더가 불가능하면 구조 검증만 했다고 구분한다. 고정 폰트 크기 하나로 모든 장을 실패 처리하거나 화면 검증을 했다고 간주하지 않는다.

합격 기준: 동일 job 재빌드에도 보정된 배치가 유지된다. 편집 가능한 글자, 도형, 표와 차트를 유지한다. boolean true 및 유효 해시만 제작되는 기존 승인 경계가 그대로 통과한다.

## 3단계 설명의 정확성과 불필요한 질문 줄이기

### 숫자와 범위를 함께 전달

HTML에는 이미 `facts`, 수치 참조, 단위와 출처 필드가 있다. 새 보고서 시스템을 만들기보다 데이터 기반 분석에 필요한 경우만 기존 fact에 기간, 포함/제외 범위, 분모, 출처를 구조화해 함께 전달하도록 확장한다. 표와 주석이 같은 fact를 참조하게 하고 자유문장 전부의 정확성을 자동 보장한다고 하지 않는다.

Excel→HTML→PPT 인계에는 기존 job/summary에 필요한 메타데이터를 추가한다. 별도 manifest 파일을 매번 여러 개 만들지 않는다. 기존 문서형 입력과 명세는 호환성을 유지한다. 전체 D03 34.3%와 계획 대상 34.4% 같은 서로 다른 범위를 한 지표로 덮어쓰지 않는 합성 회귀를 둔다. 보고서의 후속 HTML/PPT에서 범위가 회복됐다는 내용을 무시하고 “오류가 전파됐다”고 쓰지 않는다.

## 완료와 배포 기준

1. 현재 재현된 작은 실패 사례를 먼저 회귀시험에 고정한다. 이미 해결된 Excel과 승인 경계는 유지 검사로 둔다.
2. 해당 기능의 정상/실패 경로를 테스트한다. 관련 없는 전체 검사나 모델 재호출을 일반 사용 흐름에 넣지 않는다.
3. 생성 코드 관련 개선은 합성 자료로 같은 작업을 재실행하고 실패를 주입해 확인한다. 정적 지침 검사만으로 실제 모델의 지시 준수까지 완료됐다고 말하지 않는다.
4. 필요한 소수의 실제 모델 과제로 개선 전후를 비교한다. 같은 입력과 조건에서 완료율, 재질문, 오류 복구, 토큰과 시간을 측정하되 이 보고서의 단일 사례를 발생률이나 예상 절감률로 사용하지 않는다.
5. 원본과 하네스/독립 사본의 관계에 맞춰 동기화하고 최신 플랫폼 정본으로 ZIP 생성, `--check`, 패키지 실행 검사를 수행한다. 개인 기억/지식/쿼리와 설치 상태는 변경하지 않는다.
6. 커밋/푸시/Release는 별도 요청이 있을 때 진행하고, 공개본과 로컬 ZIP을 구분해 결과를 안내한다.
