# 1.4.22 변경·설치 안내

## 달라진 점

- Office 읽기 스킬 옆에 고정 실행 진입점을 추가했습니다. 모델이 상위 설치 경로를 다시 계산하지 않고 공통 읽기 기능을 호출합니다. Python 준비는 중복하지 않습니다.
- 현재 작업 폴더의 파일은 정확한 파일명만 전달할 수 있습니다. 실제 실행 폴더를 도구가 붙이며, 다른 폴더를 검색하거나 잘못된 절대 경로를 임의로 고치지 않습니다.
- `source_not_found` 경로 오류 메시지에 DRM이라는 단어가 들어 있다는 이유로 ‘보호 자료’로 오인하던 후크를 수정했습니다. 실제 접근 거부와 명시적 MCP 오류는 계속 구분하며 문서 셀의 오류 문구는 실행 오류로 해석하지 않습니다.
- Windows가 실제 공유/잠금 위반을 보고하면 해당 파일을 저장하고 닫은 뒤 다시 요청하도록 안내합니다. 단순히 Excel이 열려 있다는 이유나 일반 Office 시작 오류만으로 파일 잠금이라고 판단하지 않습니다.
- 파일을 찾지 못했을 때 현재 폴더를 한 번 확인하고 위치를 묻도록 스킬과 가이드를 정리했습니다. Desktop 전체 검색·세션 탐색·임의 파서 변경을 안내하지 않습니다.

정상 읽기에 추가 모델 호출이나 사전 잠금 검사는 넣지 않았습니다. 문서·범위별 승인, 회사 정책, 접근 권한, 원본 보존은 유지합니다. 사용자 Office를 강제 종료하거나 실패한 작업을 자동 반복하지 않습니다.

## 설치·업데이트

1. `company-agent-1.4.22-2026.09.03.zip`을 새 폴더에 풉니다. 파일명 뒤 날짜는 회사 지식팩 버전입니다. 기존 승인 Python 3.11 이상과 필요한 Office/라이브러리를 사용합니다.
2. `Install-CompanyAgent.cmd`를 실행하고 기존과 같은 User/Project 범위에서 백업 후 업데이트합니다. 개인 기억·지식·스킬·로그인·모델·별도 MCP 설정을 유지합니다.
3. Claude Code와 Workspace를 종료한 뒤 다시 열고 **새 대화**에서 시험합니다. Release 게시만으로 기존 설치가 갱신되지는 않습니다.
4. Workspace 안내서도 갱신하려면 이번 Release의 `company-workspace-preview-0.7-*.zip`을 별도 폴더에 풉니다. Workspace 실행 코드는 바뀌지 않았습니다.

## 업데이트 후 확인

민감하지 않은 시험 Excel을 현재 작업 폴더에 두고 `이 파일 내용을 읽고 확인해줘`라고 요청합니다.

- Office 스킬 → 준비된 명령과 정확한 파일명 → 파일·범위 승인 → 읽기 결과로 진행하는지 확인합니다.
- 승인 취소 시 문서를 열지 않아야 합니다. 파일이 없으면 위치를 묻고, 확인된 잠금이면 해당 파일을 저장·닫도록 안내한 뒤 기다려야 합니다.
- 파일이 열려 있어도 읽을 수 있는 상태라면 기존 읽기 절차를 사용합니다. 다른 이름의 사본이나 임의 Python 추출로 바꾸지 않아야 합니다.

운영 로그의 첫 실패는 존재하지 않는 실행 경로였고, 다음 실패는 Office 실행 전 파일 경로 검사였습니다. 실제 Excel 잠금이 원인이었다는 증거는 없습니다. 사내 HCP의 지침 준수, 실제 Office·DRM 동작은 회사 PC에서 확인해야 합니다.

자세한 범위는 [원인·수정 검증](VALIDATION_OFFICE_PATH_ERRORS_2026-09-21.md)과 [배포 검증](https://github.com/bongG-moon/claude_base_repo/blob/main/docs/VALIDATION_RELEASE_1.4.22.md)을 참고하세요. 이전 Release는 보존하며 별도 Cua 문서·Driver·MCP는 배포에 포함하지 않습니다.
