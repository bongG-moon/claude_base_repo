# 실행 지연·불필요 검증 개선 기록

2026-09-21, 1.4.19 이후 수정 내용으로 1.4.20 배포 대상입니다. 설치 ZIP·게시 검사는
[1.4.20 배포 검증 기록](VALIDATION_RELEASE_1.4.20.md)으로 분리합니다.
실제 사용자 로그의 “세션 연결 정보 탐색 → status 오류 → 도움말 → 재실행”에서 시작해
명령 분류, 작업자 위임, 스킬 참고 문서, Stop/학습 조건을 함께 점검했습니다.

## 발견한 원인과 변경

| 원인 | 수정 | 유지한 경계 |
| --- | --- | --- |
| 모델이 읽기 명령의 세션 ID를 직접 복사해야 함 | 현재 PreToolUse 입력의 세션·설치 상태 경로로 누락 옵션 보완 | 등록된 단독 Office 읽기 명령만 대상. 원본·범위·명시한 부모 세션/저장소는 수정하지 않음 |
| 누락 시 “후크 연결 확인”이라는 열린 지시 | 현재 정보로 1회 시도, 없으면 짧은 안내 후 중단 | 최근 세션 검색·다른 대화 ID 추측·임의 승인 없음 |
| Python 버전 조회를 파일 변경으로 오인 | 정확한 버전 조회를 변경 계수에서 제외 | 코드 실행·파일 출력·복합 명령은 기존 보수적 처리 |
| 지침대로 사용한 `-X utf8` 명령을 자체 CLI로 인식하지 못함 | 정확한 UTF-8 옵션 문법 지원 | 임의 스크립트·다른 저장소 쓰기를 조회로 간주하지 않음 |
| UTF-8 검증 기록 명령이 자신의 pass를 무효화 | 내부 검증 명령을 올바르게 인식 | 실제 변경 후 결과 확인과 미완료 의무는 유지 |
| 짧은 읽기에도 모호한 “실질 작업은 위임” | 라우팅에 `execution=coordinator` 추가, 제한된 읽기·요약은 현재 대화 | 모델 등급/별칭 변경 없음. 명시 요청·분석·변경·고위험·프로젝트 조율 유지 |
| Office 본문과 두 참고 문서의 반복 로드 | 일반 절차를 짧은 본문에 통합, 상세 문서는 필요할 때만 읽기 | 고정 Office 방식·분량 제한·보존 정책·실제 사용자 승인 유지 |

세션 보완은 `updatedInput`만 반환하고 `permissionDecision: allow`를 반환하지 않습니다.
실제 파일·범위의 사용자 승인은 별도이며, 승인 전에는 Office를 열지 않습니다.
지원하지 않는 셸 조합은 고치려 하지 않고 기존 경로로 넘깁니다. 기존 스킬 준비 차단과
위험 명령 차단이 우선합니다. 공식 동작 계약은
[Claude Code PreToolUse](https://code.claude.com/docs/en/hooks#pretooluse-decision-control)를 참고했습니다.

## 줄어든 지침 분량

LF로 통일하고 마지막 개행을 제외한 Unicode 문자 수입니다. 토큰이나 비용 측정이 아닙니다.

| 일반 Office 읽기에서 사전에 읽는 문서 | 이전 | 변경 후 |
| --- | ---: | ---: |
| SKILL.md 본문 파일 전체 | 6,561자 | 4,098자 |
| 본문 + 항상 요구하던 두 참고 문서 | 12,767자 | 4,098자 |
| 추가 참고 문서 Read 호출 | 필수 2회 | 일반 읽기는 0회, 문제 진단 시 필요한 문서만 |

추가 세션 오류 안내까지 포함해 본문 약 38%, 일반 읽기 필수 지침 약 68% 감소입니다. Skill을 실제로 처음 로드하는 과정은
유지하며, 존재하지 않는 스킬을 호출하거나 권한 제한을 생략하는 최적화가 아닙니다.
짧은 요청 판정은 휴리스틱이며 실제 파일 크기를 측정하지 않습니다. 문서 분량은 읽기 도구가 제한합니다.

## 검증

- 누락 세션 보완, 두 대화 간 분리, 명시한 부모 범위 보존, 복합 명령 제외, 권한 비자동승인 시험.
- 실제 Windows PowerShell 진입점에 세션 없는 읽기 명령을 보완하여 **첫 실행에서 승인 질문**을
  반환하는 시험 통과. 합성 파일이며 Office 본문은 열지 않았습니다.
- 합성 승인 답변 후에만 읽기 helper가 한 번 호출되고, 조회가 변경 의무를 만들지 않는 왕복 시험.
- UTF-8 검증 명령 이후 pass 유지, 기존 미검증 변경 의무 유지, 일반 Python 실행의 보수적 분류 시험.
- 짧은 읽기/요약, 작성·분석·고위험, 명시적 모델/작업자 요청의 라우팅 회귀 시험.
- Office 읽기 스킬 형식 검증, 공통 스킬의 기존 180줄 예산, 통합 가이드 원본/설치본 동기화 확인.
- 가이드 브라우저 확인: 1440/768/390px, Noto Sans KR, 117개 연결 지점, 깨진 본문·외부 요청·페이지 오류 0.
- 독립 검토에서 승인·권한 확대나 기존 변경 검증 누락 문제는 발견하지 못했습니다.

1차 개선 전체 회귀: `python -X utf8 -m unittest discover -s tests -v` — **1,165개 실행, 1,160개 통과, 5개 건너뜀, 실패 0** (302.316초).
건너뛴 항목은 Windows 심볼릭 링크 권한이 필요한 3개와 별도 허용 후 실행하는 실제 Claude CLI 설정/등록 시험 2개입니다.
검사 로그는 로컬 `.smoke/efficiency-tests-verified.log`에 있습니다. 실제 사내 모델 시험을 대신하지 않습니다.

## 추가 사례: 환경변수 조회 후 읽기 불가로 단정

사용자 로그의 `echo %company_agent_session_id%` / `env:company_agent_session_id`는
후크가 대화에 전달한 JSON을 조회한 것이 아닙니다. 이 값은 별도 로그인이나 DRM 권한이 아니라
같은 대화에서 승인한 파일·범위를 연결하는 내부 식별자입니다. 로그에는 실제 reader 호출이 없어
문서가 열리는지 여부도 확인되지 않았습니다.

추가 수정:

- 기존 회사 Office 스킬이 후보/선택일 때만 현재 ID·저장소가 포함된 `officeReadCommand`를 제공합니다.
  파일·범위는 사용자가 지정하며, 스킬 본문 로드·사용자 승인·권한 확인은 생략하지 않습니다.
- 시작/일반 요청/압축된 안내/작업자에 JSON과 환경변수의 차이를 동일하게 전달합니다.
  잘못된 환경변수 조회가 관찰되면 그 도구 결과를 바꾸지 않고 실제 후크 정보를 덧붙입니다.
  추가 모델 호출·프로세스 실행·환경 조회·다른 세션 검색은 없습니다.
- 빈 작업자 세션을 해시해 가짜 대화 ID로 만드는 경로를 제거했습니다. 실제로 전달된 native ID의
  정규화는 전달·명령 보완·승인 답변 관찰에서 통일했습니다. 예시 자리표시자는 승인 대상을 만들지 않습니다.
- 연결 정보 누락은 `conversation_context`, 문서 접근은 `not_checked`로 반환합니다.
  승인 질문은 `office_read_consent`와 `questions`가 있을 때만 처리하며, 다른 파서로 전환하지 않습니다.
- 소유한 단독 Office 읽기 명령에서 따옴표로 감싼 괄호·대괄호 경로를 허용합니다.
  셸 확장·복합 명령·리다이렉션·다른 실행 파일·자동 권한 부여는 여전히 제외합니다.
- 완료/학습 정보가 없으면 그 내부 기록만 보류합니다. 이미 수행한 업무나 읽기 결과를 실패로 바꾸지 않고,
  실제 미검증 변경은 그대로 보존합니다.

명시한 유효한 부모 세션은 임의로 현재 대화로 바꾸지 않습니다. 연결을 고치기 위해 과거 세션이나
다른 대화의 승인을 검색하지 않으며, 기존 세션 파일의 존재를 새 선행 조건으로 추가하지 않았습니다.
후크가 실제로 연결되지 않은 환경에서 사용자 승인 없이 Office를 여는 경로도 만들지 않았습니다.

추가 수정 후 전체 회귀: **1,172개 실행, 1,167개 통과, 5개 건너뜀, 실패 0** (307.547초).
건너뛴 조건은 위와 동일합니다. 로그는 `.smoke/session-context-tests.log`에 있습니다.
별도 검토자가 세션 환경변수 없이 준비된 명령을 사용하는 경로와 관련 시험 48개를 다시 확인했습니다.

## 줄이지 않은 검증과 측정 한계

- 변경 없는 조회·질문은 원래도 Stop 변경 검증 대상이 아닙니다. 이를 다시 구현하거나 모든 검증을
  끄지 않고, 조회를 변경으로 오인하는 원인을 고쳤습니다. 이전 실제 변경의 미완료 의무도 보존합니다.
- 학습은 새로운 지속적 교정이나 기존 pending 근거가 있을 때만 진행합니다. 빈 학습 검토를 요구하지 않습니다.
- Python 준비·실행 내부 계측은 모델 응답, 각 권한 판단, 질문 대기 등 전체 체감 시간을 포함하지 않습니다.
- 실제 사내 HCP의 자연어 요청·스킬 적용·승인·Office 읽기 전체 속도 및 토큰은 **미검증**입니다.
  모의 승인·helper 시험은 사용자 모델의 지침 준수나 DRM 호환성을 입증하지 않습니다.
- Python 준비 확인·회사 권한 검사·원본 변경 확인은 그대로입니다. 출처 검증을 생략하거나
  캐시의 과거 성공을 현재 권한으로 재사용하지 않습니다.

## 회사 PC에서 확인할 최소 항목

업데이트된 설치본과 새 Claude 대화에서 합성 Excel 파일을 지정하여
`이 파일 첫 시트 A1:F50 내용을 읽고 정리해줘`를 요청합니다. 스킬 이름을 미리 알려주지 않습니다.

1. 관련 스킬 본문 로드 후 세션 폴더·status·도움말 탐색 없이 승인 질문이 나오는지 확인합니다.
2. 승인 전에는 문서를 열지 않고, 취소 시 끝나며, 승인 후 같은 파일·범위를 한 번 읽는지 확인합니다.
3. 단순 읽기에 작업자·session verify·빈 학습 검토가 추가되지 않는지 확인합니다.
4. 두 대화를 따로 열어 승인/결과가 섞이지 않는지 확인합니다. 이후 파일 작성 요청은 정상 검증 대상이어야 합니다.
5. 도구명·시작/끝 시각·오류 코드·실제 제공 토큰만 기록합니다. 문서 본문·인증 값은 공유하지 않습니다.

동일 모델·파일·범위로 최초 실행과 다음 실행을 구분하고 승인 대기를 제외해 비교해야 합니다.
이 기록 없이 “몇 배 빨라짐”이나 토큰 절감률을 단정하지 않습니다.
