# Company Harness 1.4.37 배포 검증

검증일: 2026-10-07. 이번 배포는 간편 설치기, 조건부 비전 라우팅, 사용자 안내서를 포함합니다. 별도 개발 중인 Workspace 앱·CUA·실습 자료 변경은 제외했습니다.

## 검증한 범위

- 선별한 Git index를 별도 폴더로 내보내 실제 배포 소스로 사용했습니다. 원래 작업 폴더의 다른 개발 내용은 보존했습니다. 줄바꿈 자동 변환 없이 Git에 저장되는 바이트로 검증했습니다.
- 비전 라우팅·작업자 인계·기존 라우터·후크·스킬 실행·PPT 준비·디자인·설치 EXE·GitLab 포장·안내서 계약 회귀 테스트 179개가 통과했습니다. 운영 비전 설정은 시험 프로세스 안에서만 주입했고 모델 호출은 하지 않았습니다.
- 긴 경로 진단 회귀 1건을 추가한 뒤 설치기 전체 9개를 다시 통과했습니다. 중복 재실행을 제외한 검증 항목은 총 180개입니다.
- 안내서 재생성과 `--check`가 일치합니다. 한 HTML에 6개 부분·52개 장, 416,908바이트이며 설치 사본과 동일합니다. 내장 글꼴 문자 지원, Markdown 원본, 링크·모바일 표 계약도 검사했습니다.
- `New-OfflineBundle.ps1`의 플러그인 strict 검증, 회사 지식 검증, Python 구문 검증을 생략하지 않았습니다.
- 직원 ZIP의 manifest 220개 파일 해시를 검사했습니다. 플러그인 166개 파일은 분리한 배포 소스와 바이트 단위로 동일합니다. ZIP 전체는 manifest 자체를 포함해 221개 파일입니다.
- 실제 배포 EXE의 `--verify-only`가 내장 ZIP 추출·해시 검증을 통과했습니다. 설치·모델 호출·개인 설정 변경은 수행하지 않았습니다.
- GitLab 배포 준비 도구가 EXE 안의 ZIP과 직원 ZIP의 해시 일치를 확인했습니다. 사내 GitLab 접속·업로드·게시는 수행하지 않았습니다.

## 배포 준비 중 확인하고 고친 문제

긴 배포 소스 경로에서 시작 지침 크기 테스트가 5,063자로 한도를 초과했습니다. 반복되는 비전 안내를 짧게 줄인 뒤 같은 경로에서 회귀 테스트를 통과했습니다. 작업자 본문의 권한·실패 처리 지침은 유지했습니다.

깊은 빌드 폴더를 EXE 검증 캐시로 사용하면 `.prepare-…/bundle/…` 경로가 260자에 도달해 .NET Framework의 `PathTooLongException`이 발생했습니다. 빌더의 검증 캐시만 짧은 고유 임시 폴더로 옮겼고 실제 내장 ZIP 검증이 통과했습니다. 정리 시 해당 빌더가 만든 정확한 임시 경로인지 확인합니다. 사용자 설치 캐시·UAC·전역 경로 정책은 바꾸지 않았습니다.

## 운영 환경에서 확인할 사항

- `HCP-Vision-Latest`의 실제 접근 권한·이미지 이해·게이트웨이 요청 모델 로그는 검증하지 않았습니다. 사용자가 승인된 이미지로 직접 확인해야 합니다.
- 기존 `ANTHROPIC_CUSTOM_MODEL_OPTION`이 정확한 모델 ID일 때만 라우팅합니다. 사용자 모델 설정을 바꾸지 않으며 메인 모델은 유지합니다. 이미지 관찰만 별도 작업자가 하고 짧은 텍스트를 반환합니다.
- 이미지 경로를 통한 Read와 명시된 캡처 도구가 대상입니다. CLI 직접 이미지 붙여넣기, 모든 MCP의 혼합 이미지 결과, vLLM 서버 전체 요청에 적용되는 전역 라우터가 아닙니다.
- 비전 설정이 없는 PC, 이미지 확인 실패, 실제 권한 거절의 동작은 모형 시험으로 검증했습니다. 실제 회사 보안·DRM·MCP·설치 PC 전체의 성공이나 토큰·시간 개선을 보장하지 않습니다.
- GitHub Release 게시와 사내 GitLab 게시, 운영 PC 업데이트는 별도 작업입니다. 이전 Release와 이미 설치된 PC는 자동 변경되지 않습니다.
