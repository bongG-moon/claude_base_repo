# 최초 의도 대비 구현 점검

이 문서는 **1.4.19에 반영한 2026-09-20 감사 수정**을 설명합니다. 설치 방법은 [1.4.19 변경 안내](UPDATE_1.4.19.md)를 참고하세요. 기존 Release ZIP이나 이미 설치된 PC는 자동 갱신되지 않습니다. 스킬 읽기 기록·변경 관찰·위험 명령 보호·기억 검색·도구 검증·HTML→PPT 배치·Workspace 종료의 재현과 검증 근거는 [최신 감사 기록](AUDIT_HARNESS_2026-09-20.md)에 있습니다.

구현의 기준은 이미 사내 모델과 연결된 Windows Claude Code입니다. 모델 연결·API 변환 계층을 다시 구축하지 않습니다. 자동 학습과 기존 Company Agent의 업데이트 안내를 유지합니다. 일반 더블클릭도 높은 권한으로 감지될 수 있는 회사 PC를 위해 본인 사용자·세션·프로필을 확인하고, Claude 실행 파일과 설정 위치를 각각 확인합니다. 일반 Update는 기존 사용자 규칙·Hook과 개인 상태를 보존하며, 별도로 명시한 Replace만 규칙·Hook 비활성화를 수행합니다. 아래는 코드에서 제공하는 기능과 별도 업무 검증이 필요한 범위를 구분한 점검입니다.

Keep은 변경 없이 종료하며 명시한 Replace만 선택 범위의 기존 Markdown 지시·규칙과 settings의 최상위 hooks를 비활성화한다. 모델·MCP·개인 상태·일반 Skill·다른 플러그인은 유지한다. 상위 폴더/다른 범위/플러그인 자체의 Hook까지 초기화하지 않는다. 암호화 백업은 같은 Windows 사용자·PC에서 복구하며 지시 파일/새 Hook 충돌은 덮어쓰지 않고 Hook 이외의 설정 변경은 보존한다. |

새 Project Factory 검증에는 기존 파일 충돌, 수동 편집 보존과 명시적 재생성, 백업, 변경 실패 원복, 반복 실행, 조작된 manifest, junction 차단을 포함했습니다. 실제 CLI의 inspect → plan → apply → validate를 한글 경로의 일반 업무 분석 및 API 개발 예제로 실행합니다. 이 확인은 코드 생성기의 동작 검증이며 내부 모델 호출이나 사내 MCP의 통합 검증은 아닙니다.

이 구조를 Hermes와 같은 별도 자율 실행 엔진의 완전한 재구현으로 설명하면 과장입니다. Claude Code의 Hook·Skill·subagent 기능을 이용해 개인화 저장과 검증 절차를 제공하고, 프로젝트별 구성을 생성하는 확장입니다. 사내 도입 확인에서는 대표 업무 한 건의 실제 실행 결과, 선택된 worker 모델, 검증 증거, 사용자 피드백의 다음 요청 반영을 함께 확인하면 됩니다.

Karpathy·Superpowers·Ponytail·`i-have-adhd`는 필요한 원칙만 기존 흐름에 선별 반영했습니다. 원본 플러그인 전체를 설치한 것이 아니며 별도 `UditAkhourii/adhd` 추론 프로젝트는 미도입입니다. 현재 스킬 파일은 13개(자동 호출 가능 12개와 호환 안내 1개)입니다. [비교 근거·미도입 항목·검증 한계](AUDIT_HARNESS_2026-09-20.md)를 확인하세요.
