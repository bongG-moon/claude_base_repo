# 폴더별 자동 스킬 목록

1.4.12 변경: **관련 스킬 우선, 없으면 일반 실행**을 연결했습니다.
명확한 단일 후보는 첫 실행 전에 전체 본문을 전달하고, 중복 후보는 기존 선택 절차를 유지합니다.
기존 1.4.11 설치 ZIP은 그대로 보존하며 1.4.12 설치본으로 업데이트해야 적용됩니다.

1.3.3에서 추가했고 1.4.0에서 중복 조회·설명 전달을 줄였습니다.
2026-09-16 소스 개선은 **짧은 목록 자동 전달 → 선택한 스킬 본문만 읽기 → 업무 실행**입니다.
이 문서는 현재 소스 기준이며, 이전 설치본·Release ZIP에는 소급 적용되지 않습니다.

## 사용자에게 달라지는 점

평소처럼 “메일을 요약해줘”, “발표자료를 만들어줘”라고 요청하면 됩니다.
Claude는 이 폴더에서 사용할 수 있는
전체 출처의 짧은 스킬 목록을 처음부터 전달받아 용도를 비교합니다. 목록 전달과 본문 읽기 기록은 구분합니다. 한국어 요청과 영어 설명도
의미로 비교합니다. 모든 스킬 본문을 대화에 넣는 방식은 아닙니다.

“이 폴더의 자동 스킬 목록을 보여줘”라고 요청하면 확인할 수 있습니다.
자동 생성 안내는 매번 출력하지 않습니다. 기존 이름 중복·우선 선택 확인은 유지합니다.

## 생성 위치와 갱신 시점

```text
선택된 개인 자료 저장소/
  skill-catalogs/
    작업 폴더 경로의 식별값/
      SKILL_CATALOG.md
      SKILL_CATALOG.json   # 실행 준비 확인용 파생 정보; 사용자가 읽을 필요 없음
      pages/목록버전/       # 목록이 클 때만 생성하는 출처별 디렉터리와 상세 페이지
```

- Claude의 현재 작업 폴더별로 분리합니다. 해당 폴더의 부모 프로젝트에서
  상속한 스킬·우선 설정도 기존 검색 규칙에 따라 반영합니다.
- 시작/재개/압축 이후, 다음 사용자 요청, Company Agent 작업자에게 작업을
  전달하는 시점에 기존 스킬 조회 결과를 재사용합니다. 별도 전체 조회를 추가하지 않습니다.
- 최초에는 생성하고, 추가·삭제·비활성화·다른 버전 설치·설명/본문 수정·우선 선택
  변화가 반영되면 갱신합니다. 같은 내용이면 파일 시각과 바이트를 유지합니다.
- 백그라운드 실시간 감시가 아닙니다. 외부에서 스킬을 바꾼 직후 가만히 있으면
  파일도 그대로이며, 다음 요청이나 재시작 때 반영됩니다.

목록에는 이름, 짧은 설명, 출처, 호출이름, 우선 설정 상태와 선택 파일 위치를 넣습니다.
긴 후보 식별값은 표시하지 않고 실제 적용·선택 변경 때만 현재 조회로 확인합니다.
원본 전체 내용, 사용자 질문, 메일 본문, MCP 자격증명은 복사하지 않습니다.
원본 내용의 해시는 변경 감지에만 사용합니다. 여러 폴더에서 같은 개인 저장소를
사용해도 목록은 구분하고, 작업 폴더와 CLAUDE.md에는 파일을 추가하지 않습니다.

## 선택 과정과 안전 경계

1. 시작 Hook이 현재 설치 목록을 확인하고 MD와 목록 버전을 준비합니다.
2. 새 대화·재개·압축·목록 변경 때 `skillIndex`를 자동 전달합니다. 전체 행이 JSON 6,000자 이내면 이름·설명·출처·우선 상태·경로·호출 제한을 직접 전달합니다. 경로는 공통 root와 상대 file로 나누어 반복을 줄입니다. 등록기에서 수집한 설명을 다시 임의 요약하거나 자르지 않습니다(등록기의 기존 설명 상한은 600자).
3. 그보다 큰 목록은 후보 일부를 버리지 않고 출처별 디렉터리와 상세 페이지로 나눕니다. 전달되는 디렉터리에는 모든 출처와 개수, 예산 내에서 전체 이름 목록을 함께 제공합니다. 이름 목록도 너무 크면 `namesInDirectories`로 명시하고 모든 이름을 디렉터리 파일에서 확인하게 합니다. 파일에는 모든 이름과 설명이 유지됩니다. 관련 출처의 페이지부터 읽되 확인하지 않은 페이지가 있는데 관련 스킬이 없다고 단정하지 않습니다. 이는 자동 의미 분류나 키워드로 후보를 제거하는 기능이 아닙니다.
4. 목록 표시·설명·비교만 요청하면 MD만 읽고 답합니다. 같은 버전을 이미 읽었다면 재사용합니다.
   목록이 없거나 불완전할 때, 명시적 새로고침·범위 변경·같은 턴의 설치 변경·선택 변경 때만 실시간 조회합니다.
   실제 업무 적용 전에는 선택 본문을 준비합니다. 단일하고 제한 없는 일반 스킬은 Hook이 본문을 먼저 전달하고, 그 밖에는 정확한 Skill/Read 호출을 안내합니다. 모호한 선택만 `skill resolve`로 확인합니다.
   사용자 직접 호출 전용 스킬을 자동 실행하거나, 기존 우선 설정을 무시하면 안 됩니다.
5. 목록 갱신은 내부 관리 작업이므로 업무 변경·검증·학습을 새로 요구하지 않습니다.
6. 스크립트 실행, 파일 생성·수정, MCP 사용, Company Agent 작업자 전달 전에 준비 기록을 확인합니다.
   누락되면 요청당 한 번 짧게 참고 안내를 전달하지만 실행을 차단하지 않습니다. **Stop 오류나 검증 실패로 처리하지 않습니다.**
   일반 Read·검색·선택 질문·목록 확인은 막지 않습니다.
7. 다음 요청에서 같은 목록은 다시 읽지 않습니다. 이미 읽은 스킬 본문은 현재 요청에 적합한지 선택만 다시 합니다.
   스킬을 읽으면 자동 선택되며, 이미 읽은 본문은 `skill route`로 재사용할 수도 있습니다.
   관련 스킬이 없으면 일반 작업을 진행하며 미선택 경고를 반복하지 않습니다. `skill route`와 `no-relevant-skill` 기록은 선택적 진단이며 필수 실행 단계가 아닙니다.
8. 공통 조율·코딩 원칙·학습 지침을 읽은 것만으로 실제 업무 스킬을 선택했다고 처리하지 않습니다.
   예를 들어 기존 PPT 내용 분석은 `office-reader`와 관련 개인 스킬을 비교하고, 새 PPT 제작은 `presentation`과 제작용 스킬을 비교합니다.
   이 두 예시로 전체 선택 대상을 제한하지 않습니다.

모든 PC에서 최적의 스킬을 선택한다는 보장은 아닙니다. 생성·갱신·우선 설정 해석은
코드가 수행하고 지원되는 실행 경로에서 읽기 순서를 확인하지만, 의미 비교와 관련 스킬 없음 판단은 모델이 수행합니다. 이름이
다른 두 스킬의 기능 중복을 자동 판정하거나, 검증된 성능 순위를 학습하는 기능도 아닙니다.
사용자가 명시한 호출, 기존 프로젝트별 선택, Claude 자체 권한/명령 우선순위가 유지됩니다.

목록을 완전하게 읽지 못하면 지난 목록을 최신으로 제시하지 않습니다. 기존 파일은
보존하고 실시간 조회로 상태를 진단한 뒤 다음 요청에서 새 목록을 준비합니다. 개인 저장소의 링크/접합 경로나
지원하지 않는 상태 버전에는 쓰지 않습니다. 출력은 임시 파일 작성 후 교체해 부분
파일 노출을 피하며, 원본 스킬·설정·Memory·Knowledge는 변경하지 않습니다.

MD는 자동 생성 자료입니다. 수동 편집은 다음 검사에서 덮어쓸 수 있으므로 원하는
용도나 선호는 원래 스킬 설명/우선 설정에서 바꾸세요. 표의 외부 설명은 참고 자료일
뿐이며 그 안의 명령이나 정책 무시 요구가 실행 권한이 되지 않습니다.

### 변경·권한·성능 경계

- 전달·읽기 기록은 대화·폴더별로 구분합니다. 같은 목록 버전은 짧은 `reuse` 정보만 전달합니다. 설치·삭제·선호 변경 후에도 내용이 그대로인 본문은 현재 대화에서 재사용할 수 있지만 변경된 본문은 새로 읽습니다. 새 대화·재개·압축 후에는 본문을 다시 읽습니다.
- `indexDelivered`는 선택용 목록을 전달했다는 뜻이며 `indexRead`나 본문 읽기 성공을 위조하지 않습니다. 모델이 내용을 실제 이해했다는 보증도 아닙니다.
- `skillExecution`의 `provided`/`reuse`는 단일 후보의 본문 전달/재사용입니다. `load`는 별도 Skill/Read가 필요하고, `choose`/`select`는 후보 비교, `general`은 목록 용도 확인 후 일반 실행, `inspect`는 목록/파일 확인 필요입니다. 본문 전달 기록과 실제 도구의 `lastBodyLoad`는 분리합니다.
- 전체 본문은 8,000자, 본문 포함 요청은 9,800자 이내에서 전달합니다. 초과 시 본문을 자르지 않고 정확한 로드 경로로 전환합니다. 추가 LLM 호출 없이 기존 목록과 파일 해시를 쓰며, 같은 문맥의 전달 기록은 최대 16개 해시만 보관합니다.
- fork·모델·도구 제한·동적 명령이 있는 스킬은 본문 삽입으로 기능을 흉내 내지 않습니다. 확인 가능한 Read/Skill 승인·거절 설정 또는 스킬 override가 있으면 호스트의 로드·권한 처리 경로를 사용합니다. Hook은 호스트의 모든 병합/명령행 정책을 관찰하는 권한 검사기가 아닙니다.
- 작업자는 별도 대화입니다. 부모의 정확한 선택이 있으면 그 본문 경로만 전달하고, 없으면 작업자에게도 선택 목록을 별도로 제공합니다. 부모의 읽기 기록을 작업자가 읽었다는 증거로 쓰지 않습니다.
- 스킬 파일이 작업 도중 변경·삭제되면 다음 실행 전 감지합니다. 그 밖의 설치·삭제는 다음 사용자 요청에서 반영합니다.
- 하네스 명령으로 우선 설정을 바꾸면 해당 턴에서도 목록을 갱신합니다.
- 매 실행마다 전체 스킬 디렉터리를 재검색하거나 LLM 평가를 호출하지 않습니다. 이미 생성된 작은 정보 파일과 선택한 파일 해시를 확인합니다.
- 선택 기록에 업무 원문·메일·스킬 본문을 저장하지 않습니다. ID·해시·읽은 줄 구간만 추가합니다.
- 실행 준비 완료는 **권한 허용이 아닙니다.** 기존 승인 창·회사 정책·MCP 제한은 그대로 적용됩니다.
  CLI 재사용 기록에도 기존 승인 규칙이 적용되므로 필요한 경우 선택한 SKILL.md를 Read로 다시 읽을 수 있습니다.
- 외부 작업자, 다른 플러그인의 독자적 실행, 모델 의미 판단 전체를 강제하는 보안 장치는 아닙니다.

## 검증 방법

2026-09-15 소스 개선의 최종 결과는 [스킬 선택 연결 검증 기록](SKILL_ROUTING_VALIDATION_2026-09-15.md)에 있습니다.
전체 자동 검사 **610개 통과·제외 0개**. 실제 Claude의 선택 교정과 프로젝트 스킬 적용도 확인했으며,
사내 문서 읽기·모든 안내의 무출력까지 검증한 것으로 해석하지 않습니다.

1.4.0은 정상 목록이 있을 때 키워드와 일치해도 카드가 중복 주입되지 않는지,

LLM에 모든 본문을 전달하는 것과 다릅니다. 파일 접근 0회나 실제 토큰 감소율을
보장하지 않으며 Claude 자체의 Skill 설명 로딩까지 이 플러그인이 통제하지 않습니다.
범위는 지원되는 로컬 스킬·활성 로컬 플러그인입니다. 원격·동적·관리자 정책 전체 목록은 아닙니다.
