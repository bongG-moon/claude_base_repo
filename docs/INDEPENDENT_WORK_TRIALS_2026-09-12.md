## 실제로 발견하고 반영한 개선

1. **불필요한 폴더 탐색 승인**: 일반 파일 찾기·읽기는 기본 파일 도구를 우선하도록 수정했습니다. 실행 작업자에게도 같은 지침을 적용했습니다.
2. **실행하지 않은 명령이 거절됐다는 잘못된 설명**: 개별 명령의 거절과 전체 도구 사용 불가를 구분하고, 실제 관찰한 실행·검증만 보고하게 했습니다. HTML 작업에서는 해당 Skill을 먼저 읽고 정해진 생성 경로를 사용합니다.
3. **승인 대기를 실패로 오인한 재시도**: 승인되지 않아 수행하지 못한 검사는 `unavailable`/`partial`로 구분합니다. 보류한 작업을 다른 작업자에게 넘겨 재시도하지 않으며, 미검증 변경 의무는 지우지 않습니다. 승인된 범위가 새로 생겼을 때만 이어갑니다.
4. **문서의 조건 누락·수정 후 남은 옛 설명**: 실제 저장 문서를 읽고 원자료의 예산, 날짜, 제외 조건, 확정 여부와 비교합니다. 표를 수정하면 제목·요약·‘변경 없음’ 표현도 함께 확인합니다. 파일이 존재한다는 확인만으로 내용 검증을 주장하지 않습니다.
5. **학습 순서와 재시도 혼선**: 업무 완료 표시를 먼저 마친 뒤 학습 검토를 제출하도록 했습니다. 오류 반환에도 임시 입력 삭제 여부와 재작성 필요 여부를 함께 알려줍니다. 기존 재시도 한도는 유지합니다.
6. **학습 영수증을 최종 답변으로 보고**: 성공한 내부 학습 명령 직후 조용히 원래 업무 결과로 돌아가도록 안내합니다. 중간 설명도 같은 원칙입니다. 사용자가 학습 내역을 물었거나 실제 조치가 필요한 경고는 예외입니다. Claude 자체의 도구 실행 표시는 숨기지 않습니다.
7. **좁은 화면에서 한 글자씩 줄바꿈되는 표**: HTML 생성기의 표 최소 열 너비와 표 내부 스크롤을 보완했습니다. 전체 페이지 넘침과 표 내부 스크롤은 구분합니다.
8. **모델 등급을 지시만 하고 직접 수행**: 실질적인 업무는 해당 실행 작업자를 실제 호출하도록 명료화했습니다. 호출하지 않았다면 모델을 바꿨다고 말하지 않습니다. 작업자 호출과 사내 모델의 실제 매핑은 별도의 검증 사항입니다.
9. **지침 증가로 지식 카드가 밀려남**: 전체 컨텍스트 상한은 늘리지 않고 지침을 줄였습니다. 낮은 순위의 중복 Skill 카드를 먼저 덜어내어 관련 지식 한 종류가 통째로 사라지지 않도록 조정했습니다.
10. **주 대화가 작업자에게 실행 경로를 전달하지 않음**: Company Agent의 세 실행 작업자에 한해서 호출 직전 정확한 CLI·개인 상태·플러그인·현재 세션·선택 Skill 경로를 자동으로 덧붙입니다. 다른 플러그인의 작업자는 변경하지 않고, 선택 모델·기존 요청은 보존합니다. 실행 승인 결정을 자동 허용으로 바꾸지 않습니다. 이는 [Claude Code의 PreToolUse 입력 보완 기능](https://code.claude.com/docs/en/hooks#pretooluse-decision-control)을 사용합니다.

이 중 모델의 판단을 안내하는 지침은 결정적인 보안 통제가 아닙니다. 실제 파일·메일·DB 권한은 기존 도구와 운영 환경의 정책이 최종적으로 통제해야 합니다.

## 개인화 확인 범위

- ‘기억해줘’ 명령이나 관찰자가 작성한 성공 기록 없이, 업무 종료 후 추출된 선호가 개인 Memory로 저장됐습니다.
- 새 대화 시작 때 해당 개인 Memory가 실제 전달되는 것을 확인했습니다.
- 교육 사례에서는 이전 결과물을 읽지 못하게 한 새 업무에서도 보고 순서가 적용됐습니다.
- 같은 예산표 선호를 고치자 기존 Memory ID의 개정 번호가 올라갔고, 별개의 기존 선호는 유지됐습니다.
- 모호한 선호가 한 번 자동 포착되지 않은 사례도 있었습니다. 모든 발언을 반드시 학습하는 시스템으로 표현하지 않습니다. 명확한 현재 지시는 저장 여부와 관계없이 현재 업무에 적용해야 합니다.
- 이번 세 업무는 기본 Skill 사용과 선호 학습 중심입니다. 자동으로 개인 Skill 코드 전체를 새로 작성하거나, 개선 효과의 인과관계를 증명한 실험은 아닙니다.
- 별도의 다음 사용 효과 평가(assessment) 기록은 이 업무에서 확인되지 않았습니다. 현재 Skill 평가 경로는 실제 읽고 적용한 개인 Skill의 정확한 개정판을 대상으로 하므로, 기본 Skill로 문서를 만들고 선호 Memory를 재사용한 것과 구분해야 합니다.

## 실행 환경과 안전 경계

실제 Claude Code 실행, 실제 대화 ID, 같은 대화의 `--resume`, 다른 업무의 새 대화 ID를 사용했습니다. 테스트 실행기의 단위 테스트에 사용하는 가짜 응답은 이 실제 사용 증거와 구분합니다.

기존 Claude 인증과 모델 설정을 재사용하되 별도 프로젝트·개인 상태·플러그인 스냅샷을 사용했습니다. 기존 `settings.json`과 설치된 플러그인 목록은 실행 전후 해시를 비교했습니다. 설정 파일의 비밀값은 보고서에 복사하지 않았습니다.

가상 자료만 사용했습니다. 실제 메일 발송, 구매, 예약, DB 수정, 보호 우회, 기존 사용자 설정 변경은 하지 않았습니다. HTML 생성에 필요한 명령은 해당 가상 입력과 새 출력 경로를 확인한 뒤 정확한 명령만 별도 승인했습니다. 전체 Bash 허용이나 보안 해제는 사용하지 않았습니다. 이 도구별 승인 설정은 운영체제 수준의 완전한 격리 환경과 같지는 않습니다.

사내 HCP 모델 별칭 연결, Office 2016 Outlook/Exchange/PST, 회사 DB, DRM은 이 PC의 가상 업무만으로 운영 검증 완료라고 말할 수 없습니다.

## 다시 실행하는 개발자용 방법

`scripts/test-lab/work-trial.py`는 업무 질문이나 정답을 내장하지 않은 실행기입니다. 허용된 작업자 폴더 안의 `operator`에 새 요청을 작성한 뒤 다음처럼 실행합니다.

```powershell
python scripts/test-lab/work-trial.py run --root C:/Users/qkekt/Desktop/Company-Agent-Work-Trials-20260912/worker-one --prompt-file C:/Users/qkekt/Desktop/Company-Agent-Work-Trials-20260912/worker-one/operator/request.txt --conversation next-work --timeout 300
```

같은 `--conversation` 이름이면 실제 대화를 이어갑니다. 다른 이름이면 새 대화입니다. 소스 수정 후 `refresh --root <작업자 폴더>`를 실행하면 개인 상태와 업무 파일을 유지하면서 새 플러그인 스냅샷을 만듭니다. Claude 실행이 끝난 뒤 갱신해야 합니다. 승인할 명령의 스냅샷 경로도 다시 확인해야 합니다.

일반 직원용 설치 파일을 실행한 것이 아니라 개발 검증용 환경입니다. 사용자의 실제 Claude 설치는 이 테스트만으로 업데이트되지 않습니다.
