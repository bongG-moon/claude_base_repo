# 한 작업의 최종 결과만 전달하기 — 검증 (2026-09-19)

## 반영 범위

- HTML/PPT 기본 스킬은 `business artifact-start`로 내부 작업 공간과 최종 목적지를 한 번 정한다.
- `html`, `ppt-design-preview`, `ppt`, `ppt-template`은 같은 `--work`를 사용한다. 작업자·초안 승인·내부 수정에서도 이 값을 유지한다.
- 초안·JSON 명세·수정 시도·PPT 검사용 이미지는 내부 작업 공간에 둔다. 실제 내용/화면 확인 후 `artifact-publish`로 최신 후보 한 개만 최종 폴더에 전달한다.
- 전달을 반복하거나 완료한 작업을 다시 제작하려 해도 같은 결과를 반환한다. 임의 `v2` 파일을 만들지 않는다. 파일 내용이 바뀌었거나 목적지에 다른 파일이 생겼으면 기존 파일을 보존한다.
- 마지막 수정이 실패했거나 보호 제한/잘못된 JSON이 있으면 이전 후보를 전달하지 않는다. 다른 작업/이전 단계의 PPT 초안도 최신 승인으로 인정하지 않는다.
- 기존 `--output` 제작 호출은 호환성을 유지한다. 직접 PPT 제작에서도 검사용 이미지는 기본적으로 임시 공간에 둔다.
- 준비 명령은 내부 기록으로 분류하지만 실행 권한을 자동 승인하지 않는다. 이전 업무의 미검증 변경도 지우지 않는다.
- 다음 사용자 요청, 명시적으로 요청한 복수 형식·비교안·HTML 대표 양식은 별도 결과로 만들 수 있다. 코드 프로젝트의 소스 파일 수를 제한하지 않는다.
- 기존 파일을 일괄 삭제하거나 중간 캐시를 자동 정리하지 않는다. 사용자 기억/지식/모델/MCP 설정은 변경하지 않았다.

## 실제 PowerPoint 경로

가상 자료로 다음 검증기를 실행했다. 승인 값은 시험에서만 모사했다.

```text
python -X utf8 -B scripts/test-lab/check-ppt-html-roundtrip.py --output .smoke/single-delivery-20260919 --single-delivery --render
```

- HTML 초안 3회 생성: 합계 195.2ms. 이 PC의 단일 측정이며 모델 응답/사용자 확인 시간은 제외한다.
- 초안 생성 중과 PPT 검사 중 최종 프로젝트 폴더는 비어 있었다.
- 설치된 PowerPoint로 5장 모두 이미지 출력 성공. 5개 이미지는 내부 작업 공간에만 있다.
- PPT는 텍스트 25개, 표 2개, 차트 1개의 네이티브 개체로 생성됐다. 표 셀과 차트의 145/175/210 값을 다시 열어 대조했다.
- 최종 전달 후 `.smoke/single-delivery-20260919/project/`에는 `monthly-editable.pptx` **한 개**만 있다. 전달/제작 재호출 뒤에도 파일 개수가 늘지 않았다.
- 시험 증거와 별도의 양식 재사용 시험은 project 밖의 검증 폴더에 저장했다.

## 한계

- 실제 사내 HCP 모델의 대화 전체를 재현한 검사가 아니다. 설치 환경에서 스킬 절차를 따르는지는 추가 운영 시험이 필요하다.
- 이번 변경은 저장/전달 방식이며 디자인을 바꾸지 않는다. 이번 실행에서 이미지를 새로 육안 검토했다고 주장하지 않는다.
- 임의 Bash/Write·타사 생성기의 모든 파일 출력을 막는 보안 장치는 아니다.
- 내부 캐시는 복구를 위해 남는다. 기존 작업 폴더에 이미 쌓인 파일을 삭제하지 않았다.
- 앱이 작업 폴더 밖 파일을 제한하면 기존 파일 선택기로 해당 미리보기를 선택한다. 미리보기 때문에 사본을 늘리거나 앱의 경로 제한을 완화하지 않는다.
