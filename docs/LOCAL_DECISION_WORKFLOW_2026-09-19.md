# 외부 판단 API 없는 스킬 준비와 실행 관찰

## 적용 범위

Jev의 좁은 판단과 실제 실행을 분리하는 원칙만 참고한다. Jev SDK/API, 별도 계정·키, 모델 서버, 새 상시 Hook은 추가하지 않는다. 기존 Claude CLI/HCP와 개인 로그인·모델·MCP 설정을 그대로 사용한다. 이것은 새로운 의미 분류 모델이나 모델의 지침 준수 보장이 아니다.

## 판단과 실행의 분리

`skill_decision.py`는 이미 검증된 목록 스냅샷과 기존 후보 검색 결과만 입력으로 받는 순수 함수다. 파일·네트워크 접근, 본문 주입, 권한 변경, 도구 실행을 하지 않는다. 검색 점수를 확률이나 정확도처럼 표시하지 않는다.

| 상태 | 의미 | 다음 행동 |
| --- | --- | --- |
| general | 자동 사용 가능한 로컬 스킬이 없음 | 세션에 별도 스킬이 있는지 고려하고, 관련 스킬이 없으면 일반 실행 |
| review | 키워드 후보는 없지만 목록에는 스킬이 있음 | 이미 제공된 목록의 용도를 기존 Claude 세션에서 비교 |
| choose | 같은 이름의 후보나 기존 선택이 모호함 | 출처와 차이를 보여 주고 사용자 선택 대기 |
| select | 여러 업무 단계 또는 여러 후보가 있음 | 용도를 비교; 같은 역할이 겹칠 때만 질문 |
| load | 현재 목록의 사용 가능한 단일 후보 | 요청에 맞는지 확인하고 실제 Skill/Read로 본문 로드 |
| reuse | 같은 대화에서 읽은 변경 없는 본문 | 기존 본문 재사용; 권한·네이티브 실행 의미 유지 |
| inspect | 목록·후보·본문의 상태가 불완전하거나 변경됨 | 실제 목록/정확한 경로 확인, 스킬 부재로 단정 금지 |

후보의 ID는 현재 목록과 다시 대조한다. 삭제된 후보·중복 ID·명시 호출 전용 스킬을 임의로 로드하지 않는다. 후보가 전달한 경로/호출명을 신뢰하지 않고 검증된 목록의 실제 값을 사용한다. 기존 사용자 선택·출처 우선 설정·본문 해시 검증은 유지한다. 이 판단 계층에서는 ‘업무 실행 완료’를 판단하지 않는다. 실행 응답은 아래의 별도 관찰 기록이며 결과 검증과도 구분한다.

관련 스킬이 있는지의 최종 의미 판단은 기존 Claude 세션에 남아 있다. 명시 선택/모호한 요청을 처리하기 위해 새 모델을 호출하지 않는다. 없는 스킬을 만들어 호출하거나 선택 기록용 명령을 필수로 추가하지 않는다.

## 실행 관찰과 결과 검증의 분리

`workflow_evidence.py`는 기존 PostToolUse/PostToolUseFailure의 상태 저장에 합류한다. 현재 실행부의 정확한 business 명령을 관찰했을 때만, 현재 요청의 최신 기록 하나를 보관한다.

- 스킬 목록 전달, Skill 성공, SKILL.md 읽기는 업무 명령 실행 성공이 아니다.
- 응답을 받은 시점의 본문 상태와 업무 명령 결과를 별도로 보관한다. 이것만으로 실행 전 로드 순서, 그 본문의 실제 적용, 결과 내용의 정확성을 증명하지 않는다.
- 도구 미실행, 오류, 중단, 부분 완료, 취소, 제한, 입력 대기, 실행기 성공 보고, 결과 해석 미확인을 구분한다. 셸 종료 코드 0만으로 성공하지 않는다.
- 본문은 로드했지만 명령 응답이 없으면 실행 미관찰이다. 본문 없이 실행기 성공 응답이 와도 스킬을 사용했다고 기록하지 않는다.
- 도움말·목록 조회·선택 사양 검증·작업자 시작 응답을 업무 실행 성공으로 세지 않는다. 일반 셸 코드, 개인/외부 스킬, 다른 실행부는 임의로 대응시키지 않는다.
- 임의 리다이렉트 파일을 추가로 열지 않는다. 큰 출력/잘린 출력/알 수 없는 호스트 응답은 미확인이다.
- 저장 항목은 요청 ID와 정해진 명령 종류·결과 상태·본문 관찰 상태뿐이다. 문서·대화·파일 경로·명령·오류 원문은 새 기록에 저장하지 않는다.
- 새 요청/압축/프로젝트 변경은 실행 관찰을 재사용하지 않는다. 기존 본문 재사용은 별도로 유지한다.

진단 JSON과 기존 HTML 진단 화면에 `workflowProgress`를 표시한다. 새 관찰은 진단용이며 권한 허용, Stop 재시도, 스킬 선택, 기존 변경 검증 통과의 근거로 사용하지 않는다. 검증은 기존 절차에서 실제 확인한 범위만 보고한다.

## 시간·토큰 제한

- 추가 모델/API 호출 0회. 새 지침·새 관찰 기록을 일반 모델 컨텍스트에 넣지 않는다.
- 기존 목록 revision/본문 해시 재사용을 유지한다. 순수 판단 함수는 기존 메타데이터만 사용한다.
- 관찰은 기존 상태 쓰기에 합류하므로 별도 세션 파일 쓰기나 폴링을 추가하지 않는다.
- 응답 JSON 확인은 최대 65,536문자다. 나머지는 미확인으로 남긴다.
- 준비 누락 1회 교정/일반 폴더 조회 예외는 변경하지 않는다. 새 차단·재시도 루프·성공 마커 명령을 추가하지 않는다.

## 검증 방법

`tests/test_local_skill_decision.py`에서 스킬 없음/후보 누락/명시 호출 전용/충돌/가짜 ID/본문만 로드/실행 결과/실패/부분 완료/권한 거절/출력 제한/새 요청 격리/민감정보 제외를 검사한다. 기존 전체 회귀 테스트와 실제 CLI + 로컬 고정 응답 전송 검증을 함께 실행한다.

문자 수는 토큰 수가 아니며 로컬 준비 시간은 사내 모델·승인·Office 처리 시간을 포함하지 않는다. 실제 사내 HCP의 자율 스킬 선택과 DRM 문서 읽기는 별도 운영 검증 대상이다. 이 변경은 설치본 배포 완료를 뜻하지 않는다.

## 2026-09-19 검증 결과

- 신규 판단·실행 관찰·진단 테스트: 19개 통과.
- 전체 회귀 재실행: 898개 실행, 896개 통과, 환경 조건에 따른 2개 제외, 오류 0개(199.3초).
- 최초 전체 실행에서는 로컬 HTTP 보안 테스트 1개에서 Windows 연결 중단(10053)이 발생했고, 이후 기대 예외 객체 확인도 실패했다. 해당 모듈 재실행은 43개 중 42개 통과·1개 제외, 전체 재실행도 통과했다. 원인을 단정하거나 서버 코드를 변경하지 않았으며, 재발 여부는 별도 관찰 대상이다.
- 실제 Claude CLI + 로컬 고정 응답 서버: 목록 확인 후 본문 로드, 목록 누락 후 기존 1회 교정 시나리오 모두 통과(각 7.3초, 4.39초). 외부 모델·실제 사내 문서는 사용하지 않았다. 이는 도구·Hook 전달 경로 검증이지 HCP의 자율 판단 정확도 측정이 아니다.
