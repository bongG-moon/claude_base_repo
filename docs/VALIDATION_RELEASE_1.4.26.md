## 이번 검증에서 수정한 부분

1. 긴 설치 경로에서 후크 기본 문맥 제한을 초과하면 실행 명령·세션 정보를 통째로 잃던 실제 결함을 수정했습니다. 한도를 늘리지 않고 중복 안내를 추가로 축약합니다. 필수 경로를 자르거나 임의로 만들지 않습니다.
2. “읽은 내용을 HTML 보고서로 만들어줘”에서 완료된 입력 참조를 신규 읽기 동작으로 오인하던 회귀를 수정했습니다. 기존 실패 테스트 기대값은 그대로 유지했고 “다시 읽고”, “안 읽은” 등 실제 읽기가 필요한 경우도 검사했습니다.
3. Workspace 안내에는 있었지만 별도 ZIP에서 빠졌던 `Check-Workspace.cmd`·진단 스크립트·진단 안내를 포함했습니다. 진단 스크립트의 시작 파일 해시도 확인합니다.
4. 일반 단어 `우회/bypass`까지 일괄 금지하던 낡은 문서 테스트는 구체적인 제거 대상 문구를 검사하도록 바꾸고, 실제 권한 거절 보호를 반드시 유지하는 별도 회귀를 추가했습니다.
5. PPT 문구 테스트를 최초 모든 장 → 수정 후 영향 범위 → 공통 변경·범위 불명확 시 모든 장이라는 실제 계약에 맞췄습니다. 품질 기준을 낮추지 않았습니다.

초기 전체 실행의 샌드박스 WS-31 실패는 실제 사용자 실행에서 재검사하여 통과했습니다. 이를 위해 사용자 권한 확인·보안 가드를 해제하거나 UAC·계정·개인 설정을 변경하지 않았습니다.

## 미확인 범위와 제한

- 이 Windows 계정은 심볼릭 링크 생성 권한이 없어 산출물·하네스 맵·Workspace 관련 실제 링크 생성 검사 3개가 생략됩니다. 이를 해결하려고 사용자 정책을 변경하지 않았습니다.
- 사내 HCP·게이트웨이와 외부 개인 스킬의 실제 동작, 토큰 절감률·전체 업무 지연 감소는 검증하지 않았습니다. 파일·모의 도구 기반 계약 검사가 약한 모델의 모든 요청 준수를 보증하지는 않습니다.
- 브라우저 접근 제한을 다른 경로로 우회하지 않았습니다. 새 HTML의 실제 화면·인쇄·실제 SVG/PNG 다운로드 검증은 미실시이며 Node VM·기하·HTTP 검사를 시각적 E2E 확인으로 표현하지 않습니다.
- 일반 권한 UAC 연결 토큰이 없는 관리자 회사 PC의 WS-33 제한은 남아 있습니다. 개발 PC의 일반 사용자 테스트 통과가 그 환경 지원을 뜻하지 않습니다.
- 운영 PC의 실제 설치·업무 적용은 별도 확인이 필요합니다. 실제 개인 모델·MCP·기억과 회사 보안 설정은 변경하지 않았습니다.
