# 스킬 실행 결함 재검증과 수정

검증일: 2026-10-29. 외부 검토에서 지적한 증상을 현재 소스와 개별 배포 ZIP으로 재현했다. 개인 설정, 개인 기억, 개인 스킬과 운영 자료는 수정하지 않았다.

## 확인된 문제와 수정

| 항목 | 재현한 문제 | 반영한 수정 |
|---|---|---|
| PPT 승인 | 독립형 `build`는 `confirmed:false`여도 초안 해시가 맞으면 생성했다. 하네스 CLI의 앞단에는 이미 승인 확인이 있었다. | 공통 제작 진입점에서 승인 기록의 형식과 실제 boolean `true`, 명세 해시, HTML 초안 해시를 확인한다. 승인 기록이 같으면 재사용한다. |
| Excel 기간 | 26시간이 `1 day, 2:00:00` 문자열과 날짜 타입으로 저장되어 생성한 프로젝트를 재실행할 때 실패했다. | 기간을 날짜와 구분하고 누적 시간 문자열 `26:00:00` 또는 Python `timedelta`로 보존한다. |
| Excel 합산 | 0.1을 68개와 0.05 한 개 합산한 뒤 반올림하면 SUM과 SUMIF/SUMIFS의 결과가 6.9와 6.8로 달랐다. | SUM, SUMIF, SUMIFS와 AVERAGE가 동일한 수치 누적 함수를 사용한다. 해당 사례와 음수 사례가 각각 6.9와 -6.9로 일치한다. |
| 한국어 요청 분류 | `읽고 원본의 5행을 변경해 줘`는 조회, `삭제하지 말고 내용만 알려줘`는 변경 업무로 분류됐다. | 변경 동사와 띄어쓰기를 처리하고 부정된 동작 구절만 제외한다. 뒤에 있는 실제 변경 요청과 명시한 모델 등급은 유지한다. |
| 스킬 위임 | 작업자 안내가 선택한 SKILL.md를 무조건 Read하도록 해, 정식 Skill 호출이 필요한 실행 조건과 충돌할 수 있었다. | 이미 확인한 `load`, `nativeRequired`, fork 여부를 전달한다. native 호출을 파일 읽기로 바꾸지 않으며 fork 작업을 일반 작업자로 반복 실행하지 않는다. |
| 불필요한 제작 후보 | `초안을 확인받아 제작`의 `확인`을 문서 읽기 능력으로 보아 PPT 내용 조회에도 제작 스킬이 끼어들었다. | 승인을 받는 표현과 실제 내용을 읽는 표현을 구분한다. 회사와 개인 스킬에 같은 규칙을 적용한다. |

승인 JSON은 승인한 초안과 생성 대상의 일치를 검사하는 기록이다. 사용자 의사 자체를 인증하는 장치가 아니므로 호스트는 실제 대화의 승인 답변을 근거로 기록해야 한다. 모델이 작성한 `true`만으로 실제 사용자가 승인했다고 주장하지 않는다.

## 독립 실행 범위

개별 스킬의 실행 단위는 `skills_zip`의 **전체 ZIP을 설치한 폴더**다. HTML과 PPT의 개발 원본 폴더는 패키징할 때 공통 제작 모듈을 포함한다. 원본 SKILL.md나 scripts만 복사한 폴더와 설치된 전체 배포본은 다르다. 설치된 배포본은 Company Harness와 세션 ID를 요구하지 않으며 Python 등 명시한 환경 의존성은 필요하다.

## 확인 방법

- 승인 전, 잘못된 승인 형식, 초안 또는 내용 변경은 실패하고 출력 PPT가 생성되지 않는지 확인했다. 변경 없는 승인 기록은 반복 사용했다.
- 13개 시트, 6,802개 수식이 있는 합성 파일에서 프로젝트 생성과 `main.py` 재실행을 확인했다. DATA를 `51:30:00`으로 교체해 51.5시간 계산을 확인하고 PROCESS 및 원본 파일 해시가 유지되는지 검사했다.
- xlwings 경로는 합성 SpreadsheetML과 이미 읽은 Value2로 기간값 복원을 검사했다. 실제 Office 앱이나 매크로를 실행한 검증은 아니다. 원래 일수를 확인할 수 없으면 날짜나 하루 안의 시각으로 추측하지 않는다.
- 혼합 요청과 부정 표현, 모델 등급 유지, 실제 변경을 추적하는 기존 완료 절차를 함께 검사했다.
- 외부 스킬의 `context: fork`, `model`, `allowed-tools`, `hooks` 조건이 위임 때 사라지지 않는지 합성 로드 기록으로 검사했다. 이전 선택을 전달할 때 본문을 추가로 읽지 않는다.
- 플랫폼 배포 정본을 확인하고 소스, 하네스 사본, 개별 ZIP, 카탈로그 및 체크섬을 동기화했다.

처음 패키지 검사에서는 Excel 추가 수정 중의 이전 ZIP 해시 불일치와 시험 Python의 Flask 부재를 확인했다. 최종 ZIP을 재생성하고 Flask가 있는 로컬 시험 환경에서 34개를 모두 다시 통과했다. CMD 실행 검사 1건은 샌드박스의 PowerShell 정책으로 거절되어, 개인 설정을 바꾸지 않고 같은 격리 자료를 승인된 실행 환경에서 다시 시험해 통과했다.

### 남아 있는 별도 작업본 문제

`test_skill_execution.SkillExecutionTests.test_prompt_never_injects_body_and_stays_small`는 현재 별도 진행 중인 비전 코드가 포함되면 약 5,307자로 5,000자 기준을 초과한다. 새 스킬 연결 수정 전의 런타임을 대입해도 실패하며, 기존 커밋의 비전 동작으로 한정하면 4,807자로 통과했다. 경로 길이에 따라 문자 수는 달라진다. 이번 수정에서 기준을 높이거나 비전 변경을 되돌려 성공 처리하지 않았다. 비전 안내의 일반 요청 주입 범위는 해당 변경을 배포하기 전에 별도로 정리해야 한다.

## 비용과 검증 한계

추가 LLM 호출, 상시 후크, 승인 질문 또는 사용자 프로필 탐색을 넣지 않았다. 계산과 기존 실행 확인 단계의 로컬 코드만 보완했다. 요청 분류의 로컬 마이크로벤치마크는 약 60.14µs에서 72.61µs로 변했으며 실제 모델 처리 시간이나 토큰 측정값은 아니다.

이번 결과는 로컬 실행과 합성 자료에 대한 회귀 검증이다. 실제 사내 모델의 자동 스킬 선택률과 지시 준수율, 게이트웨이 연계, 실제 Excel 앱의 계산 결과 일치, Outlook 계정 연계 및 PPT 화면 렌더링 전체를 검증한 것으로 확대 해석하지 않는다. 공식 Skill 호출과 본문 Read의 차이는 [Claude Code Skill 문서](https://code.claude.com/docs/en/skills#run-skills-in-a-subagent)를 참고했다.

이번 수정은 로컬 소스와 `skills_zip`에 반영했다. 이 문서 작성 작업에서 GitHub Release 게시나 사용자 PC 설치는 수행하지 않았다.
