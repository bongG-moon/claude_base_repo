# 1.4.31 변경·설치 안내

## 달라진 점

### 기억 저장 위치를 결과에서 바로 확인합니다

- 저장·조회 응답에 실제 적용 범위, 기억 ID, 버전과 확인 정보를 제공합니다. 예전 파일의 `scope: personal`을 보고 프로젝트 기억을 개인 전체 기억으로 오판하지 않도록 소유권과 적용 범위를 구분합니다.
- 기존 기억을 고칠 때는 같은 ID와 원래 개인/프로젝트 범위를 유지합니다. 확인한 버전·내용 해시가 달라졌으면 덮어쓰지 않습니다. 같은 내용을 다시 저장한 경우에는 새 변경으로 안내하지 않습니다.
- 저장 명령 안에서 해당 기억의 기록 결과를 확인합니다. 성공 뒤 파일·설정·세션을 다시 찾거나 저장 확인만을 위해 Stop 응답을 이어가지 않습니다. 이 확인은 해당 기억 항목만 대상으로 하며 다른 업무의 미검증 변경을 완료 처리하지 않습니다.

### 이전 기억 복원과 학습 사용 중지를 구분합니다

- `memory history`로 해당 항목의 남아 있는 버전과 현재 상태를 확인하고, `memory restore`로 같은 범위에서 이전 내용을 새 버전으로 복원할 수 있습니다. 이후 수정된 항목은 조건부 확인에서 중단하며 오래된 내용으로 덮어쓰지 않습니다.
- 자동학습된 선호의 `learning rollback`은 현재 선호를 **비활성화**하는 동작입니다. 이전 선호 본문을 복원하는 동작이라고 안내하지 않습니다. 스킬 학습 되돌리기는 학습이 소유한 점검 구역만 대상으로 합니다.
- 기억 버전 백업과 자동학습 변경 이력은 별개입니다. 실제 보관된 기억 버전이 없으면 `memory restore`로 복원했다고 표시하지 않습니다. 학습 조회의 기록 해시는 현재 파일을 새로 검사했다는 증거가 아닙니다.
- 자동학습은 기존 활성 설치의 저장소를 유지합니다. 명시적 프로젝트 기억을 개인 전체로 옮기거나, 기존 수동 기억을 자동학습 소유로 바꾸거나, 개인·프로젝트 간 학습 이력을 자동 합치지 않습니다. 범위를 넘나드는 자동학습은 이번 변경에 포함하지 않습니다.

### 표와 요약의 순서를 제작 명세로 전달합니다

- HTML·PPT 기본 제작 명세에 선택적 `contentOrder`를 추가했습니다. “표 먼저, 그 아래 요약” 같은 순서를 지정하면 HTML의 문서 순서와 세로 배치, PPT의 편집 가능한 개체 배치에 반영합니다. 순서를 지정하지 않은 기존 결과는 기존 배치를 유지합니다.
- 없는 블록·중복·모순된 배치 요구는 명세 검사에서 확인합니다. PPT의 자유 배치 `elements`나 전체 화면 이미지 방식과 콘텐츠 순서를 무분별하게 섞지 않습니다. 공간이 부족하면 내용을 몰래 누락하거나 배치를 바꾸지 않습니다.
- 생성된 HTML 구조와 확인 가능한 PPT 배치·개체를 프로그램으로 검사하고, 그 확인 범위와 화면 확인을 구분합니다. 구조 검사가 글의 품질·문장 수·모든 화면의 가독성까지 보증하지는 않습니다. 사용자가 승인한 다른 배치는 이번 결과의 기준으로 삼고 장기 선호를 자동 수정하지 않습니다.

## 실행 비용과 기존 기능

새 후크·별도 검증 모델·필수 비전 모델 호출·학습을 위한 Stop 반복을 추가하지 않습니다. 필요한 확인은 기존 저장·생성 명령 안에서 처리합니다. 기억 이력 조회와 복원은 사용자가 요청한 변경에만 사용하며 매 답변의 기본 단계가 아닙니다. 자동학습의 근거·중복·소유권·현재 요청 연결 검사는 유지합니다.

사용자 안내서와 관련 스킬 설명을 같은 구분으로 갱신했습니다. 선택형 Workspace는 기존 **0.9** 실행 코드와 학습 카드를 유지하고 안내서만 갱신합니다. 별도로 개발 중인 Workspace 버전·실행기·권한·화면 변경은 이 배포에 포함하지 않습니다.

## 설치·업데이트

1. Release에 게시되는 `company-agent-1.4.31-2026.09.03.zip` 전체를 새 폴더에 풉니다. 뒤의 날짜 **2026.09.03**은 회사 지식팩 버전입니다.
2. 기존과 같은 설치 범위를 선택하여 백업 후 업데이트하고 Claude Code를 다시 시작합니다. 개인 Memory·Skill·Knowledge·모델·별도 MCP·인증 설정을 보존합니다.
3. 안내서만 확인하려면 Release의 단독 `Company-Agent-User-Guide.html`을 엽니다. 설치본과 Workspace에는 `Company-Agent-사용자-안내서.html`로 같은 사용자 안내서를 포함합니다.
4. Workspace를 쓴다면 기존 창을 닫고 별도 0.9 묶음을 새 폴더에 풉니다. 하네스만 업데이트해도 이미 풀어 놓은 Workspace 파일이 자동 갱신되지는 않습니다.

공개 파일 게시 여부는 [1.4.31 Release](https://github.com/bongG-moon/claude_base_repo/releases/tag/v1.4.31)에서 확인합니다. GitHub의 자동 `Source code (zip)`은 직원용 설치 ZIP이 아닙니다. 승인된 Python 3.11 이상과 Claude Code가 필요하며 설치 과정에서 새 런타임·모델·외부 도구를 다운로드하지 않습니다. 이전 태그·ZIP·개인 자료를 덮어쓰거나 설치된 PC를 자동 갱신하지 않습니다.

## 확인 범위와 한계

자동 검사·패키지 점검·업데이트 결과와 최종 배포 파일 해시는 [1.4.31 배포 검증](VALIDATION_RELEASE_1.4.31.md)에 기록합니다. 이전 버전의 검증 문서는 당시 이력으로 보존합니다.

로컬 코드 검사와 사내 모델이 지침을 정확히 적용하는지는 다릅니다. 실제 사내 HCP의 업무 성공률·체감 속도·토큰 절감량, 회사 Office·DRM을 연결한 통합 품질은 별도 확인이 필요합니다. 이번 버전은 수치로 효과를 측정했다고 주장하지 않습니다. Workspace의 WS-33, 비전 모델·게이트웨이·회사 보안 정책을 해결하거나 변경하는 배포도 아닙니다.
