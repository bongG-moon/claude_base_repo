# HTML 배치 → 편집 가능한 PPT 확장 검증

## 원인

기존 제작기의 presentationPlan은 text/table/chart/image만 표현했다. 단일 그림과 본문이
함께 있으면 그림에 본문 너비의 64%를 배정했고, 그림은 contain만 지원했다.
스킬은 모델 작성 임의 Python/VBA 실행을 막으면서도 이 제한을 보완할 공식 개체 API를
제공하지 않았다. 따라서 “카드/그림자 불가”, “그림 크기 지정 불가”는 PowerPoint의
제약이 아니라 당시 제공한 제작기/지침의 제약이었다.

HTML-first 기능도 동일한 고정 job을 HTML과 PPT로 각각 렌더링하는 구조였다.
사용자가 별도로 작성한 HTML/CSS 배치를 가져오는 기능은 없었다. 기존 HTML 대표 양식
저장 기능은 있었으나 색상/폰트/페이지 규격만 저장했다. 운영 PC의 실제 설치 상태나
과거 Memory 내용은 이 로컬 검사에서 변경하거나 현재와 같다고 가정하지 않았다.

## 반영

- `ppt_scene.py`: 네이티브 rect/roundRect/ellipse, 단색/투명도, 테두리, 외부 그림자,
  text 및 이미지의 명시적 위치/크기, contain/cover/stretch. 네이티브 표/차트 유지.
- `htmlSource`로 고정 크기의 정적 HTML 페이지를 읽고, 브라우저가 계산한 flex/grid
  위치 및 줄별 텍스트를 동일한 승인/제작 plan으로 변환한다. 1920×1080 입력은
  960×540 포인트. 슬라이드 전체 이미지로 대체하지 않는다.
- 소스 스크립트는 제거하고 안내, 프레임/네트워크 리소스는 가져오지 않는다. 양식
  계산 스크립트는 제품에 포함된 고정 코드이며 해시 CSP로만 허용한다. 임시 브라우저
  프로필을 사용한다. 사용자 브라우저나 Office를 강제 종료하지 않는다.
- 승인된 배치는 검토 HTML에 저장한다. 최종 PPT에서는 브라우저를 다시 띄우지 않고,
  소스/참조 CSS·그림 및 초안의 해시를 확인한다. 소스 수정은 새 초안으로 반영한다.
- `ppt-fit-images`: 기존 PPT의 선택한 그림만 새 파일에서 수정한다. 한 장에 그림이
  여러 개면 실제 shapeIds가 필요하다. ppt-analyze에 그림 번호를 추가했다.
- 이미지 수정은 새 디자인 질문/HTML 승인 절차를 요구하지 않는다. 동일한 artifact
  work 내부 검토 후 최종 결과 하나만 전달하고 원본은 보존한다.
- HTML 대표 양식 layoutVersion 2는 카드/그림자/텍스트 배치까지 저장한다. 본문,
  수치, 캡처, 출처 경로, 승인 기록을 저장하지 않는다. 가상 텍스트·표·차트와 그림
  자리만 저장하고 새 자료를 명시적인 슬롯에 넣는다. 기존 v1 양식도 호환된다.
- `ppt-capabilities`로 현재 설치의 기능/필수 구성요소를 확인한다. 과거 기억의
  “불가능”을 현재 기능으로 단정하지 않도록 안내했다. 설치/Memory 자동 수정은 없다.

## 검증

1. 관련 회귀 검사 194개: 193개 통과, 기존 심볼릭 링크 권한 검사 1개 건너뜀.
   새 `test_ppt_native_layout.py` 22개는 모두 통과했다.
2. 사용자 지정 로컬 HTML(1920×1080, 5장)로 실제 경로를 시험했다. 원본 해시 보존.
   HTML/PPT 텍스트를 공백 제외 전체 대조해 일치했다. 텍스트 199개, 도형 97개,
   그림 0개. CSS로 만든 막대는 도형이며 네이티브 데이터 차트로 세지 않았다.
3. 실제 PowerPoint로 5장 모두 렌더링하고 화면을 확인했다. 카드/그림자/태그/구성과
   본문이 유지됐다. 후속 재실행의 5개 PNG는 앞서 확인한 PNG와 모두 동일한 해시였다.
4. 10pt 미만인 원본 하단 출처/페이지 글자 10개를 tiny_text 경고로 남겼다. 원본의
   자간 효과 경고도 남겼다. 이를 모두 통과/완벽 일치로 바꾸지 않았다. 원자료의
   수치 근거나 사실관계는 이번 변환 검증의 범위가 아니다.
5. 해당 5장으로 HTML 대표 양식 저장 → 본문 제거 확인 → 새 텍스트로 다시 적용을
   시험했다. 장별 개체 수/배치가 유지됐다. 검증용 양식은 내부 작업 공간에만 있다.
6. native table/chart, 그림 cover/contain/stretch, 기존 그림만 변경, 다중 그림 선택,
   원본/기존 출력 보호, 제한된 입력 거절, 참조 파일 변경 시 승인 무효화, 이전 자동
   배치/템플릿 유지, 동일 작업 publish 재실행에 의한 중복 파일 방지를 검사했다.
7. Windows 로컬 Chrome에서 HTML 배치 추출 약 2.7~3.9초(5장, 환경별 차이 있음).
   최종 생성에서 capture를 다시 호출하면 실패하도록 테스트해 재사용을 확인했다.
   추가 모델/API/패키지 다운로드는 없다. PowerPoint 렌더링 시간은 이 측정과 별도다.
8. 로컬 Edge 153.0.4234.32는 이 PC에서 dump-dom 표준 출력을 반환하지 않았다.
   실패 후 자동 우회/재시도를 하지 않았다. Chrome 153.0.8010.52 경로를 별도로
   명시해 검증했고, 자동 선택은 설치된 Chrome 우선이다. Edge만 있는 운영 환경은
   별도 확인이 필요하다. 브라우저 부재/시간초과/실패는 한국어로 반환한다.
9. 스킬 구조 검사, 사용자 매뉴얼 재생성/일치 검사, 오프라인 번들 검사 통과.
   번들 필수 파일 목록에 새 Python/JS/스킬 참고 문서를 추가했다.

재현 도구: `scripts/test-lab/check-ppt-native-html.py --source <사용자 HTML> --output <격리 폴더>`.
사용자 HTML과 시험 산출물은 Git 대상이 아닌 `.smoke`에만 두었다. 실제 프로젝트 출력
폴더와 운영 설치본/Release/개인 설정/Memory에는 쓰지 않았다.

## 지원 범위와 남은 한계

- 편집 가능한 텍스트는 줄/서식 단위로 나뉠 수 있다. 웹 문단의 자동 재배치와 동일하지 않다.
- HTML 표는 native table이지만 셀 테마를 PPT 스타일로 만든다. CSS 막대는 도형이다.
- SVG/canvas, 복잡한 필터/회전/그라디언트 배경, 다중/안쪽 그림자, 병합 표, 동적
  스크립트로 생성되는 본문은 일반적인 완전 변환 대상이 아니다. 원인을 알리고
  해당 요소의 단순화/개별 그림 사용 여부를 확인한다. 전체 슬라이드 이미지 대체는 없다.
- 고급 자유 배치/HTML 가져오기/기존 그림 변경에는 기존 python-pptx가 필요하다.
  없을 때 COM 기본 배치로 몰래 강등하거나 패키지를 설치하지 않는다.
- 일반 HTML 페이지와 저장된 PPT용 HTML 대표 양식은 서로 다른 입력 경로다.
  잘못 --template으로 지정하면 htmlSource 사용법을 안내한다.
- 사내 HCP 모델이 실제 설치 후 스킬과 안내를 따르는지는 운영 환경 재검증이 필요하다.
  이번 작업은 소스 수정과 로컬/패키징 검증이며 커밋·배포·설치본 갱신은 하지 않았다.

## 참고한 제작 방식

사용 가능한 presentation/skill-creator 지침과 로컬 dashiai-ppt의 editable export 구조를
검토했다. DOM 배치 → 네이티브 개체라는 원칙을 참고하되 외부 내보내기 코드를 복사하거나
Node/PptxGenJS/브라우저 자동화 패키지를 사내 설치 요건에 추가하지 않았다.
기존 Python 제작기를 확장하고 HTML/PPT에서 같은 배치/승인 기록을 사용했다.

공식 API에서도 둥근 도형과 위치/크기 조절은 지원한다.
[python-pptx AutoShapes](https://python-pptx.readthedocs.io/en/latest/user/autoshapes.html).
이미지 자르기/맞춤도 PPT 개체의 속성이며 전체 화면 그림을 사용자가 수동 삽입해야만
하는 제약은 없다. [python-pptx Picture](https://python-pptx.readthedocs.io/en/latest/dev/analysis/shp-picture.html),
[PptxGenJS Images](https://gitbrent.github.io/PptxGenJS/docs/api-images/).
