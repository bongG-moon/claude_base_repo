# 요청형 사용성 개선 보고서 검증

검증일: 2026-10-29. 기존 기록을 요청할 때만 로컬에서 집계하는 기능을 추가했다. 실제 개인 대화 기록, 사용자 설정과 운영 자료는 시험에 사용하거나 수정하지 않았다.

## 사용 방법과 범위

`/company-agent:usability-report`를 요청하면 현재 업무 폴더의 최근 7일을 기본으로 분석한다. 기간은 1~30일로 지정할 수 있다. 반복 오류, 같은 질문, 재읽기 및 최근 실행 준비 기록에서 먼저 검토할 후보를 최대 3개로 추린다. 사용자에게는 쉬운 설명과 다음 행동을 보여주며, 후보를 원인이 확정된 결함이나 낭비로 단정하지 않는다.

결과는 새 HTML 하나다. 상세 수치와 수집 한계를 펼쳐 볼 수 있고 같은 내용을 Markdown으로 내려받을 수 있다. 이전 보고서 비교는 요청했을 때만 수행하며 같은 프로젝트, 같은 기간 길이, 겹치지 않는 기간인지 확인한다. 서로 다른 업무량을 보정한 성능 평가나 개선 효과의 인과 증명은 아니다.

## 일상 작업에 미치는 영향

- 상시 후크, 자동 실행, 추가 질문, 분석용 모델 호출, 예약 작업을 추가하지 않았다.
- CLI 파서는 명령을 등록하지만 수집기와 보고서 생성기는 요청된 명령에서만 불러온다.
- 기존 내부 명령 판별에 정확한 보고서 명령을 추가했다. 해당 명령이 스킬 선택과 종료 확인을 다시 요구하지 않는지 검사했다. 실행 권한을 자동 승인하거나 다른 명령과의 연결 실행을 허용하지 않는다.
- 원본 대화와 도구 본문은 모델 입력이나 결과물에 복사하지 않는다. 현재 대화에는 경로와 개선 후보를 담은 짧은 실행 결과만 반환한다.
- 자동 `/compact`는 추가하지 않았다. 보고서 자체의 분석량과 반환량을 제한한다. 사용자가 긴 대화 정리를 원할 때 현재 목표, 결과 파일, 확인한 사항과 남은 사항을 보존하는 방법을 안내한다.

모델 추가 호출은 0회지만 요청한 보고서를 설명하는 기존 대화 응답과 로컬 파일 분석에는 시간이 든다. 실제 사내 모델의 토큰 절감률이나 처리 속도를 측정한 결과는 아니다.

## 기록 처리와 한계

- 현재 프로젝트의 기본 Claude 대화 기록과 지정한 하네스 저장소의 최신 상태만 읽는다. 다른 프로젝트와 하위 에이전트 기록은 자동 포함하지 않는다.
- 대화는 실제 기록 시각으로 기간을 거른다. 하네스 상태 파일은 최신 스냅샷으로만 표시하며 기간 전체의 평균이나 실패 횟수로 합산하지 않는다.
- 복사와 분기된 기록의 공통 메시지, 요청 및 도구 호출 식별자를 중복 제거한다. 스트리밍 사용량은 메시지별 최대값을 사용한다. 누락된 토큰은 0이 아니라 미확인으로 남긴다.
- 읽기 상한은 총 32MiB, 줄당 1MiB, 50,000개 기록, 전체 후보 200개다. 대화와 상태 파일은 각각 최대 100개다. 잘림과 누락을 보고서에 표시한다.
- 심볼릭 링크와 재분석 지점은 따라가지 않는다. 읽는 중 바뀐 파일이나 프로젝트가 섞인 파일은 제외한다. 기존 결과 파일도 덮어쓰지 않는다.
- HTML에는 대화 원문, 명령, 오류 본문, 원본 경로와 세션 ID를 넣지 않는다. 외부 리소스 연결과 실행 스크립트 없이 생성한다.
- 보고서가 비어 있다고 정상으로 판정하지 않는다. 같은 질문과 재읽기도 필요한 동작일 수 있다.

화면 직접 검증은 브라우저 도구가 로컬 `file:` URL을 보안 정책으로 거절해 수행하지 못했다. 다른 경로로 우회하지 않았다. HTML 구조와 다운로드 데이터는 코드로 확인했지만 브라우저에서의 배치와 다운로드 버튼 클릭까지 확인한 것으로 표현하지 않는다. 실제 사내 모델과 실사용 기록으로 한 검증도 아니다.

가상 예제: `outputs/usability-report-20261029/사용성-개선-보고서.html`. 실제 업무 기록의 분석 결과가 아니라 기능 확인용임을 화면에 표시했다.

이번 기능은 하네스의 명시적 명령으로 제공한다. 별도 독립형 스킬을 추가하거나 기존 개인 스킬을 변경하지 않는다. 통합 사용자 안내서와 명령 설명도 갱신했다. Git 커밋, 푸시, 온라인 Release 게시와 사용자 프로필 설치는 이번 작업에서 수행하지 않았다.
