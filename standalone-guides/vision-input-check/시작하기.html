무엇이 다른가요?

시험이미지 전달 방식실행
A사용자 메시지에 일반 이미지로 넣기스크립트 1회
BRead의 도구 결과 안에 동일 이미지 넣기스크립트 1회
C실제 Claude 비전 작업자가 파일을 Read로 읽기새 대화에서 별도 요청
B는 실제 CLI가 아니라 전송 형식 재현입니다. A/B는 모델·이미지·질문·시스템 지침·도구 정의·출력 상한(각 600토큰)이 같습니다. B만 도구 호출/결과 이력이 더해집니다. A의 답을 B에게 보내지 않습니다.

비전 기능을 지원하는 모델이어도 회사의 현재 연결 경로가 정상이라고 확정할 수는 없습니다. 이 시험은 원인 범위를 좁히는 용도입니다.

1. 보내기 전 준비 확인

이 폴더에서 터미널을 열어 한 줄을 실행합니다. Python 3.9 이상이면 되고 패키지 설치는 없습니다.

python -X utf8 compare_inputs.py

mode: offline, network_calls: 0이면 완료입니다. 기본 실행은 네트워크도 인증값도 Claude 설정도 읽지 않습니다.

2. 승인된 회사 주소로 비교하기

담당자에게 승인된 게이트웨이 주소·모델명·인증 방식을 확인한 뒤 아래 주소를 바꿉니다.

python -X utf8 compare_inputs.py --send --base-url "https://승인된-게이트웨이" --model "HCP-Vision-Latest"

인증값은 다음 입력란에 넣습니다. 화면에 표시하거나 파일에 저장하지 않습니다. 명령어에 인증값을 쓰지 마세요. 기본은 Bearer 인증이며 회사가 x-api-key를 요구할 때만 --auth-header api-key를 추가합니다.

승인 주소가 HTTP라면 --allow-http가 필요합니다. HTTP는 인증값과 이미지를 암호화하지 않습니다. 승인받지 않은 주소로 보내지 마세요. 주소 이동(redirect)은 모두 차단하며 TLS 검증을 끄지 않습니다.

results-날짜-시간/comparison.json을 메모장으로 열어 A/B 답변을 정답표와 비교합니다. 응답 모델명, 토큰, 시간도 기록됩니다. 응답이 왔다는 표시와 정확히 읽었다는 판정은 다릅니다.

자동 재시도·OCR·모델 교체는 없습니다. 기본 네트워크 대기는 요청당 60초이며 전체 작업의 절대 시간 보장은 아닙니다. 요청 원문·base64·인증값·서버 오류 본문은 저장하지 않습니다. 답변은 최대 4,000자, 알려진 인증값과 긴 인코딩 문자열을 제거하지만 공유 전 직접 확인해 주세요.

두 번째 그림은 추가 확인이 필요할 때만 같은 명령 끝에 --image sample-02.png를 붙여 실행하세요. 그때만 2회가 추가됩니다.

3. 실제 Claude에서 읽기

sample-01.png만 별도의 빈 업무 폴더로 복사하고 앱에서 그 폴더를 엽니다. 안내서·스크립트·정답표는 복사하지 마세요. 새 대화에서 이미지 붙여넣기 대신 파일을 읽도록 요청합니다. 메인 모델 설정은 그대로 둡니다.

sample-01.png만 회사 비전 작업자로 한 번 읽어줘. 이미지에 실제로 보이는 문자와 숫자를 위에서 아래, 왼쪽에서 오른쪽 순서로 적어줘. 도형의 색·모양·위치도 알려줘. 안 보이면 추측하지 말고 판독 불가라고 해줘. 안내서·정답표·스크립트·다른 파일은 읽지 말고, OCR이나 다른 방법으로 바꾸지 말고 결과만 알려줘.

활동 내역에서 company-agent:vision-worker와 해당 파일의 Read 호출을 확인합니다. 실패하면 재시도나 설정 탐색 없이 멈추세요. 실제 서버 보고가 없으면 모델명은 ‘미확인’입니다.

일반 이미지 첨부를 승인된 회사 UI에서 별도로 시험할 수도 있지만, 앱이 내부적으로 Read로 처리할 수 있으므로 A와 같다고 단정하지 마세요.
