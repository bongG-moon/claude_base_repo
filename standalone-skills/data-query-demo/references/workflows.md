# Python 연속 조회와 작은 미리보기

이 문서는 A의 조회 결과를 B의 조건으로 쓰거나 행을 조금만 확인할 때 읽습니다. 일반 조회마다 읽거나 별도 후크로 실행하지 않습니다. 사용자는 원하는 업무를 말하고 스킬이 명세와 작은 조건 파일을 `data-query-demo/.work/`에 준비합니다. 후처리 Python도 이 안에 두고 전달할 CSV나 HTML은 `data-query-demo/outputs/`에 저장합니다. 경로는 현재 업무 폴더 기준이며 사용자가 지정한 경로는 그대로 따릅니다.

## A 결과로 B 조회하기

예를 들어 “오늘 배정된 장비를 찾고, 그 장비들의 현재 상태를 조회해줘”는 다음처럼 나눕니다.

1. 등록된 A 쿼리를 새로 실행해 장비 ID를 로컬 결과 파일에 저장합니다.
2. Python이 A의 특정 열에서 null을 제외하고 중복을 제거합니다. 모델에 ID 목록 전체를 읽히지 않습니다.
3. B 쿼리의 `IN (:equipment_ids)` 목록 바인드 조건으로 전달해 새로 조회합니다. 값을 SQL 문자열에 붙이지 않습니다.
4. A와 B의 결과 번호, 조건 연결과 실행 상태를 로컬 계보 파일에 기록하고 답변에는 건수와 위치만 전달합니다.

현재 도우미는 같은 스킬 범위 안의 두 단계를 지원합니다. 운영 스킬끼리 연결을 임의로 바꾸거나 데이터를 다른 계정으로 옮기지 않습니다. 가상 연습은 준비된 가상 연결만 사용하며 실제 접속으로 전환하지 않습니다.

다음은 이미 등록한 두 쿼리를 연결하는 명세 예입니다. 쿼리 번호, 날짜와 열 이름은 실제 등록 목록과 스키마에 맞춥니다. 예시의 번호가 현재 사용자 저장소에 존재한다고 가정하지 않습니다.

```json
{
  "source": {
    "queryId": 1,
    "params": {"fac_id": "ICPKG", "work_date": "2026-11-02"}
  },
  "target": {
    "queryId": 2,
    "params": {},
    "fromColumn": "equipment_id",
    "toParameter": "equipment_ids"
  },
  "allowPartialSource": false
}
```

A는 위의 조건을 받는 쿼리여야 하며, B의 `equipment_ids`는 목록 자료형으로 등록합니다. 예를 들어 해당 조건 정의는 `{"equipment_ids":{"type":"list[text]","required":true}}`이고 SQL에는 `WHERE equipment_id IN (:equipment_ids)`를 사용합니다. Datalake에서는 쿼리의 실제 `lake_catalog.스키마.테이블` 경로가 조회 대상을 정합니다. 이 명세에 DB 접속 주소를 다시 등록하지 않습니다.

```text
python -X utf8 -B "<현재 스킬 절대경로>/scripts/query.py" workflow --spec <연속 조회 명세 JSON> --confirm
```

`source.params`와 `target.params`는 JSON 객체입니다. CLI `--params`에 파일과 인라인 JSON을 쓰는 것과 구분합니다. B의 다른 고정 조건은 `target.params`에 넣고 `toParameter`에는 A에서 만든 값만 전달합니다. 각 단계의 `options`에는 필요한 조회 한도를 지정할 수 있으며 한도 확대와 넓은 기간은 기존 승인 절차를 따릅니다.

## 중간 단계에서 멈추는 경우

- A가 정상 0건이거나 전달 열에 null만 있으면 B를 실행하지 않습니다. 빈 목록을 조건 없는 조회로 바꾸지 않습니다.
- A가 실패했으면 오류 코드와 가린 이유를 알리고 B를 실행하지 않습니다. 부분 결과가 남아 있어도 정상 입력으로 간주하지 않습니다.
- A가 행 수나 파일 한도로 일부만 저장됐으면 기본적으로 B를 실행하지 않습니다. 사용자가 그 일부 범위를 명시적으로 허용한 경우에만 `allowPartialSource: true`로 다시 계획합니다. 후속 결과도 그 제한된 범위임을 표시합니다.
- 고유값이 500개를 넘거나 조건이 너무 크면 임의로 앞부분만 쓰거나 자동으로 수백 번 조회하지 않습니다. 필요한 범위를 줄이거나 별도 Python 처리 계획을 정합니다.
- B의 큰 조회 승인이 필요하면 아직 B가 실행되지 않았음을 알리고 반환된 `planId`와 범위로 기존 `run --plan <ID> --confirm --allow-large`를 이어갑니다. A를 무조건 처음부터 재조회하지 않습니다. 단, 계획이 만료되거나 조건이 바뀌면 새 계획이 필요합니다.

도우미가 A를 매번 새로 실행하는 것은 실시간 정보의 임의 캐시 재사용을 막기 위한 기본값입니다. 사용자가 과거 결과 재사용을 명시한 경우에는 해당 파일의 조회 시각과 조건, 완전성을 확인하는 별도 Python 처리를 사용하고 그 선택을 기록합니다. 예전 결과가 있다는 이유만으로 이 흐름을 대신하지 않습니다.

## 승인 뒤 중단 지점에서 이어가기

A 또는 B가 승인 대기로 멈추면 응답의 `workflowId`와 그 단계의 `planId`를 보존합니다. 새 `workflow --spec`을 실행하면 A를 다시 조회하므로 같은 작업을 이어갈 때는 `--resume`을 사용합니다.

```text
python -X utf8 -B "<현재 스킬 절대경로>/scripts/query.py" run --plan <반환된 단계 계획 ID> --confirm --allow-large
python -X utf8 -B "<현재 스킬 절대경로>/scripts/query.py" workflow --resume <반환된 workflowId> --confirm
```

실제 허락을 받은 같은 계획만 실행합니다. 큰 조회가 아니라 전체 조건 검토만 필요한 계획이면 `--allow-large`를 생략합니다. A 승인 뒤 `run`을 완료했다면 `--resume`은 그 A 결과에서 B로 이어가며 A를 다시 조회하지 않습니다. B 승인 뒤 실행까지 완료했다면 같은 흐름의 `--resume`은 완료 기록을 반환하고 B를 중복 실행하지 않습니다. 아직 계획을 실행하지 않았다면 승인 대기 상태를 그대로 알립니다.

흐름의 SQL이나 명세가 바뀌거나 계획이 만료됐다면 예전 허락으로 자동 실행하지 않습니다. 오류와 결과 기록 경고가 있으면 같은 조회를 반복하지 말고 어느 단계까지 확인됐는지 설명합니다. 단순한 재개는 현재 명시한 작업 안의 이어가기이며, 다른 시점의 과거 결과를 새 요청에 임의로 재사용하는 허락이 아닙니다.

## 코드로 더 복잡한 후처리하기

`dataFile`의 JSONL과 같은 폴더의 `metadata.json`을 사용합니다. 전체 파일을 모델에 출력하지 않고 필요한 열만 한 줄씩 처리합니다. 집계, 조인과 새로운 조건 만들기도 Python에서 수행하고 답변에는 처리 건수와 필요한 집계만 반환합니다. 날짜는 ISO 문자열, 정밀한 소수는 문자열일 수 있으므로 자료형을 명시적으로 변환합니다.

직접 Python으로 여러 단계를 확장할 때도 A의 오류와 부분 결과를 먼저 확인하고, 결과 값은 B의 검증된 바인드 조건으로 전달합니다. 단순히 오류를 피하려고 `IN` 조건을 제거하거나 사용자 범위를 넓히지 않습니다. 승인 대기, 실행 완료와 실패를 단계별로 구분해 기록합니다.

## 필요한 행만 미리보기

기본 조회와 연속 조회 응답에는 원문 행을 반환하지 않습니다. 사용자가 표의 일부나 값 예시를 요청한 때만 다음을 사용합니다.

```text
python -X utf8 -B "<현재 스킬 절대경로>/scripts/query.py" preview --id <결과 ID> --rows 5
python -X utf8 -B "<현재 스킬 절대경로>/scripts/query.py" preview --id <결과 ID> --rows 10 --columns equipment_id status
```

기본 5행, 최대 20행, 최대 40개 열이며 열 이름과 행을 합쳐 8,000자 안에서 반환합니다. 긴 셀과 넘치는 부분은 잘랐음을 표시하고 원본 파일은 그대로 둡니다. 저장 행 수와 표시한 행 수를 구분하며 미리보기 행을 전체 결과로 설명하지 않습니다. 실패한 조회의 부분 파일을 정상 미리보기로 보여주지 않습니다.

더 많은 데이터가 필요하면 `--rows`를 반복해 전체 파일을 대화에 쌓지 않습니다. Python으로 전체 저장 파일을 처리하고 결과 표는 별도 파일이나 HTML로 전달합니다. 현재 결과의 요약을 만드는 일과 과거 결과를 새 조회 대신 재사용하는 일은 구분합니다.
