# 데이터 조회 연습

요청한 데이터 조회만 수행합니다. 이 스킬은 로컬 Python 실행기로 동작하며 별도 하네스, MCP 등록이나 상시 후크가 필요하지 않습니다.

## 사용 흐름

1. 현재 스킬의 `scripts/query.py`를 사용합니다. 처음 연습할 때 `demo-init`으로 가상 DB와 예제 쿼리를 준비합니다. 계정이나 비밀번호를 받지 않으며 `profiles setup`이나 운영 연결을 사용하지 않습니다. 기존 연습은 `profiles list`와 `queries list`로 이어갑니다.
2. SQL을 이름으로 등록할 때만 바뀔 조건을 확인합니다. 기간, 공정 등 변수로 사용할 부분과 업무 규칙인 고정값을 구분합니다. 쿼리 등록은 조회 실행이 아닙니다. 상세 형식은 [사용 방법](references/usage.md)을 필요한 때만 읽습니다.
3. 목록은 `1. 생산실적조회 — 생산DB`처럼 **등록한 DB 이름**으로 표시합니다. `Oracle / 생산DB`처럼 엔진 이름을 앞에 붙이지 않습니다. 같은 이름이 있으면 등록된 번호와 DB 이름으로 구분합니다.
4. 조회할 쿼리와 조건을 정한 뒤 `plan`을 한 번 실행합니다. 적용할 DB 이름, 날짜와 값, 결과 한도 및 주의점을 짧게 보여주고 한 번 확인받습니다. 이미 확인한 동일 계획을 다시 묻지 않습니다. 빠진 조건을 임의로 채우지 않습니다.
5. 범위가 넓거나 데이터가 많아도 무조건 거절하지 않습니다. 확대할 행 수, 파일 크기와 시간을 안내하고 **사용자의 실제 허락 후** 해당 계획을 `run --confirm --allow-large`로 실행합니다. 일반 계획은 `run --confirm`입니다. 허용은 DB 권한과 시스템의 지원 범위를 바꾸지 않습니다. SQL, DB, 조건이나 한도를 바꾸면 새 계획을 만듭니다.
6. 조건이 매우 길어 `conditionsTruncated`가 참이면 요약만으로 전체를 확인했다고 하지 않습니다. `conditionReviewFile`의 전체 조건을 사용자가 로컬에서 확인한 뒤 실행합니다. 일반적인 짧은 조건은 이 단계가 없습니다.
7. 결과 경로, 저장 행 수와 완전성만 안내합니다. JSONL 전체, 원본 행이나 오류 원문을 대화에 넣지 않습니다. 후속 계산은 Python으로 저장 파일을 처리하고 필요한 집계만 반환합니다. 일부만 받은 결과를 전체 합계로 설명하지 않습니다.

## 알아둘 점

- DB 이름은 사용자가 정한 표시 이름이며 비밀번호나 접속 문자열이 아닙니다. 다른 DB로 조용히 대체하지 않습니다.
- 준비한 가상 DB에서 읽기 전용 SQL만 실행합니다. 실제 계정이나 비밀번호는 필요하지 않습니다.
- 건수 추정과 정확한 건수, 실제 저장 행 수를 구분합니다. 무조건 전체 COUNT부터 실행하지 않습니다. 결과 행 한도가 전체 스캔 부하를 보장하지 않습니다.
- `--confirm`, `--allow-large`는 실행 기록용 인자입니다. 인자 자체가 사용자의 의사를 인증하지 않으므로 허락을 꾸며 넣지 않습니다.
- 입력 오류나 시간 초과는 한 번 안내하고 멈춥니다. 무한 재시도나 운영 연결로 바꾸지 않습니다.
- 기본 개인 저장소는 설치 폴더 밖입니다. 업데이트할 때 개인 연결, 저장 쿼리와 결과물을 덮어쓰지 않습니다.

이 실행기는 더미 모드로 고정됩니다. 운영 설정을 읽거나 실제 네트워크에 연결하지 않습니다. 결과를 **가상 데이터**라고 표시하고 실접속 검증으로 설명하지 않습니다.
