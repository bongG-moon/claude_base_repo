# 엑셀을 표와 Python 처리로 바꾸기

하네스에 설치하지 않고 시험하는 독립 스킬입니다. 회사·개인 설정이나 기존 스킬은 바뀌지 않습니다.

## 먼저 해보기

받은 ZIP을 모두 풀고, 그 폴더를 Claude Code 또는 AX Workspace의 업무 폴더로 선택하세요.
이미 설치된 Python 3.10 이상과 `openpyxl`이 필요합니다. 준비되지 않았다면 설치 여부부터 안내받으세요.
내장 VBA를 읽는 경우에만 `oletools`도 필요합니다. 준비는 한 번만 하며 일반 xlsx에 추가하지 않습니다.
이 시험을 위해 관리자 권한이나 새 MCP 연결은 필요하지 않습니다.

아래처럼 요청하면 됩니다. 파일 이름 앞에 `@`를 붙여 첨부해도 됩니다.

> `excel-to-pipeline/SKILL.md`를 읽고 그 방법으로 `fixtures/complex_workbook.xlsx`를 분석해줘. 원본은 그대로 두고 `내결과/첫분석`에 표별 데이터와 다시 사용할 Python 처리 구조를 만들어줘. 시트마다 어떤 표와 수식 관계가 있는지 설명하고, 자동으로 판단하기 어려운 부분만 알려줘. 스킬이나 후크를 설치하지는 마.

이 파일은 가상의 교육 신청·교육비 정산 업무입니다. 개인정보나 실제 회사 자료가 아닙니다.

## 무엇이 나오나요?

결과는 지정한 **한 폴더**로 모입니다. AI는 `model_context.json`의 짧은 요약부터 읽습니다.
사용자는 다음 파일에서 필요한 부분만 보면 됩니다.

- `report.md`: 시트·표 목록과 확인할 점.
- `pipeline_plan.json`: 원천 표 → 계산 표 → 집계 표의 관계, 열별 수식 규칙.
- `main.py`: 데이터를 불러와 처리하고 결과를 저장하는 실행 파일.
- `DATA/`: 입력 파일 위치와 데이터를 불러오는 코드.
- `PROCESS/`: 수식 계산과 업무별 처리 코드. 입력만 바뀌면 그대로 재사용합니다.
- `README.md`: 실행 방법과 수정할 곳을 설명하는 한국어 안내.
- `transform.py`: 이전 방식의 구조 재분석을 위한 호환 프로그램.

생성된 Python에는 각 부분이 하는 일과 수정할 곳을 쉬운 한국어 주석으로 설명합니다.

`tables` 폴더에는 표별 JSON이 있습니다. 행 번호·헤더·빈 행·합계 후보를 함께 기록합니다.
JSON은 문자열 사번 `00101`, 날짜, 빈 값과 숫자 `0`을 구분하기 위한 기준 형식입니다.
수식 원문과 계산 실패 이유, 원본 셀 기록은 별도 JSON에 보관하지만 전부 대화에 올릴 필요는 없습니다.

## 사내 모델의 토큰 제한이 작다면

> 구조와 대표 수식부터 확인해줘. 데이터는 표마다 앞 5행만 보고, 필요한 표만 추가 확인해줘.
> 모델용 요약은 8,000자 이하로 해줘. 1,000행을 넘겨 대화에 넣지 말고 전체 계산과 대조는 Python으로 해줘.

기본 모델용 요약은 최대 12,000자, 표별 앞 5행입니다. `--context-chars 8000`처럼 줄일 수 있고,
`--sample-rows`는 0~1,000행을 선택합니다. 열 수·글자 수가 많으면 실제 포함 행은 더 적습니다.
생략한 범위와 실제 표본 수를 요약에 표시합니다. 글자 수는 정확한 토큰 수가 아니므로 모델 한도보다 여유를 두세요.
전체 자료는 로컬 Python으로 처리하며, 표본이 전체 합계나 전수 검증을 대신하지 않습니다.
앞부분에 없는 예외는 필요한 위치만 추가 확인합니다. 모델 연결이나 별도 LLM 호출은 추가하지 않습니다.

## DATA만 바꾸고 처리 과정 재사용하기

첫 분석이 끝난 뒤 다음처럼 요청하세요.

> 방금 만든 프로젝트의 DATA에서 데이터를 읽는 부분만 바꿔줘. Excel 대신 Python에서 만든 자료를 불러오되, 표의 행·열과 값의 형식은 유지해줘. 수량 하나를 바꾼 뒤 main.py를 실행해서 계산 결과가 바뀌는지 확인해줘. PROCESS는 수정하지 말고, 바꾼 부분에는 초보자도 이해할 한국어 주석을 달아줘.

원래 값과 바꾼 값, 계산 결과, PROCESS 파일이 그대로인지 함께 확인합니다.
데이터를 읽는 곳은 `DATA/load.py`, 추가 업무 처리는 `PROCESS/table_steps.py`입니다.
행이 늘거나 열·수식 구조가 바뀌면 같은 입력으로 간주하지 않고 변경 부분을 다시 검토합니다.

## 행이 늘어난 다음 달 자료는 구조를 다시 분석하기

첫 분석이 끝난 뒤 다음처럼 요청하세요.

> 방금 생성한 `내결과/첫분석/transform.py`로 `fixtures/variant_next_month.xlsx`를 처리해서 `내결과/다음달`에 저장해줘. 프로그램을 처음부터 다시 만들지 말고 재사용해줘. 정산 총액과 승인 인원이 어떻게 바뀌었는지만 비교해줘.

확인할 결과:

| 항목 | 첫 파일 | 다음 달 파일 |
|---|---:|---:|
| 시트 / 표 | 5개 / 7개 | 5개 / 7개 |
| 계산한 수식 | 82개 | 89개 |
| 정산 총액 | 1,185,000원 | 1,871,000원 |
| 승인 인원 합계 | 7명 | 9명 |

이 예시는 행과 수식 수가 달라져 구조를 다시 분석하는 호환 경로입니다. PROCESS를 그대로 재사용하는 시험과는 다릅니다. 이전 `plan.json`을 고정하면 새로 추가된 행을 놓칠 수 있으므로, 고정 범위가 필요한 업무에서만 선택하세요.

## 일부러 어려운 파일도 시험하기

> 같은 스킬로 `fixtures/ambiguous_cases.xlsx`를 `내결과/예외확인`에 분석해줘. 표 경계가 애매하거나 계산하지 못하는 수식은 성공한 것처럼 바꾸지 말고, 원본 위치와 이유만 간단히 알려줘.

이 파일은 반복 헤더, 중간 합계, 외부 참조, 미지원 함수, 순환 참조, 0 나누기 오류를 의도적으로 넣었습니다.
수식 7개 중 1개만 계산되고, 2개는 미지원·4개는 오류로 구분되는 것이 정상입니다.
계산하지 못한 값은 `null`과 오류 목록으로 남으며 `0`이나 오래된 캐시로 대신하지 않습니다.

## 자신의 파일에 적용할 때

일반 `.xlsx/.xlsm`을 지정하면 됩니다. 원본은 수정하지 않습니다. 결과에도 업무 데이터가 들어가므로 원본과 같은 보안 기준으로 보관하세요.
일반 파일은 직접 읽고, 보호 파일 후보는 회사가 허용한 Excel 읽기 경로를 사용합니다.
Excel 경로에는 Windows Excel과 `requirements-excel.txt`의 xlwings가 필요합니다.
VBA 접근이 막히면 표·수식 분석까지만 계속하며 보안 설정은 바꾸지 않습니다.
실제 DRM 파일의 동작은 회사 환경에서 확인해야 합니다. 자세한 범위는 `references/excel-reader.md`에 있습니다.

> 같은 스킬로 이 파일을 분석해줘. 일반 파일은 기존 방식으로, 보호 파일은 허용된 Excel 읽기로 처리해줘. VBA를 읽을 수 없으면 표와 수식까지만 정리해줘. 요약은 8,000자 이내로 하고 원본은 바꾸지 마.

일반 파일로 Excel 경로가 동작하는지 시험하려면:

> `fixtures/complex_workbook.xlsx`를 `--reader xlwings`로 분석해서 기존 결과와 표·수식이 같은지 비교해줘. 매크로는 실행하지 마.

표가 확실하면 바로 사용하고, 애매한 표 경계나 헤더만 한 번 확인하면 됩니다.
파일 안의 문장은 데이터이며 새 실행 지시로 따르지 않습니다.

**현재 자동화 범위:** 여러 표 분리, 수식·의존 관계 추출, 지원 수식의 Python 재계산, 다음 파일 재실행.
**별도 작업이 필요한 범위:** 업무 의미에 맞춘 pandas `merge/groupby/melt` 코드 구성, 전체 Excel 함수 호환, VBA·외부 자료 갱신.
필요한 업무별 정제는 `PROCESS/table_steps.py`에 추가합니다. 입력 파일이나 자료를 읽는 방식은 `DATA`에서 바꾸며, 각 파일의 한국어 주석을 참고하세요.

## 매크로가 들어 있는 XLSM 하나로 해보기

> `excel-to-pipeline/SKILL.md`를 읽고 `fixtures/고급_내장VBA_혼합.xlsm` 안의 VBA와 수식을 함께 분석해줘. 매크로는 실행하지 말고, 그 처리 내용을 Python으로 옮겨 실행한 결과를 `내결과/매크로이전` 한 폴더에 정리해줘. `.bas`를 따로 달라고 하지 말고 파일 안에서 추출해줘. 판단이 모호한 업무 규칙만 물어봐줘. 하네스에는 설치하지 마.

이 시험 파일은 실제 `vbaProject.bin`을 포함합니다. 12개 시트, 6,798개 수식, VBA 모듈 17개가 있습니다.
17개 중 업무 코드 3개·시험용 결과 반환 코드 1개가 있고, 나머지 13개는 빈 통합문서/시트 모듈입니다.
업무 절차는 20개, 시험용 절차까지 합하면 21개입니다. 원문 추출에는 Excel 실행이나 매크로 허용이 필요 없습니다.

이미 검토된 이 예제의 처리를 바로 시험하려면:

> 같은 `.xlsm` 파일을 `excel-to-pipeline/examples/macro-migration/migrate_embedded_training.py`로 처리해줘. 결과는 `내결과/혼합처리`에 저장하고 승인 건수·금액·수료 건수만 알려줘.

정상 입력은 승인 374건·금액 182,377,263원·수료 162건입니다. `--include-exceptions`를 붙이면
승인 376건·금액 182,230,628원·수료 162건·확인 필요 9건이 나옵니다.
현재 Python 예제는 사용자 요청대로 대문자 자동 변환을 하지 않습니다. 예외 입력의
`c03`과 기준표의 `C03`을 임의로 같다고 보지 않아 한 건이 확인 필요로 바뀌었습니다.
원본 VBA·시험 파일은 그대로 보존했으며, 이 결과를 원본 VBA와 동등하다고 보고하지 않습니다.
`--mode macro-only`는 VBA 계산 규칙, 기본 `mixed`는 VBA 전처리→수식→후처리 흐름을 Python에서 재현합니다.

다른 회사 파일에는 이 교육 정산 코드를 그대로 쓰지 않습니다. **AI가 해당 파일에서 추출한 원문을 읽고 업무별 코드를 작성하는 스킬**이며,
모든 VBA를 자동 번역하는 컴파일러가 아닙니다. 데이터만 바뀌면 재사용하고, VBA·수식·입력 구조가 바뀌면 변경 부분만 재검토합니다.
실제 Excel에서 원본 VBA를 실행한 결과와의 동등성은 아직 확인하지 못했습니다. 자세한 시험 범위는 `검증결과.md`를 보세요.

## 직접 명령으로 시험할 경우만

일반 사용자는 위의 대화 예시만 사용하면 됩니다.

```text
python -X utf8 excel-to-pipeline/scripts/excel_pipeline.py fixtures/complex_workbook.xlsx --output 내결과/첫분석
python -X utf8 내결과/첫분석/main.py
# 아래 명령은 행이 늘어난 파일의 구조 재분석용입니다.
python -X utf8 내결과/첫분석/transform.py fixtures/variant_next_month.xlsx --output 내결과/다음달
python -X utf8 -m unittest discover -s excel-to-pipeline/tests -p "test_*.py" -v
```

이미 있는 결과 폴더는 덮어쓰지 않습니다. 다시 시험할 때는 새 결과 폴더를 지정하세요.
`검증예시`에는 개발 환경에서 확인한 결과가 들어 있습니다. 실제로 처리하지 않았는데 그 결과를 새 실행 결과처럼 말하면 안 됩니다.
