# Datalake 데이터 조회

요청한 데이터 조회만 수행합니다. 이 스킬은 로컬 Python 실행기로 동작하며 별도 하네스, MCP 등록이나 상시 후크가 필요하지 않습니다.

## 사용 흐름

1. 현재 스킬의 `scripts/query.py`를 사용합니다. 조회 업무를 시작할 때 `start`를 한 번 실행해 등록된 연결과 쿼리, 24시간이 지난 결과의 정리 후보 요약을 확인합니다. 같은 업무의 반복 조회와 후속 분석마다 다시 실행하지 않습니다.
2. 정리 후보가 있을 때만 삭제 또는 보존을 한 번 묻습니다. 삭제는 준비된 정리 계획의 대상과 범위를 기준으로 실제 허락을 받은 뒤 `results cleanup --plan <계획 ID> --confirm`으로 수행합니다. 이미 사용자가 같은 범위의 삭제를 선택했다면 허락을 다시 묻지 않습니다. 후보가 없거나 보존을 선택하면 조회를 계속합니다. DB 연결과 저장 쿼리 원본은 정리하지 않습니다.
3. DB와 쿼리 현황을 보고 관리하려면 `manage`로 로컬 웹 화면을 엽니다. 처음 연결하거나 DB 추가와 수정을 요청하면 `profiles setup`을 사용합니다. 이미 지정된 연결과 쿼리가 있으면 그대로 재사용하고 설정창이나 목록을 다시 열지 않습니다. 사번과 토큰은 로컬 설정창에서만 입력하며 평소 조회마다 다시 요구하지 않습니다.
4. SQL을 이름으로 등록할 때만 바뀔 조건을 확인합니다. 기간, 공정 등 변수와 업무 규칙인 고정값을 구분합니다. 쿼리 등록은 조회 실행이 아닙니다. 목록은 `1. 생산실적조회 — 생산DB`처럼 **등록한 DB 이름**으로 표시하며 같은 이름은 번호와 DB로 구분합니다. 자세한 명령은 [사용 방법](references/usage.md)을 필요한 때만 읽습니다.
5. 사용자가 쿼리, DB와 필요한 조건을 지정해 조회를 요청했다면 기본 **50,000행**까지 `execute --id <번호> --params <조건 JSON> --confirm`으로 실행합니다. 본 조회의 파일 용량과 시간에는 기본 제한이 없으며 이를 위한 별도 확대 승인을 묻지 않습니다. 그 명시적 요청을 승인 근거로 삼고 같은 조건을 재확인하지 않습니다. DB 선택이나 날짜 경계 등 의미가 불명확하거나 조건이 빠졌을 때만 묻습니다. 조건을 임의로 채우지 않습니다.
6. `execute`가 큰 조회의 승인이 필요하다고 멈추면 반환된 계획의 범위, 한도와 주의점을 짧게 보여줍니다. **사용자의 실제 허락 후** 그 계획을 `run --confirm --allow-large`로 실행합니다. 50,000행 초과뿐 아니라 넓은 기간과 위험한 SQL 형태도 이 절차를 따릅니다. SQL, DB, 조건이나 한도를 바꾸면 새 계획이 필요합니다.
7. `conditionsTruncated`가 참이면 `conditionReviewFile`의 전체 조건을 사용자가 로컬에서 확인한 뒤 실행합니다. 큰 조회가 아닌 경우 `run --confirm`이며 `--allow-large`는 큰 조회 승인도 필요할 때만 붙입니다. 사전 검토를 요청한 업무는 기존 `plan` 후 `run` 흐름을 사용합니다.
8. 결과의 `label`, 실제 경로, 저장 행 수와 완전성만 안내합니다. JSONL 전체, 원본 행이나 오류 원문을 대화에 넣지 않습니다. 후속 계산은 Python으로 저장 파일을 처리하고 필요한 집계만 반환합니다. 일부만 받은 결과를 전체 합계로 설명하지 않습니다.

## 알아둘 점

- DB 이름은 사용자가 정한 표시 이름이며 비밀번호나 접속 문자열이 아닙니다. 다른 DB로 조용히 대체하지 않습니다.
- 쿼리는 읽기 전용으로 실행합니다. 조회 전용 계정도 필요합니다. SELECT 구문 검사만으로 모든 함수의 부수효과를 보증하지 않습니다.
- `start`와 관리 화면은 로컬 정보만 다룹니다. `plan`과 `execute`의 사전 검토는 LakeHouse 준비 API와 `EXPLAIN COSTS`를 실행하며 클러스터 기동을 유발할 수 있습니다. 기동 허용과 필요한 HTTP 사용은 설정 화면에서 사용자가 선택한 값만 재사용합니다.
- 실행계획의 최대 단계 추정치는 결과 건수나 정확한 스캔 건수가 아닙니다. 전체 COUNT와 ANALYZE는 자동 실행하지 않습니다. 실제 건수는 미확인일 수 있고 결과 행 한도가 전체 스캔 부하를 보장하지 않습니다. 연결, 클러스터 준비와 사전 계획 검토의 실패 감지 시간 제한 및 DB와 네트워크 자체 제한은 유지됩니다.
- `--confirm`, `--allow-large`는 실행 기록용 인자입니다. 인자 자체가 사용자의 의사를 인증하지 않으므로 허락을 꾸며 넣지 않습니다.
- 인증 실패나 시간 초과는 한 번 안내하고 멈춥니다. 다른 계정, 무한 재시도, 설정 탐색이나 더미 결과로 대신하지 않습니다.
- 기본 개인 저장소는 설치 폴더 밖입니다. 업데이트할 때 개인 연결, 저장 쿼리와 결과물을 덮어쓰지 않습니다.
