# Datalake 데이터 조회

사내 `lakes.client.LakeHouse` SDK를 사용합니다. SQL의 `lake_catalog.스키마.테이블` 경로가 조회 대상을 정하며 DB 이름, 호스트, 포트와 DSN을 따로 등록하지 않습니다. 현재 스킬의 `scripts/query.py`를 사용하며 별도 하네스, MCP 등록이나 상시 후크가 필요하지 않습니다.

## 인증정보 입력

저장된 값은 재사용합니다. 필요한 값이 없을 때만 `auth setup`을 실제 실행하며 **“인증정보는 채팅에 보내지 말고, 지금 여는 내 PC 입력창에 직접 입력해 주세요.”**라고 안내합니다. 사번, JWT와 S3 키를 채팅으로 먼저 묻지 않습니다. 창을 열지 못했거나 사용자가 닫으면 상태만 알리고 채팅 입력으로 우회하거나 자동 반복하지 않습니다. 이미 채팅에 적힌 값도 재출력하거나 명령 인자와 로그에 옮기지 않습니다. 자세한 예외 처리는 [사용 방법](references/usage.md)의 인증정보 입력을 참고합니다.

## 사용 흐름

1. `start`는 새 조회 업무를 시작할 때 한 번만 실행합니다. 등록 정보와 이전 결과 요약만 확인하며 같은 업무의 반복 조회와 후속 분석마다 실행하지 않습니다. 하루 이상 지난 결과의 삭제 후보가 있을 때만 보존 또는 삭제를 한 번 묻고, 실제 허락 뒤 준비된 `results cleanup --plan <ID> --confirm`으로 정리합니다. 인증정보와 저장 쿼리는 삭제하지 않습니다.
2. 저장된 사번, JWT, S3 Access Key와 S3 Secret Key를 그대로 재사용합니다. 없거나 불완전할 때만 `auth setup`을 열며 최초 스킬 사용이라는 이유로 다시 설정하지 않습니다. 키가 없으면 [My Key 발급 화면](https://lake.skhynix.com/myprofile/mykey)을 안내합니다. 명시한 현재 폴더의 `.env` 가져오기는 [사용 방법](references/usage.md)을 참고합니다.
3. SQL을 이름으로 등록할 때는 바뀔 조건과 고정값을 구분합니다. `queries register --spec <명세 JSON> --params <조건 JSON 파일 또는 JSON 객체>`는 기본적으로 저장 후 최대 10행의 실제 시험 조회를 수행하며 별도 확인 옵션이 필요하지 않습니다. 사용자가 저장만 요청한 경우에만 `--save-only`로 미검증 상태를 남기며 시험 조건을 묻지 않습니다. 시험에 필요한 조건만 한 번 확인하며 이미 정한 조건을 재질문하지 않습니다. 승인 대기와 실패를 검증 완료로 설명하지 않습니다. 명령과 시험 범위는 [사용 방법](references/usage.md)을 필요한 때만 읽습니다.
4. 실제 시험은 최대 10행으로 데이터 존재 여부를 확인합니다. 정상 0건, 데이터 확인, 서버 오류와 일부 결과를 구분하고 오류 코드와 인증정보를 가린 짧은 이유를 안내합니다. 10행 시험을 전체 건수 검증으로 설명하지 않습니다. 현재 요청을 완전히 충족한 시험 결과는 바로 중복 조회하지 않습니다.
5. 새 조회 요청은 저장 파일이 있어도 기본적으로 `execute --id <번호> --params <조건 JSON 파일 또는 JSON 객체> --confirm`으로 새로 실행합니다. 기본 한도는 **50,000행**이며 본 조회의 파일 용량과 시간에는 기본 제한이 없습니다. 실시간성 정보는 다시 조회하며 과거 결과 재사용은 사용자 허락을 받습니다. “방금 결과로 분석”처럼 현재 작업의 결과를 지정한 후속 요청만 그 파일을 사용합니다.
6. 큰 조회가 필요하면 반환된 계획의 범위와 한도를 안내하고 실제 허락 뒤 `run --plan <ID> --confirm --allow-large`로 이어갑니다. `conditionsTruncated`면 `conditionReviewFile`의 전체 조건을 확인합니다. SQL, 대상과 조건이 바뀌면 새 계획을 만들며 동일 허락을 재질문하지 않습니다.
7. 결과는 조회 시각, 조건 요약, 결과 ID, 경로, 저장 행 수와 완전성만 짧게 안내합니다. 대량 원문은 Python으로 파일에서 계산하고 필요한 집계만 반환합니다. 행을 보여 달라는 경우에만 `preview`로 기본 5행, 최대 20행과 8,000자 안의 미리보기를 사용합니다. 원본 전체를 Read, head나 출력문으로 대화에 넣지 않습니다.
8. A 조회 결과로 B를 조회하거나 결과 미리보기가 필요할 때만 [Python 연속 조회와 미리보기](references/workflows.md)를 읽습니다. A의 고유키를 코드로 B의 바인드 조건에 전달하고 모델이 값을 전부 읽거나 SQL 문자열로 이어 붙이지 않습니다.

## 알아둘 점

- 저장된 결과의 시각과 조건이 같아 보여도 재사용 허락으로 간주하지 않습니다. 새로 조회할 때는 재사용 여부를 매번 묻지 않습니다.
- 결과 0건은 오류와 다릅니다. 실패를 피하려고 다른 날짜, SQL이나 계정으로 자동 재시도하지 않습니다. 일부 결과를 전체 합계로 설명하지 않습니다.
- 쿼리는 읽기 전용이며 조회 권한과 서버 자원 제한을 그대로 따릅니다. 행 한도가 전체 스캔 부하를 보장하지 않으며 전체 COUNT와 ANALYZE를 자동 실행하지 않습니다.
- `--confirm`, `--allow-large`는 실행 기록용 인자입니다. 인자 자체가 사용자 의사를 인증하지 않으므로 허락을 꾸며 넣지 않습니다.
- SDK는 결과를 DataFrame으로 메모리에 먼저 받습니다. 파일 저장 한도가 수신 메모리를 제한하지는 않습니다. 승인된 사내 SDK 공급처와 설치 범위는 사용 방법을 참고하며 공개 PyPI의 동명 `lakes`를 대신 설치하지 않습니다.
- 기본 개인 저장소는 설치 폴더 밖입니다. 업데이트할 때 개인 인증정보, 저장 쿼리와 결과물을 덮어쓰지 않습니다.
- 새 테이블이나 미확인 컬럼과 파티션을 찾을 때만 [테이블 탐색](references/discovery.md)을 읽습니다. 저장 쿼리마다 같은 탐색을 반복하지 않습니다.
