# 테이블과 컬럼을 확인할 때

새 테이블을 찾거나 컬럼과 파티션이 아직 확인되지 않았을 때만 사용합니다. 이미 확인된 저장 쿼리로 조회할 때 매번 테이블 목록, 컬럼, 파티션, 샘플을 순서대로 다시 조회하지 않습니다. 이 명령은 실제 사내 SDK에 접속하므로 로컬 저장 쿼리 목록과 구분합니다.

## 필요한 메타데이터만 확인하기

현재 스킬 폴더의 `scripts/query.py`를 사용합니다. `auth setup`으로 설정한 인증정보를 재사용하고 사용자에게 받은 업무 범위와 스키마로 검색 범위를 좁힙니다. 조회 대상은 테이블 경로이며 테이블마다 DB를 등록하지 않습니다. 모르는 스키마나 테이블 이름을 실제 존재하는 값처럼 만들지 않습니다.

```text
python -X utf8 -B scripts/query.py discover tables --schema <스키마> --like <검색 패턴> --limit 100
python -X utf8 -B scripts/query.py discover describe --table lake_catalog.<스키마>.<테이블>
python -X utf8 -B scripts/query.py discover show-create --table lake_catalog.<스키마>.<테이블>
python -X utf8 -B scripts/query.py discover explain --sql-file <검토할 SELECT 파일>
```

인증 설정이 하나면 `--profile`을 지정하지 않습니다. 예전 인증 설정이 여러 개일 때만 사용할 계정을 확인해 `--profile <인증 설정 ID>`를 붙입니다. 이 ID는 조회할 DB나 테이블을 고르는 값이 아니며 다른 계정으로 조용히 대체하지 않습니다.

- `tables`: 주어진 스키마와 이름 패턴으로 후보를 확인합니다. SQL `LIKE` 패턴의 `%`와 `_`를 사용하므로 의도한 검색 범위를 확인합니다. 전체 카탈로그를 무작정 훑지 않습니다.
- `describe`: 선택한 테이블의 컬럼명과 자료형을 확인합니다. 업무 용도는 컬럼 이름만으로 확정하지 않고 제공된 설명과 함께 판단합니다.
- `show-create`: 테이블 정의를 읽어 파티션과 구조를 확인합니다. 반환되는 CREATE 문은 메타데이터이며 그 문장을 실행해 테이블을 생성하지 않습니다.
- `explain`: 바인드 조건이 없는 단일 읽기 전용 SELECT 파일의 실행계획을 확인합니다. 실제 결과 행 수나 완료 시간을 보장하는 값으로 해석하지 않습니다. SQL 검사를 우회하는 임의 명령 파일은 받지 않습니다.

이 경로는 허용된 메타데이터 명령만 구성합니다. 저장 쿼리의 SELECT 검사나 쓰기 차단을 해제하는 통로로 사용하지 않습니다. 필요한 테이블명, 컬럼과 파티션 정보만 짧게 정리하고 전체 메타데이터를 반복 출력하지 않습니다.

`tables --limit`은 1~100행이며 다른 탐색 명령도 반환 메타데이터를 최대 100행으로 제한합니다. SDK가 반환하기 전의 메모리 수신량까지 제한하는 값은 아닙니다. 대화 응답은 열 이름과 행 내용을 합쳐 8,000자 이내로 요약하며 긴 셀과 열 목록도 줄일 수 있습니다. `previewTruncated`가 참이면 일부 정보임을 알리고 전체 정의는 `metadataFile`에서 필요한 부분만 확인합니다. 파일에는 반환 한도 안의 메타데이터를 보존하되 확인된 인증정보는 마스킹합니다. `dataRowsReturned: 0`은 업무 데이터 행을 반환하지 않았다는 뜻이며 메타데이터 행 수는 별도입니다.

## 쿼리로 이어가기

확인한 실제 컬럼과 파티션으로 사용자 조건을 표현합니다. 최근 날짜는 Python의 `datetime`으로 현재 날짜를 확인해 계산하고 날짜 자료형, 시간대, 종료 경계와 파티션 키를 구분합니다. 파티션 조건을 무조건 WHERE의 첫 항에 놓거나 작은 테이블을 항상 JOIN 왼쪽에 놓는 규칙을 강제하지 않습니다. 실제 스키마와 지원되는 실행계획을 근거로 판단하고 결과 의미를 바꾸지 않습니다.

데이터 샘플이 필요하다고 사용자가 요청하면 작은 행 한도의 SELECT를 등록해 일반 `execute` 흐름으로 조회합니다. 결과는 로컬 파일에 저장하고 필요한 집계나 확인값만 반환합니다. 매번 원본 20행을 대화에 넣거나 발견 단계마다 전체 COUNT를 실행하지 않습니다.

빈 결과는 해당 조건에서 0건이라는 뜻으로 안내합니다. 날짜가 틀렸다고 단정하지 않습니다. 다른 날짜나 범위를 시험해야 한다면 원래 조건과 변경 이유를 설명하고 허락을 받은 뒤 새 계획으로 조회합니다. 권한, 인증이나 SQL 오류는 한 번 안내하고 중지하며 다른 계정이나 테이블을 자율적으로 대체하지 않습니다.

## 업무별 검색 시작 힌트

다음은 사용자 제공 원본의 탐색 힌트입니다. 스키마, 공장별 테이블이나 파티션이 실제 존재한다는 목록이 아니므로 테이블명으로 하드코딩하지 않습니다.

| 업무 | 검색 시작 힌트 |
| --- | --- |
| MES | `mes`, `lot`, `wafer`, `WF_his` |
| FDC | `fdc`, `alarm`, `event`, `sensor`, `his` |
| EMS | `ems`, `eqp`, `param`, `his` |
| CMS | `cms`, `chamber`, `status` |
| APC | `apc`, `recipe`, `model` |
| TAS | `tas`, `recipe`, `step` |
| HUB | `hub`와 사용자가 지정한 업무명 |
