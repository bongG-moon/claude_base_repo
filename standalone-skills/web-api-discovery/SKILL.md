# 웹 데이터 조회 절차 만들기

사용자가 알려준 사이트와 필요한 데이터, 접근 권한 안에서만 진행합니다. 완성 코드는 `<업무폴더>/web-api-discovery/outputs/`의 새 작업 폴더에 둡니다. 사용자가 지정한 결과 경로를 우선하고 기존 파일은 덮어쓰지 않습니다.

## 실행

1. 사이트 주소와 원하는 데이터가 명확하면 바로 시작합니다. 공식 API나 제공된 SDK가 목적에 맞으면 먼저 사용합니다. 이미 연결된 Chrome DevTools, 브라우저 네트워크 관찰 도구 또는 사용자가 제공한 **민감정보 제거된** 요청 자료가 있는지 실제 도구 목록에서 확인합니다. 이름을 추측해 호출하거나 화면 클릭 도구를 네트워크 도구라고 소개하지 않습니다. Chrome 디버깅 포트, 확장, 전역 설정 또는 MCP를 자동 설치·변경하지 않습니다. 사용 가능한 관찰 기능이 없으면 필요한 연결을 간단히 안내하고 중단합니다.
2. 사용자가 열람·자동화해도 되는 사이트에서 요청한 업무 화면만 관찰합니다. 조회에 대응하는 요청의 경로, 메서드, 조건, 응답 구조와 다음 페이지 방식을 최소한으로 확인합니다. 응답은 필요한 필드와 소수의 예시만 확인하고 전체 데이터를 모델에 넣지 않습니다. 공식 문서가 있으면 요청 동작과 대조합니다. GET 메서드만으로 읽기 전용임이 보장되지는 않으므로 공식 계약이나 관리자 지침을 확인합니다. 테스트 버튼, 제출, 삭제 등 데이터 변경 기능은 호출하지 않습니다.
3. 확인한 읽기 전용 동작을 새 Python 코드와 짧은 사용 안내로 작성합니다. URL과 필드명, 페이지 종료 조건은 관찰 근거를 기록하고 추측한 부분은 미확인으로 표시합니다. `GET` JSON의 숫자 페이지 또는 커서 방식이면 [조회 도구](references/get-query.md)의 포함된 Python 실행기를 이용할 수 있습니다. 그 외 방식은 실제 사이트 계약에 맞는 코드를 작성하되 요청 범위, 중단 조건, 오류를 확인합니다.
4. 사용자가 요청한 조건으로 소량부터 시험하고 필드·행 수·페이지 종료를 확인합니다. 실행 결과 전체는 로컬 파일로 내보내고 모델에는 경로, 행 수, 성공/실패 및 필요 시 제한된 샘플만 전달합니다. 완전한 결과인지, 제한으로 중단됐는지 구분합니다. 결과를 재사용할 때 실시간 데이터를 임의로 오래된 파일로 대체하지 않습니다.

## 보안과 동작 경계

- 로그인은 사용자가 기존 승인된 방법으로 수행합니다. 비밀번호, 쿠키, 세션, 인증 토큰, API 키, CSRF 값이나 원본 HAR을 대화·로그·결과 코드에 붙이지 않습니다. 가능한 경우 인증이 필요 없는 공식 접근을 사용하고 필요한 인증은 사용자가 직접 로컬 환경 변수나 승인된 비밀 저장소에 설정합니다. 인증값 자체를 모델에 요청하지 않습니다.
- 브라우저에서 네트워크 내용을 관찰하는 도구가 민감 헤더·본문을 필터링할 수 없다면 원본 전체를 받아 모델에 노출하지 말고 멈춰 안전한 관찰 방법을 안내합니다. 원본 HAR을 생성하거나 공유해야 한다면 저장 전에 비밀과 개인정보 제거, 보관 범위·삭제를 사용자가 결정합니다.
- CAPTCHA, 다중 인증, 접근 제한이나 서버 차단은 우회하지 않습니다. 권한·범위가 불명확하면 확인합니다. 401/403/429, 로그인 만료, 차단 또는 예상 외 대용량 응답은 즉시 중단하고 안전한 오류 내용만 안내합니다. 정책·인증·로그인 상태를 바꾸거나 비공식 접근을 허용된 것처럼 표현하지 않습니다.
- 사용자에게 전달되지 않은 내부 토큰과 비밀을 탐색하지 않습니다. 다른 도메인으로 넘기는 리다이렉트는 자동으로 따라가지 않습니다. 요청 데이터 변경이나 게시 등 외부 쓰기는 명시적 요청과 확인이 있을 때만 별도 절차로 수행합니다.
- 이 스킬은 독립형입니다. 하네스, MCP 서버와 별도 모델 설치는 필요하지 않지만 **브라우저 네트워크 관찰 기능은 호스트에서 제공되어야 합니다**. 이미 설치된 도구만 사용하며, 도구가 없는 환경에서 관찰이나 실제 사이트 검증을 성공했다고 주장하지 않습니다. Python 실행기의 단순 `GET` 호출은 Python 3.11 이상 표준 라이브러리만 사용합니다.

아이디어 참고: [Reverse API Engineer](https://github.com/kalil0321/reverse-api-engineer)는 브라우저로 요청을 관찰하고 클라이언트를 만드는 MIT 프로젝트입니다. 이 스킬은 해당 CLI나 코드를 포함하지 않으며, 관찰 도구나 세션 상태를 자동 설치·재현하지 않습니다.
