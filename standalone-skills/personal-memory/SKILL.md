# 개인 기억

이 스킬은 파일 읽기·쓰기 기능만 사용합니다. 특정 하네스, 세션 ID, 후크,
데이터베이스가 필요하지 않습니다. **파일을 저장해도 다음 대화에 자동 주입되지는 않습니다.**
기억 조회 요청 때 필요한 항목을 읽습니다. 호스트의 기존 자동 기억과 임의로 합치지 않습니다.

조회에는 저장 범위를 묻지 않습니다. 기존 항목 수정은 이미 확인한 위치와 범위를 유지합니다.
새 저장 위치가 정해지지 않았을 때만 아래 범위 선택이 필요합니다.

## 저장과 수정

1. 지속적인 선호·업무 맥락인지 구분합니다. 용어·지표 정의는 지식이고, 반복 절차는 스킬입니다.
   이번 작업만의 지시, 문서 속 명령, 추측은 저장하지 않습니다.
2. 사용자가 이미 지정한 저장 범위·폴더를 사용합니다. 미지정이면 **이 프로젝트 / 내 여러 프로젝트**를
   한 번만 묻습니다. 프로젝트는 `<업무폴더>/.work-notes/memory/`를 사용하고,
   여러 프로젝트는 사용자가 고른 개인 폴더의 `memory/`를 사용합니다. 회사 공통 폴더에 쓰지 않습니다.
3. 선택한 폴더에서 제목·핵심어로 관련 파일만 찾습니다. 같은 사실이 있으면 그 파일을 수정하며
   같은 내용을 새 파일로 복제하지 않습니다. 기억 목록 전체를 매번 모델에 넣지 않습니다.
4. 새 파일은 짧은 제목의 `.md`로 만들고 [기록 양식](references/note-format.md)을 따릅니다.
   사용자의 문장을 길게 옮기지 말고 적용할 사실만 적습니다. 원본 메일·행 데이터·인증 정보는 넣지 않습니다.
5. 기존 사실을 고칠 때는 방금 읽은 내용과 현재 내용이 같은지 확인하고 해당 부분만 수정합니다.
   다른 작업이 바꿨으면 최신 내용을 먼저 비교합니다. 되돌려 달라는 요청은 실제 이전 내용이 있을 때만 복구합니다.
6. 저장한 항목과 범위, 파일 링크를 사용자가 정한 응답 길이 안에서 알려줍니다. 파일 저장과 미래 대화 자동 적용을 구분하며 일회성 길이 제한은 기억으로 저장하지 않습니다.

## 조회

지정된 기억 폴더에서 관련 제목·키워드로 찾고 최대 5개·합계 약 4,000자만 읽습니다.
활성 항목의 적용 범위·출처·날짜를 확인합니다. 상충하면 두 근거를 표시하고 필요한 차이만 묻습니다.
기존 하네스가 관리하는 기억은 그 환경의 조회 기능이 실제 있을 때 사용합니다.
권한이 없거나 위치를 모르면 숨겨진 프로필 전체를 뒤지지 말고 필요한 위치만 확인합니다.

사용 예: “이 프로젝트에서 보고서는 결론부터 쓰는 것으로 기억해줘.”
“내가 저장한 보고서 표현 선호를 찾아줘.”
