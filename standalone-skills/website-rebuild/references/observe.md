# 어떤 화면을 근거로 만들 것인가

## URL을 볼 수 있을 때

- 실제 페이지 제목과 주소를 먼저 확인합니다. 로그인 화면이나 오류 화면을 목표 화면으로 오인하지 않습니다.
- 필요한 구역의 렌더링 결과와 요소 정보를 함께 봅니다. 사용할 수 있다면 계산된 스타일에서
  글꼴, 글자 크기와 굵기, 폭, 여백, 색을 확인합니다. 개발 도구의 정확한 도구 이름과 인자는 현재 설명을 따릅니다.
- 같은 컴포넌트의 반복 행은 대표 항목으로 확인합니다. 긴 표 전체나 페이지의 모든 스크립트를 수집하지 않습니다.
  표 동작 확인에는 첫 페이지, 다음 페이지, 필터 결과와 빈 결과면 보통 충분합니다.
- 탭, 메뉴, 필터처럼 화면 안에서 끝나는 동작은 요청 범위 안에서 관찰합니다.
  실제 저장, 주문, 메일 발송, 삭제처럼 외부 결과가 남는 동작은 화면 재현을 이유로 실행하지 않습니다.
- 필요한 자산만 사용합니다. 기존 프로젝트나 사용자 제공 이미지와 글꼴을 먼저 사용하고,
  외부 자산은 재사용 조건과 접근 범위가 확인된 것만 가져옵니다. 상용 글꼴을 공개 파일에 묶지 않습니다.

## 이미지로만 볼 수 있을 때

- 이미지에서 보이는 정렬, 상대 폭, 여백, 문구, 색감을 우선합니다.
  압축된 이미지에서 작은 글씨를 못 읽었다면 실제 문구처럼 창작하지 않습니다.
- 정확한 글꼴을 구분하기 어려우면 형태가 가까운 현재 사용 가능한 한글 글꼴을 쓰고 추정임을 남깁니다.
  기존 글꼴 선택은 유지합니다. 필요한 새 선택만 Noto Sans KR, Pretendard,
  나눔스퀘어 네오, 디자인에 맞게 선택, 직접 입력으로 한 번에 묻습니다. 설치나 CDN 연결은 별개입니다.
- 스크린샷 한 장은 클릭 후 모습, 로딩, 모바일 화면의 증거가 아닙니다.
  주어진 동작 요구가 있으면 구현하되 원본에서 확인한 동작과 추정한 동작을 구분합니다.
- 데스크톱 이미지뿐이면 모바일은 같은 정보 순서를 유지하는 적응형 배치로 만듭니다.
  원본 모바일과 동일하게 복제했다고 말하지 않습니다.

## 최소 작업 메모

한 페이지 작업은 대화의 짧은 메모면 충분합니다. 복수 페이지라면 기존 프로젝트의 작업 메모에
대상 페이지, 관찰한 상태, 공통 스타일, 구현할 동작, 미확인 부분을 합쳐 기록합니다.
각 단계마다 별도 보고서나 JSON 파일을 만들 필요는 없습니다.

예: `신청 목록 / 데스크톱 1440px / 회차 필터와 다음 페이지 확인 / 네이비 상단, 연한 배경,
고정 표 머리글 / 모바일 배치는 추정 / 실제 저장 API는 연결하지 않음`.
