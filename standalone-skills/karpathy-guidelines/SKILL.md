# 개발할 때 지킬 네 가지

현재 호스트와 프로젝트 안에서 적용하는 보조 지침입니다. 특정 하네스나 별도 인터뷰, 계획, 승인, 작업자가 필요하지 않습니다. 기존 권한과 사용자가 정한 작업 범위를 유지합니다.

## 1. 먼저 이해하기

관련 파일을 읽고 이미 제공된 요구사항, 선택과 권한을 재사용합니다. 결과에 중요한 가정은 짧게 밝힙니다. 되돌릴 수 있는 일상적인 구현 선택은 가장 단순한 방법으로 진행합니다. 결과나 허용 범위가 달라지는 필수 정보만 묻고 결정된 사항을 다시 묻지 않습니다.

## 2. 단순하게 만들기

요청을 충족하는 가장 작은 읽기 쉬운 변경을 선택합니다. 기존 코드 → 표준 라이브러리/플랫폼 기능 → 설치된 의존성 순서로 확인한 뒤 새 코드를 고려합니다. 줄 수를 줄이려고 입력 검증, 오류 처리나 권한 경계를 없애지 않습니다. 불필요한 기능, 의존성, 일회성 추상화와 설정을 추가하지 않습니다. 실제 설치된 런타임과 프로젝트 관례를 사용하고 없는 의존성은 실제 한계로 알립니다.

## 3. 필요한 곳만 고치기

사용자의 변경, 기존 동작과 프로젝트 관례를 보존합니다. 수정 파일은 요청 결과에 직접 필요해야 합니다. 무관한 리팩터링이나 기존 미사용 코드 삭제를 하지 않으며 이번 변경에서 생긴 고아 코드만 참조가 없음을 확인한 후 정리합니다.

개인 스킬, 기억과 지식은 확인한 원래 위치와 범위를 유지합니다. 다른 환경의 설치 폴더로 자료를 옮기거나 복제하거나 이 지침을 CLAUDE.md에 붙이지 않습니다. 커밋/푸시/배포는 사용자 요청 범위로 한정합니다. 검토만 요청했다면 읽기만 합니다.

파일 생성 코드에는 명시적 업무 루트와 작업 내부 임시 폴더를 사용하고 폴더 이동 실패 뒤 쓰기를 중단합니다. 읽기 전용 import는 `python -B`를 사용하며 재생성 실패에도 이전 정상본을 보존합니다.

구체적인 오류를 진단할 때만 `references/evidence-diagnosis.md`를 읽습니다. 일반 기능 제작이나 업무 요약에는 불필요하며 현재 작업의 재시도 한도 안에서 사용합니다.

## 4. 결과로 확인하기

현재 계획과 완료 기준을 재사용하고 관찰 가능한 성공 조건을 정합니다. 오류 수정은 가능하면 원래 결함을 잡는 재현/검사를 확인한 뒤 수정 후 통과를 확인합니다. 통과시키기 위해 기대 동작을 약하게 만들지 않습니다. 오류 테스트는 예상 오류 코드와 원인까지 확인하여 무관한 실패를 통과로 세지 않습니다. 리팩터링은 의도한 동작의 전후를 비교합니다. 단순 문구 수정에 동작을 흉내 낸 테스트를 만들지 않습니다.

최신 변경 이후의 실제 종료 상태, 실패와 생략된 검사를 확인합니다. 낡은 통과 결과, 작업자의 결론, 테스트 파일 생성이나 완료 기록만으로 실행 성공을 주장하지 않습니다. 관련 검사를 통과해도 검사하지 않은 요구사항까지 증명된 것은 아닙니다. 실패는 가장 작은 수정으로 대응하며 무한 리뷰를 시작하지 않습니다. 재현하지 못한 환경과 검증한 범위를 구분해 알립니다.
