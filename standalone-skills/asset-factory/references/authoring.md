# 짧게 만들고 같은 파일에서 고치기

- YAML 앞부분에 `name`, `description`을 둡니다. 설명은 어떤 요청에 쓰는지, 본문은 실제 실행 순서만 적습니다. 긴 형식·예시는 `references/`, 실행 코드는 `scripts/`에 둡니다.
- 출력에 필요한 원본 수치·인용·조건을 보존하며, 사용자에게 보이는 안내는 한국어로 작성합니다. 비밀번호·쿠키·API 키를 코드나 예시에 쓰지 않습니다.
- 이름이 다른 같은 업무 스킬이 있으면 활용/수정할지 확인합니다. 같은 이름의 파일을 덮어쓰거나 이름을 바꿔 사본을 만드는 방식으로 충돌을 숨기지 않습니다.
- 기존 스킬은 실제 실행 원본을 읽고 해당 파일을 직접 수정합니다. 기존 frontmatter·참조·개인 설정은 보존합니다. 별도 명세 파일을 다시 생성하게 할 필요가 없습니다.
- 새 파일 생성을 돕는 선택 명령: `python -X utf8 "<스킬폴더>/scripts/author_skill.py" --destination "새 스킬 폴더의 절대경로" --name "weekly-report" --description "주간 현황을 요약합니다" --body "작성한 본문 UTF-8 파일의 절대경로"`. `<스킬폴더>`는 이 참고자료의 상위 `SKILL.md`가 있는 실제 절대경로입니다. 설치 범위를 이미 정한 경우 사용하며, 기존 폴더는 덮어쓰지 않습니다. 부모 폴더는 현재 파일 도구로 먼저 준비합니다.
- 스킬 본문에 플랫폼이나 모델의 이름을 무조건 강제하지 않습니다. 필요한 기능만 명시하고 실제 도구 이름은 현재 제공된 목록에서 확인합니다. 사용하지 않는 도구를 위해 새 연결을 만들지 않습니다.

파일 생성은 현재 세션의 인식이나 업무 성공을 증명하지 않습니다. 합성 입력 1건과 잘못된 입력 1건을 실제 실행하고, 외부 쓰기 기능은 승인된 시험 대상에 한정합니다. 설명/정적 검토만 했다면 그 범위를 분명히 알립니다.

## 파일을 생성하는 실행 코드일 때만

업무 루트를 입력 또는 실행 파일 위치에서 절대경로로 확정하고 존재하는 폴더인지 확인합니다. `cd` 실패 뒤 명령을 이어 쓰지 않습니다. 하위 프로세스에는 `cwd=work_root`를 지정하고, 입력 자료 폴더를 작업 폴더처럼 사용하지 않습니다.

```python
from pathlib import Path
from tempfile import TemporaryDirectory
# 입력 업무 폴더를 먼저 확인하고, 임시 결과도 그 안에서만 만듭니다.
work_root = Path(work_folder).resolve(strict=True)
if not work_root.is_dir():
    raise NotADirectoryError('업무 폴더를 확인해 주세요.')
staging = work_root / '.build'
staging.mkdir(exist_ok=True)
with TemporaryDirectory(dir=staging, prefix='run-') as stage:
    # 입력 검증 → 임시 결과 작성 → 완성 검사 후 게시 순서로 구현합니다.
    # 실패하면 이전 정상 결과를 지우지 않습니다.
    pass
```

읽기 전용 자료를 import할 때는 `python -B` 또는 import 전 `sys.dont_write_bytecode = True`로 입력 폴더의 `__pycache__` 생성을 막습니다. 재생성 코드는 정상본을 먼저 삭제하지 말고 같은 실행의 결과/명세/근거를 함께 게시하며 실패 시 복원합니다. 새 실행과 실패 주입 검사는 이 재생성기를 만드는 때만 수행합니다. 오류 테스트는 단순한 예외 발생이 아닌 오류 코드와 실패 원인, 기존 결과 보존까지 확인합니다.
