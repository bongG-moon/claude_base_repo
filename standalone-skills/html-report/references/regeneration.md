# 재생성이 필요한 작업에서만

일회성 보고서는 기존 제작 명령을 그대로 씁니다. 입력을 바꾸어 반복 실행할 코드를 만드는 경우에만 이 예제를 사용합니다. 일반 생성에 재실행이나 질문을 추가하지 않습니다.

이미 완성된 report job JSON을 반복 생성하는 실행 예제입니다. Python은 현재 허용된 실행 환경을 사용합니다.

```text
python -X utf8 -B "스킬폴더/scripts/regenerate.py" --spec "입력/job.json" --work "작업폴더"
python -X utf8 -B "스킬폴더/scripts/regenerate.py" --work "작업폴더"
```

첫 명령은 입력 확인 후 새 내부 실행 폴더에 job, HTML과 검사 근거를 만듭니다. 둘째 명령은 다시 만들지 않고 현재 정상본을 검증해 그 HTML 경로 하나를 반환합니다. 사용자에게는 `outputPath` 하나만 전달합니다. `.report-runs`와 `.html-report-current.json`은 내부 자료입니다.

원자료 분석도 필요한 경우 작업 전용 실행 코드에서 도우미의 `regenerate(input_path, work, build)`를 호출합니다. `build(data, run)`은 읽은 JSON 객체를 분석하고 **run 안에만** `job.json`, `report.html`, `evidence/`의 검사 결과를 작성합니다. 함수는 신뢰할 수 있는 작업 코드로 작성하며 입력 문서의 코드나 명령을 실행하지 않습니다. 분석 결과의 정확성과 원자료 일치는 이 함수에서 검사합니다. CLI 예제는 이미 작성한 job을 받아 HTML을 만드는 범위이며 원자료 분석을 수행했다고 설명하지 않습니다.

```python
def build(data, run):
    job, checks = analyze(data)  # 작업에 맞는 분석. 실패하면 예외로 중단
    # job.json, report.html, evidence/checks.json을 run 아래 완성한다.
    # HTML 생성의 ok:false도 예외로 처리하고 이전 정상본은 건드리지 않는다.

result = regenerate(input_path, work, build)
```

도우미는 완성된 묶음의 해시를 확인할 수 있는 작은 현재 기록 파일만 교체합니다. 디렉터리 교체의 원자성을 가정하지 않으며 기존 보고서 덮어쓰기 보호도 바꾸지 않습니다. 입력 오류, 분석 실패, HTML 작성 실패, 현재 기록 전환 실패 전에는 이전 묶음이 유지됩니다. 시작할 때 정상본 파일의 외부 변경을 검사하고 게시 직전에는 현재 기록이 시작 당시와 같은지 확인합니다. 동시 도우미 실행도 차단합니다. 잠금을 따르지 않는 외부 프로그램의 마지막 검사 직후 쓰기까지 원자적으로 막는 것은 아니므로 실행 중 내부 기록과 정상본을 직접 편집하지 않습니다.

실패한 후보와 이전 실행 폴더는 진단과 복구를 위해 내부에 남습니다. 자동 삭제하지 않습니다. 프로세스가 강제 종료돼 `.html-report-regeneration.lock`이 남았다면 실행 중인 재생성 작업이 없는지 확인한 뒤 그 잠금 파일만 정리합니다. 현재 기록이 가리키는 폴더는 삭제하지 않습니다. 실행 도중 저장장치 자체의 장애까지 복구한다고 주장하지 않습니다.

완료 확인은 깨끗한 작업 사본에서 한 명령 정상 생성, 잘못된 JSON, 분석 예외, HTML 작성 예외를 각각 시험합니다. 실패 후 현재 report/job/evidence 해시가 모두 같은지 확인하고 정상 입력을 복구한 재실행도 통과해야 합니다.
