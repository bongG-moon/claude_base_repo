# 보고서 디자인

## 목적에 맞게 선택

기본 `minimal`은 긴 글·업무 요약, `bento-grid`는 지표 비교입니다. 추가 디자인을 요청하면
아래 이름·특징만 보여주고 선택을 받습니다. 이미 추천을 맡겼다면 목적에 맞게 직접 고릅니다.

|이름|명세 style|잘 맞는 표현|
|---|---|---|
|미니멀리즘|minimalism|여백·짧은 강조|
|벤토그리드|bento-grid|크기가 다른 지표 구획|
|에디토리얼|editorial|큰 제목·내용 흐름|
|글래스모피즘|glassmorphism|밝은 유리판·은은한 색|
|뉴모피즘|neumorphism|부드러운 그림자|
|브루탈리즘|brutalism|굵은 선·강한 대비|
|그라디언트 메시|gradient-mesh|배경의 부드러운 색 변화|
|자유양식|freeform|구획의 비대칭 조합|
|3D·이머시브|immersive-3d|갈색·베이지 입체 장식|
|레트로·Y2K|retro-y2k|은빛·파스텔|

## 공개 사례에서 정리한 구성 원칙

아래는 공개 HTML 보고서·발표 자료를 검토해 **이미 이 스킬에 반영한 작성 기준**입니다.
실행 중 웹을 검색하거나 사례 사이트를 열지 않습니다. 기존 job 작성·화면 검토에서 적용합니다.
선택한 스타일·글꼴·분량·표시 방식과 첨부 양식이 우선이며 구성 방식을 별도로 질문하지 않습니다.

| 목적 | 내용의 읽기 순서 | 실제 명세에 반영할 부분 |
|---|---|---|
| 현황·지표 보고 | 결론과 집계 범위 → 핵심 지표 → 차이·추이 → 상세와 확인 사항 | 첫 `summary`에 결론·기준일, 필요한 `dashboard`에 계산된 `kpis`·차트, 긴 원자료는 뒤의 `table` 구획 |
| 원인·개념 설명 | 알아볼 질문 → 작은 예시 → 비교 근거 → 해석 → 적용 조건·한계 | 질문·결론은 `title`, 근거는 `chart/table`, 해석은 `body`. 근거 뒤 해석은 `contentOrder:["chart","body"]` 등 실제 항목 순서로 지정 |
| HTML 발표 | 한 화면의 메시지 → 읽을 수 있는 근거 → 다음 판단 | 선택한 `mode`를 유지하고 구획당 한 메시지. 짧은 설명과 표·차트가 함께 있을 때 `split`, 긴 표는 별도 `table`, 마지막은 `summary` |

- 구성은 자료에 맞게 조합합니다. 모든 보고서에 표지·KPI·흐름도·다섯 단계를 강제하지 않습니다. 짧은 요청은 결론과 근거를 한 구획에 모읍니다.
- 제목만 훑어도 논지가 이어지게 씁니다. `신청 현황`보다 근거가 있을 때 `신청은 늘었지만 대기 인원도 증가했습니다`처럼 판단을 전달합니다. 상관관계를 원인으로 바꾸지 않습니다.
- 차트에는 비교 기준·단위·기간을 붙이고 곁에 해석을 둡니다. 출처·표본 수·제외 조건은 `source`에 씁니다. 모르면 미확인으로 남기며 각 수치는 원자료에서 계산합니다.
- 설명은 읽기 좋은 폭, 표·차트는 충분한 폭을 줍니다. 짧은 설명과 근거는 좌우 배치하고, 긴 한글 설명은 세로로 바꿉니다. 없는 오른쪽 내용을 장식으로 채우지 않습니다. `contentOrder`를 넣으면 세로 배치가 우선하므로 좌우 배치와 혼용하지 않습니다.
- 첫 화면의 핵심, 중간의 비교·해석, 끝의 상세·한계를 구분합니다. 같은 카드 모양으로 모든 내용을 반복하지 않고 요약과 원자료를 구별합니다.
- 발표 화면은 본문을 작게 줄여 끼워 넣지 않습니다. 긴 표·설명은 의미 단위로 나누되 요청한 자료를 누락하지 않습니다. 강조는 핵심 문장·수치에만 쓰고 페이지 전환은 기존 `motion:subtle` 또는 사용자가 고른 값으로 충분합니다.

내부 명세의 순서·`layout`·제목·해석·출처에 반영해야 적용한 것입니다. 설계 설명만 하고
기존 카드 나열을 그대로 만들지 않습니다. 위 기준은 기존 내용·화면 검토에 포함하며 검증 명령을 더 만들지 않습니다.
참고 사례의 코드·문구·사진·색상·영문 폰트를 복제하지 않습니다. 한국어의 줄 길이와 선택한 글꼴로 다시 구성합니다.
출처와 채택 이유는 [공개 사례 검토 기록](design-sources.md)에 있습니다. 근거를 묻거나 스킬을 관리할 때만 읽습니다.

### 레퍼런스를 선택했을 때

초기 디자인 메뉴에서 레퍼런스를 고르거나 `레퍼런스 2로 만들어줘`라고 직접 말할 수 있습니다.
색상 스타일을 따로 정했다면 유지하고, 없을 때만 아래 기본 스타일을 씁니다.

| 선택값 | 기본 스타일 | 작성·출력에 반영되는 구성 |
|---|---|---|
| `reference-1` · 스토리형 설명 | editorial | 질문·예시·근거·해석·한계로 내용을 구성합니다. 별도 배치 지시가 없는 구획은 근거 뒤에 해석을 세로로 배치합니다. |
| `reference-2` · 데이터 리포트형 | bento-grid | 핵심 지표·주제별 비교·상세를 구분합니다. 스크롤 보기에는 구획을 찾는 목차가 생깁니다. 페이지 보기에서는 목차를 숨깁니다. |
| `reference-3` · 발표형 | minimalism | 한 화면의 메시지와 근거를 구성합니다. 별도 배치 지시가 없고 설명과 근거가 함께 있으면 좌우로 놓으며 넓은 화면에서는 근거 쪽을 넓게 씁니다. |

명세 맨 위에 `referencePreset`을 유지합니다. 기존 `style/fontChoice/length/mode`를 덮지 않으며,
이미 명시한 `layout/contentOrder`가 기본 배치보다 우선합니다. 문서 구획 순서·원자료·수식 참조는
실행기가 재정렬하지 않습니다. 작성자가 선택한 구성에 맞는 논지와 실제 내용을 작성해야 합니다.
새 참고 파일·사이트 연결·미리보기 승인을 요구하지 않습니다. 기존 양식 직접 첨부 절차는 별개입니다.


## 글꼴과 간격

Noto Sans KR은 긴 한글 본문, Pretendard는 숫자·버튼·표, 나눔스퀘어 네오는 제목·짧은 안내에
잘 맞는 선택지입니다. 자동 선택이면 참고 양식 우선, 없으면 본문형 Noto Sans KR·지표형 Pretendard를 사용합니다.
실제 설치가 없으면 대체 글꼴로 표시된다는 점을 알립니다. 글꼴 이름만 바꿔 정확히 같은 모양이라고 주장하지 않습니다.
HTML 참고에서는 페이지·본문 글꼴과 제목 글꼴을 구분합니다. 코드·아이콘의 부분 글꼴이나
작은 배지의 둥근 모서리를 전체 보고서 스타일로 옮기지 않습니다. 정적 분석은 단순 선택자만
지원하므로 미디어 조건·외부 CSS 등으로 결정되는 최종 모양은 실제 화면을 보기 전에는 미확인입니다.

- 제목·핵심 수치·본문·출처의 크기와 강조를 구분합니다. 모든 내용을 굵게 만들지 않습니다.
- 4/8px 계열의 간격을 일관되게 사용하고 관련 내용은 가까이, 다른 구획은 더 넓게 둡니다.
- 긴 한글·숫자·빈 항목·좁은 화면에서 겹침과 가로 넘침을 확인합니다. 데이터 표는 의미를 유지한 채 스크롤할 수 있습니다.
- 보통 글자 대비 4.5:1, 키보드 초점·버튼 이름·표의 제목을 확인합니다. 클릭할 수 없는 장식에 버튼 모양을 쓰지 않습니다.
- 애니메이션은 관계 설명에 도움이 될 때만 짧게 사용하고 reduced-motion을 존중합니다. 내용 읽기를 기다리게 하지 않습니다.
- 반복 카드를 모든 구획에 쓰지 않습니다. 비교는 표, 추이는 차트, 관계는 요청된 도식 등 의미에 맞춰 선택합니다.

## 화면 한쪽이 비지 않게 배치

- 설명과 시각 자료가 모두 있을 때만 좌우 분할을 씁니다. 한쪽이 없으면 한 열로 펼치고, 글만 있는 구획은 읽기 좋은 폭으로 가운데 놓습니다. 큰 판 안에서 글줄만 왼쪽 절반에 가두지 않습니다.
- 카드 수에 맞춰 열과 마지막 줄을 정합니다. 전체 폭 표 앞뒤의 카드 묶음마다 홀수로 남는 카드는 넓히며, 읽기 순서를 바꾸는 `dense` 재배치는 피합니다. 지표가 하나면 전체 폭을 씁니다.
- 표지의 오른쪽 예약 공간은 실제 이미지·장식이 있을 때만 둡니다. 자료가 없거나 좁은 화면·인쇄에서 사라진 장식 자리를 그대로 남기지 않습니다. 요청한 비대칭 연출과 가독성을 위한 여백은 보존합니다.
- 기존 화면 검토에서 390px·1280px 이상의 첫·중간·마지막 구획을 확인합니다. 빈 칸은 열 수·폭·정렬·간격으로 고칩니다. 허위 수치·불필요한 그림·복제 내용으로 채우지 않습니다. 표·차트는 구획 폭을 쓰고 큰 표만 내부 스크롤합니다.

참고(2026-10-26): [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)의 범위에 맞춘 반응형·밀도 점검,
[frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design)의 내용 중심 배치·읽기 폭 원칙.
추가 디자인 검색 도구·모델 호출 없이 기존 작성·검토 단계에 적용합니다.

직접 작성한 한국어는 번역투·반복·근거 없는 과장을 줄입니다. 수치·인용·부정·조건·확정 정도·회사 고정 문구는 보존합니다.
이미 승인된 표현을 디자인 이유만으로 바꾸지 않습니다. 합계·분모·기간·단위는 원자료로 확인합니다.
참고 자료의 장르·문단 길이·종결 어미, 주체·행동·조건을 유지합니다. 보고서 목록과 제목을
기계적으로 없애지 않습니다. `시험 조건에서 처리 시간이 12% 줄어들 수 있음`을 `12% 단축`으로
단정하지 않습니다. 별도 교정 단계 없이 작성할 때 반영합니다.

## 전체 읽기 흐름과 짧은 전환

첨부 양식과 확정한 글꼴·색을 유지하며 제목→근거→상세 자료의 순서와 밀도를 맞춥니다.
표지뿐 아니라 긴 표·빈 값·마지막 구획도 같은 수준으로 다듬고, 없는 값과 0을 구분합니다.
`motion:subtle`이 기본이며 페이지 보기에서만 180ms 페이드, 버튼에는 120ms 색·테두리 반응이
있습니다. 별도 질문은 하지 않습니다. 요청이 없으면 스크롤 구획 반복 등장·숫자 카운트업·
긴 지연을 넣지 않습니다. `motion:none`, OS 움직임 줄이기, 인쇄에서는 전환을 끕니다.
스크립트가 동작하지 않아도 전체 본문은 보입니다. 표 스크롤·키보드·연속 클릭을 기존 검토에서 확인합니다.

## 데이터 탐색이 기본인 보고서

데이터를 담는 구획은 `data-tables.md`의 계약을 적용합니다. 검색과 필터, 정렬, 스크롤과 페이지 이동, 다운로드를 장식이 아닌 기본 동작으로 구현합니다. 작은 비교표는 간결하게 유지하고 상세 자료에는 전체 폭을 줍니다. 실제 참고 화면의 밀도와 읽는 순서를 사용하며 색상과 글꼴은 사용자가 고른 값을 유지합니다. 스크립트 실패에도 내용이 숨겨지지 않고 동작이 없는 버튼은 두지 않습니다.
