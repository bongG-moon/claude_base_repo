# HTML 보고서: 실제 사례와 적용 기준

최신 검토일: **2026-11-03**. 아래 공개 페이지는 본문과 브라우저 화면을 확인했습니다.
인기 순위나 만족도 측정 결과가 아니라, 업무 보고서에 활용할 수 있는 정보 구성 사례입니다.
**스킬 실행 절차가 아닙니다.** 작성할 때마다 검색하거나 링크를 다시 열지 않습니다.
외부 코드 설치 없이, 선택한 레퍼런스에 필요한 원칙만 기존 제작 방식으로 구현합니다.

## 기존 선택과의 관계

| 선택 | 적용 목적 | 유지할 의미 |
|---|---|---|
| `reference-1` 스토리형 설명 | 원리, 사례, 문제 해결 과정을 이해시키기 | 질문 → 사례/비교 → 해석. 현황을 보고할 때는 핵심 판단을 먼저 제시 |
| `reference-2` 데이터 리포트형 | 조건별 수치와 상세 데이터를 확인하기 | 요약 → 차트/표 탐색 → 근거와 내려받기 |
| `reference-3` 핵심 브리핑형(기존 발표형) | 한 구획에 메시지와 근거를 집중하기 | 기존 발표형 선택과 호환. 선택한 스크롤/페이지 보기 유지 |

기존 ID와 기본 테마를 변경하지 않습니다. 레퍼런스는 구성 방식이며 사용자 색상, 글꼴,
분량, 보기 선택을 덮어쓰지 않습니다. 사용자 양식이 있으면 그 양식의 특징을 우선합니다.

## 공개 사례에서 가져올 부분

### GitHub Octoverse 2026 — 판단과 근거를 연결하는 보고서

- [확인한 HTML 본문](https://github.blog/news-insights/octoverse/octoverse-commits-pushes-reach-new-highs-in-2026-as-developers-build-with-agents/)
- 관찰: 제목과 소개 뒤 핵심 발견을 제시하고, 주제별 차트와 해석, 상세 표, 용어와 방법론이 이어집니다. 본문의 우측 목차에서 실제 구획으로 이동하며 현재 위치를 표시하는 것을 확인했습니다.
- 적용: **핵심 판단 → 근거 그림/수치 → 업무 의미**를 가깝게 묶습니다. `reference-1`의 설명 흐름과 `reference-3`의 짧은 브리핑에 필요한 부분만 씁니다. 긴 보고서는 목차와 근거 설명을 분리해 찾기 쉽게 합니다.
- 제외: 브랜드 이미지, 홍보형 큰 헤더, 관련 글 추천, 장식 중심 색상. 근거 없는 수치를 채워 넣거나 전체 페이지 구성을 기계적으로 복제하지 않습니다.

### Our World in Data Energy mix — 탐색과 출처가 함께 있는 데이터 화면

- [확인한 데이터 페이지](https://ourworldindata.org/grapher/energy-mix)
- 관찰: 지표 설정과 단위/기간, 차트 옆 검색 가능한 선택 패널, 표/지도/선 그래프 전환을 확인했습니다. 표로 전환하면 옆 패널 대신 표가 넓게 배치되고 내부 스크롤, 검색, 필터, 추세 표시가 나타납니다. 결과 가까이에 출처가 있고, 아래에는 처리 설명과 전체/현재 표시 데이터 다운로드가 구분돼 있습니다.
- 적용: `reference-2`는 **요약과 탐색을 분리**하고, 차트와 표의 내용에 맞춰 폭을 배분합니다. 긴 표에 검색/필터와 스크롤 또는 페이지 탐색을 제공하며, 단위/기간/출처와 다운로드 범위를 함께 표시합니다. 표시한 데이터가 일부라면 전체 건수와 구분합니다.
- 제외: 원격 데이터 API, 지도/차트 엔진 전체, 자동 재조회, 공유/구독 UI. 실제 데이터가 없으면 추세나 내려받기 버튼을 장식으로 만들지 않습니다.

### GOV.UK 단계별 안내 — 필요한 설명을 단계 안에서 펼치기

- [확인한 실제 안내](https://www.gov.uk/learn-to-drive-a-car), [공식 패턴 설명](https://design-system.service.gov.uk/patterns/step-by-step-navigation/)
- 관찰: 짧은 목적 설명, 번호가 있는 단계, 선행조건과 하위 작업, 병렬 `and` 단계가 있습니다. 개별 펼침 버튼을 확인하고 전체 펼침을 실행했습니다.
- 적용: 별도 네 번째 레퍼런스를 추가하지 않고, 업무 흐름이 있는 보고서의 보조 패턴으로 사용합니다. **단계 목적 → 입력 → 실제 처리 → 결과/예외**를 쉬운 한국어로 설명하고 상세 내용은 필요할 때 펼칩니다. 순서가 있는 일과 병렬/선택 작업을 구분합니다.
- 제외: 행정 사이트의 좁은 본문과 큰 오른쪽 빈 공간, 다른 서비스로 이어지는 긴 링크 목록. 넓은 화면에서는 본문을 중앙 정렬하거나 실제 보조 설명에 폭을 배분합니다. 읽기만 하면 되는 내용을 억지로 체크리스트로 바꾸지 않습니다.

## 사용자 제공 설명 보고서에서 일반화한 기준

시나리오를 따라 선택하거나 상세 내용을 펼치며 이해하는 방식을 참고합니다. 처음에는
핵심 설명과 전체 흐름을 보여주고, 특정 단계의 동작과 근거를 같은 위치에서 확인하게 합니다.
현재 보고서에 필요한 상호작용만 구현하며 조작 후 어떤 내용이 바뀌었는지 명확히 보여줍니다.
개인 업무 내용, 파일 경로, 구체 제품명, 원본 문구와 스크립트는 공개 자료나 배포 문서에 옮기지 않습니다.

## 유지하는 이전 참고 사례

아래는 **2026-10-26 검토 기록**에서 유지한 원칙이며 이번에 다시 화면 검증한 사례는 아닙니다.

- [Benford's Law 설명](https://benfords-law-explainer.netlify.app/): 질문 → 짧은 예시 → 비교 → 해석을 `reference-1`에 활용합니다. 긴 스크롤 연출과 시뮬레이션은 기본으로 추가하지 않습니다.
- [State of JavaScript 2024 조사 본문](https://2024.stateofjs.com/en-US/demographics/): 주제별 구획, 응답 수와 비율, 기준과 해석을 함께 두는 원칙을 유지합니다. 대규모 질의 빌더는 추가하지 않습니다.
- [Quarto Reveal.js 공식 데모](https://quarto.org/docs/presentations/revealjs/demo/): `reference-3`의 제목/본문 위계와 근거 영역의 충분한 폭을 참고합니다. Quarto/Reveal.js 런타임이나 PPT 제작 절차를 HTML 보고서에 추가하지 않습니다.

## 적용 경계

공개 사례의 구성 패턴을 재작성하며 원문 코드, 이미지, 문구, 데이터를 패키지에 복사하지 않습니다.
사용자 자료는 공개 사이트로 전송하지 않습니다. 외부 사례가 현재 내용에 맞지 않으면 기본 구성으로
단순화하되 선택된 디자인과 글꼴을 유지합니다. 모든 양식에 차트, 카드, 애니메이션, 다단 배치를
의무적으로 넣지 않습니다. 빈 열은 없애고 표는 읽을 폭을 확보합니다. 자료 검토나 문구 수정만
요청한 경우 새 스타일 질문이나 전체 구성 절차를 시작하지 않습니다.
