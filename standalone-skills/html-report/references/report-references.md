# 완성 예제를 업무 내용으로 바꾸기

레퍼런스를 골랐을 때만 읽습니다. 갤러리는 [디자인 선택](../assets/design-picker.html)이며 예제의 수치는 모두 가상 자료입니다. 개인 업무 원문이나 공개 사이트의 코드와 브랜드를 복제한 양식이 아닙니다. 일반 실행 중 새 웹 검색을 하지 않습니다.

| 구성 | 완성 예제 | 새 내용으로 적용할 부분 |
|---|---|---|
| 스토리형 설명 | [레퍼런스 1](../assets/examples/reference-1.html) | 질문으로 시작하고 작은 사례의 입력, 처리, 결과를 보여준 뒤 비교 근거와 적용 한계를 설명합니다. |
| 데이터 리포트형 | [레퍼런스 2](../assets/examples/reference-2.html) | 집계 기준과 핵심 지표에서 근거 차트, 전체 폭 상세 표로 이어집니다. 목차, 표 검색과 필터, CSV의 범위가 실제 자료와 맞아야 합니다. |
| 핵심 브리핑형 | [레퍼런스 3](../assets/examples/reference-3.html) | 핵심 판단과 근거를 나란히 놓고 선택지, 실행 순서와 조건을 정리합니다. 기존 발표형 ID와 사용자가 고른 페이지 보기 역시 유지합니다. |

색상 테마와 문서 구성은 다릅니다. `referencePreset`을 유지하면서 이미 정한 `style`, 글꼴, 분량과 보기 방식을 그대로 사용합니다. 아무 선택도 바꾸지 않고 예제를 보여줄 수 있습니다. 섹션 순서를 자동으로 재정렬하거나 빈 정보를 지어내지 않습니다.

## 완성도를 만드는 작성 기준

- 첫 화면에는 질문 또는 판단과 그에 맞는 실제 근거를 놓습니다. 좌우 분할은 설명과 시각 자료가 모두 있을 때 사용합니다. 글만 있다면 읽기 좋은 폭으로 가운데 배치합니다.
- 본문 설명, 비교표, 전체 폭 데이터와 상세 펼침을 목적에 맞게 조합합니다. 모든 내용을 같은 카드로 나누거나 빈 칸을 채우기 위해 KPI를 만들지 않습니다.
- 같은 조건에서 처리 결과가 달라지는 이유가 중요하면 `scenarios`로 입력, 처리 순서와 결과를 함께 전환합니다. 단순 문단이나 하나의 절차라면 일반 본문을 사용합니다.
- `details`에는 보조 기술 설명, 집계 방식과 추가 근거를 둡니다. 결론을 판단하는 데 꼭 필요한 조건은 접힌 영역에만 숨기지 않습니다.
- 기간, 단위, 제외 조건과 출처를 관련 결과 가까이에 표시합니다. 고정 KPI가 표 필터와 함께 바뀐다고 설명하지 않습니다. 가상 예제와 실제 측정값을 구분합니다.

기본 읽기 흐름은 본문 → 선택한 사례 → 상세 설명 → 출처입니다. `contentOrder`는 기존 본문 항목의 순서만 지정하며 `scenarios`나 `details`를 넣지 않습니다. 정확한 필드와 제한은 내용 명세를 따릅니다.

기존 화면 검토에서 사례를 두 번 이상 바꿔 입력, 처리와 결과가 함께 바뀌는지 보고, 상세 펼침과 표 검색을 확인합니다. 좁은 화면은 읽는 순서와 내부 표 스크롤을 확인합니다. 새로운 승인이나 별도 심사 단계를 추가하지 않습니다. 브라우저로 보지 못했다면 실제 화면 미검증이라고 전달합니다.
