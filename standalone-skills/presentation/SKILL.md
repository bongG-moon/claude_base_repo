# 편집 가능한 발표자료

이 배포본은 Company Harness·세션 ID·전용 작업자 없이 동작합니다. Python 3.11 이상과
`requirements.txt`의 python-pptx가 필요합니다. 설치·모델 전환·MCP 등록은 하지 않습니다.
명령의 `스킬폴더`는 **이 SKILL.md가 있는 폴더**입니다.
실행에는 배포 ZIP 전체를 설치한 폴더를 사용합니다. 저장소의 원본 폴더는 공통 렌더링 코드를
패키징할 때 포함하는 개발용이며, 원본 SKILL.md나 scripts만 복사한 상태는 실행용 배포본이 아닙니다.

## 내용과 참고 자료

알려준 목적, 청중, 장수와 기존 job, 선택을 재사용하고 빠진 핵심 조건만 묻습니다. **새 제작에 디자인 지정도 참고자료도 없으면** `references/choices.md`에 따라 양식 선택을 한 번 보여 줍니다. 깔끔한 업무 보고형 / 흑백 간결형 / 따뜻한 설명형 / 기존 PPT·이미지·HTML 양식 활용 / 내용에 맞게 추천 / 직접 입력 중 고르게 합니다. 번호나 이름으로 답할 수 있게 하며 사용자가 JSON을 작성하게 하지 않습니다. `알아서/추천대로/질문 없이`는 추가 디자인 질문 없이 내용에 맞게 구성합니다. 수정 요청과 이미 받은 디자인에는 선택을 반복하지 않습니다.

이미지 크기 수정만 요청한 경우 새 초안 승인 절차를 시작하지 말고 현재 호스트의 편집 도구 또는 허용된 Python으로 지정 개체만 수정합니다.

PPTX·HTML·이미지 모두 참고할 수 있습니다. 참고 자료가 있을 때만 `references/reference-inputs.md`를
읽습니다. 첨부는 기본적으로 스타일 참고이며 명시적인 원본 배치 유지 요청에만 preserve를 씁니다. 필요한 PPT 장은 실제 정상 열기와 장별 캡처로 보고, 이미지 최대 60장은 전체 목록을 유지해 2~3장씩 확인합니다. 여러 장의 한글 서체, 크기, 여백, 배치, 표, 차트, 도형, 강조와 색 조합을 `referenceStyle`로 짧게 합쳐 새 내용에 맞게 재구성합니다. 도구 가용성과 미확인 장을 구분하며 보호 해제나 DRM 우회는 하지 않습니다. 참고가 있으면 기본 디자인 선택을 반복하지 않습니다.

한글 장표를 기준으로 제목과 본문, 강조와 주석의 서체 역할을 유지합니다. 내용에 맞으면 분기 흐름, 일정, 복합 도형과 곡선도 사용하며 단순한 카드나 표로만 평준화하지 않습니다. 복잡한 배치도 같은 장면 명세로 HTML을 먼저 만들고 승인 뒤 네이티브 PPT로 옮깁니다.
색은 사용자가 지정한 선택을 우선하고, 지정이 없으면 실제 참고 자료에서 관찰한 색 조합을 우선합니다. 관찰하지 않은 새 색은 참고 자료의 색으로 기록하지 않습니다.

## HTML 먼저, PPT는 다음

1. 전체 명세를 처음 작성할 때 `references/design.md`와 `references/schema.md`를 읽습니다. 새 디자인은 `pageRole`과 기존 목적에서 장별 역할을 정하고, `presentationProfile`에 확인한 한글 서체 역할과 여백을 간단히 유지합니다. 기존 job이나 참고 배치에 새 역할을 임의로 덮어쓰지 않습니다. 부분 수정은 현재 지침과 관련 필드만 재사용합니다. 장별 메시지와 근거를 먼저 정하고 그 관계에 맞는 배치를 고릅니다. 한 작업 폴더의
   `job.json`·내부 초안·최종 PPT 한 개를 유지합니다. 사용자 원본·다른 작업 결과는 덮어쓰지 않습니다.
2. 선택한 디자인과 실제 참고 관찰을 job에 반영한 뒤 `python "스킬폴더/scripts/presentation.py" draft --spec "job.json" --output "draft.html"`로 모든 장의
   HTML 초안을 만듭니다. 참고 양식을 실제로 사용하는 경우 같은 `--template "양식.pptx 또는 저장양식.html"`을 이후에도 유지합니다.
   반환된 `scenePreflight`에 경고가 있으면 승인 요청 전에 한 번 모아 살피고, 실제 문제만 같은 job에서 보정한 뒤 초안을 갱신합니다. 화면 확인이 불가능하거나 경고의 진위가 불확실하면 미확인으로 알려 줍니다. 경고를 없애려고 반복 보정하지 않으며 경고가 없으면 이 검토를 추가하지 않습니다.
3. 초안 전체를 확인하고 링크·전체 목차를 보여 줍니다. `이대로 PPT 제작 / 수정 요청`을 물어 실제 답을
   기다립니다. 이미지를 봤거나 파일을 열었다는 이유만으로 승인했다고 기록하지 않습니다.
4. 실제 승인 뒤 반환받은 `designReview`를 job.json에 그대로 넣고 `confirmed:true`로 표시합니다.
   내용·참고 자료·배치를 바꿨다면 같은 작업 안에서 초안을 갱신해 다시 확인합니다.
5. `python "스킬폴더/scripts/presentation.py" build --spec "job.json" --output "발표자료.pptx"`로 제작합니다.
   전용 하네스나 PowerPoint 앱을 시작하지 않으며, 생성 결과는 편집 가능한 네이티브 개체입니다.
6. 글자, 단위, 총계, 장수와 편집 가능 여부를 확인합니다. 호스트의 허용된 렌더링 도구가 있으면 처음에는 모든 장, 수정 뒤에는 변경과 영향받은 장을 검토합니다. 도구가 없다면 구조 검사만 했으며 화면 배치는 미확인이라고 표시합니다. 승인 후 내용·배치를 수정하면 초안부터 다시 확인받습니다. 최종 PPT 하나를 전달합니다.

글자는 색·굵기·폰트를 바꿀 수 있어야 합니다. 카드·관계도는 의미 있는 부분끼리만 그룹화하고
그룹 해제를 막지 않습니다. 전체 슬라이드를 이미지로 만들고 편집 가능하다고 설명하지 않습니다.
사진·스크린샷 내부의 글자는 별도 편집되지 않습니다. 캡처를 배경으로 붙이는 것은 편집 가능한 재구성이 아닙니다.
수치 문장을 옮길 때는 `{{fact:id.statement}}`로 지표 이름과 값을 함께 재사용하고 기존 fact의 기간, 범위와 분모를 유지합니다. 음수 막대, 항목명과 선 위 숫자의 실제 가독성은 이미 수행하는 렌더 검토에서 확인합니다.

## 필요할 때만

- 역할별 구성과 참고 서식 프로필: `references/schema.md`. 한 장에 표·차트와 도형을 함께 자유 배치해야 할 때만 실행 가능한 `references/scene-example.json`을 참고합니다. 부분 강조, 복합 도형, 연결선과 곡선은 `references/advanced-shapes.md`에 있습니다. 지원 형식 확인을 위해 렌더러 내부 코드를 반복 탐색하지 않습니다.
- PPT 배치를 보정했거나 반복 제작을 요청받은 경우: `references/rebuild-check.md`. 보정을 job 또는 재생성 코드에 남기고 전달본과 재빌드의 내용 및 배치를 비교합니다. 일반 생성에 매번 재빌드를 추가하지 않습니다.
- 기존 HTML 직접 변환: 같은 문서의 `htmlSource`. 선언형 HTML/CSS만 지원하며 승인된 Chrome/Edge가 필요합니다.
- 대표 양식 저장 요청: 확인한 명세로 `template --spec "job.json" --output "대표양식.html"`. 가상 내용으로
  저장하며 저장 위치를 사용자에게 확인합니다. 사업 내용이나 원본 이미지를 기억 저장소에 자동 보관하지 않습니다.
- 지원하지 않는 복잡한 CSS·마스터·SmartArt·애니메이션은 실제 한계를 알리고 지원 가능한 편집 개체로 재구성할지 확인합니다.

이미지 이해는 현재 호스트가 제공하는 비전 기능만 사용합니다. 없는 worker 이름을 호출하거나 base64 문자를
읽어 내용을 추측하지 않습니다. 읽기/캡처가 불가능하면 해당 참고 범위만 미확인으로 남깁니다.
