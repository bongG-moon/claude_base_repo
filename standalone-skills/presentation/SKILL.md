# 편집 가능한 HTML 발표자료

**HTML 자체가 기본 완성본**입니다. 자유 HTML/CSS로 디자인하고 공통 편집기를 붙입니다. 새 제작에 이전 PPT 제작기의 job JSON, pageRole이나 고정 카드 양식을 적용하지 않습니다. 하네스나 별도 모델, 상시 서버는 필요하지 않습니다.

## 기본 흐름

1. **내용과 방향**: 목적, 청중, 분량과 이미 정한 디자인을 이어받습니다. 참고 자료가 있으면 [스타일 관찰](references/style-transfer.md)부터 합니다. 참고와 디자인 지정이 모두 없을 때만 `업무 보고형 / 에디토리얼형 / 기술 설명형 / 알아서 구성 / 직접 지정`을 한 번 제시하고 분량과 폰트도 같은 질문에 묶습니다. `알아서`는 바로 제작합니다.
2. **자유 HTML 작성**: [작성 규약](references/free-html.md)을 읽고 장마다 `결론 / 근거 / 시각 구조`를 한 줄로 잡은 뒤 `presentation/.work/deck-source.html`에 전체 HTML을 작성합니다. 별도 계획서나 승인 단계를 추가하지 않습니다. 비교, 분기와 순서에 맞게 HTML/CSS와 인라인 SVG를 구성합니다. 문구에는 `data-edit`, 이동/크기 변경할 묶음에는 `data-object`를 붙입니다.
3. **편집기 결합과 전달**: `python "스킬폴더/scripts/slides.py" build --source "presentation/.work/deck-source.html" --output "presentation/outputs/발표본.html"`을 실행합니다. 브라우저가 있으면 [화면 검사](references/free-html.md#화면-검사)를 한 번 실행하여 모든 장의 화면과 잘림·겹침 후보를 봅니다. 발견된 문제는 저작 소스를 고친 뒤 새 파일로 빌드하고 영향받은 장만 재확인합니다. 화면 확인 불가는 구조 검사와 구분합니다.

발표 화면은 **한 화면에 한 장**이며 이전/다음 버튼, 좌우 방향키와 페이지 번호로 넘깁니다. 세로 스크롤 문서로 전달하지 않습니다. 전체 장표는 별도 보기로 열고 인쇄에는 모든 장을 포함합니다.

사용자는 **편집 → 문구/개체 선택 → 수정 → 수정본 저장**으로 사용할 수 있습니다. 저장한 HTML이 다음 작업의 정본입니다. 이전 job으로 덮어쓰지 않습니다. HTML만 요청했으면 여기서 완료하며 별도 승인이나 PPTX 제작을 추가하지 않습니다.

## 다섯 가지 핵심 기준

- **참고의 문법**: 색의 역할, 제목/본문 글꼴과 굵기, 여백, 표 밀도, 도형과 연결선, 강조 방식과 말투를 옮깁니다. 원본 문구나 실적을 새 사실로 복사하지 않습니다.
- **명확한 위계**: 제목은 작성 방법이 아닌 그 장의 결론을 말합니다. 제목, 근거, 보조 설명을 구분하고 긴 제목의 두 줄 공간을 먼저 확보합니다. 모든 장을 같은 카드 배열로 만들거나 화면 아래 절반을 이유 없이 비우지 않습니다.
- **수치와 관계 보존**: 서로 다른 단위를 같은 축으로 비교하지 않습니다. 표 행이나 분기 조건을 임의로 합치지 말고 필요한 경우 장을 나눕니다. 흐름은 자동 수행과 사람 판단을 구분하고 예외가 돌아가는 단계까지 연결합니다. 흐름선은 글자와 다른 상자를 가리지 않습니다.
- **읽을 수 있는 한국어**: 지정 폰트, 단어 단위 줄바꿈과 읽기 크기를 유지합니다. 작은 글자로 줄여 넣는 대신 정보량과 배치를 조절합니다.
- **실제 편집과 저장**: 핵심 도형 묶음도 선택 가능하게 둡니다. 원본 파일을 보존하고 클릭 가능한 링크, 장수와 저장 방법을 알려줍니다.

## 필요한 경우에만

- 첨부 PPT/HTML/이미지: [style-transfer.md](references/style-transfer.md)
- PPTX 요청 또는 이전 job 수정: [export-and-legacy.md](references/export-and-legacy.md)
- 설계 근거: [web-sources.md](references/web-sources.md)
