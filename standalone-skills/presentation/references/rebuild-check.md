# 보정을 다시 만들 수 있게 유지하기

PPT 배치를 보정했거나 반복 제작을 요청받은 경우에만 적용합니다. 일회성 정상 생성에 재빌드, 모델 호출이나 확인 질문을 추가하지 않습니다. 데이터 기반 인계에는 기존 job/facts의 기간, 집계 범위, 분모와 출처를 유지하며 별도 파일이나 질문을 늘리지 않습니다.

- 글자, 표, 차트 또는 위치를 고치면 지원하는 job 필드에 반영합니다. 지원 필드로 표현할 수 없는 후처리는 작업 전용 코드로 남기고 재생성 명령에 포함합니다. 전달 PPT만 수정하고 완료하지 않습니다.
- 같은 승인 명세와 참고 파일로 새 내부 경로에 재빌드합니다. 전달본과 새 결과를 아래 명령으로 비교합니다. 기존 결과를 지우거나 덮어쓰지 않습니다. 보정으로 내용이나 배치가 바뀌면 기존 초안 승인 계약을 따르며 승인값이나 해시를 만들어 넣지 않습니다.

```text
python -X utf8 -B "스킬폴더/scripts/compare.py" --expected "전달본.pptx" --rebuilt "작업폴더/재빌드.pptx"
```

`rebuild_matches`는 글자, 표, 차트와 내장 데이터, 개체 위치와 크기, 명시된 네이티브 개체 및 양식 구조가 같다는 뜻입니다. `rebuild_differs`의 `differences`는 변경된 장과 개체 경로를 최대 20개 보여 줍니다. 타임스탬프와 문서 핵심 속성의 차이 때문에 PPTX 전체 바이트가 같을 필요는 없습니다. 비교기는 두 파일을 읽기만 하며 Office를 실행하거나 재빌드하지 않습니다. 현재 제작 환경의 python-pptx를 사용하며 의존성을 자동 설치하지 않습니다.

비교 통과가 화면의 가독성을 보장하지는 않습니다. 실제 렌더가 가능하면 표 겹침, 차트 라벨 간격, 작은 글씨, 제목과 값의 의미를 확인합니다. 수정 후에는 영향받은 장만 다시 봅니다. 렌더가 불가능하면 구조 검증만 했다고 표시합니다. 모든 장에 고정 글자 크기를 강제하지 않습니다.

초안 상태는 가능하면 본문 밖의 미리보기 안내에 둡니다. 이미 승인된 본문의 “승인 대기” 등의 문구를 숨겨서 자동 변경하지 않으며 필요한 수정은 기존 승인 계약에 맞춰 처리합니다. 같은 잘못된 배치가 두 파일에 남아도 비교는 통과하므로 실제 화면 확인과 구분합니다.
