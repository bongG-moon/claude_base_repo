# 편집형 HTML 발표본과 PPTX 내보내기

## 모든 디자인의 기본 형식

`presentation.py draft`는 처음부터 페이지 이동, 전체 보기, 발표 메모, 문구 편집,
수정본 저장과 인쇄가 있는 독립 HTML 발표본을 만듭니다. 조작 방식은 공통이며 슬라이드의
색상, 글꼴, 배치와 내용은 job 또는 참고자료를 따릅니다. 이 HTML이 기본 결과물입니다.
HTML만 요청한 경우 PPTX 승인이나 내보내기 절차를 시작하지 않습니다.

브라우저의 `문구 편집`은 글자와 표 셀의 내용을 바꾸는 기능입니다. 도형 위치나 서식까지
마우스로 바꾸는 전체 편집기는 아닙니다. 디자인 변경은 기존 job과 선택을 이어서 수정합니다.
문구를 바꾼 뒤 `수정본 저장`으로 새 HTML을 저장하면 해당 파일에도 발표 기능이 유지됩니다.

## 선택한 흑백 보고형 디자인

[고정 한국어 양식](korean-report-deck.md)은 제공한 흑백 디자인을 선택했을 때 deck.py로 내용을 채우는 경로입니다. 모든 글자는 실제 한국어
본문이며 과한 빈 공간 대신 표와 설명, 관계도를 내용에 맞게 배분합니다. 예시의 팔레트나
말투를 다른 첨부 양식에 강제로 적용하지 않습니다. CSS 전체를 SKILL.md에 붙여 넣지 않습니다.

## 완성하거나 편집해 저장한 HTML을 PPTX로

완성된 시각 배치를 다시 기본 카드로 만들지 않습니다. HTML 수정본의 내용을 이전 job의
본문으로 덮어쓰지 않습니다. 업무 폴더에 별도의 변환 job을 만들고 **실제로 저장한 HTML**을
원본으로 지정합니다. 이 스킬의 공통 발표 화면에서 문구나 표 셀을 편집해 저장한 파일은
`nativeDeck:true`로 가져옵니다. selector나 deckMode는 추가하지 않습니다.

```json
{"title":"발표자료","creationMode":"reference","purpose":"업무 보고","audience":"담당자",
 "htmlSource":{"path":"수정한-발표본.html","nativeDeck":true}}
```

```text
python "스킬폴더/scripts/presentation.py" draft --spec "job.json" --output "PPT-변환-검토본.html"
```

파일 path는 실제 업무 폴더의 정확한 경로입니다. nativeDeck은 저장본의 장면 구조와 편집 대상
식별자를 검증하고 현재 HTML의 문구와 표 셀을 반영합니다. 네이티브 차트와 복합 도형 구조를
유지하며 단순 SVG 그림으로 다시 추정하지 않습니다. 사용자가 임의로 CSS나 배치를 수정한
외부 편집까지 보존하는 경로는 아닙니다. 그 경우 아래 일반 HTML 변환과 한계를 적용합니다.

## 외부 HTML 또는 고정 흑백 deck.py 양식

외부 HTML은 실제 장을 가리키는 selector를 사용합니다. 흑백 deck.py 양식은 아래처럼
`#slides > .slide`와 deckMode를 사용하며 nativeDeck을 지정하지 않습니다.

```json
{"title":"발표자료","htmlSource":{"path":"흑백-발표본.html","selector":"#slides > .slide","deckMode":true}}
```

deckMode는 선택한 장에 active 클래스를
적용하고 바깥 발표 프레임의 화면용 확대/축소를 제외하는 명시적 변환 모드입니다.
일반 정적 HTML에는 생략합니다. 원본 파일과 CSS는 수정하지 않습니다. 다른 방식으로 감춘
장이나 복잡한 변형은 실패 사유를 알리며 추측해서 바꾸지 않습니다.

설치된 Chrome/Edge의 격리 프로필에서 스크립트를 제거한 사본의 실제 글자 위치를 읽습니다.
발표 툴바는 PPT 내용에 들어가지 않으며 원본 JavaScript, 외부 주소와 인증은 실행하지 않습니다.
모든 장과 표의 행/열 크기, 대표 머리글/본문 색, 도형과 글자를 편집 개체로 옮깁니다.
셀마다 다른 색/강조, CSS 점선과 복잡한 테두리/그라디언트는 정확한 재현을 보장하지 않습니다.
일반 차트가 아니라 CSS 막대라면 편집 가능한 도형임을 알립니다. 자동으로 한 장 이미지를
붙여 넣거나 지원하지 않는 요소를 조용히 빼지 않습니다.

변환 검토본도 같은 발표 조작 기능을 제공합니다. 전체 변환 검토본의 링크와 한계를 보여 주고
실제 승인 뒤 새 designReview를 기록하여 build합니다. 수정본을 저장했다는 사실은 PPTX 승인과
다릅니다. 이전 job의 designReview를 재사용하지 않습니다. nativeDeck의 장면 구조도 현재
문구를 반영한 새 검토본으로 확인하며 저장본에 오래된 승인이 있다고 가정하지 않습니다.
캐시된 장면은 승인 원본과 연결되며 같은 내용을 만들 때 브라우저 측정을 반복하지 않습니다.

PPT에는 글자/도형/표가 남고 HTML의 페이지 이동, 편집, 전체 보기와 인쇄 기능은 HTML에 남습니다.
PPTX를 요청했다면 최종 HTML과 PPT를 함께 전달합니다. 특정 색/폰트를 지정하지 않았다면 원본 관찰값을 사용하며
위 예시의 흑백 값을 임의로 모든 자료에 복사하지 않습니다.
