# PPTX·HTML·이미지 참고

## PPTX

스타일 참고는 `python "스킬폴더/scripts/presentation.py" reference --file "참고.pptx" --summary`로
최대 60장의 순서, 공통 색상·글꼴과 제한된 서식 표본만 짧게 읽습니다. 원본 내용이나 모든 개체를 대화에 넣지 않습니다.
개체별 상세 좌표나 내용이 실제로 필요한 경우에만 `--summary`를 빼고 다시 확인합니다.
요약 JSON은 전체를 그대로 읽습니다. `head -c` 등으로 바이트를 잘라 불완전한 JSON이나 깨진 한글을 만들지 않습니다.
필요한 장은 `--slides 1,4,7,9`처럼 최대 60개 지정하며 순서를 유지합니다. 60장을 넘는 원본은
필요 범위를 나누어 지정합니다. 본문 전체를 모델 입력에 넣지 않으며 구조 분석은 시각 확인이 아닙니다.

**구조 분석만으로 디자인 확인을 마치지 않습니다.** 현재 호스트에 있는 실제 정상 열람 또는 렌더링 도구를 확인하고 필요한 각 장을 이미지로 봅니다. 이미 열린 문서가 있으면 정확한 파일을 먼저 확인해 재사용합니다. PowerPoint의 정상 열기, 요청 장 이동 또는 다음 장 이동, 실제 화면 캡처를 수행하고 장 번호와 캡처 경로를 연결합니다. 모든 제공 이미지를 목록에 남기고 2~3장씩 검토합니다. 같은 버전의 이미 확인한 장은 다시 보내지 않습니다. 빈 화면, 같은 장 중복 캡처와 누락 장은 확인 범위에서 빼고 사유를 남깁니다. 사용자에게 열람 권한을 다시 묻는 절차를 추가하지 않으며 현재 호스트의 승인 규칙을 따릅니다.

`reference --mode screen --file "참고.pptx" --slides 1,2,3,4`는 보호 PPT 또는 정상 화면 참고용 **캡처 계획**입니다. 명령은 문서 내용을 읽거나 PowerPoint를 열거나 캡처하지 않으며 도구 가용성이나 권한을 보증하지 않습니다. 실제 캡처는 현재 호스트가 제공하는 도구로 수행합니다. 장을 생략하면 열린 문서에서 필요한 범위와 총 장수를 확인하라는 계획이며 첫 3장만으로 완료하지 않습니다. 결과의 `coverage`는 계획 또는 구조 분석 범위이며 `visuallyReviewedSlides:[]`는 아직 화면을 보지 않았다는 뜻입니다.

파일 구조를 읽지 못한 것이 보호 파일이라는 증거는 아닙니다. 보호 파일이나 구형 PPT는 정상 권한으로 열 수 있고 화면 캡처와 AI 처리가 허용된 경우에만 현재 화면 도구로 필요한 장을 확인합니다. 파일 Export를 화면 캡처라고 설명하지 않습니다. 실제 거절을 우회하거나 보안 설정을 바꾸지 않습니다. 도구가 없으면 사용자 캡처로 진행할 수 있으며 구조 분석만 했다면 시각 확인은 미완료라고 짧게 알립니다.

첨부는 기본 `referenceMode:style`로 관찰한 여러 장의 스타일을 합성해 새 내용에 맞게 재구성합니다. 원본과 똑같은 장표 복제를 목표로 삼거나 기본 디자인 선택을 다시 묻지 않습니다. [reference-style.md](reference-style.md)의 `referenceStyle`에 한글 서체 역할, 크기, 여백, 표와 차트, 도형과 강조, 색 조합 및 근거를 짧게 유지합니다.
기존 배치 유지 요청은 원본 `--template` 및 `referenceMode:preserve`로 지원되는 플레이스홀더를 채웁니다.
그대로 둘 그룹은 `templateSlides`의 `keepShapeIds`에 명시해 하위 개체와 위치, 서식을 보존합니다. 그룹 내부의 자동 교체는 지원하지 않습니다. 이 모드의 HTML에는 판독 가능한 고정 개체와 중첩 그룹, 표와 차트, 배경을 교체 내용과 함께 투영합니다. 초안 응답의 `templatePreview`는 제한된 요약이며 `unsupportedReasons`와 `approximationsReasons`로 미지원 요소와 근사 이유를 알립니다. HTML에 포함된 전체 coverage의 `unsupported`와 `approximations`에서 세부 확인 범위를 읽고 원본과 비교합니다. 개체 투영이 모두 끝났다는 결과를 실제 PowerPoint 화면과 완전히 같다는 뜻으로 설명하지 않습니다. 새 디자인으로 재구성하려는 요청이면 style 방식을 사용합니다.
복잡한 고정 개체·마스터·SmartArt는 완전한 재편집을 보장하지 않습니다. 원본은 수정하지 않습니다.
보호 PPT의 화면 캡처를 참고했을 때는 읽지 못한 원본을 `--template`로 지정하지 않고 허용된 캡처의 `referenceImages`, 관찰한 `referenceStyle`과 새 편집 개체를 사용합니다. PNG/JPEG/WebP 절대경로를 최대 60개 유지하며 2~3장씩 확인합니다. 정상 파일 구조와 해당 캡처를 함께 참고하는 style 작업은 둘 다 유지할 수 있습니다.

## HTML과 이미지

기존 HTML은 정적 구조·배치·폰트를 참고합니다. 직접 변환은 `htmlSource` 경로를 사용하되 현재 설치된
Chrome/Edge가 필요합니다. 사용자 코드·외부 주소·인증정보를 실행하거나 자동 수집하지 않습니다.
저장해 둔 대표 HTML 양식은 `--template`로 재사용할 수 있습니다.

이미지는 현재 호스트가 실제 지원하는 이미지 읽기 기능으로 전체 목록을 2~3장씩 봅니다. 화면의 글꼴 이름을
읽을 수 없으면 시각적 추정으로 구분합니다. 텍스트·수치·레이아웃은 새 편집 개체로 재구성합니다.
추측을 실제 읽은 사실로 바꾸지 말고 `referenceImages`에 참고 경로와 관찰한 테마를 함께 기록합니다.

## 관찰을 간단한 프로필로 정리

- 배치: 제목 위치, 본문 열 수, 바깥 여백, 카드·선·표의 형태
- 글자: 선언된 폰트/크기/굵기/색과 시각적 추정의 구분
- 내용: 결론 우선인지 순서 설명인지, 지표·근거·출처가 어디에 놓이는지
- 한국어: 제목 문장/명사형, 존댓말/보고체, 강조 정도, 반복되는 고정 표현

이 프로필을 현재 작업에서 재사용합니다. 참고 자료를 다른 메모리·프로필에 자동 저장하지 않습니다.

분석 응답의 `suggestedPresentationProfile`은 명시된 제목과 본문 크기, 확인된 설치 서체, 주석 크기와 정보 밀도에서 얻은 작은 제안입니다. 현재 작업의 `presentationProfile`을 아직 정하지 않았을 때만 관찰 근거와 함께 필요한 값을 반영합니다. 기존 job과 사용자가 정한 서체나 크기를 덮어쓰지 않으며, 이미지에서 확정한 값이나 원본 전체의 완전한 스타일 분석으로 설명하지 않습니다. 별도 질문, 모델 호출이나 저장 파일은 추가하지 않습니다.

`특징 / 근거 장·shapeId / 새 자료 적용 위치 / 추정 여부`를 짧게 연결합니다. 둥근 카드·테두리·선 굵기·
그림자·연결 방향까지 살피고, 제목/본문의 서체·굵기 차이는 `elements`의 font/size/bold/color로,
도형 차이는 shape/fill/border/borderWidth/group으로 반영합니다. 기본 색·글꼴 하나로 평준화하지 않습니다.
예를 들어 같은 색은 같은 의미에 사용하고, 병렬 관계를 이유 없이 화살표로 바꾸지 않습니다.

분석의 `declaredShapeStyles`는 장당 최대 12개, `declaredParagraphStyles`는 8개 고유 표본이며
shapeId로 원래 개체와 연결됩니다. widthEmu/12700은 pt, spcPts/100은 pt, spcPct/100000은 행간 배수입니다.
schemeClr·tint·alpha와 상속 서식은 최종 화면 색으로 해석된 것이 아닙니다. 지원하는 lineSpacing·align은
개체 명세에 반영하고 미지원 점선·문단 간격·복잡한 도형은 초안에 근사 범위를 알립니다.
이미지에서는 정확한 서체·마스터·차트 원본 값·숨은 내용·애니메이션을 복원했다고 말하지 않습니다.

최종 검토에서도 같은 프로필로 도형·글꼴 역할·색 의미·말투·정보 밀도를 비교합니다. 명시 요청이 참고
자료보다 우선하며 기존 HTML 확인 외의 새 질문·별도 모델 호출·분석 파일은 추가하지 않습니다.
반복 보고서는 지정한 최종본의 시각 규칙을 이어받고 숫자와 결론은 이번 원자료로 교체합니다.
최신판 여부가 결과를 바꿀 때만 확인합니다. 색만 남기고 여백, 제목 위치, 표의 밀도와 말투를
초기화하지 않으며, 새 디자인 요청이라면 사용자가 문제라고 한 외형을 정답처럼 유지하지 않습니다.
DRM·권한 때문에 읽을 수 없으면 현재 허용된 화면 읽기/캡처 도구가 있는지 확인합니다. 허용 도구가
없으면 사용자가 제공할 수 있는 허용된 캡처나 요약으로 진행하고, 파일을 우회 해독하거나 보안 설정을 바꾸지 않습니다.
