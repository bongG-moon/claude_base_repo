# 참고 디자인에서 발표자료 만들기

Huashu 원본의 참고 맥락 관찰과 대표 장 우선 제작 방식을 발표자료에 한정한 한국어 안내다. 원문 근거는 `upstream/references/modules/deck.md.txt`, `upstream/references/workflow.md.txt`, `upstream/references/design-context.md.txt`에 보존한다. 보존 문서의 미포함 기능이나 설치 경로를 작업 지시로 따라가지 않는다.

## 내용과 참고 자료

사용자가 준 기획서, 수치, 표, 그림과 기존 승인 사항을 먼저 읽는다. 목적과 청중, 원하는 파일 형식이 이미 있으면 다시 묻지 않는다. 원문에 없는 실적이나 절감액을 만들지 않는다. 실제 수치, 가정, 목표를 구분하고 서로 다른 단위를 같은 축에 섞지 않는다.

참고 HTML은 CSS와 실제 화면, PPTX는 장별 화면과 글꼴/도형 정보, 이미지는 직접 보이는 배열을 관찰한다. 참조 파일 자체의 스크립트는 실행하지 않는다. 제목의 위치, 여백, 열 비율, 글꼴 크기, 색상 비율, 표 선과 강조 방식을 적은 뒤 새 내용으로 작성한다. 참고 자료를 열거나 렌더할 도구가 없으면 그 범위를 알리고 볼 수 있는 근거만 사용한다.

## 방향과 대표 장

방향이 정해지지 않은 디자인 작업에는 서로 다른 세 방향을 제안한다. 원본은 각 방향의 대표 2장을 먼저 만들고 사용자가 고른 뒤 나머지를 제작하는 흐름이다. 기존 방향을 따르는 작업, 변환만 하는 작업, 사용자가 한 방향 또는 즉시 제작을 요청한 경우는 그 지시대로 진행한다. 사용자에게 없는 승인 단계나 별도 설치를 완료 조건으로 만들지 않는다.

각 장을 만들기 전 다음을 짧게 판단한다. 서론/근거/비교/결정 중 무슨 일을 하는 장인가, 청중이 어디서 보는가, 어떤 분위기가 내용에 맞는가, 표와 문구가 읽을 크기로 들어가는가, 이 내용에 맞는 시각 요소는 무엇인가. 페이지 역할을 입력 스키마로 요구하지 않는다.

5장 이상이면 구조가 다른 대표 2장으로 글꼴, 색상과 간격을 먼저 잡는다. 이후 같은 시각 규칙을 유지하면서 표, 비교, 흐름도, 데이터와 결론에 맞게 구성을 바꾼다. 원본 기준 1920×1080px에서 본문 24px, 작은 설명 16px 이상을 출발점으로 삼되 한국어 길이와 실제 표시를 확인한다. 긴 제목이나 12행 이상의 표는 필요한 공간을 먼저 확보한다.

## HTML 구조

기본은 각 장의 스타일을 독립적으로 유지하는 장별 HTML이다.

```text
발표자료/
  index.html
  slides/01.html
  slides/02.html
  slides/assets/승인된이미지.png
```

각 장은 완전한 HTML 문서에 고정 크기의 `section.slide` 하나를 두고 직접 저작한다. 공통 크기는 기본 1920×1080이며 다른 크기를 선택해도 모든 장에서 동일하게 맞춘다. 이미지가 필요하면 해당 HTML 폴더 안에 로컬 자원을 둔다. 파일 하나에 여러 장을 넣어도 되며, 내보낼 때 선택한 모든 장은 0보다 큰 크기로 표시되어 있어야 한다.

기본 발표 화면은 위아래로 넘겨 읽는 문서가 아니라 한 화면 한 장이다. 이전/다음 버튼, 좌우 키, 현재/전체 페이지 번호를 제공하고 전체 보기는 별도 버튼으로 연다. 인쇄에는 전체 장이 순서대로 들어가야 한다.

`scripts/build_index.py`는 [원본 deck_index.html](../upstream/assets/deck_index.html)을 바탕으로 사용자 작업 폴더에 새 `index.html`을 만든다. 원본 파일은 변경하지 않고, 생성본에 첫 장으로 시작하는 동작과 한국어 버튼을 적용한다.

```powershell
python -X utf8 -B "<SKILL>/scripts/build_index.py" --slide "발표자료/slides/01.html" --slide "발표자료/slides/02.html" --output "발표자료/index.html"
```

장 크기가 기본 1920×1080과 다르면 `--width 1280 --height 720`처럼 함께 지정한다. 그리드 전체 보기는 별도 썸네일 도구 없이 동작한다. 파일명 대신 표시할 제목은 `--title`로 정한다. 모음 화면은 iframe 안에 실제 장을 표시하므로 PPTX 입력으로 직접 넘기지 않는다. 내보낼 장별 HTML을 같은 순서대로 지정한다.

스크립트가 장을 숨기는 단일 파일에서는 숨겨진 장을 변환했다고 주장하지 않는다. 발표용 화면과 별도로 모든 장이 보이는 저작 원본을 유지하거나 장별 HTML을 사용한다. 원본 engine은 CSS로 그린 단순 사각형과 텍스트에 적합하다. 표의 각 셀과 흐름도 문구는 실제 HTML 텍스트로 작성하고, SVG 안의 문구는 PPTX에서 그림이 된다는 점을 고려한다.

## 완성 확인

HTML의 모든 장을 직접 보고 제목 잘림, 글자 겹침, 표 누락, 화살표의 시작과 도착을 확인한다. 필요한 경우 HTML부터 수정하고 다시 변환한다. 사용자가 첫 산출물을 평가하는 경우에는 수정하지 않는다. PPTX의 텍스트 누락 대조가 통과해도 화면이 같다는 의미는 아니므로 실제 PowerPoint 화면은 별도로 확인한다.
