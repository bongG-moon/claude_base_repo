# 데이터를 탐색하는 HTML 보고서

데이터 표를 작성할 때만 읽습니다. 기존 스타일과 글꼴 선택을 유지하며 표 동작 때문에 질문, 스킬 선택, 외부 검색을 추가하지 않습니다.

## 화면의 중심은 사용자가 확인할 데이터

- 첫 화면에 보고서 제목, 집계 기간과 범위, 핵심 결론을 짧게 둡니다. 실제 판단에 필요한 지표만 가로 요약 영역에 놓고 대형 표지나 장식으로 표를 밀어내지 않습니다.
- 핵심 수치와 상세 표는 같은 자료를 사용합니다. 집계 기간, 분모, 단위, 조회 건수와 원본 ID를 남겨 필터 뒤에도 무엇을 보는지 알 수 있게 합니다.
- 데이터가 넓으면 표가 구획의 전체 폭을 사용합니다. 좌우 칸을 억지로 만들지 않고 요약과 표의 역할을 분리합니다. 주제가 여러 개일 때만 목차나 탭을 사용합니다.
- 4px 단위 간격을 바탕으로 같은 역할은 같은 간격을 쓰고, 검색 도구와 표는 가깝게, 서로 다른 주제는 넉넉히 나눕니다. 색상을 바꾸는 것보다 정보의 크기, 순서, 밀도를 먼저 맞춥니다.

## 기본 동작

현재 제작기는 표에 다음을 자동 적용합니다. 직접 작성하는 HTML에도 같은 사용성을 적용합니다.

| 상황 | 동작 |
|---|---|
| 데이터가 있는 표 | 내부 가로와 세로 스크롤, 고정 열 제목, 키보드 정렬, CSV 다운로드 |
| 13행 이상 | 전체 셀 검색, 범주 필터, 초기화, 검색 결과 CSV와 전체 CSV 구분 |
| 26행 이상 | 기본 25행, 50행 또는 100행씩 페이지 이동. 총 건수와 현재 범위 표시 |
| 반복 값이 있는 열 | 2~30개의 짧은 고유 값이면 필터 후보로 제공. 긴 설명과 고유 ID에는 불필요한 목록을 만들지 않음 |
| 검색 결과 0건 | 명확한 빈 결과 안내. 원래 데이터 0건과 구분 |
| 스크립트 미실행 | 원자료 표는 그대로 읽을 수 있음. 동작하지 않는 버튼은 표시하지 않음 |

원자료가 있으면 숫자는 JSON 숫자로, ID와 문자열은 문자열로 전달합니다. 숫자는 수치로 정렬하고 동률은 원래 순서를 유지합니다. 긴 한글은 단어 단위로 읽히게 하며 내용을 잘라 감추지 않습니다. 표 자체의 가로 스크롤을 허용하고 페이지 전체가 옆으로 밀리지 않게 합니다.

CSV는 현재 페이지가 아닌 **필터에 맞는 전체 행** 또는 **보고서에 담긴 전체 행**입니다. 두 범위를 버튼 이름으로 구분합니다. 전체 CSV는 서버나 원본 파일 전체를 다시 조회하지 않습니다. 표가 표본이면 제목과 출처에 표본 범위와 전체 미포함 사실을 명시합니다. UTF-8 BOM과 인용부호 이스케이프를 적용하고 수식처럼 시작하는 문자열은 Excel에서 실행되지 않게 보호합니다. 원래 숫자 음수는 숫자로 유지합니다. `{{fact:id}}`만 들어간 셀은 화면에 지정된 반올림과 천 단위 구분을 표시하되 정렬과 CSV에는 계산된 원래 숫자를 사용합니다. `{{fact:id}}명`처럼 단위나 설명을 붙인 셀은 텍스트입니다.

인쇄에서는 현재 필터에 맞는 모든 행을 사용하며 인쇄 뒤 페이지 상태로 돌아갑니다. 한 표는 최대 5,000행과 64열입니다. 이보다 큰 자료를 임의로 자르지 말고 핵심 집계와 명시한 표본을 HTML에 담고 원본 또는 별도 데이터 파일을 함께 제공합니다. 직접 작성한 웹 앱은 기존 페이지 조회 API를 재사용하고 전체 자료를 DOM에 한 번에 쏟지 않습니다.

설명용 비교표만 있고 동작이 필요하지 않다는 요청이면 `table.interactive:false`로 정적 표를 유지합니다. 기본은 true이며 작은 표에는 검색과 페이지 도구가 나타나지 않습니다. 기능을 끄기 위해 별도 질문을 추가하지 않습니다.

## 같은 검토에서 확인할 것

실제 0건, 긴 한글, 큰 수, 검색 뒤 페이지 범위 초기화, 숫자 정렬, 필터 결과와 CSV 행 수를 확인합니다. 좁은 화면, 키보드 포커스, 스크롤 후 열 제목과 인쇄도 확인합니다. 검증을 위해 별도 모델이나 상시 후크를 실행하지 않습니다. 브라우저 확인을 못 하면 기능과 화면을 확인했다고 단정하지 않습니다.

## 데이터 분석 보고서일 때 선택적으로 적용

원본, 중간 계산, 최종 결과가 실제로 있는 분석 보고서는 이 세 범위를 구분하고 최종 결과부터 보여줍니다. 각 범위에 여러 표가 있을 때만 표 선택을 제공합니다. 불필요한 중간 표를 만들어 채우지 않습니다. 미리보기 행 수와 전체 건수가 다르면 각각 표시하고, 연결된 보고서의 로딩 실패나 자료 만료는 0건과 구분합니다.

현재 동봉 제작기는 보고서에 담긴 **전체 셀 검색**을 제공합니다. 별도 연결형 보고서를 직접 작성할 때는 넓은 표에 검색 대상 열 선택을 추가할 수 있으며, 전체 조회와 다운로드는 이미 제공된 API가 있을 때만 재사용합니다. 이 참고 원칙 때문에 오프라인 보고서에 서버, 네트워크 요청이나 추가 연결을 넣지 않습니다.

## 참고를 적용한 범위

2026-10-28에 확인한 `pt_ai_square/static/workspace.css`와 `app.js`의 내 기여도 화면은 넓은 작업 영역, 작은 요약, 표와 건수 및 페이지 이동을 가까이 배치합니다. `metadata_driven_v5/samples/realtime_production_report/realtime_production_report_example.html`은 생산, 부족, CAPA와 장비 구획마다 검색과 필터, 고정 머리글 및 CSV를 제공합니다. 데이터와 업무 코드는 복사하지 않고 표 탐색 계약과 정보 위계만 이 제작기에 구현했습니다. 해당 프로젝트의 모든 화면이나 업무 로직을 검증한 것은 아닙니다.

변동 쿼리 분석 보고서의 실제 렌더러 `metadata_driven_v5/langflow_components/data_analysis_flow_v2/25_execution_trace_artifact_publisher.py`의 `render_execution_report_html`과 데이터 탐색 구성도 소스로 확인했습니다. 원본/중간/최종 구분, 최종 결과 우선, 표 선택, 검색 대상 열 선택, 미리보기와 전체 건수 및 로딩 실패/만료 구분은 위의 선택적 작성 원칙으로 참고했습니다. 이 기능 전부가 동봉 제작기에 구현되었다는 뜻은 아닙니다.

[Huashu Design](https://github.com/alchaincyf/huashu-design/blob/master/SKILL.md)에서는 제공된 양식과 실제 자료에서 시각적 방향을 정하고 매번 같은 장식을 반복하지 않는 원칙을 참고했습니다. [Impeccable layout](https://github.com/pbakaus/impeccable/blob/main/skill/reference/layout.md), [harden](https://github.com/pbakaus/impeccable/blob/main/skill/reference/harden.md), [animate](https://github.com/pbakaus/impeccable/blob/main/skill/reference/animate.md)에서는 작업 목적에 맞춘 밀도, 빈 값과 긴 문장, 빠른 상태 피드백을 참고했습니다. 이 문서와 구현은 해당 목적에 맞춘 재작성입니다. 세 가지 시안 강제, 외관 기록 수집, 설치기와 검사 후크는 가져오지 않습니다.
