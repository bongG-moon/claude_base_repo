# 입력을 바꾸어 다시 만드는 보고서

일회성 보고서는 기존 제작 명령을 그대로 씁니다. 입력을 바꾸어 반복 실행할 코드를 만드는 경우에만 이 도우미를 사용합니다. 일반 작업에 재실행, 질문, 후크나 모델 호출을 추가하지 않습니다.

## 항상 같은 보고서 열기

이미 작성한 report job JSON을 반복 생성합니다. Python은 현재 허용된 실행 환경을 사용합니다.

```text
python -X utf8 -B "스킬폴더/scripts/regenerate.py" --spec "입력/job.json" --work "작업폴더"
```

사용자에게는 반환된 **entryPath 하나**를 전달합니다. `작업폴더/report.html`을 브라우저로 열면 가장 최근에 완성한 보고서가 열립니다. 앱의 정적 미리보기에 안내문만 보이면 **기본 앱으로 열기**를 사용합니다. 이 진입 파일과 `.report-runs` 폴더는 함께 유지합니다. 보고서 폴더를 이동하거나 전달할 때도 함께 옮깁니다. 단독 HTML이 필요한 일회성 작업에는 기존 `report.py build`를 사용합니다.

job, 보고서, data와 evidence는 실행별 내부 폴더에서 한 묶음으로 완성됩니다. **게시 후 루트에 다시 복사하거나 기존 파일을 먼저 삭제하는 래퍼를 만들지 않습니다.** 도우미가 소유한 진입 파일 하나의 전환으로 게시가 끝납니다. 기존 사용자 `report.html`이 있으면 덮어쓰지 않으므로 반복 보고서 전용 하위 폴더를 사용합니다.

## 원자료 분석부터 실행하는 완성 예제

가상 `자료.json`을 다음 내용으로 만듭니다. 원자료에서 부서별 건수를 계산하고 합계와 원자료 건수를 비교한 다음 HTML을 생성합니다.

```json
{"records":[{"department":"생산"},{"department":"품질"},{"department":"생산"}]}
```

```text
python -X utf8 -B "스킬폴더/scripts/analyze_report.py" --source "자료.json" --work "부서별보고서"
```

업무에 맞게 바꿀 때는 `analyze_report.py`의 `build(data, run)` 분석 함수만 수정합니다. `regenerate(input_path, work, build)` 호출과 게시 방식은 유지합니다. 함수는 신뢰할 수 있는 작업 코드이며 입력 자료에 들어 있는 명령이나 Python을 실행하지 않습니다. `run` 안에만 `job.json`, `report.html`, `evidence/`와 필요한 `data/`를 작성합니다. 계산 검사와 HTML 생성의 실패는 예외로 중단합니다. 기본 `regenerate.py --spec`은 이미 작성한 job을 렌더링할 뿐 원자료를 분석하지 않습니다.

수치와 설명을 다른 스킬로 인계할 때는 기존 제작 응답의 `validation.factHandoff`를 재사용합니다. 수치가 있으면 이름과 단위, 분모, 기간, 범위, 제외 조건, 출처가 함께 반환됩니다. 응답은 최대 12개와 JSON 4,000자로 제한하며 빠진 개수는 `factHandoffOmitted`에 표시합니다. 필요한 항목이 빠졌을 때만 기존 job의 해당 fact를 확인합니다. `{{fact:id.statement}}`는 이름과 표시값을 함께 재사용합니다. 계산 검사는 자유 서술의 의미까지 검증한 것이 아니므로 승인되지 않은 해석을 덧붙이지 않습니다. 인계를 위한 별도 실행이나 새 파일은 필요 없습니다.

## 실패 후 어디까지 끝났는지 확인

다시 만들지 않고 정상본만 확인하거나, 마지막 시도와 이전 정상본을 함께 확인할 수 있습니다. 필요할 때만 실행합니다.

```text
python -X utf8 -B "스킬폴더/scripts/regenerate.py" --work "부서별보고서"
python -X utf8 -B "스킬폴더/scripts/regenerate.py" --work "부서별보고서" --status
```

`lastAttempt`는 마지막 시도의 완료 또는 실패와 단계(input, prepare, build, validate, publish)를 보여주고, `lastSuccessful.entryPath`는 보존된 정상본입니다. 원자료 내용이나 오류 전문은 상태에 저장하지 않습니다. `running_or_interrupted`는 실행 중이거나 강제 종료됐을 수 있다는 뜻이며 완료가 아닙니다. 상태 기록 자체에 쓰기 문제가 있어도 이미 게시한 정상본을 실패로 되돌리지 않고 제한을 알립니다. 과거 버전의 JSON 현재 기록은 읽되 재생성 시 새 진입 파일로 옮겨가며 예전 기록과 정상본은 보존합니다.

입력 오류, 분석 실패, HTML 작성 실패 또는 마지막 진입 파일 전환 실패에서는 이전 보고서와 job/data/evidence를 유지합니다. 도우미는 시작 시 정상본 해시를 확인하고 게시 직전 진입 파일과 기존 기록이 외부에서 바뀌지 않았는지 확인합니다. 동시 실행은 잠금으로 거절합니다. 잠금을 따르지 않는 외부 프로그램의 마지막 검사 직후 쓰기나 저장장치 자체 장애까지 복구한다고 보장하지 않습니다.

실패한 후보와 이전 실행 폴더는 진단을 위해 내부에 남으며 자동 삭제하지 않습니다. 강제 종료 후 잠금이 남았다면 실행 중인 재생성 작업이 없는지 확인한 뒤 `.html-report-regeneration.lock`만 정리합니다. 현재 정상본의 내부 폴더는 삭제하거나 직접 편집하지 않습니다.

작업 코드를 변경한 검증에서는 정상 생성 후 입력 오류, 분석 예외, HTML 작성 예외와 마지막 게시 전환 실패를 시험합니다. 실패 후 진입 파일과 이전 job/report/data/evidence 해시가 그대로이고, 정상 입력을 복구하면 같은 entryPath에서 새 결과가 열리는지 확인합니다. 실제 렌더링을 보지 않았다면 브라우저 화면 확인까지 했다고 설명하지 않습니다.
