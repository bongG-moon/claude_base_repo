# 수집 범위와 결과 계약

## 구조 찾기

MD 자산은 명시한 `--root`, `--profile-root`, `--state-root` 안에서 탐색한다. 프로젝트의 CLAUDE.md·AGENTS.md, skills 하위 SKILL.md, memory·knowledge·learning 경로의 Markdown과 일반 MD를 구분한다. 설정 JSON은 이름만 기록한다. 관리형 기억·지식 JSON도 존재 위치만 기록하며 본문 형식은 미지원으로 표시한다. Company Agent 외의 일반 Markdown 기반 환경도 같은 방식으로 처리한다.

세션 확인은 기본 켜짐이다. 현재 사용자의 `CLAUDE_CONFIG_DIR`가 있으면 그 설정 위치의 `projects`, 없으면 `~/.claude/projects`를 확인한다. `CODEX_HOME`이 있으면 그 위치의 `sessions`·`archived_sessions`, 없으면 `~/.codex` 아래의 해당 위치를 확인한다. 이 두 환경변수는 저장 위치 선택에만 사용하며 설정 파일의 환경변수·인증값을 수집하지 않는다. 모든 PC 경로를 찾는 기능이 아니다.

- `--profile-root`를 하나라도 지정하면 다른 기본 프로필의 자동 발견을 생략한다.
- `--no-auto-sessions`는 자동 발견만 끄고 명시한 경로의 세션은 확인한다.
- `--no-sessions`는 세션 읽기·자동 발견·가져온 목록의 세션 포함을 모두 끈다.
- `--include-sessions`는 이전 명령과의 호환용이다. 기본 동작이므로 새 명령에 붙일 필요가 없다.
- `--catalog`만 지정하면 현재 PC를 탐색하지 않고 해당 목록들만 합친다.

junction·심볼릭 링크·reparse 경로는 따라가지 않는다. credentials·secret·token 계열 파일, .env, .git, node_modules, 가상환경·빌드·캐시는 제외한다. 세션의 cwd나 MD 링크를 읽었다고 그 위치를 탐색 대상으로 추가하지 않는다.

## 읽기 한도와 일부 확인 표시

세션은 앞부분만 잘라 분류하지 않고 JSONL을 한 줄씩 읽어 전체 기록을 확인한다. 메모리에 원문 세션 전체를 올리거나 모델에 통째로 보내지 않는다. 기본 한도는 다음과 같다.

| 구분 | 기본 한도 |
| --- | --- |
| MD 등 자산 | 후보 파일 1,500개, 디렉터리 항목 10,000개, 깊이 8 |
| 자산 읽기 | 총 16MiB, MD·개별 JSON 512KiB |
| 세션 읽기 | 파일 20,000개, 총 2GiB, 한 줄 1MiB |
| 세션 집계 | 중복을 포함한 이벤트 처리 200,000개, 경로 탐색 항목 200,000개. 보관하는 이벤트 해시 수도 이 한도 이내 |
| 업무 단계 요약 | 세션당 최대 96개 요청 묶음, 요청당 8단계, 대표 흐름당 32단계. 이후 기록의 세션 집계는 계속하며 단계 한도는 별도 표시 |
| 실행 상세 | 세션당 최대 400개 호출의 제한된 메타데이터. 초과·손상·끊긴 기록은 일부 확인으로 표시하며 일반 집계는 기존 한도 안에서 계속 |

자산 읽기와 세션 읽기의 용량 예산은 별도다. 세션 한도는 `--max-session-files`, `--max-session-bytes`, `--max-session-line-bytes`, `--max-session-events`, `--max-session-entries`로 조정할 수 있다. 바이트 옵션의 값은 바이트 단위 정수다. 큰 한도는 실행 시간·메모리 사용을 늘릴 수 있으므로 누락 보고를 보고 필요한 범위만 늘린다. 상한 초과·손상·권한 거절·형식 미지원은 누락/일부 확인으로 표시하며, 이 경우 “전체 세션을 빠짐없이 집계했다”고 설명하지 않는다.

## 세션 의미

- Claude: user message의 요청과 assistant의 tool_use를 관찰한다. tool_result는 호출 ID로 연결하여 응답 여부·명시적 오류만 판단한다. 도구 응답을 새로운 사용자 요청으로 세지 않는다. thinking·image·assistant 본문은 제외한다.
- Claude의 첨부 안내·화면 모드·요청 사본 등 알려진 관리 기록은 본문을 읽지 않고 건너뛴다. 그 사이 사용자 요청과 호출의 연결은 유지한다. API 요청 사본을 다시 대화로 파싱하지 않으며, 알 수 없는 새 기록 형식은 연결을 끊고 일부 확인으로 표시한다.
- Codex: response_item의 user message와 function_call/custom_tool_call을 관찰하고 대응하는 output을 call_id로 연결한다. event_msg의 user_message는 중복될 수 있어 요청으로 다시 세지 않는다. 결과 본문은 내보내지 않으며 구조화된 오류/종료 코드만 상태에 반영한다.
- 도구 입력에서는 허용한 파일 이름·스킬 이름·작업자 유형과 아래 기준의 짧은 목적 설명만 제한적으로 남긴다. 쉘 명령은 Python/검증/일반 명령의 동작 종류로 분류하고 명령어나 코드를 내보내지 않는다. 절대경로·URL·인증값·임의 인수·도구 결과 본문은 결과에 넣지 않는다. 내용이 지원 형식 밖이면 아는 동작/상태만 표시한다.
- 업무 후보는 짧은 질문에서 로컬 키워드로 분류할 수 있으나 질문 원문은 기본 출력하지 않는다. `--include-intents`도 160자 발췌 최대 3개뿐이며 자동 가림 처리가 완벽한 익명화를 보장하지 않는다. 공유 전 사용자가 결과를 확인해야 한다.
- 인사·감사만 있거나 빈 기록·알려진 문맥 안내뿐인 기록은 집계에서 제외한다. 단순히 짧거나 미분류라는 이유로 버리지 않는다. 짧은 실제 요청, 실패한 작업, 의미가 불명확한 기록은 보존한다. 확인한 세션 수·남긴 수·제외 사유를 함께 보고해 제외와 미확인을 구분한다.
- 동일 자산 내용과 세션 식별자/이벤트 근거가 겹치는 경우 중복을 합치고 출처는 보존한다. 세션 복사본의 식별자가 바뀌거나 기록이 변환된 경우는 동일 실행을 입증할 수 없으므로 별도 기록이 될 수 있다.
- 세션 cwd는 이미 지정된 프로젝트 루트에 속할 때만 별칭으로 연결한다. 외부 cwd를 읽거나 폴더를 따라가지 않는다. 연결하지 못한 세션은 프로젝트 미연결로 표시한다. 하위 작업자(sidechain)는 중복 방지를 위해 제외하며 한 파일에 여러 세션 ID가 섞이면 파일 전체를 집계에서 제외한다.
- Claude isMeta와 알려진 AGENTS/환경 문맥 전용 user 메시지는 제외한다. 그래도 모든 user-role 이벤트가 사람이 직접 입력한 질문이라는 보장은 없으므로 질문 이벤트 수를 실제 요청 건수나 업무량으로 사용하지 않는다.

## 업무별 진행 흐름

보고서 첫 부분은 전체 세션의 큰 업무 유형이다. 이어지는 자산 중심 상세 FLOW에서 사용자 질문에 명시된 **처리 대상과 동작**을 로컬 규칙으로 정규화한다. 질문 문장 전체 대신 짧은 대상 이름, 읽기·중복 제거·집계·매칭·작성 등의 동작, 익명 이벤트 식별자와 요청 순서만 보관한다. 대상 이름에도 업무 정보가 포함될 수 있으므로 공유 전 검토한다. 별도 LLM 분석이나 반복 모델 호출은 없다.

- 세션을 읽는 시점에 순서를 기록한다. 기존의 정렬된 이벤트 해시에서 순서를 추정하지 않는다. 오래된 내보내기에 단계가 없으면 `단계 정보 없음`으로 두며 도구 목록으로 절차를 만들지 않는다.
- 교육 신청 집계와 재고 분석처럼 구체적 대상이 다르면 같은 세션·같은 도구라도 업무를 나눈다. `별개로`, `다른 업무로` 같은 명시적 전환은 한 질문 안에서도 나눈다. `그다음`, `위 결과` 같은 후속 요청은 대상과 동작을 비교해 앞선 업무에 연결한다. 이는 규칙 기반 후보이며 주제 전환이나 생략된 맥락을 모두 이해하는 의미 분석은 아니다.
- 같은 대상·시작 동작의 관찰 묶음을 합쳐 반복 횟수와 출처를 남긴다. 같은 이벤트/세션 복사본·같은 내보내기를 다시 합쳐도 횟수를 늘리지 않는다. 다른 절차가 섞이면 단계가 가장 많이 확인된 **실제 관찰 묶음 하나**를 대표로 보여주며, 최신·최빈 절차라고 주장하지 않는다. 절차를 합쳐 존재하지 않았던 순서를 만들지 않고 `진행 방식 비교`에서 나머지 순서를 볼 수 있게 한다.
- 상세 FLOW의 선정 기준은 아래의 자산 저장 근거다. 여러 단계·반복 여부는 흐름을 설명하는 보조 정보이며, 단계가 많다는 이유만으로 상세 대상으로 넣지 않는다. 날씨·농담처럼 업무로 보이지 않는 요청과 짧은 승인·불명확한 질문은 주요 업무의 제외 후보로 표시한다. 세션 자체는 보존하며 인사·감사·빈 기록 제외 통계와 구분한다.
- 실행하지 말라는 설명·가정 요청, `전송하지 마` 같은 부정 지시는 실행 단계로 만들지 않는다. 오류·실패를 언급한 업무는 실패 언급 표시와 함께 유지한다. 읽기 한도나 단계 한도에 걸리면 `일부 단계만 확인`으로 표시한다.
- 화살표는 요청 순서다. **실제 도구 동작**은 해당 요청 이후 관찰된 호출을 순서대로 표시한다. 이는 요청 구간 연결이며 각 요청 단계의 실행 의존성이나 코드의 업무 의미까지 입증하지 않는다. 한 질문에 여러 업무가 섞이면 연결 모호성을 표시한다. 다음 사용자 요청 뒤 도착한 결과도 원래 호출 ID로 연결하며, ID가 없거나 응답이 끊기면 결과 미확인으로 남긴다.
- 도구 상태는 `returned`(응답 수신), `error`(명시적 오류), `unconfirmed`(결과 미확인)다. 응답 수신은 업무 성공이 아니다. Agent 호출은 하위 작업자를 요청한 흔적이며, 별도 sidechain 기록을 제외하므로 그 내부 작업까지 확인한 것으로 설명하지 않는다.

### 각 동작이 하려던 일

도구 이름만 나열하지 않고, 호출 설명에 적힌 목적·지원하는 인라인 코드의 처리 구조·안전하게 확인한 대상 정보를 짧은 문장으로 보여준다. 예를 들어 표 읽기 → 중복 제거 → 그룹 집계가 코드에 있으면 그 처리를 설명하되, 실제 실행됐거나 결과가 맞다고 하지 않는다. 설명의 출처를 `호출에 적힌 목적`, `코드 구조에서 확인한 처리`, `호출 대상·인자에서 확인한 용도`로 표시한다. 설명이 없는 옛 기록이나 지원하지 않는 코드에서는 목적 미확인으로 남긴다.

이 처리는 보고서 생성 시 로컬 규칙으로만 수행한다. 명령·코드·쿼리의 원문과 리터럴 데이터는 저장하지 않고, 외부 스크립트 파일을 따라 읽거나 실행하지 않는다. 목적 설명에도 업무 정보가 포함될 수 있으므로 공유 전 검토한다. 다른 업무와 섞인 요청을 하나의 호출 목적이라고 추정하지 않으며 생각 과정·도구 결과 본문을 목적 근거로 사용하지 않는다.

HTML은 Noto Sans KR을 내장하고 각 업무의 요청 흐름·실제 도구 동작·반복 관찰·출처·미확인 범위를 보여준다. 긴 표는 내부 스크롤·고정 머리글로 읽는다. 같은 내용의 `업무자산.md`를 함께 생성하고 HTML에도 Markdown 다운로드를 내장한다. HTML만 옮겨도 같은 문서를 받을 수 있다.

보고서 디자인은 AX Workspace 사용 안내의 읽기 화면을 따른다. 배경 `#f6f6f7`, 본문 `#292d42`, 보조 설명 `#626a80`, 링크·포인트 `#6257be`, 테두리 `#e0e2e7`을 고정하고 흰색 카드 안에 제목과 내용을 함께 배치한다. 큰 숫자 지표 대신 읽는 순서 세 칸과 작은 범위 요약을 두고 목차는 처음부터 펼친다. 좁은 화면에서는 안내·흐름 카드를 세로로 배치하며 긴 표만 내부 스크롤한다. 이는 로컬 렌더러의 기본 스타일이며 실행할 때 참고 앱·외부 글꼴·별도 디자인 도구를 호출하지 않는다.

## 전체 분류와 자산 중심 상세 FLOW

전체 세션의 업무 유형 분류는 유지한다. 상세 FLOW에는 스킬·기억·지식의 생성·수정 호출이 있고 응답이 관찰된 요청 묶음만 넣는다. 같은 이름의 일반 작업이 다른 저장 업무와 합쳐져 상세 목록에 들어가지 않도록 선정 근거별로 나눈다. 일반 세션은 유형·출처만 보고서에 표시하며, 재집계용 catalog에는 한도 내의 제한된 실행 메타데이터를 보존한다.

저장 근거는 Write/Edit의 SKILL.md·스킬 지원 파일·기억/지식 Markdown 경로, 이름이 명확한 저장 MCP 호출, 지원하는 Company Agent 기억/지식 upsert·스킬 update 명령에서 얻는다. 명령·코드·결과 본문은 내보내지 않는다. 스킬 불러오기·기억 조회·저장 요청 문구·문서 단어 일치는 저장 근거가 아니다. 일반 `asset create --spec`만 있는 기록은 스킬/MCP 종류를 알 수 없어 선정하지 않는다. 이를 알아내려고 외부 spec 파일을 추가 탐색하지 않는다.

실패·응답 미확인·여러 요청이 공유하는 저장 호출은 보류한다. “이 작업을 스킬로 만들어줘”처럼 같은 업무를 명시한 후속 요청만 앞선 FLOW에 연결한다. 현재 남은 정의 파일은 따로 보여주고, 저장 이벤트와 제목이 같다는 이유로 정확한 파일 연결·성공을 주장하지 않는다. 정의만 있고 세션이 없으면 FLOW를 만들어 채우지 않는다.

`work_analysis.selection_policy`는 `saved_assets`다. 각 실행 이벤트의 선택 필드 `asset_change`는 `kind`(skill/memory/knowledge), `operation`(create_or_update), `basis`(target_path/persistence_tool/managed_command), 선택적 안전한 `target` 이름으로 구성한다. 재집계에서 다시 검증하고 충돌은 `asset_change_conflict`로 제외한다. 이전 v1 catalog도 읽지만 저장 근거가 없으면 큰 분류에만 포함한다. 원본 세션을 다시 수집하면 지원되는 근거를 추출할 수 있다.

## 비정형 업무와 도메인 자산으로 활용하기

업무별 식별자와 관찰된 자료·요청 결과, 처리 순서, 실제 도구 실행, 다른 진행 방식, 출처와 미확인 범위를 Markdown으로 보존한다. 문서 제목·짧은 설명에서 연결한 업무 지식은 **관련 지식 후보**다. 본문 전체를 해석하거나 업무 기준의 타당성을 검증한 것처럼 쓰지 않는다. 담당자가 절차와 기준·예외를 검토한 뒤 재사용 스킬이나 팀 지식을 작성할 때 활용한다.

여러 사람의 Markdown은 사람이 읽고 편집하는 자료이며, `catalog.json`은 중복 근거와 출처를 보존해 합산하는 자료다. 편집한 Markdown을 기계가 자동 재집계했다고 주장하지 않는다. 현재 버전은 원본 업무 시스템의 규칙·실행 코드를 완전히 복원하는 변환기가 아니다. 로컬 기록에 없는 암묵지나 누락된 행동은 미확인으로 남는다.

## catalog.json v1

`schema_version: 1`, `kind: work-context-catalog`. `roots`는 별칭·범위·환경 후보, `assets`는 내용 해시 ID·종류·제목/짧은 설명·출처·분류 후보와 `evidence: definition`이다. `sessions`는 해시 ID·요청/호출 이벤트 해시·출처·분류와 제한된 실행 메타데이터다. 원문 인수·결과·절대경로·전체 대화는 없다. `coverage`에 한도·누락·제외 사유를, `summary`에 정의 수·세션 수·호출 수를 기록한다.

`--catalog` 재집계는 이 스키마의 승인된 파일만 받는다. 자산과 내보내기에 담긴 세션을 기본으로 함께 합치며, `--no-sessions`로 세션을 제외할 수 있다. 발췌는 별도로 `--include-intents`가 있어야 가져온다. 목록만 지정한 실행은 현재 PC의 기록을 추가하지 않는다. 입력 파일은 크기·구조·개수 한도로 검사하고 HTML에 문구를 그대로 실행하지 않는다. 출처에는 import-01 같은 묶음 별칭을 붙인다. 이 방식은 자동 전사 수집·사용자 식별·서버 업로드가 아니라 **검토 후 내보낸 업무 자산 목록의 로컬 합산**이다.

v1의 선택 필드 `sessions[].work_requests`에는 익명 ID·요청 순서·정규화 대상·동작만 들어가며 `workflow_partial`은 일부 요약 여부다. `work_analysis`는 이 근거로 다시 계산하는 주요 흐름·보류 목록·제외 후보이며 가져온 요약의 완료 주장을 신뢰하지 않는다. 같은 ID의 서로 다른 단계가 들어오면 해당 입력을 제외한다. 기존 v1 파일은 계속 읽지만 없는 단계는 복구하거나 추정하지 않는다.

선택 필드 `sessions[].execution_events`는 ID·요청 ID 목록·호출 순서·도구·정규화 동작·제한된 대상·상태·응답 관찰 여부를 갖는다. `execution_partial`은 일부 확인이다. 여러 요청 ID에 걸친 호출은 연결 모호성을 표시한다. 재집계에서 참조 ID·상태·허용된 문자열·개수·상충 근거를 다시 검사하며 들어온 HTML/요약을 신뢰하지 않는다. 예전 목록에 이 필드가 없으면 실행 상세 미확인으로 표시한다.

각 호출의 선택 필드 `purpose`에는 최대 240자의 `text`와 `basis`를 둔다. `basis`는 `invocation_description`, `code_structure`, `target_metadata` 중 하나다. 필드가 없는 기존 v1 목록도 계속 읽는다. 같은 호출의 서로 다른 목적 설명은 합성하지 않고 `purpose_conflict: true`로 미확인 처리한다. 이 필드는 호출의 목적·처리 구조에 관한 제한된 설명이며 실행 결과나 검증된 업무 규칙이 아니다.

재집계 입력의 기본 총량은 256MiB이며 `--max-catalog-bytes`로 조정할 수 있다. 합친 자산·세션·이벤트에도 위 개수 한도를 적용한다. 한도를 늘려 만든 큰 내보내기를 합칠 때는 동일하게 늘려야 할 수 있으며, 형식이나 한도를 벗어난 입력은 일부만 섞지 않고 그 입력 전체를 제외했다고 알린다.

MD 제목이나 질문에 개인정보·업무 기밀이 있을 수 있다. 공통 인증키·메일·URL·사용자 경로 등을 가리지만 완전한 DLP는 아니다. 사용자 이름이나 인사평가용 추론을 자동 추가하지 않는다. 범위를 좁히거나 발췌 옵션을 끄고 공유 전에 반드시 확인한다.
