# 웹 화면 만들기·다듬기

요청한 화면과 기존 저장소의 실행 방법·컴포넌트·글꼴·디자인 토큰을 먼저 확인합니다.
현재 작업에 필요한 파일만 읽으며 새 프레임워크·서버·라이브러리를 먼저 설치하지 않습니다.
보고서 생성 명령을 웹앱 코드 수정에 사용하지 않습니다. 실제 프로젝트의 파일을 수정합니다.

## 짧은 작업 흐름

1. 고칠 화면·불편·완료 조건을 요청에서 파악합니다. 이미 정한 조건은 재질문하지 않습니다.
2. 기존 디자인 시스템과 정상 동작을 유지합니다. 부분 수정은 해당 컴포넌트부터 고칩니다.
   새 화면은 가장 가까운 정상 화면을 기준으로 한 가지 일관된 구성을 정합니다.
3. 글꼴이 기존 프로젝트·사용자 양식에 정해져 있으면 유지합니다. 새로 정할 때만
   `Noto Sans KR(긴 본문) / Pretendard(대시보드·버튼) / 나눔스퀘어 네오(제목·안내) /
   디자인에 맞게 알아서 선택 / 직접 이름 입력`을 한 번에 제시합니다.
   “알아서/질문 없이”면 목적에 맞게 선택합니다. 글꼴 선택만으로 CDN·설치를 추가하지 않습니다.
   기존 로컬 자산·로드 방식을 재사용하고, 없으면 대체 글꼴과 적용 한계를 알립니다.
4. 아래 기준으로 구현하고 변경에 필요한 기존 빌드와 관련 테스트를 실행합니다. 가능한 브라우저에서
   실제 화면과 주요 동작을 확인합니다. 부분 수정은 변경과 영향 범위를 확인하며 통과한 무관한 검사를 반복하지 않습니다. 검사 때문에 상시 후크나 추가 모델 호출을 만들지 않습니다.
5. 바뀐 동작·확인 범위·남은 제약을 짧게 전달합니다. 게시·배포·인증 변경은 요청 범위에 따릅니다.

## 초안부터 적용할 기준

- 카드 높이는 내용에 맞춥니다. 제목·아이콘·버튼의 크기 비율을 맞추고 과한 빈 공간을 줄입니다.
- 기존 메인 화면의 버튼·색·간격을 하위 화면·모달에도 유지합니다. 의미 없는 강제 줄바꿈을 넣지 않습니다.
- 같은 의미에 같은 SVG 아이콘과 선 굵기를 사용합니다. 아이콘만 있는 버튼에는 접근 가능한 이름을 둡니다.
- 설명은 필요한 행동부터 짧은 한국어로 씁니다. 세부 설명은 접거나 보조 영역에 둡니다.
- 좁은 화면에서는 열을 자연스럽게 쌓습니다. 표만 내부 스크롤하고 페이지 전체 가로 넘침은 막습니다. ID/날짜는 최소 폭과 의미 단위를 유지하고 긴 설명은 줄바꿈합니다.
- 일반 본문 대비 4.5:1, 보이는 키보드 포커스, 입력 라벨, 읽기 순서를 확인합니다.
  클릭·터치 영역은 44px을 목표로 하되 기존 조밀한 UI는 실제 사용성과 함께 판단합니다.
- 애니메이션은 변화·상태를 이해시키는 데 사용합니다. 반복 장식·레이아웃 흔들림을 피하고 reduced-motion을 지원합니다.
- 그래프의 기간·단위·집계 기준을 보존합니다. 고정 전체 KPI와 필터 결과 KPI의 범위를 표시합니다. 로딩·빈 결과·실패·완료 상태를 구분합니다.
- 요청 전후와 넓은/좁은 화면을 비교합니다. 직접 확인하지 못한 화면을 검증 완료로 보고하지 않습니다.
