# 필요한 자료와 수식만 XLSX로 받기

사용자가 엑셀 사본, 시트 분할 또는 필요한 데이터와 수식만 남긴 파일을 요청할 때 사용합니다.
이미 명확한 결과 범위는 다시 묻지 않습니다. 기존 분석에 아래 옵션을 붙여 한 번만 읽습니다.

```text
python -X utf8 "<스킬 폴더>/scripts/excel_pipeline.py" "<입력.xlsx>" --output "<새 결과 폴더>" --xlsx-copy --copy-target "최종현황!A1:H18"
```

- `--copy-target`은 표 ID 또는 `시트!A1:H18`이며 여러 번 지정할 수 있습니다. XLSX 사본에 남길 결과와
  선행 셀을 선택합니다. Python 프로젝트의 범위는 바꾸지 않습니다. 이 옵션만으로 사본 생성도 켜집니다.
- 기존 `--target`은 Python 프로젝트까지 축소합니다. `--xlsx-copy`와 같이 쓰면 그 결과 범위를
  사본에도 사용합니다. `--copy-target`을 따로 주면 사본 범위는 그 값을 우선합니다.
- 범위 없이 `--xlsx-copy`만 쓰면 값과 수식이 있는 셀을 보존합니다. 빈 서식, 그림, 연결과 매크로를
  제외하지만 업무 데이터까지 알아서 불필요하다고 판단해 삭제하지 않습니다. 필요한 결과를 알면 범위를 지정합니다.

새 파일은 `필요자료.xlsx`입니다. 셀을 위로 당기거나 열을 재배열하지 않아 시트 간 수식 참조를 유지합니다.
필요한 입력 열의 기존 헤더도 남깁니다. 관련 없는 시트와 값, 빈 서식은 선택 사본에 넣지 않습니다.
사본은 원래 디자인의 복제품이 아니라 자료와 수식 중심의 단순 표입니다. 숫자 형식과 날짜, 누적 시간,
앞자리 0과 대소문자를 보존합니다. 기존 파일을 덮어쓰지 않고 원본을 저장하거나 변경하지 않습니다.

## 오류값과 수식 원문은 다릅니다

- `#REF!`는 유효하지 않은 참조입니다. 수식에 `'시트'!#REF!`가 남아 있으면 주소가 손실됐음을 뜻하며,
  그 열이나 원래 계산식을 자동 복원하지 않습니다. 외부 파일이 없다는 이유 하나로 단정하지 않습니다.
- `[다른파일.xlsx]시트!A1`은 외부 파일 참조입니다. 사본에서 그대로 보존하고 미해결로 표시합니다.
  파일을 찾거나 갱신하지 않습니다. 외부 파일의 내용이 없으면 그 부분까지 완결된 사본은 아닙니다.
- `#VALUE!`는 자료형이나 함수 인수 등 여러 원인이 있어 해당 수식과 입력을 함께 봅니다.
- 오류값만 읽었다면 수식을 읽었다고 말하지 않습니다. `source_cells.formula` 또는 Formula2/Formula로
  확보한 원문이 있는지 확인합니다. 기존 오류값과 원문은 0이나 추정값으로 바꾸지 않습니다.

셀 값과 수식 원문은 보존하지만 저장된 수식 결과 캐시는 새 파일에 옮기거나 임의 재계산하지 않습니다.
새 사본은 수동 계산 상태입니다. 사용자가 Excel에서 내용을 확인한 후 계산합니다. 별도로 재계산 시험을
요청한 경우 새 시험 사본에서만 실행하고, 결과를 검증한 범위를 구분합니다.

정적으로 입력 범위를 확정할 수 없는 INDIRECT/OFFSET, 사용자 함수, 구조화/동적 참조는 선택 사본 생성을
멈추고 원인을 알려줍니다. 숨김 행이나 피벗 등의 상태에 의존하는 SUBTOTAL/AGGREGATE/GETPIVOTDATA/CUBE
함수도 해당 상태까지 옮기지 않으므로 선택 사본을 만들지 않습니다. 수식에 필요한 셀을 추정해 빼거나
부분 사본을 완전한 결과로 보고하지 않습니다. 계산 엔진이 지원하지 않아도 참조 범위가 명확한 표준 함수는
수식 원문과 선행 셀을 보존할 수 있습니다.

## Excel 경유 읽기에도 같은 원칙 적용

일반 파일은 기존 직접 읽기를 유지합니다. 보호 파일은 Excel이 허용한 읽기 결과로 새 파일을 작성하며,
원본의 보안 래퍼 추출, 복호화, 접근 권한 변경이나 보호 기능 해제를 하지 않습니다. 내보내기 거절을
다른 경로로 회피하지 않습니다. 실제 사내 보안 제품의 읽기/쓰기 허용 여부는 해당 환경에서 확인합니다.

전달할 때 `필요자료.xlsx` 링크, 보존한 셀/수식 수, 미해결 참조 여부만 설명합니다.
내부 `_details/xlsx_copy.json`과 셀별 원자료 전체를 모델에 다시 넣지 않습니다.
