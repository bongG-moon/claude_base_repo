# 분석 범위와 제한

## 처리하는 것

- 일반 `.xlsx/.xlsm`의 시트·셀·병합 구조와 Excel Table 범위.
- 한 시트의 좌우·상하 표 후보. 정식 Table 범위가 없으면 빈 행·열 기준의 추정이다.
- 1~3단 병합 헤더 자동 탐지. 애매하면 `header_ambiguous`로 표시하고 원본 셀도 보존한다.
- 수식 문자열·저장 계산값·재계산값·참조 관계를 분리해 기록.
- 표별 입력/계산 단계, 열별 함수·대표 수식, 표 간 참조를 `pipeline_plan.json`에 정리.
- 사칙연산·거듭제곱·비교·문자열 연결·백분율, 유한 A1 범위, 직접 지정된 이름 범위.
- SUM, AVERAGE, MIN, MAX, COUNT, COUNTA, IF, IFERROR, ROUND,
  SUMIF/SUMIFS, COUNTIF/COUNTIFS, 정확 일치 VLOOKUP, AND, OR의 제한된 계산.
- `.xlsm`의 주 VBA 프로젝트에서 원문을 정적으로 추출하고 프로시저·수식·재계산 후보를 함께 기록.

## 자동 성공으로 취급하지 않는 것

- 빈 줄 없는 두 표, 동일 표 내부의 공백, 헤더 없는 문자열 표, 복잡한 병합·서식의 의미.
- 외부 통합문서, 구조화 참조, 3차원 참조, 배열·동적 배열, VBA 자동 실행/번역, Power Query, 피벗 재계산.
- INDIRECT/OFFSET 등 미지원 함수, 근사 일치 조회, 이름의 동적 수식, 순환 참조.
- 의도적으로 숨긴 시트도 분석 대상으로 포함하며 숨김 상태를 기록한다. 이미지·차트는 해석하지 않는다.
- 저장 캐시는 오래됐을 수 있다. 캐시와 일치하는 것은 네이티브 Excel 전체 호환 증명이 아니다.
- 원본 오류 셀은 보존하고, 계산 실패는 null과 원인 목록으로 분리한다. IFERROR도 미지원 기능을 숨기지 않는다.

원본 수식의 지원 범위 밖이면 따로 알려야 한다. 0으로 바꾸거나 이미지/OCR·다른 파일로 우회하지 않는다.
일반 OOXML 직접 읽기에서는 Excel을 실행하지 않는다. xlwings 경로는 Excel을 읽기 전용으로
열며 VBA 실행·재계산 대조와 다르다. 세부 범위는 [excel-reader.md](excel-reader.md)를 따른다.

VBA 업무 로직을 Python으로 옮기는 요청은 별도 [vba-migration.md](vba-migration.md) 절차를 따른다.
내장 VBA 추출·원문 색인과 AI의 업무별 이전·검증 예제를 제공한다. 임의 VBA를 완전 자동 번역하는 컴파일러는 아니다.

## 성능과 보안

평상시 후크는 없다. 스킬 코드는 LLM/API를 호출하지 않는다. 일반 읽기는 Python만,
xlwings 읽기는 Excel도 실행하며 Excel 프로세스의 외부 통신까지 차단하는 것은 아니다.
원본과 결과 비교·병합 탐지 등은 이 요청 안에서만 수행한다. 전체 JSON을 모델에 넣지 않는다.
기본 시험판 한도는 압축 파일 64 MiB, 압축 해제 총합 128 MiB, 실제 XML 셀 250,000개,
시트 사각 범위 1,000,000칸, 512열·100,000행, 500개 표 후보다.
병합 범위는 파일 전체에서 누적 250,000칸까지이며, Excel을 읽기 전에 검사한다.
정식 Excel Table도 파일 전체에서 누적 1,000,000칸·500개까지이며 열기 전에 검사한다.
수식 평가에도 범위·깊이·연산 수 한도가 있다. 한도를 넘기면 일부를 몰래 잘라 성공하지 않는다.
VBA part는 16 MiB, 원문은 모듈당 2 MiB·전체 8 MiB·64개까지다. 추출 작업자는 기본 20초 안에 종료한다.
실행 코드는 해석하지 않으며 컴파일된 p-code와 원문 불일치, 모든 악성 동작을 판정하는 검사는 아니다.
전체 분석에서는 의존 셀 계산 후 연산 한도 초과 항목만 한 번 재평가한다. 한도 자체는 늘리지 않는다.
기본 소수 사칙연산은 입력의 십진 표현을 이용해 반올림 경계의 이진 오차를 줄인다.
이는 Excel/VBA의 부동소수점 모델 전체를 복제한 것은 아니다.

원본은 읽기만 한다. 코드가 외부 파일·매크로·데이터 연결 갱신·웹 요청을 실행하지 않는다.
Excel 경로의 Office 시작 동작·보호 파일 내부 연결까지 격리한 것은 아니다.
XML entity/DTD는 거절한다. 암호화·DRM 후보는 회사가 허용한 Excel 접근만 사용하며
권한 변경·보호 해제는 하지 않는다. 실제 DRM 동작은 운영환경의 추가 검증이 필요하다.
결과 폴더는 새로 만들며 기존 폴더를 덮어쓰지 않는다. 생성한 JSON도 원본과 같은 보안 수준으로 취급한다.

## 구현 참고와 라이선스

외부 스킬 코드를 복사·설치하지 않고 독립 구현했다. 다음 공개 프로젝트의 목적과 한계를 비교했다.

- https://github.com/memtomem/agent-skills-public/tree/main/skills/xlsx-parser — 표 경계와 원본 범위 추적
- https://github.com/Harryoung/efka/blob/main/skills/excel-parser/SKILL.md — 구조 먼저, 데이터는 코드 처리
- https://github.com/RexBytes/xldetect — 병합·헤더·표 경계의 모호성
- https://github.com/vinci1it2000/formulas — 수식 계산과 의미 기반 전처리는 별도라는 구분

일반 셀 분석 의존성은 openpyxl, 일반 파일의 내장 VBA 추출은 oletools다. Windows Excel 경로만
xlwings를 추가 사용한다. openpyxl은 자체 수식 계산기가 아니므로 제한된 별도 해석기를 사용한다.
시험용 실제 VBA 파일 생성에는 pyOpenVBA(MIT)를 별도로 사용했다. 일반 분석·이전 실행에는 필요 없다.
분석 요청에서만 실행하며 추가 후크·모델 호출·사용자 설정 변경은 하지 않는다.
