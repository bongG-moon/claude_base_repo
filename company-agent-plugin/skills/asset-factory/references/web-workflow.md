# 크롬 업무를 스킬로 만들기

사용자가 웹 반복 업무를 **스킬로 만들거나 고치려는 경우만** 읽습니다.
단순 웹 조회·HTML 보고서는 기존 해당 스킬을 사용합니다. 브라우저 도구가
이미 있으면 재사용하며 업무마다 MCP 서버를 새로 만들지 않습니다.

## 초보자가 보는 순서

1. 알고 있는 답은 재사용합니다. 빠진 **사이트 / 가져올 항목 / 원하는 결과**만
   한 번에 묻습니다. 예: “어느 페이지에서 어떤 항목을 가져올까요? 결과는 표로 정리할까요?”
   개발자 도구·포트·CSS 선택자·세션 ID를 사용자에게 찾게 하지 않습니다.
2. 현재 세션의 실제 도구 목록으로 승인된 브라우저 연결을 확인합니다.
   없으면 “크롬 연결 도구가 아직 없습니다. 담당자에게 연결 준비를 요청해 주세요.”로
   끝냅니다. 업무 설명은 이어서 쓸 수 있습니다. 설치·전역 설정 변경·PC 탐색을 하지 않습니다.
   가상 자료로 절차만 설계했다면 실제 연결·조회는 미확인이라고 구분합니다.
3. 사용자가 지정한 사이트·탭만 확인합니다. 여러 후보이면 한 번 선택을 받습니다.
   실제 관찰한 표 제목·열 이름·버튼의 뜻으로 대상을 설명하고 확인받습니다.
   임의 DOM 경로/좌표를 추측하거나 없는 요소 선택 기능을 약속하지 않습니다.
4. 회사에서 허용한 자료의 필요한 열을 **최대 5행**으로 시험합니다. 검색 필터도 조회
   동작임을 확인합니다. 빈 결과도 조건과 항목을 확인하면 정상일 수 있습니다.
   제출·수정·삭제·메일 발송·결재·구매는 이번 조회 스킬의 범위가 아닙니다.
5. 실제 결과의 열·조회 조건·행 수를 확인합니다. 아직 안 정했다면 **내 모든 작업에서 /
   이 프로젝트에서만** 중 저장 위치를 한 번 묻습니다. 기존 선택을 유지합니다.
   도구 응답 성공이나 연결 등록만으로 업무 시험에 통과했다고 하지 않습니다.
6. `authoring.md`의 기존 AssetSpec 생성으로 저장합니다. 새 도구가 정말 필요할 때만
   `platform-tools.md`를 읽습니다. 사용법·저장 위치·남은 제한만 한국어로 전달합니다.

## 필요할 때만 쓰는 작은 도우미

조건을 정리하거나 이어서 진행할 때 `cliCommand` 뒤에
`asset web-plan --spec "<업무 설명.json>"`을 붙일 수 있습니다. 처음 설명이 없으면
`asset web-plan`은 필요한 질문만 반환합니다. 스킬 제작의 의무 준비 명령은 아닙니다.
이 도우미는 브라우저·AI·네트워크를 실행하지 않고 파일도 저장하지 않습니다.

최소 설명 예시(가상 사이트이며 실제 접속하지 않음):

```json
{"name":"weekly-applicants","purpose":"매주 신청 현황을 항목별로 정리",
 "site":"https://training.example.invalid/applicants",
 "fields":["이름","부서","신청일"],"filter":"사용자가 지정한 조회 기간",
 "output":"table","maxRows":50,"storageScope":"project"}
```

지원 필드만 넣습니다. 이름은 기존 자산 이름 규칙을 따릅니다. 주소에는 로그인 값·검색
쿼리·fragment를 넣지 않습니다. `output`은 table/html/csv이며 기본은 table입니다.
`maxRows` 기본 50, 상한 200입니다. `storageScope`는 personal/project이고 미정이면 생략합니다.

- `connection`: missing / reported_connected / disconnected / login_required / denied.
  **실제 현재 연결 보고를 확인한 상태만** 넣습니다.
- `toolContract`: `{"server":"실제 서버 이름","tools":[{"name":"실제 도구 이름","inputSchema":{...}}]}`.
  현재 도구 목록에서 필요한 도구 1~6개의 실제 형식을 그대로 사용합니다.
  예시를 실재 도구로 가정하지 않습니다. 입력 형식에도 인증 예문·비밀값이 없어야 합니다.
- `trial_required`의 `trialPlan.fingerprint`는 사이트·항목·한도·도구 계약에 묶입니다.
  실제 작은 조회 후 `trial:{"status":"passed","fingerprint":"반환값","rowCount":3,"fieldsMatch":true}`를
  추가할 수 있습니다. 실패는 failed입니다. 페이지 응답·스크린샷·행 내용은 넣지 않습니다.
- `ready_to_save`의 `assetSpec`만 UTF-8 JSON으로 저장하여 기존 `asset create`에 전달합니다.
  선택한 `--storage-scope`와 `--project-root`를 유지합니다. 응답 전체를 AssetSpec으로 쓰지 않습니다.
  생성 전 기존 `skill resolve`로 이름 충돌을 확인합니다. 읽기 시험은 작성자의 보고이며
  이 도우미의 독립 검증·서명된 MCP 영수증·현재 세션 연결 증명이 아닙니다.

외부/공통 MCP는 실제 연결을 확인해 이름·스키마 해시를 업무 절차에 참조합니다.
같은 관리 저장소의 검증된 MCP일 때만 기존 `tool_dependencies` 결합을 사용합니다.
외부 서버를 그 저장소의 검증된 자산으로 꾸미거나 재등록하지 않습니다.

## 인증과 API를 다룰 때

사용자가 직접 로그인합니다. 쿠키·비밀번호·인증 헤더·토큰·브라우저 저장소를 탐색하거나
복사하지 않습니다. API 주소/요청 항목/응답 항목/인증 방식의 **비밀값 없는 계약**은
담당자가 준 문서나 승인된 도구로 확인할 수 있습니다. 요청 주소의 쿼리·응답 본문에도
비밀값이 있을 수 있으므로, **모델에 전달되기 전 제거가 보장되지 않은 네트워크 원문
도구는 사용하지 않습니다.** 현재 web-plan은 캡처/마스킹 도구가 아닙니다.

별도 API 도구는 승인된 인증 설정을 참조하는 전사 표준 tools.py로 만듭니다.
브라우저 인증값을 복사해 재호출하지 않습니다. GET이라는 이유만으로 조회라고 판단하지
않고 업무 의미와 허용 범위를 확인합니다. 서비스 키 발급·등록은 별도 회사 절차입니다.

## 연결 담당자에게 전달할 사항 — 연결이 없을 때만

- 후보는 승인된 고정 버전 Chrome DevTools MCP입니다. 이미 있는 다른 승인 도구도
  실제 기능이 맞으면 재사용합니다. 하네스는 설치/등록/다운로드하지 않습니다.
- 기본은 업무 전용 Chrome 프로필, 직접 로그인, 로컬 연결입니다. 평소 프로필을 복사하거나
  디버깅 포트를 외부에 공개하지 않습니다. Chrome 버전·정책은 실제 환경에서 확인합니다.
- 기존 브라우저 autoConnect는 Chrome 144+ 조건과 사용자 허용이 필요하고 선택 프로필의
  다른 창까지 접근할 수 있습니다. 탭 선택 지침이 기술적 격리는 아닙니다.
- 공식 기본값의 사용 통계·성능 URL 조회·업데이트 확인을 검토합니다.
  승인 구성에는 `--no-usage-statistics`, `--no-performance-crux`,
  `CHROME_DEVTOOLS_MCP_NO_UPDATE_CHECKS=1`을 검토하고 외부 통신은 별도로 시험합니다.
  `--slim`은 임의 스크립트 evaluate를 포함하므로 안전 모드라고 설명하지 않습니다.
- 로컬 도구라도 읽은 자료는 기존 Claude/HCP 모델로 전달됩니다. URL 허용 목록도 완전한
  네트워크 격리가 아닙니다. 접근·마스킹을 강제하려면 검토된 실행 계층이 필요하고,
  그때 제한 없는 원시 도구를 동시에 노출해서는 안 됩니다.

[연결 범위](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/main/docs/advanced-usage.md),
[보안 한계](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/main/SECURITY.md).

## 반복 실행·복구

필요한 텍스트·열만 읽고 전체 이미지/페이지 재수집을 피합니다. 같은 대화에서 변경 없는
연결 정보는 재사용합니다. 일시적 **조회** 오류만 최대 한 번 재시도합니다.
로그인 만료는 직접 로그인, 권한 거절은 허용 범위 확인, 화면 변경은 바뀐 대상만 재확인합니다.
새 설치/다른 사이트/다른 계정으로 우회하지 않습니다. 결과가 HTML이면 그때 관련 제작
스킬을 선택하고, 이 스킬에 HTML 디자인 절차를 복제하지 않습니다.
학습에는 확인된 절차와 수정 이유만 남기며 페이지 원문·화면·인증값을 자동 보관하지 않습니다.
