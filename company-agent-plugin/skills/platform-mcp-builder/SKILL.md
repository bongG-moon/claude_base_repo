# 전사 표준 MCP 도구 개발

회사 공통으로 배포하는 **개발 안내 스킬**입니다. 결과물은 사용자가 선택한 개발 폴더에 만들며 회사 배포본·플러그인 캐시를 수정하지 않습니다. 설명·검토만 요청하면 파일을 생성하거나 실행하지 않습니다.

## 시작

- 이 요청에 맞는 기존 도구·개발 폴더를 먼저 확인합니다. 전사 표준이 지정됐으면 이 스킬을 사용하고, 일반 개인 자산이면 `asset-factory`를 사용합니다. 같은 목적의 다른 스킬과 실제로 겹치고 우선 선택도 없을 때만 질문합니다.
- 신규 제작에는 용도, 입력·출력, 접근할 시스템/권한, 개발 폴더가 필요합니다. 이미 제공한 내용은 다시 묻지 않습니다. 저장 범위가 빠졌으면 **개인 전체 / 이 프로젝트** 중 어디에 둘지와 개발 폴더를 물어 답변을 기다립니다. 회사 공통으로 공유할지는 이후 담당자 검토 사항입니다.
- **소스 폴더 선택은 MCP 연결 등록이 아닙니다.** 이 스킬은 개인 상태 저장소에 활성 자산을 등록하지 않습니다. 기존 프로젝트를 수정할 때는 그 경로·범위를 유지합니다.

## 작성

처음 작성하거나 플랫폼 호환성을 검토할 때 `references/platform-contract.md`를 읽습니다. 같은 본문이 현재 대화에 있으면 재사용합니다.

1. 기존 전사 프로젝트가 있으면 기본 수정 대상은 `src/mcp/tools.py`입니다. `app.py`, `server.py`, 회사 `config`와 인증 설정은 플랫폼 담당 영역으로 유지합니다.
2. 새 로컬 프로젝트라면 이 스킬의 `scripts/create_project.py --destination "<새 절대 경로>"`를 승인된 Python으로 실행합니다. Python은 현재 하네스가 확인한 실행 경로를 사용하며 임의의 다른 사용자 환경을 찾지 않습니다. 예: `"<python>" -X utf8 -B "<스킬 경로>/scripts/create_project.py" --destination "<개발 폴더>"`. 기존 폴더는 덮어쓰지 않으므로 기존 파일 수정에는 이 생성기를 사용하지 않습니다.
3. 개발자는 `register_tools(mcp: FastMCP) -> None` 안에 `@mcp.tool()`과 타입이 있는 함수를 작성합니다. 전사 표준은 `mcp.server.fastmcp`를 쓰는 공식 Python SDK **1.x**입니다. 이름이 같은 별도 패키지나 SDK 2.x로 바꾸지 않습니다. 업무 로직에 Company Agent의 경로·상태·설정 모듈을 넣지 않습니다.
4. 함수 설명, 정상·실패 입력, 크기/시간 제한, 외부 쓰기 여부를 함께 정의합니다. 원문·자격증명을 로그에 남기지 않습니다. 설정과 비밀값은 전사에서 실제 제공하는 `config.cfg`의 항목만 사용합니다. 없는 항목은 준비물로 명시합니다.

## 시험과 전달

- 로컬 지원 파일 `config.py`, `local_server.py`, `requirements-local.txt`는 전사 환경을 대체하지 않습니다. 패키지가 없으면 승인된 환경/오프라인 패키지가 필요하다고 알리고 미검증으로 남깁니다. 인터넷 설치나 기존 환경 업그레이드를 자동 실행하지 않습니다.
- 개발 폴더에서 승인된 Python으로 `-X utf8 -B -m unittest -v test_tools`를 실행합니다. 제공된 검사는 로컬 ASGI 전송 위에서 실제 MCP SDK의 initialize → tools/list → tools/call과 입력 오류를 시험합니다. 업무 함수를 바꾸면 그 함수의 기대 결과·실패 사례도 시험에 추가합니다. 목록에 나온 모든 도구를 무작정 호출하지 않습니다. 외부 시스템 쓰기를 시험할 때는 대상과 권한을 먼저 확인합니다.
- 사용자가 연결 시험도 요청하면 `-X utf8 -B local_server.py --port 8765`로 내 PC의 `http://127.0.0.1:8765/mcp`를 엽니다. `/health`는 생존 확인일 뿐 업무 도구 성공 증거가 아닙니다. 포트 충돌 시 다른 프로그램을 종료하지 말고 비어 있는 포트를 선택합니다. 시험 후 자신이 시작한 서버만 종료합니다.
- CLI에 연결하려면 별도의 **개인 전체/현재 프로젝트 적용 범위**와 이름을 확인한 뒤 설치된 Claude CLI가 지원하는 HTTP MCP 등록 절차를 사용합니다. 요청이 없으면 등록하지 않습니다. 기존 이름·MCP·모델·플러그인 설정은 보존합니다. 기존 `asset test-mcp`의 stdio 검증/활성화를 HTTP 검증으로 대신하지 않습니다.
- 전사 제출 요청에는 `src/mcp/tools.py`, 실제 추가 의존성·cfg 항목, 입력/출력 예제, 시험 결과와 남은 확인 사항을 전달합니다. 기본적으로 로컬 설정·서버·비밀값은 제출 대상이 아닙니다. 추가 업무 모듈이 필요하면 파일 목록을 명시합니다. 자동 업로드·전사 배포는 하지 않습니다.
- 최종 답변에는 결과 파일, 실제 시험 범위, 전사에서 별도 확인할 부분만 간단히 적습니다. Markdown 스킬 안내도 함께 제출할 때는 상대 참조 파일을 포함하고 로컬 절대 경로와 Company Agent 전용 호출 지시를 전사 실행 지시로 옮기지 않습니다.
