# 한 요청의 최종 결과만 전달하기

HTML/PPT 산출물을 만드는 작업에서 읽는다. 코드 프로젝트의 여러 소스 파일이나
사용자가 명시적으로 요청한 여러 형식을 억지로 한 파일로 합치는 규칙은 아니다.

## 한 번 준비하고 같은 작업으로 수정

최종 파일의 이름·위치를 정한 뒤 아래 준비를 **한 작업에 한 번만** 실행한다.
기존 파일과 겹치면 보존하고 사용자 의도에 맞는 새 목적지를 정한다.

```text
business artifact-start --output "<최종 보고서.pptx 또는 .html>" --state-root "<stateRoot>"
```

반환된 `workFile`, `jobPath`, `workingDirectory`, `finalOutputPath`를 유지한다.
job은 `jobPath`에 작성한다. 자료 처리/저장 권한은 기존 지침대로 확인한다.
작업 공간은 현재 사용자 상태 저장소의 tmp이며 Memory/Knowledge가 아니다.
원본 파일은 복사·변경하지 않는다. 추가 모델 호출이나 외부 서비스가 없다.

- HTML 제작: `business html --spec "<jobPath>" --work "<workFile>" --state-root "<stateRoot>"`
- PPT HTML 초안: `business ppt-design-preview --spec "<jobPath>" --work "<workFile>" --state-root "<stateRoot>"`
- 승인된 PPT 제작: `business ppt --spec "<jobPath>" --work "<workFile>" --state-root "<stateRoot>"`
- 명시적으로 요청한 HTML 대표양식: 별도의 HTML 목적지 작업에 `business ppt-template --spec "<승인 job>" --work "<workFile>" --state-root "<stateRoot>"`

양식이 있으면 기존 `--template`을 그대로 전달한다. `--work`와 `--output`은 같이 쓰지 않는다.
초안·제작·내부 보정 때 새 artifact-start를 반복하지 않는다. 같은 workFile만 전달한다.
실패 후 재시도하더라도 프로젝트 폴더에 초안2/초안3/v2/이미지형 사본을 만들지 않는다.
PPT의 `designReview`는 반환된 최신 HTML 초안 경로/해시로 유지하고 실제 승인 후 갱신한다.
다른 작업에서 만든 초안이나 이전 보정 전의 초안을 임의로 승인된 것으로 바꾸지 않는다.

`outputPath`와 `previews`는 검사용 **내부 파일**이다. 이를 실제로 확인한다.
PPT 초안은 승인 질문에서 가장 최근의 HTML 한 개만 보여준다. 검사 이미지·과거 초안·
job 파일을 사용자에게 여러 결과물로 나열하지 않는다. 참고 PPT 미리보기나 첨부 HTML의
가상 예시도 workingDirectory 안에 저장하며 최종 폴더에 만들지 않는다.
앱이 작업 폴더 밖의 미리보기를 제한하면 지원되는 파일 선택기로 해당 내부 파일만
선택한다. 보기 위해 최종 폴더에 사본을 늘리거나 앱의 경로 제한을 해제하지 않는다.
내부 수정은 기존의 제한된 재시도 횟수를 유지한다. 권한 거절을 우회하지 않는다.

## 확인 후 한 번 전달

필요한 내용·수치·화면 확인을 마친 뒤 실행한다. 화면 확인이 불가능하면 그 제한을
그대로 보고하며, 이 명령을 검증을 했다는 증명으로 삼지 않는다.

```text
business artifact-publish --work "<workFile>" --state-root "<stateRoot>"
```

최신 성공 후보 한 개만 처음 지정한 목적지에 저장한다. 같은 명령을 다시 실행해도
결과를 재생성하거나 다른 이름으로 늘리지 않는다. 후보가 변경됐거나 마지막 수정이
실패했으면 이전 후보를 몰래 전달하지 않는다. 최종 파일이 이미 있고 내용이 다르면
덮어쓰지 않는다. 최종 답변에는 반환된 `deliverables`와 실제 제한만 안내한다.

이미 전달을 마친 파일을 다음 사용자 요청에서 수정하거나 다른 결과를 새로 요청하면
새 작업으로 분리할 수 있다. 기존 결과는 사용자 허락 없이 덮어쓰거나 삭제하지 않는다.
명시적인 여러 파일/형식/비교안 요청은 요청한 개수대로 별도 목적지를 만든다.
재사용 대표양식은 사용자가 원할 때만 별도로 저장한다. 매 PPT마다 추가 결과로 만들지 않는다.

## 작업이 끝난 뒤 중간 파일 정리

최종 게시가 확인되면 제작기가 생성 시 기록한 임시·중간 파일을 자동 정리한다.
원본·최종 파일·대표 양식·기억·스킬은 정리 대상이 아니다. 생성 후 수정된 파일,
미등록 파일, 이전 버전의 작업 기록은 그대로 남긴다. 이름이 temp이거나 Git에
등록되지 않았다는 이유로 소유권을 추정하지 않는다. 최종 결과가 참조하는 파일도 보존한다.

`cleanup` 결과의 실제 정리 수와 남긴 이유를 따르며 삭제하지 못한 파일 때문에
결과물을 다시 생성하지 않는다. 잠긴 파일은 남기고 반복 재시도하지 않는다.
필요할 때만 같은 작업의 정리를 다시 요청할 수 있다:

```text
business artifact-cleanup --work "<workFile>" --state-root "<stateRoot>"
```

이는 해당 작업의 등록된 중간물만 처리하는 명령이다. 범용 강제 삭제 명령으로
대체하거나 삭제 후크를 끄지 않는다. 기존 Claude 승인과 운영체제 권한은 유지한다.
정상 정리에서는 별도의 질문이나 모델 호출을 추가하지 않으며 결과가 있을 때
짧게 안내한다. 이 규칙은 기본 제작기의 저장 흐름이며 임의 Bash/Write·타사 도구의
모든 파일을 자동 추적·정리하는 기능은 아니다. 작업 기록은 재전달 방지를 위해 보존한다.
