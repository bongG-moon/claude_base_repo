# 스킬 선택 준비

이 절차는 실행 권한이나 검증 성공을 부여하지 않습니다. 사용자에게 내부 기록을 나열하지 않습니다.

1. `skillWorkflow.indexRead`가 false이면 `skillSelection.catalog.path`를 Read로 끝까지 읽습니다. 길면 나누어 읽습니다.
2. 전체 출처의 용도를 의미로 비교합니다. 같은 이름의 프로젝트 우선 설정, 명시적 사용자 호출을 존중합니다.
3. 목록의 선택 파일 경로로 필요한 SKILL.md만 읽습니다. 성공한 Read 또는 식별 가능한 Skill 호출이 선택을 기록합니다.
4. 다음 요청에서 같은 스킬이 적합하면, 이미 읽은 본문은 `cliCommand` 뒤에 `skill route --session SESSION --turn TURN --name NAME`으로 재사용합니다. TURN은 `skillWorkflow.turn`입니다. 새 본문이면 Read로 읽습니다.
5. 정말 관련 스킬이 없을 때만 `--name NAME` 대신 `--fallback no-relevant-skill`을 기록하고 일반 작업을 진행합니다. 무관한 스킬을 읽어 조건만 채우지 않습니다.

company-agent, karpathy-guidelines, self-learning 등 공통 조율·보완 지침을 읽는 것만으로 실제 업무 스킬을 선택한 것으로 처리하지 않습니다. 이 지침 자체가 요청의 목적이면 이미 읽은 해당 이름을 명시적으로 선택할 수 있습니다.

스크립트, 파일 변경, MCP, Company Agent 작업자 전달 전에 준비가 빠져 있으면 짧은 안내로 실행을 보류합니다. 누락된 목록/본문을 읽은 뒤 진행하되, 실제 권한 거절·보호 제한은 이 준비 안내와 구분하며 우회하거나 반복하지 않습니다. Stop 검증 실패로 기록하지 않습니다.

Read/Glob/Grep/선택 질문/스킬 목록 확인은 막지 않습니다. CLI 선택 기록에도 원래 Claude 권한 규칙은 적용됩니다. 승인이 필요한 환경에서는 선택을 위해 권한을 넓히지 말고 필요한 SKILL.md를 다시 Read하는 방식으로 준비할 수 있습니다.

스킬·선택 설정이 바뀌면 다음 사용자 요청에서 목록이 갱신됩니다. 작업 중 선택한 파일이 바뀌거나 삭제되면 실행을 중단하고 새 요청에서 목록을 갱신합니다. 컴팩트 이후에는 이전 읽기 기록을 재사용하지 않습니다.

이 확인은 지원되는 도구 경로에서 목록·본문 읽기 순서를 확인합니다. 모델이 요청의 의미를 정확히 이해했다는 보증, 다른 플러그인·외부 작업자의 완전한 통제, 보안 샌드박스가 아닙니다.
