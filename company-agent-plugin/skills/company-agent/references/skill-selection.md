# 스킬 선택 준비

이 절차는 실행 권한이나 검증 성공을 부여하지 않습니다. 사용자에게 내부 기록을 나열하지 않습니다.

1. `skillWorkflow.indexRead`가 false이면 `skillSelection.catalog.path`를 Read로 끝까지 읽습니다. 길면 나누어 읽습니다.
2. 전체 출처의 용도를 의미로 비교합니다. 같은 이름의 프로젝트 우선 설정, 명시적 사용자 호출을 존중합니다.
3. 목록의 선택 파일 경로로 필요한 SKILL.md만 읽습니다. 성공한 Read 또는 식별 가능한 Skill 호출이 선택을 기록합니다.
   본문을 목록보다 먼저 읽었어도 그 읽기 기록은 보존됩니다. 목록을 나중에 확인했다는 이유만으로 본문을 다시 읽지 않습니다.
4. 같은 목록 버전에서 이미 읽은 본문이 현재 요청에도 맞으면 그대로 재사용합니다. `skill route`는 선택적 진단 명령이지 필수 단계가 아닙니다. 실행 명령 앞에 결합하지 않습니다. 새 본문이면 Read로 읽습니다.
5. 관련 스킬이 없으면 일반 작업을 진행합니다. 무관한 스킬을 읽어 기록만 채우지 않습니다.

company-agent, karpathy-guidelines, self-learning 등 공통 조율·보완 지침을 읽는 것만으로 실제 업무 스킬을 선택한 것으로 처리하지 않습니다. 이 지침 자체가 요청의 목적이면 이미 읽은 해당 이름을 명시적으로 선택할 수 있습니다.

준비 기록이 빠져 있으면 요청·목록 버전당 한 번만 내부 참고 안내를 전달합니다. 이 안내는 실행을 차단하지 않으며 빨간 권한 거절을 발생시키지 않습니다. 경로가 잘못되었다고 추측하거나 pwd/ls/도움말을 반복하지 않습니다. 실제 권한 거절·보호 제한은 별개이며 그대로 준수합니다. Stop 검증 실패로 기록하지 않습니다.

사용자의 다음 답변에서 `selected`가 비어 있어도 이전 본문을 잊었다는 뜻은 아닙니다. 새 요청에 맞는지 판단하라는 뜻이며, 선택 기록을 채우기 위한 명령을 실행할 필요는 없습니다. 이전 스킬을 무조건 자동 선택하지도 않습니다.

Read/Glob/Grep/선택 질문/스킬 목록 확인은 막지 않습니다. CLI 선택 기록에도 원래 Claude 권한 규칙은 적용됩니다. 승인이 필요한 환경에서는 선택을 위해 권한을 넓히지 말고 필요한 SKILL.md를 다시 Read하는 방식으로 준비할 수 있습니다.

스킬·선택 설정이 바뀌면 다음 사용자 요청에서 목록이 갱신됩니다. 변경·삭제가 확인된 스킬은 이전 본문을 현재 파일처럼 재사용하지 않습니다. 새 요청에서 목록을 갱신합니다. 컴팩트 이후에는 이전 읽기 기록을 재사용하지 않습니다.

이 확인은 지원되는 도구 경로에서 관찰된 읽기 기록을 참고합니다. 모델이 지침을 실제 적용했거나 요청의 의미를 정확히 이해했다는 보증, 다른 플러그인·외부 작업자의 완전한 통제, 보안 샌드박스가 아닙니다.
