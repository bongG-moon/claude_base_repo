# PPT 참고 입력과 허용된 화면 캡처

이미 받은 목적·독자·장수·스타일/배치 유지 선택을 재사용한다. 디자인만 참고하면
표지·본문·표/차트 등 대표 2~3장부터, 전체 내용 참고 요청이면 요청한 모든 장을
2~3장 묶음으로 확인한다. 참고 범위와 최종 산출물의 전체 장 검토는 다르다.
기존 캡처/분석이 충분하면 명령·capabilities 검사·추가 질문 없이 제작으로 이어간다.

## 참고자료에서 읽을 기준

디자인 참고 요청이면 처음 확인한 대표 장에서 아래 네 항목을 짧게 정리해 현재 작업에서 재사용한다.
내용만 참고하라는 요청이면 기존 디자인·말투까지 그대로 복제한다고 가정하지 않는다.
별도 분석 파일·추가 승인·별도 모델 호출은 만들지 않고 기존 HTML 초안에 반영한다.

- **배치:** 화면 비율, 제목·본문·출처 위치, 여백, 정렬선, 카드·표·차트의 반복 패턴과 정보 밀도.
- **글꼴과 색:** 제목/본문/강조/수치의 서체·크기·굵기·대비. PPT 분석의
  declaredTextStyles는 장당 최대 8개 명시 서식 표본이며 sz는 1/100pt, b는 굵기다.
  shapeId로 같은 결과의 textPreview와 연결한다. 테마 상속·혼합 서식 전체가 해석된
  것은 아니다. 이미지에서 정확한 폰트 이름·굵기 수치를 확정하지 않는다. 읽기 어려운
  글꼴은 확인된 설치 글꼴 중 비슷한 한국어 대안을 써 초안에서 차이를 알린다.
- **내용 구성:** 제목이 주제형인지 결론형인지, 주장→근거→조치의 연결, 비교 기준,
  숫자의 단위·기간·분모, 도표가 설명하는 관계. 사용자가 바꾸라고 했던 부분은
  이번 요청/제공된 맥락에서 확인한 것만 반영하며 다른 대화를 자동 수집하지 않는다.
- **문장과 말투:** 명사형/서술형, 존댓말 여부, 문장 길이, 한영 혼용·약어 풀이,
  불확실성의 표현. 근거 없는 과장·번역투를 줄이되 수치·인용·회사 고정 문구·조건은
  보존한다. 참고 파일의 문체가 곧 사용자의 영구 선호라고 단정하지 않는다.

관찰된 특징과 추정을 구분하고 현재 사용자의 명시 요청을 우선한다. 새로운 업무 내용에
맞게 배치하되 같은 참고 장을 모든 페이지에 반복 복제하지 않는다. 서체·말투가 서로 다른
참고자료가 섞이면 작업을 좌우하는 모순만 짧게 질문한다. 나머지는 선택 이유를 초안에
간단히 설명한다. 단순 화면 모사보다 제목→근거→다음 장의 논리가 이어지게 구성한다.

### 관찰한 스타일을 실제 개체로 연결

현재 작업의 짧은 메모에서 **특징 / 근거 장·개체 / 적용 위치 / 불확실성**을 연결한다.
예: `둥근 회색 카드 / 3장 shapeId 7 / 실행 과제 카드 / 명시 서식`처럼 기록한다.
별도 설문·파일·재승인 단계를 추가하지 않으며 기존 HTML 초안을 보여 줄 때만 차이를 알린다.

- 도형은 사각/둥근/원형, 채움/테두리, 선 굵기, 그림자, 연결 방향, 그룹 기준을 본다.
  `declaredShapeStyles`는 장당 최대 12개 고유 표본이다. `preset`, `fill`, `line`,
  `outerShadow`를 shapeId로 원래 개체와 연결한다. widthEmu / 12700 = pt.
  schemeClr와 tint/alpha는 상속 전 선언값이다. RGB로 계산됐다고 말하지 않는다.
- 문단의 정렬·들여쓰기·행간·앞뒤 간격·불릿은 `declaredParagraphStyles` 최대 8개를 본다.
  spcPts는 1/100pt, spcPct는 100000이 100%이다. 모든 문단·마스터·테마의 최종 결과가 아니다.
- `presentationTheme`는 역할별 색, `presentationFont`는 기본 서체다. 제목과 본문의 서체·굵기나
  도형별 색이 다르면 기본 테마 하나로 덮지 않고 `elements`의 font/size/bold/color,
  shape/fill/border/borderWidth/group과 lineSpacing으로 지원되는 차이를 반영한다.
  엔진 미지원 도형·점선·단락 간격 등은 정확한 보존을 약속하지 말고 초안에서 근사 범위를 알린다.
- 내용의 표지/근거/결론 역할에 맞춰 여러 참고 배치를 사용한다. 공통 색·서체·간격은 유지하되
  모든 장을 같은 카드 모양으로 바꾸지 않는다. 원본의 관계가 병렬이면 이유 없이 화살표를 넣지 않는다.
- 캡처는 보이는 글·배치의 근거다. 이미지에서 마스터, 애니메이션, 숨은 내용, 차트 원본 값,
  정확한 폰트 이름을 복원했다고 말하지 않는다. 잘린 글·안 보이는 숫자는 추측하지 않는다.

최종 검토는 이 메모의 제목/본문 말투·글꼴 역할·도형·색 의미·정보 밀도와 비교한다.
실제 요구에 따라 바꾼 부분, 근사한 부분, 확인하지 못한 부분만 짧게 전달한다.

반복 보고서라면 사용자가 지정한 최종본의 시각 규칙은 이어받되 이전 숫자와 결론은 이번 자료로
교체한다. 최신판 여부가 불분명하고 결과를 좌우할 때만 확인한다. 색만 비슷하게 바꾸고 제목 위치,
여백, 표의 밀도와 말투를 모두 초기화하지 않는다. 반대로 새 디자인 요청이면 문제라고 지적한 이전
결과의 외형을 정답처럼 보존하지 않는다. 어느 경우에도 원본 업무 내용은 새 근거 없이 고치지 않는다.

## PPTX 직접 첨부

보호 제한 없는 PPTX는 직접 참고한다. 기존 `business ppt-analyze --template "<PPTX>"`
결과가 있으면 재사용한다. 선택 장만 필요하거나 입력 분류가 불명확할 때만
`business ppt-reference --spec "<reference.json>"`를 한 번 사용한다.
명세는 `{"file":"C:/보고/참고.pptx","purpose":"style","slides":[1,3,5]}`이다.
slides는 실제 1부터 시작하는 장 번호이며 생략 시 스타일은 처음 최대 3장,
`purpose:"content"`는 전체 장이다. 큰 자료는 요청 범위대로 최대 60장씩 나눈다.
반환된 selectedSlides/batches와 analysis를 사용하고 ppt-inspect를 중복 호출하지 않는다.
analysis는 개체당 160자·장당 80개까지의 구조 미리보기다. 전체 내용 참고라면
허용된 실제 문서 읽기/화면 도구로 요청 범위를 확인하며 이 결과만으로 완독했다고 하지 않는다.
실제 디자인은 필요할 때 기존 `ppt-preview`의 PowerPoint 이미지 출력으로 확인한다.
이 출력은 파일 Export이며 이미 열린 화면의 캡처가 아니다.

일반 형식/손상/의존성/시간 초과는 DRM으로 단정하지 않는다.
`reference_format_unreadable`이면 알려진 파일 상태와 실제 오류만 확인하며,
화면 경로로 자동 재시도하지 않는다. 명시적인 접근·AI 처리 거절은 해당 범위를 중단한다.

## 보호 PPT를 정상 PowerPoint 화면으로 참고

사용자가 정상 PowerPoint에서 볼 수 있고 회사의 화면 캡처·AI 처리·저장 범위가
허용된 경우, 현재 연결된 **실제 화면 도구**로 정확한 문서 열림을 확인하고
요청 장별 화면을 캡처한다. 도구명·연결·권한을 추측하거나 COM 존재로 승인됐다고
판단하지 않는다. 문서 정상 열기는 현재 도구/사용자의 승인 범위 안에서만 수행한다.
선택 장 화면만 비전으로 참고하고 원본을 변경·복제·복호화하거나 보호를 해제하지 않는다.
승인된 범위가 이미 명확하면 같은 동의·브리프를 반복해서 묻지 않는다.

경로/장 범위를 정리할 필요가 있을 때만 같은 명령에
`{"file":"C:/보고/참고.pptx","inputMode":"powerpoint-screen","purpose":"style","slides":[1,3,5]}`를 준다.
반환은 **캡처 계획**이다. Office를 열거나 화면을 캡처하지 않으며 권한도 부여하지 않는다.
실제 도구로 정상 열기 → 요청 장 확인 → 화면 캡처 → `image-review.md`의 비전 참고를 수행한다.
현재 도구가 없으면 허용된 사용자 캡처를 요청하고, 실제 캡처/AI 처리 차단이면 중단한다.
검은 화면·오류는 읽힌 이미지로 취급하지 않고 원인을 단정하지 않는다.
거절 뒤 다른 도구/Export/OCR로 재시도하지 않으며 장별 실제 확인 범위를 남긴다.
캡처는 스타일/배치 근거일 뿐 텍스트·표·차트가 편집 가능한 최종 결과를 대체하지 않는다.

## 이미 있는 HTML·이미지

기존 PNG/JPEG/WebP는 바로 참고하며 다시 캡처하지 않는다. HTML은 기존
`native-layout.md`의 htmlSource 또는 저장된 대표 HTML의 --template 경로를 유지한다.
PPTX 전용 분석/보호 질문을 적용하지 않는다. 미확인 장의 내용·작은 숫자를 추측하지
않고 원문·캡처·OCR 전문을 Memory에 저장하지 않는다.
