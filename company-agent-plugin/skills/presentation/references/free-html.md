# 자유 HTML 작성

슬라이드 디자인은 HTML/CSS로 직접 만듭니다. `slides.py`는 디자인 생성기가 아니라 문서 검사, 로컬 자료 내장과 공통 편집기 결합을 담당합니다. 이전 schema/pageRole/scene JSON을 작성하지 않습니다.

## 최소 구조

```html
<!doctype html><html lang="ko"><head><meta charset="utf-8"><title>발표 제목</title>
<style>
:root{--deck-font:"Pretendard","Malgun Gothic",sans-serif;--ink:#172b3a;--accent:#087f8c}
.slide{padding:52px 60px;background:#fff;color:var(--ink)}
.slide h1{font-size:40px;line-height:1.2;letter-spacing:-.03em}
.slide p,.slide td{font-size:22px;line-height:1.5}
.columns{display:grid;grid-template-columns:1fr 1fr;gap:36px}
</style></head><body><main id="deck">
<section class="slide" id="s1" data-notes="발표자에게 필요한 설명">
<h1 data-edit>이번 장의 핵심 주장</h1>
<div class="columns" data-object>
  <article><h2 data-edit>근거</h2><p data-edit>실제 자료 설명</p></article>
  <article><h2 data-edit>판단</h2><p data-edit>근거에서 이어지는 판단</p></article>
</div></section></main></body></html>
```

기본 장표는 1280×720입니다. 문서에 적힌 CSS와 개체 좌표를 유지한 채 창 크기에 맞춰 축소합니다. `section.slide`는 `main#deck`의 바로 아래에 두고 고유 ID를 붙입니다. `hd-`는 편집기용 접두어로 남깁니다. 툴바, 페이지 이동과 저장 스크립트는 직접 작성하지 않습니다.

기본 발표 방식은 한 장씩 넘기기입니다. 빌더가 이전/다음 버튼, 좌우 방향키, PageUp/PageDown과 현재 장 번호를 제공합니다. 원본 저작 파일을 세로로 나열했더라도 사용자에게는 빌더를 거친 발표본을 전달합니다. `main#deck`에 스크롤 스냅, flex/grid 목록이나 외부 여백을 지정하지 않습니다. 전체 보기는 별도 창이며 인쇄 시에는 모든 장을 출력합니다.

- `data-edit`: 제목, 문단, 표 셀, 도형 안 문구처럼 텍스트를 바꿀 단위입니다. 표 전체를 한 편집 구역으로 묶지 않습니다. 부분 강조는 strong/em/span으로 표현합니다.
- `data-object`: 이동/크기 변경할 패널, 이미지, 도형 또는 묶음입니다. 모든 자식을 중첩 선택 대상으로 만들지 않습니다. 복잡한 흐름도는 묶음에 표시하고 내부 글자에는 data-edit를 둡니다. SVG 경로의 점 단위 편집은 제공하지 않습니다.
- `data-notes`: 해당 장의 발표 메모입니다. HTML 속성의 특수문자를 이스케이프합니다.

## 디자인 방향

| 방향 | 구성 | 용도 |
|---|---|---|
| 업무 보고형 | 밝은 배경, 짙은 제목, 한두 강조색, 정돈된 표와 단위가 명확한 차트 | 현황, 비교, 실행 결정 |
| 에디토리얼형 | 큰 제목과 작은 설명의 대비, 비대칭 열, 충분한 여백 | 제안, 전략, 이야기 |
| 기술 설명형 | 모듈 관계, 조건 분기, 정렬된 선과 범례, 단계 강조 | 시스템과 업무 과정 |

이는 출발점이며 고정 컴포넌트 목록이 아닙니다. 한 장의 주장과 근거에 맞는 배치를 만들고, 관찰한 참고의 색 역할/타이포그래피/여백 규칙을 CSS 변수로 유지합니다. 같은 카드를 반복하거나 목적 없는 장식으로 공간을 채우지 않습니다.

제목 36~48px, 본문 22~28px, 표 18~22px, 출처 14~16px에서 시작하되 고정 상한이 아닙니다. 한국어는 `word-break:keep-all`, 읽는 문단은 `line-height:1.5`를 출발점으로 합니다. 행간 150%를 자간 `letter-spacing:150%`로 오해하지 않습니다. 제목보다 본문이 크지 않게 하고 긴 제목은 메시지를 유지해 다듬습니다.

표 행, 차트 값, 조건을 버려 장수에 맞추지 않습니다. 큰 표는 헤더와 합계까지 실제 높이에 들어가는지 확인하고, 부족하면 같은 양식의 이어지는 장으로 나눕니다. 흐름도는 노드와 분기 라벨, 연결선을 별도 영역에 배치하고 글자와 선 사이 여백을 확보합니다. 마름모에는 짧은 조건만 넣고 긴 문장은 도형 바깥의 빈 영역에 둡니다. 선과 노드 위에 라벨을 얹지 않습니다. 서로 다른 단위는 그래프를 나누거나 명시적인 별도 축을 사용합니다.

## 화면 검사

PPTX 변환에도 쓰는 기존 브라우저와 playwright를 이용합니다. 내장 스크립트 실행이나 외부 접속 없이 한 번에 모든 장을 캡처하며 슬라이드 밖 내용, 글자끼리와 SVG 선·라벨 교차 **후보**를 짧게 알려줍니다.

```text
node "스킬폴더/scripts/export_pptx.cjs" --input "presentation/outputs/발표본.html" --audit-only --screenshots "presentation/.work/화면검사-01"
```

폴더는 아직 없는 새 이름을 사용합니다. 브라우저 실행 파일이나 모듈이 별도 위치라면 변환 때와 같이 `--browser`와 `--node-modules`를 지정합니다. 사전 설치가 없다면 설치나 PC 전체 검색을 반복하지 않고, 사용 가능한 도구로 확인하거나 화면 미확인을 알립니다.

경고는 장식·축선 때문에 생길 수도 있어 실제 PNG를 보고 판단합니다. 모든 장을 빠르게 훑고 경고 장의 표 마지막 행, 흐름 라벨과 노드 경계를 확대해 확인합니다. 문제가 있으면 데이터와 참고 스타일은 유지하면서 상자·행 높이·여백·선 경로를 바꾸거나 장을 나눕니다. `deck-source.html`을 고친 다음 새 이름으로 빌드하여 해당 장만 재확인하고 그 최종 HTML을 전달합니다. 전달된 HTML과 소스가 다르면 안 됩니다. 사용자에게 중간 확인을 추가로 묻지 않습니다.

## 첫 결과 비교에서 확인한 작성 기준

- **제목의 자리**: 긴 문장은 짧은 결론 제목과 보조 설명으로 나눕니다. 두 줄 제목이면 제목 영역의 높이도 늘려 구분선이나 본문과 겹치지 않게 합니다. `overflow:hidden`으로 중요한 문구를 숨기지 않습니다.
- **정보량에 맞는 배치**: 대안은 비교, 추이는 차트, 역할은 나란한 구역, 반복 절차는 흐름으로 보여줍니다. 본문이 위에만 몰렸다면 근거를 크게 읽히게 재배치하거나 관련 내용을 한 장으로 합칩니다. 빈 공간을 채우려고 사실을 추가하지 않습니다.
- **돌아가는 경로**: 자동 처리와 사람의 판단을 나누고 보완/거절 뒤 어느 단계로 돌아가는지 화살표와 짧은 조건으로 표시합니다. 하단에 연결되지 않은 예외 상자만 두지 않습니다.
- **숫자와 편집성**: 숫자와 단위, 차트 레이블에는 충분한 폭을 주고 필요하면 `white-space:nowrap`을 씁니다. 의미 있는 숫자나 표 전체를 그림으로 고정하지 않습니다. 표와 차트 옆에 해석 한 줄을 두되 원본 수치를 바꾸지 않습니다.

이 기준은 별도 승인이나 매번 수행하는 평가 절차가 아닙니다. 작성에 적용하고 이미 수행하는 화면 확인에 함께 포함합니다.

## 로컬 완성본

외부 스크립트, CDN, iframe, 네트워크 의존성 없이 작성합니다. 같은 폴더 안의 로컬 이미지/CSS/폰트는 빌더가 내장합니다. 원본 참고 HTML의 스크립트를 복사하지 않습니다. SVG는 인라인 정적 도형으로 작성합니다. 이미지 하나는 10MB 미만이어야 합니다.

기본 Pretendard를 파일 안에 내장합니다. 사용자 또는 참고에서 선택한 다른 글꼴은 CSS 선언으로 유지합니다. 글꼴 파일 없이 다른 PC에서도 같은 폰트가 나타난다고 보장하지 않습니다. `--font`는 명시적인 전체 폰트 변경에만 씁니다.

편집 후 `수정본 저장`은 별도 HTML을 내려받습니다. 원본 파일 자동 덮어쓰기나 서버 업로드는 없습니다. 전체 장의 화면, 작은 표, 줄바꿈, 도형 겹침과 저장본 재열기를 한 번 확인하고 문제와 관련된 소스만 고칩니다. 반복 전체 재생성이나 상시 평가 후크를 추가하지 않습니다.
