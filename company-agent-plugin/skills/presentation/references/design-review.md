# HTML 초안 확인 후 편집 가능한 PPT 제작

1. 요청한 전체 장수의 job JSON을 준비한다. slides, 수치·표·차트·facts와
   designPreset 또는 참고 이미지에서 확인한 presentationTheme/글꼴을 담는다.
   자료에 없는 연도·증가 원인·목표 상향 제안을 임의로 추가하지 않는다.
2. output-delivery 절차에서 한 번 준비한 같은 workFile로 실행한다. 기존 파일을 덮어쓰지 않는다.
   `business ppt-design-preview --spec "<jobPath>" --work "<workFile>" --state-root "<stateRoot>"`
   기존 PPTX나 저장한 대표 HTML을 쓰면 `--template "<양식 경로>"`를 붙인다.
   전체 슬라이드의 수치와 배치를 검증하고 HTML만 만든다. Office 실행·모델 재호출·
   패키지 설치는 없다. 별도 HTML 보고서 디자인 질문도 없다.
3. HTML을 실제로 열어 전체 장을 확인하고 사용자에게 파일 링크와 구성을 보여준다.
   기존 로컬 미리보기 수단이 있으면 이용한다. 파일 생성만으로 육안 확인했다고 하지
   않는다. 브라우저를 사용할 수 없으면 그 범위를 밝힌다. HTML과 PPT는 같은 내용·
   배치 규칙을 사용하지만 글꼴 줄바꿈·차트 모양이 완전히 같지는 않다. 복잡한 CSS
   효과를 모두 재현한다고 약속하지 않는다. 기존 정적 HTML은 `native-layout.md`의
   htmlSource로 직접 변환한다. 캡처는 텍스트가 되지 않으며 전체 장을 그림으로 대체하지 않는다.
4. `이대로 PPT 제작 / 수정 요청 / 참고 디자인 변경`을 묻고 기다린다. 명시적인
   승인 전에는 최종 PPT 제작을 시작하지 않는다. 초안 검토는 전체 업무 완료가
   아니며 completionGuide에는 실제 확인한 범위만 기록한다.
5. 반환된 designReview를 같은 전체 job에 그대로 합친다. confirmed는 처음 false다.
   대화에서 초안 승인을 받은 뒤에만 true로 바꾼다. 경로·해시를 손으로 만들거나
   사용자에게 내부 기록 명령을 실행하라고 요구하지 않는다.
6. 같은 job으로 `business ppt --spec "<jobPath>" --work "<workFile>"`를
   실행한다. 양식이 있으면 동일한 `--template`을 전달한다. PPT는 캡처본이 아니라
   네이티브 텍스트·표·차트로 만들어진다. 이미지 자체는 래스터로 유지된다.
7. 내부 작업 공간의 모든 장의 PPT 미리보기·편집 개체·수치를 확인한다. 확인 후
   `business artifact-publish --work "<workFile>" --state-root "<stateRoot>"`로 최종 파일 하나만 전달한다. 렌더링이 불가능하면 구조·수치
   확인과 육안 미검증을 구분한다. HTML 검토만으로 최종 PPT 검토까지 통과했다고 하지 않는다.

내용·색상·장수·참고 캡처·양식 또는 HTML 파일이 바뀌면 기존 승인은 재사용하지
않는다. 같은 workFile 안에서 job을 고쳐 HTML을 만들고 최신 초안 하나만 다시 보여준다. 기준 HTML을 수정했으면 htmlSource로 새로 배치를 읽는다. 생성된 검토 HTML 직접 편집은 PPT에 자동
반영되지 않으므로 승인 해시 검사에서 멈춘다. 예전 PPTX 미리보기 기록은 새 HTML
초안 확인으로 전환한다.

기존 PPTX의 배치 유지 모드에서도 HTML이 먼저다. 이때 HTML은 교체하는 제목·본문·
표·차트의 위치와 내용만 표시한다. 원본 고정 그림·배경·마스터는 생략되며 이 제한을
미리보기 위에 표시한다. 최종 PPT는 기존 개체 유지 경로로 제작한다. 원본과 정확히
일치해야 하면 이 HTML만으로 시각 검증이 끝났다고 하지 않는다.

designReview는 해당 파일에 대한 사용자 확인을 전달하는 작업 기록이다. 그 JSON이
사용자의 실제 동의를 증명하는 인증 수단은 아니다. 모델은 실제 대화의 승인을
확인해야 하며, 이 기록이 외부 발송·게시 등 별도 작업의 권한을 부여하지 않는다.

단일 PPT는 전경 작업을 우선한다. 백그라운드로 맡겼다면 사용 가능한 결과 조회
도구/완료 알림으로 기다린다. 빈 Agent/resume 호출은 대기가 아니다. 최종 파일은
전체 장수·편집 가능 개체·내용 및 실제 확인 가능한 모든 슬라이드를 검토한 뒤 전달한다.
