0. 준비하기

회사에서 사용을 승인한 Claude Code와 Python 3.11 이상이 필요합니다. 회사 모델·인증서·로그인 설정은 조직 안내를 따릅니다. Node.js·Git은 모든 직원 업무의 필수 준비물이 아닙니다. 필요한 앱과 라이브러리는 업무마다 다릅니다.

  1. 기존 Claude Code가 정상 작동하는지 확인합니다. 이미 된다면 로그인·모델·API 키를 새로 설정하지 않습니다.
  2. 승인된 Company Agent 직원 ZIP 전체를 풀고 Install-CompanyAgent.cmd를 실행합니다. “Claude 전체”와 “이 프로젝트만” 중 필요한 범위를 선택합니다. 다른 하네스 교체를 선택할 때는 백업과 변경 범위를 먼저 읽습니다.
  3. 설치 후 Claude Code를 다시 엽니다. Workspace는 별도 미리보기 묶음입니다. 그 묶음의 Company-Workspace.vbs를 더블클릭합니다. 관리자 권한은 사용하지 않습니다.
  4. 탐색기에서 새로운 빈 연습 폴더를 만들고 작업 폴더로 선택합니다. 실제 고객 자료·메일·공용 폴더는 연습에 쓰지 않습니다.
  5. 신뢰하는 폴더인지 확인합니다. 이 동의는 모든 후속 행위를 무조건 허용한다는 뜻이 아닙니다.

성공 확인: 앱이 열리고 작업 폴더가 보입니다. 이는 AI 응답·Office 읽기 성공까지 확인한 것은 아닙니다. VBS·PowerShell 실행이 회사에서 제한돼 있으면 담당자에게 승인된 실행 방식을 요청하세요.

원본 CLI를 선호한다면: 기존 방식으로 해당 폴더의 Claude Code를 열고 아래 요청문을 입력합니다. /plugin, /skills, /hooks로 실제 등록을 확인할 수 있습니다. GUI가 이 터미널 메뉴 전부를 그대로 제공하는 것은 아닙니다.

성공 확인: 세 달 수치가 맞고 증가 원인을 지어내지 않습니다. 이것만으로 office-reader 사용 성공이라고 기록하지 않습니다.

첨부한 원본 자료를 읽고 핵심 내용과 확인할 사항을 정리해줘.
자료에 없는 이유는 추측하지 마. 실제 확인한 페이지·표 범위와 미확인 부분을 알려줘.
원본 파일은 변경하지 마.

성공 확인: 기본 시험에서는 스킬 이름을 지정하지 않습니다. 실제 office-reader 본문 로드와 읽기 결과, 페이지·표·수치를 각각 확인합니다. 일부 범위만 읽었다면 전체 성공으로 체크하지 않습니다.

막혔을 때: 준비·결과 확인에서 목록을 보고, 필요하면 원본 CLI에서 /company-agent:business-check로 준비물을 확인합니다. Office·승인된 Python 라이브러리·DRM 환경 문제를 하나로 단정하지 않습니다. 없는 라이브러리를 임의로 다운로드하지 않습니다.

먼저 새 디자인 또는 내가 첨부할 기존 양식을 선택하게 해줘.
내 답변을 기다린 뒤 제작해줘. 합계와 달성률을 검증하고 기존 파일은 덮어쓰지 마.

디자인 질문이 오면 예를 들어 **“글래스모피즘, 짧게, 스크롤 방식으로 만들어줘”**라고 답합니다. 추가 디자인 목록에서는 원하는 번호 또는 이름 하나를 선택합니다. 이미 정한 답을 다시 묻는다면 그 내용을 알려주고 반복 여부를 기록합니다.

성공 확인: 질문에서 실제로 기다리는지, 결과 파일이 생성됐는지, 브라우저로 열리는지 확인합니다. 목표 합계 300건, 실적 합계 330건, 누적 달성률 **110%**입니다. 이번 자료에 없는 원인·연도는 임의로 추가하지 않아야 합니다.

새 디자인이나 첨부할 기존 양식을 먼저 선택하게 해줘.
구성과 대표 디자인을 보고 내가 확인하면 제작해줘.
표·차트는 편집 가능해야 하고 기존 파일은 덮어쓰지 마. 자료에 없는 이유는 추측하지 마.

성공 확인: 실제 5장과 수치를 확인하고 표·차트를 선택해 수정 가능한 개체인지 봅니다. 화면 캡처로만 만들어진 표라면 편집 가능 조건을 통과한 것이 아닙니다.

막혔을 때: 질문 대기는 오류가 아닙니다. 백그라운드 작업 진행 중에는 같은 제작을 재요청하지 않습니다. 반복 Stop 오류가 나면 마지막 상태와 실제 파일 유무를 기록하고 중지합니다.

3. 원하는 방식으로 고치기

방금 결과에서 결론을 먼저 보여주고 확인한 사실과 확인할 사항을 구분해줘.
이번 결과만 수정하고 수치와 출처는 유지해줘. 장기 선호 저장은 아직 요청하지 않을게.

성공 확인: 순서는 바뀌고 원래 수치·출처는 유지됩니다. 전체 자료 읽기·파일 제작을 이유 없이 처음부터 반복하지 않는지도 살펴봅니다.

막혔을 때: 원하는 문장 하나를 예시로 보여주세요. 인코딩 표시만 깨졌다면 기존 파일부터 다시 확인하고 중복 생성하지 않습니다.

4. 내 방식 하나 저장하기 — 선택

연습용 선호를 실제 업무에도 사용할지 먼저 결정합니다. 원치 않으면 건너뛰어도 됩니다.

회사 필수 기준은 유지하고 허용된 범위에서 내 보고서 표현 선호를 개인 기억에 저장해줘.
선호: 결론부터 간단히 설명하고 실제 확인한 범위와 미확인 부분을 구분해줘.
이 선호 외 문서 본문이나 계정 정보는 저장하지 마. 실제 저장한 내용과 적용 범위를 알려줘.

또는 기억·하네스 관리 → 개인 전체 / 이 프로젝트 → 기억·지식 → 내 기억 추가에서 변경안을 보고 저장할 수 있습니다. 출처가 있는 용어·계산식은 같은 화면의 내 업무 지식 초안을 사용합니다. 이 관리 화면은 별도 모델을 호출하지 않습니다.

성공 확인: 기억 화면에 정확한 내용과 사용 상태가 나타납니다. 회사 기준이나 전역 설정이 덮어써지지 않습니다. 더 필요 없다면 사용 안 함으로 바꿀 수 있습니다.

막혔을 때: Project와 User 설치의 저장 범위가 같은지 확인합니다. 자동 학습 켜짐과 모든 내용 저장은 다릅니다. 핸드북에서 기억과 학습 범위를 확인하세요.

5. 새 업무에서 다시 쓰기

같은 작업 폴더에서 새 업무 시작으로 새 대화를 만들고 입력합니다.

현재 적용 범위에 저장된 내 보고서 표현 선호를 찾아서 알려줘.
실제로 조회한 내용만 설명하고 찾지 못한 기억은 지어내지 마. 설정이나 기억은 변경하지 마.

성공 확인: 저장된 내용과 실제 조회 내용이 같습니다. 이어서 가상 자료를 요약해 달라고 하고 표현에도 적용되는지 봅니다. “저장됨 → 조회됨 → 결과 반영”을 따로 확인하세요.

막혔을 때: 다른 설치 범위나 다른 폴더인지 확인합니다. PC 전체를 검색하거나 기억 저장소를 합치도록 지시하지 않습니다.

6. 공통 기억과 내 기억을 비교해 보기

이 실습에서 판단할 것: “팀원이 같이 알아야 하는 내용인가, 나만 원하는 방식인가?” 같은 가상 자료를 다시 요청하며 저장·조회·반영을 구분합니다.

먼저 알아둘 차이

공통 기억은 회사·팀이 검토해 배포한 지식이고 내 기억은 내가 저장한 선호·업무 지식입니다. 현재 별도의 공동 쓰기·실시간 동기화 저장소는 없습니다. ‘내 기억에 저장’은 공통 배포가 아닙니다. 회사 규정·공통 스킬을 기억이라고 묶지 않고 공통 하네스로 구분합니다.

남길 내용 적합한 곳 누구에게, 언제 보이나요? 변경·공유 방법
공통 용어·계산식·출처 자료 공통 기억 같은 지식 배포본을 사용하는 업무 담당자의 갱신·배포
나의 답변 순서·개인 업무 지식 내 기억 같은 개인 저장소를 쓰는 업무 나의 검토·저장·사용 중단
부서 필수 절차·공통 스킬 공통 하네스 그 구성을 배포받은 사용자 담당자의 검토·배포
내 반복 절차·계산 도구·폴더 지침 내 하네스 선택한 사용자/폴더 범위 내 자산만 수정, 공유 원본은 관리 주체 확인

Company Agent 개인 기억과 Claude Code 자체 자동 기억은 서로 다른 기능이며 자동으로 합치지 않습니다. 한쪽을 끄거나 지웠다고 다른 쪽도 바뀌지 않습니다. 공유 파일에 적은 문장도 운영체제 권한을 바꾸지는 않습니다.

6-1. 별도의 연습 폴더와 기준선 만들기

탐색기로 같은 부모 아래에 온보딩-연습-A, 온보딩-연습-B라는 빈 폴더를 만듭니다. B를 A 안에 만들지 않습니다. 기존 폴더를 재사용하거나 회사 자료를 복사하지 마세요. 부모 폴더의 CLAUDE.md도 영향을 줄 수 있으므로, 기존 지침이 있다면 삭제하지 말고 시험 기록에 남깁니다.

온보딩 실습 전 현재 적용 범위를 확인해줘. 아직 파일이나 기억을 만들지 마.

작업 폴더·저장소는 자신의 화면에서 비교하고, 다른 사람에게 보낼 기록에서는 사용자명 등 개인 경로를 가립니다. 기존 선호와 실습 선호가 겹치면 기존 값을 덮어쓰지 말고 비교 계획부터 받습니다.

6-2. 공통 기억은 읽고, 공유 여부를 확인하기

기억·하네스 관리 → 회사 공통 → 기억·지식에서 실제 등록된 항목 하나의 출처와 내용을 엽니다. 이어 개인 전체 → 기억·지식을 열어 공통 항목이 개인 편집 대상으로 섞이지 않는지 확인합니다. 공통 항목이 없으면 ‘현재 등록 없음/미확인’으로 남기고 억지로 만들지 않습니다.

현재 설치에 연결된 공통 기억에서 월간 보고에 관련된 용어 또는 계산식이 있으면
항목 이름, 실제 출처, 확인한 내용만 알려줘. 없거나 읽지 못하면 구분해서 알려줘.
내 기억이나 회사 설정에 복사하지 말고, 동료에게 전송하지 마.

성공 확인: 공통 출처를 실제로 조회했으며 개인 기억에 복사하지 않았습니다. 동료와 비교하려면 같은 배포본의 같은 항목만 확인합니다. 같은 모델 응답이 나온다는 사실만으로 공통 기억이 같다고 판단하지 마세요. 내 기억을 공통 자료로 제안하려면 검토용 내보내기 → 민감 내용 확인 → 담당자 검토·배포를 거칩니다. 내보내기 자체는 공통 반영이 아닙니다.

현재 폴더가 내가 선택한 온보딩-연습-A인지 확인해줘.

결과 제목에 [연습 A]를 붙이고 실제 확인한 수치와 확인할 사항을 구분한다.
기존 지침이 있으면 덮어쓰지 말고 알려줘. 회사 설정과 개인 기억은 변경하지 마.

# 온보딩 월간 보고 — 가상 프로젝트 A
- 목적: 가상 월간 실적을 요약한다.
- 수량의 단위는 건이다. 자료에 없는 증가 원인은 추정하지 않는다.
- 결과 제목에 [연습 A]를 붙인다.
- 실제 확인한 수치와 확인할 사항을 구분한다.

파일 생성 후 A의 새 대화에서 아래를 요청합니다. 새 대화를 쓰는 이유는 방금 지침을 말한 대화의 기억만으로 답하는 효과를 줄이기 위해서입니다.

온보딩 월간 보고로 다음 가상 자료를 요약해줘.
6월 목표 100건·실적 90건, 7월 목표 100건·실적 110건, 8월 목표 100건·실적 130건.
실제로 참고한 프로젝트 지침과 개인 기억이 있으면 출처를 구분해 마지막에 짧게 알려줘.
새로운 기억 저장이나 설정 변경은 하지 마.

비교 기준: 제목의 [연습 A], 단위 건, 합계 목표 300·실적 330·달성률 110%, 근거 없는 원인 없음. 파일 존재와 실제 로드는 다릅니다. 원본 CLI의 /context에서 Memory files를 확인할 수 있고, /memory는 Claude 자체 지침·기억을 확인하는 메뉴입니다. Company Agent 기억 목록을 대신하는 메뉴는 아닙니다. 출처를 확인하지 못했으면 ‘공유 지침 적용 미확인’으로 기록합니다.

6-3. 나만의 표현 선호를 더해 비교하기 — 저장 선택

4단계에서 이미 저장했다면 그 기억으로 비교해도 됩니다. 별도 실습용 선호를 원한다면 아래를 보냅니다.

Company Agent 개인 기억에 '온보딩 요약 순서'라는 실습용 선호를 저장하고 싶어.
온보딩 월간 보고를 요약할 때 '핵심 결론 → 수치 → 확인할 사항' 순서를 선호한다는 내용만 저장해줘.
기존 보고서 선호와 겹치면 덮어쓰거나 중복 저장하지 말고 차이를 먼저 물어봐줘.
회사 기준이나 프로젝트 지침을 바꾸지 마. 실제 저장 내용·식별자·적용 저장소를 알려줘.

A에서 다시 새 대화를 열고 6-2의 같은 가상 자료 요청을 보냅니다. 프로젝트 지침 선택 실습을 건너뛰었다면 1단계의 가상 자료로 비교하고 아래 표의 프로젝트 기준은 미시험으로 남깁니다. 이어서 실제 사용한 기억을 조회합니다. 첫 응답에 선호가 적용됐는지와, 조회를 요청한 뒤에야 적용됐는지는 따로 기록하세요.

비교 항목 개인 기억 저장 전 개인 기억 저장 후
A의 프로젝트 기준 [연습 A]·단위·원인 비추정 그대로 유지
개인 표현 순서 기존 선호 또는 기본 표현 저장한 순서가 조회·적용되는지 확인
자료의 수치 목표 300·실적 330·110% 동일해야 함
다른 사람에게 전달 공유할 것은 검토한 프로젝트 지침 개인 저장소·대화는 공유하지 않음

한 번만 다르게 요청하기: 같은 자료에 “이번에는 수치부터 설명해줘. 저장된 선호는 바꾸지 마”를 덧붙여 시험합니다. 이번 표현은 달라져도, 다시 조회한 개인 기억 원문은 그대로여야 합니다. 회사 필수 기준을 개인 선호로 해제하는 실습은 하지 않습니다.

두 사람이 비교할 수 있다면: 승인된 방법으로 가상 CLAUDE.md와 가상 입력만 동료에게 전달하고, 동료 자신의 환경에서 새 대화로 시험합니다. 프로젝트 기준은 공통이고 개인 표현은 다를 수 있습니다. 한 사람이 폴더만 바꾸는 시험은 다른 사용자 계정의 격리 시험을 대신하지 못합니다. 이 문서는 팀 공유 서버를 생성하거나 자료를 자동 전송하지 않습니다.

막혔을 때: 저장됐지만 조회되지 않으면 상태(active/사용 중)와 같은 stateRoot인지 먼저 확인합니다. 조회됐지만 적용되지 않으면 모델 적용 실패로 기록합니다. 다른 사람의 기억을 볼 수 있는지 확인하려고 그 계정 폴더를 탐색하지 않습니다.

정리: 실습용 기억이 불필요하면 선택한 범위 → 기억·지식에서 이번에 만든 식별자만 사용 안 함으로 바꿉니다. 이는 이력까지 삭제하는 작업이 아닙니다. 기존 기억·자동 학습 설정·회사 기준은 그대로 둡니다.

7. 공통 하네스·내 하네스와 적용 폴더 비교하기

한 줄로 이해하기: 회사 공통은 함께 쓰는 기준, 개인 전체는 내 여러 업무, 이 프로젝트는 현재 업무 전용입니다. CLAUDE.md는 프로젝트 지침 파일 중 하나이며 하네스 전체나 자동 기억 저장소와 같지 않습니다. 작은 규칙 네 줄에 작업자·도구를 전부 새로 만들 필요는 없습니다.

‘누가 관리하는가’와 ‘어디에 적용되는가’는 다릅니다

구성 역할 적용 범위·공유 이 실습에서 바꾸나요?
회사·팀 공통 하네스 공통 스킬·후크·업무 기준·검증 절차 설치·활성화한 범위와 회사 배포 대상 아니요. 읽어서 확인만
내 하네스 내 스킬·도구·폴더 지침과 내가 연결한 구성 내 사용자 범위 또는 해당 폴더 내 실습용 자산만. 외부·공유 원본은 보존
User 설치 현재 Windows 사용자에게 플러그인 제공 그 사용자의 여러 작업 폴더; 전 직원 배포와 다름 아니요
Project 설치 선택한 폴더에 플러그인 제공 해당 프로젝트; 다른 폴더에 있다고 가정하지 않음 아니요
프로젝트 CLAUDE.md 목적·자료 단위·출력 조건 해당 폴더와 하위 작업, 공유 시 파일을 받은 팀원 새 연습 파일만
Claude 사용자 CLAUDE.md 사용자 공통 지침 보통 사용자 설정 루트의 파일; 개인 범위 아니요
프로젝트 하네스 생성기 여러 단계·전문 작업자·검증 연결 그 프로젝트의 생성 스킬·에이전트·규칙 필요할 때 별도 선택

화면은 회사 공통 / 개인 전체 / 이 프로젝트의 세 범위를 보여줍니다. 이 프로젝트 안에도 나만 쓰는 자산과 팀이 공유한 파일이 있으므로 공유 여부를 따로 확인하세요. 어느 쪽도 회사 필수 기준을 해제하지 않습니다. Claude의 여러 지침 파일은 함께 문맥에 들어갈 수 있으므로 ‘프로젝트 파일이 전역을 전부 덮어쓴다’고 가정하지 마세요. 지침과 실제 강제 권한 설정 역시 다릅니다. Claude Code 공식 기억·지침 문서를 참고했고, 사내 배포 버전의 실제 로드는 별도로 확인합니다.

Workspace에서는 회사 공통 → 업무 구성에 배포 기준·스킬·후크를, 개인 전체 / 이 프로젝트 → 업무 구성에 해당 범위 자산을 표시합니다. 폴더 지침 편집은 이 프로젝트에만 있습니다. 외부 플러그인을 설치해도 Company Agent가 그 원본을 소유하거나 자동 학습으로 수정하지 않습니다. 스킬 목록 확인은 실제 연결·실행 성공과 별개입니다.

저장 범위와 자동 학습을 함께 시험하기

  1. A 폴더에서 “가상 보고서에 연습-A라고 표시하는 선호를 기억해줘”라고 요청합니다. 개인 전체 / 이 프로젝트 질문이 나오면 이 프로젝트를 선택합니다. 회사 공통을 저장 대상으로 제시하면 잘못된 동작입니다.
  2. 같은 사용자 설치의 B 폴더에서 새 대화를 열고 기억을 조회합니다. A 전용 기억은 나오지 않아야 합니다. A에서는 다시 조회되어야 합니다. 실제 저장·조회와 모델 답변 반영은 각각 확인합니다.
  3. 별도의 가상 선호를 “개인 전체에 저장해줘”라고 요청합니다. 재질문 없이 해당 범위에 저장하고 A/B에서 조회되는지 확인합니다. 프로젝트 지침·회사 원본은 바뀌지 않아야 합니다.
  4. 스킬 만들기도 같은 범위 선택을 사용합니다. “이 프로젝트에 저장할 월간 요약 스킬”처럼 명시하면 범위 질문을 반복하지 않습니다. 기존 항목 수정은 원래 범위이며 자동 이동하지 않습니다.
  5. 자동 학습 카드의 적용 범위를 확인합니다. User 설치는 개인 전체, 별도 Project 설치는 해당 설치 저장소입니다. 화면 이동이나 위 저장 선택만으로 자동 학습 범위가 바뀌지는 않습니다. User 설치의 프로젝트 전용 개인 자산은 명시적 저장/수정용이며 자동 수정 대상이 아닙니다.

자동 학습 흐름은 피드백 후보 → 업무 완료·검증 → 짧은 선호/기존 개인 스킬 점검 항목 반영 → 다음 사용 평가입니다. 직접 교정은 완료 시 반영할 수 있고 추정한 선호는 독립된 업무의 반복 근거가 필요합니다. 읽지 않은 스킬·회사 정책·프로젝트 CLAUDE.md·도구 코드를 자동 변경하지 않습니다. 모델 훈련, 모든 답변마다 저장, 종료 후 백그라운드 실행이 아닙니다. 학습 끄기·내역 확인·되돌리기는 자동 학습 카드에서 합니다. 연습 후 이번 항목만 사용 중단하고 원본은 보존하세요.

# 회의 메모 확인
- 제공된 텍스트만 사용한다. 입력이 없으면 메모를 요청한다.
- 결정 사항 / 할 일 / 미정 사항으로 나눈다. 없는 결정을 지어내지 않는다.
- 할 일은 내용·담당자·기한으로 정리한다. 없는 값은 미정으로 표시한다.
- 외부 조회, 메일 발송, 파일 이동은 수행하지 않는다.

첫 시험은 이름 없이 다음을 요청합니다.

회의 메모를 결정 사항, 할 일, 미정 사항으로 정리해줘.
가상 메모: 다음 보고서에는 누적 실적을 포함하기로 했다.
지민은 금요일까지 표 초안을 만든다. 검토 담당자는 다음 회의에서 정한다.
문서 저장이나 기억 저장은 하지 마.

기대 결과: 결정은 ‘누적 실적 포함’, 할 일은 ‘표 초안 / 지민 / 금요일’, 미정은 ‘검토 담당자’입니다. 금요일의 날짜는 제공되지 않았으므로 특정 날짜를 만들어내면 안 됩니다. 실제로 생성된 스킬 본문을 읽었는지도 확인합니다. 결과만 비슷하다고 자동 선택 성공으로 보지 않습니다.

이어서 새 대화에서 “방금 만든 개인 회의 메모 스킬로 같은 가상 메모를 정리해줘”라고 비교합니다. 이름 없이 실패하고 명시하면 성공하는 경우에는 자동 선택은 미확인/실패, 명시 사용은 성공으로 나눠 기록합니다. 마지막으로 빈 메모를 보내 자료를 요청하는지 시험합니다.

수정 연습: “이 스킬에서 기한이 없으면 추측하지 말고 미정으로 두는 예시를 보완해줘. 기존 이름과 외부 동작 없는 범위는 유지해줘”라고 요청하고 정상·누락 예제를 다시 확인합니다. 새로운 이름의 스킬을 중복 생성하지 않습니다.

저장 위치 주의: Company Agent 자산 생성기는 선택한 범위의 저장소 아래 personal-root/.claude/skills/<이름>/SKILL.md에 저장하고 자체 목록으로 발견합니다. User 설치의 ‘이 프로젝트’ 자산은 개인 상태 저장소의 project-scopes/<폴더 식별자> 아래에 보관합니다. Claude 자체 개인 스킬 폴더나 프로젝트 공유 폴더와 같은 경로라고 가정하지 마세요. 일반 Claude의 개인·프로젝트 스킬 위치는 공식 스킬 문서에 설명돼 있습니다. Company Agent 목록에 보인다는 것과 원본 CLI의 /이름 호출이 등록됐다는 것도 따로 확인합니다. 등록되지 않은 호출명을 반복 실행하지 않습니다.

8-2. 숫자를 일정하게 계산하는 로컬 도구

이번에는 AI가 매번 계산 코드를 새로 만드는 대신, 입력과 출력이 정해진 작은 도구를 만듭니다. 회사 시스템 연결·MCP·추가 패키지는 필요 없는 예제입니다.

개인 로컬 스크립트 도구 'onboarding-achievement'를 만들어 검증 후 사용할 수 있게 해줘.
먼저 같은 역할의 기존 도구와 이름 충돌을 확인하고, 겹치면 선택을 물어봐줘.
입력은 targets와 actuals라는 길이가 같은 비어 있지 않은 정수 목록이야.
각 값은 0 이상 1,000,000 이하, 항목은 12개 이하로 제한해줘.
출력은 targetTotal, actualTotal, achievementRate야.
달성률은 실적 합계 / 목표 합계 × 100을 소수점 둘째 자리까지 반올림해줘.
목표 합계가 0이면 달성률은 숫자가 아니라 null(계산 불가)로 반환해줘.
빈 목록, 길이 차이, 음수, 문자열·참/거짓 입력, 필수 항목 누락은 오류로 구분해줘.
표준 Python으로만 만들고 외부 통신·임의 파일 읽기/쓰기·다른 프로그램 실행은 하지 마.
정상 시험: targets=[100,100,100], actuals=[90,110,130]이면 합계 300·330, 달성률 110.
반올림 시험: targets=[3], actuals=[1]이면 33.33.
목표 0 시험: targets=[0], actuals=[30]이면 달성률 null.
앞서 정한 잘못된 입력도 실제로 시험해줘. 생성만으로 완료라고 하지 마.
검증 전에는 candidate 상태로 두고, 성공한 검증 기록으로만 활성화해줘.
기존 회사 설정, 개인 스킬, MCP 등록은 변경하지 마.

여기서 파일 읽기/쓰기 제한은 생성된 도구의 업무 동작에 대한 것입니다. 하네스가 개인 도구 소스·시험 입력·검증 기록을 저장하고 승인된 Python 프로세스로 실행하는 단계는 필요합니다. 입력 검증과 시간 제한이 있다고 OS 샌드박스가 생기는 것은 아닙니다.

시험 입력 기대 결과
정상 targets [100,100,100], actuals [90,110,130] 목표 300, 실적 330, 달성률 110
반올림 targets [3], actuals [1] 33.33
목표 0 targets [0], actuals [30] 달성률 null; 0%·무한대라고 하지 않음
잘못된 입력 빈 목록, 길이 차이, 음수, 문자열·참/거짓, 필드 누락 오류; 성공한 계산값으로 꾸미지 않음

확인 순서: 생성된 candidate → 실제 시험 결과와 검증 기록 → 활성화된 호출용 스킬 → 같은 입력 재실행. 현재 도구의 검증 기록은 시험한 코드·설정에 묶이며 모든 수학적 경우나 안전성을 증명하지는 않습니다. 코드를 바꾸면 재시험해야 합니다. 이번 연습은 AI에게 최종 수치 검증을 생략하도록 하는 것이 아닙니다.

선택: 교육 담당자가 코드와 입력을 직접 검증할 때

아래는 위 조건의 최소 계산 예제입니다. 안내서를 열어도 실행되지 않으며, 전체 AssetSpec이나 CLI 명령이 아닙니다. 자산 생성기는 별도로 입력·출력 스키마를 구성합니다. 연습 검사는 이 코드와 입력을 임시 저장소에서 사용하며 실제 개인 설정을 바꾸지 않습니다.

import json
import sys

payload = json.load(sys.stdin)
if not isinstance(payload, dict) or set(payload) != {"targets", "actuals"}:
    raise ValueError("targets and actuals are required")
targets, actuals = payload["targets"], payload["actuals"]
for values in (targets, actuals):
    if not isinstance(values, list) or not 1 <= len(values) <= 12:
        raise ValueError("provide 1 to 12 values")
    if any(type(value) is not int or not 0 <= value <= 1000000 for value in values):
        raise ValueError("values must be nonnegative integers up to 1000000")
if len(targets) != len(actuals):
    raise ValueError("list lengths must match")
target_total, actual_total = sum(targets), sum(actuals)
rate = round(actual_total / target_total * 100, 2) if target_total else None
json.dump({"targetTotal": target_total, "actualTotal": actual_total,
           "achievementRate": rate}, sys.stdout, ensure_ascii=False)

8-3. 언제 팀에 나누고, 어떻게 정리하나요?

개인 스킬·도구를 만들었다고 회사 전체에 배포되는 것은 아닙니다. 팀에 유용하다면 목적, 입력·출력, 정상/실패 시험, 권한·준비물, 담당자를 정리하고 민감 내용이 없는 소스만 담당자에게 검토 요청합니다. 회사 공통 반영은 별도 배포 작업입니다. 검증 기록을 다른 PC에 복사해 활성화를 대신하지 않습니다.

정리: 현재 온보딩에는 개인 자산 전체를 한 번에 삭제하는 버튼을 추가하지 않았습니다. 생성된 파일·등록·참조를 먼저 조회해 이번에 만든 이름만 정리할 계획을 받으세요. 실제 정리는 범위를 확인한 뒤 진행하고, 승인된 정리 방법이 없으면 유지합니다. 설치 캐시 수정·기존 스킬 비활성화·MCP 초기화로 충돌을 피하지 않습니다.

막혔을 때: 스킬 목록, 본문 로드, 도구 시험, 활성화를 나눠 확인합니다. 준비물이 없으면 설치를 추측해 진행하지 않습니다. MCP가 필요하지 않은 계산에 MCP 서버를 추가하거나, 연습을 이유로 전체 후크를 끄지 않습니다.

9. 사용량과 결과 확인하기

사용 현황 · 결과 확인을 엽니다. 토큰이 미제공이면 0으로 해석하지 않습니다. 실행 구간과 질문·승인 대기를 구분하고 CLI 보고값을 무조건 요청별로 합산하지 않습니다.

준비·결과 확인에서 내용·범위·파일을 직접 확인한 뒤 통과/실패/미확인/중지를 기록합니다. 스킬 목록의 개수나 준비물 점수가 실제 업무 정확도를 대신하지 않습니다. 확인 기록 내보내기는 자동 전송하지 않으며, 기록 비우기는 대화·기억·결과 파일 삭제와 다릅니다.

성공 확인: 확인하지 않은 항목은 미확인으로 남고, 같은 예제로 재시험할 때 전후 결과를 비교할 수 있습니다. 일반 업무를 위해 매번 진단 화면을 열 필요는 없습니다.

10. 화면 조작은 필요할 때만 시험하기

Workspace의 업무 도우미에서 화면 조작 시험을 선택합니다. 설치 후보·현재 연결 확인은 파일 후보와 이미 실행 중인 CLI의 보고만 읽습니다. Cua를 설치하거나 MCP를 연결하거나 화면을 캡처하지 않습니다.

Driver 미발견이나 연결 미표시는 정상적인 미준비 상태일 수 있습니다. 준비와 회사 승인이 끝났다면 Cua Driver 시험 안내의 계산기 관찰 → 계획 확인 → 작은 입력 → 실제 결과 확인 순서로 시험합니다. 해당 도구를 관찰하지 못했으면 앱은 실행 예문 버튼을 제공하지 않습니다.

11. 마무리 체크리스트와 의견

  • 실제 설치 범위와 작업 폴더를 구분했다.

  • 디자인 질문에 답하고 실제 결과 파일을 열었다.
  • 이번 결과 수정과 장기 선호 저장을 구분했다.
  • 선택한 경우 기억을 새 대화에서 조회·비교했다.
  • 팀의 공유 기준과 개인 기억, Claude 자체 자동 기억이 다른 저장 방식임을 구분했다.
  • A/B 폴더에서 프로젝트 지침과 개인 저장소의 적용 범위를 따로 비교했다.

  • 토큰·시간의 미제공 값과 실제 관찰값을 구분했다.
