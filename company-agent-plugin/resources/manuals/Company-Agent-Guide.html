0. 준비하기

회사에서 사용을 승인한 Claude Code와 Python 3.11 이상이 필요합니다. 회사 모델·인증서·로그인 설정은 조직 안내를 따릅니다. Node.js·Git은 모든 직원 업무의 필수 준비물이 아닙니다. 필요한 앱과 라이브러리는 업무마다 다릅니다.

  1. 기존 Claude Code가 정상 작동하는지 확인합니다. 이미 된다면 로그인·모델·API 키를 새로 설정하지 않습니다.
  2. 승인된 Company Agent 직원 ZIP 전체를 풀고 Install-CompanyAgent.cmd를 실행합니다. “Claude 전체”와 “이 프로젝트만” 중 필요한 범위를 선택합니다. 다른 하네스 교체를 선택할 때는 백업과 변경 범위를 먼저 읽습니다.
  3. 설치 후 Claude Code를 다시 엽니다. Workspace는 별도 미리보기 묶음입니다. 그 묶음의 Company-Workspace.vbs를 더블클릭합니다. 관리자 권한은 사용하지 않습니다.
  4. 탐색기에서 새로운 빈 연습 폴더를 만들고 작업 폴더로 선택합니다. 실제 고객 자료·메일·공용 폴더는 연습에 쓰지 않습니다.
  5. 신뢰하는 폴더인지 확인합니다. 이 동의는 모든 후속 행위를 무조건 허용한다는 뜻이 아닙니다.

성공 확인: 앱이 열리고 작업 폴더가 보입니다. 이는 AI 응답·Office 읽기 성공까지 확인한 것은 아닙니다. VBS·PowerShell 실행이 회사에서 제한돼 있으면 담당자에게 승인된 실행 방식을 요청하세요.

원본 CLI를 선호한다면: 기존 방식으로 해당 폴더의 Claude Code를 열고 아래 요청문을 입력합니다. /plugin, /skills, /hooks로 실제 등록을 확인할 수 있습니다. GUI가 이 터미널 메뉴 전부를 그대로 제공하는 것은 아닙니다.

1. 자료 하나 읽기

가지고 있는 파일이 없어도 시작할 수 있습니다. 먼저 가상 자료를 만들고, 다음 요청에서 읽습니다. 생성과 읽기를 나누면 방금 만든 내용을 기억해서 답한 것인지 실제 파일을 읽었는지 비교하기 쉽습니다.

1-1. 준비물 없는 가상 자료 만들기

Office·참고 PPT·회사 자료가 필요 없는 첫 실습입니다. 빈 연습 폴더에서 아래 요청을 보냅니다. 다음 단계에서 쓸 파일은 이것 하나면 됩니다.

온보딩용 가상 자료를 온보딩_가상자료.md 한 파일로 만들어줘.

제목: 온보딩용 월간 실적 (가상 자료)
단위: 건. 6월 목표 100, 실적 90 / 7월 목표 100, 실적 110 / 8월 목표 100, 실적 130.

실제 만든 파일 경로와 계산 확인 결과만 알려줘. 기억이나 회사 지식에는 저장하지 마.

성공 확인: 가상 자료라는 표시와 위 수치·문구를 확인합니다. 이 과정은 파일 쓰기·계산 연습이며 Office 문서 생성 시험은 아닙니다. 작업 폴더가 비어 있다면 하네스가 기본 CLAUDE.md를 만들 수도 있습니다. 이는 업무 결과 파일이 아닌 프로젝트 시작 안내입니다.

성공 확인: 세 달 수치가 맞고 증가 원인을 지어내지 않습니다. 이것만으로 office-reader 사용 성공이라고 기록하지 않습니다.

승인된 가상 PPT·Excel·Word 파일이 이미 있다면 파일 선택으로 원본을 첨부해도 됩니다. 경로를 안다고 원본을 다른 사본으로 바꾸지 않습니다.

원본 파일은 변경하지 마.

막혔을 때: 준비·결과 확인에서 목록을 보고, 필요하면 원본 CLI에서 /company-agent:business-check로 준비물을 확인합니다. Office·승인된 Python 라이브러리·DRM 환경 문제를 하나로 단정하지 않습니다. 없는 라이브러리를 임의로 다운로드하지 않습니다.

8-2. 숫자를 일정하게 계산하는 로컬 도구

이번에는 AI가 매번 계산 코드를 새로 만드는 대신, 입력과 출력이 정해진 작은 도구를 만듭니다. 회사 시스템 연결·MCP·추가 패키지는 필요 없는 예제입니다.

개인 로컬 스크립트 도구 'onboarding-achievement'를 만들어 검증 후 사용할 수 있게 해줘.
먼저 같은 역할의 기존 도구와 이름 충돌을 확인하고, 겹치면 선택을 물어봐줘.
입력은 targets와 actuals라는 길이가 같은 비어 있지 않은 정수 목록이야.
각 값은 0 이상 1,000,000 이하, 항목은 12개 이하로 제한해줘.
출력은 targetTotal, actualTotal, achievementRate야.
달성률은 실적 합계 / 목표 합계 × 100을 소수점 둘째 자리까지 반올림해줘.
목표 합계가 0이면 달성률은 숫자가 아니라 null(계산 불가)로 반환해줘.
빈 목록, 길이 차이, 음수, 문자열·참/거짓 입력, 필수 항목 누락은 오류로 구분해줘.
표준 Python으로만 만들고 외부 통신·임의 파일 읽기/쓰기·다른 프로그램 실행은 하지 마.
정상 시험: targets=[100,100,100], actuals=[90,110,130]이면 합계 300·330, 달성률 110.
반올림 시험: targets=[3], actuals=[1]이면 33.33.
목표 0 시험: targets=[0], actuals=[30]이면 달성률 null.
앞서 정한 잘못된 입력도 실제로 시험해줘. 생성만으로 완료라고 하지 마.
검증 전에는 candidate 상태로 두고, 성공한 검증 기록으로만 활성화해줘.
기존 회사 설정, 개인 스킬, MCP 등록은 변경하지 마.

여기서 파일 읽기/쓰기 제한은 생성된 도구의 업무 동작에 대한 것입니다. 하네스가 개인 도구 소스·시험 입력·검증 기록을 저장하고 승인된 Python 프로세스로 실행하는 단계는 필요합니다. 입력 검증과 시간 제한이 있다고 OS 샌드박스가 생기는 것은 아닙니다.

시험 입력 기대 결과
정상 targets [100,100,100], actuals [90,110,130] 목표 300, 실적 330, 달성률 110
반올림 targets [3], actuals [1] 33.33
목표 0 targets [0], actuals [30] 달성률 null; 0%·무한대라고 하지 않음
잘못된 입력 빈 목록, 길이 차이, 음수, 문자열·참/거짓, 필드 누락 오류; 성공한 계산값으로 꾸미지 않음

확인 순서: 생성된 candidate → 실제 시험 결과와 검증 기록 → 활성화된 호출용 스킬 → 같은 입력 재실행. 현재 도구의 검증 기록은 시험한 코드·설정에 묶이며 모든 수학적 경우나 안전성을 증명하지는 않습니다. 코드를 바꾸면 재시험해야 합니다. 이번 연습은 AI에게 최종 수치 검증을 생략하도록 하는 것이 아닙니다.

선택: 교육 담당자가 코드와 입력을 직접 검증할 때

아래는 위 조건의 최소 계산 예제입니다. 안내서를 열어도 실행되지 않으며, 전체 AssetSpec이나 CLI 명령이 아닙니다. 자산 생성기는 별도로 입력·출력 스키마를 구성합니다. 연습 검사는 이 코드와 입력을 임시 저장소에서 사용하며 실제 개인 설정을 바꾸지 않습니다.

import json
import sys

payload = json.load(sys.stdin)
if not isinstance(payload, dict) or set(payload) != {"targets", "actuals"}:
    raise ValueError("targets and actuals are required")
targets, actuals = payload["targets"], payload["actuals"]
for values in (targets, actuals):
    if not isinstance(values, list) or not 1 <= len(values) <= 12:
        raise ValueError("provide 1 to 12 values")
    if any(type(value) is not int or not 0 <= value <= 1000000 for value in values):
        raise ValueError("values must be nonnegative integers up to 1000000")
if len(targets) != len(actuals):
    raise ValueError("list lengths must match")
target_total, actual_total = sum(targets), sum(actuals)
rate = round(actual_total / target_total * 100, 2) if target_total else None
json.dump({"targetTotal": target_total, "actualTotal": actual_total,
           "achievementRate": rate}, sys.stdout, ensure_ascii=False)

8-3. 언제 팀에 나누고, 어떻게 정리하나요?

개인 스킬·도구를 만들었다고 회사 전체에 배포되는 것은 아닙니다. 팀에 유용하다면 목적, 입력·출력, 정상/실패 시험, 권한·준비물, 담당자를 정리하고 민감 내용이 없는 소스만 담당자에게 검토 요청합니다. 회사 공통 반영은 별도 배포 작업입니다. 검증 기록을 다른 PC에 복사해 활성화를 대신하지 않습니다.

정리: 현재 온보딩에는 개인 자산 전체를 한 번에 삭제하는 버튼을 추가하지 않았습니다. 생성된 파일·등록·참조를 먼저 조회해 이번에 만든 이름만 정리할 계획을 받으세요. 실제 정리는 범위를 확인한 뒤 진행하고, 승인된 정리 방법이 없으면 유지합니다. 설치 캐시 수정·기존 스킬 비활성화·MCP 초기화로 충돌을 피하지 않습니다.

막혔을 때: 스킬 목록, 본문 로드, 도구 시험, 활성화를 나눠 확인합니다. 준비물이 없으면 설치를 추측해 진행하지 않습니다. MCP가 필요하지 않은 계산에 MCP 서버를 추가하거나, 연습을 이유로 전체 후크를 끄지 않습니다.

8-4. 선택 실습: 전사와 같은 형식으로 MCP 만들기

회사 표준으로 개발해 나중에 전사 플랫폼에 제출하려면 **company-agent:platform-mcp-builder**를 사용합니다. 일반 개인용 stdio MCP를 만드는 asset-factory와 목적이 다릅니다. 이 개발 스킬은 회사 공통이며, 연습 결과는 회사 공통 배포본이 아닌 내가 지정한 개발 폴더에 저장됩니다.

전사 표준 tools.py / register_tools 형식으로 MCP를 개발하고 싶어.
이 프로젝트에서만 연습할 거야. 새 개발 폴더는 [실제 절대 경로]야.
먼저 합성 한글 문자열을 되돌려 주는 예제로 로컬 시험까지 진행해줘.
MCP 연결 등록, 인터넷 패키지 설치, 회사 플랫폼 업로드는 하지 마.

만들어지는 것: src/mcp/tools.py가 업무 코드입니다. 함께 제공하는 config.py·local_server.py·requirements-local.txt는 로컬 시험 전용이며 전사 파일을 교체하지 않습니다. test_tools.py는 실제 MCP SDK로 목록·입출력·실패 입력을 확인합니다. 기존 폴더를 덮어쓰지 않습니다. Python과 승인된 SDK 1.x 환경이 없으면 준비물을 안내하며 자동 설치하지 않습니다.

이렇게 되면 성공: 한글 응답이 원래 입력과 같고, 잘못된 입력은 오류로 구분되며, 검사한 코드 경로와 결과를 확인할 수 있습니다. 이 기본 검사는 포트를 열지 않는 로컬 HTTP 전송 시험입니다. 사용자가 별도 연결 시험을 요청하면 내 PC의 127.0.0.1에만 서버를 열어 확인합니다. 소스가 생성됐다고 CLI에 MCP가 등록되거나 다른 프로젝트에서 자동 사용되는 것은 아닙니다.

전사에 전달할 때: 기본 제출물은 src/mcp/tools.py와 추가 의존성·필요한 설정 항목명·사용 예제·시험 결과입니다. 업무용 보조 모듈이 있다면 목록을 함께 냅니다. 로컬 설정, 비밀값, 개인 기억, 개발 환경은 제외합니다. 담당자가 실제 전사 SDK·인증·권한을 검증한 뒤 배포합니다. “로컬 시험 통과”와 “전사 배포 완료”는 다릅니다. Markdown 스킬도 공유할 수 있지만 필요한 상대 참조 파일까지 포함하고, 개인 경로나 하네스 전용 호출을 그대로 전사에 적용하지 않습니다.

9. 사용량과 결과 확인하기

사용 현황 · 결과 확인을 엽니다. 토큰이 미제공이면 0으로 해석하지 않습니다. 실행 구간과 질문·승인 대기를 구분하고 CLI 보고값을 무조건 요청별로 합산하지 않습니다.

준비·결과 확인에서 내용·범위·파일을 직접 확인한 뒤 통과/실패/미확인/중지를 기록합니다. 스킬 목록의 개수나 준비물 점수가 실제 업무 정확도를 대신하지 않습니다. 확인 기록 내보내기는 자동 전송하지 않으며, 기록 비우기는 대화·기억·결과 파일 삭제와 다릅니다.

성공 확인: 확인하지 않은 항목은 미확인으로 남고, 같은 예제로 재시험할 때 전후 결과를 비교할 수 있습니다. 일반 업무를 위해 매번 진단 화면을 열 필요는 없습니다.

10. 화면 조작은 필요할 때만 시험하기

Workspace의 업무 도우미에서 화면 조작 시험을 선택합니다. 설치 후보·현재 연결 확인은 파일 후보와 이미 실행 중인 CLI의 보고만 읽습니다. Cua를 설치하거나 MCP를 연결하거나 화면을 캡처하지 않습니다.

Driver 미발견이나 연결 미표시는 정상적인 미준비 상태일 수 있습니다. 준비와 회사 승인이 끝났다면 Cua Driver 시험 안내의 계산기 관찰 → 계획 확인 → 작은 입력 → 실제 결과 확인 순서로 시험합니다. 해당 도구를 관찰하지 못했으면 앱은 실행 예문 버튼을 제공하지 않습니다.

3. 보고서·HTML·편집 가능한 PPT

먼저 디자인·분량·결과 형식을 정합니다. HTML은 새 디자인 또는 참고 HTML, PPT는 새 디자인·참고 캡처 2~3장·기존 PPT·저장한 HTML 양식 중 필요한 방식을 사용합니다. 새 디자인에서는 참고 파일을 요구하지 않습니다.

가상 월간 실적으로 짧은 HTML 보고서를 만들어줘.
6월 목표 100건·실적 90건, 7월 목표 100건·실적 110건, 8월 목표 100건·실적 130건.

최종 HTML 한 파일만 전달하고 기존 파일은 덮어쓰지 마.

PPT는 전체 HTML 초안 → 사용자 확인 → 편집 가능한 PPT → 실제 결과 확인 순서입니다. 카드·둥근 모서리·그림자·태그는 지원하지만 임의의 웹 화면을 모두 동일하게 변환하지는 않습니다. 정적 HTML 배치 변환에는 로컬 Chrome/Edge와 python-pptx가 필요하며 소스 스크립트는 실행하지 않습니다. 복잡한 효과·동적 내용·병합 표 등은 제한을 확인합니다. CSS 막대 도형과 수치 편집이 가능한 네이티브 차트도 구분합니다.

HTML 초안·변환 시도·검사 이미지는 내부 임시 작업 공간에 두고 한 요청에서는 최종 결과 한 개가 기본입니다. 여러 결과를 명시적으로 요청하거나 다음 질문에서 다른 형식을 요청하면 별도로 생성할 수 있습니다. 기존 결과는 자동 삭제하지 않습니다.

7. 겹치는 스킬과 프로젝트 지침

스킬 이름을 외우지 않고 업무부터 요청합니다. 사용 가능한 목록에 관련 스킬이 있으면 본문을 읽어 적용하고, 없으면 일반 작업을 합니다. 같은 역할이 여럿이고 우선 선택이 없으면 실제 이름·출처·차이를 질문합니다. 이번 선택과 지속적인 우선 설정 저장은 별개입니다. 없는 스킬을 설치하거나 추측 이름 company로 실행하지 않습니다.

목록 확인·단순 파일 탐색마다 오류를 내는 방식은 아닙니다. 실제 관련 후보 본문을 건너뛴 실행에는 짧은 [스킬 확인] 교정이 한 번 보일 수 있습니다. 해당 도구는 아직 실행되지 않았고 파일 권한 오류도 아닙니다. 정확한 본문을 로드한 뒤 진행합니다. 회사 정책·도구 권한은 별도로 적용됩니다.

새 작업 폴더에서 실제 작업 요청을 하면 조건에 따라 기본 CLAUDE.md를 한 번 생성합니다. 기존 지침·상위 지침은 보존하며 계획/변경 금지 요청이나 시스템·설정 폴더에는 만들지 않습니다. 이는 짧은 시작 안내이며 CLI /init의 프로젝트 분석을 실행하는 것은 아닙니다. 프로젝트 지침은 목적·단위·완료 기준부터 짧게 유지하세요.

Workspace 기억·하네스 관리 → 개인 전체 / 이 프로젝트 → 기억·지식 → 내 기억 추가 → 변경안 확인 → 확인하고 저장 순서입니다. 제목과 짧은 선호만 적고 원본 문서·계정 정보는 넣지 마세요. 사용 안 함, 수정, 이전 내용 복원안을 지원합니다. 저장 위치와 적용 범위가 같아야 새 대화에서도 비교할 수 있습니다. Claude Code 자체 자동 기억은 별도 관리하며 자동으로 합치거나 덮어쓰지 않습니다.

앞으로 내 보고서는 결론부터 짧게 설명하고 확인한 범위와 미확인 부분을 구분해줘.
이 표현 선호만 개인 기억에 저장하고 문서 본문은 저장하지 마.

자동 학습은 User 설치에서는 개인 전체, Project 설치에서는 해당 설치 저장소에서만 작동합니다. 명시적 저장 범위 선택은 학습 설정을 바꾸지 않습니다. 의미 있는 업무 완료 시 조건을 확인해 선호나 실제 읽은 개인 스킬의 제한된 점검 항목을 개선하며 User 설치의 프로젝트 전용 자산은 자동 수정하지 않습니다. 모든 교정을 즉시 영구 저장하는 것은 아닙니다. 공통 자료·회사 정책·프로젝트 CLAUDE.md를 자동 수정하지 않습니다. 원하지 않으면 내 기억 화면에서 자동 학습을 끄고 내역을 확인하세요. 끄기와 기존 기억 삭제는 다른 일입니다.

출처가 있는 용어·계산식은 같은 화면의 내 업무 지식 초안에서 저장하고, 직접 검토 후 사용으로 바꿉니다. 개인 초안을 만들었다고 공통 기억이 바뀌지 않습니다. 공통 기억 검토용 내보내기는 로컬 ZIP 생성이며 자동 업로드·회사 반영이 아닙니다. 전달 전 민감 내용을 검토하세요. 공통 자료로의 반영은 담당자의 검토·배포 단계입니다.

공통 하네스는 회사 업무 기준·공통 스킬·후크 정의를 확인하는 화면입니다. 목록이 있다는 사실과 현재 CLI에서 실제 실행됐다는 사실은 다릅니다. 화면에 수정·삭제 버튼을 두지 않으며 개인 선호로 회사 필수 기준을 해제하지 않습니다.

같은 화면의 이 폴더에만 적용할 업무 지침에 목표·입력·결과물·완료 기준을 적습니다. 저장 파일은 .claude/rules/company-workspace-brief.md이며 기존 CLAUDE.md와 다릅니다. 기존 또는 직접 수정한 지침은 덮어쓰지 않습니다. 회사 공통 규정을 개인 폴더에 복사해 별도 정책 계층으로 만들 필요는 없습니다.

  2. 디자인·양식 등 이미 답한 내용은 유지해 달라고 요청합니다.
  3. 새 주제는 새 대화로 나누고, 긴 자료는 필요한 범위부터 읽습니다.
  4. 표시 인코딩만 깨졌다면 파일 생성·발송 등 원래 업무부터 반복하지 않습니다.
  5. 화면 조작보다 기존 Office·전용 도구가 적합하면 그것을 먼저 사용합니다.

새 폴더의 기본 CLAUDE.md 생성은 3장의 조건에서 지원합니다. /revise-claude-md라는 별도 명령, 업무 종료마다 강제 /compact, 자동 후속 질문 전송은 제공하지 않습니다. 개인 자동 학습과 CLI 자체 대화 압축은 프로젝트 지침의 자동 수정이나 공통 기억 공유가 아닙니다. 대화 압축과 기억 저장은 다른 일입니다.

Workspace 사용 현황은 CLI가 실제 제공한 토큰과 앱이 관찰한 실행·질문·승인 대기를 구분합니다. 빠진 값은 0이 아니라 미제공입니다. 요청 값이 세션 누적일 수 있으므로 서로 더하지 않습니다. 사내 모델 단가를 모르면서 청구 금액이나 절감률을 만들지 않습니다.

토큰 알림은 다음 요청부터의 안내이며 강제 예산 제한이 아닙니다. 과거 로그 분석은 사용자가 고른 파일만 대상으로 하며 자동으로 대화 전체를 검색하지 않습니다. 준비·결과 확인의 평가는 사용자가 직접 확인해 기록한 표본이지 모델 전체 성능 점수가 아닙니다.

명령은 메시지 맨 앞에 입력합니다. 현재 사용 가능한 항목은 계정·플랫폼·버전마다 다릅니다. 공식 명령 안내

Company Agent가 제공하는 명령은 /company-agent:skills, /company-agent:learning, /company-agent:business-check입니다. 각각 스킬 선택, 자동 학습 관리, 업무 준비 확인 용도입니다. 진단 성공은 실제 Office·메일·DB 작업의 성공이 아닙니다. /revise-claude-md는 이 하네스에 포함되지 않습니다.

3. 작업 중 다음 질문과 제안 문장

실행 중 보낸 메시지는 대기하다가 도구 실행 경계 등에 전달될 수 있습니다. ‘지금 작업을 보완’하는지 ‘다음 업무’인지 명확히 적으세요. 반드시 완료 후 시작해야 한다면 결과를 받은 다음 보냅니다. Tab은 다음 업무를 예약하는 키가 아닙니다.

현재 요청 보충: 원본을 보존하고 실제 확인한 범위만 알려줘.

입력칸에 제안 문장이 보이는 것과 메시지를 전송하는 것은 다릅니다. 제안은 CLI·조직 설정에 따라 없을 수 있고, Company Agent가 자동으로 후속 질문을 보내지는 않습니다. 공식 실행 중 메시지·제안 안내

4. 압축·기억·프로젝트 지침은 다른 일

큰 작업이 끝났다고 매번 압축할 필요는 없습니다. 먼저 결과 파일과 남은 일을 확인합니다. 대화가 길어졌을 때 원본 CLI에서 아래처럼 중요한 조건을 남길 수 있습니다.

/compact 현재 목표, 원본 보존 조건, 최종 파일 경로, 검증한 범위와 미확인 사항을 남겨줘

압축에도 처리가 필요하며 비용 절감률을 보장하지 않습니다. 회사 모델의 자동 압축 지원은 운영 환경에서 확인합니다. 이 하네스는 매 작업 후 강제 /compact를 실행하지 않습니다. 공식 대화 관리

Claude의 CLAUDE.md와 자동 기억은 대화 요약과 다릅니다. Company Agent 개인 기억도 별도입니다. 기본 CLAUDE.md 자동 생성은 짧은 시작 안내이며 /init의 코드 분석을 대신하지 않습니다. 자동 학습 역시 프로젝트 지침을 몰래 고치는 기능이 아닙니다. 공식 기억 안내

5. 되돌리기·여러 세션·종료

원본 CLI의 /rewind는 되돌릴 대상을 확인하는 메뉴입니다. 모든 외부 작업·명령 실행·메일 발송을 취소하는 기능은 아닙니다. 중단 후에는 실제 파일과 실행 기록을 먼저 확인하세요. 공식 되돌리기 한계

서로 독립적인 업무만 별도 폴더·대화로 나눕니다. 같은 파일을 동시에 수정하면 충돌할 수 있습니다. 하나의 회사 계정 사용량이 세션별로 독립되는 것도 아닙니다. 폴더 간 이동과 새 대화는 기억·권한 범위를 다시 확인할 기회입니다.

터미널에서 다시 시작할 때 claude는 새 실행, claude --continue는 최근 대화 이어가기 용도로 사용할 수 있습니다. 인증은 기존 회사 안내를 따릅니다. 이 명령들은 대화 입력칸의 슬래시 명령과 다릅니다. 공식 CLI 실행 옵션

Workspace는 전원 버튼으로 종료하며 창의 X만 닫으면 서버가 남을 수 있습니다. 기본 가이드 열기·문서 검색·인쇄는 AI 호출이나 설정 변경이 아닙니다. 복사한 요청문을 실제 대화에 보냈을 때만 업무가 시작됩니다.

Cua Driver 가능성 확인 안내

API 없이 화면으로만 쓰는 프로그램을 조작할 수 있을지, 작은 가상 업무로 확인합니다.

현재 제공하는 것은 실행 없는 준비 확인 + 사용자가 보내는 시험 예문입니다. Driver 자동 설치·MCP 자동 등록·권한 변경·자동 화면 조작은 구현하지 않았습니다. 실제 사내 HCP·회사 프로그램의 성공은 미검증입니다.

1. 무엇이 추가됐나요?

Workspace → 첫 업무 따라 하기 또는 내 업무 방식 → 화면 조작 시험에서 확인합니다.

확인 항목 확인 근거 증명하지 않는 것
Driver 파일 후보 명시한 절대 경로 또는 상속한 PATH의 제한된 경로 정품·버전·실행 가능·전체 PC 설치 여부
MCP 연결 살아 있는 현재 CLI의 초기 연결 보고 설치 파일과 같은 Driver인지, 계속 정상인지
읽기·입력 도구 같은 MCP 이름의 실제 보고된 도구 목록 실제 권한·업무 성공·모델 이미지 이해
실제 결과 사용자가 요청한 시험 후 직접 관찰 모든 프로그램·DRM·무인 운영 호환성

화면을 여는 것만으로 PC를 조사하지 않습니다. 확인 버튼을 누를 때만 경로와 현재 보고를 확인합니다. 모델 호출, 새 CLI 실행, 프로세스 실행, 화면/인증 정보 수집, 개인 설정 변경, 결과 디스크 저장을 하지 않습니다. 오래된 대화 기록은 현재 연결 증거로 사용하지 않습니다. 체험 모드는 실제 준비 상태도 조사하지 않습니다.

2. 회사 담당자의 사전 준비

  1. 대상 Windows 프로그램과 데이터 처리 범위를 승인합니다. 처음에는 계산기만 사용합니다.
  2. 공식 Driver의 고정 버전·출처·해시를 검토하고 사내 승인 경로로 준비합니다. 이 프로젝트의 직원 ZIP에는 Cua 실행 파일을 넣지 않습니다.
  3. 기존 Claude 실행·설정 범위를 확인하고 그 범위에만 MCP를 별도로 등록합니다. 개인 모델·인증·다른 MCP·스킬을 초기화하지 않습니다. Windows MCP 등록은 공식 안내의 cua-driver mcp 연결 방식입니다.
  4. 기본 standard 모드는 여러 앱에 입력할 수 있으므로, 앱·도구·경로가 제한된 bounded 구성과 승인된 manifest를 검토합니다. 이는 PC 전체를 격리하는 샌드박스가 아닙니다.
  5. 시작 전에 사용 통계와 별도 업데이트 확인을 검토합니다. 필요하면 MCP 프로세스 환경에 CUA_DRIVER_RS_TELEMETRY_ENABLED=false, CUA_DRIVER_RS_UPDATE_CHECK=false를 설정합니다. 앱이 대신 바꾸지는 않습니다.
  6. 화면·도구 결과가 기존 Claude/HCP 모델로 전달되는 범위를 확인합니다. 로컬 Driver라고 모델 처리까지 오프라인인 것은 아닙니다.
  7. 실제 사용할 스킬을 파일로 등록할지 검토합니다. MCP의 원격 skill 리소스가 Claude의 시작 스킬 목록에 자동 등록되는 것은 아닙니다. 스킬만 설치해도 Driver가 생기는 것은 아닙니다.

Windows의 bounded MCP는 런타임 소유 프로세스의 CUA_DRIVER_PERMISSION_MODE, CUA_DRIVER_CAPABILITY_MANIFEST_FILE, CUA_DRIVER_CAPABILITY_MANIFEST_APPROVED 또는 별도 승인된 daemon 연결로 구성합니다. 승인 표시는 담당자가 검토한 정확한 manifest에만 적용해야 합니다. 모델에게 권한 확대를 맡기지 않습니다.

브라우저의 허용 사이트 제한과 일반 데스크톱 입력은 같은 정책이라고 가정하지 마세요. 공식 문서는 사이트 제한 브라우저와 일반 앱 조작에 별도 런타임·범위를 요구합니다. 범용 클릭이 브라우저까지 닿으면 사이트 제한의 의미가 사라질 수 있습니다.

공식 근거: Claude Code 연결, 스킬 등록, 범위 제한, 통계와 업데이트. 확인일 2026-09-19. 버전별 차이는 도입 시 다시 확인합니다.

3. 준비 확인 화면 읽는 법

  • 파일 후보 발견: 파일이 있다는 뜻입니다. 버전 검사 명령도 실행하지 않았습니다.
  • 미발견: 제한된 PATH 또는 지정 경로에서 못 찾았다는 뜻입니다. 다른 설치 위치를 자동 검색하지 않습니다.
  • 현재 CLI 연결 보고 없음: 아직 요청을 보내지 않았거나 연결이 종료됐을 수 있습니다. 준비 확인만 위해 AI 요청을 자동으로 보내지 않습니다.
  • 연결됨으로 보고: CLI의 초기 보고를 관찰했습니다. Driver 기능을 실행해 시험한 것은 아닙니다.
  • 도구 미확인: 도구 목록이 지연 노출되거나 버전·프로필에 따라 이름이 다를 수 있습니다. 없는 도구를 추측해 실행하지 않습니다.
  • 여러 후보: 사용할 MCP 이름 하나를 입력합니다. cua-driver, cua-computer-use, cua를 기본 후보로 보며 사용자 지정 이름은 현재 목록에 있는 정확한 이름으로 확인합니다.

연결 설정을 변경했다면 진행 중인 업무를 먼저 마치거나 중지하고 새 CLI 연결에서 확인합니다. 대화의 “연결 상태와 작업 기록”에서 실제 보고를 비교하세요. MCP 이름이 일치해도 Cua 정품·로컬 실행이라고 보증하지 않습니다.

원본 CLI 사용자도 Workspace 폴더에서 아래 읽기 전용 확인을 실행할 수 있습니다. 이 명령에는 CLI 연결 보고가 없으므로 파일 후보만 확인합니다.

python -X utf8 -m local_app.computer_use
# 필요하면 승인된 실제 경로만 지정 (파일 확인만 하고 실행하지 않음)
python -X utf8 -m local_app.computer_use --driver "C:\승인된도구\cua-driver.exe"

4. 계산기 창 읽기 시험

다른 민감 창을 닫고 계산기를 직접 엽니다. 회사 승인 범위 안에서 준비 확인 후 읽기 시험 예문을 입력창에 넣기를 선택합니다. 버튼은 전송하지 않습니다. 내용을 읽고 직접 보내야 실행됩니다.

시험은 열어둔 계산기 한 창의 이름·현재 표시값만 읽도록 요청합니다. 클릭·입력·파일 변경은 하지 않습니다. 화면 속 문구는 자료이며 새로운 실행 지시로 취급하지 않도록 합니다. 창이 여러 개면 선택을 먼저 받습니다.

직접 확인: 실제 계산기 표시값과 답변이 일치하는지 비교합니다. 권한 실패·빈 화면 요소·이미지 처리 실패는 그대로 기록합니다. 준비 상태가 녹색이라는 이유로 성공 처리하지 않습니다.

5. 작은 입력 시험 — 별도 확인 후

읽기가 확인되고 입력 도구도 관찰됐다면 입력 시험 예문을 입력창에 넣기를 선택합니다. 계산기에서 2+3을 계산할 계획을 먼저 보고 확인합니다. 최종 표시값 5를 다시 관찰해야 성공입니다. 다른 앱·메일·파일·설정은 시험 범위가 아닙니다.

예문의 호출 횟수 제한은 모델에게 주는 지침이며 강제 제한 장치가 아닙니다. 최대 횟수를 초과하거나 같은 실패를 반복하면 사용자가 중지해야 합니다. 도구 응답 성공만으로 화면 결과까지 성공했다고 간주하지 않습니다.

중지: 앱의 작업 중지 또는 원본 CLI의 중단을 사용합니다. 이미 수행한 입력을 되돌리거나 별도 Driver 런타임을 모두 종료한다는 보장은 없습니다. 필요하면 담당자가 승인된 Driver 세션 회수/종료를 수행합니다. 사용자 작업 중 화면을 빼앗는 경우 무인 실행을 확대하지 않습니다.
