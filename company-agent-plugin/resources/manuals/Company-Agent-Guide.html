01

Company Agent 시작하기

명령어 암기보다 작은 업무 하나를 맡기고 직접 확인하는 연습입니다.

처음에는 1단계: 가상 자료 만들고 읽기만 해보세요. 회사 자료나 참고 파일은 필요 없습니다. 익숙해지면 보고서 만들기, 기억 저장, 내 스킬 만들기로 이어갈 수 있습니다. 필요한 단계만 골라 진행하세요.

먼저 세 범위만 구분하세요. 회사 공통 / 개인 전체 / 이 프로젝트 안에서 기억·지식과 업무 구성을 확인합니다.

구분 쉬운 예 내가 할 수 있는 일
회사 공통 배포 지식·회사 기준·공통 스킬·후크 읽기, 담당자에게 수정 제안
개인 전체 여러 프로젝트에서 사용할 선호·지식·개인 자산 범위 선택 후 저장·수정·사용 중단
이 프로젝트 이 업무에서만 사용할 기억·스킬·도구·지침 개인 자산과 공유 프로젝트 파일을 구분해 관리

새로 저장할 때는 두 선택지입니다. 개인 전체(여러 프로젝트) / 이 프로젝트(현재 작업에서만). 범위를 말하지 않았다면 한 번 질문하고 답변을 기다립니다. 이미 명시했다면 다시 묻지 않습니다. 회사 공통은 직접 저장하지 않습니다. ‘전역’이라고 모두에게 공유되지 않고 폴더에 있다고 모두 개인 소유도 아닙니다. 프로젝트 개인 자료는 로컬 개인 저장소에 있어 폴더 공유만으로 전달되지 않습니다.

실제 위치는 기억·하네스 관리 → 구성 한눈에에서 확인합니다. 회사 공통은 연결된 배포본, 개인 기억·자산은 선택한 로컬 저장소, 폴더 지침은 프로젝트 파일입니다. Claude 자체 자동 기억은 Company Agent 기억과 별도입니다. 기본 스킬 11개와 후크 7개의 역할·한계는 핸드북 4~5장에서 확인할 수 있습니다.

단계 고르기: 0–5는 첫 업무, 6은 공통 기억·내 기억 비교, 7은 폴더별 적용 범위 비교, 8은 내 스킬·도구 만들기입니다. 생성·저장 예문을 보내면 실제 파일이나 기억이 생기므로, 실습 후 정리 방법도 확인하세요.

0. 준비하기

회사에서 사용을 승인한 Claude Code와 Python 3.11 이상이 필요합니다. 회사 모델·인증서·로그인 설정은 조직 안내를 따릅니다. Node.js·Git은 모든 직원 업무의 필수 준비물이 아닙니다. 필요한 앱과 라이브러리는 업무마다 다릅니다.

  1. 기존 Claude Code가 정상 작동하는지 확인합니다. 이미 된다면 로그인·모델·API 키를 새로 설정하지 않습니다.
  2. 승인된 Company Agent 직원 ZIP 전체를 풀고 Install-CompanyAgent.cmd를 실행합니다. “Claude 전체”와 “이 프로젝트만” 중 필요한 범위를 선택합니다. 다른 하네스 교체를 선택할 때는 백업과 변경 범위를 먼저 읽습니다.
  3. 설치 후 Claude Code를 다시 엽니다. Workspace는 별도 미리보기 묶음입니다. 그 묶음의 Company-Workspace.vbs를 더블클릭합니다. 관리자 권한은 사용하지 않습니다.
  4. 탐색기에서 새로운 빈 연습 폴더를 만들고 작업 폴더로 선택합니다. 실제 고객 자료·메일·공용 폴더는 연습에 쓰지 않습니다.
  5. 신뢰하는 폴더인지 확인합니다. 이 동의는 모든 후속 행위를 무조건 허용한다는 뜻이 아닙니다.

성공 확인: 앱이 열리고 작업 폴더가 보입니다. AI 응답과 실제 업무 결과는 다음 단계에서 확인합니다. VBS·PowerShell 실행이 회사에서 제한돼 있으면 담당자에게 승인된 실행 방식을 요청하세요.

원본 CLI를 선호한다면: 기존 방식으로 해당 폴더의 Claude Code를 열고 아래 요청문을 입력합니다. /plugin, /skills, /hooks로 실제 등록을 확인할 수 있습니다. GUI가 이 터미널 메뉴 전부를 그대로 제공하는 것은 아닙니다.

1. 자료 하나 읽기

가지고 있는 파일이 없어도 시작할 수 있습니다. 먼저 가상 자료를 만들고, 다음 요청에서 읽습니다. 생성과 읽기를 나누면 방금 만든 내용을 기억해서 답한 것인지 실제 파일을 읽었는지 비교하기 쉽습니다.

1-1. 준비물 없는 가상 자료 만들기

Office·참고 PPT·회사 자료가 필요 없는 첫 실습입니다. 빈 연습 폴더에서 아래 요청을 보냅니다. 다음 단계에서 쓸 파일은 이것 하나면 됩니다.

요청 예문선택 후 Ctrl+C로 복사
실습용 가상 자료를 실습_가상자료.md 한 파일로 만들어줘.
회사 시스템·메일·다른 파일을 조회하지 말고 다음 내용만 사용해줘.
제목: 실습용 월간 실적 (가상 자료)
단위: 건. 6월 목표 100, 실적 90 / 7월 목표 100, 실적 110 / 8월 목표 100, 실적 130.
목표 합계 300, 실적 합계 330, 누적 달성률 110%를 계산해서 대조해줘.
가상 회의 메모: 점검표 수정 완료. 현장 확인 진행 중. 새 양식 적용일은 미정.
가상 비교 문구: 이전안은 월 1회 점검, 변경안은 월 2회 점검. 그 외 조건은 동일.
원인·연도·실제 사람 이름은 추가하지 마. UTF-8로 저장해줘.
같은 이름의 파일이 있으면 덮어쓰지 말고 기존 파일을 사용할지 먼저 물어봐줘.
실제 만든 파일 경로와 계산 확인 결과만 알려줘. 기억이나 회사 지식에는 저장하지 마.

성공 확인: 가상 자료라는 표시와 위 수치·문구를 확인합니다. 이 과정은 파일 쓰기·계산 연습입니다. 작업 폴더가 비어 있다면 하네스가 기본 CLAUDE.md를 만들 수도 있습니다. 이는 업무 결과 파일이 아닌 프로젝트 시작 안내입니다.

1-2. 만든 파일을 실제로 읽어 보기

요청 예문선택 후 Ctrl+C로 복사
방금 만든 실습_가상자료.md 파일을 실제로 읽고 핵심 내용과 확인할 사항을 정리해줘.
다른 이름으로 저장됐다면 앞서 확인한 실제 경로만 사용해줘.
대화에 있는 수치를 그대로 답하지 말고 파일을 읽은 범위를 알려줘.
자료에 없는 이유는 추측하지 마. 원본 파일·설정·기억은 변경하지 마.

CLI에서는 @로 실제 파일을 고르고, Workspace에서는 파일 선택으로 첨부해도 됩니다. 파일을 만들고 싶지 않거나 쓰기 권한이 없다면 아래 텍스트 연습만 해도 됩니다.

요청 예문선택 후 Ctrl+C로 복사
다음 가상 자료를 요약해줘.
6월 목표 100건·실적 90건, 7월 목표 100건·실적 110건, 8월 목표 100건·실적 130건.
자료에 없는 이유는 추측하지 마. 실제 확인한 범위와 미확인 부분을 알려줘.
이 작업은 대화에 입력한 텍스트를 요약하는 연습이야.

성공 확인: 세 달 수치가 맞고 증가 원인을 지어내지 않습니다. MD 파일을 지정했다면 실제 파일 내용과 읽은 범위를 대조합니다. 대화에 붙여 넣은 텍스트만 사용했다면 파일을 읽었다고 기록하지 않습니다.

막혔을 때: 파일 경로와 읽기 권한을 확인합니다. 파일을 만들거나 읽을 수 없다면 위 텍스트 예문으로 연습합니다.

2. 결과 만들기

요청 예문선택 후 Ctrl+C로 복사
가상 월간 실적으로 HTML 보고서를 만들어줘.
6월 목표 100건·실적 90건, 7월 목표 100건·실적 110건, 8월 목표 100건·실적 130건.
먼저 새 디자인 또는 내가 첨부할 기존 양식을 선택하게 해줘.
내 답변을 기다린 뒤 제작해줘. 합계와 달성률을 검증하고 기존 파일은 덮어쓰지 마.

저장 범위와 자동 학습을 함께 시험하기

  1. A 폴더에서 “가상 보고서에 연습-A라고 표시하는 선호를 기억해줘”라고 요청합니다. 개인 전체 / 이 프로젝트 질문이 나오면 이 프로젝트를 선택합니다. 회사 공통을 저장 대상으로 제시하면 잘못된 동작입니다.
  2. 같은 사용자 설치의 B 폴더에서 새 대화를 열고 기억을 조회합니다. A 전용 기억은 나오지 않아야 합니다. A에서는 다시 조회되어야 합니다. 실제 저장·조회와 모델 답변 반영은 각각 확인합니다.
  3. 별도의 가상 선호를 “개인 전체에 저장해줘”라고 요청합니다. 재질문 없이 해당 범위에 저장하고 A/B에서 조회되는지 확인합니다. 프로젝트 지침·회사 원본은 바뀌지 않아야 합니다.
  4. 스킬 만들기도 같은 범위 선택을 사용합니다. “이 프로젝트에 저장할 월간 요약 스킬”처럼 명시하면 범위 질문을 반복하지 않습니다. 기존 항목 수정은 원래 범위이며 자동 이동하지 않습니다.

선택: 교육 담당자가 코드와 입력을 직접 검증할 때

아래는 위 조건의 최소 계산 예제입니다. 안내서를 열어도 실행되지 않으며, 전체 AssetSpec이나 CLI 명령이 아닙니다. 자산 생성기는 별도로 입력·출력 스키마를 구성합니다. 연습 검사는 이 코드와 입력을 임시 저장소에서 사용하며 실제 개인 설정을 바꾸지 않습니다.

입력 예시선택 후 Ctrl+C로 복사
import json
from mcp.server.fastmcp import FastMCP
from pydantic import StrictInt

def register_tools(mcp: FastMCP) -> None:
    @mcp.tool()
    async def achievement(targets: list[StrictInt], actuals: list[StrictInt]) -> str:
        """최대 12개 가상 실적의 합계와 달성률을 계산합니다."""
        for values in (targets, actuals):
            if not 1 <= len(values) <= 12:
                raise ValueError("provide 1 to 12 values")
            if any(not 0 <= value <= 1000000 for value in values):
                raise ValueError("values must be between 0 and 1000000")
        if len(targets) != len(actuals):
            raise ValueError("list lengths must match")
        target_total, actual_total = sum(targets), sum(actuals)
        rate = round(actual_total / target_total * 100, 2) if target_total else None
        return json.dumps({"targetTotal": target_total, "actualTotal": actual_total,
                           "achievementRate": rate}, ensure_ascii=False)

Claude Code 기본 사용법

Claude Code가 처음인 분을 위한 설명입니다. 명령어를 외우기 전에 어느 폴더에서, 어떤 자료로, 무엇을 만들지 정하면 됩니다. 작은 실습은 시작하기, 키와 명령은 명령어·단축키에서 확인하세요.

1. Claude Code와 Company Agent는 무엇이 다른가요?

Claude Code는 요청을 이해하고 파일 읽기·수정·명령 실행 같은 도구를 사용할 수 있는 프로그램입니다. 대화만 하는 것과 달리 실제 파일이나 외부 시스템에 영향을 줄 수 있습니다. 실행할 수 있는 범위는 연결된 도구와 권한에 따라 달라집니다. 공식 소개

구분 하는 일
AI 모델 요청을 해석하고 답이나 작업 계획을 만듭니다. 사내에서는 승인된 모델을 사용합니다.
Claude Code 모델과 대화하면서 파일·명령·도구를 연결합니다.
Company Agent 회사 기준, 업무 스킬, 기억 관리, 실행·결과 확인 절차를 더합니다. 별도의 AI 계정을 만드는 기능은 아닙니다.
Workspace 기존 Claude Code를 사용하는 별도 입력·파일 선택·확인 화면입니다. 원본 CLI의 모든 메뉴와 단축키가 같은 것은 아닙니다.

이미 회사 환경에서 Claude Code가 된다면 개인 API 키·모델·로그인을 새로 설정하지 않습니다. 연결 문제를 해결하려고 기존 설정 전체를 초기화하지 마세요.

2. 작업 폴더부터 확인하세요

작업 폴더는 이번 업무의 출발점입니다. 처음에는 빈 연습 폴더를 사용하고 회사 문서·메일·공용 폴더는 넣지 않습니다. CLI·VS Code·Workspace 중 회사에서 허용한 화면으로 그 폴더를 선택하세요.

폴더를 선택했다고 PC의 다른 경로에 접근할 수 없게 되는 것은 아닙니다. 요청에 대상과 제외 범위를 적고, 승인 화면의 실제 경로를 확인합니다.

요청 예문선택 후 Ctrl+C로 복사
지금 선택한 연습 폴더가 어디인지 알려줘.
바로 아래 파일 이름만 확인하고, 다른 폴더나 파일 본문은 읽지 마.
파일·설정·기억을 만들거나 변경하지 마.

파일을 지정할 때는 CLI의 @ 목록이나 사용 중인 화면의 파일 선택을 이용합니다. 파일을 첨부한 것과 전체 내용을 실제로 읽은 것은 다릅니다. 페이지·시트·읽은 범위를 결과에서 확인하세요.

3. 요청하고 확인하는 기본 순서

  1. 요청: 목적, 자료, 결과 형식, 하지 말아야 할 일을 적습니다.
  2. 선택: 디자인·저장 위치처럼 필요한 질문에 답합니다.
  3. 확인: 파일 읽기·변경·발송 안내가 나오면 대상과 범위를 봅니다.
  4. 실행: 같은 요청을 다시 보내지 말고 결과나 추가 질문을 기다립니다.
  5. 검증: 실제 결과 파일과 숫자를 열어 확인하고 미확인 부분을 구분합니다.

설명·계획만 원하면 실제 변경을 하지 말라고 적으세요. 실제 작업을 원하면 확인한 계획의 어느 범위를 실행할지 말합니다.

요청 예문선택 후 Ctrl+C로 복사
가상 실적 3개월치를 설명할 보고서를 만들고 싶어.
먼저 필요한 자료와 진행 계획만 알려줘.
아직 파일 생성, 프로그램 설치, 설정 변경은 하지 말고 내 답변을 기다려줘.

Company Agent는 관련 스킬이 있으면 설명서 본문을 읽어 적용하고, 없으면 허용된 일반 방식으로 진행합니다. 스킬이 둘 이상 같은 역할을 한다면 기존 우선 선택이나 내 답변을 따릅니다. “스킬 사용”이라는 말뿐 아니라 실제 본문 로드와 업무 결과를 따로 확인합니다.

중단 멈추기 전에 이미 생성·변경·전송된 것이 있는지
되돌리기 실제 복구 가능한 대상과 복구되지 않는 외부 작업이 무엇인지

Claude Code의 실행 승인과 Company Agent의 업무 범위 확인은 별도 절차일 수 있습니다. 하나를 승인했다고 모든 후속 작업을 허용한 것은 아닙니다. 자주 묻는다는 이유로 회사 정책이나 승인 절차를 끄지 않습니다.

Esc로 응답을 멈추거나 /rewind를 열어도 모든 작업이 취소되는 것은 아닙니다. 특히 이미 보낸 메일, 외부 변경, 일부 명령 실행은 별도로 확인해야 합니다. 공식 되돌리기 안내

Workspace의 작업 중지도 이미 수행한 일을 되돌리지 않습니다. 앱이 시작한 CLI의 종료 확인을 기다리며, 종료를 확인하지 못하면 중지 성공으로 표시하지 않습니다. 직접 시작한 CLI가 끝나도 모든 하위 프로그램의 종료를 보장하지는 않습니다. 같은 요청을 다시 보내기 전에 실제 결과와 남은 작업을 확인하세요.

5. 대화·프로젝트 지침·기억을 구분하세요

/compact는 대화 요약, /clear는 새 대화, /resume는 이전 대화 이어가기입니다. 영구 기억 저장이나 파일 복구를 대신하지 않습니다. 공식 대화 관리

Company Agent의 기본 프로젝트 안내 생성과 개인 자동 학습도 서로 다릅니다. 자동 학습이 회사 규정이나 프로젝트 CLAUDE.md를 마음대로 고치는 것은 아닙니다. 저장·적용 범위의 비교는 하네스 이해하기를 참고하세요.

Company Agent 업무별 사용 가이드

하고 싶은 업무의 예문을 복사하고 자료·범위·결과 형식을 바꿔 요청하세요. Company Agent는 기존 Claude Code의 회사 계정·모델·권한을 그대로 사용합니다.

1. 요청은 목적·자료·결과·제한 순서로

알려줄 것 예
목적과 독자 부서장에게 월간 실적을 설명
자료와 범위 가상 세 달 수치, 또는 첨부 파일 1~5장
결과 핵심 요약과 확인할 사항, 편집 가능한 PPT
제한과 완료 조건 원인 추측 금지, 원본 보존, 직접 확인한 범위만 보고

어렵다면 “필요한 정보만 한국어로 물어봐줘”라고 시작합니다. 질문이 오면 번호나 이름으로 답하고, 답변 대기 중 같은 제작 요청을 다시 보내지 않습니다.

질문 제목·선택지·설명·추천 표시는 기본 한국어입니다. 흔한 영문 선택 문구는 추가 AI 호출 없이 바꿉니다. 파일명·명령어·제품명은 유지하며, 대화 언어를 따로 요청하면 그 범위를 따릅니다. Claude 자체 메뉴·권한 버튼이나 외부 도구의 원문까지 번역하는 기능은 아닙니다.

참고 파일은 필수가 아닙니다. 시작하기 1단계에서 가상 자료를 만들어 연습할 수 있습니다. PPT는 2단계의 새 디자인 예문으로 제작합니다.

2. 문서 읽기와 비교

실제 파일은 CLI의 @ 또는 Workspace의 파일 선택으로 지정합니다. 처음에는 가상 MD·텍스트 자료로 연습하세요. 파일 형식별 읽기 지원은 실제 설치된 스킬과 도구에서 확인합니다. 문서 본문이 대화에 전달될 수 있으므로 승인된 자료만 사용합니다.

요청 예문선택 후 Ctrl+C로 복사
첨부한 실습_가상자료.md를 읽고 핵심 내용·월별 수치·확인할 사항을 정리해줘.
원본은 수정하지 말고 실제 읽은 범위와 미확인 부분을 알려줘.
자료에 없는 증가 원인은 추측하지 마.

실패·시간초과·개수 차이만으로 DRM 원인을 단정하거나 실제 접근 제한을 다른 사본으로 우회하지 않습니다.

문서 비교 파일이 없어도 아래 예문으로 시작할 수 있습니다.

다음 가상 문구 두 개를 비교해줘.
이전안: 월 1회 점검. 변경안: 월 2회 점검. 그 외 조건은 동일.
바뀐 항목과 바뀌지 않은 항목만 표로 정리해줘. 실제 회사 규정으로 기억하지 마.

3. 보고서·HTML·편집 가능한 PPT

먼저 디자인·분량·결과 형식을 정합니다. HTML은 새 디자인 또는 참고 HTML, PPT는 새 디자인·참고 캡처 2~3장·기존 PPT·저장한 HTML 양식 중 필요한 방식을 사용합니다. 새 디자인에서는 참고 파일을 요구하지 않습니다.

이미 알려준 조건은 다시 묻지 않습니다. 처음에는 필요한 선택만 질문하며, 선택을 시작하려고 임시 파일을 만들거나 설치 폴더를 검색할 필요는 없습니다. 선택이 끝나면 본문과 HTML 초안을 준비합니다. “초안 필요”나 “확인 대기”는 제작 오류가 아닙니다.

요청 예문선택 후 Ctrl+C로 복사
가상 월간 실적으로 짧은 HTML 보고서를 만들어줘.
6월 목표 100건·실적 90건, 7월 목표 100건·실적 110건, 8월 목표 100건·실적 130건.
참고 파일은 없어. 새 디자인 목록에서 하나 고른 뒤 스크롤 방식으로 만들어줘.
목표 300건·실적 330건·달성률 110%를 대조해줘. 원인과 연도는 추측하지 마.
최종 HTML 한 파일만 전달하고 기존 파일은 덮어쓰지 마.

PPT는 전체 HTML 초안 → 사용자 확인 → 편집 가능한 PPT → 결과 확인 순서입니다. 카드·둥근 모서리·그림자·태그를 지원하지만 웹 화면과 모든 효과가 같지는 않습니다. 복잡한 효과·움직이는 내용·병합 표는 변환 가능 여부를 먼저 확인하세요. 차트 수치도 바꾸려면 “데이터도 수정 가능한 차트로 만들어줘”라고 요청합니다.

HTML 초안·변환 시도·검사 이미지는 내부 임시 작업 공간에 두고 한 요청에서는 최종 결과 한 개가 기본입니다. 여러 결과를 명시적으로 요청하거나 다음 질문에서 다른 형식을 요청하면 별도로 생성할 수 있습니다. 기존 결과는 자동 삭제하지 않습니다.

작업 중지는 이미 만든 파일·보낸 메일을 되돌리지 않습니다. Workspace가 직접 시작한 CLI의 종료를 확인했어도 모든 하위 프로그램이 종료됐다는 뜻은 아닙니다. 중지가 확인되지 않으면 마지막 상태를 담당자에게 전달하고 실제 결과부터 확인합니다.

3. 세 범위, 두 종류의 내용

범위 내용과 저장 위치 누가 바꾸나요? 어디에서 이어지나요?
회사 공통 설치에 연결된 배포 지식과 공통 기준·스킬·후크 담당자가 검토·배포. 사용자 화면은 읽기 전용 같은 배포본과 연결 설정을 사용하는 환경
개인 전체 로컬 개인 저장소의 선호·지식·개인 스킬·도구 나. 저장 전 범위와 내용 확인 같은 사용자 설치·저장소를 쓰는 여러 작업 폴더
이 프로젝트 로컬 개인 저장소의 프로젝트별 기억·자산. 폴더 지침은 실제 프로젝트 파일 내 자산은 나. 공유 프로젝트 파일은 작성·공유 주체 확인 저장한 프로젝트 경로와 연결된 설치에서 사용

‘회사 공통’은 회사가 관리하는 내용이며 ‘개인 전체/이 프로젝트’는 내 자료를 적용할 범위입니다. 각 화면에서 기억·지식 / 업무 구성을 선택합니다.

새 기억·지식·스킬·도구를 저장할 때는 어디에 저장할까요? → 개인 전체 / 이 프로젝트를 선택합니다. 이미 요청에 범위를 명시했다면 재질문하지 않습니다. 기존 항목 수정은 원래 범위를 유지하고, 회사 공통은 직접 저장 선택지에서 제외합니다. ‘내 것’이라고만 말하면 두 범위 중 하나를 물어봅니다. 화면에서도 새 저장 범위는 미선택으로 시작합니다.

실제 저장 경로는 구성 한눈에에서 확인합니다. 같은 PC의 새 대화라도 같은 설치·저장소를 사용해야 기억을 다시 조회할 수 있습니다. 다른 PC나 계정으로 자동 동기화하지 않으며, 옮겨 쓰려면 담당자와 백업·이전·연결 설정을 확인한 뒤 다시 조회합니다. 프로젝트 폴더 복사나 이름 변경만으로 프로젝트 개인 기억이 따라오지는 않습니다. ‘개인 전체’에 저장할 수 없다는 안내가 나오면 담당자에게 설치 범위를 확인하세요.

Claude 자체 자동 기억은 이 화면의 Company Agent 기억과 별도로 관리합니다. 원래 CLI에서 해당 기억의 경로·설정을 확인하며, 두 저장소를 자동 합치지 않습니다. 프로젝트 폴더를 공유해도 Company Agent 개인 자료가 동료에게 자동으로 전달되지는 않습니다.

확인할 저장소 일반적인 위치 또는 구분
Company Agent 개인 전체 현재 User 설치 기본값은 %LOCALAPPDATA%\CompanyAgent\states\user. 기존 설치 등록·사용자 지정 위치가 우선
User 설치의 프로젝트 개인 자료 위 저장소의 project-scopes/<폴더 식별자>/. 현재 작업 폴더의 절대경로로 구분
별도 Project 설치 기본값은 %LOCALAPPDATA%\CompanyAgent\states\projects\<폴더 식별자>. 해당 설치의 등록된 stateRoot가 우선
Claude Code 자체 설정·기억 별도 Claude 설정 루트. 일반적으로 %USERPROFILE%\.claude를 사용하지만 실제 설정·기억 위치는 원래 CLI에서 확인

각 Company Agent 저장소 안에서 기억은 memory/items/, 개인 스킬은 personal-root/.claude/skills/, 학습 이력은 learning/state.json에 있습니다. 프로젝트 폴더 안의 지침 파일과는 다른 위치입니다. User 설치의 프로젝트별 저장소와 별도 Project 설치를 혼동하거나, 같은 폴더 이름·상위·하위 관계만으로 같은 기억을 쓴다고 가정하지 마세요. 예전 설치의 다른 경로를 위 기본값으로 수동 이동하지 않습니다. 이 경로는 확인용이며 기억 변경·중지·복구는 관리 화면이나 해당 명령으로 요청합니다.

부서 기준도 회사 영역에 포함합니다. 프로젝트는 “어느 폴더에 적용할지”이지 세 번째 정책 소유자가 아닙니다. 회사 필수 기준, 개인화 가능한 기본값, 참고 지식은 구분합니다. required라는 표시만으로 운영체제 권한이 강제되는 것은 아닙니다.

User 설치와 Project 설치는 적용 범위·개인 저장소가 다를 수 있습니다. 다른 범위의 기억이 보이지 않는다고 삭제됐다고 단정하거나 자동으로 합치지 마세요. 회사 업데이트는 개인 기억·지식·스킬과 기존 모델·MCP 설정을 임의로 초기화하지 않습니다.

‘공통’과 ‘전역 설치’는 다릅니다. 공통은 관리 주체, User/Project는 적용 범위입니다. ‘내 사용자 설치’는 내 여러 폴더에, ‘이 프로젝트’는 해당 설치 범위에 적용됩니다. User 설치 하나로 다른 직원에게 배포되거나 개인 기억이 공유되지는 않습니다. ‘폴더에 있으니 내 것’이라고도 판단하지 마세요. 함께 받은 프로젝트 파일은 공유 구성일 수 있습니다.

프로젝트 CLAUDE.md는 목적·단위·완료 조건을 적는 설명서입니다. 공통 스킬·후크·연결·검증을 포함하는 하네스 전체와 같지 않습니다. 작은 규칙은 짧은 프로젝트 지침으로 시작하고, 반복 업무에 여러 역할이 필요할 때 프로젝트 하네스를 생성하세요. 기존 CLAUDE.md를 생성기가 교체하지 않습니다. 시작하기 7단계에서 A/B 폴더로 차이를 시험합니다.

새 작업 폴더의 첫 시작: 파일 읽기·작성·수정 같은 작업 요청이 들어오면 지침이 없는 작업 폴더에 짧은 기본 CLAUDE.md를 한 번 생성합니다. 기존 파일·.claude/CLAUDE.md·부모 프로젝트 지침이 있으면 보존합니다. 홈·시스템·설치/설정 폴더, 계획 모드, 변경 금지 요청에서는 생성하지 않습니다. 별도 AI 호출이나 전체 폴더 탐색 없이 시작 안내만 만들므로 /init의 코드 분석과 동일하지 않습니다. 실행법·프로젝트 지식은 확인 후 별도로 보완합니다. 단순히 폴더를 여는 것만으로는 생성하지 않습니다.

질문과 피드백 언어: Company Agent의 질문 제목·선택지·설명·추천 표시·승인 안내는 기본 한국어입니다. 흔한 영문 선택 문구는 추가 AI 호출 없이 바꾸고, 알 수 없는 영문 설명의 재작성은 제한된 횟수만 요청합니다. 대화 언어를 따로 요청하면 그 범위를 따르며, 영어 보고서 요청만으로 선택 질문까지 영어로 바꾸지는 않습니다. 코드·파일명·제품명과 Claude 자체 메뉴·권한 버튼·Windows/Office 화면은 원래 표기를 유지할 수 있습니다.

4. 기본 스킬 11개와 이전 이름 1개

7. 범위별 기억과 업무 구성을 다듬는 방법

회사 공통 → 기억·지식 — 함께 참고, 담당자가 갱신

회사 공통 → 기억·지식에서 회사·팀이 배포한 지식을 읽습니다. 회사 필수 규정과 실행 절차는 회사 공통 → 업무 구성에서 봅니다. 팀원이 실시간으로 공동 편집하는 공간은 아니므로, 수정할 내용은 담당자에게 제안하세요. 프로젝트 CLAUDE.md나 일반 문서가 이 목록에 자동 등록되지는 않습니다.

개인 전체 / 이 프로젝트 → 기억·지식 — 선호와 업무 지식을 한곳에서

Workspace 기억·하네스 관리 → 개인 전체 / 이 프로젝트 → 기억·지식 → 내 기억 추가 → 변경안 확인 → 확인하고 저장 순서입니다. 제목과 짧은 선호만 적고 원본 문서·계정 정보는 넣지 마세요. 사용 안 함, 수정, 이전 내용 복원안을 지원합니다. 저장 위치와 적용 범위가 같아야 새 대화에서도 비교할 수 있습니다. Claude Code 자체 자동 기억은 별도 관리하며 자동으로 합치거나 덮어쓰지 않습니다.

요청에 참고할 기억은 허용된 개인 전체·현재 프로젝트에서 관련도 순으로 고르고, 같은 관련도일 때 프로젝트 항목을 먼저 봅니다. 중복을 제외하고 합계 최대 5개를 참고 대상으로 고릅니다. 프로젝트 기억이 많아도 더 관련 있는 개인 기억을 무조건 뒤로 밀지 않습니다. 이는 검색 순서이지 회사 정책이나 저장 범위를 바꾸는 규칙이 아닙니다. 목록에 없는 기억도 남아 있을 수 있으므로 범위와 제목을 지정해 조회하세요.

요청 예문선택 후 Ctrl+C로 복사
앞으로 내 보고서는 결론부터 짧게 설명하고 확인한 범위와 미확인 부분을 구분해줘.
이 표현 선호만 개인 기억에 저장하고 문서 본문은 저장하지 마.

자동 학습은 User 설치에서는 개인 전체, Project 설치에서는 해당 설치 저장소에서만 작동합니다. 명시적 저장 범위 선택은 학습 설정을 바꾸지 않습니다. 진행 중인 교정은 임시 후보로 모으고, 의미 있는 업무가 완료·검증된 시점에 선호나 전체 본문을 실제 로드한 개인 스킬의 제한된 점검 항목을 개선합니다. 단순 조회, 재사용할 교훈이 없는 답변, 질문·승인 대기는 학습 완료가 아닙니다. User 설치의 프로젝트 전용 자산은 자동 수정하지 않습니다.

장기적으로 쓸 명시적 교정은 조건을 만족하면 기억 요청 없이 반영할 수 있습니다. 추정한 선호는 독립된 업무에서 반복 확인해야 하며, 같은 업무의 재답변·재시도를 독립된 반복 근거로 늘리지 않습니다. 같은 범위·같은 항목을 A → B → A로 고치면 마지막 교정을 사용합니다. 개인 스킬의 같은 점검 항목은 새 문장으로 교체하며 서로 모순되는 문장을 계속 덧붙이지 않습니다. 수동 편집과 충돌하거나 과거 항목의 식별자를 이력에서 복원할 수 없으면 해당 자동 개선만 보류하고 기존 스킬을 보존합니다.

새 스킬 생성은 별도입니다. 기존 개인 스킬의 점검 항목 개선은 조건부 자동 처리하지만, 새로운 업무 절차를 스킬로 만드는 일은 생성 요청이나 제안에 대한 동의 후 제작 스킬로 진행합니다. 공통 스킬을 쓰다가 자동으로 개인 복제본을 만드는 기능은 없습니다. 명시적인 “기억해줘” 요청은 완료 학습을 기다리지 않고 선택한 범위에 저장합니다.

본문 전체 로드는 개선 대상의 근거이며 실제 적용·업무 성공의 증명은 아닙니다. 모든 교정을 즉시 영구 저장하지 않습니다. 매 요청마다 별도 학습 모델을 자동 호출하거나 종료 후 백그라운드 학습하지 않지만, 완료 시 교정 정리와 검토에는 현재 대화의 모델 처리 비용이 들 수 있습니다. 복잡한 개선을 별도 작업자에게 검토하게 하면 그 처리 비용도 포함됩니다. 공통 자료·회사 정책·프로젝트 CLAUDE.md·도구 코드를 자동 수정하지 않고 현재 요청을 덮어쓰지 않습니다.

자동 학습 카드나 /company-agent:learning에서 관찰·적용 내역을 확인하고 일시 중지·재개·선택한 변경 되돌리기를 요청합니다. 중지해도 기존 기억을 지우거나 사용을 멈추지는 않습니다. 되돌리기는 자동 선호의 사용 중단 또는 스킬 점검 영역의 이전 상태 복원이며, 업무 파일이나 발송 메일의 취소가 아닙니다.

출처가 있는 용어·계산식은 같은 화면의 내 업무 지식 초안에서 저장하고, 직접 검토 후 사용으로 바꿉니다. 개인 초안을 만들었다고 공통 기억이 바뀌지 않습니다. 공통 기억 검토용 내보내기는 로컬 ZIP 생성이며 자동 업로드·회사 반영이 아닙니다. 전달 전 민감 내용을 검토하세요. 공통 자료로의 반영은 담당자의 검토·배포 단계입니다.

회사 공통 → 업무 구성 — 실행 방식과 공통 규정

공통 하네스는 회사 업무 기준·공통 스킬·후크 정의를 확인하는 화면입니다. 목록이 있다는 사실과 현재 CLI에서 실제 실행됐다는 사실은 다릅니다. 화면에 수정·삭제 버튼을 두지 않으며 개인 선호로 회사 필수 기준을 해제하지 않습니다.

개인 전체 / 이 프로젝트 → 업무 구성 — 내 추가 구성과 폴더별 지침

개인 전체 / 이 프로젝트 → 업무 구성에서 개인·사용자 설치·프로젝트·외부 플러그인의 스킬 출처와 개인 도구 등록 기록을 확인합니다. 이는 모든 외부 도구의 연결 상태 목록이 아닙니다. 외부 설치 원본과 MCP 자격증명을 편집하지 않습니다. 등록·활성화 기록만으로 실행 성공을 판정하지 마세요.

같은 화면의 이 폴더에만 적용할 업무 지침에 목표·입력·결과물·완료 기준을 적습니다. 저장 파일은 .claude/rules/company-workspace-brief.md이며 기존 CLAUDE.md와 다릅니다. 기존 또는 직접 수정한 지침은 덮어쓰지 않습니다. 회사 공통 규정을 개인 폴더에 복사해 별도 정책 계층으로 만들 필요는 없습니다.

개인 스킬·도구 만들기

반복하는 처리 순서는 스킬, 계산·조회처럼 재사용할 실행 코드는 도구입니다. 둘 다 같은 제작 스킬로 요청합니다. 새 업무 도구는 회사 표준 tools.py로 만들고 내 PC에서는 가벼운 stdio 연결로 실행합니다. 별도 웹 서버를 켜거나 회사 서버에 배포할 필요가 없습니다. 글쓰기 스킬이나 일회성 작업까지 도구로 만들지는 않습니다. 같은 기능이 있으면 재사용하고 기존 스크립트 도구는 그대로 유지합니다.

저장할 때 개인 전체 / 이 프로젝트를 한 번 선택합니다. 선택 저장소의 personal-root/.claude/skills에는 스킬, mcp/servers에는 새 도구를 보관합니다. 회사 플러그인 캐시는 수정하지 않습니다. 도구는 후보 생성 → 정상·잘못된 입력 시험 → 검증 기록 → 연결 등록 → Claude 재시작 후 실제 호출 순서입니다. 스킬은 필요한 도구를 연결해 사용하고, 없는 도구를 임의 코드로 대신하지 않습니다. 도구의 코드·입력 형식이 바뀌면 재시험하고 연결된 스킬도 확인합니다.

도구 연결 확인은 필요한 스킬을 처음 쓸 때 수행하며 LLM이나 서버를 새로 띄우지 않습니다. 현재 대화에서 바뀌지 않은 확인 결과는 재사용합니다. 다른 저장소·외부 MCP도 연결된 실제 도구로 재사용할 수 있지만, 같은 저장소에서 만든 도구에 적용하는 소스·스키마 검증과는 구분합니다. 등록 여부만으로 현재 세션의 연결 성공을 보장하지 않습니다.

기존 도구가 재시험을 요청하면: 과거 검사 기록으로 새 검사 기준을 통과했다고 보지 않습니다. 해당 도구가 원래 저장된 범위에서 정상 입력과 잘못된 입력을 다시 시험하고, 통과한 현재 기록으로 활성화·연결을 확인하세요. JSON 입력·출력은 선언한 형식·필수 값·범위 등을 검사하며, 지원하지 않는 조건은 무시하지 않고 알립니다. 검사 조건을 지워 통과시키지 않습니다. 재시험 안내가 소스 삭제나 이미 별도 등록된 MCP의 자동 해제를 뜻하지는 않습니다.

시작하기 8단계에서 회의 메모 정리 스킬과 달성률 계산 도구를 만들어 봅니다. 이름 없는 자동 선택과 명시 사용을 따로 시험하고, 목표 0·누락 입력도 확인합니다. 생성된 코드는 내 Windows 계정 권한으로 실행되므로 외부 연결·파일 변경 여부도 확인하세요. 시험 통과가 모든 상황의 안전성을 보장하지는 않습니다.

관리자 참고: 현재 같은 미완료 업무에서 한 개인 스킬의 서로 다른 교정을 연이어 모으면 앞선 후보가 남지 않을 수 있습니다. 여러 항목의 자동 보존·반영을 보장하지 말고 실제 적용 내역을 확인하세요. 저장·조회 성공만으로 사내 모델의 실제 적용 품질까지 입증되는 것은 아닙니다.

8. 느리거나 토큰을 많이 쓰면

  1. 요청에 대상 파일·확인 범위·완료 기준을 한 번에 적습니다.
  2. 디자인·양식 등 이미 답한 내용은 유지해 달라고 요청합니다.
  3. 새 주제는 새 대화로 나누고, 긴 자료는 필요한 범위부터 읽습니다.
  4. 표시 인코딩만 깨졌다면 파일 생성·발송 등 원래 업무부터 반복하지 않습니다.
  5. 문서 읽기·계산 등은 실제로 사용 가능한 스킬·도구와 지원 범위를 확인합니다.

새 폴더의 기본 CLAUDE.md 생성은 3장의 조건에서 지원합니다. /revise-claude-md라는 별도 명령, 업무 종료마다 강제 /compact, 자동 후속 질문 전송은 제공하지 않습니다. 개인 자동 학습과 CLI 자체 대화 압축은 프로젝트 지침의 자동 수정이나 공통 기억 공유가 아닙니다. 대화 압축과 기억 저장은 다른 일입니다.

Workspace 사용 현황은 CLI가 실제 제공한 토큰과 앱이 관찰한 실행·질문·승인 대기를 구분합니다. 빠진 값은 0이 아니라 미제공입니다. 요청 값이 세션 누적일 수 있으므로 서로 더하지 않습니다. 사내 모델 단가를 모르면서 청구 금액이나 절감률을 만들지 않습니다.

토큰 알림은 다음 요청부터의 안내이며 강제 예산 제한이 아닙니다. 과거 로그 분석은 사용자가 고른 파일만 대상으로 하며 자동으로 대화 전체를 검색하지 않습니다. 준비·결과 확인의 평가는 사용자가 직접 확인해 기록한 표본이지 모델 전체 성능 점수가 아닙니다.

Claude Code 명령어·단축키

원본 Claude Code CLI 기준입니다. Workspace·VS Code의 메뉴와 키는 다를 수 있습니다. 현재 설치에서 /를 입력해 보이는 항목을 먼저 확인하세요. 없는 명령을 억지로 실행하거나 명령 하나 때문에 재설치하지 않습니다. 아래 기능은 별도 표시가 없으면 Claude Code 기능이며 Company Agent가 새로 만든 명령이 아닙니다.

처음에는 @로 파일 선택, Ctrl+J로 줄바꿈, Esc로 중단, /help로 도움말만 익혀도 됩니다. 전체 사용 흐름은 Claude Code 기본 사용법을 먼저 읽으세요.

1. 입력·중단·확인에 필요한 키

파일 지정 @ 목록에서 실제 파일 선택

입력 위치를 구분하세요. /help는 Claude 대화 입력칸, claude --continue는 운영체제 터미널에 입력합니다. 설치 명령이나 터미널 명령을 자연어 질문처럼 보내지 마세요. 사용량 값이 없거나 사내 가격과 연결되지 않으면 실제 청구액을 추측하지 않습니다.

3. 작업 중 다음 질문과 제안 문장

실행 중 보낸 메시지는 대기하다가 도구 실행 경계 등에 전달될 수 있습니다. ‘지금 작업을 보완’하는지 ‘다음 업무’인지 명확히 적으세요. 반드시 완료 후 시작해야 한다면 결과를 받은 다음 보냅니다. Tab은 다음 업무를 예약하는 키가 아닙니다.

요청 예문선택 후 Ctrl+C로 복사
현재 요청 보충: 원본을 보존하고 실제 확인한 범위만 알려줘.

입력칸에 제안 문장이 보이는 것과 메시지를 전송하는 것은 다릅니다. 제안은 CLI·조직 설정에 따라 없을 수 있고, Company Agent가 자동으로 후속 질문을 보내지는 않습니다. 공식 실행 중 메시지·제안 안내

4. 압축·기억·프로젝트 지침은 다른 일

큰 작업이 끝났다고 매번 압축할 필요는 없습니다. 먼저 결과 파일과 남은 일을 확인합니다. 대화가 길어졌을 때 원본 CLI에서 아래처럼 중요한 조건을 남길 수 있습니다.

요청 예문선택 후 Ctrl+C로 복사
/compact 현재 목표, 원본 보존 조건, 최종 파일 경로, 검증한 범위와 미확인 사항을 남겨줘

압축에도 처리가 필요하며 비용 절감률을 보장하지 않습니다. 회사 모델의 자동 압축 지원은 운영 환경에서 확인합니다. 이 하네스는 매 작업 후 강제 /compact를 실행하지 않습니다. 공식 대화 관리

Claude의 CLAUDE.md와 자동 기억은 대화 요약과 다릅니다. Company Agent 개인 기억도 별도입니다. 기본 CLAUDE.md 자동 생성은 짧은 시작 안내이며 /init의 코드 분석을 대신하지 않습니다. 자동 학습 역시 프로젝트 지침을 몰래 고치는 기능이 아닙니다. 공식 기억 안내

5. 되돌리기·여러 세션·종료

원본 CLI의 /rewind는 되돌릴 대상을 확인하는 메뉴입니다. 모든 외부 작업·명령 실행·메일 발송을 취소하는 기능은 아닙니다. 중단 후에는 실제 파일과 실행 기록을 먼저 확인하세요. 공식 되돌리기 한계

서로 독립적인 업무만 별도 폴더·대화로 나눕니다. 같은 파일을 동시에 수정하면 충돌할 수 있습니다. 하나의 회사 계정 사용량이 세션별로 독립되는 것도 아닙니다. 폴더 간 이동과 새 대화는 기억·권한 범위를 다시 확인할 기회입니다.

터미널에서 다시 시작할 때 claude는 새 실행, claude --continue는 최근 대화 이어가기 용도로 사용할 수 있습니다. 인증은 기존 회사 안내를 따릅니다. 이 명령들은 대화 입력칸의 슬래시 명령과 다릅니다. 공식 CLI 실행 옵션

Workspace는 전원 버튼으로 종료하세요. 창의 X만 닫으면 프로그램이 계속 실행될 수 있습니다.
