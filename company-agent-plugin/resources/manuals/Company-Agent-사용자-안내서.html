01

Company Agent 시작하기

명령어 암기보다 작은 업무 하나를 맡기고 직접 확인하는 연습입니다.

처음에는 1단계: 가상 자료 만들고 읽기만 해보세요. 회사 자료나 참고 파일은 필요 없습니다. 익숙해지면 보고서 만들기, 기억 저장, 내 스킬 만들기로 이어갈 수 있습니다. 필요한 단계만 골라 진행하세요.

먼저 세 범위만 구분하세요. 회사 공통 / 개인 전체 / 이 프로젝트 안에서 기억·지식과 업무 구성을 확인합니다.

구분 쉬운 예 내가 할 수 있는 일
회사 공통 배포 지식·회사 기준·공통 스킬·후크 읽기, 담당자에게 수정 제안
개인 전체 여러 프로젝트에서 사용할 선호·지식·개인 자산 범위 선택 후 저장·수정·사용 중단
이 프로젝트 이 업무에서만 사용할 기억·스킬·도구·지침 개인 자산과 공유 프로젝트 파일을 구분해 관리

새로 저장할 때는 두 선택지입니다. 개인 전체(여러 프로젝트) / 이 프로젝트(현재 작업에서만). 범위를 말하지 않았다면 한 번 질문하고 답변을 기다립니다. 이미 명시했다면 다시 묻지 않습니다. 회사 공통은 직접 저장하지 않습니다. ‘전역’이라고 모두에게 공유되지 않습니다. 프로젝트 기억·도구는 비공개 저장소에 남지만 새 프로젝트 스킬은 작업 폴더 안에 있어 함께 공유될 수 있습니다.

실제 위치는 기억·하네스 관리 → 구성 한눈에에서 확인합니다. 회사 공통은 연결된 배포본, 개인 기억·자산은 선택한 로컬 저장소, 폴더 지침은 프로젝트 파일입니다. Claude 자체 자동 기억은 Company Agent 기억과 별도입니다. 기본 스킬 13개와 후크 7개의 역할·한계는 핸드북 4~5장에서 확인할 수 있습니다.

단계 고르기: 0–5는 첫 업무, 6은 공통 기억·내 기억 비교, 7은 폴더별 적용 범위 비교, 8은 내 스킬·도구 만들기입니다. 생성·저장 예문을 보내면 실제 파일이나 기억이 생기므로, 실습 후 정리 방법도 확인하세요.

0. 준비하기

회사에서 사용을 승인한 Claude Code와 Python 3.11 이상이 필요합니다. 회사 모델·인증서·로그인 설정은 조직 안내를 따릅니다. Node.js·Git은 모든 직원 업무의 필수 준비물이 아닙니다. 필요한 앱과 라이브러리는 업무마다 다릅니다.

  1. 기존 Claude Code가 정상 작동하는지 확인합니다. 이미 된다면 로그인·모델·API 키를 새로 설정하지 않습니다.
  2. 담당자가 공유한 배포 페이지에서 Company-Harness-Setup.exe를 내려받아 두 번 클릭합니다. Company Harness 설치 화면에서 “내 Claude Code 전체에서 사용” 또는 “선택한 업무 폴더에서만 사용”을 고르고 설치하기를 누릅니다. 기존 Company Agent가 있으면 업데이트합니다. 다른 하네스 교체가 필요하면 표시된 설명을 읽고 선택합니다. ZIP으로 받았다면 모두 압축 풀고 Install-CompanyAgent.cmd를 실행해도 됩니다.
  3. 설치 후 Claude Code를 다시 엽니다. Workspace는 별도 미리보기 묶음입니다. 그 묶음의 Company-Workspace.vbs를 더블클릭합니다. 관리자 권한은 사용하지 않습니다.
  4. 탐색기에서 새로운 빈 연습 폴더를 만들고 작업 폴더로 선택합니다. 실제 고객 자료·메일·공용 폴더는 연습에 쓰지 않습니다.
  5. 신뢰하는 폴더인지 확인합니다. 이 동의는 모든 후속 행위를 무조건 허용한다는 뜻이 아닙니다.

성공 확인: 앱이 열리고 작업 폴더가 보입니다. AI 응답과 실제 업무 결과는 다음 단계에서 확인합니다. VBS·PowerShell 실행이 회사에서 제한돼 있으면 담당자에게 승인된 실행 방식을 요청하세요.

GitHub의 Code → Download ZIP과 GitHub·GitLab의 Source code는 설치용이 아닌 개발용 소스입니다. 직원은 담당자가 첨부한 Company-Harness-Setup.exe 설치 파일을 선택하세요. 비공개 배포 페이지가 열리지 않으면 사내 GitLab 로그인과 프로젝트 접근 권한을 담당자에게 확인합니다. 하네스는 한 번 설치하면 기존 Claude Code에서 사용하며, 새 버전이 안내됐을 때만 설치 파일을 다시 내려받아 업데이트합니다.

이 안내서는 하네스 1.4.45를 기준으로 합니다. 새 스킬은 Claude 기본 위치에 저장하고 기존 스킬은 원래 위치에서 수정합니다. 운영 환경에 비전 설정이 준비되어 있으면 이미지 파일 경로와 확인할 부분을 알려주세요. 필요한 이미지 관찰만 별도 작업자가 수행하고 기존 모델이 결과를 받아 같은 업무를 계속합니다. 비전 설정이 없으면 기존 읽기 흐름을 유지합니다. 작업자가 정상 종료해도 실제 이미지 판독이 성공했다는 뜻은 아닙니다. 이미지 내용을 확인하지 못했거나 모델을 사용할 수 없을 때는 시각 검증 미확인으로 안내하며 OCR·다른 모델로 조용히 대체하지 않습니다. 평소 업무에 별도 연결 시험이나 추가 검증 호출을 넣지 않습니다. 자세한 사용 범위는 핸드북 6장에서 확인하세요. 이전 Release는 보존하고 별도 Workspace 앱 변경은 이번 하네스 배포에 포함하지 않습니다.

원본 CLI를 선호한다면: 기존 방식으로 해당 폴더의 Claude Code를 열고 아래 요청문을 입력합니다. /plugin, /skills, /hooks로 실제 등록을 확인할 수 있습니다. GUI가 이 터미널 메뉴 전부를 그대로 제공하는 것은 아닙니다.

1. 자료 하나 읽기

가지고 있는 파일이 없어도 시작할 수 있습니다. 먼저 가상 자료를 만들고, 다음 요청에서 읽습니다. 생성과 읽기를 나누면 방금 만든 내용을 기억해서 답한 것인지 실제 파일을 읽었는지 비교하기 쉽습니다.

가상 비교 문구: 이전안은 월 1회 점검, 변경안은 월 2회 점검. 그 외 조건은 동일.

import json
from mcp.server.fastmcp import FastMCP
from pydantic import StrictInt

def register_tools(mcp: FastMCP) -> None:
    @mcp.tool()
    async def achievement(targets: list[StrictInt], actuals: list[StrictInt]) -> str:
        """최대 12개 가상 실적의 합계와 달성률을 계산합니다."""
        for values in (targets, actuals):
            if not 1 <= len(values) <= 12:
                raise ValueError("provide 1 to 12 values")
            if any(not 0 <= value <= 1000000 for value in values):
                raise ValueError("values must be between 0 and 1000000")
        if len(targets) != len(actuals):
            raise ValueError("list lengths must match")
        target_total, actual_total = sum(targets), sum(actuals)
        rate = round(actual_total / target_total * 100, 2) if target_total else None
        return json.dumps({"targetTotal": target_total, "actualTotal": actual_total,
                           "achievementRate": rate}, ensure_ascii=False)

만들어지는 것: src/mcp/tools.py가 업무 코드입니다. 함께 제공하는 config.py·local_server.py·requirements-local.txt는 로컬 시험 전용이며 전사 파일을 교체하지 않습니다. test_tools.py는 실제 MCP SDK로 목록·입출력·실패 입력을 확인합니다. 기존 폴더를 덮어쓰지 않습니다. Python과 승인된 SDK 1.x 환경이 없으면 준비물을 안내하며 자동 설치하지 않습니다.

이렇게 되면 성공: 한글 응답이 원래 입력과 같고, 잘못된 입력은 오류로 구분되며, 검사한 코드 경로와 결과를 확인할 수 있습니다. 이 기본 검사는 포트를 열지 않는 로컬 HTTP 전송 시험입니다. 사용자가 별도 연결 시험을 요청하면 내 PC의 127.0.0.1에만 서버를 열어 확인합니다. 소스가 생성됐다고 CLI에 MCP가 등록되거나 다른 프로젝트에서 자동 사용되는 것은 아닙니다.

전사에 전달할 때: 기본 제출물은 src/mcp/tools.py와 추가 의존성·필요한 설정 항목명·사용 예제·시험 결과입니다. 업무용 보조 모듈이 있다면 목록을 함께 냅니다. 로컬 설정, 비밀값, 개인 기억, 개발 환경은 제외합니다. 담당자가 실제 전사 SDK·인증·권한을 검증한 뒤 배포합니다. “로컬 시험 통과”와 “전사 배포 완료”는 다릅니다. Markdown 스킬도 공유할 수 있지만 필요한 상대 참조 파일까지 포함하고, 개인 경로나 하네스 전용 호출을 그대로 전사에 적용하지 않습니다.

요청 예문선택 후 Ctrl+C로 복사

연결이 없으면 준비 안내와 실제 조회 미확인인 절차 초안까지만 해줘.
도구 설치나 자동 로그인은 하지 마.

확인 순서는 기존 연결 → 대상 화면·항목·기간 → 최대 3건 시험 → 저장 범위 → 스킬 저장입니다. 이미 정한 저장 범위는 다시 묻지 않습니다. 같은 기능의 승인된 도구가 있으면 재사용합니다. 필요한 기능이 없을 때만 8-2의 표준 도구 제작·시험 절차를 따릅니다.

공통 브라우저 연결 도구(MCP)의 반입·설치·설정은 담당자의 별도 작업입니다. 이 하네스가 Chrome을 설치·실행하거나 로그인에 자동 접속하지 않습니다. 비밀번호·쿠키·토큰을 요청에 넣지 않으며, 인증 값과 네트워크 요청·응답 원문은 모델·스킬·로그로 전달하지 않습니다.

성공 확인: 실제 도구로 조회한 항목·조건·건수가 승인한 화면과 일치하고, 저장한 스킬의 위치·범위와 사용 예문을 받습니다. 조건에 맞는 공지가 없으면 0건도 정상일 수 있습니다. ‘초안 작성’, ‘스킬 저장’, ‘실제 조회 시험’을 나눠 확인합니다. 도구 이름이 목록에 보이거나 절차 안내가 완성된 것만으로 조회 성공이라 하지 않습니다.

연결이 없으면: 담당자에게 “이 사이트를 읽을 수 있는 승인된 브라우저 연결을 준비해 주세요”라고 요청하세요. 준비 전에는 위 가상 표 연습까지만 진행합니다.

9. 사용량과 결과 확인하기

사용 현황 · 결과 확인을 엽니다. 토큰이 미제공이면 0으로 해석하지 않습니다. 실행 구간과 질문·승인 대기를 구분하고 CLI 보고값을 무조건 요청별로 합산하지 않습니다.

준비·결과 확인에서 내용·범위·파일을 직접 확인한 뒤 통과/실패/미확인/중지를 기록합니다. 스킬 목록의 개수나 준비물 점수가 실제 업무 정확도를 대신하지 않습니다. 확인 기록 내보내기는 자동 전송하지 않으며, 기록 비우기는 대화·기억·결과 파일 삭제와 다릅니다.

성공 확인: 확인하지 않은 항목은 미확인으로 남고, 같은 예제로 재시험할 때 전후 결과를 비교할 수 있습니다. 일반 업무를 위해 매번 진단 화면을 열 필요는 없습니다.

10. 마무리 체크리스트와 의견

  • 실제 설치 범위와 작업 폴더를 구분했다.
  • 자료의 수치·범위를 직접 확인했다. 실제 파일 읽기와 대화 텍스트 요약을 구분했다.
  • 필요한 조건을 알려주고 실제 초안과 결과 파일을 열었다.
  • 이번 결과 수정과 장기 선호 저장을 구분했다.
  • 선택한 경우 기억을 새 대화에서 조회·비교했다.
  • 팀의 공유 기준과 개인 기억, Claude 자체 자동 기억이 다른 저장 방식임을 구분했다.
  • A/B 폴더에서 프로젝트 지침과 개인 저장소의 적용 범위를 따로 비교했다.
  • 개인 스킬은 발견·본문 로드·실제 결과를, 도구는 생성·시험·활성화를 구분했다.
  • 웹 조회를 선택했다면 가상 표 연습·스킬 저장·실제 브라우저 시험을 구분했다.
  • 토큰·시간의 미제공 값과 실제 관찰값을 구분했다.
  • 불필요하거나 바꾸고 싶은 기능을 핸드북의 개선 의견 양식에 적었다.

Claude Code 기본 사용법

Claude Code가 처음인 분을 위한 설명입니다. 명령어를 외우기 전에 어느 폴더에서, 어떤 자료로, 무엇을 만들지 정하면 됩니다. 작은 실습은 시작하기, 키와 명령은 명령어·단축키에서 확인하세요.

1. Claude Code와 Company Agent는 무엇이 다른가요?

Claude Code는 요청을 이해하고 파일 읽기·수정·명령 실행 같은 도구를 사용할 수 있는 프로그램입니다. 대화만 하는 것과 달리 실제 파일이나 외부 시스템에 영향을 줄 수 있습니다. 실행할 수 있는 범위는 연결된 도구와 권한에 따라 달라집니다. 공식 소개

구분 하는 일
AI 모델 요청을 해석하고 답이나 작업 계획을 만듭니다. 사내에서는 승인된 모델을 사용합니다.
Claude Code 모델과 대화하면서 파일·명령·도구를 연결합니다.
Company Agent 회사 기준, 업무 스킬, 기억 관리, 실행·결과 확인 절차를 더합니다. 별도의 AI 계정을 만드는 기능은 아닙니다.
Workspace 기존 Claude Code를 사용하는 별도 입력·파일 선택·확인 화면입니다. 원본 CLI의 모든 메뉴와 단축키가 같은 것은 아닙니다.

이미 회사 환경에서 Claude Code가 된다면 개인 API 키·모델·로그인을 새로 설정하지 않습니다. 연결 문제를 해결하려고 기존 설정 전체를 초기화하지 마세요.

2. 작업 폴더부터 확인하세요

작업 폴더는 이번 업무의 출발점입니다. 처음에는 빈 연습 폴더를 사용하고 회사 문서·메일·공용 폴더는 넣지 않습니다. CLI·VS Code·Workspace 중 회사에서 허용한 화면으로 그 폴더를 선택하세요.

폴더를 선택했다고 PC의 다른 경로에 접근할 수 없게 되는 것은 아닙니다. 요청에 대상과 제외 범위를 적고, 승인 화면의 실제 경로를 확인합니다.

요청 예문선택 후 Ctrl+C로 복사
지금 선택한 연습 폴더가 어디인지 알려줘.
바로 아래 파일 이름만 확인하고, 다른 폴더나 파일 본문은 읽지 마.
파일·설정·기억을 만들거나 변경하지 마.

파일을 지정할 때는 CLI의 @ 목록이나 사용 중인 화면의 파일 선택을 이용합니다. 파일을 첨부한 것과 전체 내용을 실제로 읽은 것은 다릅니다. 페이지·시트·읽은 범위를 결과에서 확인하세요.

3. 요청하고 확인하는 기본 순서

  1. 요청: 목적, 자료, 결과 형식, 하지 말아야 할 일을 적습니다.
  2. 선택: 디자인·저장 위치처럼 필요한 질문에 답합니다.
  3. 확인: 파일 읽기·변경·발송 안내가 나오면 대상과 범위를 봅니다.
  4. 실행: 같은 요청을 다시 보내지 말고 결과나 추가 질문을 기다립니다.
  5. 검증: 실제 결과 파일과 숫자를 열어 확인하고 미확인 부분을 구분합니다.

설명·계획만 원하면 실제 변경을 하지 말라고 적으세요. 실제 작업을 원하면 확인한 계획의 어느 범위를 실행할지 말합니다.

요청 예문선택 후 Ctrl+C로 복사
가상 실적 3개월치를 설명할 보고서를 만들고 싶어.
먼저 필요한 자료와 진행 계획만 알려줘.
아직 파일 생성, 프로그램 설치, 설정 변경은 하지 말고 내 답변을 기다려줘.

Company Agent는 관련 스킬이 있으면 설명서 본문을 읽어 적용하고, 없으면 허용된 일반 방식으로 진행합니다. 스킬이 둘 이상 같은 역할을 한다면 기존 우선 선택이나 내 답변을 따릅니다. “스킬 사용”이라는 말뿐 아니라 실제 본문 로드와 업무 결과를 따로 확인합니다.

2. 용어를 쉽게 이해하기

용어 여기서의 의미 오해하기 쉬운 점
CLI 기존 Claude Code 실행 프로그램 Workspace는 이를 대체하는 별도 AI가 아니라 입력·확인 창
하네스 AI의 업무 절차·도구·설정·검증을 연결하는 틀 모델 자체를 더 똑똑하게 학습시키는 기능은 아님
스킬(Skill) 업무별 처리 설명서 설치된 프로그램·실행 권한과는 별개
후크(Hook) 요청 시작·도구 실행·종료 시 자동으로 호출되는 처리 모든 후크가 차단 장치인 것은 아님
MCP 외부 도구를 CLI에 연결하는 방식 연결만으로 관련 스킬이 자동 활성화되는 것은 아님
작업자(Agent) 조율자가 맡긴 업무를 수행하는 별도 실행 역할 이름이 표시됐다고 실제 실행이 증명되는 것은 아님
기억(Memory) 다음 업무에 참고할 내용. 공통 지식과 내 선호·업무 지식을 관리 주체로 구분 원본 문서·대화 전체를 저장하는 창고가 아님
지식(Knowledge) 기억 중 출처를 확인할 용어·계산식·업무 자료 별도 관리 영역이 아님. 참고 자료가 명령이나 권한이 되는 것도 아님

3. 세 범위, 두 종류의 내용

범위 내용과 저장 위치 누가 바꾸나요? 어디에서 이어지나요?
회사 공통 설치에 연결된 배포 지식과 공통 기준·스킬·후크 담당자가 검토·배포. 사용자 화면은 읽기 전용 같은 배포본과 연결 설정을 사용하는 환경
개인 전체 선호·지식·도구는 개인 저장소, 새 스킬은 현재 Claude 설정 폴더 나. 저장 전 범위와 내용 확인 같은 사용자 설정·저장소를 쓰는 여러 작업 폴더
이 프로젝트 기억·도구는 비공개 프로젝트 저장소, 새 스킬·폴더 지침은 실제 프로젝트 파일 내 자산은 나. 프로젝트 파일은 공유 여부 확인 현재 프로젝트 범위에서 사용

‘회사 공통’은 회사가 관리하는 내용이며 ‘개인 전체/이 프로젝트’는 내 자료를 적용할 범위입니다. 각 화면에서 기억·지식 / 업무 구성을 선택합니다.

새 기억·지식·스킬·도구를 저장할 때는 어디에 저장할까요? → 개인 전체 / 이 프로젝트를 선택합니다. 이미 요청에 범위를 명시했다면 재질문하지 않습니다. 기존 항목 수정은 원래 범위를 유지하고, 회사 공통은 직접 저장 선택지에서 제외합니다. ‘내 것’이라고만 말하면 두 범위 중 하나를 물어봅니다. 화면에서도 새 저장 범위는 미선택으로 시작합니다.

실제 저장 경로는 구성 한눈에에서 확인합니다. 같은 PC의 새 대화라도 같은 설치·저장소를 사용해야 기억을 다시 조회할 수 있습니다. 다른 PC나 계정으로 자동 동기화하지 않으며, 옮겨 쓰려면 담당자와 백업·이전·연결 설정을 확인한 뒤 다시 조회합니다. 프로젝트 폴더 복사나 이름 변경만으로 프로젝트 개인 기억이 따라오지는 않습니다. ‘개인 전체’에 저장할 수 없다는 안내가 나오면 담당자에게 설치 범위를 확인하세요.

Claude 자체 자동 기억은 이 화면의 Company Agent 기억과 별도로 관리합니다. 원래 CLI에서 해당 기억의 경로·설정을 확인하며, 두 저장소를 자동 합치지 않습니다. 비공개 기억·도구는 프로젝트 폴더 공유만으로 전달되지 않습니다. 새 프로젝트 스킬은 폴더 안의 파일이므로 공유 전에 내용을 확인하세요.

확인할 저장소 일반적인 위치 또는 구분
Company Agent 개인 전체 현재 User 설치 기본값은 %LOCALAPPDATA%\CompanyAgent\states\user. 기존 설치 등록·사용자 지정 위치가 우선
User 설치의 프로젝트 개인 자료 위 저장소의 project-scopes/<폴더 식별자>/. 현재 작업 폴더의 절대경로로 구분
별도 Project 설치 기본값은 %LOCALAPPDATA%\CompanyAgent\states\projects\<폴더 식별자>. 해당 설치의 등록된 stateRoot가 우선
Claude Code 자체 설정·기억 별도 Claude 설정 루트. 일반적으로 %USERPROFILE%\.claude를 사용하지만 실제 설정·기억 위치는 원래 CLI에서 확인
새 개인 전체 스킬 현재 Claude 설정 폴더의 skills/<이름>/SKILL.md. CLAUDE_CONFIG_DIR을 사용하면 그 설정 폴더를 따름
새 프로젝트 스킬 현재 프로젝트의 .claude/skills/<이름>/SKILL.md. 폴더와 함께 공유 가능

각 Company Agent 저장소 안에서 기억은 memory/items/, 학습 이력은 learning/state.json에 있습니다. 기존 비공개 스킬은 personal-root/.claude/skills/에 그대로 보관합니다. 새 스킬의 본문은 위 Claude 기본 위치에 한 개만 두며 하네스에는 관리 정보만 기록합니다. User 설치의 프로젝트별 저장소와 별도 Project 설치를 혼동하거나, 같은 폴더 이름·상위·하위 관계만으로 같은 기억을 쓴다고 가정하지 마세요. 기존 자료는 자동 이동하지 않습니다.

저장한 스킬의 실제 원본은 한 곳입니다. 새 스킬은 /스킬이름으로 사용하고 “저장한 스킬을 수정해줘”라고 요청하면 같은 원본을 갱신합니다. 기존 비공개 스킬은 이름으로 실행을 요청하거나 /company-agent:skills 스킬이름 실행을 사용합니다. 기존 파일·참조·도구 연결을 유지하며 편집 중 다른 변경을 발견하면 덮어쓰지 않습니다. 생성 결과는 원본 위치와 구조 확인 범위를 알려주며 현재 세션 발견·업무 성공을 대신하지 않습니다.

새 /스킬이름이 목록에 없으면 원본 Claude의 /reload-skills 또는 새 대화로 확인합니다. 기존 user-invocable, disable-model-invocation, context, model, allowed-tools 등의 조건은 그대로 둡니다. 같은 이름의 native 스킬·기존 command는 덮어쓰지 않습니다. 하네스의 선호 선택은 Claude 자체 이름 우선순위를 바꾸지 않으며, 기존 모델·MCP·권한 설정도 유지합니다.

부서 기준도 회사 영역에 포함합니다. 프로젝트는 “어느 폴더에 적용할지”이지 세 번째 정책 소유자가 아닙니다. 회사 필수 기준, 개인화 가능한 기본값, 참고 지식은 구분합니다. required라는 표시만으로 운영체제 권한이 강제되는 것은 아닙니다.

User 설치와 Project 설치는 적용 범위·개인 저장소가 다를 수 있습니다. 다른 범위의 기억이 보이지 않는다고 삭제됐다고 단정하거나 자동으로 합치지 마세요. 회사 업데이트는 개인 기억·지식·스킬과 기존 모델·MCP 설정을 임의로 초기화하지 않습니다.

‘공통’과 ‘전역 설치’는 다릅니다. 공통은 관리 주체, User/Project는 적용 범위입니다. ‘내 사용자 설치’는 내 여러 폴더에, ‘이 프로젝트’는 해당 설치 범위에 적용됩니다. User 설치 하나로 다른 직원에게 배포되거나 개인 기억이 공유되지는 않습니다. ‘폴더에 있으니 내 것’이라고도 판단하지 마세요. 함께 받은 프로젝트 파일은 공유 구성일 수 있습니다.

프로젝트 CLAUDE.md는 목적·단위·완료 조건을 적는 설명서입니다. 공통 스킬·후크·연결·검증을 포함하는 하네스 전체와 같지 않습니다. 작은 규칙은 짧은 프로젝트 지침으로 시작하고, 반복 업무에 여러 역할이 필요할 때 프로젝트 하네스를 생성하세요. 기존 CLAUDE.md를 생성기가 교체하지 않습니다. 시작하기 7단계에서 A/B 폴더로 차이를 시험합니다.

새 작업 폴더의 첫 시작: 파일 읽기·작성·수정 같은 작업 요청이 들어오면 지침이 없는 작업 폴더에 짧은 기본 CLAUDE.md를 한 번 생성합니다. 기존 파일·.claude/CLAUDE.md·부모 프로젝트 지침이 있으면 보존합니다. 홈·시스템·설치/설정 폴더, 계획 모드, 변경 금지 요청에서는 생성하지 않습니다. 별도 AI 호출이나 전체 폴더 탐색 없이 시작 안내만 만들므로 /init의 코드 분석과 동일하지 않습니다. 실행법·프로젝트 지식은 확인 후 별도로 보완합니다. 단순히 폴더를 여는 것만으로는 생성하지 않습니다.

질문과 피드백 언어: Company Agent의 질문 제목·선택지·설명·추천 표시·승인 안내는 기본 한국어입니다. 흔한 영문 선택 문구는 추가 AI 호출 없이 바꾸고, 알 수 없는 영문 설명의 재작성은 제한된 횟수만 요청합니다. 대화 언어를 따로 요청하면 그 범위를 따르며, 영어 보고서 요청만으로 선택 질문까지 영어로 바꾸지는 않습니다. 코드·파일명·제품명과 Claude 자체 메뉴·권한 버튼·Windows/Office 화면은 원래 표기를 유지할 수 있습니다.

4. 기본 스킬 14개와 이전 이름 1개

이 폴더의 구성 지도: Workspace의 기억·하네스 관리 → 구성 한눈에에서 회사 공통 / 개인 전체 / 이 프로젝트를 나란히 볼 수 있습니다. 이름·상태·파일 위치를 펼쳐 확인하고 HTML로 저장할 수 있습니다.

설정 켜짐, 사용 가능, 정의 발견, 꺼짐, 미확인을 구분합니다. 스킬의 본문 로드 기록은 현재 폴더와 대화의 동일 본문 기록을 대조한 경우에만 표시하며 업무 적용·성공 증거가 아닙니다. MCP는 연결을 시도하지 않고 등록 상태만 보여줍니다. 저장한 HTML에는 경로와 이름이 포함되므로 공유 전 확인하세요. 전체 서버/OS 정책·실행 옵션·원격 도구나 다른 프로젝트 기억을 모두 탐색한 결과가 아닙니다.

아래는 기본 제공 스킬입니다. 추가로 설치한 항목은 PC마다 다를 수 있습니다. 실제 목록은 Claude Code의 /skills, /company-agent:skills 또는 Workspace의 준비·결과 확인 → 발견한 스킬에서 확인하세요.

호출명에는 company-agent:가 붙습니다. company는 이 플러그인의 스킬 호출명이 아닙니다. 평소에는 이름 대신 자연어로 요청하며, 자동 선택을 점검할 때만 정확한 이름을 지정해 비교하세요.

요청에 참고할 기억은 허용된 개인 전체·현재 프로젝트에서 관련도 순으로 고르고, 같은 관련도일 때 프로젝트 항목을 먼저 봅니다. 중복을 제외하고 합계 최대 5개를 참고 대상으로 고릅니다. 프로젝트 기억이 많아도 더 관련 있는 개인 기억을 무조건 뒤로 밀지 않습니다. 이는 검색 순서이지 회사 정책이나 저장 범위를 바꾸는 규칙이 아닙니다. 목록에 없는 기억도 남아 있을 수 있으므로 범위와 제목을 지정해 조회하세요.

저장할 때 개인 전체 / 이 프로젝트를 한 번 선택합니다. 새 스킬은 위 Claude 기본 폴더에, 새 도구는 선택한 비공개 저장소의 mcp/servers에 보관합니다. 회사 플러그인 캐시는 수정하지 않습니다. 스킬에는 MCP 활성화 단계가 없습니다. 도구는 후보 생성 → 정상·잘못된 입력 시험 → 검증 기록 → 연결 등록 → Claude 재시작 후 실제 호출 순서입니다. 스킬은 필요한 도구를 연결해 사용하고, 없는 도구를 임의 코드로 대신하지 않습니다. 도구의 코드·입력 형식이 바뀌면 재시험하고 연결된 스킬도 확인합니다.

기존 도구가 재시험을 요청하면: 과거 검사 기록으로 새 검사 기준을 통과했다고 보지 않습니다. 해당 도구가 원래 저장된 범위에서 정상 입력과 잘못된 입력을 다시 시험하고, 통과한 현재 기록으로 활성화·연결을 확인하세요. JSON 입력·출력은 선언한 형식·필수 값·범위 등을 검사하며, 지원하지 않는 조건은 무시하지 않고 알립니다. 검사 조건을 지워 통과시키지 않습니다. 재시험 안내가 소스 삭제나 이미 별도 등록된 MCP의 자동 해제를 뜻하지는 않습니다.

“깔끔하게”, “세련되게”만으로 원하는 모양을 설명하기 어려울 때 참고하세요. 첨부된 스타일 키워드 이미지 3장의 30개 용어를 쉬운 설명과 요청 예문으로 정리했습니다. 용어를 외울 필요 없이 마음에 드는 느낌 하나를 골라 쓰면 됩니다.

2. 기본 분위기와 정보 강조

그라디언트 배경 (Gradient background) 색이 자연스럽게 이어지는 배경입니다. 표지나 구역 구분에 쓰고, 긴 본문 뒤에서는 은은하게 사용합니다. “표지에 연한 하늘색과 보라색이 이어지는 배경을 넣고 본문은 흰색으로 해줘.”
글래스모피즘 (Glassmorphism) 반투명 유리처럼 보이는 카드입니다. 배경색이 비치고 얇은 테두리나 흐림 효과가 깊이감을 줍니다. “유리 같은 카드를 쓰되 글자가 비치지 않게 바탕을 충분히 밝게 해줘.”
미니멀·스위스 (Minimal / Swiss style) 미니멀은 불필요한 장식을 줄이는 방향, 스위스 스타일은 격자 정렬과 글자 위계를 중시하는 방향입니다. 업무 보고서에 활용하기 좋습니다. “장식은 줄이고 제목·수치·본문을 격자에 맞춰 정렬해줘. 여백은 넉넉하게 해줘.”
다크 모드 (Dark mode) 어두운 바탕과 밝은 글자를 쓰는 화면입니다. 여기서는 색 표현을 뜻하며 테마 전환 버튼이 자동으로 생기는 것은 아닙니다. “검정에 가까운 남색 바탕에 밝은 글자를 쓰고, 표와 보조 설명도 선명하게 해줘.”
그레인 텍스처 (Grain texture) 종이나 필름처럼 미세한 입자감을 더합니다. 차분한 소개 자료에 어울리며 글자 위에 거친 무늬를 겹치지 않습니다. “배경에만 아주 약한 종이 입자감을 넣고 표·글자 주변은 깨끗하게 유지해줘.”
빅 타이포 (Big typography) 핵심 단어나 숫자를 크게 보여주는 방식입니다. 한 장에 메시지 하나를 강조할 때 좋습니다. “핵심 수치 하나를 크게 보여주고, 단위와 비교 기준은 바로 아래에 붙여줘.”

3. 카드와 입체감

플랫 디자인 (Flat design) 그림자와 질감을 줄이고 단순한 색 면·선·아이콘으로 표현합니다. 정보가 많은 화면을 정리하기 좋습니다. “질감과 그림자를 빼고 색 면과 가는 구분선으로 정보 구역을 나눠줘.”

머티리얼 디자인 (Material Design) 면이 층층이 놓인 것처럼 높이와 그림자로 관계를 표현하는 디자인 체계입니다. 그림자 하나만 넣는 것과는 다릅니다. “카드·버튼의 간격과 높이감을 일관되게 해줘. 중요한 조작은 구분하기 쉽게 보여줘.”
클레이모피즘 (Claymorphism) 점토처럼 둥글고 부풀어 보이는 형태입니다. 부드러운 하이라이트와 그림자를 쓰며 친근한 안내에 어울립니다. “소개 카드에 둥근 점토 느낌을 약하게 적용하고 본문 표는 평평하고 또렷하게 해줘.”
스큐어모피즘 (Skeuomorphism) 나무·가죽·실제 버튼 같은 사물의 재질과 모양을 닮게 표현합니다. 단순한 그림자 효과와 구분합니다. “표지에만 종이 노트 같은 재질감을 쓰고, 본문은 실제 노트 그림이 아닌 편집 가능한 글자로 해줘.”
3D 렌더 (3D render) 입체 물체를 조명·재질·그림자와 함께 그린 이미지입니다. 실제 3D 모델링이나 편집 기능이 있다는 뜻은 아닙니다. “표지에 부드러운 입체 장식을 원해. 실제 이미지가 필요한지, 현재 도구로 가능한 표현은 무엇인지 먼저 알려줘.”

4. 글자와 그래픽을 강하게 쓰는 표현

키네틱 타이포그래피 (Kinetic typography) 글자의 움직임과 시간 차로 메시지를 강조합니다. 정적 HTML·PDF·PPT 이미지에서는 같은 움직임을 전달할 수 없습니다. “글자로 변화감을 강조하고 싶어. 정적 보고서에서는 움직임 대신 굵기·크기·배치로 표현해줘.”

멤피스 디자인 (Memphis design) 낙서 같은 선과 작은 도형, 서로 대비되는 색을 자유롭게 배치합니다. 활기찬 행사·교육 안내에 어울립니다. “행사 안내 표지에 작은 원·삼각형·물결선을 넣고 일정표 주변은 비워줘.”
브루탈리즘(웹) (Brutalism) 구조를 드러내고 거칠거나 덜 꾸민 인상을 주는 표현입니다. 굵은 선과 원색을 쓰는 변형도 있지만 항상 같은 모양은 아닙니다. “꾸밈을 줄이고 제목·표·버튼의 경계를 확실히 해줘. 굵은 테두리와 대비는 필요한 곳에만 써줘.”

스칸디나비안 (Scandinavian) 밝은 바탕, 부드러운 중성색, 자연스러운 재료 느낌을 사용합니다. 편안한 소개 자료에 어울립니다. “흰색·연한 베이지·차분한 초록을 쓰고 여백을 넓게 해줘. 나무 질감은 꼭 필요할 때만 넣어줘.”
저팬디 (Japandi) 절제된 구성과 따뜻한 자연색을 조합하는 방향입니다. 낮은 색 대비를 쓰더라도 글자는 선명해야 합니다. “저팬디 느낌의 차분한 베이지와 회색, 넓은 여백을 원해. 글자 대비는 충분히 유지해줘.”
와비사비 (Wabi-sabi) 불규칙함과 자연스러운 재료의 흔적을 살리는 미적 태도입니다. 자료의 오류나 어긋난 정렬을 허용하라는 뜻은 아닙니다. “표지의 장식만 자연스럽고 비정형적으로 하고, 수치·표·정렬은 정확하게 유지해줘.”
아르누보 (Art Nouveau) 식물 줄기 같은 유기적인 곡선과 장식 무늬를 사용합니다. 감성적인 표지나 구역 장식에 어울립니다. “가느다란 식물 곡선을 모서리에만 넣고 본문 글꼴과 표는 간결하게 해줘.”

레트로 퓨처리즘 (Retrofuturism) 과거 사람들이 상상한 미래의 모습을 표현합니다. 둥근 기계 모양, 복고 색감 등 참고 방향을 구체적으로 지정하면 좋습니다. “크림색·주황·청록과 둥근 모서리로 복고적인 미래 분위기를 내고 수치는 현대적인 표로 정리해줘.”
Y2K 은빛 금속, 광택, 파스텔 등으로 세기 전환기의 디지털 분위기를 표현하는 이름입니다. 모든 요소를 동시에 쓸 필요는 없습니다. “은빛과 연보라 포인트로 디지털 느낌을 주고, 본문에는 금속 효과나 반짝임을 넣지 마.”

사이버펑크 (Cyberpunk) 어두운 배경 위 네온색과 기술적인 요소를 강조합니다. 빛나는 글자를 많이 쓰면 읽기 어려워질 수 있습니다. “검정에 가까운 배경에 청록 포인트를 쓰고, 네온은 구분선에만 적용해줘. 본문은 빛 번짐 없이 해줘.”
