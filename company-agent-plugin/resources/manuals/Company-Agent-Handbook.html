회사 공통 / 개인 전체 / 이 프로젝트를 먼저 구분하는 사용 설명서입니다. 각 범위 안에서 기억·지식과 업무 구성(스킬·도구·규칙)을 확인합니다.

기준: 코어 1.4.16과 Workspace 0.4 · 2026-09-19. 이 문서를 읽는 것만으로 기존 설치본이 업데이트되지는 않습니다. 구성 지도·세 범위 관리·Cua 준비 확인은 1.4.16 하네스와 같은 Release의 Workspace 0.4 ZIP을 사용하세요. Cua 실제 조작은 별도 승인·운영 시험이 필요합니다.

1. 처음이라면 여기부터

먼저 처음부터 따라 하기를 열고 작은 가상 업무 하나를 해보세요. 이 핸드북은 기능의 뜻과 바꾸는 방법이 궁금할 때 찾아보는 문서입니다. HTML판은 내려받아 더블클릭해 읽고 브라우저의 찾기·인쇄를 사용할 수 있습니다. 문서를 읽는 데 AI 호출·로그인은 필요 없습니다.

회사에서 준비한 것은 업무 절차와 설정입니다. Claude Code와 승인된 Python, 필요한 Office·MCP는 별도 준비물입니다. “스킬이 목록에 있다”와 “업무를 실제로 성공했다”는 다릅니다.

2. 용어를 쉽게 이해하기

용어 여기서의 의미 오해하기 쉬운 점
CLI 기존 Claude Code 실행 프로그램 Workspace는 이를 대체하는 별도 AI가 아니라 입력·확인 창
하네스 AI의 업무 절차·도구·설정·검증을 연결하는 틀 모델 자체를 더 똑똑하게 학습시키는 기능은 아님
스킬(Skill) 업무별 처리 설명서 설치된 프로그램·실행 권한과는 별개
후크(Hook) 요청 시작·도구 실행·종료 시 자동으로 호출되는 처리 모든 후크가 차단 장치인 것은 아님
MCP 외부 도구를 CLI에 연결하는 방식 연결만으로 관련 스킬이 자동 활성화되는 것은 아님
작업자(Agent) 조율자가 맡긴 업무를 수행하는 별도 실행 역할 이름이 표시됐다고 실제 실행이 증명되는 것은 아님
기억(Memory) 다음 업무에 참고할 내용. 공통 지식과 내 선호·업무 지식을 관리 주체로 구분 원본 문서·대화 전체를 저장하는 창고가 아님
지식(Knowledge) 기억 중 출처를 확인할 용어·계산식·업무 자료 별도 관리 영역이 아님. 참고 자료가 명령이나 권한이 되는 것도 아님

3. 세 범위, 두 종류의 내용

범위 무엇을 담나요? 누가 바꾸나요?
회사 공통 배포 지식과 공통 기준·스킬·후크 담당자가 검토·배포. 사용자 화면은 읽기 전용
개인 전체 여러 프로젝트에서 쓸 선호·지식·개인 스킬·도구 나. 저장 전 범위와 내용 확인
이 프로젝트 해당 프로젝트의 개인 기억·자산, 프로젝트 지침 내 자산은 나. 공유 프로젝트 파일은 작성·공유 주체 확인

‘회사 공통’은 배포 주체이며 ‘개인 전체/이 프로젝트’는 적용 범위입니다. 각 화면에서 기억·지식 / 업무 구성을 선택합니다. 기존의 공통 기억·내 기억·공통 하네스·내 하네스라는 네 메뉴를 외울 필요는 없습니다. 기존 원본은 이동·복제하지 않습니다.

새 기억·지식·스킬·도구를 저장할 때는 어디에 저장할까요? → 개인 전체 / 이 프로젝트를 선택합니다. 이미 요청에 범위를 명시했다면 재질문하지 않습니다. 기존 항목 수정은 원래 범위를 유지하고, 회사 공통은 직접 저장 선택지에서 제외합니다. ‘내 것’이라고만 말하면 두 범위 중 하나를 물어봅니다. 화면에서도 새 저장 범위는 미선택으로 시작합니다.

User 설치의 프로젝트 전용 개인 자료는 기존 상태 경로 아래 project-scopes/<폴더 식별값>에 보관합니다. Project 설치의 기존 상태 경로는 그대로 사용합니다. Project 전용 설치에서 개인 전체 등록이 없으면 저장 위치를 임의로 만들지 않고 설치 확인을 안내합니다. 개인 자료는 프로젝트 파일 공유만으로 동료에게 전달되지 않습니다. Claude 자체 자동 기억은 개인 PC 안에서도 프로젝트별이며, 이 화면의 Company Agent 기억과 자동 통합하지 않습니다.

부서 기준도 회사 영역에 포함합니다. 프로젝트는 “어느 폴더에 적용할지”이지 세 번째 정책 소유자가 아닙니다. 회사 필수 기준, 개인화 가능한 기본값, 참고 지식은 구분합니다. required라는 표시만으로 운영체제 권한이 강제되는 것은 아닙니다.

User 설치와 Project 설치는 적용 범위·개인 저장소가 다를 수 있습니다. 다른 범위의 기억이 보이지 않는다고 삭제됐다고 단정하거나 자동으로 합치지 마세요. 회사 업데이트는 개인 기억·지식·스킬과 기존 모델·MCP 설정을 임의로 초기화하지 않습니다.

‘공통’과 ‘전역 설치’는 다릅니다. 공통은 관리 주체, User/Project는 적용 범위입니다. ‘내 사용자 설치’는 내 여러 폴더에, ‘이 프로젝트’는 해당 설치 범위에 적용됩니다. User 설치 하나로 다른 직원에게 배포되거나 개인 기억이 공유되지는 않습니다. ‘폴더에 있으니 내 것’이라고도 판단하지 마세요. 함께 받은 프로젝트 파일은 공유 구성일 수 있습니다.

프로젝트 CLAUDE.md는 목적·단위·완료 조건을 적는 설명서입니다. 공통 스킬·후크·연결·검증을 포함하는 하네스 전체와 같지 않습니다. 작은 규칙은 짧은 프로젝트 지침으로 시작하고, 반복 업무에 여러 역할이 필요할 때 프로젝트 하네스를 생성하세요. 기존 CLAUDE.md를 생성기가 교체하지 않습니다. 온보딩 코스 7단계에서 A/B 폴더로 차이를 시험합니다.

4. 기본으로 들어 있는 스킬 12개

이 폴더의 구성 지도: Workspace의 기억·하네스 관리 → 구성 한눈에에서 회사 공통 / 개인 전체 / 이 프로젝트를 나란히 볼 수 있습니다. 이름·상태·파일 위치를 펼쳐 확인하고 HTML로 저장합니다. 조회·새로고침에 AI를 호출하지 않으며 스킬 본문이나 지침을 대화에 자동 주입하지 않습니다. 기존 설치본에는 새 코어와 Workspace 반영이 필요합니다.

설정 켜짐, 사용 가능, 정의 발견, 꺼짐, 미확인을 구분합니다. 스킬의 본문 로드 기록은 현재 폴더와 대화의 동일 본문 기록을 대조한 경우에만 표시하며 업무 적용·성공 증거가 아닙니다. MCP는 연결을 시도하지 않고 등록 상태만 보여줍니다. 저장한 HTML에는 경로와 이름이 포함되므로 공유 전 확인하세요. 전체 서버/OS 정책·실행 옵션·원격 도구나 다른 프로젝트 기억을 모두 탐색한 결과가 아닙니다.

아래는 이 소스에 포함된 기본 구성입니다. 개인·다른 플러그인·회사 추가 구성은 PC마다 다릅니다. 실제 목록은 원본 CLI의 /skills, /company-agent:skills 또는 Workspace의 준비·결과 확인 → 발견한 스킬에서 확인하세요. 목록 조회는 설치나 실행 성공 확인이 아닙니다.

호출명에는 company-agent:가 붙습니다. company는 이 플러그인의 스킬 호출명이 아닙니다. 평소에는 이름 대신 자연어로 요청하며, 자동 선택을 점검할 때만 정확한 이름을 지정해 비교하세요.

자동 선택의 실제 흐름: 사용 가능한 목록의 용도 비교 → 관련 본문만 로드 → 필요한 업무 실행. 맞는 스킬이 없으면 허용된 일반 방식으로 진행합니다. 같은 역할이 겹치면 기존 우선 선택 또는 사용자 답변을 따릅니다. 읽기와 제작처럼 서로 다른 단계는 중복이 아닙니다.

목록은 모든 스킬의 본문이 아닙니다. 목록을 전달했다는 로그만으로 모델이 이를 적용했다고 볼 수 없습니다. 로컬 목록도 모든 원격·동적·기본 내장 스킬을 완전히 열거한다고 보장하지 않습니다.

5. 자동으로 동작하는 후크 7개

후크는 별도 버튼 없이 CLI 이벤트에 따라 실행됩니다. 안내, 실행 관찰, 정책 판단, 완료 검토를 구분해서 읽어주세요. 모델의 지침 준수와 운영체제 권한을 모두 보장하는 장치는 아닙니다.

PreToolUse 실행 전 스킬 준비와 대상 회사 MCP 정책 확인, 회사 작업자에 실행 정보 전달 명확한 단일 스킬의 누락은 요청/목록 기준 최대 한 번 교정 가능. 무관한 업무를 계속 차단하지 않음
PermissionRequest 정확히 확인된 읽기 전용 내부 준비 명령의 제한된 승인 처리 현재 범위는 신뢰된 Python 진입점의 doctor/mail-capabilities 등 정해진 형태. 임의 명령·Office 열기·파일 쓰기 자동 승인이 아님
PostToolUse 도구 결과·스킬 본문 로드·변경 및 실행 관찰 기록 도구 호출/본문 로드와 업무 내용의 정확성은 별개
PostToolUseFailure 실행 실패 관찰, 보완에 필요한 상태 유지 출력을 못 봤다고 성공 기록을 만들지 않음
Stop 변경 작업의 완료 확인과 의미 있는 시점의 학습 검토 질문·승인·작업자 대기를 완료로 오인하지 않아야 함. 보정은 제한되며 무한 반복하지 않음

“아직 실행하지 않았습니다”라고 나오면 해당 동작은 실행되지 않은 것입니다. 반대로 내부 참고 안내가 표시됐다는 사실만으로 파일 권한 오류라고 단정하지 마세요. 같은 안내가 반복되면 멈추고 해당 요청·버전·실제 상태를 담당자에게 전달합니다. 샌드박스를 끄거나 성공 기록을 꾸며서 통과시키지 않습니다.

이 프로젝트에 다른 저장소의 team-guards, TDD Guard, AI-Ready 100점 진단이 기본 설치돼 있다고 가정하지 마세요. 여기의 구성은 위 목록과 실제 코드가 기준입니다.

6. 명령 3개와 작업자 3개

명령은 원본 CLI에서 사용할 수 있습니다. GUI는 터미널 전용 슬래시 화면 전체를 구현하지 않습니다. 필요하면 진행 중인 연결을 정리한 후 고급 · 원본 CLI 열기를 사용하세요.

명령 용도
/company-agent:skills 사용 가능한 스킬과 겹침 확인, 요청한 경우 사용할 후보·적용 범위 선택
/company-agent:learning 개인 자동 학습 내역 확인, 일시 중지/재개, 선택한 변경 복구
/company-agent:business-check 업무 기능의 의존성·준비 상태 확인. Office·메일을 실제로 열어 검증하지 않음
작업자 기본 모델 별칭 역할
company-agent:small-worker haiku 짧은 설명·조회·작은 수정
company-agent:medium-worker sonnet 일반 업무·개발·자료 분석
company-agent:large-worker opus 복잡한 설계·보안 검토·원인 분석·재사용 도구 제작

이 별칭이 사내 어느 HCP 모델로 연결되는지는 실제 회사 설정으로 확인합니다. UI가 임의로 모델을 바꾸거나 별도 모델 계정을 요구하지 않습니다. 작업자에게 위임했다는 문장 대신 실제 실행과 결과를 확인해야 합니다.

7. 범위별 기억과 업무 구성을 다듬는 방법

회사 공통 → 기억·지식 — 함께 참고, 담당자가 갱신

회사 공통 → 기억·지식에서 설치에 연결된 회사·팀의 배포 지식을 읽습니다. 회사 필수 규정과 실행 절차는 공통 하네스에서 봅니다. 현재 별도의 팀 공동 쓰기·실시간 동기화 메모리는 없습니다. 새 이름을 붙였다고 서버가 생긴 것은 아닙니다. 프로젝트 CLAUDE.md·일반 문서를 공통 기억 목록으로 자동 수집하지도 않습니다.

개인 전체 / 이 프로젝트 → 기억·지식 — 선호와 업무 지식을 한곳에서

Workspace 기억·하네스 관리 → 개인 전체 / 이 프로젝트 → 기억·지식 → 내 기억 추가 → 변경안 확인 → 확인하고 저장 순서입니다. 제목과 짧은 선호만 적고 원본 문서·계정 정보는 넣지 마세요. 사용 안 함, 수정, 이전 내용 복원안을 지원합니다. 저장 위치와 적용 범위가 같아야 새 대화에서도 비교할 수 있습니다. Claude Code 자체 자동 기억은 별도 관리하며 자동으로 합치거나 덮어쓰지 않습니다.

앞으로 내 보고서는 결론부터 짧게 설명하고 확인한 범위와 미확인 부분을 구분해줘.
이 표현 선호만 개인 기억에 저장하고 문서 본문은 저장하지 마.

자동 학습은 User 설치에서는 개인 전체, Project 설치에서는 해당 설치 저장소에서만 작동합니다. 명시적 저장 범위 선택은 학습 설정을 바꾸지 않습니다. 의미 있는 업무 완료 시 조건을 확인해 선호나 실제 읽은 개인 스킬의 제한된 점검 항목을 개선하며 User 설치의 프로젝트 전용 자산은 자동 수정하지 않습니다. 모든 교정을 즉시 영구 저장하는 것은 아닙니다. 공통 자료·회사 정책·프로젝트 CLAUDE.md를 자동 수정하지 않습니다. 원하지 않으면 내 기억 화면에서 자동 학습을 끄고 내역을 확인하세요. 끄기와 기존 기억 삭제는 다른 일입니다.

출처가 있는 용어·계산식은 같은 화면의 내 업무 지식 초안에서 저장하고, 직접 검토 후 사용으로 바꿉니다. 개인 초안을 만들었다고 공통 기억이 바뀌지 않습니다. 공통 기억 검토용 내보내기는 로컬 ZIP 생성이며 자동 업로드·회사 반영이 아닙니다. 전달 전 민감 내용을 검토하세요. 공통 자료로의 반영은 담당자의 검토·배포 단계입니다.

회사 공통 → 업무 구성 — 실행 방식과 공통 규정

공통 하네스는 회사 업무 기준·공통 스킬·후크 정의를 확인하는 화면입니다. 목록이 있다는 사실과 현재 CLI에서 실제 실행됐다는 사실은 다릅니다. 화면에 수정·삭제 버튼을 두지 않으며 개인 선호로 회사 필수 기준을 해제하지 않습니다.

개인 전체 / 이 프로젝트 → 업무 구성 — 내 추가 구성과 폴더별 지침

개인 전체 / 이 프로젝트 → 업무 구성에서 개인·사용자 설치·프로젝트·외부 플러그인의 스킬 출처와 개인 도구 등록 기록을 확인합니다. 이는 모든 외부 도구의 연결 상태 목록이 아닙니다. 외부 설치 원본과 MCP 자격증명을 편집하지 않습니다. 등록·활성화 기록만으로 실행 성공을 판정하지 마세요.

같은 화면의 이 폴더에만 적용할 업무 지침에 목표·입력·결과물·완료 기준을 적습니다. 저장 파일은 .claude/rules/company-workspace-brief.md이며 기존 CLAUDE.md와 다릅니다. 기존 또는 직접 수정한 지침은 덮어쓰지 않습니다. 회사 공통 규정을 개인 폴더에 복사해 별도 정책 계층으로 만들 필요는 없습니다.

개인 스킬·도구 만들기

반복하는 처리 순서는 스킬, 입력에 따른 일정한 계산은 로컬 스크립트 도구가 적합합니다. 외부 시스템 연결이 필요하지 않다면 MCP부터 만들지 않습니다. 사용 가능한 목록에 같은 기능이 있으면 먼저 비교하고, 이름이 겹치면 덮어쓰지 않습니다.

자산 생성기의 개인 스킬은 현재 stateRoot의 personal-root/.claude/skills에, 스크립트는 tools에 저장됩니다. 설치된 회사 플러그인 캐시는 수정하지 않습니다. 스킬은 생성 후 자체 목록에서 사용 가능하며, 스크립트는 candidate → 실제 시험 → 검증 기록 → 활성화 순서입니다. 하네스가 발견한 개인 스킬을 Claude의 /이름으로도 호출할 수 있는지는 별도 등록 확인이 필요합니다.

온보딩 코스 8단계에서 회의 메모 정리 스킬과 달성률 계산 도구를 만들어 봅니다. 이름 없는 자동 선택과 명시 사용을 따로 시험하고, 목표 0·누락 입력도 확인합니다. 안내서 읽기만으로 생성·활성화·공유되지는 않습니다. 생성된 코드는 Windows 사용자 권한으로 실행되므로 시험 통과를 OS 격리나 모든 안전성 보장으로 오해하지 마세요.

8. 느리거나 토큰을 많이 쓰면

  1. 요청에 대상 파일·확인 범위·완료 기준을 한 번에 적습니다.
  2. 디자인·양식 등 이미 답한 내용은 유지해 달라고 요청합니다.
  3. 새 주제는 새 대화로 나누고, 긴 자료는 필요한 범위부터 읽습니다.
  4. 표시 인코딩만 깨졌다면 파일 생성·발송 등 원래 업무부터 반복하지 않습니다.
  5. 화면 조작보다 기존 Office·전용 도구가 적합하면 그것을 먼저 사용합니다.

새 폴더의 CLAUDE.md 자동 생성, /revise-claude-md라는 별도 명령, 업무 종료마다 강제 /compact, 자동 후속 질문 전송은 이번 범위별 화면 정리에 추가하지 않았습니다. 현재의 개인 자동 학습과 CLI 자체 대화 압축을 프로젝트 문서 수정이나 공통 기억 공유로 설명하지 않습니다. 대화 압축과 기억 저장은 다른 일입니다.

Workspace 사용 현황은 CLI가 실제 제공한 토큰과 앱이 관찰한 실행·질문·승인 대기를 구분합니다. 빠진 값은 0이 아니라 미제공입니다. 요청 값이 세션 누적일 수 있으므로 서로 더하지 않습니다. 사내 모델 단가를 모르면서 청구 금액이나 절감률을 만들지 않습니다.

토큰 알림은 다음 요청부터의 안내이며 강제 예산 제한이 아닙니다. 과거 로그 분석은 사용자가 고른 파일만 대상으로 하며 자동으로 대화 전체를 검색하지 않습니다. 준비·결과 확인의 평가는 사용자가 직접 확인해 기록한 표본이지 모델 전체 성능 점수가 아닙니다.
