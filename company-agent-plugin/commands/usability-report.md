# 사용성 개선 보고서

사용자 요청: $ARGUMENTS

현재 업무 폴더, 기본 최근 7일입니다. 사용자가 이미 지정한 1~30일 기간은 그대로 사용하며 범위를 다시 묻지 않습니다. 다른 사람이나 다른 폴더의 기록은 묵시적으로 포함하지 않습니다.

1. 주입된 `company_agent_runtime.cliCommand` 접두부와 `stateRoot`, 현재 업무 폴더의 절대경로를 사용해 한 번 실행합니다. 예문의 `company-agent`만 실제 접두부로 바꿉니다.
   `company-agent usability-report --state-root "<stateRoot>" --project-root "<현재 업무 폴더>" --days 7`
   사용자가 이전 HTML을 제공해 비교를 요청한 경우에만 `--compare-to "<이전 보고서의 정확한 절대경로>"`를 붙입니다. 같은 폴더와 같은 길이의 겹치지 않는 기간만 비교합니다. 이 비교도 개선 효과의 인과 증명은 아닙니다.
2. 짧은 반환값의 `reportPath`를 연결하고 주요 후보 최대 3개와 다음 행동을 한국어로 안내합니다. HTML에서 상세 수치와 한계를 보며 Markdown으로 내려받을 수 있습니다. HTML 전체나 원본 로그를 다시 Read해서 대화에 넣지 않습니다.
3. 기록 없음은 정상 판정이 아닙니다. 이미 삭제되었거나 다른 환경에 저장된 기록을 찾으려고 PC 전체를 뒤지지 않습니다. 짧은 기간, 누락된 사용량과 최근 상태만 관찰한 부분을 구분합니다. 반복 질문과 재읽기를 무조건 불필요하다고 판단하지 않습니다.

기존 기록을 로컬 코드로 집계하며 추가 모델 분석, 예약, 상시 후크, 설정 변경, 자동 수정과 학습 저장을 실행하지 않습니다. 짧은 결과만 현재 대화에서 설명하고 보고서 작성 때문에 별도 작업자나 제작 스킬을 불러오지 않습니다. 런타임 정보가 없으면 설정이나 세션 ID를 탐색하지 말고 현재 연결에서 이 명령을 실행할 수 없는 사유만 알립니다.

긴 기록은 코드의 분석 상한과 요약으로 제한합니다. `/compact`를 대신 실행하거나 강제하지 않습니다. 사용자가 긴 대화 정리를 요청하면 현재 목표, 결과 파일, 완료한 검증과 미확인 사항을 남기는 방법을 설명합니다.
