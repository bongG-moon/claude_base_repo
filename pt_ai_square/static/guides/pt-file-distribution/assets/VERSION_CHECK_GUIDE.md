# 실행할 때 배포 버전만 확인하기

배포할 도구에 버전 확인 코드를 넣어 달라는 요청이 있을 때 참고하는 개발 자료입니다. 기본 배포 ZIP 제작에 필요한 절차가 아니며, 배포 Skill 자체의 플랫폼 조회나 연결 기능을 뜻하지 않습니다. Skill 실행 중 KEY를 요청하거나 이 예제를 회사 서버에 실행하지 않습니다.

이 기능은 파일을 교체하지 않습니다. 등록자는 실행 코드에 확인 절차를 넣고, 사용자는 알림을 보고 원할 때 새 파일을 받아 설치합니다. ZIP을 올리는 것만으로 이미 만들어진 모든 도구에 자동으로 삽입되는 기능은 아닙니다.

## 사용자에게 보이는 동작

| PC의 버전 | 웹의 현재 배포 | 안내 |
|---|---|---|
| v2 | v2 | 현재 배포 버전입니다. 조용히 계속 실행할 수도 있습니다. |
| v2 | v3 | 새 버전 v3가 있습니다. 기존 도구는 계속 사용할 수 있습니다. |
| v3 | 문제로 v2 복구 | 서버가 v2로 복구되었습니다. 배포 안내를 확인하세요. |
| 확인 실패 | 알 수 없음 | 지금은 버전을 확인할 수 없습니다. |

## 등록자가 연결하는 순서

1. `scripts/version_check.py`를 공유 도구의 실행 코드와 함께 넣습니다.
2. 웹에 게시한 뒤 등록된 도구 ID와 발급된 배포 번호를 확인합니다. 예를 들어 ID 17, v2입니다.
3. 설치 안내에서 서버 주소, ID 17, 설치한 번호 2를 로컬 설정에 기록하도록 안내합니다. 실제 파일 설치가 끝난 경우에만 번호를 기록합니다. 웹에서 최신 번호를 조회했다고 로컬 번호까지 바꾸면 항상 최신으로 잘못 판단합니다.
4. 실행 코드에서 아래 함수를 호출하고, 결과의 `message`를 기존 프로그램의 알림·상태 표시 영역에 보여줍니다. 예제에는 팝업 UI를 강제로 만들거나 파일을 다운로드하는 코드가 없습니다.
5. 운영 환경에서는 실행하는 사용자 본인의 **연결 KEY**를 전달합니다. 웹 상단 KEY 아이콘에서 개인 KEY를 발급하면 됩니다. 이미 보관 중인 유효한 개인 KEY는 그대로 쓸 수 있습니다. 웹 브라우저 로그인만으로 Python 인증이 자동 완성되지 않습니다. 아래 코드에서 서버 주소와 도구·배포 번호는 실제 값으로 바꾸고, KEY는 사용자 실행 세션에서 제공하도록 연결합니다.

```python
import os
from scripts.version_check import check_version

# 예시 값입니다. 설치된 파일의 배포 번호를 로컬 설정에서 읽으세요.
key = os.environ.get("PTAI_API_TOKEN", os.environ.get("PTAI_READ_TOKEN", "")).strip()
result = check_version("https://회사-플랫폼-주소", 17, 2, token=key)
# 사내 HTTP를 최초 연결 시 사용자에게 알리고 허용한 경우에만:
# result = check_version("http://회사-플랫폼-주소", 17, 2, token=key,
#                        allow_http_origin="http://회사-플랫폼-주소")
# 로컬 mock 시험: check_version("http://127.0.0.1:5080", 17, 2)
# result['status']가 current이면 그대로 실행합니다.
# 그 외에는 기존 UI에 result['message']를 표시한 후 실행을 이어갑니다.
# MCP라면 print()로 stdout에 쓰지 마세요. 프로토콜을 깨뜨립니다.
```

KEY를 채팅·소스 코드·설정 예시·배포 ZIP·로그에 넣지 않습니다. 위 예시는 프로세스 환경변수에서 읽으며 `.env` 파일을 자동으로 읽지 않습니다. 앱에 보안 입력 기능이 있다면 입력받은 값을 `token`으로 직접 전달할 수도 있습니다. 이미 별도의 승인된 HTTP 인증 클라이언트가 있으면 `opener=`로 연결하되 `token`과 함께 전달하지 않습니다. 기본 KEY 방식은 다른 주소로의 리다이렉트를 따라가지 않습니다. 실제 사내 HTTP 주소는 최초 연결 때 KEY 전송이 암호화되지 않음을 확인한 경우에만 같은 origin(프로토콜·호스트·포트)을 `allow_http_origin`으로 지정합니다. 다른 서버 주소로 바꾸면 다시 확인해야 합니다.

새로 발급한 KEY는 유효기간 없이 사용하지만, 사번당 활성 KEY는 하나입니다. **KEY 재발급** 또는 취소 시 기존 KEY는 즉시 사용할 수 없으며 기존 연결 프로그램도 갱신해야 합니다. 과거에 만료일을 지정한 KEY는 그 만료일을 유지합니다. 원문은 발급 직후에만 볼 수 있습니다.

`authentication_required`는 KEY·인증 상태 확인 필요, `permission_required`는 도구 조회 권한 필요, `not_found`는 삭제되었거나 존재하지 않는 도구, `unknown_release`는 잘못 기록된 배포 번호, `unavailable`은 서버·네트워크·응답 확인 실패입니다. 401이면 `플랫폼주소/local-access`에서 KEY 상태·재발급 여부를 확인하고, 403이면 웹에서 해당 도구의 조회 권한을 신청합니다. 어느 경우에도 '최신입니다'로 표시하지 않습니다. `installedWithdrawn`이 true이면 현재 설치 버전이 웹에서 철회되었다는 안내도 함께 표시합니다. 버전 확인은 다운로드 건수를 올리거나 원본 업무 기능의 인증을 대신하지 않습니다.

Markdown만 있는 Skill은 자동 실행 지점이 없으므로 Python 진입점 등 실제 실행 방식이 마련된 경우에만 연결할 수 있습니다. MCP 서버가 계속 실행 중이라면 시작 시 한 번 확인하는 것과 매 도구 호출 시 확인하는 것은 다릅니다. 등록자는 도구 사용 방식에 맞는 지점을 선택하고 설치 안내에 명시합니다.

## 배포 정보 JSON 활용

ai-square.json이 있는 ZIP을 게시했다면 완료 화면 또는 상세의 **배포 정보 JSON 받기**를 사용합니다. `toolId`, `release`, `sha256`, `versionCheckUrl`이 해당 배포에 맞춰 발급됩니다. URL은 플랫폼 주소 기준의 상대 경로입니다. 예를 들어 toolId=17, release=2이면 기존 check_version 함수의 인수로 17과 2를 사용합니다.

이 JSON은 원본 ZIP 밖에 제공하며 ZIP 내부 코드를 바꾸지 않습니다. 설치 완료 후 JSON의 배포 번호를 로컬 설정에 기록하도록 안내하세요. 파일을 내려받았다는 이유만으로 설치 완료로 처리하거나 실행 때마다 최신 배포 번호를 덮어쓰지 않습니다. 사용자 KEY 입력과 버전 확인 함수 호출 지점은 도구에서 연결해야 합니다.
