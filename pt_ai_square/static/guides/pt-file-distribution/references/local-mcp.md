# MCP로 이어가기

배포 Skill은 로컬 원본으로 공유할 파일과 설명을 만드는 도구다. AI SQUARE MCP는 플랫폼에 연결해 항목을 찾고, 다운로드하거나 설치하고, 본인 계정으로 등록하는 도구다. MCP에서도 원본을 확인하고 배포 ZIP을 준비할 수 있으므로 모든 사용자가 이 Skill을 먼저 설치할 필요는 없다.

## 배포 Skill이 전달할 것

- 완성한 ZIP 또는 단일 MD 파일의 위치
- 쉬운 이름과 소개, 실제 기능에 맞는 업무 태그
- 설치 안내와 필요한 환경, 변경 내용
- 파일 구성 등 확인한 내용과 아직 검증하지 못한 내용

배포 선언의 규칙은 [배포 정보 규칙](package-format.md), 소개 문장의 기준은 [등록 글 작성 기준](catalog-writing.md)을 따른다. 기존 도구의 새 버전을 준비할 때 사용자가 이미 알려준 도구 ID는 인계 정보로 전달할 수 있지만 ZIP의 `ai-square.json`에 넣지 않는다. 새 파일의 packageId가 기존 것과 다르더라도 기존 도구를 명시적으로 선택해 업데이트할 수 있다. 플랫폼의 고정 ID와 새 파일의 원본 ID는 별개다.

## 사용자가 실제 등록을 원할 때

배포 Skill의 작업은 파일 전달로 마친다. 연결된 AI SQUARE MCP가 있다면 사용자가 같은 채팅에서 "이 배포 파일을 AI SQUARE에 등록해줘"라고 이어서 요청할 수 있다. MCP가 연결되어 있지 않으면 웹의 **도구 등록**에서 파일을 올릴 수 있다.

실제 등록 시에는 조직과 업무 분류, 신규 또는 기존 도구 업데이트, 공개 범위를 사용자 요청에 맞게 선택해야 한다. 로그인 부서와 게시할 조직은 같은 개념이 아니다. 파일을 만들었다는 사실만으로 공개 등록에 동의한 것으로 처리하지 않는다. 본인 도구만 업데이트할 수 있는 권한 확인은 플랫폼과 MCP가 담당한다.

MCP 연결, KEY 입력, 검색, 다운로드, 설치와 게시 절차는 **최신 MCP ZIP의 README와 웹 연결 안내**를 따른다. 이 문서를 그 실행 절차로 사용하지 않는다. 별도 업로드용 KEY나 예전 게시 CLI 설정을 배포 Skill의 필수 준비물로 요구하지 않는다.

## 이전 버전의 Skill을 바꿀 때

최신 배포 Skill ZIP으로 기존 `pt-file-distribution` 폴더 전체를 교체한다. 예전 파일 위에 덮어쓰기만 하면 현재 배포에서 빠진 연결 또는 게시 스크립트가 남을 수 있다. 개인 KEY나 플랫폼 연결 설정은 배포 Skill 폴더에 보관하지 않는다. 이미 만든 배포 ZIP과 플랫폼에 등록한 도구는 이 역할 구분 때문에 다시 만들 필요가 없다.
