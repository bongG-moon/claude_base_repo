# P&T AI SQUARE 파일 배포 준비

사용자가 만든 도구를 다른 동료가 이해하고 사용할 수 있는 배포 파일로 정리한다. 이 Skill의 작업은 **로컬 자료 확인 → 배포 설명과 안내 작성 → 배포 파일 제작 → 파일 검증과 전달**까지다. 서버 주소나 개인 KEY 없이 사용할 수 있다.

## Skill과 MCP의 역할

| 사용하려는 기능 | 담당 |
|---|---|
| 원본을 읽고 배포 ZIP과 등록 설명 만들기 | 이 배포 Skill. MCP에서도 배포 준비 기능을 사용할 수 있다. |
| 플랫폼의 등록 항목 찾기, 추천, 좋아요 | AI SQUARE MCP |
| 개인 KEY 연결, 다운로드와 실제 설치 | AI SQUARE MCP |
| 신규 등록, 본인 도구의 새 버전 업로드 | AI SQUARE MCP 또는 사용자가 웹에서 직접 등록 |

이 Skill을 사용 중일 때 플랫폼 작업까지 이어서 실행하지 않는다. `square_client.py configure`, `publish_client.py prepare`, `publish_client.py publish` 같은 과거 CLI 절차는 이 Skill의 작업이 아니다. KEY를 요청하거나 플랫폼에 접속하거나 게시 초안을 만들지 않는다. 작업 설명에서도 이를 가능한 기능으로 나열하지 않는다.

사용자가 "등록해줘"라고 요청했더라도 이 Skill은 배포 파일을 준비해 전달한다. 실제 게시까지 원하면 연결된 AI SQUARE MCP로 이어갈 수 있음을 안내한다. MCP가 없으면 웹의 도구 등록에서 만든 파일을 올릴 수 있다고 알려준다. MCP를 연결하거나 설치를 시작하는 것은 이 Skill의 완료 조건이 아니다. 역할 구분과 인계 항목은 [MCP로 이어가기](references/local-mcp.md)를 참고한다.

"무엇을 할 수 있나요?"에는 예를 들어 "원본 파일을 확인하고, 동료가 이해하기 쉬운 이름과 설명, 설치 안내를 붙여 배포 ZIP을 만듭니다. 필요한 파일과 배포 정보가 빠졌는지도 확인합니다. 플랫폼 검색, 설치와 업로드는 AI SQUARE MCP에서 할 수 있습니다."처럼 답한다.

## 대상과 사용 방식 파악

기존 프로젝트의 안내 문서와 실행 진입점을 먼저 확인한다. 이미 있는 설정과 구조를 존중하고, 꼭 필요한 정보가 없을 때만 질문한다.

- 사용 프로그램은 Claude / ChatGPT / 기타 중 선택한다. 대상이 불명확하면 Claude가 맞는지 확인하되 실제 호환성을 임의로 확정하지 않는다.
- 실제 진입점과 사용 방식을 보고 공유 유형을 판단한다. MCP 서버 또는 독립 실행 도구는 `MCP/Tool`, 모델이 읽는 SKILL.md 중심의 지침과 보조 코드는 `Skill`, 호스트 플러그인 manifest·훅이나 실행 흐름을 묶은 패키지는 `플러그인/하네스`로 기록한다. 여러 유형이 섞이면 사용자가 설치하는 최상위 배포 단위로 분류하고 판단 근거를 설명한다. 불명확한 경우에만 묻는다. 확장자만으로 판단하지 않는다.
- 파일 설치, 터미널 명령어 설치, 원격 서버 연결, 웹 접속 중 실제 사용 방식을 확인한다. 웹은 ZIP 선언의 type을 읽어 자동 입력하며 소스 코드를 분석해 추론하는 것은 아니다.
- Skill에는 SKILL.md뿐 아니라 Python 코드, 참고 자료, 필요한 리소스가 포함될 수 있다.

## 기존 도구를 보존하며 배포 자료 준비

- 원본을 변경하지 않아도 되는 작업은 별도의 배포 폴더에서 수행한다. 기존 제품 동작을 바꾸는 수정은 요청 범위에 포함될 때만 한다.
- 여러 파일을 참조하는 Skill이나 소스 묶음은 ZIP으로 준비한다. 기존 상대 경로와 디렉터리 구조를 유지한다. 단일 Markdown만으로 동작하고 사용자가 MD 배포를 원하면 `.md` 원본으로 제공한다. 설명 파일을 추가하려고 억지로 ZIP으로 만들지 않는다. 설치 안내는 웹 입력용 텍스트로 별도 전달한다.
- 단일 MD는 `python scripts/prepare_package.py "원본/SKILL.md" "배포/SKILL.md"`로 원본 바이트를 보존해 복사할 수 있다. 웹에서 **파일 등록 → MD 선택**으로 게시한다. 이 경우 ZIP 선언 자동 입력 대신 유형 `Skill`과 설명을 직접 선택·입력한다.
- 명령어 배포는 ZIP 없이 **명령어 안내 자료**로 준비한다. 실제 도구의 공식 CLI와 지원 범위를 확인하고 프로젝트용·사용자 전역용 명령어를 각각 준비한다. 추측한 CLI 옵션을 만들지 않는다. 지원하지 않는 범위는 비워 두고 이유를 설치 안내에 적는다. 사용자 비밀번호·토큰을 명령어에 포함하지 않는다.
- 원격 MCP·API·웹앱은 HTTP 또는 HTTPS URL과 인증·권한 안내를 준비한다. 사내 주소의 포트·경로도 그대로 적되 주소에 아이디·비밀번호·KEY를 넣지 않는다. URL 등록은 연결 안내를 공유하는 것이며 원격 MCP 자동 설정이 아니다. URL을 억지로 ZIP이나 EXE로 바꾸거나 HTTP를 임의로 HTTPS로 고치지 않는다. AI SQUARE 개인 KEY 연결의 HTTP 확인 규칙과는 별개다.
- AX Workspace의 `.axextension`은 AX 앱이 여는 ZIP 구조의 확장 파일이다. 이미 준비된 파일은 원본 형식으로 전달하며 Claude Skill이나 MCP 설치 파일이라고 안내하거나 임의로 확장자만 바꾸지 않는다. 서버는 ZIP과 동일하게 내부 경로와 선언을 검사한다.
- EXE·MSI·PS1이 이미 있으면 원래 용도와 실행 절차를 기록한다. 해당 도구가 없는 환경에서 설치 파일을 만들었다고 주장하지 않는다.
- 실행 파일이 필요하다는 이유만으로 NSIS 등 시스템 프로그램을 임의 설치하거나 관리자 권한을 요구하지 않는다. 빌드 도구가 없으면 가능한 배포 형식과 남은 작업을 명시한다.
- 사용자 토큰, .env, 비밀키, 개인 데이터, 로그, 개인 PC 절대 경로를 포함하지 않는다. 필요한 환경변수는 값 없는 예시로 설명한다.
- 원래 프로젝트의 의존성과 라이선스를 확인한다. 가상환경 전체를 복사하기보다 필요한 라이브러리와 설치 방법을 기록한다. 사내망에서 의존성을 받을 수 있는지도 구분한다.

## 등록 설명과 설치 안내

### 카드 소개와 동작 흐름

이름·소개·태그를 작성하거나 다듬을 때는 [동료가 이해하고 찾을 수 있는 등록 글](references/catalog-writing.md)을 읽는다. ZIP의 `ai-square.json`과 단일 MD, URL, 명령어를 위한 등록 설명에 같은 기준을 쓴다. MCP에서도 이 작성 기준을 재사용할 수 있지만, 이 Skill이 직접 게시하지는 않는다.

- `name`은 **무엇을 하는지 바로 알 수 있는 짧은 이름**으로, 50자 이내로 쓴다. 예: `업무 메모로 주간 보고서 작성`. 추상적인 제목과 홍보 문장을 두 줄로 붙이지 않는다. 사용자가 지정한 제품명은 보존하고 필요한 경우 동작을 짧게 덧붙인다. 표시 이름을 다듬는 일과 `packageId`·설치 경로를 바꾸는 일은 별개다.
- `desc`는 200자 이내의 1~2문장으로 쓴다. 동료가 넣을 자료, 도구가 하는 일, 언제 쓰는지를 실제 자료에 근거해 설명한다. 구현 방식보다 결과를 먼저 쓰고, 짧은 소개를 파일 형식·내부 모듈·기술 용어 목록으로 채우지 않는다.
- 쉬운 말로 바꾸되 대상과 조건은 숨기지 않는다. Claude·Codex 기록만 읽는 도구를 모든 업무 기록을 수집하는 도구처럼 소개하지 않는다. 필요한 계정·권한, 정보 수집 범위와 제한은 설치·사용 안내에서 명확히 설명한다.
- 카드와 안내는 자연스러운 `합니다`체로 쓴다. 과한 칭찬, 막연한 효율 향상, 슬로건, 같은 뜻의 반복을 구체적인 동작으로 바꾼다. 특정 단어가 있다는 이유만으로 기계적으로 지우지 않는다. 실제 동작을 확인하지 못한 부분은 꾸미지 않는다.
- 작성하는 제목, 소개, 사용 안내, 동작 흐름과 추천 문장에서 여러 항목을 나열할 때 가운데점(`·`, `ㆍ`)이나 비슷한 점 기호를 구분자로 쓰지 않는다. 쉼표를 쓰거나 `와`, `과`, `및`으로 자연스럽게 잇고, 길면 문장을 나눈다. 예: `글자와 도형, 표, 차트를 직접 수정합니다.` 코드, 식별자, 공식 고유명과 원문 인용은 임의로 바꾸지 않는다. 이 규칙은 AI SQUARE의 글쓰기 기준이며 기존 게시물을 일괄 치환하거나 서버에서 등록을 거절하는 규칙이 아니다.

원본 코드·SKILL.md·사용 안내와 대조해 이름, 소개, 태그에 약속한 기능이 있는지 다시 읽는다. 이미 게시된 항목이나 사용자가 확정한 이름을 일괄 개명하지 않으며, 새 등록·업데이트를 준비하는 범위에서 적용한다.

실제 코드·SKILL.md·사용 안내에서 확인한 동작을 `workflow.steps`의 1~8개 단계로 정리한다. 각 단계는 `title`(필수, 60자)과 `description`(선택, 240자)으로 작성한다. 웹이 이 선언을 순서형 도식으로 표시하므로 HTML·Mermaid·스크립트를 생성하지 않는다. 검증되지 않은 처리·권한 검사·외부 연동을 단계에 추가하지 않는다. 흐름이 명확하지 않으면 확인하거나 생략한다. 구체적인 JSON 예시는 [배포 정보 규칙](references/package-format.md)의 동작 흐름 표시를 따른다.

ZIP은 ai-square.json에, 단일 MD, URL, 명령어의 등록 자료는 별도 metadata JSON에 workflow를 넣는다. 흐름을 넣기 위해 단일 MD를 ZIP으로 변환하지 않는다. 새 버전을 준비할 때 기존 흐름이 실제 변경 사항과 맞는지도 확인한다. 단일 MD·URL·명령어의 기존 흐름은 새 metadata에서 생략하면 유지하고, `workflow`를 지정하면 교체하며 `"workflow": null`이면 제거한다. 정상적으로 읽힌 ZIP 선언은 해당 버전의 기준이므로 흐름을 생략한 새 선언은 이전 흐름을 이어받지 않는다. 흐름 정보가 없는 기존 도구도 정상적으로 등록·사용할 수 있다. 웹 서버가 설명 문장을 임의로 해석해 만들어 내는 흐름은 아니다.

### 설치 범위는 항상 명시적으로 선택

생성하는 설치 프로그램은 **어떤 파일 복사·의존성 설치·설정 변경보다 먼저** `현재 디렉토리(프로젝트)` / `전역(내 계정)` 선택을 받아야 한다. 기본 선택은 두지 않는다. 빈 입력·입력 취소·비대화형 실행에서 전역으로 자동 전환하지 않는다. 비대화형 실행은 사용자가 명시한 scope가 있을 때만 진행한다. 지원하지 않는 범위를 선택하면 이유를 알리고 중단한다.

이 규칙은 배포 자료에 포함하는 설치 프로그램의 실행 절차다. 이 Skill이 사용자 PC에 실제 설치하거나 폴더 선택 창을 여는 절차가 아니다. 실제 설치는 사용자가 선택한 MCP 또는 설치 프로그램에서 진행한다.

- Python 설치기는 `scripts/install_scope.py`의 `select_scope()`를 가져와 사용한다. 이 도우미는 선택한 범위·기준 경로만 반환한다. 실제 파일 설치는 호스트 규칙에 맞춰 작성한다.
- PowerShell 설치기는 `assets/SELECT_SCOPE.template.ps1`을 시작 부분에 반영한다. 다른 언어·EXE 생성 시에도 같은 선택·취소 동작을 구현한다. 기존 EXE가 선택을 지원하지 않으면 내부를 고쳤다고 주장하지 말고 해당 제약을 알린다.
- 프로젝트 경로는 설치 스크립트가 있는 폴더가 아니라 사용자가 터미널에서 열어 둔 작업 폴더 또는 명시한 프로젝트 경로다. 전역은 현재 사용자 홈 범위이며 모든 Windows 사용자나 관리자 권한 설치를 뜻하지 않는다. 쓰기 전에 실제 대상 경로를 보여준다.
- MD만 배포할 때는 실행 설치기가 없으므로 안내 첫 단계에 두 범위를 설명하고 사용자가 선택한 위치로 복사하도록 한다. 파일 자체가 대화창을 띄운다고 설명하지 않는다.
- URL 연결도 호스트에 범위 개념이 있으면 사용자가 선택하도록 안내한다. 범위 개념이 없는 서비스는 적용 불가와 이유를 명시한다.

빈 입력, 취소, 프로젝트 선택, 전역 선택을 검증하고 어느 경우에도 묵시적 전역 설치가 없는지 확인한다. 웹은 임의로 올린 EXE·PS1 내부의 선택 절차까지 강제할 수 없으므로 실제 설치기의 검증 여부를 구분해 인계한다.

관련 업무 태그를 등록자와 함께 정리한다. 넓은 업무 분야(제조·장비·기술)와 별개로, 동료가 찾을 때 쓸 업무명·자료명·동작을 최대 8개, 각 30자 이내로 적는다. 예: `주간 보고`, `업무 메모`, `보고서 작성`. 실제 지원하는 범위 안에서 `발표자료`와 `PPT`처럼 익숙한 표현도 반영한다. 태그 수를 채우려고 같은 뜻을 반복하거나 지원하지 않는 업무를 넣지 않는다. 웹에서는 쉼표로 구분해 입력하며 이름·소개와 함께 검색된다. 상세 안내에만 검색 표현을 숨겨 두거나 지원하지 않는 `searchKeywords` 필드를 만들지 않는다.

`assets/INSTALL_GUIDE.template.md`를 실제 도구에 맞게 채운다. 사용자 PC에서 설치하는 위치와 서버에서 실행하는 위치를 구분한다. 파일 생성·설정 변경 범위와 제거 방법을 구체적으로 적는다. 기존 사용자의 다른 도구나 개인 설정을 덮어쓰지 않는 방법을 우선한다.

파일 ZIP은 `assets/ai-square.example.json`을 실제 프로젝트에 맞춰 작성하여 ZIP 최상위에 `ai-square.json`으로 넣는다. 정확한 필드와 제약은 [배포 정보 규칙](references/package-format.md)을 따른다. 웹이 이 선언을 읽어 기본 정보·설치 안내를 자동 입력하고 시작 파일·필수 파일을 검사한다. 코드나 의존성을 실행하지 않으며 EXE로 변환하지 않는다. 기존 `assets/registration.example.json`은 수동 등록 참고 양식이며 ZIP 선언으로 사용하지 않는다.

공유할 파일만 있는 별도 폴더를 준비하고 `python scripts/prepare_package.py <준비폴더> <폴더밖의출력.zip>`으로 ZIP을 만든다. 경로에 공백이 있으면 따옴표로 감싼다. 스크립트가 참조하는 `package_contract.py`를 같은 scripts 폴더에 둔다. 원래 프로젝트 전체를 무조건 압축하지 않는다. 출력 ZIP과 검증 결과를 사용자에게 전달한다. 사용자는 웹의 **도구 등록 → 배포 파일에서 불러오기** 또는 연결된 MCP에서 이 파일을 사용할 수 있다. 새 배포 파일로 교체할 때 웹이 내용 적용 여부를 물으면 원하는 내용을 확인해 선택한다. 조직, 업무 분류와 공개 범위는 실제 게시할 때 사용자가 선택하며, 로그인 부서나 로컬 폴더 이름으로 추정해 넣지 않는다.

버전 번호는 웹에서 발급하도록 두고, 등록자는 바뀐 내용을 적는다. 업데이트·복구 지원 여부는 실제 구현을 확인한 범위에서만 설명한다. 웹의 배포 버전 변경과 사용자 PC의 설치 버전 변경은 다르다.

게시 단계의 버전 발급, 조회 승인과 사용자 PC의 실제 설치는 별개다. 이 Skill은 배포 파일과 안내를 만들며 그 작업들을 완료한 것으로 표시하지 않는다.

ChatGPT 대상은 자료를 복사·첨부하는 방식과 원격 MCP 연결을 구분한다. 계정 정책이나 연결 기능을 확인하지 못했다면 '파일 활용 안내' 또는 '연결 조건 확인 필요'로 적는다. 로컬 플러그인을 곧바로 설치할 수 있다고 가정하지 않는다.

## 검증과 인계

### 선택 사항: 배포하는 도구의 버전 확인 코드

사용자가 배포할 도구에 실행 시 버전 확인 기능을 넣어 달라고 명시한 경우에만 `scripts/version_check.py`와 [버전 확인 안내](assets/VERSION_CHECK_GUIDE.md)를 참고한다. 이는 제작하는 도구에 넣을 선택적 예제이며, 배포 Skill이 서버에 접속해 등록 항목이나 최신 버전을 조회하는 기능이 아니다. 기본 ZIP 제작에 서버 설정, KEY 입력, 버전 조회를 추가하지 않는다.

숫자 도구 ID와 배포 번호는 게시 뒤 서버가 정한다. 제작 중 값을 만들어 넣지 않는다. 사용자의 KEY를 코드나 ZIP에 포함하지 않으며, 이미 설치한 버전을 최신 서버 번호로 덮어써서는 안 된다. Markdown 전용 Skill은 실행 훅이 없어 자동 버전 확인을 보장할 수 없다.

가능한 범위에서 ZIP 내부 경로, 필요한 파일 누락, 의존성 설명, 비밀정보 포함 여부를 확인한다. 필요한 실행 검증은 격리된 예제 자료로 한다. 검증을 이유로 실제 사내 시스템에 접속하거나 계정을 변경하거나 사용자 PC에 설치하지 않는다.

완료 시 다음을 짧게 제시한다.

1. 업로드할 파일, 등록할 URL 또는 범위별 설치 명령어. 단일 MD는 MD 그대로 제공한다.
2. 도구 이름, 한 줄 소개, 프로그램, 유형, 관련 업무 태그와 필요한 권한. 게시 조직과 공개 범위는 등록 단계에서 선택한다고 안내한다.
3. 동료가 따라 할 설치·연결 안내와 사용 예시.
4. 확인한 항목과 아직 확인하지 못한 항목.

보안 검사, 코드 서명, 자동 업데이트, 롤백을 검증하지 않았다면 완료했다고 표시하지 않는다. 배포 파일을 만들었다고 플랫폼 등록이나 PC 설치까지 완료한 것으로 설명하지 않는다. **파일과 안내를 전달하면 이 Skill의 작업을 마친다.**
